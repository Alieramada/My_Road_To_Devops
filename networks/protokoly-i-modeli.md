# Протоколы и Модели

Сети могут различаться по размеру и сложности. Недостаточно иметь соединение,\
устройства должны договориться о том, “как” взаимодействовать.\
В любой коммуникации есть три элемента:

* Должен быть источник(src) (отправитель).
* Должен быть пункт назначения (dst)(получатель).
* Будет существовать канал (медиа), который обеспечивает канал передачи\
  данных.

### **Коммуникационные протоколы**

* Все коммуникации регулируются протоколами.
* Протоколы - это правила, которым должны соответствовать коммуникации.
* Эти правила будут варьироваться в зависимости от протокола.

### **Установление правил**

В протоколах должны учитываться следующие требования:

* Идентификация отправителя и получателя
* Общий язык и грамматики
* Скорость и сроки доставки
* Требования к подтверждению

Компьютерные протоколы должны быть согласованы и включать следующие требования:

* Кодирование сообщений
* Форматирование и инкапсуляция сообщений
* Размер сообщения
* Время отправки сообщений
* Параметры доставки сообщений

### **Кодирование сообщений**

* Кодирование - это процесс преобразования информации в другую приемлемую для\
  передачи форму.
* Декодирование обращает этот процесс для интерпретации информации.

### **Форматирование сообщений**

* При отправке сообщения необходимо использовать определенный формат или структуру.
* Форматы сообщений зависят от типа сообщения и канала, который используется для\
  доставки сообщения.

### **Размер сообщения**

* Кодирование между хостами должна быть в соответствующем формате для носителя.
* Сообщения, передаваемые по сети, преобразуются в биты
* Биты кодируются в виде последовательности световых, звуковых или электрических импульсов.
* Хост-получатель должен декодировать сигналы для интерпретации сообщения.
* Сообщения определённых протоколов имеют максимальный и минимальный размер.

### **Синхронизация сообщений**

Синхронизация сообщений включает в себя следующее:

* **Управление потоком (Flow Control)**\
  Управляет скоростью передачи данных и определяет, какой объем информации\
  может быть отправлен и с какой скоростью она может быть доставлена.
* **Время ожидания ответа(Response Timeout)**\
  Определяет, как долго устройство ожидает, когда не получит ответа от\
  адресата.
* **Способ доступа (Access method)**\
  Определяет, когда кто-либо может отправить сообщение.

Могут существовать различные правила, регулирующие такие проблемы, как “коллизии”. Это происходит, когда несколько устройств отправляют трафик одновременно и сообщения становятся поврежденными.\


Некоторые протоколы являются превентивными (CSMA/CА) и пытаются предотвратить коллизии; другие протоколы реагируют и устанавливайте метод восстановления после возникновения коллизии.

### **Варианты доставки сообщений**

Доставка сообщений может осуществляться одним из следующих способов:\


* Одноадресная передача данных "один к одному" **Unicast**
* Многоадресная передача "один ко многим", обычно не ко всем **Multicast**
* Широковещательная передача "один ко всем" **Broadcast**

{% hint style="info" %}
Широковещательные передачи используются в сетях IPv4, но не являются опцией для IPv6. Позже мы также увидим “Anycast” в качестве дополнительного варианта доставки для IPv6
{% endhint %}

Существует несколько стэков протоколов. Самые популярные стэк протоколов TCP/IP и OSI (Разработан International&#x20;Organization for Standardization (ISO) и&#x20;the International Telecommunications Union).

Выше приведена модель tcp/ip которая имеет 4 уровня:

1. Канальный уровень

* Отвечает за физическую передачу данных
* Определяет стандарты и протоколы передачи
* Работает с технологиями Ethernet и Wi-Fi
* Преобразует данные в сигналы для передачи
* Управляет передачей по физическим средам

2. Межсетевой уровень

* Обеспечивает маршрутизацию пакетов
* Использует протокол IP
* Назначает IP-адреса пакетам
* Управляет трафиком между сетями
* Настраивает маршрутизаторы
* Формирует маршрутизационные таблицы

3. Транспортный уровень

* Обеспечивает надежную передачу данных
* Использует протоколы TCP и UDP
* TCP отвечает за:
  * Установление соединения
  * Контроль потока данных
  * Обработку ошибок
* UDP обеспечивает быструю передачу без управления потоком и ошибками

4. Прикладной уровень

* Обеспечивает взаимодействие приложений
* Использует протоколы:
  * HTTP (для веб-браузеров)
  * FTP (для передачи файлов)
  * SMTP (для электронной почты)
  * DNS (для преобразования доменных имен в IP-адреса)
* Предоставляет интерфейс для работы пользователя
* Обрабатывает запросы приложений

Модель OSI Имеет 7 уровней:

<figure><img src="../.gitbook/assets/image (26).png" alt=""><figcaption></figcaption></figure>

1. **Физический уровень (L1)**

* Передача данных в виде электрических, световых или радиосигналов
* Работа с проводниками и физическими носителями
* Преобразование информации в двоичный код
* Настройка физических параметров (частота, амплитуда, напряжение)
* Работает с кабелями (Ethernet), беспроводными сигналами (Wi-Fi, Bluetooth)
* Взаимодействие с аппаратными компонентами

2. **Канальный уровень (L2)**

* Управление адресами устройств
* Обнаружение и исправление ошибок
* Контроль целостности данных
* Преобразование битов в структурированные кадры
* Управление доступом к среде передачи через MAC-протоколы
* Обработка физических сигналов

3. **Сетевой уровень (L3)**

* Маршрутизация данных
* Выбор оптимального пути передачи
* Работа с IP-адресами
* Пакетирование данных
* Сопоставление IP- и MAC-адресов
* Обеспечение доставки в сложных сетях

4. **Транспортный уровень (L4)**

* Передача данных между узлами
* Обеспечение надежности передачи
* Сегментация данных
* Управление потоком информации
* Контроль ошибок
* Мультиплексирование

5. Сеансовый уровень (L5)

* Управление соединением между устройствами
* Синхронизация передачи данных
* Обработка разрывов связи
* Обеспечение стабильности соединения
* Поддержка мультимедиа-приложений
* Проверка совместимости устройств

6. **Уровень представления данных (L6)**

* Преобразование форматов данных
* Кодирование и декодирование
* Сжатие информации
* Шифрование и расшифровка
* Подготовка данных к передаче
* Обработка битового потока

7. **Прикладной уровень (L7)**

* Взаимодействие с пользователем через приложения
* Работа с сетевыми протоколами (FTP, HTTP, SMTP)
* Обработка запросов и ответов
* Предоставление графического интерфейса
* Управление сетевыми интерфейсами
* Обеспечение доступа к сетевым ресурсам

Обе модели являются взаимозаменяемыми.

### **Сегментирование сообщений**

Сегментация - это процесс разделения сообщений на более мелкие блоки.&#x20;

Мультиплексирование - это процесс получения нескольких потоков сегментированных данных и их чередования.\


Сегментация сообщений имеет два основных\
преимущества:

* Увеличивает скорость передачи больших объемов\
  данных по сети\
  без подключения к каналу связи.
* Повышает эффективность повторной передачи только тех сегментов,\
  которые не доходят до адресата, а не всего потока данных.

## Sequencing

Упорядочивание сообщений - это процесс нумерации сегментов, чтобы сообщение могло быть повторно собрано в пункте назначения.\
Протокол TCP отвечает за упорядочивание отдельных сегментов.

### Protocol Data Units(PDU), Инкапсуляция

<figure><img src="../.gitbook/assets/image (28).png" alt=""><figcaption></figcaption></figure>

PDU (Protocol Data Unit) – это стандартизированная единица данных, которая используется для передачи информации через сеть.&#x20;

#### Структура PDU:

* Состоит из заголовка (header) и полезной нагрузки (payload)
* Заголовок содержит управляющую информацию для маршрутизации и обработки
* Полезная нагрузка несет фактические данные для передачи
* Некоторые PDU также содержат tail

PDU в соответствии с протоколами пакета TCP/IP:\
Ниже по стеку передаются следующие PDU\
1.Данные Data (поток данных)\
2.Сегмент\
3.Пакет\
4.Фрейм\
5.Бит (поток битов)

### **Инкапсуляция**

Инкапсуляция - это процесс, при котором протоколы добавляют свою информацию к данным.\
На каждом этапе процесса PDU получает другое имя, отражающее его новые функции.

<figure><img src="../.gitbook/assets/image (29).png" alt=""><figcaption></figcaption></figure>

<figure><img src="../.gitbook/assets/image (30).png" alt=""><figcaption></figcaption></figure>

* Инкапсуляция - это нисходящий процесс.
* На верхнем уровне выполняется свой процесс, а затем он передается на следующий уровень\
  модели. Этот процесс повторяется на каждом уровне до тех пор, пока не будет отправлен в виде потока битов.

### **Декапсуляция**

Данные деинкапсулируются по мере их продвижения вверх\
по стеку.\
Когда уровень завершает обработку, он удаляет свой заголовок и\
передает остальное содержимое для обработки на следующий уровень.

Это повторяется на каждом уровне до тех пор, пока приложение не сможет обработать поток данных.\
1\.  Полученные в виде битов (поток битов)\
2\. Кадр\
3\. Пакет\
4\. Сегмент\
5\. Данные (поток данных)
