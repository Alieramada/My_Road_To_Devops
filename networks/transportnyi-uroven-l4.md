# Транспортный уровень L4



\
Транспортный уровень выполняет следующие&#x20;функции:

* Отслеживание отдельных диалогов
* Сегментирование данных и повторная сборка  &#x20;сегментов
* Добавление информации в заголовки
* Идентификация, разделение и управление  &#x20;несколькими диалогами
* Использует сегментацию и  &#x20;мультиплексирование, чтобы обеспечить  \
  возможность чередования различных коммуникационных разговоров  \
  в одной и той же сети

## **Протоколы транспортного уровня**

Протокол IP не определяет, как&#x20;происходит доставка или транспортировка\
пакетов.

Протоколы транспортного уровня&#x20;определяют, как передавать\
сообщения между хостами, и&#x20;отвечают за управление&#x20;требованиями к надежности&#x20;обмена данными.\
\
Транспортный уровень включает протоколы&#x20;TCP и UDP.

## **Transmission Control Protocol**

Протокол TCP обеспечивает надежность и&#x20;управление потоком данных. Основные операции TCP:

* Подсчет и отслеживание сегментов данных  , передаваемых на определенный хост из  &#x20;определенного приложения
* Подтверждение полученных данных
* Повторная передача любых неподтвержденных  &#x20;данных через определенный промежуток  &#x20;времени
* Упорядочивайте данные, которые могут поступать  &#x20;в неправильном порядке
* Отправляйте данные с эффективной скоростью,  &#x20;приемлемой для получателя

## **Функции TCP**

\
**Установление сеанса**: TCP - это протокол, ориентированный на подключение, который согласовывает и&#x20;устанавливает постоянное соединение (или сеанс) между исходным и целевым устройствами&#x20;перед пересылкой любого трафика.\
\
**Обеспечение надежной доставки:** По многим причинам **сегмент(PDU транспортного уровня)** может быть&#x20;поврежден или полностью потерян при передаче по сети. Протокол TCP гарантирует, что каждый&#x20;сегмент, отправленный источником, достигнет адресата.

**Обеспечение порядка доставки:** Поскольку сети могут предоставлять несколько маршрутов, которые могут&#x20;при разной скорости передачи данные могут поступать в неправильном порядке.

**Управление потоком данных:** Сетевые узлы имеют ограниченные ресурсы (например, память и&#x20;вычислительную мощность). Когда TCP узнает, что эти ресурсы перегружены, он может запросить, чтобы отправляющее приложение уменьшило скорость передачи данных

#### **Диаграмма установки TCP-соединения (Three-Way Handshake)**

```
Клиент                             Сервер
   |                                   |
   |          SYN, Seq=X               |
   |---------------------------------->|
   |                                   |
   |      SYN-ACK, Seq=Y, Ack=X+1      |
   |<----------------------------------|
   |                                   |
   |          ACK, Ack=Y+1             |
   |---------------------------------->|
   |                                   |
```

1. **SYN (Synchronize)** — Клиент отправляет запрос на соединение с начальным номером последовательности `X`.
2. **SYN-ACK** — Сервер подтверждает (`ACK=X+1`) и отправляет свой SYN (`Seq=Y`).
3. **ACK** — Клиент подтверждает (`Ack=Y+1`), соединение установлено.

***

#### **Диаграмма завершения TCP-соединения**

```
Клиент                             Сервер
   |                                   |
   |          FIN, Seq=U               |
   |---------------------------------->|
   |                                   |
   |          ACK, Ack=U+1             |
   |<----------------------------------|
   |                                   |
   |          FIN, Seq=V               |
   |<----------------------------------|
   |                                   |
   |          ACK, Ack=V+1             |
   |---------------------------------->|
   |                                   |
```

1. **FIN (Finish)** — Одна из сторон (например, клиент) инициирует разрыв, отправляя `FIN` с номером `U`.
2. **ACK** — Вторая сторона (сервер) подтверждает (`Ack=U+1`), но может продолжать передачу данных.
3. **FIN** — Когда сервер готов закрыть соединение, он отправляет свой `FIN` (`Seq=V`).
4. **ACK** — Клиент подтверждает (`Ack=V+1`), соединение закрыто.

**RST (Reset)** — Аварийный разрыв соединения (например, при неожиданном порте или атаке).

```
Клиент -> Сервер: SYN  
Сервер -> Клиент: RST-ACK (если порт закрыт)  
```

**PSH (Push)** — Требование немедленно передать данные приложению (без буферизации).

**URG (Urgent)** — Указание на срочные данные (редко используется, например, в Telnet).

### **Поле Window Size и флаг Window Scale (WS) в TCP**

**Window Size (Размер окна) — 16 бит**

Указывает, сколько байт данных получатель готов принять без подтверждения (ACK). Однако в современных высокоскоростных сетях этого недостаточно (например, для 1+ Gbps  каналов)

При стандартном 16-битном поле максимальная пропускная способность = `Window Size / RTT` (Round-Trip Time). Если `RTT = 100 мс`, то максимум ≈ **0.5 Гбит/с** (65 535 × 8 / 0.1).

**Как работает  Window Scaling (RFC 1323)**

Опция TCP (`Window Scale`), позволяющая **масштабировать** значение `Window Size` через сдвиг влево (умножение на `2^N`).

Передается во время **three-way handshake** в поле `Options`.

**Установка соединения**:

* Клиент и сервер объявляют свои `Window Scale` факторы в `SYN` и `SYN-ACK`.
*   Например:

    ```
    Клиент -> Сервер: SYN (Window Scale = 7)  
    Сервер -> Клиент: SYN-ACK (Window Scale = 6)
    ```



`Shift count` ограничен 14 (максимальное окно ≈ **1 ГБ**).

Должна быть включена на обоих концах (обычно активирована в современных ОС).

`Window Size` может адаптироваться к перегрузкам (через алгоритмы вроде **TCP BBR** или **CUBIC**).
