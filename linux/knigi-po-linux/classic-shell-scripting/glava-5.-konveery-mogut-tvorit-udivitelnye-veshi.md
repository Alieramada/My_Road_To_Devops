# Глава 5. Конвееры могут творить удивительные вещи

В этой главе мы решаем несколько относительно простых задач по обработке текста. Что интересно во всех приведенных здесь примерах, так это то, что они представляют собой скрипты, созданные на основе простых конвейеров: цепочки из одной команды, подключенной к другой. Тем не менее, каждый из них выполняет важную задачу.

Когда вы решаете проблему обработки текста в Unix, важно помнить о философии инструментов Unix: спросите себя, как можно разбить проблему на более простые задачи, для каждой из которых уже есть инструмент, или для которых вы можете легко предоставить несколько строк описания. программа-оболочка или с помощью языка сценариев.

## 5.1 Извлечение данных из структурированных текстовых файлов

Большинство административных файлов в Unix представляют собой простые текстовые файлы, которые вы можете редактировать, распечатывать и читать без каких-либо специальных инструментов для работы с файлами. Многие из них находятся в стандартном каталоге /etc. Типичными примерами являются файлы паролей и групп (passwd и group), таблица подключения файловой системы (fstab или vfstab), файл хостов (hosts), файл запуска оболочки по умолчанию (profile) и сценарии запуска и завершения работы системы, хранящиеся в деревьях подкаталогов rc0.d, rc1.d и так далее, через rc6.d. (Могут быть и другие каталоги).

Форматы файлов традиционно описываются в разделе 5 руководства по Unix, поэтому команда man 5 passwd предоставляет информацию о структуре файла /etc/passwd.\*

Несмотря на свое название, файл паролей всегда должен быть общедоступным. Возможно, его следовало бы назвать user файлом, поскольку он содержит основную информацию о каждой учетной записи пользователя в системе, собранную в одну строку для каждой учетной записи, с полями, разделенными двоеточиями. Мы описали формат файла в разделе “Соглашения о текстовых файлах”. \[3.3.1]. Вот несколько типичных записей:

```bash
jones:*:32713:899:Adrian W. Jones/OSD211/555-0123:/home/jones:/bin/ksh
dorothy:*:123:30:Dorothy Gale/KNS321/555-0044:/home/dorothy:/bin/bash
toto:*:1027:18:Toto Gale/KNS322/555-0045:/home/toto:/bin/tcsh
ben:*:301:10:Ben Franklin/OSD212/555-0022:/home/ben:/bin/bash
jhancock:*:1457:57:John Hancock/SIG435/555-0099:/home/jhancock:/bin/bash
betsy:*:110:20:Betsy Ross/BMD17/555-0033:/home/betsy:/bin/ksh
tj:*:60:33:Thomas Jefferson/BMD19/555-0095:/home/tj:/bin/bash
george:*:692:42:George Washington/BST999/555-0001:/home/george:/bin/tcsh
```

Для ознакомления рассмотрим семь полей ввода файла password.:

1. Имя пользователя
2. Зашифрованный пароль или указание на то, что пароль хранится в отдельном файле
3. Цифровой идентификатор пользователя
4. Цифровой идентификатор группы
5. Имя пользователя и, возможно, другие важные данные (номер офиса, номер телефона и т.д.)
6. Домашний каталог
7. Оболочка входа в систему

Все эти поля, кроме одного, имеют значение для различных программ Unix. Пятое поле, которое не имеет значения, обычно содержит пользовательскую информацию, относящуюся только к локальным пользователям. Исторически это называлось полем gecos, потому что оно было добавлено в 1970-х годах в Bell Labs, когда Unix-системам потребовалось взаимодействовать с другими компьютерами, работающими под управлением комплексной операционной системы General Electric, и для этой системы требовалась некоторая дополнительная информация о пользователе Unix. Сегодня большинство организаций используют его только для записи имени, поэтому мы называем его просто полем имени.

Для целей этого примера мы предполагаем, что организация записывает дополнительную информацию в поле "Имя": идентификатор здания и номера офиса (OSD211 в первом примере ввода) и номер телефона (555-0123), отделенный от личного имени косой чертой.

Одна очевидная полезная вещь, которую мы можем сделать с таким файлом, - это написать некоторое программное обеспечение для создания каталога office. Таким образом, необходимо поддерживать в актуальном состоянии только один файл, /etc/passwd , а производные файлы могут создаваться при изменении основного файла или, что более разумно, с помощью задания cron, которое выполняется с подходящими интервалами. ((Мы обсудим “crontab: Повторный запуск в указанное время” \[13.6.4].)

Для нашей первой попытки мы создадим office directory в виде простого текстового файла с записями, подобными этой:

```bash
Franklin, Ben •OSD212•555-0022
Gale, Dorothy •KNS321•555-0044
```

где • обозначает символ табуляции ASCII. Мы указываем имя пользователя в обычном порядке (сначала фамилия), заполняя поле "имя" пробелами до удобной фиксированной длины. Мы добавляем к номеру офиса и телефона символы табуляции, чтобы сохранить некоторую полезную структуру, которую могут использовать другие инструменты.

Языки сценариев, такие как awk, были разработаны для упрощения таких задач, поскольку они обеспечивают автоматизированную обработку входных данных и разбиение входных записей на поля, поэтому мы могли бы полностью написать задание преобразования на таком языке. Однако мы хотим показать, как добиться того же самого с помощью других инструментов Unix.

Для каждой строки файла паролей нам нужно извлечь пятое поле, разделить его на три подполя, переставить имена в первом подполе, а затем записать строку каталога office в процесс сортировки.

awk и cut - это удобные инструменты для извлечения информации из полей:

```bash
... | awk -F: '{ print $5 }' | ...
... | cut -d: -f5 | ...
```

Существует небольшая сложность в том, что у нас есть две задачи обработки полей, которые мы хотим разделить для простоты, но нам нужно объединить их выходные данные, чтобы создать запись в каталоге. Команда join - это как раз то, что нам нужно: она ожидает два входных файла, каждый из которых упорядочен по общему уникальному значению ключа, и объединяет строки, имеющие общий ключ , в одну строку вывода, при этом пользователь может контролировать, какие поля выводятся.

Поскольку записи нашего каталога содержат три поля, чтобы использовать join, нам нужно создать три промежуточных файла, содержащих пары, разделенные двоеточием, ключ:человек, ключ:офис и ключ:телефон, по одной паре в строке. Все это могут быть временные файлы, поскольку они автоматически выводятся из файла паролей.

Какой ключ мы используем? Оно просто должно быть уникальным, поэтому это может быть номер записи в исходном файле паролей, но в данном случае это также может быть имя пользователя, поскольку мы знаем , что имена пользователей уникальны в файле паролей и имеют больше смысла для людей , чем цифры. Позже, если мы решим дополнить наш каталог дополнительной информацией, такой как название должности, мы можем создать другой несвоевременный файл с ключом jobtitle: название должности и добавить его в этапы обработки.

Вместо жесткого кодирования имен входных и выходных файлов в нашей программе более гибко написать программу в виде фильтра, чтобы она считывала стандартный ввод и записывала стандартный вывод. Для команд, которые используются нечасто, желательно давать им описательные, а не короткие и загадочные названия, поэтому мы запускаем нашу командную оболочку следующим образом:

```bash
#! /bin/sh
# Filter an input stream formatted like /etc/passwd,
# and output an office directory derived from that data.
#
# Usage:
# passwd-to-directory < /etc/passwd > office-directory-file
# ypcat passwd | passwd-to-directory > office-directory-file
# niscat passwd.org_dir | passwd-to-directory > office-directory-file
```

Поскольку файл паролей доступен для общего доступа, любые данные, полученные из него, также являются общедоступными, поэтому нет реальной необходимости ограничивать доступ к промежуточным файлам нашей программы. Однако, поскольку всем нам время от времени приходится иметь дело с конфиденциальными данными, полезно выработать у программистов привычку разрешать доступ к файлам только тем пользователям или процессам, которые в этом нуждаются. Поэтому мы сбрасываем umask (см. “Разрешения по умолчанию” в приложении B) в качестве первого действия в нашей программе:

```bash
umask 077                     Restrict temporary file access to just us
```

Для обеспечения подотчетности и отладки полезно иметь некоторую общность во временных именах файлов и избегать загромождения ими текущего каталога: мы присваиваем им имена с префиксом /tmp/pd.. Чтобы избежать коллизий имен, если несколько экземпляров нашей программы выполняются одновременно, нам также необходимо, чтобы имена были уникальными: номер процесса, доступный в переменной оболочки \$$ содержит отличительный суффикс. (Такое использование \$$ более подробно описано в главе 10.) Поэтому мы определяем эти переменные оболочки для представления наших временных файлов:

```bash
PERSON=/tmp/pd.key.person.$$                 Unique temporary filenames
OFFICE=/tmp/pd.key.office.$$
TELEPHONE=/tmp/pd.key.telephone.$$
USER=/tmp/pd.key.user.$$
```

Когда задание завершается, как обычно, так и ненормально, мы хотим, чтобы временные файлы были удалены, поэтому мы используем команду trap:

```bash
trap "exit 1" HUP INT PIPE QUIT TERM
trap "rm -f $PERSON $OFFICE $TELEPHONE $USER" EXIT
```

Во время разработки мы можем просто закомментировать второй trap, сохранив временные файлы для последующего изучения. (Команда trap описана в разделе “Перехват  обработка сигналов” \[13.3.2]. На данный момент достаточно понять, что при завершении работы скрипта команда trap автоматически запускает rm с заданными аргументами.)

Нам постоянно нужны поля номер один и номер пять, и как только они у нас будут, нам больше не потребуется поток ввода из стандартного ввода, поэтому мы начнем с извлечения их во временный файл:

```bash
awk -F: '{ print $1 ":" $5 }' > $USER                     This reads standard input
```

Сначала мы создаем файл пары ключ:person с помощью двухэтапной программы sed, за которой следует простая линейная сортировка; команда сортировки подробно описана в разделе “Сортировка текста” \[4.1].

```bash
sed -e 's=/.*= =' \
 -e 's=^\([^:]*\):\(.*\) \([^ ]*\)=\1:\3, \2=' <$USER | sort >$PERSON
```

Скрипт использует = в качестве символа-разделителя для команды sed s, поскольку в данных отображаются как косые черты, так и двоеточия. При первом редактировании все от первой косой черты до конца строки удаляется, сокращая строку такого вида:

```
jones:Adrian W. Jones/OSD211/555-0123                     Input line
```

к этому:

```bash
jones:Adrian W. Jones                                         Result of first edit
```

Вторая правка более сложная, она соответствует трем дополнительным шаблонам в записи. Первая часть, ^\\(\[^:]\*\\)_, соответствует полю имени пользователя (например, jones). Вторая часть,_          \\(.\*\\)❒, соответствует тексту с точностью до пробела (например, Adrian❒W.❒; ❒ обозначает символ пробела). Последняя часть, \\(\[^❒]\*\\),соответствует оставшемуся в записи тексту без пробелов (например, Jones). Заменяющий текст изменяет порядок совпадений, в результате чего получается что-то вроде Jones,❒Adrian W. Результатом выполнения этой единственной команды sed является желаемое изменение порядка:

```
jones:Jones, Adrian W.                 Printed result of second edit
```

Далее мы создаем файл пары ключ:office&#x20;

```bash
sed -e 's=^\([^:]*\):[^/]*/\([^/]*\)/.*$=\1:\2=' < $USER | sort > $OFFICE
```

В результате будет получен список пользователей и офисов:

```bash
jones:OSD211
```

Ключ: telephone аналогично: нам просто нужно настроить шаблон соответствия&#x20;

```bash
sed -e 's=^\([^:]*\):[^/]*/[^/]*/\([^/]*\)=\1:\2=' < $USER | sort > $TELEPHONE
```

На данном этапе у нас есть три отдельных файла, каждый из которых отсортирован. Каждый файл состоит из ключа (имени пользователя), двоеточия и конкретных данных (имя пользователя, должность, номер телефона). Содержимое файла $PERSON выглядит следующим образом:

```bash
ben:Franklin, Ben
betsy:Ross, Betsy
...
```

Файл $OFFICE содержит имя пользователя и данные office:

```bash
ben:OSD212
betsy:BMD17
...
```

В файле $TELEPHONE записаны имена пользователей и телефонные номера:

```bash
ben:555-0022
betsy:555-0033
...
```

По умолчанию join выводит общий ключ, затем остальные поля строки из первого файла, за которыми следуют остальные поля строки из второго файла. В качестве общего ключа по умолчанию используется первое поле, но это можно изменить с помощью параметра командной строки: здесь нам это не нужно. Обычно поля для объединения разделяются пробелами, но мы можем изменить разделитель с помощью параметра –t: мы используем его как –t:.

Операции соединения выполняются с помощью пятиэтапного конвейера следующим образом:

1. Объедините личную информацию и местоположение офиса.:

```bash
join -t: $PERSON $OFFICE | ...
```

Результаты этой операции, которые становятся входными данными для следующего этапа, выглядят следующим образом:

```bash
ben:Franklin, Ben:OSD212
betsy:Ross, Betsy:BMD17
...
```

2. Добавьте номер телефона.:

```bash
... | join -t: - $TELEPHONE | ...
```

Результаты этой операции, которые становятся входными данными для следующего этапа, выглядят следующим образом:

```bash
ben:Franklin, Ben:OSD212:555-0022
betsy:Ross, Betsy:BMD17:555-0033
...
```

3. Удалите ключ (который является первым полем), поскольку он больше не нужен. Это проще всего сделать с помощью cut и диапазона, в котором указано “использовать поля со второго по конец”, например , так:

```bash
... | cut -d: -f 2- | ...
```

Результаты этой операции, которые становятся входными данными для следующего этапа, выглядят следующим образом:

```bash
Franklin, Ben:OSD212:555-0022
Ross, Betsy:BMD17:555-0033
...
```

4. Ранее данные были отсортированы по имени пользователя, но теперь их нужно отсортировать по фамилии пользователя. Это делается с помощью функции сортировки:

```bash
... | sort -t: -k1,1 -k2,2 -k3,3 | ...
```

Эта команда использует двоеточие для разделения полей, сортируя поля 1, 2 и 3 по порядку. Результаты этой операции, которые становятся входными данными для следующего этапа, выглядят следующим образом:

```bash
Franklin, Ben:OSD212:555-0022
Gale, Dorothy:KNS321:555-0044
...
```

5. Наконец, переформатируйте выходные данные, используя инструкцию printf в awk, чтобы разделить каждое поле символами табуляции. Для этого используется следующая команда:

```bash
... | awk -F: '{ printf("%-39s\t%s\t%s\n", $1, $2, $3) }'
```

Для обеспечения гибкости и простоты обслуживания форматирование всегда следует оставлять до конца. До этого момента все, что требуется, - это просто текстовые строки произвольной длины.

Вот полный конвейер:

```bash
join -t: $PERSON $OFFICE |
  join -t: - $TELEPHONE |
     cut -d: -f 2- |
        sort -t: -k1,1 -k2,2 -k3,3 |
            awk -F: '{ printf("%-39s\t%s\t%s\n", $1, $2, $3) }'
```

Используемая здесь инструкция awk printf достаточно похожа на команду shell printf , чтобы ее смысл был понятен: выведите первое поле, разделенное двоеточием, с корректировкой по левому краю в поле длиной 39 символов, затем табуляцию, второе поле, другую табуляцию и третье поле. Вот полные результаты:

```bash
Franklin, Ben •OSD212•555-0022
Gale, Dorothy •KNS321•555-0044
Gale, Toto •KNS322•555-0045
Hancock, John •SIG435•555-0099
Jefferson, Thomas •BMD19•555-0095
Jones, Adrian W. •OSD211•555-0123
Ross, Betsy •BMD17•555-0033
Washington, George •BST999•555-0001
```

Вот и все, что нужно сделать! Весь наш скрипт содержит чуть более 20 строк, не считая комментариев, и состоит из пяти основных этапов обработки. Мы собираем его в одном месте в Примере 5-1.

```bash
#! /bin/sh
# Filter an input stream formatted like /etc/passwd,
# and output an office directory derived from that data.
#
# Usage:
# passwd-to-directory < /etc/passwd > office-directory-file
# ypcat passwd | passwd-to-directory > office-directory-file
# niscat passwd.org_dir | passwd-to-directory > office-directory-file
umask 077
PERSON=/tmp/pd.key.person.$$
OFFICE=/tmp/pd.key.office.$$
TELEPHONE=/tmp/pd.key.telephone.$$
USER=/tmp/pd.key.user.$$
trap "exit 1" HUP INT PIPE QUIT TERM
trap "rm -f $PERSON $OFFICE $TELEPHONE $USER" EXIT
awk -F: '{ print $1 ":" $5 }' > $USER
sed -e 's=/.*= =' \
 -e 's=^\([^:]*\):\(.*\) \([^ ]*\)=\1:\3, \2=' < $USER | sort > $PERSON
sed -e 's=^\([^:]*\):[^/]*/\([^/]*\)/.*$=\1:\2=' < $USER | sort > $OFFICE
sed -e 's=^\([^:]*\):[^/]*/[^/]*/\([^/]*\)=\1:\2=' < $USER | sort > $TELEPHONE
join -t: $PERSON $OFFICE |
  join -t: - $TELEPHONE |
   cut -d: -f 2- |
    sort -t: -k1,1 -k2,2 -k3,3 |
     awk -F: '{ printf("%-39s\t%s\t%s\n", $1, $2, $3) }'
```

Реальная мощь shell-скриптов проявляется, когда мы хотим изменить скрипт, чтобы он выполнял несколько иную работу, например, вставить название задания из отдельно сохраняемого файла key:jobtitle. Все, что нам нужно сделать, это изменить конечный конвейер, чтобы он выглядел примерно так:

```bash
join -t: $PERSON /etc/passwd.job-title |                          Extra join with job title
    join -t: - $OFFICE |
         join -t: - $TELEPHONE |
              cut -d: -f 2- |
                     sort -t: -k1,1 -k3,3 -k4,4 | Modify sort command
                       awk -F: '{ printf("%-39s\t%-23s\t%s\t%s\n",$1, $2, $3, $4) }'           And formatting command
```

Общая стоимость дополнительного поля каталога - это еще одно объединение, изменение полей сортировки и небольшая правка в последней команде форматирования awk.

Поскольку мы постарались сохранить специальные разделители полей в наших выходных данных, мы можем тривиально подготовить полезные альтернативные каталоги, подобные этому:

```bash
passwd-to-directory < /etc/passwd | sort -t'•' -k2,2 > dir.by-office
passwd-to-directory < /etc/passwd | sort -t'•' -k3,3 > dir.by-telephone
```

Как обычно, • представляет собой символ табуляции ASCII.

Важнейшим допущением нашей программы является то, что для каждой записи данных существует уникальный ключ . С помощью этого уникального ключа можно сохранять отдельные представления данных в файлах в виде пар ключ:значение. Здесь ключом было имя пользователя в Unix, но в более широком контексте это мог быть номер книги (ISBN), номер кредитной карты, номер сотрудника, номер национальной пенсионной системы, номер части, номер студента и так далее. Теперь вы знаете, почему нам присваивают так много номеров! Вы также можете видеть, что эти маркеры не обязательно должны быть цифрами: они должны быть просто уникальным текстом.

## 5.2 Структурированные данные для Web

Огромная популярность Всемирной паутины делает желательным иметь возможность представлять данные, подобные справочнику office, разработанному в предыдущем разделе, в форме, которая немного более причудлива, чем наш простой текстовый файл.

Веб-файлы в основном написаны на языке разметки, называемом HyperText Markup Language (HTML). Это семейство языков, которые являются конкретными экземплярами стандартного обобщенного языка разметки (SGML), который был определен в нескольких стандартах ISO с 1986 года. Рукопись этой книги была написана в формате DocBook/XML, который также является специфическим экземпляром SGML. Полное описание HTML вы можете найти в HTML & XHTML: The Definitive Guide (O'Reilly).\*

Для целей этого раздела нам понадобится лишь небольшая часть HTML, которую мы представим в небольшом руководстве. Если вы уже знакомы с HTML, просто просмотрите одну-две следующие страницы.

Вот HTML-файл, соответствующий минимальным стандартам, созданный с помощью полезного инструмента, написанного одним из нас:\*

```
$ echo Hello, world. | html-pretty
<!-- -*-html-*- -->
<!-- Prettyprinted by html-pretty flex version 1.01 [25-Aug-2001] -->
<!-- on Wed Jan 8 12:12:42 2003 -->
<!-- for Adrian W. Jones (jones@example.com) -->
<!DOCTYPE HTML PUBLIC "-//IETF//DTD HTML//EN">
<HTML>
   <HEAD>
       <TITLE>
           <!-- Please supply a descriptive title here -->
       </TITLE>
       <!-- Please supply a correct e-mail address here -->
         <LINK REV="made" HREF="mailto:jones@example.com">
  </HEAD>
  <BODY>
     Hello, world.
  </BODY>
</HTML>
```

В этом выводе HTML следует обратить внимание на следующие моменты::&#x20;

* &#x20;HTML-комментарии заключены в \<!--  и -- > .
* Специальные команды процессора заключены в \<! и >: здесь команда DOCTYPE сообщает синтаксическому анализатору SGML, к какому типу относится документ и где найти его грамматический файл.&#x20;
* Разметка задается словами, заключенными в угловые скобки, которые называются тегами. В HTML буквенный регистр не играет существенной роли в названиях тегов: html-обычно имена тегов пишутся в верхнем регистре для лучшей наглядности.&#x20;
* Среды разметки состоят из начального тега и конечного тега , и для многих тегов среды могут быть вложены друг в друга в соответствии с правила, определенные в грамматиках HTML.&#x20;
* &#x20;HTML-документ структурирован как HTML-объект, содержащий один объект HEAD и один объект BODY.&#x20;
* &#x20;Внутри HEAD объект TITLE определяет заголовок документа, который веб-браузеры отображают в строке заголовка окна и в списках закладок. Также внутри заголовка объект LINK обычно содержит информацию о разработчике веб-страницы.
* &#x20;Видимая часть документа, которую отображают браузеры, это текст заключенный в тег BODY.&#x20;
* &#x20;Пробелы не являются существенными за пределами строк, заключенных в кавычки, поэтому мы можем использовать горизонтальные и интервалы по вертикали, чтобы подчеркнуть структуру, как это делает HTML prettyprinter.&#x20;
* Все остальное - это просто текст в формате ASCII для печати, за тремя исключениями. Буквальные угловые скобки должны быть представлены специальными кодировками, называемыми сущностями, которые состоят из амперсанда, идентификатора и точки с запятой: `&lt; и &gt`;. Поскольку с амперсанда начинаются сущности, у него есть собственное буквальное название сущности: `&amp`. HTML поддерживает скромный набор сущностей для символов с ударением, которые охватывают большинство языков Западной Европы, так что мы можем написать, например, café du bon зайдите в café du bon goût.&#x20;
* &#x20;Хотя это и не показано в нашем минимальном примере, изменения стиля шрифта в HTML выполняются с помощью B (жирный шрифт), EM (выделение), I (курсив), STRONG (дополнительный жирный шрифт) и  TT (пишущая машинка (символы фиксированной ширины)): напишите фразу, выделенную жирным шрифтом, чтобы получить фразу, выделенную жирным шрифтом.&#x20;

Чтобы преобразовать наш офисный каталог в надлежащий HTML, нам нужна всего лишь еще одна информация: как отформатировать таблицу, поскольку это то, чем на самом деле является наш каталог, и мы не хотим использовать шрифты пишущей машинки, чтобы все было в порядке отображения в браузере.

В HTML 3.0 и более поздних версиях таблица состоит из табличной среды, внутри которой находятся строки, каждая из которых является средой строк таблицы (TR). Внутри каждой строки находятся ячейки, называемые табличными данными, каждая из которых является средой TD. Обратите внимание, что столбцы данных не получают специальной разметки: столбец данных - это просто набор ячеек, взятых из одной и той же позиции во всех строках таблицы. К счастью, нам не нужно заранее указывать количество строк и столбцов. Задача браузера или средства форматирования состоит в том, чтобы собрать все ячейки, определите самую широкую ячейку в каждом столбце, а затем отформатируйте таблицу так, чтобы столбцы были достаточно широкими, чтобы вместить эти самые широкие ячейки.

Для нашего примера с офисным справочником нам нужно всего три столбца, поэтому наша примерная запись может быть помечена следующим образом:

```bash
<TABLE>
 ...
   <TR>
     <TD>
       Jones, Adrian W.
     </TD>
     <TD>
       555-0123
     </TD>
     <TD>
       OSD211
     </TD>
   </TR>
   ...
</TABLE>
```

Эквивалентная, но компактная и трудночитаемая кодировка может выглядеть следующим образом:

```bash
<TABLE>
 ...
    <TR><TD>Jones, Adrian W.</TD><TD>555-0123</TD><TD>OSD211</TD></TR>
 ...
</TABLE>
```

Поскольку мы решили сохранить специальные разделители полей в текстовой версии справочника office, у нас достаточно информации для идентификации ячеек в каждой строке. Кроме того, поскольку пробелы в HTML-файлах, как правило, не играют существенной роли, нам не нужно особенно тщательно подбирать теги: если это понадобится позже, html-pretty прекрасно справится с этим. Наш фильтр преобразования состоит из трех этапов:

1. Выведите начальный шаблон вплоть до начала текста документа.
2. Оберните каждую строку справочника в табличную разметку.
3. Выведите конечный шаблон.

Мы должны внести одно небольшое изменение в наш минимальный пример: команда DOCTYPE должна быть обновлена до более позднего уровня грамматики, чтобы она выглядела следующим образом:

```bash
<!DOCTYPE HTML PUBLIC "-//IETF//DTD HTML//EN//3.0">
```

Вам не нужно запоминать это: в html-pretty есть опции для вывода на любом из стандартных уровней грамматики HTML, поэтому вы можете просто скопировать подходящую команду DOCTYPE из ее выходных данных.

Очевидно, что большая часть работы заключается в написании шаблонов, но это несложно, поскольку мы можем просто скопировать текст из минимального примера HTML. Единственный необходимый программный шаг средний, который мы могли бы выполнить, используя всего пару строк в awk. Однако мы можем добиться этого с еще меньшими затратами, используя замену в потоковом редакторе sed двумя командами редактирования: одна для замены встроенной табуляции, разделенной `</TD><TD>` , и следующая для переноса всей строки `<TR><TD> .. </TD></TR>`. Мы временно предполагаем , что в каталоге не требуются символы с ударением, но мы можем легко разрешить использование угловые скобки и амперсанды во входном потоке, добавив начальные шаги настройки. Мы собираем полную программу в примере 5-2.

```
Example 5-2. Converting an office directory to HTML
#! /bin/sh
# Convert a tab-separated value file to grammar-conformant HTML.
#
# Usage:
# tsv-to-html < infile > outfile
cat << EOFILE Leading boilerplate
<!DOCTYPE HTML PUBLIC "-//IETF//DTD HTML//EN//3.0">
<HTML>
  <HEAD>
     <TITLE>
        Office directory
     </TITLE>
     <LINK REV="made" HREF="mailto:$USER@`hostname`">
  </HEAD>
  <BODY>
  <TABLE>
EOFILE
sed -e 's=&=\&amp;=g' \                      Convert special characters to entities
    -e 's=<=\&lt;=g' \
    -e 's=>=\&gt;=g' \
    -e 's=\t=</TD><TD>=g' \ And supply table markup
    -e 's=^.*$= <TR><TD>&</TD></TR>='
cat << EOFILE                                                 Trailing boilerplate
 </TABLE>
 </BODY>
</HTML>
EOFILE
```

Запись << называется документом here. Более подробно она описана в разделе ”Дополнительные операторы перенаправления" \[7.3.1]. Вкратце, оболочка считывает все строки вплоть до разделителя, следующего за << (в данном случае EOFILE), выполняет замену переменных и команд в содержащихся строках и передает результаты в качестве стандартного ввода в команду.

В скрипте из примера 5-2 есть важный момент: он не зависит от количества столбцов в таблице! Это означает, что его можно использовать для преобразования любого файла значений, разделенных табуляцией, в HTML. Программы для работы с электронными таблицами обычно могут сохранять данные в таком формате, поэтому наш простой инструмент может создать правильный HTML-код из данных электронной таблицы.

При преобразовании csv в html мы постарались сохранить структуру интервалов в исходном каталоге office, поскольку это упрощает применение дополнительных фильтров в дальнейшем. Действительно, html-pretty был написан именно по этой причине: стандартизация HTML -разметки радикально упрощает другие инструменты HTML.

Как бы мы справились с преобразованием символов с ударением в HTML-объекты? Мы могли бы дополнить команду sed дополнительными шагами редактирования, такими как 's=é=é=g', но необходимо обработать около 100 объектов, и нам, вероятно, понадобятся аналогичные замены при преобразовании других типов текстовых файлов в HTML.

Поэтому имеет смысл делегировать эту задачу отдельной программе, которую мы можем использовать повторно, либо как этап конвейера, следующий за командой sed в примере 5-2, либо как фильтр , применяемый позже. (Это принцип “обходного пути для создания специализированных инструментов” в действии.) Такая программа представляет собой просто утомительную таблицу команд подстановки, и нам нужна одна для каждой из локальных кодировок текста, таких как различные кодовые страницы ISO 8859-n, упомянутые в разделе “Как называются файлы?” в приложении B. Мы не показываем здесь такой фильтр полностью, но приведем фрагмент из него. один из них в примере 5-3 дает понимание. Для читателей, которым это необходимо, мы предлагаем полную программу для обработки распространенного регистра западноевропейских символов в кодировке ISO 8859-1 вместе с примерами программ, приведенных в этой книге. Набор сущностей HTML недостаточен для других символов с ударением, но поскольку Всемирная паутина движется в направлении Unicode и XML вместо ASCII и HTML, эта проблема решается по-другому, путем устранения ограничений на набор символов.

```bash
#! /bin/sh
# Convert an input stream containing characters in ISO 8859-1
# encoding from the range 128..255 to HTML equivalents in ASCII.
# Characters 0..127 are preserved as normal ASCII.
#
# Usage:
# iso8859-1-to-html infile(s) >outfile
sed \
 -e 's= =\&nbsp;=g' \
 -e 's=¡=\&iexcl;=g' \
 -e 's=¢=\&cent;=g' \
 -e 's=£=\&pound;=g' \
...
 -e 's=ü=\&uuml;=g' \
 -e 's= =\&yacute;=g' \
 -e 's= =\&thorn;=g' \
 -e 's=ÿ=\&yuml;=g' \
 "$@
```

Вот пример использования этого фильтра:

<pre><code>$ cat danish                             Show sample Danish text in ISO 8859-1 encoding
Øen med åen lå i læ af én halvø,
og én stor ø, langs den græske kyst.
<strong>
</strong><strong>$ iso8859-1-to-html                             danish Convert text to HTML entities
</strong>&#x26;Oslash;en med &#x26;aring;en l&#x26;aring; i l&#x26;aelig; af &#x26;eacute;n halv&#x26;oslash;,
og &#x26;eacute;n stor &#x26;oslash;, langs den gr&#x26;aelig;ske kyst.
</code></pre>

## 5.3 Cheating at Word Puzzles

Кроссворды дают вам подсказки о словах, но большинство из нас застревает, когда не может придумать, скажем, слово из десяти букв, начинающееся с буквы "b ", в седьмой позиции которого стоит буква "x" или "z".

Очевидно, что требуется сопоставление шаблонов регулярных выражений с awk или grep, но в каких файлах мы ищем? Одним из хороших вариантов является орфографический словарь Unix, доступный во многих системах как /usr/dict/words. (Другими популярными расположениями для этого файла являются /usr/share/dict/words и /usr/share/lib/dict/words.) Это простой текстовый файл с одним словом в строке, отсортированный в лексикографическом порядке. Мы можем легко создать другие похожие файлы из любой коллекции текстовых файлов, например, этот:

```bash
cat file(s) | tr A-Z a-z | tr -c a-z\' '\n' | sort -u
```

Второй этап конвейера преобразует прописные буквы в строчные, третий заменяет небуквенные символы на новые строки, а последний сортирует результат, сохраняя только уникальные строки. Третий этап обрабатывает апострофы как буквы, поскольку они используются в сокращениях. В каждой системе Unix есть наборы текста, которые можно обработать таким образом — например, отформатированные страницы руководства в /usr/man/cat\*/\* и /usr/local/man/cat\*/_. В одной из наших систем они предоставили более 1 миллиона строк и составили список около 44 000 уникальных слов. В различных интернет-архивах также есть списки слов для десятков языков._

Давайте предположим, что мы создали коллекцию списков слов таким образом и сохранили их в стандартном месте, на которое мы можем ссылаться из скрипта. Затем мы можем написать программу, показанную в примере 5-4.

```bash
#! /bin/sh
# Match an egrep(1)-like pattern against a collection of
# word lists.
#
# Usage:
# puzzle-help egrep-pattern [word-list-files]
FILES="
 /usr/dict/words
 /usr/share/dict/words
 /usr/share/lib/dict/words
 /usr/local/share/dict/words.biology
 /usr/local/share/dict/words.chemistry
 /usr/local/share/dict/words.general
 /usr/local/share/dict/words.knuth
 /usr/local/share/dict/words.latin
 /usr/local/share/dict/words.manpages
 /usr/local/share/dict/words.mathematics
 /usr/local/share/dict/words.physics
 /usr/local/share/dict/words.roget
 /usr/local/share/dict/words.sciences
 /usr/local/share/dict/words.unix
 /usr/local/share/dict/words.webster
 "
pattern="$1"
egrep -h -i "$pattern" $FILES 2> /dev/null | sort -u -f
```

Переменная FILES содержит встроенный список файлов word-списка, настроенный для локального сайта. Параметр grep –h подавляет имена файлов из отчета, параметр –i игнорирует регистр букв, и мы отбрасываем стандартный вывод ошибки с помощью 2> /dev/null, в случае, если какой-либо из файлов списка слов не существует или у них нет необходимого разрешения на чтение. (Этот вид перенаправления описан в разделе “Манипулирование файловыми дескрипторами” \[7.3.2].) Заключительный этап сортировки сводит отчет к простому списку уникальных слов, игнорируя регистр букв.

Теперь мы можем найти то слово, которое искали:

```bash
$ puzzle-help '^b.....[xz]...$' | fmt
bamboozled Bamboozler bamboozles bdDenizens bdWheezing Belshazzar
botanizing Brontozoum Bucholzite bulldozing
```

Можете ли вы назвать английское слово с шестью согласными подряд? Вот небольшая справка:

```bash
 puzzle-help '[^aeiouy]{6}' /usr/dict/words
Knightsbridge
mightn't
oughtn't
```

Если вы не считаете y гласной, то появляется гораздо больше вариантов: encryption, klystron, porphyry, syzygy и так далее.

Мы могли бы легко исключить сокращения из списков слов с помощью последнего шага фильтрации — egrep -i '^\[a-z]+$', но нет ничего плохого в том, чтобы оставить их в списках слов.

## 5.4 Списки слов

С 1983 по 1987 год исследователь из Bell Labs Джон Бентли (Jon Bentley) вел интересную колонку в журнале Communications of the ACM под названием "Жемчужины программирования". Некоторые из статей были позже объединены, с существенными изменениями, в две книги, перечисленные в библиографии. В одной из колонок Бентли поставил такую задачу: написать программу для обработки текстового файла и вывести список из n наиболее часто встречающихся слов с указанием их частоты встречаемости, отсортированных по убыванию количества. Известный специалист по информатике Дональд Кнут а Дэвид Хэнсон ответил отдельно интересными и умными грамотными программами, на написание каждой из которых ушло несколько часов. Первоначальная спецификация Bentley была неточной, поэтому Хэнсон перефразировал ее следующим образом: учитывая текстовый файл и целое число n, вы должны напечатать слова (и их частоту встречаемости), частота встречаемости которых входит в число n самых больших в порядке убывания частоты.

В первой из статей Бентли, друг Бентли,  научный сотрудник лаборатории Дуг Макилрой пересмотрел программу Кнута, и предложил шестиступенчатое Unix-решение на разработку которого потребовалось всего несколько минут. Более того, в отличие от двух других программ, программа Макилроя лишена явных магических констант, которые ограничивают длину слов , количество уникальных слов и размер входного файла. Кроме того, его представление о том, что представляет собой слово, полностью определяется простыми шаблонами, приведенными в первых двух исполняемых инструкциях, что упрощает внесение изменений в алгоритм распознавания слов.

Программа Макилроя иллюстрирует мощь подхода Unix tools: разбейте сложную задачу на более простые части, с которыми вы уже знаете, как справиться. Чтобы решить проблему частотности слов, Макилрой преобразовал текстовый файл в список слов, по одному в строке (tr выполняет эту работу), сопоставил слова с одним регистром букв (снова tr), отсортировал список (sort), сократив его до списка уникальных слов с количеством (uniq), отсортировал этот список по убыванию количества элементов (sort) и, наконец, напечатал первые несколько записей в списке (sed, хотя head тоже сработал бы).

Результирующую программу назвали wf  и завернули в сценарий оболочки с заголовком комментария. Мы также расширили исходную команду McIlroy sed, сделав необязательным параметр длины выходного списка, и модернизировали параметры сортировки. Мы показываем полную программу в примере 5-5.

```
#! /bin/sh
# Read a text stream on standard input, and output a list of
# the n (default: 25) most frequently occurring words and
# their frequency counts, in order of descending counts, on
# standard output.
#
# Usage:
# wf [n]
tr -cs A-Za-z\' '\n' |                               Replace nonletters with newlines
 tr A-Z a-z |                                        Map uppercase to lowercase
 sort |                                              Sort the words in ascending order
 uniq -c |                                           Eliminate duplicates, showing their counts
 sort -k1,1nr -k2 |                                  Sort by descending count, and then by ascending word
 sed ${1:-25}q                                       Print only the first n (default: 25) lines; see Chapter 3
```

POSIX tr поддерживает все управляющие последовательности стандарта ISO C. Более старая версия X/Open Спецификация руководства по переносимости содержала только восьмеричные escape-последовательности, а в оригинальной tr их вообще не было, что заставляло переводить новую строку буквально, что было одним из критических замечаний, высказанных в адрес оригинальной программы Макилроя. К счастью, команда tr в каждой системе, которую мы тестировали, теперь содержит управляющие последовательности POSIX.

Конвейер shell - не единственный способ решить эту проблему с помощью инструментов Unix: в предыдущей статье Бентли представил шестистрочную awk-реализацию этой программы\*, которая примерно эквивалентна первым четырем этапам конвейера Макилроя.

Кнут и Хэнсон обсудили вычислительную сложность своих программ, и Хэнсон использовал профилирование во время выполнения для изучения нескольких вариантов своей программы, чтобы найти самый быстрый из них.

Сложность алгоритма Макилроя легко определить. Все этапы, кроме сортировки, выполняются за время , линейное по размеру вводимых данных, и этот размер обычно резко уменьшается после завершения этапа uniq. Таким образом, этап, ограничивающий скорость, - это первый этап сортировки. Хороший алгоритм сортировки , основанный на сравнениях, как в Unix sort, может отсортировать n элементов за время, пропорциональное $$n*log_2n$$. Коэффициент логарифмирования по основанию 2 невелик: для n, равного примерно 1 миллиону, он равен примерно 20. Таким образом, на практике мы ожидаем, что wf будет работать в несколько раз медленнее, чем потребовалось бы для простого копирования его входного потока с помощью cat.&#x20;

Вот пример применения этого скрипта к тексту самой популярной пьесы Шекспира "Гамлет",† переформатирование выходных данных с помощью pr для отображения в четырех столбцах.:

```bash
$ wf 12 < hamlet | pr -c4 -t -w80
 1148 the   671 of       550 a       451 in
 970 and    635 i        514 my      419 it
 771 to     554 you      494 hamlet  407 that
```

Результаты примерно такие, как и ожидалось для английской прозы. Пожалуй, интереснее спросить, сколько уникальных слов в пьесе:

```bash
$ wf 999999 < hamlet | wc -l
4548
```

и обратить внимание на некоторые из наименее часто встречающихся слов:

```bash
$ wf 999999 < hamlet | tail -n 12 | pr -c4 -t -w80
 1 yaw     1 yesterday    1 yielding  1 younger
 1 yawn    1 yesternight  1 yon       1 yourselves
 1 yeoman  1 yesty        1 yond      1 zone
```

В аргументе 999999 нет ничего волшебного: это просто должно быть число , превышающее любое ожидаемое количество уникальных слов, а функция повтора с клавиатуры упрощает ввод.

Мы также можем спросить, сколько из 4548 уникальных слов было использовано только один раз:

```bash
$ wf 999999 < hamlet | grep -c '^ *1•'
2634
```

Символ •, следующий за цифрой 1 в шаблоне grep, обозначает табуляцию. Этот результат удивителен и, вероятно, нетипичен для большинства произведений современной английской прозы: несмотря на большой словарный запас пьесы, почти 58 процентов слов встречаются только один раз. И все же основной словарный запас часто встречающихся слов довольно невелик:

```bash
$ wf 999999 < hamlet | awk '$1 >= 5' | wc -l
740
```

Речь идет о количестве слов, которые, как ожидается, студент должен будет выучить за семестровый курс иностранного языка или которые ребенок выучит перед поступлением в школу. У Шекспира не было компьютеров, которые помогли бы анализировать его произведения,\* но мы можем предположить, что часть его гениальности заключалась в том, что он сделал большую часть написанного понятной самой широкой аудитории своего времени.&#x20;

Когда мы применили wf к отдельным текстам пьес Шекспира, мы обнаружили, что У "Гамлета" самый большой словарный запас (4548 слов), в то время как у "Комедии ошибок" самый маленький (2443).&#x20;

Общее количество уникальных слов в собрании пьес и сонетов Шекспира составляет почти 23 700, что говорит о том, что вам нужно ознакомиться с несколькими пьесами, чтобы насладиться богатством его творчества. Около 36% этих слов употребляются только один раз, и только одно слово начинается на букву "x": "Xanthippe" в "Укрощении строптивой". Очевидно, что у Шекспира есть много материала для любителей разгадывать словесные головоломки и анализировать словарный запас!

## 5.5 Списки тегов

Использование команды tr для получения списков слов или, в более общем плане, для преобразования одного набора символов в другой, как в примере 5-5 в предыдущем разделе, - это удобная для запоминания идиома Unix-инструмента. Это естественным образом приводит к решению проблемы , с которой мы столкнулись при написании этой книги: как нам обеспечить согласованную разметку примерно 50 тысяч строк в файлах? Например, команда может быть помечена как \<command>tr\</command>, когда мы говорим о ней в текущем тексте, но в другом месте мы могли бы привести пример того, что вы вводите, обозначенный символом разметка \<literal>tr\</literal> . Третий вариант - это ссылка на страницу руководства в виде \<emphasis>tr\</emphasis>.

Программа taglist из примеров 5-6 предлагает решение. Она находит все пары начальных и конечных тегов , записанные в одной строке, и выводит отсортированный список, который связывает использование тегов с входными файлами. Кроме того, он помечает стрелкой случаи, когда одно и то же слово выделено несколькими способами. Вот фрагмент его выходных данных из файла для версии этой главы:

```
$ taglist ch05.xml
...
 2 cut    command     ch05.xml
 1 cut    emphasis    ch05.xml <----
...
 2 uniq   command     ch05.xml
 1 uniq   emphasis    ch05.xml <----
 1 vfstab filename    ch05.xml
...
```

Задача составления списка тегов достаточно сложна, и ее было бы довольно сложно выполнить на большинстве обычных языков программирования, даже на тех, которые имеют большие библиотеки классов, таких как C++ и Java, и даже если бы вы начали с программ Knuth или Hanson literate для решения несколько похожей проблемы с частотностью слов. Тем не менее, достаточно выполнить всего девять шагов в конвейере Unix с использованием уже знакомых инструментов.

Программа word-frequency не работала с именованными файлами: она просто использовала один поток данных. Это не является серьезным ограничением, поскольку мы можем легко передать ей несколько входных файлов с помощью cat. Однако здесь нам нужно имя файла, поскольку бесполезно сообщать о проблеме, не сообщая, в чем она заключается. Имя файла - это единственный аргумент taglist, доступный в скрипте как $1.

1. Мы отправляем входной файл в конвейер с помощью cat. Мы могли бы, конечно, исключить этот шаг, перенаправив ввод на следующем этапе с $1, но в сложных конвейерах мы обнаруживаем, что проще отделить создание данных от их обработки. Это также немного упрощает вставку еще одного этапа в конвейер, если программа впоследствии будет развиваться.&#x20;

```bash
cat "$1" | ...
```

2. Мы используем его для упрощения сложной разметки, необходимой для web URLs:

```bash
... | sed -e 's#systemitem *role="url"#URL#g' \
 -e 's#/systemitem#/URL#' | ...
```

Это преобразует такие теги, как \<systemitem role="URL"> и \</systemitem>, в более простые теги \<URL> и  \</URL> соответственно.

3. На следующем этапе используется tr для замены пробелов и парных разделителей новыми строками:

```
... | tr ' ( ){ }[ ]' '\n\n\n\n\n\n\n' | ...
```

4.  На этом этапе вводимые данные состоят из одного “слова” в строке (или пустых строках). Слова

    это либо текст, либо теги SGML/XML. На следующем этапе, используя egrep, выбираются слова, вложенные в тег:

```bash
... | egrep '>[^<>]+</' | ... <literal>tr</literal>
```

Это регулярное выражение соответствует словам, заключенным в тег: прямоугольная скобка, за которой следует, по крайней мере, одна не угловая скобка, за которой следует левая угловая скобка, за которой следует косая черта (для закрывающего тега).

5. На данный момент входные данные состоят из строк с тегами. На первом этапе awk в качестве разделителей полей используются угловые скобки, поэтому входные данные  literal>tr\</literal> разбиваются на четыре поля: пустое поле, за которым следуют literal, tr и /literal. Имя файла передается в awk из командной строки, где параметр –v присваивает переменной awk FILE значение filename. Затем эта переменная используется в инструкции print, которая выводит слово, тег и имя файла:

```bash
... | awk -F'[<>]' -v FILE="$1" \
 '{ printf("%-31s\t%-15s\t%s\n", $3, $2, FILE) }' | ...
```

6. На этапе сортировки строки сортируются в порядке слов:

```bash
... | sort | ...
```

7. Команда uniq предоставляет исходное поле count. Результатом является список записей, в котором используются следующие поля: count, word, tag, file:

```bash
... | uniq -c | ...
```

8. Вторая сортировка упорядочивает выходные данные по слову и тегу (второе и третье поля).:

```bash
... | sort -k2,2 -k3,3 | ...
```

На заключительном этапе используется небольшая awk-программа для фильтрации последовательных строк, добавляющая конечную стрелку, когда она видит то же слово, что и в предыдущей строке. Эта стрелка четко указывает на случаи, когда слова были выделены по-другому и , таким образом, заслуживают более тщательного изучения авторами, редакторами или персоналом, занимающимся выпуском книг:

```bash
... | awk '{
 print ($2 = = Last) ? ($0 " <----") : $0
 Last = $2
 }'
```

```bash
#! /bin/sh -
# Read an HTML/SGML/XML file given on the command
# line containing markup like <tag>word</tag> and output on
# standard output a tab-separated list of
#
# count word tag filename
#
# sorted by ascending word and tag.
#
# Usage:
# taglist xml-file
cat "$1" |
 sed -e 's#systemitem *role="url"#URL#g' -e 's#/systemitem#/URL#' |
  tr ' ( ){ }[ ]' '\n\n\n\n\n\n\n' |
   egrep '>[^<>]+</' |
    awk -F'[<>]' -v FILE="$1" \
     '{ printf("%-31s\t%-15s\t%s\n", $3, $2, FILE) }' |
    sort |
     uniq -c |
      sort -k2,2 -k3,3 |
       awk '{
        print ($2 = = Last) ? ($0 " <----") : $0
        Last = $2
       }
```

## 5.6 Краткое содержание&#x20;

В этой главе показано, как решить несколько задач обработки текста, ни одна из которых не была бы простой для большинства языков программирования. Важнейшие уроки этой главы таковы:&#x20;

* &#x20;Разметка данных чрезвычайно полезна, хотя и не обязательно должна быть сложной. Часто бывает достаточно одного уникального символа, такого как табуляция, двоеточие или запятая.&#x20;
* Конвейеры простых инструментов Unix и коротких, часто интерактивных, программ на подходящем языке обработки текста, таком как awk, могут использовать разметку данных для прохождения нескольких фрагментов данных через ряд этапов обработки, в результате чего получается полезный отчет.&#x20;
* &#x20;Благодаря простоте разметки данных выходные данные наших инструментов могут легко использоваться в новых инструментах, как показал наш небольшой анализ выходных данных фильтра частотности слов wf, примененного к текстам Шекспира.
* Сохранив минимальную разметку в выходных данных, мы сможем позже вернуться и доработать эти данные, как мы это сделали, чтобы превратить простой офисный каталог ASCII в веб-страницу. Действительно, разумно никогда не рассматривать какую-либо форму электронных данных как окончательную: в некоторых кругах растет спрос на языки описания страниц, такие как PCL, PDF и PostScript, для сохранения исходной разметки, которая привела к форматированию страницы. Документы в текстовом редакторе в настоящее время практически лишены полезной логической разметки, но в будущем это может измениться. В это время на момент написания этой статьи сообщалось, что один из известных поставщиков текстовых редакторов рассматривает возможность использования XML-представления для хранения документов. Электронная таблица gnumeric в рамках проекта GNU Project, проект документации Linux\* и OpenOffice.org† офисный пакет office уже поддерживают это.
* Строки с полями, разделенными разделителями, представляют собой удобный формат для обмена данными с более сложным программным обеспечением, таким как электронные таблицы и базы данных. Хотя такие системы обычно предлагают какую-то функцию создания отчетов, часто проще извлекать данные в виде потока строк полей, а затем применять фильтры, написанные на подходящих языках программирования, для дальнейшей обработки данных. Например, для создания каталогов и публикации в справочниках часто лучше всего использовать этот способ.
