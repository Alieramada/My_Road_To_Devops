# 9. DKMS

DKMS (поддержка динамических модулей ядра) была разработана компанией Dell в 2003 году. DKMS была создана как решение для борьбы с программными проблемами, вызванными зависимостями между ядрами и модулями ядра. Как поставщик компьютерных систем, работающих под управлением (среди прочего) операционных систем Linux, компания Dell предлагала клиентам поддержку программного обеспечения. Когда клиенты обновляли ядро Linux, необходимо было также обновить модули ядра. И всякий раз, когда Dell выпускала новые версии модулей ядра для аппаратной поддержки, эти модули должны были соответствовать используемому ядру Linux.

DKMS - это платформа, способная автоматически компилировать и/или устанавливать модули ядра для каждой версии ядра, доступной в системе. DKMS обеспечивает эту функциональность путем отделения файлов модулей ядра или исходных текстов от фактического дерева исходных текстов ядра. Таким образом, ядро и его модули могут обновляться независимо друг от друга. Основные дистрибутивы Linux предлагают платформу DKMS через свою систему пакетов. Когда ядро обновляется с помощью программного обеспечения для управления пакетами в системе при запуске DKMS программа-перехватчик позаботится о том, чтобы решить, нужно ли компилировать и/или устанавливать какие-либо модули ядра для нового ядра. И наоборот, новые модули ядра могут быть скомпилированы и/или установлены DKMS без требований к версии ядра.

У DKMS есть несколько требований для правильной работы. Зависимости программного обеспечения зависят от используемого дистрибутива Linux. Но одно требование, которое является единым для всех дистрибутивов, - это необходимость в заголовочных файлах ядра. Заголовки для запущенной версии ядра можно установить с помощью следующих команд менеджера пакетов:

В дистрибутивах Linux на базе Red Hat:

```bash
$ yum install kernel-devel
```

В дистрибутивах Linux на базе Debian:

```bash
$ apt install linux-headers-$(uname -r)
```

В связи с распространением DKMS среди основных дистрибутивов Linux, многие модули ядра, доступные через менеджеры пакетов , (также) доступны как DKMS-модули. В системах Linux на базе Debian эти модули ядра DKMS можно идентифицировать по их соглашению об именовании. Имена пакетов для этих файлов заканчиваются на -dkms . Например: oss4-dkms. После установки этих пакетов исходные файлы модулей ядра помещаются в соответствующий каталог /usr/src/module-version вместе с файлом dkms.conf. файл конфигурации. Всякий раз, когда изменение ядра или модуля ядра запускает систему DKMS, каталог, указанный переменной source\_tree из /etc/dkms/framework.conf, будет проверяться на наличие подкаталогов, содержащих файлы dkms.conf. Содержимое этих файлов dkms.conf затем определяет, что произойдет дальше. Следующий пример взят из приложения на базе Debian Системе Linux и следует пояснить это объяснение:

```bash
$ sudo apt-get install flashcache-dkms
 $ ls /usr/src/
 flashcache-3.1.1+git20140801 linux-headers-3.16.0-4-amd64 linux-headers-3.16.0-4-common linux-kbuild-3.16
 $ ls /usr/src/flashcache-3.1.1+git20140801/
 dkms.conf flashcache.h flashcache_ioctl.h flashcache_procfs.c flashcache_subr.c
 flashcache_conf.c flashcache_ioctl.c flashcache_main.c flashcache_reclaim.c Makefile
 $ cat /usr/src/flashcache-3.1.1+git20140801/dkms.conf
 BUILT_MODULE_NAME="flashcache"
 DEST_MODULE_LOCATION="/kernel/drivers/block"
 PACKAGE_NAME="flashcache"
 PACKAGE_VERSION="3.1.1+git20140801"
 AUTOINSTALL="yes"
 REMAKE_INITRD="yes"
 MAKE="COMMIT_REV=3.1.1+git20140801 KERNEL_TREE=$kernel_source_dir make modules"
```

BUILT\_MODULE\_NAME определяет имя скомпилированного модуля. Эта директива обязательна, если пакет DKMS-module содержит более одного модуля. DEST\_MODULE\_LOCATION определяет местоположение скомпилированного модуля. Значение для этой директивы всегда должно начинаться с "/kernel", которое, в свою очередь, перенаправляет на /lib/modules/kernelversion/kernel . Это значение является обязательным , за исключением следующих дистрибутивов Linux, которые используют определенный каталог дистрибутива: Fedora Core 6 и выше, RHEL 5 и более поздней версии, Novell SuSE Linux ES 10 и более поздней версии и Ubuntu. PACKAGE\_NAME определяет имя, связанное со всем пакетом модулей. Эта директива обязательна к исполнению. PACKAGE\_VERSION определяет версию, связанную со всем пакетом модулей , и является обязательной. AUTOINSTALL - это логическое значение, которое определяет, будет ли служба dkms\_autoinstaller пытаться установить этот модуль для каждого ядра, с которым загружается система. REMAKE\_INITRD определяет, следует ли генерировать исходный образ повторно после установки этого модуля. Значение этой директивы по умолчанию равно "no". При настройке значения помните, что все символы после первого символа отбрасываются. Первый символ интерпретируется только в том случае, если это "y" или "Y". MAKE - это одна из многих директив, значение которой сохраняется в массиве. Значение MAKE определяет параметры сборки. Если оно не определено, DKMS попытается собрать модуль с помощью универсальной команды MAKE.

В дистрибутивах Linux на базе Debian каталог /usr/share/doc/dkms/examples содержит файлы конфигурации с примерами. В системах Linux на базе Red Hat файлы с примерами можно найти в каталоге /usr/share/doc/dkms.

После создания модуля с помощью DKMS он становится частью расширяемой платформы. DKMS предоставляет несколько команд для работы с модулем. Описание всех этих команд выходит за рамки данной книги. Но, помимо man dkms, вам должна быть знакома команда dkms. Команда dkms позволяет добавлять или удалять модули в дерево исходных текстов или из него. Модули, которые являются частью дерева исходных текстов, могут быть созданы. После сборки модуль может быть установлен в ядро, для которого он был собран, с помощью опции install. удаление возвращает этот процесс вспять. Параметр status выводит информацию о добавленных модулях на стандартный вывод.

В приведенном выше примере используется модуль из менеджера пакетов. DKMS также поддерживает форматы архивов, содержащие двоичные модули, исходные тексты модулей или и то, и другое. При добавлении модулей в DKMS таким образом важно, чтобы в архиве также содержался допустимый файл dkms.conf. Используя команду dkms mktarball, такой архив может быть создан на основе модулей, извлеченных из текущей системы. Затем этот архив может быть импортирован в дерево исходных текстов с помощью команды dkms ldtarball.
