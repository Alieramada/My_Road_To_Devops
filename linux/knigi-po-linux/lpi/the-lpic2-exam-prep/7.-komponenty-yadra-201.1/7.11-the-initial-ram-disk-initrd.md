# 7.11 The initial ram disk ( initrd )

Допустим, на вашем загрузочном диске есть загрузчик, ядро и соответствующие модули. Учитывая преимущества модулей ядра, вы решили их использовать. Но если вы также хотите использовать их для драйверов загрузочных устройств, вы столкнетесь с проблемой. GRUB загрузит ядро, а затем выполнит его. Ядро попытается получить доступ к диску, чтобы получить модули. Однако, поскольку оно еще не загрузило нужный модуль, оно не может получить доступ к этому диску и зависает.

Идеальным решением было бы создать ядро с жестко запрограммированным в нем необходимым драйвером диска. Но если вам приходится обслуживать большее количество различных систем, вам либо потребуется индивидуальная конфигурация и ядро для каждого типа системы, либо придется работать с раздутым ядром. Чтобы обойти все эти проблемы, разработчики ядра придумали решение: initrd initial ram disk.

RAMdisk - это фрагмент памяти, который ядро воспринимает как диск. Его можно монтировать как любой другой диск. Ядро поддерживает RAM-диски по умолчанию. GRUB и LILO также могут работать с RAM-дисками. Вы можете поручить им загрузить RAM-диск из файла, и при загрузке ядра RAM-диск будет легко доступен. Такие RAM-диски часто используются для хранения сценариев и модулей , облегчающих процесс загрузки.

Обычно образ, содержащий исходный RAM-диск, называется initrd. Это сокращение от "начальный ram-диск".

Загрузчик загружает файл initrd, который монтируется ядром как корневая файловая система. После установки в качестве корневой файловой системы из него можно запускать программы и загружать модули ядра. После этого шага новая корневая файловая система может быть подключена с другого устройства. Предыдущая корневая файловая система (из initrd ) затем либо перемещается в каталог /initrd, либо размонтируется.

Существует несколько способов создать свой собственный файл initrd. Очень удобный метод, который в основном используется в дистрибутивах на базе Red Hat, заключается в использовании скрипта mkinitrd. Это сценарий оболочки, который вы, возможно, захотите проверить, чтобы увидеть, как он работает. В дистрибутивах на базе Debian для этой же цели можно использовать утилиту под названием mkinitramfs. Вы также можете создать файл вручную, см. главу ниже.

## 7.11.1 Создание **initrd** вручную

Файлы initrd представляют собой сжатые архивы, содержащие файлы минимальной корневой файловой системы. Эта корневая файловая система обычно содержит модули, скрипты и некоторые дополнительные двоичные файлы, необходимые для правильной загрузки ядра.

Как уже говорилось, скрипт mkinitrd предлагает удобный способ создания файла initrd, однако не все дистрибутивы предоставляют его. Если вы хотите (или должны) создать его вручную, выполните следующие действия: создайте корневую файловую систему, заполните ее модулями и файлами, создайте из нее архив tar или cpio и, наконец, распакуйте его в gzip.

Какой тип архива использовать, зависит от дистрибутива и версии ядра. В старых ядрах используется tar, в более новых - cpio. Если вы не уверены и у вас под рукой есть initrd, который поставляется с вашим дистрибутивом, вы можете использовать последовательность команд, подобную приведенной ниже, для проверки:

```bash
$ sudo zcat /boot/initrd-2.6.18-348.6.1.el5.img |file -
 /dev/stdin: ASCII cpio archive (SVR4 with no CRC)
```

В приведенном выше примере показаны выходные данные дистрибутива CentOS 5, использующего cpio в качестве средства архивации.

Чтобы иметь возможность работать с образами initrd, ядро должно быть скомпилировано с поддержкой RAM-диска и сконфигурировано таким образом, чтобы оно могло его использовать. Что бы вы ни поместили на исходный RAM-диск, оно должно быть совместимо с ядром и архитектурой, которые вы будете использовать. Например, ваше загрузочное ядро должно уметь распознавать тип файловой системы, используемый в образе, а включаемые вами модули должны соответствовать версии загрузочного ядра.

Следующим шагом будет собственно создание образа RAMdisk. Сначала создайте файловую систему на блочном устройстве, а затем скопируйте файлы в эту файловую систему по мере необходимости. Для этой цели подходят следующие блочные устройства:

1. RAM disk (быстрый, выделяет физическую память)
2. Loopback device (немного медленнее, выделяет место на диске)

В оставшейся части этого примера мы будем использовать метод RAMdisk, поэтому нам нужно будет убедиться в наличии узла устройства RAM-диска (их может быть несколько).:

```bash
# ls -la /dev/ram0
 brw-rw---- 1 root disk 1, 0 Feb 13 00:18 /dev/ram0
```

{% hint style="info" %}
Обратите внимание, что количество дисков оперативной памяти, доступное в системе по умолчанию, определяется параметром конфигурации ядра: CONFIG\_BLK\_DEV\_RAM\_COUNT
{% endhint %}

Затем необходимо создать пустую файловую систему соответствующего размера:

```bash
 # mke2fs -m0 /dev/ram0 300
```

{% hint style="info" %}
Если вам не хватает места, возможно, вы захотите использовать файловую систему, которая более эффективно использует пространство, например Minix FS. Помните , что загрузочному ядру потребуется встроенная поддержка любой файловой системы, которую вы выберете.
{% endhint %}

После создания файловой системы вам необходимо смонтировать ее в соответствующем каталоге:

```bash
# mount -t ext2 /dev/ram0 /mnt
```

Теперь необходимо создать заглушку для консольного устройства. Это будет узел устройства, который будет использоваться при активном initrd.

```bash
# mkdir /mnt/dev
# mknod /mnt/dev/tty1 c 4 1
```

Затем скопируйте в образ все файлы, которые, по вашему мнению, необходимы; модули, скрипты, двоичные файлы - не имеет значения. Одним из наиболее важных файлов для копирования является /linuxrc . Всякий раз, когда ядро настроено на использование образа initrd, оно будет искать файл /linuxrc и запускать его. Это может быть скрипт или скомпилированный двоичный файл. Следовательно, то, что произойдет после монтирования вашего файла образа, полностью находится под вашим контролем. В этом примере мы сделаем /linuxrc ссылкой на /bin/sh . Убедитесь, что у /linuxrc есть разрешения на выполнение.

```bash
# ln -s /bin/sh /mnt/linuxrc
```

После того как вы завершите копирование файлов и убедитесь, что файл /linuxrc имеет правильные атрибуты, вы можете размонтировать образ RAM-диска:

```bash
# umount /dev/ram0
```

Затем образ RAM-диска можно скопировать в файл:

```bash
# dd if=/dev/ram0 bs=1k count=300 of=/boot/initrd
```

Наконец, если вам больше не нужен RAM-диск и вы хотите освободить память, освободите RAM-диск:

```bash
# freeramdisk /dev/ram0
```

Чтобы протестировать только что созданный initrd, добавьте в свой файл меню GRUB новый раздел, который ссылается на только что созданный вами образ initrd :

```bash
title=initrd test entry
 root (hd0,0)
 kernel /vmlinuz-2.6.28
 initrd /initrd
```

Если вы выполнили описанные выше действия и перезагрузились, используя эту тестовую запись в меню загрузчика, система продолжит загрузку. Через несколько секунд вы должны оказаться в командной строке, поскольку /linuxrc ссылается на /bin/sh, оболочку.&#x20;

Конечно, реальные файлы initrd будут содержать более сложный загрузочный файл /linuxrc, который загружает модули, монтирует реальную корневую файловую систему и т.д.
