# 7.3 Обзор схем нумерации ядер и исправлений

Схемы нумерации, используемые для ядер Linux, за прошедшие годы менялись несколько раз: первоначальная схема, действующая для всех ядер вплоть до версии 2.6.0, схема для ядер версии 2.6.0 до версии 3.0, предыдущая схема для ядер 3.0 и более поздних версий и текущая схема, начиная с версии 4.0. В следующих разделах мы обсудим каждую из них.

## 7.3.1 Схема до ядер версии 2.6.0

Изначально номер версии ядра состоял из трех частей: номер основного выпуска, номер дополнительного выпуска и уровень исправления, разделенных точками.&#x20;

Основной выпуск увеличивался при внесении существенных изменений в ядро.&#x20;

Дополнительный выпуск увеличивался при внесении значительных изменений и дополнений. Младшие версии с четными номерами, например, 2.2, 2.4, считались стабильными, а нечетные номера, например, 2.1, 2.3, 2.5, считались выпусками для разработки. В основном они использовались разработчиками ядра и людьми, которые предпочитали передовые функциональные возможности, рискуя получить нестабильность.&#x20;

Последняя часть номера версии ядра указывала на уровень исправления. По мере исправления ошибок в коде (и/или добавления новых функций) уровень исправления увеличивался. Ядро следует обновлять до более высокого уровня исправлений только в том случае, если текущее ядро имеет проблемы с функциональностью или безопасностью.

## 7.3.2 Версии ядра, начиная с версии ядра 2.6.0 и вплоть до версии 3.0

В 2004 году, после выхода версии 2.6.0, система нумерации версий была изменена, и было решено ввести временной цикл выпуска . В течение следующих семи лет ядро оставалось на уровне 2.6, а третье число увеличивалось с каждым новым выпуском (что происходило каждые два-три месяца). Четвертое число было добавлено для учета исправлений ошибок и безопасности. Примером такой схемы является ядро 2.6.32.71. Четно-нечетная система нумерации больше не использовалась.

## 7.3.3 Изменение версий ядра с версии 3.0  до  4.0

29 мая 2011 года Линус Торвальдс объявил о выпуске версии ядра 3.0.0 в честь 20-летия Linux. Это еще раз изменило схему нумерации. Это все равно будет система выпуска, основанная на времени, но вторая цифра будет указывать на номер выпуска, а третья - на номер исправления. Для тестовых выпусков используется обозначение -rc. Следуя этой схеме, 3.2.84 будет ссылаться на стабильную версию ядра. 3.2-rc4, с другой стороны, будет указывать на четвертый релиз-кандидат ядра 3.2.

## 7.3.4 Версии ядра с 4.0

В апреле 2015 года была выпущена версия ядра 4.0.0. На этот раз система управления версиями не изменилась. На момент написания этой статьи версия ядра 6.13.4 является последней стабильной версией, доступной через https://kernel.org. Однако в ядре 4.x появилось несколько новых функций. Одной из наиболее примечательных является возможность выполнения "оперативного исправления". Оперативное исправление предоставляет возможность устанавливать исправления ядра без необходимости перезагрузки системы. Это может быть достигнуто путем выгрузки и загрузки соответствующих модулей ядра. Каждый раз, когда выходит новая версия ядра Linux, она сопровождается списком изменений. Эти файлы журнала изменений содержат подробную информацию о том, что изменилось в этом выпуске по сравнению с предыдущими версиями.

## 7.3.5 Сжатие XZ

Каждый дистрибутив Linux поставляется с ядром, которое было сконфигурировано и скомпилировано разработчиками дистрибутива. Большинство дистрибутивов Linux также предоставляют возможности для обновления двоичного файла ядра с помощью какой-либо системы пакетов. Однако также возможно скомпилировать ядро для вашей системы, используя исходные тексты ядра с вышеупомянутого веб-сайта kernel.org. Эти исходные тексты ядра упакованы с использованием tar и сжаты с использованием метода сжатия XZ. XZ является преемником LZMA и LZMA2. В последних версиях ядер Linux предусмотрена встроенная поддержка XZ. В зависимости от используемого дистрибутива Linux может потребоваться установка xz-utils или аналогичного пакета для распаковки файлов, сжатых в формате xz. После загрузки исходных текстов ядра для одного из доступных ядер в виде архива tar.xz эти исходные файлы можно распаковать с помощью следующей командной строки:

```bash
$ tar xvf linux-4.10-rc3.tar.xz
```

{% hint style="info" %}
Для работы приведенной выше команды GNU tar должен быть как минимум версии 1.22
{% endhint %}
