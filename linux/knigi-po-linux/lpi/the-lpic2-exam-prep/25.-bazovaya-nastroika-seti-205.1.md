### ifconfig

Хотя `ifconfig` считается **устаревшим** (вместо него рекомендуется `ip` из пакета `iproute2`), он до сих пор используется в некоторых системах и остается частью экзаменов&#x20;

Команда ifconfig используется для отображения текущей информации о конфигурации сети, настройки IP-адреса, маски подсети или широковещательного адреса для сетевого интерфейса, создания псевдонима для сетевого интерфейса, настройки аппаратного адреса и включения или отключения сетевых интерфейсов.

### **Cопоставление нескольких IP-адресов с одной сетевой картой:**

При настройке сети системы мы обычно назначаем один IP-адрес на каждый сетевой интерфейс (NIC). Он служит основным адресом. Но в некоторых ситуациях может потребоваться установить несколько IP-адресов на компьютере. Хорошая новость в том, что нам не нужен один NIC на каждый IP-адрес. Linux позволяет сопоставлять несколько IP-адресов с одним NIC с помощью псевдонимов IP-адресов

#### **Синтаксис добавления Alias-интерфейсов**

```bash
# Основной IP (eth0)
ifconfig eth0 192.168.1.100 netmask 255.255.255.0 up

# Дополнительные IP (из той же подсети)
ifconfig eth0:0 192.168.1.101 netmask 255.255.255.0 up

# IP из другой подсети (например, 10.0.0.0/24)
ifconfig eth0:1 10.0.0.100 netmask 255.255.255.0 up
```

#### **Проверка назначенных адресов**

```bash
ifconfig -a | grep eth0
```

Вывод:

```bash
eth0      Link encap:Ethernet  HWaddr 08:00:27:4a:12:34  
          inet addr:192.168.1.100  Bcast:192.168.1.255  Mask:255.255.255.0
eth0:0    Link encap:Ethernet  HWaddr 08:00:27:4a:12:34  
          inet addr:192.168.1.101  Bcast:192.168.1.255  Mask:255.255.255.0
eth0:1    Link encap:Ethernet  HWaddr 08:00:27:4a:12:34  
          inet addr:10.0.0.100  Bcast:10.0.0.255  Mask:255.255.255.0
```

### **Неразборчивый режим** Promiscuous Mode <a href="#promiscuous-mode" id="promiscuous-mode"></a>

В обычном режиме, когда сетевая карта получает пакет, она проверяет, принадлежит ли он ей. Если нет, она отбрасывает пакет в обычном режиме, но в Promiscuous Mode режиме принимает все пакеты, проходящие через сетевую карту.

```
sudo ifconfig eth0 promisc  # Включить режим promisc
sudo ifconfig eth0 -promisc # Выключить режим promisc
```

**MTU**

Аргумент mtu устанавливает максимальный размер передаваемого пакета для интерфейса. MTU позволяет установить предельный размер пакетов, передаваемых по интерфейсу. MTU позволяет обрабатывать максимальное количество октетов на интерфейсе за одну транзакцию. Не все сетевые интерфейсы поддерживают настройку MTU.

<figure><img src="../../../../.gitbook/assets/image (4) (1).png" alt=""><figcaption></figcaption></figure>

Настройка MTU важна для:

* Оптимизации производительности сети.
* Решения проблем с фрагментацией пакетов (например, в VPN, PPPoE, IPv6).
* Поддержки jumbo frames (гигабитные сети).

```bash
sudo ifconfig eth0 mtu 9000   # Установка MTU 9000 (jumbo frames)
```

**Добавление маршрута**

Через шлюз (Gateway)

```bash
sudo route add -net 10.0.0.0 netmask 255.255.255.0 gw 192.168.1.1 eth0
```

Прямой маршрут (без шлюза)

```
sudo route add -net 192.168.2.0 netmask 255.255.255.0 dev eth0
```

Маршрут по умолчанию (default gateway)

```
sudo route add default gw 192.168.1.1 eth0
```

Удаление маршрута

```
sudo route del -net 10.0.0.0 netmask 255.255.255.0
sudo route del default gw 192.168.1.1
```

### arp <a href="#arp" id="arp"></a>

![](https://borosan.gitbook.io/~gitbook/image?url=https%3A%2F%2F2787151686-files.gitbook.io%2F%7E%2Ffiles%2Fv0%2Fb%2Fgitbook-legacy-files%2Fo%2Fassets%252F-LqAGY8p7AfWa13f3JeS%252F-LqAGZA_6YfLR1j9u-KK%252F-LqAG_JXvXodVWa7bldQ%252Flookup.jpg%3Fgeneration%3D1569999708149253%26alt%3Dmedia\&width=300\&dpr=4\&quality=100\&sign=971649ad\&sv=2)

В сетевой модели ISO есть семь уровней. Интернет-протокол — это протокол третьего уровня, а сетевая карта — это устройство второго уровня. В локальной сети (второй уровень) устройства узнают друг друга по MAC-адресу (Media Access Control). В IP-сети (третий уровень) устройства узнают друг друга по IP-адресу.

Для передачи данных с уровня 3 на уровень 2 и обратно требуется протокол для сопоставления между уровнями 2 и 3. Этот протокол известен как ARP — протокол разрешения адресов. ARP создаёт сопоставление между IP-адресом и MAC-адресом, на котором настроен IP-адрес.

Когда устройства с поддержкой IP хотят обменяться данными, ядро исходного устройства передаёт IP-пакет программному обеспечению драйвера сетевого интерфейса и запрашивает доставку IP-пакета получателю. Единственный способ обмена данными в локальной сети Ethernet — с помощью MAC-адреса, IP-адреса там бесполезны. Чтобы узнать MAC-адрес получателя с соответствующим IP-адресом, сетевой драйвер интерфейса на стороне источника отправляет запрос ARP. Запрос ARP — это широковещательный запрос: он отправляется на любой компьютер в локальной сети. Компьютер, у которого есть запрошенный IP-адрес, теперь ответит своим MAC-адресом. После этого отправитель получит всю необходимую информацию для передачи пакета. Кроме того, MAC- и IP-адреса сохраняются в локальном кэше для дальнейшего использования.

```
pirog@pirog:~$ arp -help
Usage:
  arp [-vn]  [<HW>] [-i <if>] [-a] [<hostname>]             <-Display ARP cache
  arp [-v]          [-i <if>] -d  <host> [pub]               <-Delete ARP entry
  arp [-vnD] [<HW>] [-i <if>] -f  [<filename>]            <-Add entry from file
  arp [-v]   [<HW>] [-i <if>] -s  <host> <hwaddr> [temp]            <-Add entry
  arp [-v]   [<HW>] [-i <if>] -Ds <host> <if> [netmask <nm>] pub          <-''-

        -a                       display (all) hosts in alternative (BSD) style
        -e                       display (all) hosts in default (Linux) style
        -s, --set                set a new ARP entry
        -d, --delete             delete a specified entry
        -v, --verbose            be verbose
        -n, --numeric            don't resolve names
        -i, --device             specify network interface (e.g. eth0)
        -D, --use-device         read <hwaddr> from given device
        -A, -p, --protocol       specify protocol family
        -f, --file               read new entries from file or from /etc/ethers

  <HW>=Use '-H <hw>' to specify hardware address type. Default: ether
  List of possible hardware types (which support ARP):
    ash (Ash) ether (Ethernet) ax25 (AMPR AX.25) 
    netrom (AMPR NET/ROM) rose (AMPR ROSE) arcnet (ARCnet) 
    dlci (Frame Relay DLCI) fddi (Fiber Distributed Data Interface) hippi (HIPPI) 
    irda (IrLAP) x25 (generic X.25) eui64 (Generic EUI-64) 

```

основные опции команды `arp`

| **Опция** | **Пример**                              | **Описание**                                               |
| --------- | --------------------------------------- | ---------------------------------------------------------- |
| `-n`      | `arp -n`                                | Показать ARP-таблицу **без DNS-резолвинга** (только IP).   |
| `-a`      | `arp -a`                                | Показать ARP-таблицу **с именами хостов** (если доступно). |
| `-s`      | `arp -s 192.168.1.50 aa:bb:cc:dd:ee:ff` | **Добавить статическую запись** (IP → MAC).                |
| `-d`      | `arp -d 192.168.1.50`                   | **Удалить запись** из ARP-таблицы.                         |
| `-v`      | `arp -v`                                | **Подробный вывод** (флаги, интерфейсы).                   |
| `-i`      | `arp -i eth0`                           | Показать записи только для интерфейса **eth0**.            |

### **ip**

команда ifconfig устарела и заменена командой ip. Команда ip может отображать информацию о маршрутизации, устройствах, политике маршрутизации и туннелях, а также управлять ими.

#### **`ip` в Linux**

| **Функция**                                | **Команда (`ifconfig`)**                                       | **Команда (`ip` из `iproute2`)**                               | **Примечания**                                                                     |
| ------------------------------------------ | -------------------------------------------------------------- | -------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| **Просмотр интерфейсов**                   | `ifconfig`                                                     | `ip link show`                                                 | `ip` показывает больше деталей (включая MAC, состояние, MTU).                      |
| **Включение/выключение интерфейса**        | `ifconfig eth0 up` / `ifconfig eth0 down`                      | `ip link set eth0 up` / `ip link set eth0 down`                | Одинаково работают, но `ip` — современный стандарт.                                |
| **Назначение IP-адреса**                   | `ifconfig eth0 192.168.1.100 netmask 255.255.255.0`            | `ip addr add 192.168.1.100/24 dev eth0`                        | `ip` использует CIDR-нотацию (`/24` вместо `netmask 255.255.255.0`).               |
| **Добавление нескольких IP на интерфейс**  | `ifconfig eth0:0 192.168.1.101` (Alias)                        | `ip addr add 192.168.1.101/24 dev eth0`                        | `ip` не требует создания Alias-интерфейсов, поддерживает метки (`label eth0:web`). |
| **Просмотр IP-адресов**                    | `ifconfig eth0`                                                | `ip addr show eth0`                                            | `ip` показывает IPv4 и IPv6 в одном выводе.                                        |
| **Изменение MAC-адреса**                   | `ifconfig eth0 hw ether 00:11:22:33:44:55`                     | `ip link set eth0 address 00:11:22:33:44:55`                   | Оба метода временные (для постоянной настройки правьте конфиги).                   |
| **Promiscuous Mode (неразборчивый режим)** | `ifconfig eth0 promisc` / `ifconfig eth0 -promisc`             | `ip link set eth0 promisc on` / `ip link set eth0 promisc off` | Используется для сниффинга трафика (Wireshark, tcpdump).                           |
| **Настройка MTU**                          | `ifconfig eth0 mtu 9000`                                       | `ip link set eth0 mtu 9000`                                    | `ip` поддерживает jumbo frames (MTU 9000) так же, как и `ifconfig`.                |
| **Просмотр маршрутов**                     | `route -n`                                                     | `ip route show`                                                | `route` устарел, `ip route` — современный аналог.                                  |
| **Добавление маршрута**                    | `route add -net 10.0.0.0 netmask 255.255.255.0 gw 192.168.1.1` | `ip route add 10.0.0.0/24 via 192.168.1.1`                     | `ip` использует CIDR (`/24`) вместо `netmask`.                                     |
| **Удаление маршрута**                      | `route del -net 10.0.0.0`                                      | `ip route del 10.0.0.0/24`                                     | `ip route` более точен при удалении.                                               |
| **Default Gateway (шлюз по умолчанию)**    | `route add default gw 192.168.1.1`                             | `ip route add default via 192.168.1.1`                         | Одинаково работают, но `ip` — предпочтительный вариант.                            |

### **Команды для управления Wi-Fi в Linux: `iw`, `iwconfig`, `iwlist`**

Эти утилиты используются для настройки и диагностики беспроводных сетей (Wi-Fi).\
**Сравнение и основные функции:**

| Утилита                     | Назначение                                         | Примеры команд                                                                             | Примечания                                        |
| --------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------- |
| **`iw`** (современная)      | Управление беспроводными интерфейсами (802.11)     | <p><code>iw dev wlan0 scan</code><br><code>iw wlan0 set power_save off</code></p>          | Рекомендуется для новых систем (часть `iproute2`) |
| **`iwconfig`** (устаревшая) | Базовая настройка Wi-Fi (ESSID, мощность, частота) | <p><code>iwconfig wlan0 essid "MyWiFi"</code><br><code>iwconfig wlan0 channel 6</code></p> | Устарела, но полезна для простых задач            |
| **`iwlist`**                | Детальное сканирование Wi-Fi (частоты, шифрование) | <p><code>iwlist wlan0 scan</code><br><code>iwlist wlan0 freq</code></p>                    | Показывает больше информации, чем `iw`            |

***

### **`iw` (Рекомендуемый инструмент)**

**Основные команды:**



```
iw dev                         # Список беспроводных интерфейсов
iw dev wlan0 scan              # Сканировать сети
iw dev wlan0 connect "MyWiFi"  # Подключиться к сети (с паролем через `wpa_supplicant`)
iw dev wlan0 set txpower 20mBm # Установить мощность передачи
iw dev wlan0 link              # Показать статус подключения
```

***

### **`iwconfig` (Устаревший аналог)**

**Примеры:**

bashCopy

```
iwconfig wlan0 essid "MyWiFi"  # Установить SSID
iwconfig wlan0 key s:password  # Пароль (небезопасно!)
iwconfig wlan0 mode managed    # Режим (managed/ad-hoc)
iwconfig wlan0 channel 6       # Выбрать канал
iwconfig wlan0 txpower 15      # Мощность (в dBm)
```

***

#### **`iwlist` (Детальная информация)**

**Полезные команды:**

bashCopy

```
iwlist wlan0 scan              # Сканировать с детализацией (ESSID, каналы, шифрование)
iwlist wlan0 freq              # Доступные частоты

```



### **Настройка сети в Linux (2024) с сохранением параметров**

### **Netplan (Ubuntu/Debian)**

**Конфигурация:** YAML-файлы в `/etc/netplan/`

**Пример статического IP (`01-netcfg.yaml`):**

yamlCopy

```
network:
  version: 2
  renderer: networkd
  ethernets:
    eth0:
      addresses:
        - 192.168.1.100/24
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses: [8.8.8.8, 1.1.1.1]
```

**Пример DHCP:**

```
network:
  version: 2
  renderer: networkd
  ethernets:
    eth0:
      dhcp4: true
```

**Применить настройки:**

```
sudo netplan apply
```

***

### **NetworkManager (RHEL/Fedora/CentOS)**

**Управление через `nmcli/nmtui`:**

**Статический IP:**

```
sudo nmcli con add con-name "my-lan" ifname eth0 type ethernet \
  ip4 192.168.1.100/24 gw4 192.168.1.1
sudo nmcli con mod "my-lan" ipv4.dns "8.8.8.8 1.1.1.1"
sudo nmcli con up "my-lan"
```

**DHCP:**

```
sudo nmcli con add con-name "my-dhcp" ifname eth0 type ethernet
```

**Просмотр подключений:**

```
nmcli con show
```

***

### **Systemd-networkd (Универсальное решение)**

**Конфигурация в `/etc/systemd/network/`**

**Статический IP (`10-eth0.network`):**

```
[Match]
Name=eth0

[Network]
Address=192.168.1.100/24
Gateway=192.168.1.1
DNS=8.8.8.8
```

**DHCP (`10-eth0.network`):**

```
[Match]
Name=eth0

[Network]
DHCP=yes
```

**Активировать:**

```
sudo systemctl restart systemd-networkd
```

### **Приоритеты конфигурации между systemd-networkd, NetworkManager (nmcli) и Netplan**

В современных Linux-дистрибутивах могут одновременно присутствовать несколько систем управления сетью. Важно понимать, как они взаимодействуют и какие конфиги имеют приоритет.

***

#### **Иерархия управления сетью**

Уровни конфигурации (от высшего к низшему):

1. **NetworkManager (nmcli/nmtui)**
   * Управляет интерфейсами, если они не исключены явно
   * Конфиги: `/etc/NetworkManager/`
   * CLI: `nmcli`, `nmtui`
2. **Netplan (YAML-конфиги)**
   * Генерирует конфиги для systemd-networkd/NetworkManager
   * Конфиги: `/etc/netplan/`
   * Рендереры: `networkd` или `NetworkManager`
3. **systemd-networkd**
   * Работает с интерфейсами, не управляемыми NetworkManager
   * Конфиги: `/etc/systemd/network/`

***

#### **Таблица приоритетов конфигов**

| Компонент            | Путь к конфигам                                                                                         | Приоритет | Условия применения                      |
| -------------------- | ------------------------------------------------------------------------------------------------------- | --------- | --------------------------------------- |
| **Netplan**          | `/etc/netplan/*.yaml`                                                                                   | Высший    | Преобразуется в настройки networkd/NM   |
| **NetworkManager**   | <p><code>/etc/NetworkManager/conf.d/</code><br><code>/etc/NetworkManager/system-connections/</code></p> | Средний   | Если интерфейс не в "unmanaged-devices" |
| **systemd-networkd** | `/etc/systemd/network/*.network`                                                                        | Низший    | Только для интерфейсов без NM           |

***

#### **Как они взаимодействуют?**

#### **Сценарий 1: Netplan + NetworkManager**

```bash
# /etc/netplan/01-config.yaml
network:
  version: 2
  renderer: NetworkManager
```

* Netplan передает управление NetworkManager
* Все настройки делаются через `nmcli`/`nmtui`
* systemd-networkd не участвует

#### **Сценарий 2: Netplan + systemd-networkd**

```bash
# /etc/netplan/01-config.yaml
network:
  version: 2
  renderer: networkd
```

* Netplan генерирует конфиги в `/run/systemd/network/`
* NetworkManager автоматически исключает эти интерфейсы
* Управление через файлы в `/etc/systemd/network/`

#### &#x20;**Ручная настройка (без Netplan)**

* NetworkManager управляет всеми интерфейсами по умолчанию
*   Чтобы передать интерфейс systemd-networkd:



    ```bash
    # /etc/NetworkManager/conf.d/unmanaged.conf
    [keyfile]
    unmanaged-devices=interface-name:eth0
    ```

***

**Практические рекомендации**

**Для серверов (рекомендуется)**

1. Использовать **Netplan + systemd-networkd**
2. Конфиги хранить в `/etc/netplan/`
3.  Отключить NetworkManager:

    bashCopy

    ```
    sudo systemctl stop NetworkManager
    sudo systemctl disable NetworkManager
    ```

**Для рабочих станций**

1. Использовать **Netplan + NetworkManager**
2. Настройки делать через `nmcli`/`nmtui`
3.  Netplan-конфиг должен содержать:

    yamlCopy

    ```
    renderer: NetworkManager
    ```

#### **Как проверить текущее управление**

```
# Для systemd-networkd
networkctl list

# Для NetworkManager
nmcli device status
```

***

**Пример конфликта и решения**

**Проблема**:\
Интерфейс `eth0` не поднимается, так как:

* Netplan настроил его для systemd-networkd
* Но NetworkManager тоже пытается им управлять

**Решение**:

1.  Либо добавить в NetworkManager:

    ```
    [keyfile]
    unmanaged-devices=interface-name:eth0
    ```
2. Либо полностью отключить NetworkManager на сервере

***

| Ситуация               | Рекомендуемая связка              | Конфигурация              |
| ---------------------- | --------------------------------- | ------------------------- |
| Сервер (Ubuntu/Debian) | Netplan → systemd-networkd        | `/etc/netplan/*.yaml`     |
| Рабочая станция (GUI)  | Netplan → NetworkManager          | `nmcli` + `/etc/netplan/` |
| Минимальная система    | Прямая настройка systemd-networkd | `/etc/systemd/network/`   |
