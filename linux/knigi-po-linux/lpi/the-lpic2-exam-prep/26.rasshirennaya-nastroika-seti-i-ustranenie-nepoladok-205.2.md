### ethtool

#### **ethtool**

Утилита для настройки и диагностики сетевых интерфейсов в Linux. Позволяет просматривать параметры оборудования, статистику, настраивать скорость, режимы работы, аппаратные функции и многое другое.

#### **Основные возможности**

#### **Информация о сетевом интерфейсе**:

* Драйвер, версия, firmware.
* Поддерживаемые скорости и режимы (дуплекс, автосогласование).
* Статус соединения (активно/неактивно).

**Статистика**:

* Количество принятых/отправленных пакетов.
* Ошибки, коллизии, переполнения буферов.

**Настройка параметров**:

* Скорость и дуплекс.
* Размеры кольцевых буферов (RX/TX).
* Параметры аппаратного ускорения (offload).
* Управление потоком (Flow Control).
* Настройка прерываний (Coalesce).

**Диагностика**:

* Проверка поддержки функций (например, PTP).
* Тестирование кабеля (для некоторых устройств).

\


| **Ключ**                      | **Описание**                                                       | **Пример команды**                      |
| ----------------------------- | ------------------------------------------------------------------ | --------------------------------------- |
| `ethtool <интерфейс>`         | Показать базовую информацию (скорость, дуплекс, автосогласование). | `ethtool eth0`                          |
| `-i` (`--driver`)             | Информация о драйвере и firmware.                                  | `ethtool -i eth0`                       |
| `-S` (`--statistics`)         | Вывести статистику сетевого интерфейса.                            | `ethtool -S eth0`                       |
| `-a` (`--show-pause`)         | Показать настройки управления потоком (Pause Frames).              | `ethtool -a eth0`                       |
| `-A` (`--pause`)              | Настроить управление потоком (rx/tx).                              | `ethtool -A eth0 rx on tx on`           |
| `-s` (`--change`)             | Установить скорость, дуплекс, автосогласование.                    | `ethtool -s eth0 speed 100 duplex full` |
| `-k` (`--show-features`)      | Показать параметры аппаратного ускорения (offload).                | `ethtool -k eth0`                       |
| `-K` (`--features`)           | Включить/отключить offload (например, `tso`, `gso`).               | `ethtool -K eth0 tso off`               |
| `-g` (`--show-ring`)          | Показать размеры кольцевых буферов (RX/TX).                        | `ethtool -g eth0`                       |
| `-G` (`--set-ring`)           | Изменить размеры буферов.                                          | `ethtool -G eth0 rx 4096 tx 4096`       |
| `-c` (`--show-coalesce`)      | Показать параметры объединения прерываний.                         | `ethtool -c eth0`                       |
| `-C` (`--coalesce`)           | Настроить параметры прерываний (rx-usecs, tx-usecs).               | `ethtool -C eth0 rx-usecs 100`          |
| `-T` (`--show-time-stamping`) | Показать поддержку временных меток (PTP).                          | `ethtool -T eth0`                       |
| `--reset`                     | Сбросить статистику.                                               | `ethtool -S eth0 --reset`               |
| `-p` (`--identify`)           | Мигать светодиодами на интерфейсе (для идентификации).             | `ethtool -p eth0 5`                     |

```
sudo ethtool -t eth0 online
```

Проверяет только те компоненты, которые не требуют остановки работы интерфейса.

Результаты выводятся в консоль, но детализированная информация может отсутствовать&#x20;



```
sudo ethtool -t eth0 offline
```

Сеть временно отключается на время теста.

Подходит для диагностики сложных проблем, таких как аппаратные сбои.

### **ping ping6**

Обе команды используются для:

* Проверки доступности сетевого узла
* Измерения времени отклика (RTT — Round-Trip Time)
* Диагностики проблем соединения
* Тестирования MTU (максимального размера пакета)

**Основное отличие:**

* `ping` → Работает с **IPv4**
* `ping6` → Работает с **IPv6**\
  &#xNAN;_(В современных системах `ping` часто поддерживает оба протокола через флаги `-4`/`-6`)_

***

**Принцип работы**

1. **Отправка ICMP-пакетов**:
   * `ping` → ICMP Echo Request (тип 8)
   * `ping6` → ICMPv6 Echo Request (тип 128)
2. **Ожидание ответа**:
   * Целевой узел отвечает пакетом Echo Reply (ICMP тип 0 / ICMPv6 тип 129)
3. **Анализ результатов**:
   * Время между запросом и ответом (RTT)
   * Процент потерь пакетов

**Основные функции и опции**

**Общие для `ping` и `ping6`**

| Опция  | Пример                  | Описание                        |
| ------ | ----------------------- | ------------------------------- |
| `-c N` | `ping -c 5 8.8.8.8`     | Остановиться после N пакетов    |
| `-i N` | `ping -i 2 8.8.8.8`     | Интервал между пакетами (сек)   |
| `-s N` | `ping -s 1200 8.8.8.8`  | Размер пакета (байт)            |
| `-W N` | `ping -W 3 8.8.8.8`     | Таймаут ожидания ответа (сек)   |
| `-q`   | `ping -q -c 10 8.8.8.8` | Тихий режим (только статистика) |
| `-D`   | `ping -D 8.8.8.8`       | Вывод временных меток UNIX      |

#### **Специфичные для `ping6`**

| Опция        | Пример                  | Описание                                   |
| ------------ | ----------------------- | ------------------------------------------ |
| `-I <iface>` | `ping6 -I eth0 fe80::1` | Указать интерфейс для link-local адресов   |
| `-X`         | `ping6 -X 2001:db8::1`  | Использовать RAW-сокеты (для некоторых ОС) |

**Практические примеры**

**IPv4 (ping)**

```
# Базовая проверка
ping 8.8.8.8

# С ограничением пакетов
ping -c 4 google.com

# Проверка MTU (без фрагментации)
ping -s 1472 -M do 192.168.1.1

# Быстрый пинг с коротким таймаутом
ping -c 3 -W 1 8.8.8.8
```

#### **IPv6 (ping6)**

```
# Пинг IPv6-адреса
ping6 2001:4860:4860::8888

# Пинг link-local адреса
ping6 -I eth0 fe80::1%eth0

# Проверка MTU для IPv6
ping6 -s 1232 -M do 2001:db8::1
```

***

**Особенности IPv6**

**Link-Local адреса** требуют указания интерфейса:

```
ping6 fe80::1%eth0
```

**Размер заголовка**:

* IPv4: 20 байт → Макс. payload для MTU 1500: **1472** байта
* IPv6: 40 байт → Макс. payload для MTU 1500: **1452** байта

**Отсутствие ARP**: В IPv6 используется NDP (Neighbor Discovery Protocol).

***

**Интерпретация результатов**

```
64 bytes from 8.8.8.8: icmp_seq=1 ttl=117 time=15.3 ms
```

* `icmp_seq` — порядковый номер пакета
* `ttl` — время жизни пакета
* `time` — время отклика (RTT)

**Статистика в конце:**

```
--- 8.8.8.8 ping statistics ---
5 packets transmitted, 5 received, 0% packet loss, time 4006ms
rtt min/avg/max/mdev = 14.3/15.1/16.2/0.7 ms
```

**Типичные проблемы**

**Нет ответа**:

* Проверьте фаервол (`nft list ruleset`)
* Убедитесь, что узел доступен (`traceroute`)

**Высокий packet loss**:

* Проблемы с каналом связи
* Перегрузка сети

**Большая вариация RTT** (mdev):

* Перегрузка маршрутизаторов
* Проблемы с Wi-Fi



**Трассировка маршрута**

`traceroute` и `traceroute6` — это инструменты, используемые для обнаружения шлюзов на пути. Обнаружение пути — важный этап диагностики проблем с маршрутизацией. Обратите внимание, что `traceroute6` эквивалентно `traceroute -6`

Команда `traceroute` основана на эффективном использовании поля Time-To-Live (TTL) в заголовке IP-пакета. Поле TTL используется для ограничения срока действия пакета. Если маршрутизатор выйдет из строя или будет неправильно настроен, может возникнуть петля маршрутизации или циклический путь. Поле TTL предотвращает бессрочное пребывание пакетов в сети в случае возникновения такой петли маршрутизации. Поле TTL пакета уменьшается каждый раз, когда пакет проходит через маршрутизатор по пути через сеть. Когда его значение достигает 0, пакет отбрасывается, а не пересылается. При отбрасывании пакету отправляется сообщение ICMP TIME\_EXCEEDED TIME\_EXCEEDED, чтобы сообщить источнику, что пакет был отброшен. Управляя полем TTL исходного пакета, программа `traceroute` использует информацию из этих сообщений ICMP для поиска путей в сети.

`traceroute` отправляет серию UDP-пакетов с адресом назначения устройства, к которому вы хотите проложить маршрут. По умолчанию `traceroute` отправляет наборы из трёх пакетов для определения каждого перехода. Трассировка устанавливает для поля TTL в первых трёх пакетах значение 1, чтобы они были отброшены первым маршрутизатором на пути. Когда этот маршрутизатор возвращает сообщения ICMP TIME\_EXCEEDED, `traceroute` записывает IP-адрес источника этих сообщений ICMP. Это IP-адрес первого перехода на пути к месту назначения.

Затем отправляются три пакета с полем TTL, установленным на 2. Они будут отброшены вторым маршрутизатором на пути. Сообщения ICMP, возвращаемые этим маршрутизатором, раскрывают IP-адрес второго маршрутизатора на пути. Программа продолжает в том же духе до тех пор, пока у набора пакетов не будет достаточно большого значения TTL, чтобы они достигли пункта назначения. В большинстве реализаций `traceroute` по умолчанию выполняется только 30 попыток, после чего программа останавливается.

### **`traceroute6` (IPv6)**

Аналогичен `traceroute`, но работает с **IPv6** и использует **ICMPv6**.

**Схема работы:**

**Отправка пакетов с Hop Limit=1**

* В IPv6 аналог TTL называется **Hop Limit**.
* Первый пакет (ICMPv6 Echo Request) отправляется с `Hop Limit=1`.
* Первый маршрутизатор отвечает **ICMPv6 Time Exceeded (тип 3, код 0)**.

**Увеличение Hop Limit**

* Каждый следующий пакет отправляется с увеличенным `Hop Limit`.
* Процесс продолжается, пока не будет достигнут конечный узел.

**Фиксация ответа от цели**

* Конечный узел отвечает **ICMPv6 Echo Reply (тип 129)**.



**Различия между `traceroute` и `traceroute6`**

| Характеристика                  | `traceroute` (IPv4)                          | `traceroute6` (IPv6)         |
| ------------------------------- | -------------------------------------------- | ---------------------------- |
| **Протокол**                    | UDP/ICMP (по умолчанию UDP)                  | ICMPv6 (Echo Request)        |
| **Поле TTL/Hop Limit**          | TTL (Time To Live)                           | Hop Limit (аналог TTL)       |
| **Ответ маршрутизатора**        | ICMP Time Exceeded (тип 11)                  | ICMPv6 Time Exceeded (тип 3) |
| **Ответ цели**                  | ICMP Echo Reply (тип 0) или Port Unreachable | ICMPv6 Echo Reply (тип 129)  |
| **Локальные адреса**            | Обычно IPv4 (`192.168.x.x`)                  | IPv6 (`fe80::...`)           |
| **Необходимость `-I` для ICMP** | Да (если UDP блокируется)                    | Нет (всегда ICMPv6)          |

**Основные опции в Linux**

#### **Общие для `traceroute` и `traceroute6`:**

| Опция      | Описание                                           |
| ---------- | -------------------------------------------------- |
| `-n`       | Не резолвить имена (вывод только IP)               |
| `-m <max>` | Максимальное число хопов (по умолчанию 30)         |
| `-w <sec>` | Таймаут ожидания ответа (в секундах)               |
| `-q <num>` | Количество пробных пакетов на хоп (по умолчанию 3) |

#### **Специфичные для `traceroute` (IPv4):**

| Опция | Описание                                            |
| ----- | --------------------------------------------------- |
| `-I`  | Использовать ICMP вместо UDP (если UDP блокируется) |
| `-T`  | Использовать TCP SYN (если ICMP/UDP блокируются)    |
| `-U`  | Использовать UDP (по умолчанию)                     |

```bash
# IPv4 (UDP)
traceroute -n 8.8.8.8

# IPv4 (ICMP)
traceroute -I google.com

# IPv6 (ICMPv6)
traceroute6 -n 2a00:1450:4010::1

# Указание максимального числа хопов
traceroute -m 15 example.com
```

### **mtr**

Команда **`mtr`** (My Traceroute) — это гибрид **`traceroute`** и **`ping`**, который предоставляет удобный способ диагностики сетевых проблем. Она показывает маршрут трафика до целевого хоста, а также статистику потерь пакетов и задержек в реальном времени.

***

### &#x20;**Основные опции `mtr`**

| Опция               | Описание                                                                           |
| ------------------- | ---------------------------------------------------------------------------------- |
| **`-c <число>`**    | Отправить указанное количество пакетов и завершить работу (`mtr -c 10 google.com`) |
| **`-n`**            | Не преобразовывать IP-адреса в доменные имена (ускоряет работу)                    |
| **`-r`**            | Режим отчета (выводит статистику и завершает работу)                               |
| **`-s <размер>`**   | Установить размер пакета (в байтах)                                                |
| **`-i <секунды>`**  | Интервал между пакетами (по умолчанию 1 сек)                                       |
| **`-p`**            | Использовать ICMP ECHO вместо UDP (как `ping`)                                     |
| **`-T`**            | Использовать TCP вместо UDP/ICMP (полезно для обхода блокировок)                   |
| **`-u`**            | Использовать UDP (по умолчанию — ICMP)                                             |
| **`-4`** / **`-6`** | Принудительно использовать IPv4 или IPv6                                           |
| **`--no-dns`**      | Аналог `-n` (не делать DNS-запросы)                                                |
| **`--show-ips`**    | Показывать IP-адреса даже с DNS                                                    |

### **lsof**

`lsof` (List Open Files) — мощная утилита для вывода списка открытых файлов и процессов, которые их используют. В Linux "всё является файлом" (сокеты, каналы, устройства), поэтому `lsof` крайне полезна для диагностики.

| **Опция**          | **Описание**                                                               | **Пример использования**            |
| ------------------ | -------------------------------------------------------------------------- | ----------------------------------- |
| **`-i`**           | Показать сетевые соединения (TCP/UDP)                                      | `lsof -i`                           |
| **`-i :ПОРТ`**     | Показать процессы, использующие определённый порт                          | `lsof -i :80`                       |
| **`-i TCP`**       | Показать только TCP-соединения                                             | `lsof -i TCP`                       |
| **`-i UDP`**       | Показать только UDP-соединения                                             | `lsof -i UDP`                       |
| **`-i @IP`**       | Показать соединения с определённым IP-адресом                              | `lsof -i @8.8.8.8`                  |
| **`-u user`**      | Показать файлы, открытые конкретным пользователем                          | `lsof -u root`                      |
| **`-u ^user`**     | Исключить файлы, открытые пользователем                                    | `lsof -u ^nginx`                    |
| **`-c proc_name`** | Показать файлы, открытые процессами с определённым именем                  | `lsof -c sshd`                      |
| **`-p PID`**       | Показать файлы, открытые процессом с указанным ID                          | `lsof -p 1234`                      |
| **`-d FD`**        | Показать файлы с определёнными дескрипторами (0=stdin, 1=stdout, 2=stderr) | `lsof -d 0-2`                       |
| **`+D directory`** | Рекурсивный поиск открытых файлов в директории                             | `lsof +D /var/log`                  |
| **`-t`**           | Вывести только PID процессов (удобно для `kill`)                           | `lsof -t -i :8080 \| xargs kill -9` |
| **`-n`**           | Не преобразовывать IP-адреса в имена (ускоряет вывод)                      | `lsof -i -n`                        |
| **`-P`**           | Не преобразовывать номера портов в имена (показывает числа)                | `lsof -i -P`                        |
| **`-s`**           | Показать состояние сокета (LISTEN, ESTABLISHED и т.д.)                     | `lsof -i -sTCP:LISTEN`              |
| **`-r N`**         | Повторять вывод каждые N секунд (режим реального времени)                  | `lsof -i -r 5`                      |
|                    |                                                                            |                                     |

### netstat и ss

В Linux утилиты `netstat` и `ss` используются для анализа сетевых подключений, сокетов и статистики, но они имеют различия в функциональности, производительности и рекомендуемом использовании.

#### **Происхождение и актуальность**

* **`netstat`** — классическая утилита, входящая в пакет `net-tools`. Устарела и не рекомендуется к использованию в современных дистрибутивах.
* **`ss`** (socket statistics) — часть пакета `iproute2`, пришедшая на смену `netstat`. Разработана для работы с современным ядром Linux и поддерживает новые функции.

**Ключевые отличия:**

**Производительность**:

* `ss` работает через `netlink` (быстрее, особенно при тысячах соединений).
* `netstat` читает `/proc/net/` (медленнее).

**Фильтрация**:

* В `ss` встроена мощная фильтрация (например, `ss -t '( dport = :443 )'`).
* В `netstat` требуется `grep`.

**Совместимость**:

* `netstat` устарел и удаляется из новых дистрибутивов (например, RHEL 8+, Ubuntu 20.04+).
* `ss` — часть `iproute2`, актуальна и рекомендуется.

**Что использовать?**

* **`ss`** — для всего, что связано с сокетами (основная замена `netstat`).
* **`ip`** (из `iproute2`) — для работы с интерфейсами и маршрутами (замена `ifconfig`/`route`).
* **`netstat`** — только если нужна устаревшая функциональность (например, `netstat -i`).

### nc

`nc` используется для установления TCP- и UDP-соединений между произвольными портами на обоих концах. После открытия порта он может прослушивать входящие данные, которые могут быть переданы другой команде для дальнейшей обработки. Обратите внимание, что для открытия порта прослушивания ниже 1024 вам потребуются права администратора в системе, в которой вы запускаете эту команду. Команда позволяет пользователю настраивать, анализировать и считывать соединения между системами. Это очень полезный инструмент для устранения неполадок. `nc`. может использоваться для открытия любого порта.

Поскольку `nc` может подключаться и прослушивать любой порт, его можно использовать для передачи файлов между системами, в которых нет Samba, FTP, SSH и т. д.

если `nmap` недоступно, для проверки открытых портов можно использовать команду `nc`: запустите команду nc с флагом -z.&#x20;

| Опция                | Описание                                                            |
| -------------------- | ------------------------------------------------------------------- |
| **`-l`**             | Режим "слушателя" (сервер), ожидает входящие соединения             |
| **`-p <порт>`**      | Указать локальный порт (часто используется с `-l`)                  |
| **`-u`**             | Использовать UDP вместо TCP (по умолчанию TCP)                      |
| **`-v`**             | Подробный вывод (**`-vv`** — ещё более детальный)                   |
| **`-n`**             | Не использовать DNS (только IP-адреса)                              |
| **`-z`**             | Режим "сканирования" (проверка открытых портов без передачи данных) |
| **`-w <сек>`**       | Таймаут ожидания (например, `-w 5` — 5 секунд)                      |
| **`-k`**             | Не закрывать соединение после разрыва (удерживать сервер)           |
| **`-e <программа>`** | Выполнить программу после подключения (опасно!)                     |
| **`-4`** / **`-6`**  | Использовать IPv4 или IPv6                                          |

### **tcpdump**

`tcpdump` Это программа, которая позволяет сетевым администраторам просматривать каждый пакет, проходящий через сеть, в режиме реального времени. Этот инструмент обычно используется для мониторинга активных подключений или устранения случайных проблем с подключением к сети. Однако для просмотра трафика хост, на котором запущен `tcpdump` должен находиться где-то на пути между двумя (или более) хостами, обменивающимися трафиком. В полностью коммутационной сети это может оказаться затруднительным. Простое решение — запустить tcpdump на хосте, который должен отправлять или получать трафик. Другой вариант — настроить порт на одном из коммутаторов, через который будет передаваться копия трафика с определённых портов источника и назначения. Такой порт называется SPAN-портом.

`tcpdump` может генерировать большой объём выходных данных, поэтому полезно сузить область захвата пакетов, указав интерфейс, на котором вы хотите прослушивать трафик, с помощью `-i`. Кроме того, вы можете указать источник, получателя, тип протокола и/или номер порта трафика, который вы хотите видеть, при необходимости объединив их с помощью логических операторов И и ИЛИ. Примером команды может быть: `tcpdump -i eth0 src 10.10.0.1 and dst 10.10.0.254 and tcp port 80`). Другие полезные опции: `-n` для отключения разрешения имён и `-w` для записи захваченных пакетов в файл для последующего просмотра (например, в Wireshark).

**Основыне команды**

**Захват трафика на интерфейсе**

```bash
sudo tcpdump -i eth0
```

* `-i eth0` — интерфейс для захвата (можно использовать `any` для всех интерфейсов).

**Запись в файл и чтение**

```bash
sudo tcpdump -i eth0 -w dump.pcap       # Запись в файл
tcpdump -r dump.pcap                     # Чтение из файла
```

**Фильтрация по IP-адресу**

```bash
sudo tcpdump host 8.8.8.8                # Трафик только с/на указанный IP
sudo tcpdump src 192.168.1.1             # Только исходящий с указанного IP
sudo tcpdump dst 10.0.0.1                # Только входящий на указанный IP
```

**Фильтрация по порту**

```bash
sudo tcpdump port 80                     # HTTP-трафик
sudo tcpdump src port 22                 # Исходящий SSH
sudo tcpdump dst port 443                # Входящий HTTPS
```

**Фильтрация по протоколу**

```bash
sudo tcpdump icmp                        # Только ICMP (ping)
sudo tcpdump tcp                         # Только TCP
sudo tcpdump udp                         # Только UDP
sudo tcpdump arp                         # Только ARP-запросы
```

**Комбинированные фильтры**

```bash
sudo tcpdump "src 192.168.1.1 and dst port 80"
sudo tcpdump "host 8.8.8.8 and (icmp or tcp)"
```

| **Опция** | **Описание**                                                             |
| --------- | ------------------------------------------------------------------------ |
| `-i`      | Указать интерфейс (например, `-i eth0`). По умолчанию — первый активный. |
| `-n`      | Отключить преобразование адресов в имена (не резолвить DNS).             |
| `-c N`    | Остановиться после захвата N пакетов.                                    |
| `-w file` | Сохранить трафик в файл (например, `-w dump.pcap`).                      |
| `-r file` | Читать трафик из файла.                                                  |
| `-v`      | Увеличить детализацию вывода (можно использовать `-vv`, `-vvv`).         |
| `-A`      | Выводить пакеты в ASCII (удобно для анализа текстовых протоколов).       |
| `-s`      | Указать размер захватываемой части пакета (например, `-s 1500`).         |
| `-q`      | Тихий режим (минимальный вывод).                                         |
| `-X`      | Выводить пакеты в HEX и ASCII.                                           |

### nmap

`nmap` Это универсальный инструмент для исследования сети и аудита безопасности. В основном он используется как сканер портов, который также может определять запущенные службы, версии запущенных служб и типы операционных систем.

#### **Самые частые команды**

| Команда                          | Описание                 |
| -------------------------------- | ------------------------ |
| `nmap 192.168.1.1`               | Базовое сканирование     |
| `nmap -p- 192.168.1.1`           | Все порты                |
| `nmap -A 192.168.1.1`            | Агрессивное сканирование |
| `nmap -sV -O 192.168.1.1`        | Версии сервисов + ОС     |
| `nmap --script vuln 192.168.1.1` | Проверка уязвимостей     |
| `nmap -sn 192.168.1.0/24`        | Поиск живых хостов       |

**Сканирование одного хоста**

```
nmap 192.168.1.1
```

* Сканирует **1000 самых популярных портов** (TCP).
* Показывает **открытые (open)**, **закрытые (closed)** и **фильтруемые (filtered)** порты.

**Сканирование нескольких хостов**

```
nmap 192.168.1.1 192.168.1.2 192.168.1.3
nmap 192.168.1.1-100       # Диапазон IP
nmap 192.168.1.0/24        # Вся подсеть
```

**Проверка доступности хостов (Ping-сканирование)**

```
nmap -sn 192.168.1.0/24
```

Только проверяет, какие хосты **"живые"**, без сканирования портов.

**Сканирование конкретных портов**

```
nmap -p 22,80,443 192.168.1.1
```

Проверяет только **SSH (22), HTTP (80), HTTPS (443)**.

#### **Сканирование всех 65535 портов**

```
nmap -p- 192.168.1.1
```

**Медленно**, но проверяет **все порты**.

**Быстрое сканирование (только топ-портов)**

```
nmap --top-ports 100 192.168.1.1
```

Сканирует **100 самых популярных портов**

**Детекция сервисов и ОС**

**Определение версий сервисов**

```
nmap -sV 192.168.1.1
```

Показывает, какое ПО работает на открытых портах (например, `Apache 2.4.7`).

**Определение операционной системы**

```
nmap -O 192.168.1.1
```

Использует TCP/IP-фингерпринтинг для **определения ОС**.

**Агрессивное сканирование (версии ПО + ОС)**

```
nmap -A 192.168.1.1
```

Включает:

* `-sV` (версии сервисов),
* `-O` (определение ОС),
* `--traceroute` (трассировка маршрута),
* NSE-скрипты.



### **Wireshark**

Wireshark — это анализатор сетевых протоколов с открытым исходным кодом. Он позволяет просматривать данные из сети в реальном времени или из файла захвата на диске. Вы можете в интерактивном режиме просматривать данные захвата, углубляясь в детализацию пакетов по мере необходимости.

Wireshark обладает несколькими мощными функциями, включая расширенный язык фильтрации отображения и возможность просмотра реконструированного потока сеанса TCP. Он также поддерживает сотни протоколов и типов носителей. Также включена консольная версия, похожая на tcpdump, с именем tethereal. Единственное предостережение заключается в том, что Ethereal пострадал от десятков дыр в системе безопасности, которые можно использовать удаленно, поэтому будьте в курсе событий и остерегайтесь запускать его с правами root в ненадежных или враждебных сетях (таких как конференции по безопасности).

### **nslookup**

Утилита для выполнения DNS-запросов в командной строке. Позволяет получать информацию о доменных именах, IP-адресах, DNS-записях (A, MX, NS, SOA и др.) и диагностировать проблемы с DNS-серверами.

#### **Основные возможности**

**Запрос DNS-записей**:

* A (IPv4-адрес), AAAA (IPv6-адрес).
* MX (почтовые серверы), NS (DNS-серверы зоны).
* SOA (информация о зоне), TXT (текстовые записи).
* PTR (обратная запись для IP → домен).

**Ручное указание DNS-сервера** для запроса.

**Интерактивный режим** для последовательных запросов.

**Проверка обратного DNS** (поиск домена по IP).

| `-type=<тип_записи>`   | Указать тип DNS-записи (например, `A`, `MX`, `NS`).           |
| ---------------------- | ------------------------------------------------------------- |
| `-query=<тип_записи>`  | Аналог `-type`.                                               |
| `-server=<DNS_сервер>` | Использовать конкретный DNS-сервер вместо системного.         |
| `-debug`               | Вывести подробную информацию (включая заголовки DNS-пакетов). |
| `-port=<порт>`         | Указать порт DNS-сервера (по умолчанию 53).                   |
| `-timeout=<секунды>`   | Установить время ожидания ответа.                             |

&#x20;**Поиск A-записи (IPv4-адрес домена)**

```
nslookup example.com  
```

**Вывод:**

```

Address:    8.8.8.8#53

### **dig (Domain Information Groper)**

Утилита для выполнения DNS-запросов в Linux/Unix. Отличается от `nslookup` более детализированным выводом, гибкостью и удобством для автоматизации.

#### **Основные возможности**

**Запрос любых DNS-записей**:

* `A`, `AAAA`, `MX`, `NS`, `CNAME`, `TXT`, `SOA`, `PTR` и др.

**Ручное указание DNS-сервера** (включая DNS-over-HTTPS/TLS).

**Трассировка пути запроса** (от корневых серверов до целевого домена).

**Пакетный режим** для обработки множества запросов.

**Проверка DNSSEC** (безопасность DNS).

**Короткий вывод** (удобно для скриптов).

| **Опция**         | **Описание**                                                 |
| ----------------- | ------------------------------------------------------------ |
| `@<DNS-сервер>`   | Указать DNS-сервер (например, `@8.8.8.8`).                   |
| `-t <тип_записи>` | Тип DNS-записи (`A`, `MX`, `NS` и т.д.). По умолчанию — `A`. |
| `-x <IP-адрес>`   | Обратный DNS-запрос (IP → домен).                            |
| `+short`          | Вывести только результат (без метаданных).                   |
| `+trace`          | Трассировка пути DNS-запроса через корневые серверы.         |
| `+nocmd`          | Скрыть технические детали (только ответ).                    |
| `+noall +answer`  | Показать только ответы DNS-сервера.                          |
| `+stats`          | Показать статистику выполнения запроса.                      |
| `-f <файл>`       | Выполнить пакетные запросы из файла.                         |
| `-4` / `-6`       | Использовать IPv4 или IPv6 для запроса.                      |

***

**Информация о DNS-ответе:**

```
;; Got answer:
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 15698
;; flags: qr rd ra; QUERY: 1, ANSWER: 3, AUTHORITY: 0, ADDITIONAL: 1
```

* **opcode: QUERY** — тип операции: стандартный запрос.
* **status: NOERROR** — успешный ответ (ошибок нет).
* **id: 15698** — уникальный идентификатор запроса для сопоставления с ответом.
* **flags**:
  * **qr** (Query Response) — это ответ, а не запрос.
  * **rd** (Recursion Desired) — клиент запросил рекурсивный поиск.
  * **ra** (Recursion Available) — сервер поддерживает рекурсию.
* **QUERY: 1** — количество запросов в пакете.
* **ANSWER: 3** — три ответа (A-записи).
* **AUTHORITY: 0** — нет авторитативных DNS-серверов в ответе.
* **ADDITIONAL: 1** — одна дополнительная секция (EDNS).

**Расширение EDNS:**

```
;; OPT PSEUDOSECTION:
; EDNS: version: 0, flags:; udp: 65494
```

* **EDNS** (Extension Mechanisms for DNS) — расширение DNS для поддержки больших пакетов и дополнительных опций.
* **udp: 65494** — максимальный размер UDP-пакета, который может принять сервер.

***

**Секция запроса:**

```
;; QUESTION SECTION:
;ya.ru.				IN	A
```

* Запрос **A-записи** (IPv4-адрес) для домена `ya.ru`.
* **IN** — класс записи (Internet).

ya.ru.			237	IN	A	5.255.255.242
ya.ru.			237	IN	A	77.88.44.242
ya.ru.			237	IN	A	77.88.55.242
```

* **3 A-записи** — домен `ya.ru` привязан к трём IPv4-адресам (балансировка нагрузки).
* **237** — TTL (Time To Live) в секундах. Через это время кеш DNS обновится.
* **IN A** — класс и тип записи (IPv4).

***

**Статистика запроса:**

```
;; Query time: 29 msec
;; SERVER: 127.0.0.53#53(127.0.0.53) (UDP)
;; WHEN: Sun May 18 18:39:54 MSK 2025
;; MSG SIZE  rcvd: 82
```

* **Query time** — время выполнения запроса: **29 мс**.
* **SERVER** — DNS-сервер, обработавший запрос: `127.0.0.53:53` (локальный резолвер, например, `systemd-resolved`).
* **WHEN** — дата и время запроса (возможна опечатка в году **2025**, если команда выполнена в 2023).
* **MSG SIZE rcvd** — размер полученного DNS-пакета: **82 байта**.
