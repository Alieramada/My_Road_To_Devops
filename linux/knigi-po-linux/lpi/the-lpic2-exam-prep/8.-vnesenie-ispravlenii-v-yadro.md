# 8. Внесение исправлений в ядро

{% hint style="info" %}
В этом разделе представлена информация по теме, которая больше не входит в задачи LPIC-2. Он сохранен, поскольку по-прежнему содержит достоверную и ценную информацию.
{% endhint %}

В более старых версиях LPIC-2 предполагалось, что кандидаты на выполнение задач смогут должным образом исправлять исходный код ядра, чтобы добавить поддержку нового оборудования. В число задач входила возможность удалять исправления ядра из исправленных ядер.&#x20;

Ключевые файлы, условия и утилиты включают:

* Kernel Makefiles&#x20;
* patch&#x20;
* xz

Файл исправлений содержит список различий между двумя версиями файла. Стандартная команда diff способна создавать такие списки. Команда patch может использоваться для применения содержимого файла исправлений для обновления файла со старой версии до более новой .

Внести исправления в ядро очень просто:

* Поместите файл исправления в каталог /usr/src.
* Перейдите в каталог  /usr/src.&#x20;
* Распакуйте файл исправления с помощью unix&#x20;
* Используйте утилиту patch, чтобы применить файл исправления к исходному коду ядра:

```bash
# patch -p1 <patchfile>
```

* Проверьте, нет ли сбоев.&#x20;
* Создайте ядро.

Если утилита patch не может применить часть исправления, она помещает эту часть в файл отклонения. Имя отклоненного файла - это имя выходного файла плюс суффикс .rej или #, если добавление .rej приведет к слишком длинному имени файла. В случае, если даже простое добавление приведет к слишком длинному имени файла, последний символ имени файла заменяется на # .

Основные параметры утилиты patch:

-p number ; --strip=число

Удаляет наименьший префикс, содержащий число начальных косых черт, из каждого имени файла, найденного в файле исправления. Последовательность из одной или нескольких смежных косых черт считается одной косой чертой. Это определяет, как обрабатываются имена файлов, найденные в файле исправления, на случай, если вы храните свои файлы в каталоге, отличном от каталога человека, отправившего исправление. Например, предположим, что имя файла в файле исправления было /u/howard/src/blurfl/blurfl.c , тогда при использовании -p0 имя файла остается неизмененным, а при использовании -p1  получается u/howard/src/blurfl/blurfl.c.&#x20;

-s ; --silent ; --quiet&#x20;

Выполняет работу в автоматическом режиме (подавляйте вывод), если не возникнет ошибка.&#x20;

-E ; --remove-empty-files&#x20;

Удаляет выходные файлы, которые остались пустыми после применения исправлений. Обычно в этой опции нет необходимости, поскольку исправление может проверить временные метки в заголовке, чтобы определить, должен ли файл существовать после исправления. Однако, если входные данные не являются контекстными различиями или если patch соответствует спецификации POSIX, patch не удаляет пустые исправленные файлы, если не указана эта опция . Когда patch удаляет файл, он также пытается удалить все пустые каталоги-предки.

-R ; --reverse&#x20;

Предположим, что этот патч был создан с заменой старого и нового файлов, так что вы, по сути, применяете патч к файлу , который уже содержит изменения в файле исправления. Патч попытается поменять местами каждый фрагмент перед его применением, и отклонения будут отображаться в измененном формате. Опция -R не работает с diff скриптами, поскольку слишком мало информации для восстановления обратной операции. Если первый фрагмент исправления не работает, исправление меняет его на другой, чтобы посмотреть, можно ли его восстановить. применено таким образом. Если это возможно, вас спросят, хотите ли вы установить параметр -R. Если это невозможно, исправление продолжает применяться в обычном режиме.

{% hint style="info" %}
TЭтот метод не может обнаружить обратное исправление, если это обычный diff и если первой командой является append (т.е. это должно было быть delete), поскольку добавления всегда завершаются успешно. Это связано с тем, что нулевой контекст совпадает везде. К счастью, большинство исправлений добавляют или изменяют строки, а не удаляют их, поэтому большинство обратных обычных изменений начинаются с удаления, которое завершается неудачей, запуская эвристику.
{% endhint %}

Для получения дополнительной информации обратитесь к справочным страницам команд diff и patch.

## 8.0.1 Удаление исправления ядра из ядра продакшена

Исправление ядра можно удалить из ядра продакшена, удалив его из дерева исходных текстов ядра продакшена и скомпилировав новое ядро. Из предыдущего раздела мы узнали, что для удаления исправления из файла вам нужно либо применить его снова, либо запустить исправление с параметром -R:

```bash
# patch -p1<patch-2.6.28
patching file linux/Documentation/Configure.help
Reversed (or previously applied) patch detected! Assume -R? [n] y
```
