# 18. Создание и настройка параметров файловой системы (203.3)

## 18.1 Создание и настройка параметров файловой системы&#x20;

Кандидаты должны уметь настраивать файловые системы автоматического монтирования с помощью AutoFS. Эта задача включает в себя настройку автоматического монтирования для\
сетевых файловых систем и файловых систем устройств. Также предусмотрено создание файловых систем для таких устройств, как CD-ROM.

### 18.1.1 Ключевые области знаний

* конфигурационные файлы autofs&#x20;
* UDF and ISO9660 инструменты и утилиты

* осведомлённость  о расширениях CD-ROM файловых систем  (Joliet, Rock Ridge, El Torito)
* базовые знания о зашифрованных файловых системах

### 18.1.3 Autofs и автоматическое монтирование

Когда мы монтируем устройство с помощью fstab, оно всегда подключено и готово к работе. Это нормально, за исключением случаев, когда мы используем nfs, cifs, smb и т. д. через сеть. Идея autofs заключается в том, чтобы монтировать файлы по мере необходимости. Вот и всё! Таким образом, мы избегаем перегрузки сети.

Для ubuntu 24.04 LTS сначала необходимо установить соотвествующий пакет:

```bash
sudo apt install autofs -y
```

autofs помещает свои файлы конфигурации в каталог /etc :&#x20;

```bash
pirog@pirog:~$ ls -l /etc/auto*
-rw-r--r-- 1 root root 16213 Dec 20 19:48 /etc/autofs.conf
-rw-r--r-- 1 root root  1291 Dec 20 19:48 /etc/auto.master
-rw-r--r-- 1 root root   519 Dec 20 19:48 /etc/auto.misc
-rwxr-xr-x 1 root root  1602 Dec 20 19:48 /etc/auto.net
-rwxr-xr-x 1 root root  2083 Dec 20 19:48 /etc/auto.smb

/etc/auto.master.d:
```

**auto.master** - основная конфигурация autofs, и это первая проверка файла конфигурации autofs. Внутри autofs.master мы указываем, где должна находиться точка монтирования и где находится соответствующий файл конфигурации. Странно, но именно так работает autofs. Итак, помимо файла auto.master , вам могут понадобиться другие файлы конфигурации auto.\[\*], на которые ссылается auto.master, для создания и монтирования. Формат таков:

### Автоматическое монтирование с помощью systemd

Для запуска автоматического подключения к системам необходимо создать unit файл в /etc/systemd/system . Unit файл должен быть назван в честь точки\
подключения. В этом примере имя файла: mnt.mount, поскольку точка подключения /mnt.

```bash
# cat /etc/systemd/systemd/mnt.mount
[Unit]
Description=My new file system
[Mount]
What=/dev/sdb1
Where=/mnt
Type=ext4
Options=
[Install]
WantedBy=multi-user.target
```

После создания unit  файла его следует активировать с помощью команды:

```bash
# systemctl start mnt.mount
```

Проверьте активированную точку монтирования:

```bash
# mount | grep sdb1
/dev/sdb1 on /mnt type ext4 (rw,relatime,data=ordered)
```

Чтобы активировать автоматическое монтирование при запуске, используйте команду:

```bash
# systemctl enable mnt.mount
```

Запустите перезагрузку и проверьте, подключен ли раздел. Более подробную информацию о монтаже с помощью systems можно найти на странице руководства по systemd.mount(5).

### Autofs c systemd

Чтобы включить aurofs с systemd, в /etc/systemd/system должен быть создан unit файл с расширением .automount . Информация в этом файле контролируется systemd. Модули автоматического монтирования должны быть названы в соответствии с направлениями, которыми они управляют. В этом примере имя файла конфигурации модуля автоматического монтирования таково: mnt.automount .

```bash
# cat /etc/systemd/system/mnt.automount
[Unit]
Description=My new automounted file system.
[Automount]
Where=/mnt
[Install]
WantedBy=multi-user.target
```

После создания unit  файла его следует активировать:

```bash
# systemctl status mnt.automount
mnt.automount - My new automounted file system.
Loaded: loaded (/etc/systemd/system/mnt.automount; disabled; vendor preset: disabled)
Active: inactive (dead)
    Where: /mnt

# systemctl enable mnt.automount
Created symlink from /etc/systemd/system/multi-user.target.wants/mnt.automount to /etc/systemd/system/mnt.automount.

# systemctl start mnt.automount

# systemctl status mnt.automount
mnt.automount - My new automounted file system.
Loaded: loaded (/etc/systemd/system/mnt.automount; enabled; vendor preset: disabled)
Active: active (waiting) since Thu 2016-12-29 14:01:57 AST; 1min 2s ago
    Where: /mnt
Dec 29 14:01:57 sue systemd[1]: Set up automount My new automounted file system..
```

Как только он был запущен, на выходе монтирования отображается точка монтирования, включенная с помощью autofs.

```bash
# mount |grep mnt
systemd-1 on /mnt type autofs (rw,relatime,fd=25,pgrp=1,timeout=0,minproto=5,maxproto=5,direct)
```

### 18.1.4 CD-ROM файловая система

Создание образа для компакт-диска

Обычные утилиты для создания файловых систем на разделах жесткого диска CD-ROM с файловой системой ISO9660 записывают на них пустую файловую систему, которая затем монтируется и заполняется файлами пользователями по мере необходимости. Записываемый компакт-диск доступен для записи только один раз, поэтому, если бы мы записали на него пустую файловую систему, он был бы отформатирован и навсегда остался бы полностью пустым. Это также верно для перезаписываемых носителей, поскольку вы пока не можете изменять произвольные сектора; вы должны стереть весь диск целиком. Инструмент для создания файловой системы называется mkisofs.\
Пример использования выглядит следующим образом:&#x20;

```bash
$ mkisofs -r -o cd_image private_collection/
```

Параметр -r устанавливает общедоступные права доступа для всех файлов на компакт-диске и включает расширения Rock Ridge. Возможно, вы захотите использовать этот параметр, если только вы действительно не знаете, что делаете (подсказка: без параметра -r точка монтирования получает права доступа такие же как у каталога private\_collection!)

mkisofs постарается привести все имена файлов к формату 8.3, используемому DOS, чтобы обеспечить максимально возможную совместимость с форматом имен файлов 8.3. В случае конфликтов имен (разные файлы имеют одинаковое имя в версии 8.3) в именах файлов используются цифры, а информация о выбранном имени файла выводится через STDERR (обычно на экран). Не паникуйте: в Linux вы никогда не увидите эти странные имена файлов версии 8.3, потому что Linux использует расширения Rock Ridge, которые содержат исходный файл Rock Ridge\
информация (права доступа, имя файла и т.д.). Используйте параметр -J (расширения MS Joliet) или используйте mkhybrid, если вы хотите создать более удобный для Windows CD-ROM. Вы также можете использовать mkhybrid для создания компакт-дисков в формате HFS. Подробнее о\
различных опциях читайте на странице руководства. Другим расширением является El Torito, которое используется для создания загрузочных файловых систем на CD-ROM.

Помимо файловой системы ISO9660, созданной mkisofs, существует файловая система UDF (Universal Disk Format). Optical Storage&#x20;Technology Association стандартизировала файловую систему UDF, чтобы создать общую файловую систему для всех оптических носителей (доступных только для чтения и перезаписываемых). Она была предназначена для замены файловой системы ISO9660.

Инструментами для создания и обслуживания файловой системы UDF являются:

**mkudffs**

Создает новую файловую систему UDF. Может использоваться как на жестких дисках, так и на CD-R(W).

**udffsck**

Используется для проверки целостности и исправления ошибок в файловых системах UDF.

**wrudf**

Эта команда используется для поддержки файловых систем UDF. Она предоставляет интерактивную оболочку для операций с существующими файловыми системами UDF: cp, rm, mkdir, rmdir, ls,.... и т.д.

**cdrwtool**

Cdrwtool предоставляет средства для управления дисководами CD-RW. Это включает в себя форматирование новых дисков, настройку скорости чтения и записи и т.д.

Эти инструменты являются частью пакета UDFtools.

### HFS  <a href="#hfs-date-range-1904-2040" id="hfs-date-range-1904-2040"></a>

Иерархическая файловая система (HFS) — это проприетарная файловая система, разработанная компанией Apple Inc. для использования в компьютерных системах под управлением Mac OS. Изначально она была предназначена для использования на гибких и жёстких дисках, но её также можно найти на носителях только для чтения, таких как компакт-диски. HFS также называют Mac OS Standard, а её преемницу, HFS Plus, — Mac OS Extended. С выходом Mac OS X 10.6 компания Apple прекратила поддержку форматирования или записи на диски и образы HFS, которые по-прежнему поддерживаются как тома только для чтения.

### 18.1.5 Зашифрованные файловые системы

### Device Mapper

Начиная с Linux 2.6, можно использовать device mapper, универсальную платформу Linux для сопоставления одного блочного устройства с другим. Device mapper используется для программного RAID и LVM. Он используется в качестве фильтра между файловой системой на виртуальном блочном устройстве и зашифрованными данными, которые должны быть записаны на жесткий диск. Это позволяет файловой системе представлять себя расшифрованной, в то время как все считываемые и записываемые данные на диске будут зашифрованы. В /dev/mapper создается виртуальное блочное устройство, которое можно использовать как любое другое блочное устройство. Все данные, поступающие на него и исходящие из него, проходят процедуру шифрования или дешифрования, а затем передаются на другое блочное устройство.

### Device Mapper crypt (dm-crypt)

Device mapper crypt предоставляет универсальный способ прозрачного шифрования блочных устройств с использованием API ядра и может использоваться в сочетании с томами RAID или LVM. Когда пользователь создает новое блочное устройство, он может указать несколько параметров: симметричный шифр, режим шифрования, ключ и режим iv генерации. Dm-crypt не хранит никакой информации в заголовке, как это делает LUKS. После шифрования диск будет неотличим от диска со случайными данными. Это означает, что наличие зашифрованных файлов в нем невозможно.\
это невозможно опровергнуть в том смысле, что невозможно доказать существование зашифрованных данных. Пользователь должен следить за параметрами, которые используются\
при настройке dm-crypt, в противном случае это может привести к потере данных, поскольку метаданные недоступны. Для шифрования и дешифрования блочных устройств может использоваться только один ключ шифрования, а мастер-ключ не может быть использован. Если пароль зашифрованного блочного устройства утерян, восстановить данные невозможно. Dm-crypt следует использовать только опытным пользователям. Обычным пользователям следует использовать LUKS для шифрования диска.

### Linux Unified Key Setup (LUKS)

\
LUKS - это стандартная утилита для всех универсальных дистрибутивов Linux. Она обеспечивает шифрование дисков для различных типов томов (обычные тома dm crypt, тома LUKS и т.д.). Она обеспечивает совместимость между дистрибутивами и обеспечивает безопасное управление\
паролями пользователей. Он также обеспечивает хранение криптографических параметров, включая главный ключ, в заголовке раздела, что позволяет беспрепятственно осуществлять транспортировку или миграцию данных. LUKS также предоставляет до 8 различных ключей для каждого раздела LUKS, чтобы обеспечить возможность депонирования ключей (использование ключей в зависимости от значения). При создании зашифрованных разделов в разных дистрибутивах Linux настройки по умолчанию могут отличаться, но их достаточно для защиты данных на томах. LUKS является предпочтительным методом защиты данных для обычных пользователей.

### Пример с dm-crypt

Это пример настройки зашифрованной файловой системы. Все соответствующие модули должны быть загружены во время загрузки:

```
# echo aes >> /etc/modules
 # echo dm_mod >> /etc/modules
 # echo dm_crypt >> /etc/modules
 # modprobe -a aes dm_mod dm_crypt
```

Создайте device mapperblock и используйте (например) sda3 для него. Выберите свой пароль, используя: : `cryptsetup -y create crypt /dev/sda3:`

```
# echo "crypt /dev/sda3 none none" >> /etc/crypttab
# echo "/dev/mapper/crypt /crypt reiserfs defaults 0 1" >> /etc/fstab
```

Создайте файловую систему:

```
# mkfs.reiserfs /dev/mapper/crypt
```

Теперь подключите вашу зашифрованную файловую систему. Вам будет предложено ввести пароль, который вы выбрали с помощью cryptsetup. Вам будет предложено вводить его при каждой загрузке:

```
# mkdir /crypt
# mount /crypt
```



### Пример с LUKS

Это пример создания зашифрованного контейнера LUKS объемом 512 МБ в среде Linux.

```
# dd if=/dev/urandom of=/root/encrypted bs=1M count=512
```

Отформатируйте разреженный файл с помощью LUKS и введите ключевую фразу:

```bash
# cryptsetup -y luksFormat encrypted
 WARNING!
 ========
 This will overwrite data on encrypted irrevocably.
 Are you sure? (Type uppercase yes): YES
 Enter passphrase:
 Verify passphrase:
```

Откройте контейнер, укажите имя и введите кодовую фразу:

```bash
# cryptsetup luksOpen encrypted encrypted
Enter passphrase for encrypted:
```

Создайте файловую систему в незашифрованном контейнере:

```bash
mkfs.ext4 /dev/mapper/encrypted
 mke2fs 1.43.3 (04-Sep-2016)
 Creating filesystem with 522240 1k blocks and 130560 inodes
 Filesystem UUID: 9fb28cc0-5a3e-4e0b-b3cc-3cbd6cf3c8f4
 Superblock backups stored on blocks:
 8193, 24577, 40961, 57345, 73729, 204801, 221185, 401409
 Allocating group tables: done
 Writing inode tables: done
 Creating journal (8192 blocks): done
 Writing superblocks and filesystem accounting information: done
```

Смонтируйте зашифрованный контейнер для использования:

```bash
# mount /dev/mapper/encrypted /mnt
```
