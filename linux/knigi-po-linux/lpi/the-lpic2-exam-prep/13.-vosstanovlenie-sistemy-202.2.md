### 13.1.4 Объяснение GRUB

GRUB (сокращение от GRand Unified Bootloader) загружает ядро операционной системы и передает ему управление.

Существуют две основные версии GRUB. Текущая версия известна как GRUB, но на самом деле это GRUB 2. GRUB был разработан примерно в 2011 году. Более старая версия была разработана еще в 1999 году и теперь называется GRUB Legacy. GRUB Legacy все еще используется , но его разработка была заморожена.

### **GRUB 2**

GRUB - это модульный загрузчик, который поддерживает загрузку с ПК UEFI, ПК BIOS и других платформ. Преимущество его модульной конструкции заключается в том, что по мере добавления в ядро новых файловых систем и/или решений для хранения данных поддержка загрузки может быть легко добавлена в GRUB 2 в виде отдельных модулей.

Примерами поддержки загрузки, добавляемой такими модулями, являются модули для поддержки файловых систем (таких как ext4, NTFS, btrfs и zfs), а также LVM и программные RAID-устройства.

GRUB способен загружать множество операционных систем, как бесплатных, так и проприетарных. Открытые операционные системы, такие как FreeBSD, NetBSD, OpenBSD и Linux, поддерживаются GRUB напрямую. Проприетарные  (например, для DOS, Windows и OS/2) используют chain-loading загрузчика GRUB. Цепная загрузка(chain-loading) подразумевает, что GRUB будет использоваться для загрузки системы и, в свою очередь, загрузит и запустит проприетарный системный загрузчик, который затем загрузит операционную систему.

Процесс загрузки GRUB включает в себя как интерфейс меню, так и интерфейс командной строки (CLI). Вызываемый интерфейс командной строки называется оболочкой GRUB и позволяет вам выполнять команды для выбора корневого устройства (команда root), загрузки с него ядра (команда linux) и, при необходимости, загрузки некоторых дополнительных модулей ядра (insmod) и последующей загрузки ядра (команда boot). Интерфейс меню позволяет быстро выбрать желаемую среду выполнения. Во время загрузки доступны оба интерфейса. При загрузке отобразится меню, и пользователь может просто выбрать один из пунктов меню. Без участия пользователя система загрузит пункт по умолчанию по истечении заданного времени.

В качестве альтернативы пользователь может нажать e, чтобы отредактировать текущую запись перед загрузкой, или нажать c, чтобы войти в интерфейс командной строки. Некоторые дистрибутивы Linux скрывают экран GRUB во время загрузки. Нажатие клавиши SHIFT сразу после инициализации BIOS/UEFI приведет к отображению экрана GRUB.

GRUB использует свой собственный синтаксис для описания жестких дисков. Названия устройств должны быть заключены в квадратные скобки, например:

```
(fd0)
```

обозначает гибкий диск, а:

```
(hd0,1)
```

обозначает первый раздел на первом жестком диске. Обратите внимание, что, хотя номера дисков начинаются с нуля, номера разделов начинаются с единицы, поэтому в последнем примере указаны первый диск и первый раздел.

GRUB использует BIOS компьютера, чтобы узнать, какие жесткие диски доступны. Но он не всегда может понять связь между Имена файлов устройств Linux и дисков BIOS. Для их сопоставления может быть создан специальный файл /boot/grub/device.map, например:

```
(fd0) /dev/fd0
(hd0) /dev/hda
```

{% hint style="info" %}
Обратите внимание, что при использовании программного RAID-1 (зеркалирование) вам необходимо настроить GRUB на обоих дисках. После загрузки система еще не сможет использовать программную RAID-систему, поэтому загрузка может быть выполнена только с одного диска. Если вы настроите GRUB только на первом диске и этот диск будет поврежден, система не сможет загрузиться.
{% endhint %}

Файл конфигурации GRUB

Конфигурационным файлом для GRUB 2 является файл /boot/grub/grub.cfg . Конфигурационный файл GRUB написан на языке сценариев, похожем на оболочку , с условными операторами и функциями. Не рекомендуется изменять grub.cfg напрямую; файл конфигурации обновляется всякий раз, когда ядро добавляется, обновляется или удаляется с помощью менеджера пакетов дистрибутива или когда пользователь запускает скрипт update-grub.&#x20;

Программа update-grub является оболочкой для grub-mkconfig, в качестве выходного файла которой указан grub.cfg. Поведение grub-mkconfig контролируется файлами в каталог /etc/grub.d и ключевые слова в файле /etc/default/grub.&#x20;

Примеры ключевых слов: элемент меню по умолчанию для загрузки (GRUB\_DEFAULT) или время ожидания в секундах для загрузки элемента меню по умолчанию после отображения меню (GRUB\_TIMEOUT). Операционные системы, включая сторонние операционные системы, такие как Windows, автоматически определяются скриптом /etc/grub.d/30\_os\_prober .&#x20;

Пользовательский файл (по умолчанию 40\_custom ) может быть изменен пользователем для создания пользовательских записей. Пункты меню GRUB 2 начинаются с ключевого слова menuentry. Название пункта меню можно найти в кавычках на странице строка меню. Строка меню заканчивается открывающей фигурной скобкой ({). Элемент меню заканчивается закрывающей фигурной скобкой (}). Очень простой пример:

```bash
menuentry 'Linux 3.3.10' {
 <... >
 }
```

### Различия с GRUB Legacy

На первый взгляд, две версии не сильно отличаются друг от друга. Однако есть некоторые очевидные отличия:&#x20;

* Конфигурационный файл GRUB теперь называется /boot/grub/menu.list, в то время как в дистрибутивах на базе Red Hat используется /boot/grub/grub.conf.&#x20;
* Помимо немного другого названия, файл конфигурации также имеет другой синтаксис. Файл grub.cfg теперь создается во время установки grub и не должен редактироваться вручную.&#x20;
* Ядро GRUB engine стало меньше по размеру и в меньшей степени зависит от платформы. В настоящее время поддерживается множество различных файловых систем и платформ. доступны в отдельных модулях. Как следствие, используемая платформа и файловая система (ы) определяют, какие модули загружаются во время загрузки.&#x20;
* В отличие от этого, GRUB Legacy имеет фиксированную последовательность загрузки с жестко запрограммированными критически важными компонентами, что делает его менее гибким. Нумерация разделов в GRUB 2 начинается с 1, а не с 0. Диски по-прежнему нумеруются с 0. Это может немного сбивать с толку.&#x20;
* Спецификация ядра GRUB 2 выполняется с помощью команды Linux, в то время как в GRUB Legacy мы используем вместо этого команду ядра.&#x20;
* Корневое устройство можно выбрать с помощью команды set root вместо команды root.&#x20;
* Корневое устройство также можно задать с помощью команды search, которая позволяет находить устройства по метке диска или UUID.&#x20;
* GRUB 2 использует insmod для загрузки модулей.&#x20;
* В GRUB устаревшие модули загружаются с помощью module или modulenounzip .

Другие устаревшие команды GRUB включают команду blocklist, которая может быть использована для определения того, на каких дисковых блоках хранится файл, или команду geometry, которая может быть использована для определения геометрии диска. Вы можете создавать новые (первичные) разделы с помощью команды partnew, загружать образ initrd с помощью команды initrd и многое другое. Все опции описаны в документации GRUB. GRUB является частью библиотеки программного обеспечения GNU и как таковой документируется с помощью информационной системы. В большинстве систем также доступна ограниченная справочная страница.

В процессе начальной загрузки BIOS обращается к исходному сектору жесткого диска, так называемому MBR (Master Boot Record), загружает найденные там данные в память и передает им выполнение. Если используется GRUB, MBR содержит копию первого этапа GRUB, который пытается загрузить этап 2.

Чтобы иметь возможность загрузить этап 2, GRUB должен иметь доступ к коду для работы с файловой системой (ами). Существует множество типов файловых систем, и код для их обработки не поместится в 512-байтовом MBR-файле, тем более что MBR также содержит таблицу секционирования. Таким образом, части GRUB, связанные с файловыми системами, хранятся в так называемой области совместимости с DOS. Эта область состоит из секторов на том же цилиндре, где находится MBR (цилиндр 0). В прежние времена, когда адресация дисков осуществлялась с помощью CHS в соответствии со спецификацией (цилиндр/головка/сектор), MBR обычно загружает DOS. DOS требует, чтобы его изображение находилось на том же цилиндре. Поэтому, по традиции, первый цилиндр на диске резервируется, и именно это пространство GRUB использует для хранения кода файловой системы. Этот раздел называется stage 1.5. Этап 1.5 обычно называется core.img; он создается установщиком из нескольких файлов на основе файловых систем, которые grub должен поддерживать во время загрузки.

Этап 2 содержит большую часть логики загрузки. Он предоставляет конечному пользователю меню и дополнительную командную строку, в которой пользователь может вручную указать параметры загрузки. GRUB обычно настроен на автоматическую загрузку определенного ядра по истечении периода ожидания. Как только конечный пользователь сделал свой выбор, GRUB загружает выбранное ядро в память и передает управление ядру. На этом этапе GRUB может передать управление процессом загрузки другому загрузчику, используя цепную загрузку, если того требует операционная система.

В Linux команда grub-install используется для установки этапа 1 либо в MBR, либо в раздел

**Влияние на процесс загрузки**

Обычный процесс загрузки - это процесс, который обычно выполняется при повторной загрузке системы GRUB. На этот процесс можно повлиять с помощью GRUB prompt. На что можно повлиять, будет рассмотрено в следующих разделах, но сначала мы должны GRUB prompt.

**Выбор другого ядра**

Если вы только что скомпилировали новое ядро и испытываете трудности с его использованием, скорее всего, вы хотели бы вернуться к старому ядру.&#x20;

Для GRUB, как только вы увидите экран загрузки, используйте клавиши управления курсором, чтобы выбрать ядро, которое вы хотите загрузить, и нажмите Enter для его загрузки .

**Загрузка в однопользовательский режим или на определенный уровень выполнения**

Это может быть полезно, если, например, у вас установлена графическая среда, которая не работает должным образом. Вы либо вообще ничего не видите, либо система не достигает конечного состояния, потому что продолжает пытаться запустить X снова и снова. Загрузка в однопользовательском режиме или на другом рабочем уровне, где графическая среда однопользовательского режима не запущена, даст вам доступ к системе, чтобы вы могли устранить проблему.&#x20;

Чтобы загрузиться в GRUB в однопользовательском режиме, наведите курсор на запись ядра, которую вы хотите загрузить, и нажмите e. Затем выберите строка, начинающаяся с "linux" (для GRUB 2) или "kernel" в GRUB Legacy. Перейдите в конец строки и добавьте "single". После этого нажмите Enter, чтобы выйти из режима редактирования, а затем нажмите \[CTRL+x]{комбинацию клавиш} (GRUB2) или b в GRUB Legacy, чтобы выйти из редактора и загрузить эту запись.

**Переключение уровней выполнения**

В Linux можно переключиться на другой уровень выполнения, отличный от текущего активного. Это делается с помощью команды telinit. Его синтаксис прост: telinit \[ПАРАМЕТР] RUNLEVEL, где RUNLEVEL - это номер уровня выполнения.&#x20;

Единственная опция, которую поддерживает telinit, -это -e KEY=VALUE . Он используется для указания дополнительной переменной среды, которая будет включена в событие вместе с RUNLEVEL и PREVLEVEL. Обычно вы не используете эту опцию.&#x20;

Вы обнаружите, что используете telinit в основном для перехода в однопользовательский режим (уровень выполнения 1), например, чтобы иметь возможность смонтировать файловую систему и проверьте это. В этом случае вы можете использовать:

```bash
# telinit 1
```

{% hint style="info" %}
Обратите внимание, что telinit в большинстве систем является символической ссылкой на команду init
{% endhint %}

использование команды /sbin/init q заставляет init перезагрузить файл /etc/inittab .

**Передача параметров ядру**

```bash
ether=5,0x300,eth0 ether=11,0x340,eth1
```

**Процесс восстановления загрузки**

Во время загрузки проверяются файловые системы. В системе Debian это выполняется с помощью fsck /etc/rcS.d/S 30 check.fs . Все файловые системы проверяются на основе содержимого файла /etc/fstab .&#x20;

Если команда fsck возвращает статус завершения, превышающий 1, команда завершилась ошибкой. Статус завершения является результатом выполнения одного или нескольких из следующих условий:

```
0 - No errors
1 - File system errors corrected
2 - System should be rebooted
4 - File system errors left uncorrected
8 - Operational error
16 - Usage or syntax error
128 - Shared library error
```

Если команда не была выполнена, вы получите соответствующее сообщение:

```
fsck failed. Please repair manually
"CONTROL-D" will exit from this shell and
continue system startup.
```

Если вы не нажмете \[Ctrl+D]{комбинацию клавиш}, а введете пароль root, вы получите оболочку,  /sbin/sulogin , и в состоянии /sbin/sulogin  вы можете запустить fsck и устранить проблему, если корневая файловая система подключена только для чтения.

В качестве альтернативы (см. следующий раздел) вы можете загрузиться с загрузочного носителя.

**Если ваша корневая (/) файловая система повреждена**

**Использование загрузочного носителя дистрибутива**

Многие дистрибутивы поставляются с одним или несколькими компакт-дисками или загрузочными образами, которые можно поместить на USB-накопитель. На одном из таких компакт-дисков обычно содержится опция "восстановления" для загрузки Linux .&#x20;

Это позволяет вам исправлять ошибки. Не забудьте настроить порядок загрузки в BIOS таким образом, чтобы сначала загружаться с CD-ROM или USB-накопителя, а затем с жесткого диска.&#x20;

В случае использования USB-накопителя также может потребоваться включить в bios "Устаревшую поддержку USB".&#x20;

Режим восстановления зависит от конкретного дистрибутива. Но это должно позволить вам открыть консоль с правами суперпользователя. Там вы можете запустить fsck в размонтированной поврежденной файловой системе.

Давайте предположим, что ваш корневой раздел был /dev/sda2 . Затем вы можете запустить проверку файловой системы в корневой файловой системе, введя fsck -y /dev/sda2 . Флаг "-y" запрещает fsck задавать вопросы, на которые вы должны ответить (это может привести к большому количеству вводов), и заставляет fsck использовать "да" в качестве ответа на все вопросы. Несмотря на то, что корневая файловая система (/) восстановленного образа полностью находится в оперативной памяти, вы можете смонтировать файловую систему с жесткого диска в существующей точке монтирования в оперативной памяти, такой как /target . Или же вы можете сначала создать каталог, а затем смонтировать в нем раздел жесткого диска.

После того, как вы исправили ошибки, не забудьте размонтировать файловые системы, которые вы смонтировали, перед перезагрузкой системы, в противном случае во время загрузки вы получите сообщение о том, что одна или несколько файловых систем не были полностью размонтированы, и fsck попытается исправить их снова.

**Рекомендации по загрузке UEFI и NVMe**

В течение многих десятилетий системная система BIOS (Basic Input Output System) выполняла инициализацию аппаратного и программного обеспечения в процессе загрузки. Ранние версии BIOS требовали ручной настройки физических перемычек на материнской плате. В более поздних версиях процедура ручной перестановки была заменена программным меню, способным предоставить интерфейс для настройки самых элементарных параметров компьютера. Как бы удобно это ни звучало, постоянное развитие компьютерных систем привело к тому, что даже самое сложное программное обеспечение BIOS, как оказалось, имеет свои ограничения. Чтобы преодолеть эти ограничения, Intel в 1998 году разработала систему EFI (Extensible Firmware Interface) в качестве замены BIOS. Система EFI не прижилась, пока стандарт не был принят Форумом UEFI примерно в 2005 году. Затем стандарт был переименован из UEFI в UEFI (Универсальное расширяемое микропрограммное обеспечение Интерфейс). UEFI иногда также называют (U)EFI. Ядро Linux версии 3.15 и новее должно иметь возможность использовать преимущества UEFI .

В чем заключаются эти преимущества, спросите вы? Чтобы ответить на этот вопрос, мы должны сначала рассмотреть ограничения BIOS. Одно из ограничений систем BIOS заметно при загрузке операционных систем. Традиционно BIOS можно настроить на использование одного или нескольких загрузочных устройств в определенном порядке. Загрузочным устройством может быть оптический привод, жесткий диск, портативный USB-накопитель или сетевая интерфейсная плата. После того, как BIOS выполнит POST (самопроверку при включении питания), каждое настроенное загрузочное устройство будет проверено на соответствие наличие загрузчика. Будет загружен первый обнаруженный загрузчик. В случае жесткого диска BIOS ожидает, что загрузчик будет расположен в секторе 0 или в MBR\* (Главной загрузочной записи). Поскольку MBR позволяет хранить только небольшой объем данных (446 байт) , MBR обычно содержит инструкции, указывающие на другой фрагмент кода на диске. Этот двухэтапный подход известен как \*цепная загрузка. Тогда этот другой фрагмент кода мог бы состоять из менеджера загрузки. Менеджер загрузки способен загружать операционные системы. системы расположены в разных местах на томах хранилища. Как первый, так и второй этап загрузочного кода должны храниться в пределах первого мегабайта доступной памяти на жестком диске.

UEFI использует другой подход. Вместо того, чтобы ограничиваться содержимым MBR одного конкретного диска, UEFI считывает загрузочные данные из раздела ESP. ESP расшифровывается как системный раздел EFI. ESP - это специальный загрузочный раздел. Файловая система обычно имеет тип FAT и может содержать загрузчик любого размера или даже несколько загрузчиков. В системах Linux ESP обычно монтируется как /boot/efi . Под этой точкой монтирования будет находиться структура каталогов, которая зависит от используемой операционной системы. Загрузочные файлы, расположенные эти каталоги имеют расширение .efi. При использовании UEFI программное обеспечение UEFI действует как мини-загрузчик, который ищет имена файлов, оканчивающиеся на .efi, в заранее определенных местах.

```bash
# cd /boot/efi/
 # ls -a
 . .. EFI
 # cd EFI
 # ls
 BOOT fedora
 # ls -l BOOT
 total 1332
 -rw-r--r-- 1 root root 1293304 May 17 2016 BOOTX64.EFI
 -rw-r--r-- 1 root root 66072 May 17 2016 fallback.efi
 # ls -l fedora/
 total 3852
 -rw-r--r-- 1 root root 104 May 17 2016 BOOT.CSV
 drwxr-xr-x 2 root root 4096 Sep 28 22:17 fw
 -rwxr-xr-x 1 root root 70864 Sep 28 22:17 fwupx64.efi
 -rw-r--r-- 1 root root 1276192 May 17 2016 MokManager.efi
 -rw-r--r-- 1 root root 1293304 May 17 2016 shim.efi
 -rw-r--r-- 1 root root 1287000 May 17 2016 shim-fedora.efi
```

В приведенном выше примере каждый файл, оканчивающийся на .efi, может добавить функциональность системе UEFI. Таким образом, в то время как системы на базе BIOS зависят от метаданных жесткого диска для загрузки системы, системы на базе UEFI способны считывать файлы в ESP-части жесткого диска. UEFI обеспечивает обратную совместимость с устаревшими функциями BIOS и в то же время предлагает более продвинутые функции для современных компьютеров. Компьютеры, использующие программное обеспечение BIOS, испытывают трудности при работе с современными жесткими дисками емкостью >8 ТБ. Компьютеры на базе UEFI могут использовать схемы расположения дисков GPT, которые превышают ограничение на 2 ТБАЙТ для их аналогов в BIOS. Программное обеспечение UEFI поддерживает сетевые протоколы IPv4 и IPv6. Поддерживаются протоколы TCP и UDP, а загрузка с удаленного загрузочного носителя поддерживается с помощью TFTP и даже HTTP. Для загрузки по протоколу HTTP требуется UEFI 2.5 или новее. Версия 2.5 была выпущена в январе 2016 года.

Кандидаты на сдачу экзамена LPIC-2 должны знать о возможности переключения между режимами загрузки UEFI и устаревшим BIOS на современных компьютерах. Несмотря на преимущества, которыми может обладать UEFI, существуют также требования, которым необходимо соответствовать. Предполагается, что загрузочные файлы .efi будут расположены по определенному пути. Если включена функция безопасной загрузки, загрузочный код должен быть подписан цифровой подписью. В противном случае системы могут столкнуться с проблемами при загрузке. При устранении неполадок при загрузке на современном компьютере с Linux старайтесь отличать MBR от Схемы расположения дисков GPT. При использовании режима загрузки UEFI убедитесь, что используемый дистрибутив Linux также может выполнять загрузку UEFI. Когда Безопасная загрузка включена, убедитесь, что выполнены необходимые условия. Если вы сомневаетесь, переключитесь обратно на "Устаревший BIOS" или аналогичный интерфейс в интерфейсе UEFI. При загрузке с USB может потребоваться включить настройки "Устаревшего USB" для устройств массового хранения данных Устройств в интерфейсе UEFI.

**NVM**

В предыдущей главе жесткие диски емкостью 8 ТБ упоминались как результат недавнего развития компьютерных систем хранения данных. Эти обычные Жесткие диски SATA (Serial Advanced Technology Attachmenti) имеют движущиеся части и управляются с помощью протокола AHCI (Advanced Host Configuration Interface)). В последние годы все большую популярность приобретают жесткие диски SSD (Solid State Disk). Одним из преимуществ этих накопителей является отсутствие движущихся частей. Это делает жесткие диски SSD не только более энергоэффективными, но и быстрее, чем механические жесткие диски. Поскольку SSD-накопители должны быть совместимы с существующими компьютерами, они подключаются с помощью того же разъема SATA, что и механические жесткие диски. И в них также используется тот же протокол AHCI. Этот протокол изначально разрабатывался с учетом механических жестких дисков. Для управления жестким диском AHCI использует 1 очередь с 32 командами. Это создает проблему для нового поколения твердотельных накопителей SSD. Для устранения этой проблемы используется новая технология NVMe ((Non Volatile Memory Express). Технология NVMe позволяет подключать жесткие диски SSD к контроллеру NVMe, который подключен к шине PCI-E на материнской плате. Управление жестким диском SSD осуществляется с помощью NVMHCI (Non Volatile Memory Host Configuration Interface) протокола. Вместо 1 очереди, содержащей 32 команды одновременно, SSD-накопителем теперь можно управлять с помощью 65 000 очередей , содержащих до 65 000 команд в каждой. Это возможно благодаря тому, что шина PCI-E намного быстрее шины SATA. Самый последний поколение быстрых твердотельных накопителей SSD позволяет увеличить пропускную способность до семи раз с помощью NVMe по сравнению с жесткими дисками AHCI, подключенными по протоколу PCI-E.&#x20;

Так же, как традиционные жесткие диски, подключенные к компьютеру Linux, представлены ссылками /dev/hda\* или /dev/sda\*, NVMe жесткие диски представлены /dev/nvme\* в дереве файловой системы Linux. При работе с этими жесткими дисками имейте в виду, что обозначение диска начинается с 0, но пространство имен и раздел на диске начинаются с 1. Таким образом, первый раздел на первом пространство имен на первом жестком диске NVMe в системе представлено как /dev/nvme0n1p1 . Подробнее о загрузке UEFI и NVMe в 204.2
