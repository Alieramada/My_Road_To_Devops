# 21. Настройка доступа к устройству хранения данных (204.2)

## **21.1 Настройка доступа к устройствам хранения (204.2)**

Кандидаты должны уметь настраивать параметры ядра для поддержки различных дисков. Эта задача включает в себя программные средства для просмотра и изменения настроек жесткого диска, включая устройства iSCSI.

### 21.1.1 **Ключевые области знаний**

* Инструменты и утилиты для настройки DMA для IDE-устройств, включая ATAPI и SATA
* Инструменты и утилиты для управления или анализа системных ресурсов (например, прерываний)
* Осведомленность о команде `sdparm`и ее использовании
* Инструменты и утилиты для iSCSI
* Настройка SSD и NVMe и осведомленность о SAN

**21.1.2 Термины и утилиты:**

* hdparm, sdparm
* nvme
* tune2fs
* fstrim
* sysctl
* /dev/hd\*, /dev/sd\*, /dev/nvme\*
* iscsiadm, scsi\_id, iscsid и iscsid.conf
* WWID, WWN, LUN номера

В этом курсе рассматриваются многие стандарты и концепции хранения данных. Прежде чем начать, давайте разберём некоторые темы, а затем поймем, для чего нужен каждый инструмент.

### **Физическая установка**

Чтобы установить новый диск в вашей системе, вам нужно будет физически установить жёсткий диск и настроить его в BIOS|UEFI вашего компьютера. В большинстве случаев Linux автоматически обнаружит новый диск. Вы можете ввести `dmesg | more` , чтобы узнать имя и файл устройства диска. Например, второй SATA-диск в вашей системе будет называться `/dev/sdb`. Предположим, что новый диск называется `/dev/sdb`.

В более старых ядрах имена устройств IDE соответствуют шаблону `/dev/hd[a-d]`, где a используется для основного ведущего устройства IDE, b — для основного ведомого устройства, c — для вторичного ведущего устройства, а d — для вторичного ведомого устройства IDE. Для дисков PATA/SATA используется драйвер Linux SCSI, поскольку архитектура PATA/SATA аналогична архитектуре SCSCI. Поэтому в более новых устройствах файлы устройств соответствуют шаблону `/dev/sd*`.

После установки диска и его распознавания ядром вы можете (пере)разбить новый диск на разделы. В оболочке с судо правами введите:

```bash
 sudo fdisk /dev/sdb
```

Это приведет вас к подсказке. В командной строке введите `p` для отображения существующих разделов. Если у вас есть разделы, которые нужно удалить, введите `d`, затем в командной строке введите номер раздела, который вы хотите удалить. Затем введите `n` для создания нового раздела. Введите `1` (при условии, что это будет первый раздел на новом диске) и нажмите `enter`. Затем вам будет предложено ввести номер цилиндра, с которого вы хотите начать работу с диском. Затем вам будет предложено ввести номер последнего цилиндра раздела. Повторяйте эти действия , пока не будут созданы все разделы.

Чтобы создать чистую файловую систему на первом разделе вашего нового диска, введите:

```bash
sudo mkfs /dev/sdb1
```

Повторите этот шаг для всех разделов. Вы можете использовать параметр `-t` для определения типа создаваемой файловой системы, например `ext2`, `ext3`, `xfs`, `minix` и т. д.

Теперь вам нужно будет выбрать точку подключения для каждого нового раздела на вашем диске. Мы будем использовать `/new`. Введите:

```bash
mkdir /new
```

чтобы создать точку подключения для вашего диска. Теперь вам нужно отредактировать `/etc/fstab`. Вам нужно будет сделать запись в конце файла, похожую на эту:

```bash
    /dev/sdb1       /new     ext4          defaults       1   1
```

Современные твердотельные накопители (SSD) могут выиграть от некоторой оптимизации. SSD очень быстры по сравнению со стандартными жёсткими дисками с пластинами, но у них больше шансов столкнуться с повреждёнными блоками после многократной перезаписи. SSD могут использовать TRIM для эффективного удаления этих блоков. `noatime` или `relatime` также могут использоваться для уменьшения количества операций записи на диск. Это позволит файловой системе не отслеживать время последнего обращения, а только время последней модификации. В `/etc/fstab` это выглядело бы как:

```bash
/dev/sdb1       /new     ext4    discard,noatime       1      1
```

NVM Express (NVMe) - это спецификация для доступа к подключенным твердотельным накопителям через шину PCI Express. Драйвер Linux NVMe включен в ядро версии 3.3 и выше. Устройства NVMe можно найти в разделе `/dev/nvme*`. Устройства NVMe представляют собой семейство твердотельных накопителей, которые нельзя выбрасывать. Отбрасывает обычно отключен используется ext4 и ЛВМ, но и другие файловые системы, возможно, потребуется отбрасывает будет явно отключен.

```bash
 /dev/nvme0n1p1  /new     ext4 defaults 0 0
```

Перенос раздела `/tmp` в память (tmpfs) — ещё один способ уменьшить количество операций записи на диск. Это рекомендуется, если в вашей системе достаточно памяти. Добавьте в `/etc/fstab` следующую запись:

```bash
    none             /tmp/                   tmpfs   size=10%                 0       0
```

После того как вы создадите аналогичную запись для каждого раздела, запишите файл.

```bash
mount -a
```

смонтирует разделы в каталоге, указанном вами в разделе `/etc/fstab`.

### **hdparm**

hdparm — это программа командной строки для установки и просмотра аппаратных параметров жёстких дисков ATA. Первая (в 2005 году) утилита hdparm была разработана Mrk Lord для тестирования драйверов Linux для жёстких дисков IDE. С тех пор программа превратилась в ценный инструмент для диагностики и настройки жёстких дисков. Она может устанавливать такие параметры, как кэш-память, спящий режим, управление питанием и настройки DMA. Поскольку hdparm напрямую взаимодействует с оборудованием, она может привести к потере данных и другим повреждениям файловой системы.

hdparm необходимо запускать с правами суперпользователя, иначе он либо не будет найден, либо запрошенные действия не будут выполнены должным образом.

### **sdparm**

Команда `sdparm` используется для доступа к mode pages SCSI, чтения страниц VPD (Vital Product Data) и отправки простых команд SCSI.

Утилита извлекает и может изменять mode pages SCSI-устройства. Также могут отображаться данные запроса, включая Vital Product Data pages. Эта утилита может выполнять команды, связанные с запуском и остановкой носителя, загрузкой и выгрузкой носителя, а также другие вспомогательные функции.

### tune2fs <a href="#tune2fs" id="tune2fs"></a>

Команда tune2fs используется системным администратором для изменения настраиваемых параметров файловых систем типов ext2, ext3 и ext4. В отличие от hdparm, она управляет дисковым накопителем на уровне файловой системы.

```bash
pirog@pirog:~$ tune2fs
tune2fs 1.47.0 (5-Feb-2023)
Usage: tune2fs [-c max_mounts_count] [-e errors_behavior] [-f] [-g group]
	[-i interval[d|m|w]] [-j] [-J journal_options] [-l]
	[-m reserved_blocks_percent] [-o [^]mount_options[,...]]
	[-r reserved_blocks_count] [-u user] [-C mount_count]
	[-L volume_label] [-M last_mounted_dir]
	[-O [^]feature[,...]] [-Q quota_options]
	[-E extended-option[,...]] [-T last_check_time] [-U UUID]
	[-I new_inode_size] [-z undo_file] device

```

Мы уже рассмотрели команду tune2fs -l /dev/sda и использовали флаги -i и -c для изменения интервала проверки fsck. Давайте сделаем что-нибудь более интересное. По умолчанию в каждой файловой системе Linux есть место, зарезервированное для root, поэтому обычный пользователь не может заполнить файловую систему на 100%. По стандарту каждая файловая система резервирует 5% от общего объёма. Давайте изменим это:

```bash
pirog@pirog:~$ sudo tune2fs -l /dev/sda2 | grep -i reserved 
Reserved block count:     655321
Reserved GDT blocks:      1024
Reserved blocks uid:      0 (user root)
Reserved blocks gid:      0 (group root)

pirog@pirog:~$ sudo tune2fs -m 6 /dev/sda2
tune2fs 1.47.0 (5-Feb-2023)
Setting reserved blocks percentage to 6% (786385 blocks)

pirog@pirog:~$ sudo tune2fs -l /dev/sda2 | grep -i reserved 
Reserved block count:     786385
Reserved GDT blocks:      1024
Reserved blocks uid:      0 (user root)
Reserved blocks gid:      0 (group root)
pirog@pirog:~$ 

```

Если у нас очень большой раздел, файловая система ext, в которой много резервных суперблоков в разных местах жёсткого диска, занимающих заметное пространство, мы можем ограничить количество резервных суперблоков, чтобы сэкономить место в больших файловых системах, с помощью команды `tune2fs -s 0 /dev/sdaX`

Обратите внимание, что после любых манипуляций необходимо запустить fsck, чтобы изменения вступили в силу.

### **Использование файловой системы `/proc`**&#x20;

Современные ядра также поддерживают динамическую настройку параметров ядра. Самый простой способ настройки параметров ядра — изменение файловой системы `/proc` . Для настройки параметров можно использовать команду `echo` в следующем формате:

```bash
# echo value > /proc/kernel/parameter
```

например, для активации IP-переадресации:

```bash
# echo 1 >/proc/sys/net/ipv4/ip_forward
```

Изменения вступают в силу немедленно, но теряются при перезагрузке.

Файловую систему `/proc/` также можно запросить. Например, чтобы узнать, какие прерывания использует система, можно выполнить команду /proc/interrupts

```bash
# cat /proc/interrupts
```

который генерирует выходные данные, которые могут выглядеть следующим образом:


В многоядерных системах вы увидите несколько столбцов CP, например, CP0..CP3 для четырёхъядерной системы. По умолчанию прерывания передаются на ядро 0. Это может привести к снижению производительности, особенно в сетевых системах хранения данных. Поскольку CP0 перегружен IRQ, система работает медленно, даже если другим ядрам почти нечего делать. Более новые ядра пытаются сбалансировать нагрузку на прерывания. Но вы можете изменить настройки по умолчанию и выбрать, какое ядро будет обрабатывать то или иное прерывание.&#x20;

Каждое прерывание, указанное в `/proc/interrupts` файле, имеет подкаталог в `/proc/irq/` . Таким образом, прерывание 12 соответствует каталогу `/proc/irq/12`. В этом каталоге находится файл`smp_affinity`, содержащий данные, описывающие, какое ядро обрабатывает прерывание. Файл содержит битовую маску, содержащую один бит на ядро. Установив соответствующий бит, микросхема APIC передаст прерывание соответствующему ядру, например, 2 выбирает CPU1, 4 выбирает CPU2, 8-3, 16-4 .. и т.д. Чтобы, например, CPU5 получал все прерывания № 13, выполните:

```bash
# echo 32 >/proc/irq/13/smp_affinity
```

Тщательно выбирая, какие прерывания отправляются на какой процессор, вы можете значительно повысить производительность загруженной системы.

### **Настройка iSCSI**

Прежде чем говорить об iscsi, давайте поговорим о scsi, чтобы лучше понять, что это такое. Что такое scsi? SCSI (Small Computer System Interface) — это набор стандартных электронных интерфейсов Американского национального института стандартов (ANSI), которые позволяют персональным компьютерам (ПК) взаимодействовать с периферийным оборудованием, таким как дисководы, ленточные накопители, приводы компакт-дисков, принтеры и сканеры, быстрее и гибче, чем предыдущие интерфейсы для передачи данных. Но что, если бы мы могли делать это удалённо?

iSCSI (интерфейс малых компьютерных систем Интернета) работает поверх TCP (протокола управления передачей) и позволяет отправлять команды SCSI по локальным и глобальным сетям или через Интернет.

Как это работает? iSCSI работает за счёт передачи данных на уровне блоков между инициатором iSCSI на компьютере (в качестве клиента) и целью iSCSI на устройстве хранения данных (в качестве сервера). Протокол iSCSI инкапсулирует команды SCSI и собирает данные в пакеты для уровня TCP/IP. Пакеты отправляются по сети по двухточечному соединению. Когда пакеты поступают, протокол iSCSI разбирает их, извлекая команды SCSI, чтобы операционная система могла видеть хранилище как локальное устройство SCSI, которое можно отформатировать обычным способом.

### WWID

Каждому подключенному устройству SCSI присваивается уникальное имя. Имя устройства начинается с `/dev/sd`, например `/dev/sdd`, `/dev/sda`. Кроме того, каждое устройство SCSI имеет уникальный всемирный идентификатор (WWID). Идентификатор можно получить на самом устройстве с помощью команды `inquiry`. В системах Linux WWID можно найти в каталоге `/dev/disk/by-id/`. Там вы увидите символические ссылки, имена которых содержат WWID и которые указывают на присвоенное имя устройства. Существует два типа WWID, известных как «страница 0x83» и «страница 0x80», и у любого устройства SCSI есть один из них.

```
pirog@pirog:/etc/tgt$ ls -la /dev/disk/by-id/
total 0
drwxr-xr-x  2 root root  80 Mar 22 18:46 .
drwxr-xr-x 10 root root 200 Mar 22 18:46 ..
lrwxrwxrwx  1 root root   9 Mar 22 18:46 ata-VMware_Virtual_SATA_CDRW_Drive_00000000000000000001 -> ../../sr0
lrwxrwxrwx  1 root root   9 Mar 22 18:46 ata-VMware_Virtual_SATA_CDRW_Drive_01000000000000000001 -> ../../sr1

```



Например, устройство с идентификатором страницы 0x83 будет иметь:

```
scsi-3600508b400105e210000900000490000 -> ../../sda
```

Или устройство с идентификатором страницы 0x80 будет иметь:

```
 scsi-SSEAGATE_ST373453LW_3HW1RHM6 -> ../../sda
```

Приложения могут использовать `/dev/disk/by-id/` имя для обращения к данным на диске, даже если путь к устройству меняется, и даже при доступе к устройству из разных систем. Это также позволяет обнаруживать подключаемые устройства, например фотокамеру, и получать к ним доступ. Если она подключена, система отправит команду `inquiry` и создаст соответствующую символическую ссылку, что позволит вам получить доступ к камере под тем же именем.

Возможно и целесообразно иметь несколько путей к устройству, например, для обеспечения отказоустойчивости или резервного копирования и/или для повышения производительности. Такие «пути» могут быть реализованы в виде дополнительных сетевых путей (предпочтительно с использованием собственной сетевой карты) или по оптоволоконному кабелю (предпочтительно с использованием собственных HBA) и т. д. Если существует несколько путей от системы к устройству, специальный модуль ядра и связанные с ним демоны, а также другое программное обеспечение будут использовать WWID для определения путей. Они создадут одно «псевдоустройство» в `/dev/mapper/wwid` с именем `/dev/mapper/3600508b400105df70000e00000ac0000`, которое обеспечит доступ к устройству независимо от того, какой путь (пути) к нему используется, при условии, что хотя бы один из них может быть использован («активен»).

Команда `multipath -l` показывает сопоставление с непостоянными идентификаторами.

Device-mapper-multipath автоматически поддерживает правильное сопоставление каждого имени устройства на основе WWID с соответствующим именем `/dev/sd` в системе. Эти имена сохраняются при изменении пути и являются согласованными при доступе к устройству из разных систем. При использовании функции user\_friendly\_names (в device-mapper-multipath) WWID сопоставляется с именем вида `/dev/mapper/mpathn`. По умолчанию это сопоставление поддерживается в файле `/etc/multipath/bindings`. Эти имена `mpath` являются постоянными до тех пор, пока поддерживается файл.

**Примечание** Важно: если вы используете user\_friendly\_names, то для получения согласованных имен в кластере потребуются дополнительные действия. См. раздел «Согласованные имена многопутевых устройств в кластере» в книге «Using DM Multipath Configuration and Administration book».

### **LUN**

номер логического блока, или LUN, - это номер, используемый для идентификации логического блока, который представляет собой устройство, адресуемое по протоколу SCSI или протоколам сети хранения данных, которые инкапсулируют SCSI, таким как Fibre Channel или iSCSI.

Другой способ обратиться к устройству SCSI - это использовать его LUN, номер логической единицы. LUN - это трехразрядное число (0 ..7), которое указывает устройство в пределах целевого объекта. Любая цель должна, по крайней мере, иметь устройство с LUN 0, которое может использоваться как любое устройство, но также способно предоставлять информацию о других LUN в устройстве (если таковые имеются). Если в целевом объекте есть только одно устройство, то это устройство имеет LUN 0, поскольку любая цель должна иметь LUN 0.

Допустим, вы купили устройство SCSI, содержащее три диска (все они подключены к одному и тому же кабелю SCSI). Чтобы узнать, сколько дисков (или ленточных накопителей и т. д.) в вашей цели, вы отправляете запрос на LUN 0. Устройство с LUN 0 предназначено для того, чтобы сообщать вам о конфигурации и, возможно, о других устройствах. Для обращения к ним клиент использует LUN, указанные в LUN 0.

Поскольку диски SCSI часто называли по их LUN, эта привычка закрепилась, и в настоящее время этот термин также используется для обозначения логического диска в SAN. Но в SAN может быть гораздо больше LUN, чем скромные 7, которые используются в старых конфигурациях. Кроме того, такой SAN-LUN может состоять из нескольких дисков, которые могут быть сконфигурированы как RAID, разделены на тома и т. д. — для клиента это просто диск с LUN.

### **Настройка сохранения имени устройства (также известного как сохранение LUN)**

Имена устройств в Linux могут меняться при загрузке. Это может привести к путанице и повреждению данных. Поэтому существует ряд методов, которые позволяют сохранять имена устройств. В этом разделе рассказывается о том, как реализовать сохранение имён устройств в гостевых системах и на хост-машине с мультипутем и без него. Сохранение просто означает, что у вас будет одно и то же имя устройства независимо от путей доступа к нему. Таким образом, ваша камера или диск всегда будут распознаваться как таковые и получать одно и то же имя устройства независимо от того, где вы их подключаете.

### **Реализация сохранения имени устройства без multipath**

Если ваша система не использует мультипуть, вы можете использовать `udev` для реализации постоянства LUN. `udev` — это менеджер устройств, который прослушивает интерфейс с ядром. Если подключено новое устройство или устройство отключается, `udev` получит сигнал от ядра и с помощью набора правил выполнит действия, например присвоит устройству дополнительное имя.

Прежде чем внедрять LUN в свою систему, вам нужно будет получить соответствующие идентификаторы WWID для устройств, которыми вы хотите управлять. Это можно сделать с помощью программы `scsi_id` . После того как вы получите идентификаторы WWID для своих устройств, вам нужно будет написать правило, чтобы `udev` можно было присвоить ему постоянное имя.

scsi\_id Сначала нужно преодолеть небольшое препятствие. По умолчанию программа `scsi_id` не будет перечислять устройства и будет перечислять только те устройства, которые ей разрешено видеть (устройства, внесённые в «белый список»). Чтобы внести устройство в «белый список», вам нужно добавить его WWID в файл конфигурации `scsi_id`, который находится по адресу `/etc/scsi_id.conf`. Это безопасно, но неудобно, если вы хотите узнать WWID новых устройств. Поэтому вы можете указать опцию `-g` для обнаружения любого диска, который ещё не был перечислен. Если вы считаете, что это должно быть поведением по умолчанию, вы можете отредактировать `/etc/scsi_id.conf`. Если есть строка, которая гласит

```
options=-b
```

удалите её или закомментируйте. Затем добавьте строку, которая гласит:

```bash
options=-g
```

Если это было настроено, то при следующем использовании командой `scsi_id` программы она добавит параметр `-g` (и любые другие параметры, которые вы могли указать в файле конфигурации) и, следовательно, позволит извлекать WWID с новых устройств. Параметр `-g` должен использоваться либо по умолчанию из файла конфигурации, либо быть задан вручную в любом правиле `udev`, использующем команду `scsi_id`, иначе ваше новое подключённое устройство не будет распознано.

Затем вам нужно будет узнать, какой файл устройства был выделен ядром для вашего нового устройства. Обычно это делается с помощью команды `dmesg` после подключения нового устройства. Как правило, вы увидите примерно такие строки:

```bash
    usb 1-5: new high speed USB device using ehci_hcd and address 25
    usb 1-5: configuration #1 chosen from 1 choice
    scsi7 : SCSI emulation for USB Mass Storage devices
    usb-storage: device found at 25
    usb-storage: waiting for device to settle before scanning
      Vendor: USB       Model: Flash Disk        Rev: 8.07
      Type:   Direct-Access                      ANSI SCSI revision: 04
    SCSI device sdc: 7886848 512-byte hdwr sectors (4038 MB)
```

Как видите, мы подключили флэш-накопитель на 4 ГБ, которому было присвоено имя устройства 'sdc'. Теперь это устройство доступно как `/sys/block/sdc` в `/sys` псевдофайловой системе, а также как файл устройства `/dev/sdc`.

Чтобы определить WWID устройства, используйте команду `scsi_id`:

```bash
    # scsi_id -g -u -s /block/sdc
    3200049454505080f
```

Как видите, мы принудительно использовали `-g` . Опция `-s` указывает, что вы хотите использовать имя устройства относительно корня `sysfs` файловой системы (`/sys`). Более новые версии scsi\_id  больше не поддерживают использование `sysfs` имён, поэтому следует использовать имя устройства:

```bash
    /sbin/scsi_id -g -u -d /dev/sdc
    3200049454505080f
```

Длинная строка символов в выводе — это WWID. WWID не изменяется при добавлении нового устройства в систему. Чтобы создать правила для устройств, получите WWID для каждого устройства. Чтобы создать новые правила для устройств, отредактируйте файл `20-names.rules` в каталоге `/etc/udev/rules.d` . Правила именования устройств имеют следующий формат:

```bash
 KERNEL="sd<?>",  BUS="scsi",  PROGRAM="<scsi_id -options..>", RESULT="<WWID>", NAME="<devicename>"
```

Таким образом, когда вы подключаете новое устройство, ядро подаст сигнал `udev` о том, что оно нашло новое устройство SCSCI. Будет выполнена ПРОГРАММА, и РЕЗУЛЬТАТ должен совпасть. Если это так, то ИМЯ будет использоваться для файла устройства.

Примером может быть:

```bash
ERNEL="sd*",  BUS="scsi",  PROGRAM="/sbin/scsi_id -g -u -d /dev/$parent", RESULT="3200049454505080f", NAME="bookone"
```

Когда ядро выделяет новое устройство, имя которого соответствует шаблону KERNEL , выполняется ПРОГРАММА, и при обнаружении РЕЗУЛЬТАТА создаётся ИМЯ. Обратите внимание на опцию `-g`, которую мы добавили, чтобы мы могли видеть устройство, даже если оно не входит в белый список.

Демон `udevd` обычно запускается с помощью локального сценария запуска, который обычно выполняется процессом `init` и инициируется строкой в файле `/etc/inittab`: В старых системах нужно было убедиться, что эта строка находится в `/etc/rc.local`:

### **Реализация сохранения имени устройства с помощью** `multipath`

Вы можете реализовать сохранение имени устройства с помощью `multipath` драйверов и программного обеспечения. Конечно, обычно это используется только в том случае, если у вас есть несколько путей к устройству. Но вы можете определить `multipath` только с одним активным путём, и он будет работать как любой другой диск. Просто определите псевдоним, и имя будет сохраняться при перезагрузке.

Программное обеспечение `multipath` состоит из демона, который отслеживает пути к различным устройствам. При сбое он выполняет внешнюю команду `multipath`. Команда `multipath` в свою очередь сигнализирует демону после перенастройки путей.

Чтобы реализовать постоянство LUN в среде с несколькими путями, вы можете задать имя псевдонима для устройства `multipath`: Отредактируйте псевдонимы устройств в файле конфигурации демона `multipath`: `/etc/multipath.conf`&#x20;

```bash
    multipaths {
        multipath  {  
            wwid       3600a0b80001327510000015427b625e
            alias      backupdisk
        }
    }
```

Это определяет устройство, у которого есть постоянный файл устройства `/dev/mpath/backupdisk`. Это обеспечит доступ к устройству — независимо от его названия — с идентификатором WWID 600a0b80001327510000015427b625e. Псевдонимы сохраняются при перезагрузке.
