# 10.3 Настройка модулей

## 10.3.1 /etc/modules.conf

Иногда вам может потребоваться управлять назначением ресурсов, используемых модулем, таких как аппаратные прерывания или Direct Memory Access (DMA). В других ситуациях могут потребоваться специальные процедуры для подготовки или очистки после установки или удаления модуля. Этот тип специального управления модулями настроен в файле /etc/modules.conf .

## 10.3.2 Module Dependency File

Команда modprobe может определять зависимости модулей и автоматически устанавливать необходимые модули. Для этого modprobe просматривает первый столбец /lib/modules/kernel-version/modules.dep, чтобы найти модуль, который требуется установить. Строки в файле modules.dep имеют следующий вид:

```bash
module_name.(k)o: dependency1 dependency2 ...
```

Ниже приведен пример для датчиков температуры и процессорных модулей (которые являются частью уровня ACPI).:

```bash
/lib/modules/2.6.31/kernel/drivers/acpi/thermal.ko: \
 /lib/modules/2.6.31/kernel/drivers/thermal/thermal_sys.ko
 /lib/modules/2.6.31/kernel/drivers/acpi/processor.ko: \
 /lib/modules/2.6.31/kernel/drivers/thermal/thermal_sys.ko
```

В этом случае и процессор, и тепловой модуль зависят от модуля thermal\_sys. Все модули, доступные в системе, должны быть перечислены в файле modules.dep. Они указаны с полным путем и именами файлов, включая их расширение .(k)o. Те, которые не зависят от других модулей, перечислены без зависимостей. Перечисленные зависимости сначала вставляются в ядро с помощью modprobe, и после того, как они будут успешно вставлены, можно будет загрузить сам соответствующий модуль.&#x20;

Файл modules.dep должен постоянно обновляться для обеспечения корректной работы modprobe . Если бы зависимости модулей изменились без соответствующей модификации modules.dep, то modprobe завершился бы ошибкой, поскольку была бы пропущена зависимость. В результате файл modules.dep необходимо (заново) создавать при каждой загрузке системы. Большинство дистрибутивов делают это, автоматически запуская depmod -a при загрузке системы.

## 10.3.3 depmod

Процедура depmod -a также необходима после любого изменения зависимостей модуля.

Файл /lib/modules/kernel-version/modules.dep содержит список зависимостей модулей. Он генерируется командой depmod, которая считывает каждый модуль из /lib/modules/kernel-version, чтобы определить, какие символы нужны модулю и какие из них он экспортирует. По умолчанию список записывается в файл modules.dep . Команда modprobe, в свою очередь, использует этот файл для определения порядка , в котором модули должны загружаться в ядро или выгружаться из него.

```bash
kmod versus kerneld
```

kmod и kerneld оба обеспечивают динамическую загрузку модулей ядра. Модуль загружается, когда он впервые требуется ядру. Описание модулей приведено в разделе ???.

kerneld- это демон, kmod - это поток в самом ядре. Связь kerneld осуществляется через SystemV IPC. kmod работает непосредственно из ядра и не использует SystemV IPC, что делает его дополнительным модулем.

kmod заменил kerneld начиная с Linux kernel 2.2.x

И kerneld, и kmod облегчают динамическую загрузку модулей ядра. Оба они используют modprobe для управления зависимостями и динамической загрузкой модулей.

Ручная загрузка модулей с помощью modprobe или insmod возможна без использования kmod и kerneld. В обоих случаях необходимо установить параметр ядра CONFIG\_MODULES, чтобы разрешить использование модулей.

CONFIG\_KMOD CONFIG\_MODULES включает использование kmod, ядро должно быть скомпилировано с включенной функцией kernel-option CONFIG\_KMOD . Поскольку kmod реализован как модуль ядра, функция kernel-option CONFIG\_MODULES должна быть так же включена.

## 10.3.4 Создание кастомного ядра

Ниже приводится краткое описание того, как настроить и скомпилировать ядро в соответствии с пользовательскими потребностями. Вы начинаете с настройки, обычно используя одну из целей make для настройки (make config , xconfig , menuconfig , xconfig , oldconfig ), смотрите раздел о создании файла .config.

Как только ядро настроено, его можно собрать с помощью команды make zImage/bzImage . Для сборки модулей используйте команду make modules , за которой следует make modules\_install . Чтобы скомпилировать образ ядра и загружаемые модули за один шаг, вы можете использовать команду make all . После настройки и компиляции ядра его можно установить с помощью make install . Установка ядра означает установку следующих файлов в каталог /boot:

```bash
System.map-x.x.x
config-x.x.x
vmlinuz-x.x.x
```

Команда depmod создает файл modules.dep, который необходим modprobe для определения зависимостей (новых) созданных модулей.

Помимо сборки и установки ядра на локальном компьютере, вы также можете создавать пакеты, которые позволяют распространять ваше новое ядро на других компьютерах. Доступны все распространенные форматы пакетов, каждый из которых имеет свой собственный параметр make:

`make rpm-pkg : создает как исходные, так и двоичные RPM-пакеты.`&#x20;

`make binrpm-pkg : создает (только) двоичный пакет RPM для ядра.`&#x20;

`make deb-pkg : создает пакет ядра в виде пакета deb(ian).`

## 10.3.5 /proc filesystem

Файловая система /proc является псевдофайловой системой, что означает, что ее содержимое напрямую отображается ядром. Она содержит каталоги и другие файлы, которые отражают состояние работающей системы. Некоторые команды считывают файловую систему /proc, чтобы получить информацию о состоянии системы. Вы можете извлекать статистическую информацию, информацию об оборудовании , параметры сети и хоста, а также информацию о памяти и производительности. Файловая система /proc также позволяет изменять некоторые параметры во время выполнения, записывая значения в файлы.

Содержимое  / , /boot и /lib

В качестве примера представлено содержимое этих каталогов в системе Ubuntu 24.04 LTS.

```bash
pirog@pirog:/$ ls -a
.    bin.usr-is-merged  dev   lib                lost+found  opt   run                 snap      sys  var
..   boot               etc   lib64              media       proc  sbin                srv       tmp
bin  cdrom              home  lib.usr-is-merged  mnt         root  sbin.usr-is-merged  swap.img  usr
```

Наиболее важными каталогами являются /bin, который содержит общие общесистемные команды, /var, который является каталогом верхнего уровня для данных, которые будут постоянно изменяться (журналы и т.д.), /srv, который содержит данные, относящиеся к сервисам, предоставляемым системой (например , веб-серверу), /tmp для хранения временных файлов, /mnt, где могут быть временно подключены USB-диски, ленточные накопители и другие устройства, содержащие файловую систему, /lib , /lib32 и /lib64 для хранения модулей и других библиотек, /boot для хранения файлов, используемых во время загрузки, /sbin в котором мы находим специальные команды для системного администратора, /opt для сторонних пакетов и /etc, содержащий файлы конфигурации для вашей системы.

Каталог /usr содержит теневую иерархию, которая частично имитирует содержимое корневого каталога. Таким образом, вы найдете каталог /usr/bin, каталог /usr/sbin, каталог /usr/lib и каталог /usr/etc. "Вторичная иерархия" предназначалась для того, чтобы позволить пользователям переопределять или улучшать систему, например, позволяя им вводить команды локального системного администратора в /usr/sbin , а данные конфигурации локальной системы - в /usr/etc .&#x20;

Особым случаем являются /usr/local и его подкаталоги, который содержит еще одну теневую иерархия, имитирующая часть содержимого корневого каталога, на этот раз содержащая очень специфические (локальные системные) команды и данные конфигурации. Следовательно, вы найдете команды в /bin , /usr/bin и /usr/local/bin: команды в /bin будут частью дистрибутива, команды в /usr/bin могут быть необязательными или добавленными позже системным администратором, и, наконец, команды в /usr/bin могут быть включены в дистрибутив. команды в /usr/local/bin - это команды, специфичные для локальной системы.

{% hint style="info" %}
Обратите внимание, что каталог lost+found используется самой файловой системой.
{% endhint %}
