# 10.4 Инструменты и утилиты для отслеживания программного обеспечения и его системных и библиотечных

## 10.4.1 strace - trace system calls and signals

```bash
STRACE(1)                                 General Commands Manual                                STRACE(1)

NAME
       strace - trace system calls and signals

SYNOPSIS
       strace [-ACdffhikqqrtttTvVwxxyyYzZ] [-a column] [-b execve] [-e expr]... [-I n] [-o file]
              [-O overhead] [-p pid]... [-P path]... [-s strsize] [-S sortby] [-U columns] [-X format]
              [--seccomp-bpf] [--stack-trace-frame-limit=limit] [--syscall-limit=limit] [--tips[=format]]
              { -p pid | [-DDD] [-E var[=val]]... [-u username] command [args] }

       strace -c [-dfwzZ] [-b execve] [-e expr]... [-I n] [-O overhead] [-p pid]... [-P path]...
              [-S sortby] [-U columns] [--seccomp-bpf] [--syscall-limit=limit] [--tips[=format]] { -p pid
              | [-DDD] [-E var[=val]]... [-u username] command [args] }

       strace --tips[=format]

```

strace - это полезный инструмент диагностики, обучения и отладки. Системные администраторы, диагносты и специалисты по устранению неполадок найдут его незаменимым для решения проблем с программами, исходные тексты которых недоступны, поскольку их не нужно перекомпилировать, чтобы отследить. Студенты, хакеры и чрезмерно любопытные обнаружат, что можно многое узнать о системе и ее системных вызовах, отслеживая даже обычные программы. И программисты обнаружат, что, поскольку системные вызовы и сигналы - это события, которые происходят на интерфейсе пользователя и ядра, тщательное изучение этой границы очень полезно для выделения ошибок, проверки работоспособности.

В простейшем случае strace выполняет указанную команду до тех пор, пока она не завершится. Он перехватывает и записывает системные вызовы , которые вызываются процессом, и сигналы, которые принимаются процессом. Имя каждого системного вызова, его аргументы и возвращаемое значение выводятся при стандартной ошибке или в файл, указанный с параметром -o.

По умолчанию strace сообщает имя системного вызова, его аргументы и возвращаемое значение при стандартной ошибке.

## 10.4.2 strings

strings - вывод строк с печатаемыми символами в файлах. строки могут быть полезны для чтения нетекстовых файлов.

```bash
STRINGS(1)                                 GNU Development Tools                                STRINGS(1)

NAME
       strings - print the sequences of printable characters in files

SYNOPSIS
       strings [-afovV] [-min-len]
               [-n min-len] [--bytes=min-len]
               [-t radix] [--radix=radix]
               [-e encoding] [--encoding=encoding]
               [-U method] [--unicode=method]
               [-] [--all] [--print-file-name]
               [-T bfdname] [--target=bfdname]
               [-w] [--include-all-whitespace]
               [-s] [--output-separator sep_string]
               [--help] [--version] file...

```

Для каждого предоставленного файла GNU strings выводит доступные для печати последовательности символов длиной не менее 4 символов (или количество , указанное в приведенных ниже вариантах), за которыми следует непечатаемый символ. По умолчанию программа выводит только строки из инициализированных и загруженных разделов объектных файлов; для других типов файлов она выводит строки из всего файла целиком. Функция strings в основном полезна для определения содержимого нетекстовых файлов, таких как исполняемые файлы. Часто используется для проверки имен переменных среды и конфигурационных файлов, используемых исполняемым файлом.

## 10.4.3 ltrace

ltrace - средство отслеживания вызовов библиотеки

```bash
LTRACE(1)                                      User Commands                                     LTRACE(1)

NAME
       ltrace - A library call tracer

SYNOPSIS
       ltrace  [-e  filter|-L]  [-l|--library=library_pattern]  [-x  filter]  [-S]  [-b|--no-signals] [-i]
       [-w|--where=nr] [-r|-t|-tt|-ttt] [-T] [-F  filename]  [-A  maxelts]  [-s  strsize]  [-C|--demangle]
       [-a|--align  column]  [-n|--indent  nr] [-o|--output filename] [-D|--debug mask] [-u username] [-f]
       [-p pid] [[--] command [arg ...]]

       ltrace -c [-e filter|-L] [-l|--library=library_pattern] [-x  filter]  [-S]  [-o|--output  filename]
       [-f] [-p pid] [[--] command [arg ...]]

```

Подобно strace, который перехватывает и записывает системные вызовы, ltrace перехватывает и записывает вызовы динамической библиотеки , которые вызываются выполняемым процессом, и сигналы, которые принимаются этим процессом. Для этого не требуется перекомпилировать отслеживаемую программу, поэтому вы можете использовать ее для двоичных файлов, для которых у вас нет исходного кода. По умолчанию trace запускает программу, указанную вами в командной строке, и отслеживает ее до завершения работы программы.

Пример:
