# 10.7 Управление временем выполнения ядра

С помощью команды dmesg вы можете записывать сообщения ядра в стандартный вывод. Или записывать их в файл, используя dmesg > /var/log/ boot.messages . Это может быть полезно, когда речь заходит об устранении неполадок в вашей системе или когда вы просто хотите получить некоторую информацию об оборудовании в вашей системе. Выходные данные dmesg обычно можно найти в /var/log/dmesg . Используйте dmesg в сочетании с grep для поиска конкретной информации.

## 10.7.1 udev

Кандидаты должны разбираться в обнаружении устройств и управлении ими с помощью udev. Эта цель включает в себя устранение неполадок с помощью правил udev&#x20;

Ключевые области знаний:

* udev rules&#x20;
* Kernel interfaces

udev был разработан для того, чтобы сделать работу с устройствами Linux более гибкой и безопасной, перенеся управление устройствами из системного пространства в пользовательское.

**udev** состоит из демона пользовательского пространства (udevd ), который получает "события" от ядра. Связь между демоном пользовательского пространства и ядром осуществляется через псевдофайловую систему _**sysfs**_. Ядро отправляет вышеупомянутые "'uevents", когда обнаруживает добавление или удаление оборудования, например, при подключении камеры или USB-диска. На основе набора правил , соответствующих этим событиям, ядро предоставляет динамический каталог устройств, содержащий только файлы устройств, которые на самом деле подключены. присутствует и может запускать скрипты и т.д. для выполнения различных действий. Таким образом, можно, например, подключить камеру, которая будет автоматически обнаружена и должным образом установлена в нужном месте. После этого может быть запущен скрипт, который скопирует все файлы на локальный диск в подкаталог с соответствующим именем, который будет создан с соответствующими правами.

```bash
/etc/udev/
```

Каталог /etc/udev/ содержит файлы конфигурации и правил для утилиты udev. Файл udev.conf является основным файлом конфигурации для udev. Здесь, например, можно изменить приоритет ведения журнала.

**udev rules**

правила udev считываются из файлов, расположенных в каталоге правил по умолчанию. /lib/udev/rules.d/ . Пользовательские правила, переопределяющие эти правила по умолчанию, указаны в каталоге /etc/udev/rules.d/.

Когда устройства инициализируются или удаляются, ядро отправляет "'uevent". Эти 'ueventы содержат такую информацию, как подсистема (например, net, sub), действие и атрибуты (например, mac, поставщик). udev прослушивает эти события, сопоставляет информацию о событии с указанными правилами и реагирует соответствующим образом.

Правило udev состоит из нескольких пар ключ-значение, разделенных запятой. Каждая пара ключ-значение представляет собой либо ключ сопоставления, который соответствует информации, предоставляемой в событии, либо ключ назначения, который присваивает значения, имена и действия узлам устройства , поддерживаемым udev :

```bash
# do not edit this file, it will be overwritten on update

ACTION=="remove", GOTO="net_end"
SUBSYSTEM!="net", GOTO="net_end"

IMPORT{builtin}="net_id"

SUBSYSTEMS=="usb", IMPORT{builtin}="usb_id", IMPORT{builtin}="hwdb --subsystem=usb"
SUBSYSTEMS=="usb", GOTO="net_end"

SUBSYSTEMS=="pci", ENV{ID_BUS}="pci", ENV{ID_VENDOR_ID}="$attr{vendor}", ENV{ID_MODEL_ID}="$attr{device}"
SUBSYSTEMS=="pci", IMPORT{builtin}="hwdb --subsystem=pci"

LABEL="net_end"

```

Как показано, пара ключ-значение также определяет оператор. В зависимости от используемого оператора выполняются различные действия. Допустимыми операторами являются: ==, Сравнение на равенство, !=, Сравнение на неравенство, =, Присвоение значения ключу. Ключи, представляющие собой список, сбрасываются, и присваивается только это единственное значение, +=, Добавление значения к ключу окончательно; запрещает любые последующие изменения, которые могут быть использованы для предотвращения изменений по любым более поздним правилам.

При указании правил следите за тем, чтобы они не противоречили друг другу (например, не указывайте двум разным сетевым картам одно и то же имя устройства). Кроме того, изменение имен устройств на что-то другое может привести к несовместимости программного обеспечения в пользовательском пространстве. У вас есть возможности, используйте их с умом.

**udevmonitor**

udevmonitor выведет udev и kernel uevents на стандартный вывод. Вы можете использовать его для анализа синхронизации событий, сравнивая временные метки kernel uevent и udev-события. Обычно udevmonitor представляет собой символическую ссылку на udevadm . В некоторых дистрибутивах эта символическая ссылка больше не существует. Чтобы получить доступ к монитору в этих системах, используйте команду udevadm monitor .

```bash
root@pirog:/lib/udev/rules.d# udevadm monitor
monitor will print the received events for:
UDEV - the event which udev sends out after rule processing
KERNEL - the kernel uevent

```
