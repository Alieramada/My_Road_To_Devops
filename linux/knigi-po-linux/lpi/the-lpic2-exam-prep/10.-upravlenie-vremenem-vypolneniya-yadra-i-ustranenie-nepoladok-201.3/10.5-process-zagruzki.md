# 10.5 Процесс загрузки

Загрузчик загружает ядро и initial RAM disk.&#x20;

Ядро преобразует initrd в "обычный" RAM disk и освобождает память, используемую образом initrd.&#x20;

Образ initrd монтируется для чтения и записи от имени пользователя root&#x20;

Запускается linuxrc (это может быть любой допустимый исполняемый файл, включая сценарии оболочки; он запускается с uid 0 и может выполнять все , что может выполнить init)

После завершения работы linuxrc монтируется "настоящая" корневая файловая система&#x20;

Если каталог /initrd существует, то образ initrd перемещается туда, в противном случае образ initrd размонтируется&#x20;

Обычная последовательность загрузки (например, вызов /sbin/init) выполняется в корневой файловой системе.

Поскольку для перемещения initrd из / в /initrd не требуется его размонтировать, процессы, использующие файлы на жестком диске, могут продолжать выполняться. Все файловые системы, которые были смонтированы, останутся смонтированными во время перемещения. Однако, если /initrd не существует, перемещение не выполняется, и в этом случае любые запущенные процессы, использующие файлы из образа initrd, не позволят ему размонтироваться. Он будет оставаться в памяти до тех пор, пока не будет удален в результате продолжения процесса загрузки.

## 10.5.1 /proc/mounts

Кроме того, даже если перемещение может быть произведено и файловые системы, смонтированные с помощью initrd, остаются доступными, записи в /proc/mounts обновляться не будут. Также имейте в виду, что если каталог /initrd не существует, то размонтировать образ RAM disk невозможно. Образ будет принудительно удален на время остальной части процесса загрузки, поэтому все файловые системы, смонтированные в нем, также исчезнут и не смогут быть смонтированы повторно. Поэтому настоятельно рекомендуется размонтировать все файловые системы перед переключением с файловой системы initrd на обычную корневую файловую систему, включая файловую систему /proc .

Память, используемая для создания образа initrd, может быть восстановлена. Для этого необходимо использовать команду `freeramdisk` непосредственно после размонтирования /initrd .

## 10.5.2 Опции загрузки

Initrd=&#x20;

Включение поддержки initrd в ядро добавляет параметры в командную строку загрузки:

Этот параметр загружает файл, указанный в качестве исходного RAM-диска.

noinitrd

Этот параметр позволяет сохранить данные initrd, но они не преобразуются в RAMdisk, а вместо этого подключается обычная корневая файловая система. Данные initrd можно прочитать из /dev/initrd . При чтении через /dev/initrd данные могут иметь любую структуру , поэтому необязательно, чтобы это был образ файловой системы. Этот параметр используется в основном для целей отладки.

{% hint style="info" %}
Обратите внимание, что файл /dev/initrd доступен только для чтения и может быть использован только один раз. Как только последний процесс закроет его, вся память будет освобождена , и доступ к файлу /dev/initrd больше невозможен.
{% endhint %}

root=/dev/ram

Файл initrd монтируется от имени пользователя root, после чего запускается файл /linuxrc. Если файл /linuxrc отсутствует, будет выполнена обычная процедура загрузки . Без использования этого параметра файл initrd был бы перемещен или выгружен, однако в этом случае корневой файловой системой по-прежнему будет оставаться оперативный диск. Преимущество этого метода в том, что он позволяет использовать сжатую файловую систему и работает немного быстрее.
