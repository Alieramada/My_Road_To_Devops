## 10.2.1 insmod

Вставить модуль в работающее ядро. Модуль будет найден и вставлен автоматически. Для установки модулей вы должны войти в систему как суперпользователь . Обычно рекомендуется использовать modprobe, поскольку insmod возвращает только самые общие коды ошибок, а modprobe более конкретно описывает ошибки. Кроме того, вам нужно будет передать полное имя файла в insmod, тогда как modprobe будет работать только с именем модуля.

-s

* Записывать результаты в системный журнал, а не в терминал.

-v

* Подробный режим.

Предположим, ядро было скомпилировано с модульной поддержкой для конкретной scsi-карты. Чтобы убедиться, что этот конкретный модуль существует, в данном случае sym53c8xx.ko найдите файл sym53c8xx.ko в каталоге /lib/modules/kernel-version/kernel/drivers/scsi/.:

```bash
# insmod sym53c8xx.ko
 # echo
 0
```

Модули могут зависеть от других модулей. В этом примере все необходимые модули были загружены ранее, поэтому данный конкретный модуль был загружен успешно. Однако insmod не знает о необходимых модулях, он просто загружает все, что вы ему скажете. Это может произойти неправильно, если отсутствуют необходимые модули:

```bash
# insmod snd-ens1371.ko
 insmod: error inserting 'snd-ens1371.ko': -1 Unknown symbol in module
 # echo $?
 1
```

Сообщение указывает на то, что модулю требуется функция или переменная, которые отсутствуют в текущем ядре. Обычно это происходит из-за того, что в ядро не загружены или не скомпилированы необходимые модули.

## 10.2.2 rmmod

```bash
device or resource busy
```

Если модуль не используется или на него не ссылается другой модуль, он удаляется из запущенного ядра. Для удаления модулей вы должны войти в систему как суперпользователь.

```bash
# rmmod snd_ac97_codec
 ERROR: Module snd_ac97_codec is in use by snd_ens1371
 # echo $?
 1
```

В этом примере модуль не удалось выгрузить, поскольку он использовался, в данном случае модулем snd\_ens1371. Решение состоит в том, чтобы сначала удалить модуль snd\_ens1371:

```bash
 # rmmod snd_ens1371
 # rmmod snd_ac97_codec
 # echo $?
 0
```

Выполните команду lsmod, чтобы убедиться, что модули действительно были удалены из запущенного ядра.

## 10.2.3 modprobe

Как и insmod, modprobe используется для вставки модулей. Однако modprobe имеет возможность загружать отдельные модули, модули и их предварительные требования или все модули, хранящиеся в определенном каталоге. Команда modprobe также может удалять модули в сочетании с параметром -r. Он также более конкретен в своих сообщениях об ошибках, чем insmod .

Модули могут быть вставлены с необязательными параметрами symbol=value, такими как irq=5 или dma=3 . Такие параметры можно задать в командной строке или указав их в файле конфигурации модуля, что будет объяснено позже. Если модуль зависит от других модулей, они будут загружены первыми. Команда modprobe определяет необходимые связи между модулями, например, путем чтения файла modules.dep, расположенного на вершине иерархии каталогов модулей /lib/modules/2.6.31/modules.dep . Для установки модулей вы должны войти в систему как суперпользователь.

-a&#x20;

Загрузить все модули.  При использовании с тегом -t значение "все" ограничено модулями в каталоге тегов. Это действие проверяет оборудование путем последовательных попыток установки модулей для одного типа оборудования, например сетевого адаптера. Это может быть необходимо, например, для поиска нескольких типов сетевых интерфейсов.&#x20;

-c&#x20;

Отобразить полную конфигурацию модуля, включая значения по умолчанию и директивы, которые можно найти в /etc/modules.conf (или /etc/conf.modules, в зависимости от используемой версии утилит модуля.) Параметр -c не используется ни с какими другими параметрами.&#x20;

-l

Перечислить модули. При использовании с тегом -t перечислите только модули в теге directory.&#x20;

-r&#x20;

Удалить модуль, аналогично rmmod . Можно указать несколько модулей.&#x20;

-s&#x20;

Отобразить результаты в системном журнале, а не на терминале.&#x20;

-t tag

Попытаться загрузить несколько модулей, найденных в теге directory, до тех пор, пока какой-либо модуль не завершится успешно или пока не будут исчерпаны все модули в теге. Это действие проверяет оборудование путем последовательных попыток установки модулей для одного типа оборудования, например сетевого адаптера.&#x20;

-v&#x20;

Установить подробный режим.

Загрузка звуковых модулей с помощью modprobe .

```
pirog@pirog:/lib/modules/6.11.0-17-generic/kernel/sound$ modprobe snd_ens1371
pirog@pirog:/lib/modules/6.11.0-17-generic/kernel/sound$ lsmod
....
snd_ens1371            36864  1
snd_ac97_codec        196608  1 snd_ens1371
gameport               20480  1 snd_ens1371
ac97_bus               12288  1 snd_ac97_codec
snd_pcm               196608  2 snd_ac97_codec,snd_ens1371

```

Все необходимые модули для snd\_ens1371 уже загружены. Чтобы удалить оба модуля snd\_ac97\_codec и snd\_ens1371, используйте modprobe -r snd\_ac97\_codec .

Конфигурация модуля обрабатывается в файле /etc/modules.conf . Если этот файл не существует, утилита modprobe попытается прочитать файл / etc/conf.modules вместо этого. Последний файл является историческим именем и устарел. Он должен быть заменен на /etc/modules.conf .

{% hint style="info" %}
Обратите внимание, что в некоторых системах этот файл называется /etc/modprobe.conf или файлы конфигурации находятся в каталоге /etc/modprobe.d .
{% endhint %}

10.2.4 modinfo

Отобразить информацию о модуле из его объектного файла module-object-file . Некоторые модули не содержат никакой информации вообще, некоторые содержат краткое описание в одну строку, другие содержат достаточно описательное сообщение.

-a, --автор&#x20;

&#x20;Автор модуля.&#x20;

d, --description

Описание модуля.&#x20;

-n, ----filename

Имя файла модуля.&#x20;

-fformat\_string ,--format format\_string&#x20;

Позволяет пользователю указпть строку произвольного формата, которая может извлекать значения из раздела ELF в module\_file, содержащего информацию о модуле. Замены состоят из знака процента, за которым следует имя тега в фигурных скобках. Имя тега % {filename} поддерживается всегда, даже если в модуле нет раздела modinfo.&#x20;

-p , --parameters&#x20;

Отображает введенные параметры, которые могут поддерживаться модулем.&#x20;

-h , --help

Отобразить небольшую справку по использованию.

&#x20;-V , --version&#x20;

Отобразить версию modinfo .
