### 16.1.3 Файловая иерархия

Исторически сложилось так, что расположение определенных файлов и утилит не всегда было стандартным (или фиксированным). Это привело к проблемам при разработке и обновлении различных "дистрибутивов" Linux. Структура каталогов Linux (или файловая иерархия структуры каталогов Linux) была основана на существующих версиях UNIX, но по мере ее развития появились некоторые несоответствия. Часто это были мелочи, такие как расположение (или расстановка) определенных конфигурационных файлов, но это приводило к трудностям при переносе программного обеспечения с хоста на хост.

Чтобы сгладить эти различия, был разработан файловый стандарт. На сегодняшний день это развивающийся процесс, результатом которого является довольно статичная модель файловой иерархии Linux. Данная иерархия файловой системы является стандартизированной файловой иерархией Linux. Более подробную информацию и документацию по FHS можно найти на [домашней странице](https://www.pathname.com/fhs/) стандарта иерархии файловой системы. Смотрите также раздел, посвященный стандарту FHS.

Верхний уровень файловой иерархии Linux называется корневым (или / ). Корневой каталог обычно содержит несколько других каталогов. Обзор уже был представлен в разделе, посвященном содержимому корневой файловой системы. Краткое описание:

```
`bin/` Необходимые двоичные файлы во время загрузки
`boot/` Загрузочные конфигурационные файлы для загрузчика операционной системы и образа ядра
`dev/` Файлы устройств
`etc/` Файлы и скрипты конфигурации системы
`home/` Домашние каталоги пользователей
`lib/` Основные общие библиотеки операционной системы и модули ядра
`lost+found/` Каталог хранения "восстановленных" файлов
`media/` Точки монтирования для съемных носителей, таких как CD-ROM, флэш-диски и дискеты
`mnt/` Временная точка монтирования для файловых систем по требованию системного администратора
`opt/` Зарезервировано для установки больших дополнительных пакетов прикладного программного обеспечения
`proc/`"Виртуальная" файловая система, используемая системами Linux для хранения информации о ядре, процессах и текущем использовании ресурсов.
`root/` Домашний каталог Linux (нестандартный) для пользователя root. Альтернативным расположением является сам каталог `/`
` sbin/` Двоичные файлы и инструменты системного администрирования
` tmp/` Расположение временных файлов
` usr/` Доступные только для чтения данные, содержащие, например, пользовательские команды, заголовочные файлы программ на C и несущественные системные двоичные файлы
` var/` Переменные данные, обычно относящиеся к конкретному компьютеру. Включает каталоги буферов для почты и новостей, административные данные и данные журнала
```

Как правило, корневой каталог не должен содержать никаких дополнительных файлов. Возможным исключением могут быть точки монтирования для различных целей.

### 16.1.4 Файловые системы

Файловая система состоит из методов и структур данных, которые операционная система файловых систем использует для отслеживания файлов на диске или разделе; то есть способа организации файлов на диске. Это слово также используется для обозначения раздела или диска, который используется для хранения файлов, или типа файловой системы. Таким образом, можно сказать "у меня две файловые системы", что означает наличие двух разделов, на которых хранятся файлы, или можно сказать "Я использую файловую систему XFS", что означает тип файловой системы XFS.

Разница между диском или разделом и файловой системой раздела, которую он содержит, очень важна. Некоторые программы (в том числе те , которые создают файловые системы) работают непосредственно с необработанными секторами диска или раздела; если файловая система уже существует, она будет уничтожена или серьезно повреждена. Большинство программ работают с файловой системой и, следовательно, не будут работать с разделом, который ее не содержит (или который содержит файловую систему неправильного типа).

Прежде чем раздел или диск можно будет использовать в качестве файловой системы, его необходимо инициализировать, а структуры учётных данных нужно записать на диск. Этот процесс называется созданием файловой системы.&#x20;

Большинство типов файловых систем UNIX имеют схожую общую структуру, хотя точные детали довольно сильно различаются.Central superblock, inode directory blocks, indirection blocks, inode, data block, directory block, and indirection block.&#x20;

Суперблок содержит информацию о файловой системе в целом, например, о ее размере (точная информация здесь зависит от файловой системы).

inode содержит всю информацию о файле, за исключением его имени. Имя хранится в каталоге вместе с номером inode.&#x20;

Запись в каталоге состоит из имени файла и номера inode, который представляет файл. inode содержит номера нескольких блоков данных, которые используются для хранения данных в файле.

Однако в индексном дескрипторе есть место только для нескольких номеров блоков данных, и если требуется больше, то динамически выделяется больше места для указателей на блоки данных. Эти динамически распределяемые блоки являются indirect blocks; название указывает на то, что для того, чтобы найти блок данных, сначала нужно найти его номер в indirect blocks.

### Создание файловых систем

Прежде чем раздел может быть смонтирован (или использован), на него сначала должна быть установлена файловая система, создающая файловую систему с ext2, это процесс создания inode и блоков данных.

Этот процесс эквивалентен инициализации раздела. Команда для создания файловой системы называется mkfs .

Команда выдается следующим образом:

```bash
mkfs [-c] [ -t fstype ] filesystem [ blocks ]
```

например:

```bash
mkfs -t ext2 /dev/fd0 # Make a ext2 filesystem on a floppy
```

где:

-c

принудительно выполняет проверку на наличие поврежденных блоков

-t fstype

указывает тип файловой системы. Для большинства типов файловых систем для этого существует сокращение, например: mkfs -t ext2 также может называться ext2 mke2fs или mkfs.ext2 mkfs.ext2, а mkfs -t vfat или mkfs -t msdos также могут называться mkfs.vfat, mkfs.msdos или mkdosfs

filesystem

это либо файл устройства, связанный с разделом или устройством, либо каталог, в котором смонтирована файловая система (используется для удаления старой файловой системы и создания новой).

{% hint style="info" %}
Создание файловой системы на устройстве с существующей файловой системой приведет к удалению всех данных из старой файловой системы
{% endhint %}

### Монтирование и размонтирование

Linux представляет все файловые системы в виде одного дерева каталогов. Следовательно, чтобы добавить новое устройство с файловой системой, его файловая система должна быть включена в это дерево каталогов. Это делается путем присоединения новой файловой системы к существующей (предпочтительно пустой) директории , которая является частью существующего дерева каталогов - точка "монтирования".

Чтобы подключить новую файловую систему к иерархии монтирования и размонтирования каталогов, вы должны подключить соответствующий файл устройства. Сначала вам нужно создать точку монтирования - каталог, к которому будет подключено устройство. Поскольку каталоги являются частью файловой системы , точка монтирования существует на ранее подключенном устройстве. Она должна быть пустой. В противном случае файлы в каталоге будут недоступны , пока устройство подключено к нему, но снова появятся после того, как устройство будет отключено (или размонтировано). Этот тип защиты с помощью скрытности иногда используется для сокрытия информации от случайного наблюдателя.

Чтобы подключить устройство, используйте команду mount:

```bash
mount [options] device_file mount_point
```



На некоторых устройствах mount определяет, какой тип файловой системы существует на устройстве, однако более привычно использовать mount в виде:

```bash
mount [options] -t file_system_type device_file mount_point
```

Как правило, только пользователь root может использовать команду mount - в основном из-за того, что файлы устройства принадлежат пользователю root. Например, чтобы смонтировать первый раздел на втором жестком диске (IDE) из каталога /usr и предположить, что он содержит файловую систему ext2, вы должны ввести команду:

```bash
mount -t ext2 /dev/hdb1 /usr
```

Чтобы увидеть, какие устройства у вас подключены в данный момент, просто введите команду mount . Некоторые примеры выходных данных:

```bash
pirog@pirog:~$ mount
sysfs on /sys type sysfs (rw,nosuid,nodev,noexec,relatime)
proc on /proc type proc (rw,nosuid,nodev,noexec,relatime)
udev on /dev type devtmpfs (rw,nosuid,relatime,size=8126032k,nr_inodes=2031508,mode=755,inode64)
devpts on /dev/pts type devpts (rw,nosuid,noexec,relatime,gid=5,mode=620,ptmxmode=000)
tmpfs on /run type tmpfs (rw,nosuid,nodev,noexec,relatime,size=1632744k,mode=755,inode64)
/dev/sda2 on / type ext4 (rw,relatime)
```

Каждая строка показывает, на каком устройстве подключен файл, где он подключен по стандарту iso9660, к какому типу файловой системы относится каждый раздел и как он подключен (ro = только для чтения, rw = чтение/запись). Обратите внимание на странную запись в третьей строке - файловая система proc. Это специальная "виртуальная" файловая система, используемая системами Linux для хранения информации о ядре, процессах и текущем использовании ресурсов. На самом деле это часть системной памяти. Другими словами, ядро выделяет область памяти, в которой оно хранит информация о системе. Эта же область монтируется в файловую систему, чтобы пользовательские программы имели доступ к этой информации.

Информация, содержащаяся в файловой системе proc, также может быть использована для того, чтобы узнать, какие файловые системы смонтированы, выполнив команду:

```bash
pirog@pirog:~$ cat /proc/mounts
sysfs /sys sysfs rw,nosuid,nodev,noexec,relatime 0 0
proc /proc proc rw,nosuid,nodev,noexec,relatime 0 0
udev /dev devtmpfs rw,nosuid,relatime,size=8126032k,nr_inodes=2031508,mode=755,inode64 0 0
devpts /dev/pts devpts rw,nosuid,noexec,relatime,gid=5,mode=620,ptmxmode=000 0 0
tmpfs /run tmpfs rw,nosuid,nodev,noexec,relatime,size=1632744k,mode=755,inode64 0 0
/dev/sda2 / ext4 rw,relatime 0 0
securityfs /sys/kernel/security securityfs rw,nosuid,nodev,noexec,relatime 0 0
tmpfs /dev/shm tmpfs rw,nosuid,nodev,inode64 0 0
tmpfs /run/lock tmpfs rw,nosuid,nodev,noexec,relatime,size=5120k,inode64 0 0
cgroup2 /sys/fs/cgroup cgroup2 rw,nosuid,nodev,noexec,relatime,nsdelegate,memory_recursiveprot 0 0
pstore /sy
```

Разница между /etc/mtab и /proc/mounts заключается в том, что /etc/mtab - это администрирование пользовательского пространства, которое поддерживается mount, а /proc/ mounts - это информация, хранящаяся в ядре. Последнее отражает информацию в пользовательском пространстве. Из-за этих различных реализаций информация в /proc/mounts всегда актуальна, в то время как информация в /etc/mtab может стать противоречивой.

Чтобы освободить устройство и отсоединить его от файловой системы, используется команда umount. Она выдается в виде: amount

```bash
umount device_file
```

или

```bash
umount mount_point
```

Например:

```bash
umount /dev/sdb2

umount /mnt
```

Опять же, для этого вы должны быть пользователем root или пользователем с привилегиями. Вы не можете отключить устройство/точку монтирования, которые используются пользователем (например, текущий рабочий каталог пользователя находится в точке монтирования) или используются процессом. Вы также не можете отключить устройства/ точки подключения, к которым, в свою очередь, подключены устройства.

Системе необходимо подключать устройства во время загрузки. В обычной UNIX-системе существует файл, который управляет поведением подключаемых устройств во время загрузки. В Linux этот файл называется /etc/fstab. Строки из файла /etc/fstab имеют следующий формат:

```
device_file mount_point file_system_type mount_options [n] [n]
```

Первые три поля говорят сами за себя; четвертое поле, mount\_options, определяет способ подключения устройства (оно включает информацию о режиме доступа ro / rw, разрешениях на выполнение и другую информацию) - информацию об этом можно найти на страницах руководства по монтированию (обратите внимание, что это поле обычно содержит слово "настройки по умолчанию" ). Пятое и шестое поля используются системными утилитами dump и fsck соответственно - подробности смотрите в следующем разделе.

Существует также файл под названием /etc/mtab . В нем перечислены подключенные в данный момент разделы в формате fstab.

### Systemd Mount Units

В дистрибутивах Linux, использующих systemd, есть дополнительный способ монтирования файловых систем. Вместо использования файла fstab для постоянного монтирования файловая система может быть сконфигурирована с помощью файла модуля монтирования. Этот файл модуля монтирования содержит сведения о конфигурации, необходимые системе для постоянного монтирования файловых систем.

Файл модуля монтирования systemd имеет определенное соглашение об именовании. Имя файла указывает на абсолютный каталог, в который он будет монтироваться , а расширение файла - .mount . В названии файла первая и последняя косая черта (/), обозначающие путь монтирования , удаляются, а оставшиеся косые черты преобразуются в тире (-). Таким образом, если, например, файловая система подключена к точке монтирования `/home/user/data/` файл модуля монтирования должен иметь имя `home-user-data.mount`.

В файле монтирования определены три обязательных раздела: \[Unit] , \[Mount] и \[Install] . Пример файла модуля монтирования /etc/systemd/system/snap-firefox-5783.mount:

```bash
pirog@pirog:/etc/systemd/system$ cat snap-firefox-5783.mount 
[Unit]
Description=Mount unit for firefox, revision 5783
After=snapd.mounts-pre.target
Before=snapd.mounts.target

[Mount]
What=/var/lib/snapd/snaps/firefox_5783.snap
Where=/snap/firefox/5783
Type=squashfs
Options=nodev,ro,x-gdu.hide,x-gvfs-hide
LazyUnmount=yes

[Install]
WantedBy=snapd.mounts.target
WantedBy=multi-user.target
```

Чтобы протестировать конфигурацию, перезагрузите демон systemctl с помощью команды systemctl daemon-reload, а затем вручную запустите файл модуля монтирования командой systemctl start, за которой следует файл модуля монтирования. В нашем примере это будет systemctl start snap-firefox-5783.mount . Далее вы можете проверить, правильно ли была смонтирована файловая система, получив обзор из mount . Если все работает так, как ожидалось, выполните постоянное монтирование файловой системы, включив модуль монтирования файла с помощью команды systemctl enable snap-firefox-5783.mount .

### Swap

Пространство подкачки в Linux - это раздел или файл, который используется для перемещения содержимого неактивных страниц оперативной памяти, когда оперативная память заполняется. Linux может использовать либо обычный файл в файловой системе, либо отдельный раздел подкачки для пространства подкачки. Раздел подкачки работает быстрее, но при этом проще изменить размер файла подкачки (нет необходимости разбивать на разделы весь жесткий диск и, возможно, устанавливать все с нуля). Когда вы знаете, сколько места для подкачки вам нужно, вам следует использовать раздел подкачки, но если вы сомневаетесь, вы можете использовать сначала файл подкачки и некоторое время пользоваться системой, чтобы понять, какой объем подкачки вам нужен, а затем создать раздел подкачки, когда будете уверены в его размере. Рекомендуется использовать отдельный раздел, поскольку это исключает вероятность фрагментации файловой системы, которая может снизить производительность. Кроме того, используя отдельный раздел подкачки, можно гарантировать, что область подкачки находится в самом быстром месте на диске. На современных жестких дисках это находится в начале пластин (внешний обод, первый цилиндры). Можно использовать несколько разделов подкачки и/или файлов подкачки одновременно. Это означает, что если вам только иногда требуется необычный объем пространства подкачки, вы можете создать дополнительный файл подкачки в такие моменты, вместо того чтобы постоянно выделять весь объем.

Команда mkswap используется для инициализации раздела подкачки  или файла подкачки. Раздел или файл должны существовать, прежде чем их можно будет инициализировать. Раздел подкачки создается с помощью инструмента разбиения диска на разделы, такого как fdisk, а файл подкачки может быть создан с помощью: /dev/zero:

```bash
dd if=/dev/zero of=swapfile bs=1024 count=65535
```

Когда раздел или файл созданs, он может быть инициализирован с помощью:

```bash
mkswap {device|file}
```

С помощью swapon используется инициализированное пространство подкачки. Эта команда swapon сообщает ядру, что пространство подкачки может быть использовано. В качестве аргумента указывается путь к пространству подкачки, поэтому для запуска подкачки временного файла подкачки можно использовать следующую команду:

```bash
swapon /dev/sdc3
```

Пространства подкачки можно использовать автоматически, указав их в файле /etc/fstab:

```
/dev/sdc3 none swap sw 0 0
/swapfile none swap sw 0 0
```

Скрипты запуска запустят команду swapon -a , которая запустит замену во всех пространствах подкачки, перечисленных в /etc/fstab . Поэтому команда swapon обычно используется только тогда, когда требуется дополнительная замена. Вы можете отслеживать использование пространства подкачки с помощью free. В нем будет отображаться общий объем используемого пространства подкачки:

```bash
pirog@pirog:/etc/systemd/system$ free
               total        used        free      shared  buff/cache   available
Mem:        16327420     1304692    13243120       33968     2119628    15022728
Swap:        4194300           0     4194300

```

В первой строке выходных данных ( Mem: ) отображается физическая память. В столбце total отображается физическая память, используемая ядром, которая загружается в оперативную память во время процесса загрузки. В столбце "использовано" отображается объем используемой памяти (во второй строке буферы не учитываются). В столбце "Свободно" отображается полностью неиспользуемая память. В столбце shared отображается объем памяти, используемый tmpfs (shmem в /proc/meminfo); в столбце buffers отображается текущий размер дискового буферного кэша.

В последней строке ( Swap: ) приведена аналогичная информация о пространствах подкачки. Если в этой строке все нули, пространство подкачки не активируется. Ту же информацию, но в несколько ином формате, можно отобразить, используя cat в файле /proc/meminfo /proc/meminfo :

Чтобы отключить устройство или файл подкачки, используйте команду swapoff:

### UUIDs

Термин UUID расшифровывается как Универсальный уникальный идентификатор. Это 128-битное число, которое можно использовать для идентификации практически всего. Генерирование таких UUID может быть выполнено с помощью соответствующего программного обеспечения. Существует 5 различных версий UUID, все они используют (псевдо) случайный элемент, текущее системное время и некоторые, в основном, уникальные аппаратные идентификаторы, например MAC-адрес. Теоретически существует очень и очень незначительная вероятность того, что UUID не будет уникальным, но на практике это представляется невозможным.

В Linux поддержка UUID была запущена в пакете e2fsprogs. В файловой системе UUID используются для представления конкретной файловой системы. Например, вы можете использовать UUID в файле /etc/fstab для представления раздела, который вы хотите смонтировать.

Обычно UUID представлен в виде 32 шестнадцатеричных цифр, сгруппированных в последовательности из 8,4,4,4 и 12 цифр, разделенных дефисами. Вот как выглядит запись в fstab со спецификатором UUID:

```bash
UUID=652b786e-b87f-49d2-af23-8087ced0c828 / ext4 errors=remount-ro,noatime 0 1
```

Возможно, вам интересно узнать об использовании Uuid в fstab, поскольку имена устройств работают нормально. Идентификаторы UUID пригодятся, когда диски перемещаются в разные разъемы или на разные компьютеры, на компьютере установлено несколько операционных систем или в других случаях, когда имена устройств могут изменяться без изменения файловой системы. Пока файловая система не меняется, UUID остается неизменным.

Обратите внимание на "до тех пор, пока файловая система не изменится". Это означает, что при переформатировании раздела UUID изменится. Например, когда вы используете mke2fs для переформатирования раздела /dev/sda3 , UUID будет изменен. Таким образом, если вы используете UUID в /etc/fstab , вам также придется изменить их.

Если вы хотите узнать UUID определенного раздела, используйте blkid /path/to/partition:

```bash
# blkid /dev/sda5
 /dev/sda5: UUID="24df5f2a-a23f-4130-ae45-90e1016031bc" TYPE="swap"
```

{% hint style="info" %}
Обратите внимание, что можно создать новую файловую систему и при этом сохранить тот же UUID, что и раньше, по крайней мере, для файловых систем типа ext.
{% endhint %}

```bash
# tune2fs /dev/sda5 -U 24df5f2a-a23f-4130-ae45-90e1016031bc
```

{% hint style="info" %}
В большинстве дистрибутивов Linux вы можете сгенерировать свои собственные UUID с помощью команды uuidgen .
{% endhint %}

### sync

Для повышения производительности файловых систем Linux многие операции выполняются в буферах файловой системы, хранящихся в оперативной памяти. Чтобы фактически сбросить данные, содержащиеся в этих буферах, на диск, используется команда sync.

Функция sync вызывается автоматически в нужный момент при перезагрузке или остановке системы. Вам редко потребуется использовать эту команду самостоятельно. Функция sync может использоваться, например, для принудительной синхронизации данных с USB-устройством перед его удалением из вашей системы.

**sync** не имеет каких-либо параметров, влияющих на выполнение операции, поэтому, когда вам нужно, просто выполните команду.
