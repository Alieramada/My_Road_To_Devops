# Урок 5.1.

## Введение <a href="#sec.5.1_01-in" id="sec.5.1_01-in"></a>

В этом уроке мы рассмотрим базовую терминологию, связанную с учётными записями, контролем доступа и безопасностью локальных систем Linux, инструменты интерфейса командной строки (CLI) в системе Linux для базового контроля доступа и основные файлы для поддержки учётных записей пользователей и групп, в том числе те, которые используются для повышения привилегий.

Базовая система безопасности в Linux-системах построена по образцу средств контроля доступа в Unix, которые, несмотря на то, что им почти пятьдесят лет, довольно эффективны по сравнению с некоторыми популярными потребительскими операционными системами, появившимися гораздо позже. Даже некоторые другие популярные операционные системы на базе Unix склонны «допускать вольности», ориентированные на «простоту доступа», в то время как Linux этого не делает.

Современные среды и интерфейсы рабочего стола Linux упрощают создание учётных записей пользователей и управление ими, а также часто автоматизируют назначение прав доступа при входе пользователя в систему — например, к дисплею, аудио и другим сервисам — практически не требуя вмешательства системного администратора. Однако важно понимать основные концепции базовой операционной системы Linux.

## Учетные записи <a href="#accounts" id="accounts"></a>

Безопасность включает в себя множество концепций, одна из наиболее распространённых — это общая концепция управления доступом. Прежде чем приступить к управлению доступом к файлам, таким как право собственности и разрешения, необходимо понять основные концепции учётных записей _пользователей_ Linux, которые делятся на несколько типов.

У каждого пользователя в системе Linux есть учётная запись, которая, помимо информации для входа (например, имени пользователя и пароля), также определяет, как и где пользователь может взаимодействовать с системой. Привилегии и контроль доступа определяют «границы», в пределах которых может работать каждый пользователь.

## **Идентификаторы (UID/GID)**

_Идентификаторы пользователей_ и _групп_ (UID/GID) — это базовые, перечисляемые ссылки на учётные записи. Ранние реализации были ограничены 16-битными (значения от 0 до 65535) целыми числами, но системы XXI века поддерживают 64-битные UID и GID. Пользователи и группы перечисляются независимо друг от друга, поэтому один и тот же идентификатор может относиться как к пользователю, так и к группе.

У каждого пользователя есть не только UID, но и _основной GID_. Основной GID пользователя может быть уникальным только для этого пользователя и может не использоваться другими пользователями. Однако эта группа может быть общей для многих пользователей. Помимо этих основных групп, каждый пользователь может быть членом и других групп.

По умолчанию в системах Linux каждый пользователь назначается в группу с тем же именем, что и его имя пользователя, и с тем же GID, что и его UID. Например, создайте нового пользователя с именем `newuser` и по умолчанию его группа по умолчанию также будет называться `newuser`

## **Учетная запись суперпользователя**

В Linux учётная запись суперпользователя — это `root`, которая всегда имеет UID 0. Суперпользователя иногда называют _системным администратором_, и он имеет неограниченный доступ и контроль над системой, включая других пользователей.

Группа по умолчанию для суперпользователя имеет идентификатор GID `0` и также называется `root`. Домашний каталог суперпользователя — это выделенный каталог верхнего уровня `/root`, доступный только самому пользователю `root`.

## **Стандартные учетные записи пользователей**

Все учётные записи, кроме `root` технически являются обычными учётными записями пользователей, но в системе Linux разговорный термин _учётная запись пользователя_ часто означает «обычную» (непривилегированную) учётную запись пользователя. Обычно они обладают следующими свойствами, за некоторыми исключениями:

* Идентификаторы пользователей начинаются с 1000 (4 цифры), хотя в некоторых устаревших системах они могут начинаться с 500.
* Определённый домашний каталог, обычно подкаталоги `/home` в зависимости от локальной конфигурации.
* Определённая оболочка для входа в систему. В Linux оболочкой по умолчанию обычно является _Bourne Again Shell_ (`/bin/bash`), хотя могут быть доступны и другие.

Если в атрибутах учётной записи пользователя нет допустимой оболочки, пользователь не сможет открыть интерактивную оболочку. Обычно `/sbin/nologin` используется в качестве недопустимой оболочки. Это может быть целесообразно, если пользователь будет проходить аутентификацию только для служб, отличных от консоли или доступа по SSH, например, только для доступа по безопасному FTP (`sftp`).

{% hint style="info" %}
Чтобы избежать путаницы, в дальнейшем термин _«учётная запись пользователя»_ будет применяться только к стандартным или обычным учётным записям пользователей. Например, _«системная учётная запись»_ будет использоваться для обозначения учётной записи пользователя Linux системного типа.
{% endhint %}

## **Системные учетные записи**

_Системные учётные записи_ обычно создаются заранее во время установки системы. Они предназначены для объектов, программ и служб, которые не будут работать от имени суперпользователя. В идеальном мире все они были бы объектами операционной системы.

Системные учетные записи различаются, но их атрибуты включают:

* UID обычно не превышают 100 (двухзначное число) или 500–1000 (трёхзначное число).
* Либо _нет_ выделенного домашнего каталога, либо каталог, который обычно не находится в `/home`.
* Нет действительной оболочки входа (обычно `/sbin/nologin`), за редкими исключениями.

Большинство системных учётных записей в Linux никогда не входят в систему и не нуждаются в определении оболочки в своих атрибутах. Многие процессы, принадлежащие системным учётным записям и выполняемые ими, разветвляются в собственную среду системой управления и выполняются от имени указанной системной учётной записи. Эти учётные записи обычно имеют ограниченные или, чаще всего, _никаких_ привилегий.

{% hint style="info" %}
С точки зрения LPI Linux Essentials, системные учетные записи представляют собой UID <1000 с 2-или 3-значными UID (и GID).
{% endhint %}

В целом, системные учётные записи _не должны_ иметь действующую оболочку для входа. В большинстве случаев обратное является проблемой безопасности.

## **Учетные записи служб**

_Учетные записи служб_ обычно создаются при установке и настройке служб. Как и системные учетные записи, они предназначены для объектов, программ и служб, которые не будут работать от имени суперпользователя.

Во многих документах системные и служебные учётные записи похожи и часто взаимозаменяемы. Это включает в себя расположение домашних каталогов, которые обычно находятся за пределами `/home`, если они вообще определены (служебные учётные записи чаще имеют домашние каталоги, чем системные), а также отсутствие допустимой оболочки входа. Хотя строгого определения не существует, основное различие между системными и служебными учётными записями сводится к UID/GID.

Системная учетная запись

UID/GID <100 (двухзначное число) или <500-1000 (трехзначное число)

Учетная запись службы

UID/GID >1000 (4+ цифры), но не «стандартная» или «обычная» учётная запись пользователя, а учётная запись для сервисов с UID/GID >1000 (4+ цифры)

Некоторые дистрибутивы Linux по-прежнему имеют предварительно зарезервированные учетные записи служб с UID <100, и их также можно считать системными учетными записями, даже если они не создаются при установке системы. Например, в дистрибутивах Linux на базе Fedora (включая Red Hat) пользователь веб-сервера Apache имеет UID (и GID) 48, что явно является системной учетной записью, несмотря на наличие домашнего каталога (обычно по адресу `/usr/share/httpd` или `/var/www/html/`).

{% hint style="info" %}
С точки зрения LPI Linux Essentials, системные учетные записи имеют UID <1000, а учетные записи обычных пользователей - UID > 1000. Поскольку учетные записи обычных пользователей > 1000, эти UID также могут включать учетные записи служб.
{% endhint %}

## **Оболочки входа в систему и домашние каталоги**

Некоторые учётные записи имеют оболочку для входа в систему, в то время как другие не имеют её в целях безопасности, поскольку им не требуется интерактивный доступ. Оболочкой для входа в систему по умолчанию в большинстве дистрибутивов Linux является _Bourne Again Shell_, или `bash`, но могут быть доступны и другие оболочки, например C Shell (`csh`), Korn shell (`ksh`) или Z shell (`zsh`), и это лишь некоторые из них.

Пользователь может изменить свою оболочку входа в систему с помощью команды `chsh` . По умолчанию команда работает в интерактивном режиме и выводит запрос о том, какую оболочку следует использовать. В качестве ответа должен быть указан полный путь к двоичному файлу оболочки, как показано ниже:

```sh
$ chsh

Changing the login shell for emma
Enter the new value, or press ENTER for the default
	Login Shell [/bin/bash]: /usr/bin/zsh
```

Вы также можете запустить команду в неинтерактивном режиме, указав после параметра `-s` путь к двоичному файлу, например:

```sh
$ chsh -s /usr/bin/zsh
```

У большинства учётных записей есть определённый домашний каталог. В Linux это, как правило, единственное место, где у учётной записи пользователя есть гарантированный доступ на запись, за некоторыми исключениями (например, временные области файловой системы). Однако некоторые учётные записи намеренно настраиваются так, чтобы у них не было доступа на запись даже в собственный домашний каталог в целях безопасности.

## Получение информации о Ваших Пользователях <a href="#getting_information_about_your_users" id="getting_information_about_your_users"></a>

Отображение базовой информации о пользователе — распространённая повседневная практика в системе Linux. В некоторых случаях пользователям необходимо переключаться между пользователями и повышать привилегии для выполнения задач с повышенными правами.

Даже пользователи могут просматривать атрибуты и получать к ним доступ из командной строки с помощью приведённых ниже команд. Базовая информация в ограниченном контексте не требует привилегий.

Чтобы вывести текущую информацию о пользователе в командной строке, достаточно ввести команду из двух букв `id`. Вывод будет зависеть от вашего идентификатора входа:

```sh
$ id
uid=1024(emma) gid=1024(emma) 1024(emma),20(games),groups=10240(netusers),20480(netadmin) context=unconfined_u:unconfined_r:unconfined_t:s0-s0:c0.c1023
```

В предыдущем списке у пользователя (`emma`) есть идентификаторы, которые разбиваются следующим образом:

* `1024` = Идентификатор пользователя (UID), за которым следует имя пользователя (обычное имя, также называемое логином) в скобках.
* `1024` = _основной_ идентификатор группы (GID), за которым следует название группы (общее название) в скобках.
* Список дополнительных GID (имен групп), к которым также принадлежит пользователь.

Чтобы узнать, когда пользователи в последний раз входили в систему, выполните команду `last`:

```sh
$ last
emma     pts/3        ::1              Fri Jun 14 04:28   still logged in
reboot   system boot  5.0.17-300.fc30. Fri Jun 14 04:03   still running
reboot   system boot  5.0.17-300.fc30. Wed Jun  5 14:32 - 15:19  (00:46)
reboot   system boot  5.0.17-300.fc30. Sat May 25 18:27 - 19:11  (00:43)
reboot   system boot  5.0.16-100.fc28. Sat May 25 16:44 - 17:06  (00:21)
reboot   system boot  5.0.9-100.fc28.x Sun May 12 14:32 - 14:46  (00:14)
root     tty2                          Fri May 10 21:55 - 21:55  (00:00)
	...
```

Информация, указанная в столбцах, может отличаться, но некоторые примечательные записи в предыдущем списке:

* Пользователь (`emma`) вошёл в систему через сеть (псевдо TTY `pts/3`) и до сих пор находится в системе.
* Время текущей загрузки указано вместе с ядром. В приведённом выше примере это произошло примерно за 25 минут до входа пользователя в систему.
* Суперпользователь (`root`) ненадолго вошёл в систему через виртуальную консоль (TTY `tty2`) в середине мая.

Вариантом команды `last` является команда `lastb`, которая выводит список всех последних неудачных попыток входа в систему.

Команды `who` и `w` содержат список только активных учетных записей в системе:

```bash
$ who
emma  pts/3        2019-06-14 04:28 (::1)

$ w
 05:43:41 up  1:40,  1 user,  load average: 0.25, 0.53, 0.51
USER     TTY        LOGIN@   IDLE   JCPU   PCPU WHAT
emma  pts/3     04:28    1:14m  0.04s  0.04s -bash
```

Обе команды выводят примерно одинаковую информацию. Например, один пользователь (`emma`) вошёл в систему с помощью псевдотерминала (`pts/3`), и время входа — 04:28.

Команда `w` содержит дополнительную информацию, включая следующую:

* Текущее время и как долго система была в рабочем состоянии
* Сколько пользователей подключено
* _Средняя загрузка_ за последние 1, 5 и 15 минут

И дополнительная информация для каждого активного сеанса пользователя.

* Общее время загрузки процессора (`IDLE`, `JCPU` и `PCPU`)
* Текущий процесс (`-bash`). Общее время использования ЦП этим процессом — последний элемент (`PCPU`).

Обе команды имеют дополнительные опции для отображения различной дополнительной информации.

## Переключение пользователей и повышение привилегий <a href="#switching_users_and_escalating_privilege" id="switching_users_and_escalating_privilege"></a>

В идеальном мире пользователям никогда не пришлось бы повышать уровень доступа для выполнения своих задач. Система всегда «просто работала бы», и всё было бы настроено для различных уровней доступа.

К счастью для нас, Linux — по умолчанию — работает именно так для большинства пользователей, которые не являются системными администраторами, несмотря на то, что всегда следует модели безопасности _с наименьшими привилегиями_.

Однако существуют команды, которые при необходимости позволяют повысить уровень привилегий. Две наиболее важные из них — `su` и `sudo`.

В большинстве современных систем Linux команда `su` используется только для повышения привилегий до уровня root, который является пользователем по умолчанию, если после имени команды не указано имя пользователя. Хотя эту команду можно использовать для переключения на другого пользователя, это не рекомендуется: пользователи должны входить в систему с другой системы, по сети или с физической консоли или терминала в системе.

```sh
emma ~$ su -
Password:
root ~#
```

После ввода пароля суперпользователя (`root`) пользователь получает оболочку суперпользователя (обратите внимание на `#` в конце командной строки) и становится суперпользователем (`root`).

Совместное использование паролей — очень плохая практика с точки зрения безопасности, поэтому в современной системе Linux команда `su` должна использоваться очень редко, если вообще использоваться.

Символ доллара (`$`) должен завершать приглашение командной строки для оболочки непривилегированного пользователя, а символ фунта (`#`) должен завершать приглашение командной строки для оболочки суперпользователя (`root`). Настоятельно рекомендуется _никогда_ не изменять последний символ любого приглашения, так как эта общепринятая номенклатура используется в учебных материалах, в том числе в этих.

{% hint style="info" %}
Никогда не переключайтесь на суперпользователя (`root`) без передачи параметра оболочки входа (`-`). Если только производитель ОС или программного обеспечения не указал иное, при необходимости `su` всегда выполняйте `su -` с крайне ограниченными исключениями. При использовании в режиме суперпользователя с полными правами среды пользователя могут вызывать нежелательные изменения конфигурации и проблемы.
{% endhint %}

В чём самая большая проблема при использовании `su` для переключения на суперпользователя (`root`)? Если сеанс обычного пользователя был взломан, пароль суперпользователя (`root`) может быть перехвачен. Именно здесь на помощь приходит «Switch User Do» (или «Superuser Do»):

```sh
$ cat /sys/devices/virtual/dmi/id/board_serial
cat: /sys/devices/virtual/dmi/id/board_serial: Permission denied

$ sudo cat /sys/devices/virtual/dmi/id/board_serial
[sudo] password for emma:
/6789ABC/
```

В предыдущем списке пользователь пытается найти серийный номер своей системной платы. Однако разрешение отклонено, так как эта информация является конфиденциальной.

Однако при использовании `sudo` пользователь вводит свой пароль для подтверждения личности. Если он был авторизован в конфигурации `sudoers` для выполнения этой команды с привилегиями и разрешёнными параметрами, она будет работать.

{% hint style="info" %}
По умолчанию первая авторизованная команда `sudo` будет подтверждать подлинность последующих команд `sudo` в течение (очень короткого) периода времени. Это настраивается системным администратором.
{% endhint %}

## Файлы управления доступом <a href="#access_control_files" id="access_control_files"></a>

Почти во всех операционных системах есть набор мест, используемых для хранения элементов управления доступом. В Linux это, как правило, текстовые файлы, расположенные в каталоге `/etc`, где должны храниться файлы конфигурации системы. По умолчанию этот каталог доступен для чтения каждому пользователю системы, но для записи — только `root`.

Основными файлами, связанными с учетными записями пользователей, атрибутами и контролем доступа, являются:

`/etc/passwd`

В этом файле хранится основная информация о пользователях системы, включая UID и GID, домашний каталог, оболочку и т. д. Несмотря на название, здесь не хранятся пароли.

`/etc/group`

В этом файле хранится основная информация обо всех группах пользователей в системе, например, название группы, GID и участники.

`/etc/shadow`

Здесь хранятся пароли пользователей. Они хешируются для обеспечения безопасности.

`/etc/gshadow`

В этом файле хранится более подробная информация о группах, включая хешированный пароль, который позволяет пользователям временно становиться членами группы, список пользователей, которые могут стать членами группы в любое время, и список администраторов группы.

{% hint style="info" %}
Эти файлы не предназначены для прямого редактирования и не должны редактироваться напрямую. В этом уроке рассматривается только информация, хранящаяся в этих файлах, а не их редактирование.
{% endhint %}

По умолчанию каждый пользователь может входить в `/etc` и читать файлы `/etc/passwd` и `/etc/group`. Также по умолчанию ни один пользователь, кроме `root`, не может читать файлы `/etc/shadow` или `/etc/gshadow`.

В системах Linux также есть файлы, связанные с повышением базовых привилегий, например, в командах `su` и `sudo`. По умолчанию они доступны только пользователю `root`

`/etc/sudoers`

Этот файл определяет, кто и как может использовать `sudo` команду.

`/etc/sudoers.d`

Этот каталог может содержать файлы, которые дополняют настройки в `sudoers` файле.

С точки зрения экзамена LPI Linux Essentials, достаточно знать путь и имя файла конфигурации sudo по умолчанию `/etc/sudoers`. Его настройка выходит за рамки этих материалов.

{% hint style="info" %}
Несмотря на то, что `/etc/sudoers` является текстовым файлом, его ни в коем случае нельзя редактировать напрямую. Если необходимо внести какие-либо изменения в его содержимое, это следует делать с помощью утилиты `visudo`
{% endhint %}

## **/etc/passwd**

Файл `/etc/passwd` обычно называют «файлом паролей». Каждая строка содержит несколько полей, разделённых двоеточием (`:`). Несмотря на название, в настоящее время в этом файле не хранится фактический односторонний хэш пароля.

Типичный синтаксис для строки в этом файле следующий:

```
USERNAME:PASSWORD:UID:GID:GECOS:HOMEDIR:SHELL
```

Где:

`USERNAME`

Имя пользователя, также известное как login (имя), такие как `root`, `nobody`, `emma`.

`PASSWORD`

Устаревшее расположение хэша пароля. Почти всегда `x` указывает на то, что пароль хранится в файле `/etc/shadow`.

`UID`

Идентификатор пользователя (UID), такой как `0`, `99`, `1024`.

`GID`

Идентификатор группы по умолчанию (GID), такой как `0`, `99`, `1024`.

`GECOS`

Список пользователей в формате CSV, включая имя, местоположение, номер телефона. Например: `Emma Smith,42 Douglas St,555.555.5555`

`HOMEDIR`

Путь к домашнему каталогу пользователя, например, `/root`, `/home/emma` и т.д.

`SHELL`

Оболочка по умолчанию для этого пользователя, например `/bin/bash`, `/sbin/nologin`, `/bin/ksh` и т.д.

Например, следующая строка описывает пользователя `emma`:

```shell
emma:x:1000:1000:Emma Smith,42 Douglas St,555.555.5555:/home/emma:/bin/bash
```

**Понимание поля GECOS**

Поле GECOS содержит три (3) или более полей, разделённых запятыми (`,`), то есть список _значений, разделённых запятыми_ (CSV). Несмотря на отсутствие обязательного стандарта, поля обычно располагаются в следующем порядке:

```
NAME,LOCATION,CONTACT
```

Где:

`NAME`

Это «полное имя» пользователя или «имя программы» в случае учётной записи службы.

`LOCATION`

Обычно это физическое местоположение пользователя в здании, номер комнаты или контактный отдел или сотрудник в случае служебной учётной записи.

`CONTACT`

содержит контактную информацию, такую как номер домашнего или рабочего телефона.

Дополнительные поля могут содержать дополнительную контактную информацию, например номер домашнего телефона или адрес электронной почты. Чтобы изменить информацию в поле GECOS, используйте команду `chfn` и ответьте на вопросы, как показано ниже. Если после названия команды не указано имя пользователя, вы измените информацию для текущего пользователя:

```sh
$ chfn

Changing the user information for emma
Enter the new value, or press ENTER for the default
	Full Name: Emma Smith
	Room Number []: 42
	Work Phone []: 555.555.5555
	Home Phone []: 555.555.6666
```

## **/etc/group**

Файл `/etc/group` содержит поля, которые всегда разделяются двоеточием (`:`), и хранит основную информацию о группах в системе. Иногда его называют «групповым файлом». Синтаксис каждой строки:

```
NAME:PASSWORD:GID:MEMBERS
```

Где:

`NAME`

\- это название группы, например, `root`, `users`, `emma` и т.д.

`PASSWORD`

устаревшее расположение необязательного хэша пароля группы. Почти всегда `x` указывает на то, что пароль (если он задан) хранится в файле `/etc/gshadow`.

`GID`

Идентификатор группы (GID), например `0`, `99`, `1024`.

`MEMBERS`

список имён пользователей, являющихся членами группы, разделённых запятыми, например `jsmith,emma`.

В приведенном ниже примере показана строка, содержащая информацию о  группе `students`:

```sh
students:x:1023:jsmith,emma
```

Пользователю не нужно указывать себя в поле «Участники», если группа является основной для пользователя. Если пользователь указан, то это избыточно, то есть функциональность не меняется, независимо от того, указан он или нет.

{% hint style="info" %}
Использование паролей для групп выходит за рамки данного раздела, однако, если пароль задан, его хэш сохраняется в файле `/etc/gshadow`. Это также выходит за рамки данного раздела.
{% endhint %}

## **/etc/shadow**

В следующей таблице перечислены атрибуты, хранящиеся в файле `/etc/shadow`, который обычно называют «shadow file». Файл содержит поля, которые всегда разделяются двоеточием (`:`). Хотя в файле много полей, большинство из них выходят за рамки этого урока, за исключением первых двух.

Основной синтаксис для строки в этом файле следующий:

```
USERNAME:PASSWORD:LASTCHANGE:MINAGE:MAXAGE:WARN:INACTIVE:EXPDATE
```

Где:

`USERNAME`

Имя пользователя (такое же, как `/etc/passwd`), как `root`, `nobody`, `emma`.

`PASSWORD`

Односторонний хэш пароля, включая предшествующую соль. Например: `!!`, `!$1$01234567$ABC…​`, `$6$012345789ABCDEF$012…​`.

{% hint style="info" %}
**Соль (salt)** — это случайная строка, которая добавляется к паролю перед хэшированием. Это делает каждый хэш уникальным, даже если два пользователя используют один и тот же пароль.&#x20;
{% endhint %}



`LASTCHANGE`

Дата последнего изменения пароля в днях с момента «эпохи», например `17909`.

`MINAGE`

Минимальный срок действия пароля в днях.

`MAXAGE`

Максимальный срок действия пароля в днях.

`WARN`

Период предупреждения до истечения срока действия пароля, в днях.

`INACTIVE`

Максимальный срок действия пароля после истечения срока действия, в днях.

`EXPDATE`

Дата истечения срока действия пароля в днях, прошедших с момента “эпохи”.

В приведённом ниже примере вы можете увидеть образец записи из файла `/etc/shadow` . Обратите внимание, что некоторые значения, такие как `INACTIVE` и `EXPDATE`, не определены.

```sh
emma:$6$nP532JDDogQYZF8I$bjFNh9eT1xpb9/n6pmjlIwgu7hGjH/eytSdttbmVv0MlyTMFgBIXESFNUmTo9EGxxH1OT1HGQzR0so4n1npbE0:18064:0:99999:7:::
```

«Эпохой» системы POSIX является полночь (00:00) по всемирному координированному времени (UTC) в четверг, 1 января 1970 года. Большинство дат и времени в POSIX указываются в секундах с «эпохи» или, в случае с файлом `/etc/shadow`, в днях с «эпохи».

{% hint style="info" %}
Файл теневых данных предназначен только для чтения суперпользователем и выбранными службами аутентификации ядра системы, которые проверяют односторонний хэш пароля при входе в систему или во время другой аутентификации.
{% endhint %}

Несмотря на то, что существуют различные решения для аутентификации, основным методом хранения паролей является односторонняя _хеш-функция_. Это делается для того, чтобы пароль никогда не хранился в системе в открытом виде, поскольку хеш-функция необратима. Вы можете преобразовать пароль в хэш, но (в идеале) невозможно преобразовать хэш обратно в пароль.

В лучшем случае для хеширования всех комбинаций пароля до тех пор, пока не будет найдено совпадение, потребуется метод перебора. Чтобы снизить вероятность взлома хеша пароля в одной системе, в системах Linux для каждого хеша пароля пользователя используется случайная «соль». Таким образом, хеш пароля пользователя в одной системе Linux обычно не совпадает с хешем в другой системе Linux, даже если пароль один и тот же.

В файле `/etc/shadow` пароль может иметь несколько форм. Обычно эти формы включают следующее:

`!!`

Это означает, что учётная запись «отключена» (аутентификация невозможна) и не содержит хэш пароля.

`!$1$01234567$ABC…​`

«Отключённая» учётная запись (из-за начального восклицательного знака) с сохранённой предыдущей функцией хеширования, солью хеширования и строкой хеширования.

`$1$0123456789ABC$012…​`

«Активированная» учётная запись с сохранённой хэш-функцией, хэш-солью и хэш-строкой.

Хеш-функция, хеш-соль и хеш-строка предваряются и разделяются символом доллара (`$`). Длина хеш-соли должна составлять от восьми до шестнадцати (8-16) символов. Примеры трёх наиболее распространённых:

`$1$01234567$ABC…​`

Хэш-функция MD5 (`1`), примерная длина хеша — восемь.

`$5$01234567ABCD$012…​`

Хэш-функция SHA256 (`5`), примерная длина хеша — двенадцать.

`$6$01234567ABCD$012…​`

Хеш-функция SHA512 (`6`), примерная длина хеша — двенадцать.

{% hint style="info" %}
Хэш-функция MD5 считается криптографически небезопасной при современном (2010-е годы и позже) уровне производительности ASIC и даже общих вычислительных SIMD-устройств. Например, Федеральные стандарты обработки информации США (FIPS) не разрешают использовать MD5 для каких-либо криптографических функций, только для очень ограниченного числа аспектов проверки, но не для целостности цифровых подписей или аналогичных целей.
{% endhint %}

С точки зрения целей и экзамена LPI Linux Essentials, просто поймите, что хэш пароля локального пользователя хранится только в файле `/etc/shadow`, который могут читать только службы аутентификации или суперпользователь с помощью других команд.

## Краткие сведения

В этом уроке мы познакомились с базами данных пользователей и групп Linux. Мы изучили наиболее важные свойства пользователей и групп, включая их имена и числовые идентификаторы. Мы также выяснили, как в Linux работает хеширование паролей и как пользователи назначаются в группы.

Вся эта информация хранится в следующих четырёх файлах, которые обеспечивают базовый контроль доступа к локальной системе безопасности в Linux:

`/etc/passwd`

Все атрибуты локальной учётной записи пользователя POSIX, кроме хэша пароля, доступны для чтения всем.

`/etc/group`

Все системные атрибуты POSIX учетной записи локальной группы, доступные для чтения всем.

`/etc/shadow`

Все локальные для системы хэши паролей пользователей (и информация о сроке действия) не могут быть прочитаны (только некоторыми процессами).

`/etc/sudoers`

Вся информация/разрешения на повышение системных привилегий с помощью команды `sudo`

В этом уроке обсуждались следующие команды:

`id`

Перечислите реальные (или действующие) идентификаторы пользователей и групп.

`last`

Составьте список пользователей, которые вошли в систему последними.

`who`

Составьте список пользователей, которые в данный момент вошли в систему.

`w`

Аналогично `who`, но с дополнительным контекстом.

`su`

Переключитесь на другого пользователя с помощью командной строки или выполняйте команды от имени этого пользователя, указав его пароль.

`sudo`

Переключитесь на пользователя (или суперпользователя) Если у вас есть права, текущий пользователь вводит свой пароль (при необходимости) для повышения привилегий.

`chsh`

Измените оболочку пользователя.

`chfn`

Измените информацию о пользователе в поле GECOS.

## Ответы на упражнения с руководством <a href="#sec.5.1_02-age" id="sec.5.1_02-age"></a>

1.  Сравните результаты `last` с `w` и `who`. Какие детали отсутствуют в каждой из команд по сравнению с другими?

    Инструменты `w` и `who` отображают только список текущих пользователей, вошедших в систему, в то время как `last` также отображает список отключившихся пользователей. Команда `w` отображает загрузку системы, а `who` — нет.
2. Попробуйте выполнить команды `who` и `w -his`.
   *   Какая информация была удалена из вывода команды `w` с параметрами «без заголовка» (`-h`) и «кратко» (`-s`)?

       Заголовок не выводится, что полезно для анализа, а время входа в систему и информация о процессоре не отображаются.
   *   Какая информация была добавлена в вывод команды `w` с параметром «ip-адрес» (`-i`)?

       Вместо попытки разрешить DNS-запрос выводится IP-адрес и имя хоста. Эта опция `w` лучше соответствует выводу команды `last` по умолчанию.
3.  В каком файле хранится односторонний хэш пароля учётной записи пользователя?

    Файл `/etc/shadow` хранит односторонний хэш пароля учётной записи пользователя, поскольку он не доступен для чтения обычной, непривилегированной учётной записи пользователя, в отличие от файла `/etc/passwd`.
4.  Какой файл содержит список групп, членом которых является учётная запись пользователя? Какую логику можно использовать для составления списка групп, членом которых является учётная запись пользователя?

    В файле `/etc/group` в последнем поле «участники» любой строки для группы есть список имён пользователей в формате CSV.

    Любая строка в файле `/etc/group` с именем пользователя в последнем поле «участники» означает, что пользователь является участником этой группы — при условии, что файл правильно отформатирован (разделены запятыми). Кроме того, основная группа, участником которой является пользователь, в файле `/etc/passwd` также будет иметь соответствующую запись в файле `/etc/group` для имени группы и GID.
5. Один или несколько (1+) из следующих файлов по умолчанию недоступны для чтения обычными пользователями без привилегий. Какие именно?
   * `/etc/group`
   * `/etc/passwd`
   * `/etc/shadow`
   *   `/etc/sudoers`

       Файлы `/etc/shadow` и `/etc/sudoers` по умолчанию недоступны для чтения, за исключением некоторых служб или суперпользователя. Эти ответы будут настраиваться в зависимости от систем и имён пользователей, используемых в лаборатории.
6.  Как изменить оболочку входа текущего пользователя на Korn Shell (`/usr/bin/ksh`) в неинтерактивном режиме?

    ```
    $ chsh -s /usr / bin / ksh
    ```
7.  Почему домашний каталог `root` пользователя не помещен в `/home` каталог?

    Потому что учётная запись `root` необходима для устранения неполадок и ошибок, которые могут включать проблемы с файловой системой, связанные с каталогом `/home`. В таких случаях `root` должна быть полностью работоспособной, даже если файловая система `/home` ещё не доступна.

### Ответы на исследовательские упражнения <a href="#sec.5.1_02-aee" id="sec.5.1_02-aee"></a>

1.  Рассмотрим следующий вывод команды `id`:

    ```sh
    $ id emma
    uid=1000(emma) gid=1000(emma) groups=1000(emma),4(adm),5(tty),10(uucp),20(dialout),27(sudo),46(plugdev)
    ```

    В каких файлах хранятся следующие атрибуты?

    | UID и GID | `/etc/passwd` |
    | --------- | ------------- |
    | Группы    | `/etc/group`  |

    *   Кроме того, в каком файле хранится пароль пользователя?

        Хэшированный пароль пользователя хранится в `/etc/shadow`.
2.  Какой из следующих типов шифрования используется по умолчанию для локального хранения паролей в системе Linux?

    По умолчанию для хранения паролей используется односторонний хэш.
3.  Если идентификатор пользователя (UID) учётной записи меньше 1000, к какому типу она относится?

    Учётные записи с UID ниже 1000 обычно являются системными.
4.  Как вы можете получить список активных учётных записей в вашей системе, а также их количество?

    Используйте команду `w` . Помимо списка всех активных учётных записей, она также покажет информацию о том, сколько пользователей вошли в систему, а также о загрузке системы и времени работы.
5.  Используя команду `grep` мы получили результат с информацией о пользователе `emma`.
