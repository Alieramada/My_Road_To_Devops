# Урок 7.1.2.

## Введение <a href="#sec.107.1_02-in" id="sec.107.1_02-in"></a>

Инструменты командной строки, о которых говорилось в предыдущем уроке, и графические приложения, предоставляемые каждым дистрибутивом, которые выполняют те же задачи, обновляют ряд файлов, содержащих информацию о пользователях и группах.

Эти файлы расположены в каталоге `/etc/` и являются:

`/etc/passwd`

Файл из семи полей, разделенных двоеточием, содержащий основную информацию о пользователях.

`/etc/group`

Файл из четырех полей, разделенных двоеточием, содержащий основную информацию о группах.

`/etc/shadow`

Файл из девяти полей, разделенных двоеточием, содержащих зашифрованные пароли пользователей.

`/etc/gshadow`

Файл из четырех полей, разделенных двоеточием, содержащий зашифрованные групповые пароли.

Хотя эти четыре файла представляют собой обычный текст, их не следует редактировать напрямую, а только с помощью инструментов, предоставляемых используемым вами дистрибутивом.

## /etc/passwd <a href="#etcpasswd" id="etcpasswd"></a>

Это доступный для чтения всем файл, содержащий список пользователей, каждый из которых указан в отдельной строке. Каждая строка состоит из семи полей, разделённых двоеточиями:

_Username_

Имя, используемое при входе пользователя в систему.

_Password_

Зашифрованный пароль (или `x`, если используются теневые пароли).

_User ID (UID)_

Идентификационный номер, присвоенный пользователю в системе.

_Group ID (GID)_

Основной групповой номер пользователя в системе

_GECOS_

Дополнительное поле для комментариев, которое используется для добавления дополнительной информации о пользователе (например, полного имени). Поле может содержать несколько записей, разделённых запятыми.

_Home Directory_

Абсолютный путь к домашнему каталогу пользователя.

_Shell_

Абсолютный путь к программе, которая автоматически запускается при входе пользователя в систему (обычно это интерактивная оболочка, например `/bin/bash`).

## /etc/group <a href="#etcgroup" id="etcgroup"></a>

_Group Name_

Название группы.

_Group Password_

Зашифрованный пароль группы (или `x` при использовании теневых паролей).

_Group ID (GID)_

Идентификационный номер, присвоенный группе в системе.

_Member List_

Список пользователей, входящих в группу, разделённый запятыми, за исключением тех, для кого эта группа является основной.

## /etc/shadow <a href="#etcshadow" id="etcshadow"></a>

Это файл, доступный только для чтения пользователю root и пользователям с правами root, который содержит зашифрованные пароли пользователей, каждый в отдельной строке. Каждая строка состоит из девяти полей, разделённых двоеточиями:

_Username_

Имя, используемое при входе пользователя в систему.

_Encrypted Password_

Зашифрованный пароль пользователя (если значение начинается с `!`, учётная запись заблокирована).

_Date of Last Password Change_

Дата последнего изменения пароля в виде количества дней, прошедших с 01.01.1970 (значение 0 означает, что пользователь должен изменить пароль при следующем входе в систему).

_Minimum Password Age_

Минимальное количество дней после смены пароля, которое должно пройти, прежде чем пользователю будет разрешено снова сменить пароль.

_Maximum Password Age_

Максимальное количество дней, которое должно пройти, прежде чем потребуется смена пароля.

_Password Warning Period_

Количество дней до истечения срока действия пароля, в течение которых пользователь получает предупреждение о необходимости смены пароля.

_Password Inactivity Period_

Количество дней после истечения срока действия пароля, в течение которых пользователь должен обновить пароль. По истечении этого срока, если пользователь не изменит пароль, учётная запись будет отключена.

_Account Expiration Date_

Дата, выраженная в количестве дней, прошедших с 01.01.1970, по истечении которых учётная запись пользователя будет отключена (пустое поле означает, что срок действия учётной записи пользователя не ограничен).

_A reserved field_

Поле, которое зарезервировано для использования в будущем.

## /etc/gshadow

_Group Name_

Название группы.

_Encrypted Password_

Зашифрованный пароль для группы (используется, когда пользователь, не являющийся членом группы, хочет присоединиться к группе с помощью команды `newgrp` — если пароль начинается с `!`, доступ к группе с помощью `newgrp` запрещён).

_Group Administrators_

Список администраторов группы, разделённый запятыми (они могут изменить пароль группы, а также добавлять или удалять участников группы с помощью команды `gpasswd`).

_Group Members_

Список членов группы, разделенный запятыми.

## Фильтрация базы данных паролей и их группировка <a href="#filter_the_password_and_group_databases" id="filter_the_password_and_group_databases"></a>

Очень часто может потребоваться просмотреть информацию о пользователях и группах, хранящуюся в этих четырёх файлах, и найти конкретные записи. Для выполнения этой задачи можно использовать команду `grep` или объединить `cat` и `grep`.

```bash
# grep emma /etc/passwd
emma:x:1020:1020:User Emma:/home/emma:/bin/bash
# cat /etc/group | grep db-admin
db-admin:x:1050:grace,frank
```

Другой способ получить доступ к этим базам данных — использовать команду `getent` . Как правило, эта команда отображает записи из баз данных, поддерживаемых библиотеками _Name Service Switch_ (NSS), и требует указания имени базы данных и ключа поиска. Если аргумент ключа не указан, отображаются все записи в указанной базе данных (если только база данных не поддерживает перечисление). В противном случае, если указан один или несколько аргументов ключа, база данных фильтруется соответствующим образом.

```bash
# getent passwd emma
emma:x:1020:1020:User Emma:/home/emma:/bin/bash
# getent group db-admin
db-admin:x:1050:grace,frank
```

Команда `getent` не требует прав суперпользователя; вам просто нужно иметь возможность читать базу данных, из которой вы хотите получить записи.

{% hint style="info" %}
Помните, что `getent` вы можете получить доступ только к базам данных, настроенным в `/etc/nsswitch.conf` файле.
{% endhint %}

### Ответы на Упражнения с Руководством <a href="#sec.107.1_02-age" id="sec.107.1_02-age"></a>

1.  Обратите внимание на следующие выходные данные и ответьте на следующие вопросы:

    ```bash
    # cat /etc/passwd | grep '\(root\|mail\|catherine\|kevin\)'
    root:x:0:0:root:/root:/bin/bash
    mail:x:8:8:mail:/var/spool/mail:/sbin/nologin
    catherine:x:1030:1025:User Chaterine:/home/catherine:/bin/bash
    kevin:x:1040:1015:User Kevin:/home/kevin:/bin/bash
    # cat /etc/group | grep '\(root\|mail\|db-admin\|app-developer\)'
    root:x:0:
    mail:x:8:
    db-admin:x:1015:emma,grace
    app-developer:x:1016:catherine,dave,christian
    # cat /etc/shadow | grep '\(root\|mail\|catherine\|kevin\)'
    root:$6$1u36Ipok$ljt8ooPMLewAhkQPf.lYgGopAB.jClTO6ljsdczxvkLPkpi/amgp.zyfAN680zrLLp2avvpdKA0llpssdfcPppOp:18015:0:99999:7:::
    mail:*:18015:0:99999:7:::
    catherine:$6$ABCD25jlld14hpPthEFGnnssEWw1234yioMpliABCdef1f3478kAfhhAfgbAMjY1/BAeeAsl/FeEdddKd12345g6kPACcik:18015:20:90:5:::
    kevin:$6$DEFGabc123WrLp223fsvp0ddx3dbA7pPPc4LMaa123u6Lp02Lpvm123456pyphhh5ps012vbArL245.PR1345kkA3Gas12P:18015:0:60:7:2::
    # cat /etc/gshadow | grep '\(root\|mail\|db-admin\|app-developer\)'
    root:*::
    mail:*::
    db-admin:!:emma:emma,grace
    app-developer:!::catherine,dave,christian
    ```

    *   Каковы идентификатор пользователя (UID) и идентификатор группы (GID) для `root` и `catherine`?

        UID и GID `root` равны 0 и 0, а UID и GID `catherine` равны 1030 и 1025.
    *   Как называется основная группа `kevin`? Есть ли в этой группе другие участники?

        Название группы — `db-admin`. Также `emma` и `grace` входят в эту группу.
    *   Какая оболочка установлена для пользователя `mail`? Что это значит?

        `mail` Это системная учётная запись пользователя, и её оболочка — `/sbin/nologin`. На самом деле системные учётные записи пользователей, такие как `mail`, `ftp`, `news` и `daemon`, используются для выполнения административных задач, и поэтому для этих учётных записей следует запретить обычный вход в систему. Вот почему для оболочки обычно устанавливается `/sbin/nologin` или `/bin/false`.
    *   Кто входит в группу `app-developer`? Кто из них является администратором группы, а кто обычным участником?

        Участниками являются `catherine`, `dave` и `christian`, и все они являются рядовыми участниками.
    *   Каков минимальный срок действия пароля для `catherine`? И каков максимальный срок действия пароля?

        Минимальный срок действия пароля составляет 20 дней, а максимальный — 90 дней.
    *   Какой период неактивности пароля для `kevin`?

        Период бездействия пароля составляет 2 дня. В течение этого периода `kevin` необходимо обновить пароль, иначе учётная запись будет заблокирована.
2.  По соглашению, какие идентификаторы присваиваются системным учётным записям, а какие — обычным пользователям?

    Системные учётные записи обычно имеют UID меньше 100 или от 500 до 1000, в то время как обычные пользователи имеют UID, начиная с 1000, хотя в некоторых устаревших системах нумерация может начинаться с 500. Пользователь `root` имеет UID 0. Помните, что значения `UID_MIN` и `UID_MAX` в `/etc/login.defs` определяют диапазон UID, используемых для создания обычных пользователей. С точки зрения LPI Linux Essentials и LPIC-1, системные учётные записи имеют UID меньше 1000, а обычные пользователи — UID больше 1000.
3.  Как узнать, заблокирована ли учётная запись пользователя, которая ранее могла получать доступ к системе? Предположим, что в вашей системе используются теневые пароли.

    При использовании теневых паролей второе поле в `/etc/passwd` содержит символ `x` для каждой учётной записи пользователя, поскольку зашифрованные пароли пользователей хранятся в `/etc/shadow`. В частности, зашифрованный пароль учётной записи пользователя хранится во втором поле этого файла, и если он начинается с восклицательного знака, то учётная запись заблокирована.

### Ответы на Исследовательские упражнения <a href="#sec.107.1_02-aee" id="sec.107.1_02-aee"></a>

1.  Создайте учётную запись пользователя с именем `christian` с помощью команды `useradd -m` и определите её идентификатор пользователя (UID), идентификатор группы (GID) и оболочку.

    ```bash
    # useradd -m christian
    # cat /etc/passwd | grep christian
    christian:x:1050:1060::/home/christian:/bin/bash
    ```

    UID и GID `christian` равны 1050 и 1060 соответственно (третье и четвёртое поля в `/etc/passwd`). `/bin/bash` — это оболочка, установленная для этой учётной записи (седьмое поле в `/etc/passwd`).
2.  Определите название основной группы `christian`. Что вы можете из этого вывести?

    ```bash
    # cat /etc/group | grep 1060
    christian:x:1060:
    ```

    Имя основной группы `christian` — `christian` (первое поле в `/etc/group`). Поэтому `USERGROUPS_ENAB` в `/etc/login.defs` установлено значение «да», чтобы `useradd` по умолчанию создавал группу с тем же именем, что и учётная запись пользователя.
3.  Используя `getent` команду, просмотрите информацию о сроке действия пароля для учетной записи пользователя `christian`.

    ```bash
    # getent shadow christian
    christian:!:18015:0:99999:7:::
    ```

    Для учётной записи `christian` пользователя не установлен пароль, и она заблокирована (второе поле в `/etc/shadow` содержит восклицательный знак). Для этой учётной записи пользователя не установлен минимальный и максимальный срок действия пароля (четвёртое и пятое поля в `/etc/shadow` имеют значения 0 и 99999 дней), а срок действия предупреждения о смене пароля составляет 7 дней (шестое поле в `/etc/shadow`). Наконец, для этой учётной записи не установлен период бездействия (седьмое поле в `/etc/shadow`), а срок действия учётной записи не ограничен (восьмое поле в `/etc/shadow`).
4.  Добавьте `editor` группу во второстепенные группы `christian`. Предположим, что эта группа уже содержит `emma`, `dave` и `frank` в качестве обычных членов. Как вы можете убедиться, что в этой группе нет администраторов?

    ```bash
    # cat /etc/group | grep editor
    editor:x:1100:emma,dave,frank
    # usermod -a -G editor christian
    # cat /etc/group | grep editor
    editor:x:1100:emma,dave,frank,christian
    # cat /etc/gshadow | grep editor
    editor:!::emma,dave,frank,christian
    ```

    Третье и четвёртое поля в `/etc/gshadow` содержат информацию об администраторах и обычных участниках указанной группы. Таким образом, поскольку третье поле в `editor` пусто, в этой группе нет администраторов (`emma`, `dave`, `frank` и `christian` — все обычные участники).
5.  Выполните команду `ls -l /etc/passwd /etc/group /etc/shadow /etc/gshadow` и опишите полученный результат с точки зрения прав доступа к файлам. Какие из этих четырёх файлов скрыты по соображениям безопасности? Предположим, что в вашей системе используются скрытые пароли.

    ```bash
    # ls -l /etc/passwd /etc/group /etc/shadow /etc/gshadow
    -rw-r--r-- 1 root root 853 mag 1 08:00 /etc/group
    -rw-r----- 1 root shadow 1203 mag 1 08:00 /etc/gshadow
    -rw-r--r-- 1 root root 1354 mag 1 08:00 /etc/passwd
    -rw-r----- 1 root shadow 1563 mag 1 08:00 /etc/shadow
    ```

    Файлы `/etc/passwd` и `/etc/group` доступны для чтения всем пользователям и скрыты по соображениям безопасности. При использовании скрытых паролей во втором поле этих файлов вы увидите `x`, потому что зашифрованные пароли пользователей и групп хранятся в `/etc/shadow` и `/etc/gshadow`, которые доступны для чтения только пользователю root и, в системе из примера, также участникам группы `shadow.`
