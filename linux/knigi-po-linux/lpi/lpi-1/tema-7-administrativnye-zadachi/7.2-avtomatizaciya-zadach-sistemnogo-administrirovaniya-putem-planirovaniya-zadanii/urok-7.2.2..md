# Урок 7.2.2.

## Введение <a href="#sec.107.2_02-in" id="sec.107.2_02-in"></a>

Как вы узнали из предыдущего урока, вы можете планировать регулярные задачи с помощью таймеров cron или systemd, но иногда вам может понадобиться запустить задачу в определённое время в будущем только один раз. Для этого вы можете использовать другую мощную утилиту: команду `at`

#### Планировние заданий с помощью `at` <a href="#schedule_jobs_with_at" id="schedule_jobs_with_at"></a>

Команда `at` испоззльзуется для однократного планирования задач и требует только указания времени, когда задача должна быть выполнена в будущем. После ввода `at` в командной строке и указания времени вы войдёте в командную строку `at`, где сможете задать команды для выполнения. Выйти из командной строки можно с помощью последовательности клавиш Ctrl+D.

```bash
$ at now +5 minutes
warning: commands will be executed using /bin/sh
at> date
at> Ctrl+D
job 12 at Sat Sep 14 09:15:00 2019
```

Задание `at` в приведённом выше примере просто выполняет команду `date` через пять минут. Как и в случае с `cron`, стандартный вывод и ошибки отправляются вам по электронной почте. Обратите внимание, что для использования планирования заданий `atd` в системе должен быть запущен демон `at`.

{% hint style="info" %}
В Linux команда `batch` похожа на `at`, однако задания `batch` выполняются только тогда, когда нагрузка на систему достаточно низкая.
{% endhint %}

Наиболее важными параметрами, которые применяются к команде `at` , являются:

`-c`

Выведите команды с определенным идентификатором задания на стандартный вывод.

`-d`

Удалите задания по их идентификатору. Это псевдоним для `atrm`.

`-f`

Считывает задание из файла вместо стандартного ввода.

`-l`

Выводит список ожидающих выполнения заданий пользователя. Если пользователь является администратором, выводятся все задания всех пользователей. Это псевдоним для `atq`.

`-m`

Отправьте письмо пользователю в конце работы, даже если результатов не было.

`-q`

Укажите очередь в виде одной буквы от `a` до `z` и от `A` до `Z` (по умолчанию `a` для `at` и `b` для `batch`). Задания в очередях с наибольшим количеством букв выполняются с повышенной точностью. Задания, отправленные в очередь с заглавной буквы, обрабатываются как `batch` задания. «Укажите очередь в виде одной буквы от a до z и от A до Z (по умолчанию используется буква a для at и b для batch). Задания в очередях с буквами идущими дальше по алфавиту будут выполняются с повышенным приоритетом. Задания, отправленные в очередь с заглавной буквой, обрабатываются как пакетные задания».

`-v`

Покажите время, в которое будет выполняться задание, прежде чем читать его.

## Список Запланированных заданий с помощью `atq` <a href="#list_scheduled_jobs_with_atq" id="list_scheduled_jobs_with_atq"></a>

Теперь давайте запланируем ещё два `at` задания: первое выполнит `foo.sh` скрипт в 09:30, а второе выполнит `bar.sh` скрипт через час.

```bash
$ at 09:30 AM
warning: commands will be executed using /bin/sh
at> ./foo.sh
at> Ctrl+D
job 13 at Sat Sep 14 09:30:00 2019
$ at now +2 hours
warning: commands will be executed using /bin/sh
at> ./bar.sh
at> Ctrl+D
job 14 at Sat Sep 14 11:10:00 2019
```

Чтобы просмотреть список ожидающих выполнения заданий, вы можете использовать команду `atq`, которая показывает следующую информацию о каждом задании: идентификатор задания, дату выполнения задания, время выполнения задания, очередь и имя пользователя.

```
$ atq
14      Sat Sep  14 11:10:00 2019 a frank
13      Sat Sep  14 09:30:00 2019 a frank
12      Sat Sep  14 09:15:00 2019 a frank
```

Помните, что `at -l` команда является псевдонимом для `atq`.

{% hint style="info" %}
Если вы запустите `atq` от имени пользователя root, он отобразит задания в очереди для всех пользователей.
{% endhint %}

## Удаление заданий с помощью `atrm` <a href="#delete_jobs_with_atrm" id="delete_jobs_with_atrm"></a>

Если вы хотите удалить задание `at` , вы можете использовать команду `atrm` с идентификатором задания. Например, чтобы удалить задание с идентификатором 14, выполните следующее:

```bash
$ atrm 14
```

Вы можете удалить несколько заданий с помощью `atrm`, указав несколько идентификаторов, разделённых пробелами. Помните, что команда `at -d` является псевдонимом для `atrm`.

{% hint style="info" %}
Если вы запустите `atrm` от имени root, вы можете удалить задания всех пользователей.
{% endhint %}

## Настройка доступа к расписанию заданий <a href="#configure_access_to_job_scheduling" id="configure_access_to_job_scheduling"></a>

Авторизация обычных пользователей для планирования `at` заданий определяется файлами `/etc/at.allow` и `/etc/at.deny`. Если `/etc/at.allow` существует, только пользователи, не являющиеся root-пользователями, перечисленные в нём, могут планировать `at` задания. Если `/etc/at.allow` не существует, но `/etc/at.deny` существует, только пользователи, не являющиеся root-пользователями, перечисленные в нём, не могут планировать `at` задания (в этом случае пустой `/etc/at.deny` файл означает, что каждому пользователю разрешено планировать `at` задания). Если ни один из этих файлов не существует, доступ пользователя к планированию `at` заданий зависит от используемого дистрибутива.

#### Спецификации времени <a href="#time_specifications" id="time_specifications"></a>

Вы можете указать время выполнения конкретного задания `at` с помощью формы `HH:MM`, за которой при необходимости следует AM или PM в случае 12-часового формата. Если указанное время уже прошло, предполагается, что задание будет выполнено на следующий день. Если вы хотите запланировать выполнение задания на определённую дату, вы должны добавить информацию о дате после времени с помощью одной из следующих форм: `month-name day-of-month`, `month-name day-of-month year`, `MMDDYY`, `MM/DD/YY`, `DD.MM.YY` и `YYYY-MM-DD`).

Также допустимы следующие ключевые слова: `midnight`, `noon`, `teatime` (16:00) и `now` со знаком «плюс» (`+`) и периодом времени (минуты, часы, дни и недели). Наконец, вы можете указать `at` для выполнения задания сегодня или завтра, добавив к времени слова `today` или `tomorrow`. Например, вы можете использовать `at 07:15 AM Jan 01` для выполнения задания в 07:15 1 января и `at now +5 minutes` для выполнения задания через пять минут. Вы можете прочитать `timespec` файл под `/usr/share` деревом для получения дополнительной информации о точном определении временных характеристик.

## Альтернатива `at` <a href="#an_alternative_to_at" id="an_alternative_to_at"></a>

Используя systemd в качестве системного и сервисного менеджера, вы также можете планировать разовые задачи с помощью команды `systemd-run` . Обычно она используется для создания временного таймера, чтобы команда выполнялась в определённое время без необходимости создавать файл службы. Например, действуя от имени пользователя root, вы можете запустить команду `date` в 11:30 06.10.2019, используя следующее:

```bash
# systemd-run --on-calendar='2019-10-06 11:30' date
```

Если вы хотите запустить скрипт `foo.sh`, расположенный в вашем текущем рабочем каталоге, через две минуты, вы можете использовать:

```bash
# systemd-run --on-active="2m" ./foo.sh
```

Обратитесь к страницам руководства, чтобы узнать обо всех возможных вариантах использования `systemd-run` with `systemd-run(1)`.

{% hint style="info" %}
Помните, что таймеры записываются в журнал systemd, и вы можете просмотреть журналы различных модулей с помощью команды `journalctl` . Также помните, что если вы действуете как обычный пользователь, вам нужно использовать опцию `--user` команд `systemd-run` и `journalctl` .
{% endhint %}

### Исследовательские упражнения <a href="#sec.107.2_02-ee" id="sec.107.2_02-ee"></a>

1. Создайте задание `at` для запуска скрипта `foo.sh` в 10:30 утра 31 октября. Предположим, что вы действуете как обычный пользователь.
2. Войдите в систему как другой обычный пользователь и создайте ещё одно `at` задание, которое запустит `bar.sh` скрипт завтра в 10:00. Предположим, что скрипт находится в домашнем каталоге пользователя.
3. Войдите в систему как другой обычный пользователь и создайте ещё одно `at` задание, которое запустит `foobar.sh` скрипт ровно через 30 минут. Предположим, что скрипт находится в домашнем каталоге пользователя.

5. От имени пользователя root удалите все эти отложенные `at` задания с помощью одной команды.
6. Запустите команду `ls -l /usr/bin/at` и проверьте ее разрешения.

## Краткие сведения <a href="#sec.107.2_02-su" id="sec.107.2_02-su"></a>

На этом уроке вы узнали:

* Как использовать `at` для выполнения одноразовых заданий в определенное время.
* Как управлять `at` заданиями.
* Как настроить доступ пользователей к `at` планированию заданий.
* Как использовать `systemd-run` в качестве альтернативы `at`.

В этом уроке обсуждались следующие команды и файлы:

`at`

Выполнить команду в указанное время.

`atq`

Вывести список ожидающих выполнения заданий `at` пользователя, если только он не является суперпользователем.

`atrm`

Удалить `at` задания, идентифицируемые по их номеру задания.

`/etc/at.allow` и `/etc/at.deny`

Определенные файлы, используемые для установки `at` ограничений.

`systemd-run`

Создать и запустить временный модуль `timer` в качестве альтернативы `at` для однократного планирования.

## Ответы на Упражнения с Руководством <a href="#sec.107.2_02-age" id="sec.107.2_02-age"></a>

1.  Для каждой из следующих временных характеристик укажите, какая из них действительна, а какая нет для `at`:

    | `at 08:30 AM next week`          | Действительный   |
    | -------------------------------- | ---------------- |
    | `at midday`                      | Недействительный |
    | `at 01-01-2020 07:30 PM`         | Недействительный |
    | `at 21:50 01.01.20`              | Действительный   |
    | `at now +4 days`                 | Действительный   |
    | `at 10:15 PM 31/03/2021`         | Недействительный |
    | `at tomorrow 08:30 AM monotonic` | Недействительный |


2.  После того как вы запланировали задание с помощью `at`, как вы можете просмотреть его команды?

    Вы можете использовать команду `at -c` с идентификатором задания, команды которого вы хотите просмотреть. Обратите внимание, что вывод также содержит большую часть информации об окружении, которое было активным во время планирования задания. Помните, что root может просматривать задания всех пользователей.
3.  Какие команды можно использовать для просмотра ожидающих выполнения `at` заданий? Какие команды можно использовать для их удаления?

    Вы можете использовать команду `at -l` для просмотра ожидающих выполнения заданий, а также команду `at -d` для удаления заданий. `at -l` — это псевдоним для `atq` и `at -d` — это псевдоним для `atrm`. Помните, что root может просматривать и удалять задания всех пользователей.
4.  В systemd какая команда используется в качестве альтернативы `at`?

    Команду `systemd-run` можно использовать в качестве альтернативы `at` для планирования разовых заданий. Например, с её помощью можно запускать команды в определённое время, задав _таймер по календарю_ или _монотонный таймер_ относительно разных начальных точек.

### Ответы на Исследовательские упражнения <a href="#sec.107.2_02-aee" id="sec.107.2_02-aee"></a>

1.  Создайте задание `at` в 10:30 утра 31 октября, которое запустит скрипт `foo.sh` из вашего домашнего каталога. Предположим, что вы действуете как обычный пользователь.

    ```bash
    $ at 10:30 AM October 31
    warning: commands will be executed using /bin/sh
    at> ./foo.sh
    at> Ctrl+D
    job 50 at Thu Oct 31 10:30:00 2019
    ```
2.  Войдите в систему как другой обычный пользователь и создайте ещё одно `at` задание, которое запустит `bar.sh` скрипт завтра в 10:00. Предположим, что скрипт находится в домашнем каталоге пользователя.

    ```bash
    $ at 10:00 AM tomorrow
    warning: commands will be executed using /bin/sh
    at> ./bar.sh
    at> Ctrl+D
    job 51 at Sun Oct 6 10:00:00 2019
    ```
3.  Войдите в систему как другой обычный пользователь и создайте ещё одно `at` задание, которое запустит `foobar.sh` скрипт ровно через 30 минут. Предположим, что скрипт находится в домашнем каталоге пользователя.

    ```bash
    $ at now +30 minutes
    warning: commands will be executed using /bin/sh
    at> ./foobar.sh
    at> Ctrl+D
    job 52 at Sat Oct 5 10:19:00 2019
    ```
4.  Теперь от имени пользователя root выполните команду `atq` для просмотра запланированных заданий `at` всех пользователей. Что произойдёт, если эту команду выполнит обычный пользователь?

    <pre class="language-bash"><code class="lang-bash"><strong># atq
    </strong>52      Sat Oct  5 10:19:00 2019 a dave
    50      Thu Oct 31 10:30:00 2019 a frank
    51      Sun Oct  6 10:00:00 2019 a emma
    </code></pre>

    Если вы запускаете команду `atq` от имени пользователя root, отображаются все ожидающие выполнения `at` задания всех пользователей. Если вы запускаете её от имени обычного пользователя, отображаются только ваши собственные ожидающие выполнения `at` задания.
5.  От имени пользователя root удалите все эти отложенные `at` задания с помощью одной команды.

    ```
    # atrm 50 51 52
    ```
6.  От имени пользователя root запустите команду `ls -l /usr/bin/at` и проверьте ее разрешения.

    ```
    # ls -l /usr/bin/at
    -rwsr-sr-x 1 daemon daemon 43762 Dec  1  2015 /usr/bin/at
    ```

    В этом дистрибутиве у команды `at` установлены биты SUID (символ `s` вместо флага исполняемого файла для владельца) и SGID (символ `s` вместо флага исполняемого файла для группы), что означает, что она выполняется с правами владельца и группы файла (`daemon` для обоих). Именно поэтому обычные пользователи могут планировать задания с помощью `at`.
