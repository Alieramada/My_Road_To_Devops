# Урок 7.2.1.

## Введение <a href="#sec.107.2_01-in" id="sec.107.2_01-in"></a>

Одна из важнейших задач хорошего системного администратора — планировать задания, которые необходимо выполнять регулярно. Например, администратор может создавать и автоматизировать задания для резервного копирования, обновления системы и выполнения многих других повторяющихся действий. Для этого можно использовать средство `cron` для автоматизации периодического планирования заданий.

## Планирование заданий с помощью Cron <a href="#schedule_jobs_with_cron" id="schedule_jobs_with_cron"></a>

В Linux `cron` — это демон, который работает непрерывно и каждую минуту проверяет набор таблиц, чтобы найти задачи для выполнения. Эти таблицы известны как _crontab_ и содержат так называемые _задания cron_. Cron подходит для серверов и систем, которые постоянно включены, потому что каждое задание cron выполняется только в том случае, если система работает в запланированное время. Его могут использовать обычные пользователи, у каждого из которых есть свой `crontab`, а также пользователь root, который управляет системными crontab.

{% hint style="info" %}
В Linux также есть функция `anacron` для систем, которые можно выключать (например, настольных компьютеров или ноутбуков). Ею может пользоваться только пользователь с правами root. Если компьютер выключен, когда необходимо выполнить задания `anacron` , они будут запущены при следующем включении компьютера. `anacron` не входит в сертификацию LPIC-1.
{% endhint %}

## Пользовательские Crontabs <a href="#user_crontabs" id="user_crontabs"></a>

_Пользовательские crontab-файлы_ — это текстовые файлы, которые управляют расписанием пользовательских заданий cron. Они всегда называются в честь учётной записи пользователя, который их создал, но расположение этих файлов зависит от используемого дистрибутива (обычно это подкаталог `/var/spool/cron`).

Каждая строка в пользовательском crontab содержит шесть полей, разделённых пробелами:

* Минута часа (0-59).
* Час суток (0-23).
* День месяца (1-31).
* Месяц в году (1-12).
* День недели (0-7, где воскресенье = 0 или воскресенье = 7).
* Команда для запуска.

Вместо соответствующего числа для обозначения месяца года и дня недели можно использовать первые три буквы названия.

Первые пять полей указывают, когда следует выполнить команду, указанную в шестом поле, и могут содержать одно или несколько значений. В частности, вы можете указать несколько значений с помощью:

`*` (звездочка)

Относится к любому значению.

`,` (запятая)

Задает список возможных значений.

`-` (тире)

Задает диапазон возможных значений.

`/` (косая черта)

Задает ступенчатые значения.

Многие дистрибутивы включают файл `/etc/crontab` , который можно использовать в качестве примера для оформления файла `cron` . Вот пример файла `/etc/crontab` из дистрибутива Debian:

```bash
SHELL=/bin/sh
PATH=/usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin

# Example of job definition:
# .---------------- minute (0 - 59)
# |  .------------- hour (0 - 23)
# |  |  .---------- day of month (1 - 31)
# |  |  |  .------- month (1 - 12) OR jan,feb,mar,apr ...
# |  |  |  |  .---- day of week (0 - 6) (Sunday=0 or 7) OR sun,mon,tue,wed,thu,fri,sat
# |  |  |  |  |
# *  *  *  *  * user-name command to be executed
```

## Системные Crontabs

_Системные таблицы cron_ — это текстовые файлы, которые управляют планированием системных заданий cron и могут быть отредактированы только пользователем с правами root. `/etc/crontab` и все файлы в каталоге `/etc/cron.d` являются системными таблицами cron.

Большинство дистрибутивов также включают каталоги `/etc/cron.hourly`, `/etc/cron.daily`, `/etc/cron.weekly` и `/etc/cron.monthly`, которые содержат скрипты для запуска с соответствующей периодичностью. Например, если вы хотите запускать скрипт ежедневно, вы можете поместить его в `/etc/cron.daily`.

{% hint style="info" %}
В некоторых дистрибутивах используются `/etc/cron.d/hourly`, `/etc/cron.d/daily`, `/etc/cron.d/weekly` и `/etc/cron.d/monthly`. Не забывайте проверять правильность каталогов, в которых вы размещаете скрипты, которые хотите запускать с помощью cron.
{% endhint %}

Синтаксис системных crontab-файлов аналогичен синтаксису пользовательских crontab-файлов, однако в нём также требуется дополнительное обязательное поле, в котором указывается, какой пользователь будет запускать задание cron. Таким образом, каждая строка в системном crontab-файле содержит семь полей, разделённых пробелами:

* Минута часа (0-59).
* Час суток (0-23).
* День месяца (1-31).
* Месяц в году (1-12).
* День недели (0-7, где воскресенье = 0 или воскресенье = 7).
* Имя учетной записи пользователя, которое будет использоваться при выполнении команды.
* Команда для запуска.

Как и в пользовательских кронтабах, вы можете указать несколько значений для полей времени с помощью операторов `*`, `,` , `-` и `/` . Вы также можете указать месяц года и день недели с помощью первых трёх букв названия вместо соответствующего числа.

## Конкретные Временные характеристики <a href="#particular_time_specifications" id="particular_time_specifications"></a>

При редактировании файлов crontab вместо указания времени можно использовать специальные сокращения в первых пяти столбцах:

`@reboot`

Запустите указанную задачу один раз после перезагрузки.

`@hourly`

Выполняйте указанную задачу один раз в час, в начале часа.

`@daily` (или `@midnight`)

Запускайте указанную задачу один раз в день в полночь.

`@weekly`

Выполняйте указанную задачу раз в неделю в полночь в воскресенье.

`@monthly`

Выполняйте указанное задание раз в месяц в полночь первого дня месяца.

`@yearly` (или `@annually`)

Выполняйте указанное задание раз в год в полночь 1 января.

## Переменные Crontab <a href="#crontab_variables" id="crontab_variables"></a>

В файле crontab перед объявлением запланированных задач иногда определяются переменные. Обычно устанавливаются следующие переменные среды:

`HOME`

Каталог, в котором `cron` вызываются команды (по умолчанию домашний каталог пользователя).

`MAILTO`

Имя пользователя или адрес, на который отправляются стандартные выходные данные и ошибка (по умолчанию владелец crontab). Также допускается использование нескольких значений, разделенных запятыми, а пустое значение указывает на то, что почту отправлять не следует.

`PATH`

Путь, по которому можно найти команды.

`SHELL`

Используемая оболочка (по умолчанию `/bin/sh`).

## Создание пользовательских заданий Cron <a href="#creating_user_cron_jobs" id="creating_user_cron_jobs"></a>

Команда `crontab` используется для управления файлами crontab для отдельных пользователей. В частности, вы можете запустить команду `crontab -e` для редактирования собственного файла crontab или для его создания, если он ещё не существует.

```bash
$ crontab -e
no crontab for frank - using an empty one

Select an editor.  To change later, run 'select-editor'.
  1. /bin/ed
  2. /bin/nano        < ‑‑‑‑ easiest
  3. /usr/bin/emacs24
  4. /usr/bin/vim.tiny

Choose 1-4 [2]:
```

По умолчанию команда `crontab` открывает редактор, указанный в переменных среды `VISUAL` или `EDITOR`, чтобы вы могли начать редактировать файл crontab в предпочитаемом редакторе. В некоторых дистрибутивах, как показано в примере выше, при первом запуске `crontab` можно выбрать редактор из списка.

Если вы хотите запускать скрипт `foo.sh` в вашем домашнем каталоге каждый день в 10:00, вы можете добавить следующую строку в файл crontab:

```bash
0 10 * * * /home/frank/foo.sh
```

Рассмотрим следующие примеры записей crontab:

```bash
0,15,30,45 08 * * 2 /home/frank/bar.sh
30 20 1-15 1,6 1-5 /home/frank/foobar.sh
```

В первой строке скрипт `bar.sh` выполняется каждый вторник в 08:00, в 08:15, в 08:30 и в 08:45. Во второй строке скрипт `foobar.sh` выполняется в 20:30 с понедельника по пятницу в течение первых пятнадцати дней января и июня.

{% hint style="info" %}
Хотя файлы crontab можно редактировать вручную, всегда рекомендуется использовать команду `crontab` . Права доступа к файлам crontab обычно позволяют редактировать их только с помощью команды `crontab` .
{% endhint %}

Помимо упомянутой выше опции `-e` команда `crontab` имеет и другие полезные опции:

`-l`

Отобразите текущую crontab в стандартном выводе.

`-r`

Удалите текущий crontab.

`-u`

Укажите имя пользователя, чей файл crontab необходимо изменить. Эта опция требует прав суперпользователя и позволяет пользователю с правами суперпользователя редактировать файлы crontab других пользователей.

## Создание системных заданий Cron

В отличие от пользовательских кронтабов, системные кронтабы обновляются с помощью редактора: поэтому вам не нужно запускать команду `crontab` для редактирования `/etc/crontab` и файлов в `/etc/cron.d`. Помните, что при редактировании системных кронтабов необходимо указать учётную запись, которая будет использоваться для запуска задания cron (обычно это учётная запись пользователя root).

Например, если вы хотите запускать скрипт `barfoo.sh` в каталоге `/root` каждый день в 01:30, вы можете открыть `/etc/crontab` в предпочитаемом вами редакторе и добавить следующую строку:

```bash
30 01 * * * root /root/barfoo.sh >>/root/output.log 2>>/root/error.log
```

В приведённом выше примере выходные данные задания добавляются в `/root/output.log`, а ошибки — в `/root/error.log`.

{% hint style="info" %}
Если вывод не перенаправлен в файл, как в приведённом выше примере (или переменная `MAILTO` не имеет значения), весь вывод из задания cron будет отправлен пользователю по электронной почте. Обычно стандартный вывод перенаправляется в `/dev/null` (или в файл для последующего просмотра, если это необходимо), а стандартный вывод ошибок не перенаправляется. Таким образом, пользователь будет немедленно уведомлён по электронной почте о любых ошибках.
{% endhint %}

## Настройка доступа к расписанию заданий <a href="#configure_access_to_job_scheduling" id="configure_access_to_job_scheduling"></a>

В Linux файлы `/etc/cron.allow` и `/etc/cron.deny` используются для установки `crontab` ограничений. В частности, они используются для того, чтобы разрешить или запретить планирование заданий cron для разных пользователей. Если `/etc/cron.allow` существует, только пользователи, не являющиеся root, перечисленные в нём, могут планировать задания cron с помощью команды `crontab` . Если `/etc/cron.allow` не существует, но `/etc/cron.deny` существует, только пользователи, не являющиеся root, перечисленные в этом файле, не могут планировать задания cron с помощью команды `crontab` (в этом случае пустой `/etc/cron.deny` означает, что каждому пользователю разрешено планировать задания cron с помощью `crontab`). Если ни один из этих файлов не существует, доступ пользователя к планированию заданий cron зависит от используемого дистрибутива.\


{% hint style="info" %}
Файлы `/etc/cron.allow` и `/etc/cron.deny` содержат список имён пользователей, каждое в отдельной строке.
{% endhint %}

## Альтернатива Cron <a href="#an_alternative_to_cron" id="an_alternative_to_cron"></a>

Используя systemd в качестве системного и сервисного менеджера, вы можете настроить _таймеры_ в качестве альтернативы `cron` для планирования задач. Таймеры — это файлы модулей systemd, обозначаемые суффиксом `.timer`, и для каждого из них должен быть соответствующий файл модуля, описывающий модуль, который будет активирован по истечении времени таймера. По умолчанию `timer` активирует службу с тем же именем, за исключением суффикса.

Таймер включает в себя раздел `[Timer]` с указанием времени выполнения запланированных заданий. В частности, вы можете использовать опцию `OnCalendar=` для определения _таймеров реального времени_, которые работают так же, как задания cron (они основаны на выражениях событий календаря). Для опции `OnCalendar=` требуется следующий синтаксис:

```
DayOfWeek Year-Month-Day Hour:Minute:Second
```

`DayOfWeek` является необязательным. Операторы `*`, `/` и `,` имеют то же значение, что и операторы, используемые для заданий cron, а `..` между двумя значениями можно использовать для обозначения непрерывного диапазона. Для указания `DayOfWeek` можно использовать первые три буквы имени или полное имя.

{% hint style="info" %}
Вы также можете задать _монотонные таймеры_, которые активируются по истечении определённого времени с момента начала отсчёта (например, при загрузке компьютера или при активации самого таймера).
{% endhint %}

Например, если вы хотите запустить службу с именем `/etc/systemd/system/foobar.service` в 05:30 в первый понедельник каждого месяца, вы можете добавить следующие строки в соответствующий файл службы `/etc/systemd/system/foobar.timer`:

```bash
[Unit]
Description=Run the foobar service

[Timer]
OnCalendar=Mon *-*-1..7 05:30:00
Persistent=true

[Install]
WantedBy=timers.target
```

После создания нового таймера вы можете включить его и запустить, выполнив следующие команды от имени пользователя root:

```
# systemctl enable foobar.timer
# systemctl start foobar.timer
```

Вы можете изменить периодичность запланированного задания, изменив значение `OnCalendar` и введя команду `systemctl daemon-reload` .

Наконец, если вы хотите просмотреть список активных таймеров, отсортированных по времени их следующего срабатывания, вы можете использовать команду `systemctl list-timers` . Вы также можете добавить опцию `--all` , чтобы увидеть неактивные таймеры.

{% hint style="info" %}
Помните, что таймеры записываются в журнал systemd, и вы можете просмотреть журналы различных модулей с помощью команды `journalctl` . Также помните, что если вы действуете как обычный пользователь, вам нужно использовать опцию `--user` команд `systemctl` и `journalctl` .
{% endhint %}

Вместо более длинной нормализованной формы, упомянутой выше, вы можете использовать специальные выражения, описывающие определённые частоты выполнения заданий:

`hourly`

Выполняйте указанную задачу один раз в час, в начале часа.

`daily`

Запускайте указанную задачу один раз в день в полночь.

`weekly`

Запускайте указанную задачу раз в неделю в полночь понедельника.

`monthly`

Выполняйте указанное задание раз в месяц в полночь первого дня месяца.

`yearly`

Выполняйте указанное задание раз в год в полночь первого января.

## Краткие сведения <a href="#sec.107.2_01-su" id="sec.107.2_01-su"></a>

### Ответы на Исследовательские упражнения <a href="#sec.107.2_01-aee" id="sec.107.2_01-aee"></a>

1.  Предположим, что вы имеете право планировать задания с помощью `cron` как обычный пользователь. Какую команду вы бы использовали для создания собственного файла crontab?

    ```bash
    dave@hostname ~ $ crontab -e
    no crontab for dave - using an empty one

    Select an editor.  To change later, run 'select-editor'.
      1. /bin/ed
      2. /bin/nano        < ---- easiest
      3. /usr/bin/emacs24
      4. /usr/bin/vim.tiny

    Choose 1-4 [2]:
    ```
2.  Создайте простое запланированное задание, которое будет выполнять команду `date` каждую пятницу в 13:00. Где вы можете увидеть результаты выполнения этого задания?

    ```bash
    00 13 * * 5 date
    ```

    Результат отправляется пользователю по электронной почте; чтобы просмотреть его, вы можете использовать команду `mail` .
3.  Создайте ещё одно запланированное задание, которое будет выполнять скрипт `foobar.sh` каждую минуту, перенаправляя вывод в файл `output.log` в вашем домашнем каталоге, чтобы вам по электронной почте отправлялись только стандартные ошибки.

    ```bash
    */1 * * * * ./foobar.sh >> output.log
    ```
4.  Посмотрите на запись `crontab` в только что созданном запланированном задании. Почему необязательно указывать абсолютный путь к файлу, в котором сохраняется стандартный вывод? И почему для выполнения скрипта можно использовать команду `./foobar.sh`?

    `cron` запускает команды из домашнего каталога пользователя, если другое местоположение не указано в переменной среды `HOME` в файле `crontab`. По этой причине вы можете использовать относительный путь к выходному файлу и запустить скрипт с помощью `./foobar.sh`.
5.  Отредактируйте предыдущую запись `crontab` , удалив перенаправление вывода и отключив первое созданное вами задание cron.

    ```bash
    #00 13 * * 5 date
    */1 * * * * ./foobar.sh
    ```

    Чтобы отключить задание cron, вы можете просто закомментировать соответствующую строку в файле `crontab`
6.  Как вы можете отправлять выходные данные и ошибки запланированного задания на электронную почту `emma` учётной записи пользователя? И как можно избежать отправки стандартных выходных данных и ошибок по электронной почте?

    Чтобы отправить стандартный вывод и ошибки в `emma`, необходимо задать переменную среды `MAILTO` в файле `crontab` следующим образом:

    ```
    MAILTO="emma"
    ```

    Чтобы сообщить `cron` о том, что письмо не должно быть отправлено, вы можете присвоить переменной среды `MAILTO` пустое значение.

    ```
    MAILTO=""
    ```
7.  Выполните команду `ls -l /usr/bin/crontab`. Какой специальный бит установлен и что он означает?

    ```bash
    $ ls -l /usr/bin/crontab
    -rwxr-sr-x 1 root crontab 25104 feb 10  2015 /usr/bin/crontab
    ```

    У `crontab` команды установлен бит SGID (`s` символ вместо флага исполняемого файла для группы), что означает, что она выполняется с привилегиями группы (таким образом, `crontab`). Вот почему обычные пользователи могут редактировать свой `crontab` файл с помощью `crontab` команды. Обратите внимание, что во многих дистрибутивах права доступа к файлам установлены таким образом, что `crontab` файлы можно редактировать только с помощью `crontab` команды.
