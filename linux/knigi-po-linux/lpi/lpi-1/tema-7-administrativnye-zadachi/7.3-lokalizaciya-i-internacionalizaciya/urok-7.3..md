# Урок 7.3.

## Введение <a href="#sec.107.3_01-in" id="sec.107.3_01-in"></a>

Все основные дистрибутивы Linux можно настроить для использования пользовательских параметров локализации. Эти параметры включают определения, связанные с регионом и языком, такие как часовой пояс, язык интерфейса, а также кодировку символов. Их можно изменить во время установки операционной системы или в любое другое время после этого.

Приложения используют переменные среды, файлы конфигурации системы и команды для определения подходящего времени и языка; поэтому в большинстве дистрибутивов Linux используется стандартизированный способ настройки времени и параметров локализации. Эти настройки важны не только для улучшения пользовательского опыта, но и для корректного расчёта времени системных событий, например, для отслеживания проблем, связанных с безопасностью.

Чтобы иметь возможность отображать любой письменный текст, независимо от языка, на котором он написан, современным операционным системам требуется эталонный _стандарт кодировки символов (character encoding standard)_, и системы Linux не являются исключением. Поскольку компьютеры могут работать только с числами, текстовый символ — это не что иное, как число, связанное с графическим символом. Разные компьютерные платформы могут присваивать разные числовые значения одному и тому же символу, поэтому для их совместимости необходим общий стандарт кодировки символов. Текстовый документ, созданный в одной системе, будет читаться в другой системе только в том случае, если обе системы согласуют формат кодировки и то, какое число соответствует какому символу, или, по крайней мере, если они знают, как преобразовывать между двумя стандартами.

Разнообразие настроек локализации в системах на базе Linux приводит к незначительным различиям между дистрибутивами. Несмотря на эти различия, все дистрибутивы используют одни и те же базовые инструменты и концепции для настройки аспектов интернационализации системы.

## Часовые пояса <a href="#sec.107.3_01-tdst" id="sec.107.3_01-tdst"></a>

Часовые пояса — это примерно пропорциональные дискретные полосы на поверхности Земли, охватывающие один час, то есть регионы мира, в которых в любой момент времени наступает один и тот же час суток. Поскольку не существует единой долготы, которая могла бы считаться началом суток для всего мира, часовые пояса отсчитываются от _нулевого меридиана_, где угол долготы Земли равен 0. Время на нулевом меридиане называется _всемирным координированным временем Coordinated Universal Time_ и по соглашению сокращается до UTC. По практическим соображениям часовые пояса не соответствуют точному продольному расстоянию от исходной точки (нулевого меридиана). Вместо этого часовые пояса искусственно адаптированы к границам стран или других значимых подразделений.

Политические подразделения настолько важны, что часовые пояса названы в честь какого-либо крупного географического объекта в этой конкретной области, обычно по названию крупной страны или города внутри пояса. Тем не менее, часовые пояса разделены в соответствии с их смещением относительно UTC, и это смещение также может использоваться для обозначения соответствующего пояса. Например, часовой пояс _GMT-5_ указывает на регион, в котором время UTC на пять часов опережает местное время, то есть этот регион на 5 часов отстаёт от UTC. Аналогичным образом, часовой пояс _GMT+3_ указывает на регион, в котором время UTC отстаёт на три часа. Термин GMT — от _среднего времени по Гринвичу Greenwich Mean Time_  — используется как синоним UTC в названиях часовых поясов, основанных на смещении.

Доступ к подключенному компьютеру возможен из разных уголков мира, поэтому рекомендуется устанавливать аппаратные часы на UTC (часовой пояс GMT + 0) и оставлять выбор часового пояса для каждого конкретного случая. Облачные сервисы, например, обычно настроены на использование UTC, поскольку это может помочь уменьшить случайные несоответствия между местным временем и временем на клиентах или других серверах. Напротив, пользователи, открывающие удаленный сеанс на сервере, могут захотеть использовать свой местный часовой пояс. Таким образом, операционная система будет самостоятельно устанавливать правильный часовой пояс в каждом конкретном случае.

Помимо текущей даты и времени, команда `date` также выведет текущий часовой пояс:

```bash
$ date
Mon Oct 21 10:45:21 -03 2019
```

Смещение относительно UTC задаётся значением `-03`, что означает, что отображаемое время на три часа меньше UTC. Таким образом, UTC на три часа опережает время, что делает _GMT-3_ соответствующим часовым поясом для данного времени. Команда `timedatectl`, доступная в дистрибутивах, использующих systemd, показывает более подробную информацию о системном времени и дате:

```bash
$ timedatectl
                      Local time: Sat 2019-10-19 17:53:18 -03
                  Universal time: Sat 2019-10-19 20:53:18 UTC
                        RTC time: Sat 2019-10-19 20:53:18
                       Time zone: America/Sao_Paulo (-03, -0300)
       System clock synchronized: yes
systemd-timesyncd.service active: yes
                 RTC in local TZ: no
```

Как показано в записи `Time zone` , также принимаются названия часовых поясов, основанные на названиях населённых пунктов, например `America/Sao_Paulo` . Часовой пояс по умолчанию для системы хранится в файле `/etc/timezone` либо в виде полного описательного названия часового пояса, либо в виде смещения. Общие названия часовых поясов, заданные смещением UTC, должны включать `Etc` в качестве первой части названия. Таким образом, чтобы установить часовой пояс по умолчанию GMT+3, название часового пояса должно быть `Etc/GMT+3`:

```
$ cat /etc/timezone
Etc/GMT+3
```

Хотя для работы с названиями часовых поясов, основанными на географических названиях, не требуется смещение во времени, их не так просто выбрать. Один и тот же часовой пояс может иметь несколько названий, что затрудняет запоминание. Чтобы решить эту проблему, команда `tzselect` предлагает интерактивный метод, который поможет пользователю выбрать правильный часовой пояс. Команда `tzselect` должна быть доступна по умолчанию во всех дистрибутивах Linux, так как она предоставляется пакетом, содержащим необходимые служебные программы, связанные с библиотекой GNU C.


## Переход на Летнее время <a href="#sec.107.3_01-dst" id="sec.107.3_01-dst"></a>

Во многих регионах в течение части года действует переход на летнее время, когда часы обычно переводятся на час вперёд. Из-за неправильно настроенной системы в этот сезон года может отображаться неправильное время.

Файл `/etc/localtime` содержит данные, используемые операционной системой для соответствующей настройки часов. В стандартных системах Linux файлы для всех часовых поясов находятся в каталоге `/usr/share/zoneinfo/`, поэтому `/etc/localtime` — это просто символическая ссылка на фактический файл данных в этом каталоге. Файлы в `/usr/share/zoneinfo/` организованы по названию соответствующего часового пояса, поэтому файл данных для часового пояса `America/Sao_Paulo` будет `/usr/share/zoneinfo/America/Sao_Paulo`

Поскольку определения перехода на летнее время могут меняться, важно поддерживать файлы в `/usr/share/zoneinfo/` в актуальном состоянии. Команда обновления инструмента управления пакетами, предоставляемого дистрибутивом, должна обновлять их каждый раз, когда появляется новая версия.

## Язык и кодировка символов <a href="#sec.107.3_01-lce" id="sec.107.3_01-lce"></a>

Системы Linux могут работать с широким спектром языков и не западных кодировок символов, которые называются _локалями_. Самая базовая конфигурация локали — это определение переменной среды `LANG`, с помощью которой большинство программ командной оболочки определяют используемый язык.

Содержимое переменной `LANG` соответствует формату `ab_CD`, где `ab` — код языка, а `CD` — код региона. Код языка должен соответствовать стандарту ISO-639, а код региона — стандарту ISO-3166. Например, в системе, настроенной на использование бразильского португальского языка, переменная `LANG` должна быть определена как `pt_BR.UTF-8`:

```bash
$ echo $LANG
pt_BR.UTF-8
```

Как видно из примера вывода, переменная `LANG` также содержит кодировку символов, предназначенную для системы. ASCII, сокращение от _«Американский стандартный код для обмена информацией American Standard Code for Information Interchange»_, был первым широко используемым стандартом кодировки символов для электронной связи. Однако, поскольку ASCII имеет очень ограниченный диапазон доступных числовых значений и основан на английском алфавите, он не содержит символы, используемые в других языках, или расширенный набор неалфавитных символов. Кодировка UTF-8 — это _стандарт Юникода_ для обычных западных символов, а также многих других нестандартных символов. Как заявляет _Консорциум Юникод_, разработчик _стандарта Юникод_, он должен использоваться по умолчанию для обеспечения совместимости между компьютерными платформами:

> Стандарт Юникод предоставляет уникальный номер для каждого символа, независимо от платформы, устройства, приложения или языка. Он был принят всеми современными разработчиками программного обеспечения и теперь позволяет передавать данные между различными платформами, устройствами и приложениями без потери информации. Поддержка Юникода лежит в основе представления языков и символов во всех основных операционных системах, поисковых системах, браузерах, ноутбуках и смартфонах, а также в Интернете и Всемирной паутине (URL-адреса, HTML, XML, CSS, JSON и т. д.). (…) Стандарт Юникод и доступность поддерживающих его инструментов являются одними из наиболее значимых тенденций в области программного обеспечения в мире.

— Консорциум Unicode\
&#xNAN;_&#x427;то такое Юникод?_

<mark style="background-color:green;">Некоторые системы по-прежнему могут использовать стандарты ISO, такие как ISO-8859-1, для кодирования символов, отличных от ASCII. Однако такие стандарты кодирования символов следует заменить стандартами кодирования Unicode. Тем не менее, все основные операционные системы по умолчанию используют стандарт Unicode.</mark>

Настройки локали для всей системы задаются в файле `/etc/locale.conf`. Переменная `LANG` и другие переменные, связанные с локалью, задаются в этом файле как обычные переменные оболочки, например:

```bash
$ cat /etc/locale.conf
LANG=pt_BR.UTF-8
```

Пользователи могут использовать пользовательскую конфигурацию локали, переопределив `LANG` переменную окружения. Это можно сделать только для текущего сеанса или для будущих сеансов, добавив новое определение в профиль пользователя Bash в `~/.bash_profile` или `~/.profile`. Однако до тех пор, пока пользователь не войдет в систему, язык системы по умолчанию по-прежнему будет использоваться независимыми от пользователя программами, такими как экран входа в display Manager.

{% hint style="info" %}
Команда `localectl`, доступная в системах, использующих _systemd_ в качестве системного менеджера, также может использоваться для запроса и изменения системного языка. Например: `localectl set-locale LANG=en_US.UTF-8`.
{% endhint %}

Помимо переменной `LANG` другие переменные среды влияют на определённые аспекты локали, например, на то, какой символ валюты использовать или какой разделитель тысяч использовать для чисел:

`LC_COLLATE`

Устанавливает алфавитный порядок. Одна из его функций — определять порядок перечисления файлов и каталогов.

`LC_CTYPE`

Задаёт, как система будет обрабатывать определённые наборы символов. Например, определяет, какие символы считать _прописными_ или _строчными_.

`LC_MESSAGES`

Задает язык для отображения программных сообщений (в основном программ GNU).

`LC_MONETARY`

Задает денежную единицу и формат валюты.

`LC_NUMERIC`

Устанавливает числовой формат для неденежных значений. Его основная задача — определить разделители тысяч и десятичных дробей.

`LC_TIME`

Задает формат времени и даты.

`LC_PAPER`

Задает стандартный формат бумаги.

`LC_ALL`

Переопределяет все остальные переменные, включая `LANG`.

Команда `locale` покажет все определенные переменные в текущей конфигурации локали:

```
$ locale
LANG=pt_BR.UTF-8
LC_CTYPE="pt_BR.UTF-8"
LC_NUMERIC=pt_BR.UTF-8
LC_TIME=pt_BR.UTF-8
LC_COLLATE="pt_BR.UTF-8"
LC_MONETARY=pt_BR.UTF-8
LC_MESSAGES = "pt_BR.UTF-8"
LC_PAPER = pt_BR.UTF-8
LC_NAME = pt_BR.UTF-8
LC_ADDRESS = pt_BR.UTF-8
LC_TELEPHONE = pt_BR.UTF-8
LC_MEASUREMENT = pt_BR.UTF-8
LC_IDENTIFICATION = pt_BR.UTF-8
LC_ALL =
```

Единственная неопределённая переменная — это `LC_ALL`, которую можно использовать для временного переопределения всех остальных настроек локали. В следующем примере показано, как команда `date` — запущенная в системе, настроенной на локаль `pt_BR.UTF-8` — изменит свой вывод в соответствии с новой переменной `LC_ALL`:

```bash
$ date
seg out 21 10:45:21 -03 2019
$ env LC_ALL=en_US.UTF-8 date
Mon Oct 21 10:45:21 -03 2019
```

Изменение переменной `LC_ALL` привело к тому, что сокращения для обозначения дня недели и названия месяца отображаются на американском английском (`en_US`). Однако необязательно устанавливать один и тот же языковой стандарт для всех переменных. Например, можно установить язык на `pt_BR` и числовой формат (`LC_NUMERIC`) на американский стандарт.

Некоторые настройки локализации изменяют то, как программы работают с алфавитным порядком и числовыми форматами. В то время как обычные программы обычно готовы правильно выбрать общую локаль для таких ситуаций, скрипты могут вести себя неожиданно при попытке, например, правильно упорядочить список элементов по алфавиту. По этой причине рекомендуется установить переменную среды `LANG` на общую локаль `C`, как в `LANG=C`, чтобы скрипт выдавал однозначные результаты независимо от определений локализации, используемых в системе, в которой он выполняется. Локаль C выполняет только простое побайтовое сравнение, поэтому она также будет работать лучше, чем другие.

## Преобразование кодировки <a href="#sec.107.3_01-ec" id="sec.107.3_01-ec"></a>

При отображении текста в системе с другой кодировкой символов, отличной от той, в которой был создан текст, могут отображаться непонятные символы. Для решения этой проблемы можно использовать команду `iconv` для преобразования файла из исходной кодировки символов в нужную. Например, чтобы преобразовать файл с именем `original.txt` из кодировки ISO-8859-1 в файл с именем `converted.txt` в кодировке UTF-8, можно использовать следующую команду:

```bash
$ iconv -f ISO-8859-1 -t UTF-8 original.txt > converted.txt
```

Параметр `-f ISO-8859-1` (или `--from-code=ISO-8859-1`) устанавливает кодировку исходного файла, а параметр `-t UTF-8` (или `--to-code=UTF-8`) устанавливает кодировку преобразованного файла. Все кодировки, поддерживаемые командой `iconv`, перечислены с помощью команды `iconv -l` или `iconv --list`. Вместо перенаправления вывода, как в примере, можно также использовать параметр `-o converted.txt` или `--output converted.txt`.

## Ответы на Упражнения с Руководством <a href="#sec.107.3_01-age" id="sec.107.3_01-age"></a>

1.  Исходя из следующего вывода команды `date`, каков часовой пояс системы в формате GMT?

    ```bash
    $ date
    Mon Oct 21 18:45:21 +05 2019
    ```

    Это `Etc/GMT+5` часовой пояс.
2.  На какой файл должна указывать символическая ссылка `/etc/localtime` для того, чтобы `Europe/Brussels` стало системным временем по умолчанию?

    Ссылка `/etc/localtime` должна указывать на `/usr/share/zoneinfo/Europe/Brussels`.
3.  Символы в текстовых файлах могут отображаться некорректно в системе с кодировкой, отличной от той, которая используется в текстовом документе. Как можно `iconv` преобразовать файл `old.txt` с кодировкой WINDOWS-1252 в файл `new.txt` с кодировкой UTF-8?

    Команда `iconv -f WINDOWS-1252 -t UTF-8 -o new.txt old.txt` выполнит желаемое преобразование.

### Ответы на Исследовательские упражнения <a href="#sec.107.3_01-aee" id="sec.107.3_01-aee"></a>

1.  Какая команда установит `Pacific/Auckland` часовой пояс по умолчанию для текущего сеанса командной строки?

    `export TZ=Pacific/Auckland`
2.  Команда `uptime` показывает, помимо прочего, _среднюю загрузку_ системы в дробных числах. Она использует текущие настройки локали, чтобы определить, должен ли десятичный разделитель быть точкой или запятой. Если, например, текущая локали установлена на `de_DE.UTF-8` (стандартную локаль Германии), `uptime` будет использовать запятую в качестве разделителя. Зная, что в американском английском в качестве разделителя используется точка, какая команда заставит `uptime` отображать дроби с точкой вместо запятой до конца текущего сеанса?

    Команда `export LC_NUMERIC=en_US.UTF-8` или `export LC_ALL=en_US.UTF-8`.
3.  Команда `iconv` заменит все символы, не входящие в целевой набор символов, на вопросительный знак. Если `//TRANSLIT` добавить к целевой кодировке, символы, не входящие в целевой набор символов, будут заменены (транслитерированы) на один или несколько похожих символов. Как использовать этот метод для преобразования текстового файла UTF-8 с именем `readme.txt` в обычный файл ASCII с именем `ascii.txt`?

    Команда `iconv -f UTF-8 -t ASCII//TRANSLIT -o ascii.txt readme.txt` выполнит желаемое преобразование.
