# Урок 3.5.1.

## Введение <a href="#sec.103.5_01-in" id="sec.103.5_01-in"></a>

Каждый раз, когда мы запускаем команду, запускается один или несколько процессов. Хорошо обученный системный администратор должен не только создавать процессы, но и уметь отслеживать их и при необходимости отправлять им различные типы сигналов. В этом уроке мы рассмотрим управление заданиями и способы отслеживания процессов.

## Контроль выполнения задания <a href="#job_control" id="job_control"></a>

_Задания_ — это процессы, которые были запущены в интерактивном режиме через терминал, отправлены в фоновый режим и ещё не завершили выполнение. Вы можете узнать об активных заданиях (и их статусе) в вашей системе Linux, выполнив `jobs`:

```bash
$ jobs
```

Приведённая выше команда `jobs` не выдала никаких результатов, что означает, что в данный момент нет активных заданий. Давайте создадим наше первое задание, запустив команду, выполнение которой занимает некоторое время (команда `sleep` с параметром `60`), и во время выполнения нажмите Ctrl+Z:

```bash
$ sleep 60
^Z
[1]+  Stopped                 sleep 60
```

Выполнение команды было остановлено (или, скорее, приостановлено), и командная строка снова доступна. Вы можете поискать задания во второй раз и теперь найдёте _приостановленное_:

```bash
$ jobs
[1]+  Stopped                 sleep 60
```

Давайте объясним результат:

`[1]`

Это число является идентификатором задания и может использоваться — перед символом процента (`%`) — для изменения статуса задания с помощью `fg`, `bg` и `kill` утилит (как вам будет показано позже).

`+`

Знак «плюс» указывает на текущее задание по умолчанию (то есть на последнее задание, которое приостановлено или отправлено в фоновый режим). Предыдущее задание помечается знаком «минус» (`-`). Другие предыдущие задания не помечаются.

`Stopped`

Описание статуса задания.

`sleep 60`

Сама команда или задание.

С опцией `-l` задания будут дополнительно отображать идентификатор процесса (PID) непосредственно перед статусом:

```bash
$ jobs -l
[1]+  1114 Stopped                 sleep 60
```

Остальные возможные варианты заданий следующие:

`-n`

Перечисляются только процессы, статус которых изменился с момента последнего уведомления. Возможные статусы: `Running`, `Stopped`, `Terminated` или `Done`.

`-p`

Перечисляет идентификаторы процессов.

`-r`

Перечислены только запущенные задания.

`-s`

Перечислены только остановленные (или приостановленные) задания.

{% hint style="info" %}
Помните, что у задания есть как _идентификатор задания_, так и _идентификатор процесса_ (PID).
{% endhint %}

## **Спецификация задания**

Команде `jobs` и другим утилитам, таким как `fg`, `bg` и `kill` (которые вы увидите в следующем разделе), для работы с конкретным заданием требуется спецификация задания (или `jobspec`). Как мы только что увидели, это может быть — и обычно является — идентификатором задания, перед которым стоит `%`. Однако возможны и другие спецификации заданий. Давайте рассмотрим их:

`%n`

Работа, идентификационный номер которой `n`:

```bash
$ jobs %1
[1]+  Stopped                 sleep 60
```

`%str`

Задание, командная строка которого начинается с `str`:

```bash
$ jobs %sl
[1]+  Stopped                 sleep 60
```

`%?str`

Задание, командная строка которого содержит `str`:

```bash
$ jobs %?le
[1]+  Stopped                 sleep 60
```

`%+` или `%%`

Текущее задание (последнее запущенное в фоновом режиме или приостановленное на переднем плане):

```bash
$ jobs %+
[1]+  Stopped                 sleep 60
```

`%-`

Предыдущее задание (то, которое было `%+` до текущего задания по умолчанию):

```bash
$ jobs %-
[1]+  Stopped                 sleep 60
```

В нашем случае, поскольку есть только одна работа, она является и текущей, и предыдущей.

## **Статус задания: Приостановка, передний план и задний план**

Если задание выполняется в фоновом режиме или приостановлено, мы можем сделать с ним одно из трёх действий:

1.  Перенесите это на передний план с помощью `fg`:

    ```bash
    $ fg %1
    sleep 60
    ```

    `fg` выводит указанное задание на передний план и делает его текущим заданием. Теперь мы можем дождаться его завершения, снова остановить его с помощью Ctrl+Z или завершить с помощью Ctrl+C.
2.  Перенесите это на задний план с помощью `bg`:

    ```bash
    $ bg %1
    [1]+ sleep 60 &
    ```

    После перехода в фоновый режим задание можно вернуть на передний план с помощью `fg` или завершить (см. ниже). Обратите внимание на амперсанд (`&`), означающий, что задание было отправлено в фоновый режим. Кстати, амперсанд можно использовать и для запуска процесса непосредственно в фоновом режиме:

    ```bash
    $ sleep 100 &
    [2] 970
    ```

    Вместе с идентификатором задания (`[2]`), мы также получаем идентификатор процесса (`970`). Теперь оба задания выполняются в фоновом режиме:

    ```bash
    $ jobs
    [1]-  Running                 sleep 60 &
    [2]+  Running                 sleep 100 &
    ```

    Чуть позже завершается выполнение первого задания:

    ```bash
    $ jobs
    [1]-  Done                    sleep 60
    [2]+  Running                 sleep 100 &
    ```
3.  Завершите его с помощью `SIGTERM` сигнала с помощью `kill`:

    ```bash
    $ kill %2
    ```

    Чтобы убедиться, что задание было завершено, запустите `jobs` еще раз:

    ```bash
    $ jobs
    [2]+  Terminated                 sleep 100
    ```

{% hint style="info" %}
Если задание не указано, `fg` и `bg` будут работать с текущим заданием по умолчанию. Однако `kill` всегда требует указания задания.
{% endhint %}

## **Независимые задания: `nohup`**

Задания, которые мы рассматривали в предыдущих разделах, были привязаны к сеансу пользователя, который их запустил. Это означает, что если сеанс будет завершён, задания исчезнут. Однако задания можно отсоединить от сеансов и запускать их даже после закрытия сеанса. Для этого используется команда `nohup` («без завершения»). Синтаксис следующий:

```bash
nohup COMMAND &
```

Помните, что `&` отправляет процесс в фоновый режим и освобождает терминал, в котором вы работаете.

Давайте отключим фоновое задание `ping localhost` от текущего сеанса:

```bash
$ nohup ping localhost &
[1] 1251
$ nohup: ignoring input and appending output to 'nohup.out'
^C
```

В выводе отображается идентификатор задания (`[1]`) и идентификатор процесса (`1251`), а затем сообщение о файле `nohup.out`. Это файл по умолчанию, в котором будут сохранены `stdout` и `stderr`. Теперь мы можем нажать Ctrl+C, чтобы освободить командную строку, закрыть сеанс, запустить другой сеанс с помощью `root` и использовать `tail -f` для проверки выполнения команды и записи вывода в файл по умолчанию:

```bash
$ exit
logout
$ tail -f /home/carol/nohup.out
64 bytes from localhost (::1): icmp_seq=3 ttl=64 time=0.070 ms
64 bytes from localhost (::1): icmp_seq=4 ttl=64 time=0.068 ms
64 bytes from localhost (::1): icmp_seq=5 ttl=64 time=0.070 ms
^Chint
```

{% hint style="info" %}
Вместо использования `nohup.out` по умолчанию вы могли бы указать выходной файл по своему выбору с помощью `nohup ping localhost > /path/to/your/file &`.
{% endhint %}

Если мы хотим завершить процесс, мы должны указать его PID:

```bash
# kill 1251
```

## Мониторинг процесса <a href="#process_monitoring" id="process_monitoring"></a>

Процесс или задача — это экземпляр запущенной программы. Таким образом, вы создаёте новые процессы каждый раз, когда вводите команды в терминал.

Команда `watch` периодически (по умолчанию каждые 2 секунды) запускает программу и позволяет нам _наблюдать_ за изменением её выходных данных с течением времени. Например, мы можем отслеживать, как меняется средняя нагрузка по мере запуска большего количества процессов, введя `watch uptime`:

```bash
Every  2.0s: uptime          debian: Tue Aug 20 23:31:27 2019

 23:31:27 up 21 min,  1 user,  load average: 0.00, 0.00, 0.00
```

Команда выполняется до тех пор, пока не будет прервана, поэтому нам нужно будет остановить её с помощью Ctrl+C. В результате мы получим две строки: первая соответствует `watch` и сообщает нам, как часто будет выполняться команда (`Every 2.0s: uptime`), какую команду/программу нужно отслеживать (`uptime`), а также имя хоста и дату (`debian: Tue Aug 20 23:31:27 2019`). Вторая строка вывода — это время безотказной работы, которое включает в себя время (`23:31:27`), в течение которого система работала (`up 21 min`), количество активных пользователей (`1 user`) и среднюю нагрузку на систему или количество процессов, выполняющихся или находящихся в состоянии ожидания, за последние 1, 5 и 15 минут (`load average: 0.00, 0.00, 0.00`).

Аналогичным образом вы можете отслеживать использование памяти при создании новых процессов с помощью `watch free`:

```bash
Every  2.0s: free            debian: Tue Aug 20 23:43:37 2019

 23:43:37 up 24 min,  1 user,  load average: 0.00, 0.00, 0.00
              total        used        free      shared  buff/cache   available
Mem:       16274868      493984    14729396       35064     1051488    15462040
Swap:      16777212           0    16777212
```

Чтобы изменить интервал обновления для `watch` используйте параметры `-n` или `--interval` и укажите количество секунд, например:

```bash
$ watch -n 5 free
```

Теперь команда `free` будет выполняться каждые 5 секунд.

Для получения дополнительной информации о параметрах для `uptime`, `free` и `watch`, пожалуйста, обратитесь к их справочным страницам.

{% hint style="info" %}
Информация, предоставляемая `uptime` и `free`, также интегрирована в более комплексные инструменты `top` и `ps` (см. ниже).
{% endhint %}

## **Отправка сигналов процессам: `kill`**

У каждого процесса есть уникальный идентификатор процесса, или PID. Один из способов узнать PID процесса — использовать команду `pgrep` с указанием имени процесса:

```bash
$ pgrep sleep
1201
```

{% hint style="info" %}
Идентификатор процесса также можно узнать с помощью команды `pidof` (например, `pidof sleep`).
{% endhint %}

Аналогично `pgrep`, `pkill` команда завершает процесс на основе его имени:

```bash
$ pkill sleep
[1]+  Terminated              sleep 60
```

Чтобы завершить несколько экземпляров одного и того же процесса, можно использовать команду `killall`:

```bash
$ sleep 60 &
[1] 1246
$ sleep 70 &
[2] 1247
$ killall sleep
[1]-  Terminated              sleep 60
[2]+  Terminated              sleep 70
```

И `pkill` и `killall` работают почти так же, как `kill`: они отправляют сигнал завершения указанному процессу (процессам). Если сигнал не указан, по умолчанию отправляется `SIGTERM`-сигнал. Однако `kill` принимает в качестве аргумента только задание или идентификатор процесса.

Сигналы могут быть заданы либо с помощью:

*   Имя:

    ```bash
    $ kill -SIGHUP 1247
    ```
*   Число:

    ```bash
    $ kill -1 1247
    ```
*   Опция:

    ```bash
    $ kill -s SIGHUP 1247
    ```

Чтобы `kill` работало так же, как `pkill` или `killall` (и чтобы не вводить команды для поиска PID), мы можем использовать подстановку команд:

```bash
$ kill -1 $ (pgrep sleep)
```

Как вы уже должны знать, альтернативным синтаксисом является `` kill -1 `pgrep sleep` ``.

{% hint style="info" %}
Чтобы получить полный список всех `kill` сигналов и их кодов, введите `kill -l` в терминале. Используйте `-KILL` (`-9` или `-s KILL`) для завершения процессов, нарушающих работу системы, если не работает другой сигнал.
{% endhint %}

## **`top` и `ps`**

Когда дело доходит до мониторинга процессов, двумя незаменимыми инструментами являются `top` и `ps`. Первый из них выводит данные динамически, а второй — статически. В любом случае, оба являются отличными инструментами для получения полного представления обо всех процессах в системе.

```bash
   PID USER      PR  NI    VIRT    RES    SHR S %CPU %MEM     TIME+ COMMAND
   436 carol     20   0   42696   3624   3060 R  0,7  0,4   0:00.30 top
     4 root      20   0       0      0      0 S  0,3  0,0   0:00.12 kworker/0:0
   399 root      20   0   95204   6748   5780 S  0,3  0,7   0:00.22 sshd
     1 root      20   0   56872   6596   5208 S  0,0  0,6   0:01.29 systemd
     2 root      20   0       0      0      0 S  0,0  0,0   0:00.00 kthreadd
     3 root      20   0       0      0      0 S  0,0  0,0   0:00.02 ksoftirqd/0
     5 root       0 -20       0      0      0 S  0,0  0,0   0:00.00 kworker/0:0H
     6 root      20   0       0      0      0 S  0,0  0,0   0:00.00 kworker/u2:0
     7 root      20   0       0      0      0 S  0,0  0,0   0:00.08 rcu_sched

    10 root       0 -20       0      0      0 S  0,0  0,0   0:00.00 lru-add-drain

```

`top` позволяет пользователю взаимодействовать с программой. По умолчанию вывод сортируется по проценту времени процессора, используемого каждым процессом, в порядке убывания. Это поведение можно изменить, нажав следующие клавиши в `top`:

`M`

Сортировка по использованию _памяти_.

`N`

Сортировка по _номеру_ идентификатора процесса.

`T`

Сортировка по _времени_ выполнения.

`P`

Сортировка по _проценту_ загрузки процессора.

{% hint style="info" %}
Для переключения между порядком убывания и возрастания просто нажмите `R`.
{% endhint %}

Другими интересными ключами для взаимодействия `top` являются:

`?` или `h`

Справка.

`k`

Убить процесс. `top` запросит уничтожение `PID` процесса, а также отправку сигнала (по умолчанию `SIGTERM` или `15`).

`r`

Измените приоритет процесса (`renice`). `top` запросит у вас значение `nice` . Возможные значения находятся в диапазоне от <mark style="color:red;">-20 до 19,</mark> но только суперпользователь (`root`) может установить отрицательное значение или значение ниже текущего.

`u`

Выведите список процессов конкретного пользователя (по умолчанию отображаются процессы всех пользователей).

`c`

Покажите абсолютные пути к программам и проведите различие между процессами пользовательского пространства и процессами ядра (в квадратных скобках).

`V`

Представление процессов в виде леса/иерархии.

`t` и `m`

Измените внешний вид показателей процессора и памяти в четыре этапа: при первых двух нажатиях отображаются индикаторы выполнения, при третьем нажатии индикатор скрывается, а при четвёртом — появляется снова.

`W`

Сохраните параметры конфигурации в `~/.toprc`.

{% hint style="info" %}
Более продвинутая и удобная для пользователя версия `top` — это `htop`. Другой — возможно, более полный — вариант — `atop`. Если они ещё не установлены в вашей системе, воспользуйтесь менеджером пакетов, чтобы установить их и попробовать.
{% endhint %}

## **Объяснение выходных данных `top`**

`top` Результат выводится в двух областях: _сводных данных_ и _область задач_.

## **Область** _сводных данных_ **в `top`**

_Область сводных данных_ состоит из пяти верхних строк и содержит следующую информацию:

* `top - 11:10:29 up 2:21, 1 user, load average: 0,11, 0,20, 0,14`
  * текущее время (в 24-часовом формате): `11:20:29`
  * время безотказной работы (сколько времени система была запущена): `up 2:21`
  * количество пользователей, вошедших в систему, и средняя загрузка ЦП за последние 1, 5 и 15 минут соответственно: `load average: 0,11, 0,20, 0,14`
* `Tasks: 73 total, 1 running, 72 sleeping, 0 stopped, 0 zombie` (информация о процессах)
  * общее количество процессов в активном режиме: `73 total`
  * запущенные (те, которые выполняются): `1 running`
  * спящие (те, кто ожидает возобновления выполнения): `72 sleeping`
  * остановлено (по сигналу управления заданием): `0 stopped`
  * зомби (те, которые завершили выполнение, но всё ещё ожидают, пока родительский процесс удалит их из таблицы процессов): `0 zombie`
* `%Cpu(s): 0,0 us, 0,3 sy, 0,0 ni, 99,7 id, 0,0 wa, 0,0 hi, 0,0 si, 0,0 st` (процент затраченного процессорного времени на)
  * пользовательские процессы: `0,0 us`
  * процессы системы/ ядра: `0,4 sy`
  * процессы с установленным значением _nice_ — чем выше значение, тем ниже приоритет: `0,0 ni`
  * nothing  ничего — время простоя процессора: `99,7 id`
  * процессы, ожидающие операций ввода-вывода: `0,0 wa`
  * процессы, обслуживающие аппаратные прерывания — периферийные устройства, отправляющие процессору сигналы, требующие внимания: `0,0 hi`
  * процессы, обслуживающие программные прерывания: `0,0 si`
  * процессы, выполняющие задачи других виртуальных машин в виртуальной среде, тем самым отнимают время: `0,0 st`
* `KiB Mem : 1020332 total, 909492 free, 38796 used, 72044 buff/cache` (информация о памяти в килобайтах)
  * общий объем памяти: `1020332 total`
  * неиспользуемая память: `909492 free`
  * используемая память: `38796 used`
  *   память, которая буферизуется и кэшируется во избежание чрезмерного доступа к диску: `72044 buff/cache`

      Обратите внимание, что `total` — это сумма трёх других значений — `free`, `used` и `buff/cache` (примерно 1 ГБ в нашем случае).
* `KiB Swap: 1046524 total, 1046524 free, 0 used. 873264 avail Mem` (обмен информацией в килобайтах)
  * общий объем пространства подкачки: `1046524 total`
  * неиспользуемое пространство подкачки: `1046524 free`
  * используемое пространство подкачки: `0 used`
  * объём памяти подкачки, который может быть выделен процессам без дополнительной подкачки: `873264 avail Mem`

## **Область задач в `top`: поля и столбцы**

Под _областью сводки_ находится _область задач_, которая включает ряд _полей_ и _столбцов_ с информацией о запущенных процессах:

`PID`

Идентификатор процесса.

`USER`

Пользователь, который выдал команду, сгенерировавшую процесс.

`PR`

Приоритет процесса перед ядром.

`NI`

_nice_ значение процесса. Более низкие значения имеют более высокий приоритет, чем более высокие.

`VIRT`

Общий объем памяти, используемой процессом (включая подкачку).

`RES`

Оперативная память, используемая процессом.

`SHR`

Общая память процесса с другими процессами.

`S`

Статус процесса. Значения включают: `S` (interruptible sleep  — ожидание завершения события), `R` (runnable выполняемый — либо выполняющийся, либо находящийся в очереди на выполнение) или `Z` (зомби — завершённые дочерние процессы, структуры данных которых ещё не удалены из таблицы процессов).

`%CPU`

Процент процессора, используемого процессом.

`%MEM`

Процент оперативной памяти, используемой процессом, то есть значение `RES` в процентах.

`TIME+`

Общее время действия процесса.

`COMMAND`

Название команды / программы, которая сгенерировала процесс.

## **Статический просмотр процессов: `ps`**

Как было сказано выше, `ps` показывает снимок процессов. Чтобы увидеть все процессы с помощью терминала (tty), введите `ps`&#x20;

```bash
$ ps a

  424 tty7     Ssl+   0:00 /usr/lib/xorg/Xorg :0 -seat seat0 (...)
  655 pts/0    Ss     0:00 -bash
 1186 pts/0    R+     0:00 ps a
 (...)
```

**Объяснение `ps` синтаксиса опции и выходных данных**

Что касается опций, `ps` может принимать три разных стиля: BSD, UNIX и GNU. Давайте посмотрим, как каждый из этих стилей работает при отображении информации об идентификаторе конкретного процесса:

BSD

Параметры не следуют за какой-либо ведущей черточкой:

```bash
$ ps p 811
  PID TTY      STAT   TIME COMMAND
  811 pts/0    S      0:00 -su
```

UNIX

Опции следуют за начальным тире:

```bash
$ ps -p 811
  PID TTY          TIME CMD
  811 pts/0    00:00:00 bash
```

GNU

Опции следуют за двойными начальными тире:

```bash
$ ps --pid 811
  PID TTY          TIME CMD
  811 pts/0    00:00:00 bash
```

Во всех трёх случаях `ps` сообщает информацию о процессе, чьим `PID` является `811` — в данном случае `bash`.

Аналогичным образом вы можете использовать `ps` для поиска процессов, запущенных конкретным пользователем:

* `ps U carol` (BSD)
* `ps -u carol` (UNIX)
* `ps --user carol` (GNU)

Давайте проверим процессы, запущенные `carol`:

```bash
$ ps U carol
  PID TTY      STAT   TIME COMMAND
  811 pts/0    S      0:00 -su
  898 pts/0    R+     0:00 ps U carol
```

Она запустила два процесса: `bash` (`-su`) и `ps` (`ps U carol`). В столбце `STAT` указано состояние процесса (см. ниже).

Мы можем извлечь максимум пользы из `ps` , объединив некоторые из её опций. Очень полезная команда (выдающая результат, аналогичный `top` ) — `ps aux` (в стиле BSD). В этом случае отображаются процессы из всех оболочек (не только из текущей). Переключатели имеют следующее значение:

`a`

Покажите процессы, которые подключены к `tty` или терминалу.

`u`

Отображать формат, ориентированный на пользователя.

`x`

Покажите процессы, которые не подключены к `tty` или терминалу.

```bash
$ ps aux
USER       PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root         1  0.0  0.1 204504  6780 ?        Ss   14:04   0:00 /sbin/init
root         2  0.0  0.0      0     0 ?        S    14:04   0:00 [kthreadd]
root         3  0.0  0.0      0     0 ?        S    14:04   0:00 [ksoftirqd/0]
root         5  0.0  0.0      0     0 ?        S<   14:04   0:00 [kworker/0:0H]
root         7  0.0  0.0      0     0 ?        S    14:04   0:00 [rcu_sched]
root         8  0.0  0.0      0     0 ?        S    14:04   0:00 [rcu_bh]
root         9  0.0  0.0      0     0 ?        S    14:04   0:00 [migration/0]
(...)
```

Давайте объясним  столбцы:

`USER`

Владелец процесса.

`PID`

Идентификатор процесса.

`%CPU`

Процент использования процессора.

`%MEM`

Процент используемой физической памяти.

`VSZ`

Виртуальная память процесса в КиБ.

`RSS`

Физическая память без подкачки, используемая процессом в КиБ.

`TT`

Терминал (`tty`), управляющий процессом.

`STAT`

Код, представляющий состояние процесса. Помимо `S`, `R` и `Z` (которые мы видели при описании вывода `top`), другие возможные значения включают: `D` (uninterruptible sleep — обычно в ожидании ввода-вывода), `T` (stopped  — обычно сигналом управления). Некоторые дополнительные модификаторы включают: `<` (высокий приоритет — не nice для других процессов), `N` (низкий приоритет — nice для других процессов) или `+` (в группе процессов переднего плана).

`STARTED`

Время начала процесса.

`TIME`

Накопленное процессорное время.

`COMMAND`

Команда, запустившая процесс.

## Краткие сведения <a href="#sec.103.5_01-su" id="sec.103.5_01-su"></a>

На этом уроке вы узнали о заданиях и _контроле за заданиями_. Важно помнить о следующих фактах и понятиях:

* Задания - это процессы, которые отправляются в фоновом режиме.
* Помимо _идентификатора процесса_, при создании задания также присваивается _идентификатор задания_.
* Для контроля заданий требуется должностная спецификация (`jobspec`).
* Задания можно вывести на передний план, отправить в фоновый режим, приостановить и завершить (или _убить_).
* Задание может быть отделено от терминала и сеанса, в котором оно было создано.

Кроме того, мы также обсудили концепцию _процессов_ и _мониторинга процессов_. Наиболее важные идеи:

* Процессы - это запущенные программы.
* Процессы можно отслеживать.
* Различные утилиты позволяют нам узнать _идентификатор процесса_, а также отправлять им сигналы для завершения работы.
* Сигналы можно указать по имени (например, `-SIGTERM`), номеру (например, `-15`) или опции (например, `-s SIGTERM`).
* `top` и `ps` очень эффективны при мониторинге процессов. Выходные данные первого типа являются динамическими и постоянно обновляются; с другой стороны, `ps` показывает статические выходные данные.

Команды, используемые в этом уроке:

`jobs`

Отображение активных заданий и их состояния.

`sleep`

Приостановить на определенный промежуток времени.

`fg`

&#x20;Переместите задание на передний план.

`bg`

Переместите задание в фоновый режим.

`kill`

Завершите задание.

`nohup`

Отсоедините задание от сеанса / терминала.

`exit`

Выйдите из текущей командной строки.

`tail`

Отображение самых последних строк в файле.

`watch`

Отследить команду несколько раз (по умолчанию цикл составляет 2 секунды).

`uptime`

Отобразить, как долго работает система, количество текущих пользователей и среднюю нагрузку на систему.

`free`

Отображение использования памяти.

`pgrep`

Найти идентификатор процесса на основе имени.

`pidof`

Найти идентификатор процесса на основе имени.

`pkill`

Отправьте сигнал процессу по имени.

`killall`

Уничтожьте процесс (ы) по имени.

Отображение процессов Linux.

Создать отчет о моментальном снимке текущих процессов.

       ```bash
       $ kill -SIGHUP 1653
       ```
   *   Убедитесь, что родитель не был убит и что были созданы новые дочерние элементы:

       ```bash
       $ ps aux | grep apache2
       ```

       Теперь вы должны увидеть родительский `apache2` процесс вместе с двумя новыми дочерними процессами.
2. Хотя изначально вывод `ps` является статичным, его можно _сделать_ динамичным, объединив `ps` и `watch`. Мы будем отслеживать новые подключения на _веб-сервере Apache HTTPD_. Прежде чем выполнять описанные ниже задачи, рекомендуется ознакомиться с описанием директивы `MaxConnectionsPerChild` в [общих директивах Apache MPM](https://httpd.apache.org/docs/current/mod/mpm\_common.html).
   *   Добавьте `MaxConnectionsPerChild` директиву со значением `1` в конфигурационный файл `apache2` — в _Debian_ и производных от него, который находится в `/etc/apache2/apache2.conf`; в семействе _CentOS_, в `/etc/httpd/conf/httpd.conf`. Не забудьте перезапустить, `apache2` чтобы изменения вступили в силу.

       Строка, которую нужно включить в файл конфигурации, выглядит так: `MaxConnectionsPerChild 1`. Один из способов перезапустить веб-сервер — использовать `sudo systemctl restart apache2`.
   *   Введите команду, которая использует соединения `watch`, `ps` и `grep` for `apache2`.



       ```bash
       $ watch 'ps aux | grep apache2'
       $ watch "ps aux | grep apache2"
       ```
   *   Теперь откройте веб-браузер или используйте браузер командной строки, например `lynx`, чтобы установить соединение с веб-сервером по его IP-адресу. Что вы видите в выводе `watch`?

       Один из дочерних процессов, принадлежащих `www-data`, исчезает.
3. Как вы узнали, по умолчанию `top` сортирует задачи по проценту загрузки ЦП в порядке убывания (более высокие значения вверху). Это поведение можно изменить с помощью интерактивных клавиш `M` (загрузка памяти), `N` (уникальный идентификатор процесса), `T` (время выполнения) и `P` (процент загрузки ЦП). Однако вы также можете отсортировать список задач по своему усмотрению, запустив `top` с ключом `-o` (для получения дополнительной информации см. страницу `man` команды top). Теперь выполните следующие задачи:
   *   Запустите `top`, чтобы задачи были отсортированы по использованию памяти:

       ```bash
       $ top -o %MEM
       ```
   *   Убедитесь, что вы ввели правильную команду, выделив столбец памяти:

       `Press x`.
4. `ps` Также есть переключатель `o` для указания столбцов, которые вы хотите отобразить. Изучите этот вопрос и выполните следующие задачи:
   *   Запустите `ps` так, чтобы отображалась только информация о _пользователе_, _проценте используемой памяти_, _проценте используемого процессорного времени_ и _полной команде_:

       ```bash
       $ ps o user,%mem,%cpu,cmd
       ```
   *   Теперь запустите `ps` так, чтобы отображалась только информация о пользователе и названиях используемых им программ:

       ```bash
       $ ps o user,comm
       ```
