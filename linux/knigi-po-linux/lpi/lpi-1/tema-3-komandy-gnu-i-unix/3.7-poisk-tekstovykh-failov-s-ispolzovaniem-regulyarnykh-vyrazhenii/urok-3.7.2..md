# Урок 3.7.2.

## Введение <a href="#sec.103.7_02-in" id="sec.103.7_02-in"></a>

Потоковая передача данных по цепочке команд позволяет применять составные фильтры на основе регулярных выражений. Регулярные выражения — важный метод, используемый не только в системном администрировании, но и в _анализе данных_ и смежных областях. Две команды специально предназначены для работы с файлами и текстовыми данными с помощью регулярных выражений: `grep` и `sed`. `grep` — это поиск шаблонов, а `sed` — редактор потоков. Они полезны сами по себе, но особенно эффективны в сочетании с другими процессами.

## Поиск шаблонов: grep <a href="#the_pattern_finder_grep" id="the_pattern_finder_grep"></a>

Одно из наиболее распространённых применений `grep` — упрощение просмотра длинных файлов с помощью регулярного выражения в качестве фильтра, применяемого к каждой строке. Его можно использовать для отображения только строк, начинающихся с определённого термина. Например, `grep` можно использовать для изучения файла конфигурации модулей ядра, отображая только строки с параметрами:

```bash
$ grep '^options' /etc/modprobe.d/alsa-base.conf
options snd-pcsp index=-2
options snd-usb-audio index=-2
options bt87x index=-2
options cx88_alsa index=-2
options snd-atiixp-modem index=-2
options snd-intel8x0m index=-2
options snd-via82xx-modem index=-2
```

Символ  `|` можно использовать для перенаправления вывода команды непосредственно на `grep`'s ввод. В следующем примере используется выражение в квадратных скобках для выбора строк из `fdisk -l` вывода, начиная с `Disk /dev/sda` или `Disk /dev/sdb`:

```bash
# fdisk -l | grep '^Disk /dev/sd[ab]'
Disk /dev/sda: 320.1 GB, 320072933376 bytes, 625142448 sectors
Disk /dev/sdb: 7998 MB, 7998537728 bytes, 15622144 sectors
```

Простое выделение строк с совпадениями может не подойти для конкретной задачи и потребовать корректировки поведения `grep` с помощью опций. Например, опция `-c` или `--count` указывает `grep` на то, что нужно показать, сколько строк содержат совпадения:

```bash
# fdisk -l | grep '^Disk /dev/sd[ab]' -c
2
```

Опцию можно разместить до или после регулярного выражения. Другие важные `grep` опции:

`-c` или `--count`

Вместо отображения результатов поиска выведите только общее количество совпадений в каждом файле.

`-i` или `--ignore-case`

Сделайте поиск нечувствительным к регистру.

`-f FILE` или `--file=FILE`

Укажите файл, содержащий регулярное выражение для использования.

`-n` или `--line-number`

Покажите номер строки.

`-v` или `--invert-match`

Выделите все строки, кроме тех, которые содержат совпадения.

`-H` или `--with-filename`

Выведите также имя файла, содержащего эту строку.

`-z` или `--null-data`

Вместо того, чтобы рассматривать потоки входных и выходных данных как отдельные строки (используя _новую строку_ по умолчанию) принимать входные или выходные данные как последовательность строк. При объединении выходных данных команды `find` с использованием ее `-print0` опции с `grep` командой для обработки потока таким же образом следует использовать опцию `-z` или `--null-data`.

Хотя опция `-H` активируется по умолчанию при вводе нескольких путей к файлам, она не активируется для отдельных файлов. Это может быть важно в особых ситуациях, например, когда `grep` вызывается напрямую с помощью `find`, например:

```bash
$ find /usr/share/doc -type f -exec grep -i '3d modeling' "{}" \; | cut -c -100
artistic aspects of 3D modeling. Thus this might be the application you are
This major approach of 3D modeling has not been supported
oce is a C++ 3D modeling library. It can be used to develop CAD/CAM softwares, for instance [FreeCad
```

В этом примере `find` выводит список всех файлов в `/usr/share/doc` и передаёт каждый из них в `grep`, который, в свою очередь, выполняет поиск `3d modeling` в файле без учёта регистра. Канал `cut` используется только для того, чтобы ограничить длину вывода 100 столбцами. Однако обратите внимание, что невозможно узнать, из какого файла были взяты строки. Эта проблема решается добавлением `-H` в `grep`:

```bash
$ find /usr/share/doc -type f -exec grep -i -H '3d modeling' "{}" \; | cut -c -100
/usr/share/doc/openscad/README.md:artistic aspects of 3D modeling. Thus this might be the applicatio
/usr/share/doc/opencsg/doc/publications.html:This major approach of 3D modeling has not been support
```

Теперь можно определить файлы, в которых было найдено каждое совпадение. Чтобы сделать список ещё более информативным, к строкам с совпадениями можно добавить начальные и конечные строки:

```bash
$ find /usr/share/doc -type f -exec grep -i -H -1 '3d modeling' "{}" \; | cut -c -100
/usr/share/doc/openscad/README.md-application Blender), OpenSCAD focuses on the CAD aspects rather t
/usr/share/doc/openscad/README.md:artistic aspects of 3D modeling. Thus this might be the applicatio
/usr/share/doc/openscad/README.md-looking for when you are planning to create 3D models of machine p
/usr/share/doc/opencsg/doc/publications.html-3D graphics library for Constructive Solid Geometry (CS
/usr/share/doc/opencsg/doc/publications.html:This major approach of 3D modeling has not been support
/usr/share/doc/opencsg/doc/publications.html-by real-time computer graphics until recently.
```

Опция `-1` указывает `grep` включать одну строку до и одну строку после найденной строки с совпадением. Эти дополнительные строки называются _строками контекста_ и обозначаются в выводе знаком минус после имени файла. Тот же результат можно получить с помощью `-C 1` или `--context=1` и других значений количества строк контекста.

Существует две дополнительные программы для grep: `egrep` и `fgrep`. Программа `egrep` эквивалентна команде `grep -E`, которая включает дополнительные функции, помимо базовых регулярных выражений. Например, с помощью `egrep` можно использовать расширенные функции регулярных выражений, такие как ветвление:

```bash
$ find /usr/share/doc -type f -exec egrep -i -H -1 '3d (modeling|printing)' "{}" \; | cut -c -100
/usr/share/doc/openscad/README.md-application Blender), OpenSCAD focuses on the CAD aspects rather t
/usr/share/doc/openscad/README.md:artistic aspects of 3D modeling. Thus this might be the applicatio
/usr/share/doc/openscad/README.md-looking for when you are planning to create 3D models of machine p
/usr/share/doc/openscad/RELEASE_NOTES.md-* Support for using 3D-Mouse / Joystick / Gamepad input dev
/usr/share/doc/openscad/RELEASE_NOTES.md:* 3D Printing support: Purchase from a print service partne
/usr/share/doc/openscad/RELEASE_NOTES.md-* New export file formats: SVG, 3MF, AMF
/usr/share/doc/opencsg/doc/publications.html-3D graphics library for Constructive Solid Geometry (CS
/usr/share/doc/opencsg/doc/publications.html:This major approach of 3D modeling has not been support
/usr/share/doc/opencsg/doc/publications.html-by real-time computer graphics until recently.
```

В этом примере либо `3D modeling` либо `3D printing` будут соответствовать выражению без учёта регистра. Чтобы отобразить только те части текстового потока, которые соответствуют выражению, используемому `egrep` , используйте опцию `-o` .

Программа `fgrep` эквивалентна `grep -F`, то есть она не анализирует регулярные выражения. Она полезна при простом поиске, когда нужно найти точное соответствие выражению. Поэтому специальные символы, такие как знак доллара и точка, будут восприниматься буквально, а не по их значению в регулярном выражении.

## Редактор потоков: sed <a href="#the_stream_editor_sed" id="the_stream_editor_sed"></a>

Цель программы `sed` — изменять текстовые данные неинтерактивным способом. Это означает, что все редактирование выполняется с помощью заранее заданных инструкций, а не путём произвольного ввода текста непосредственно в текст, отображаемый на экране. В современном понимании `sed` можно рассматривать как синтаксический анализатор шаблонов: при вводе текста он размещает пользовательский контент в заранее заданных позициях или при обнаружении соответствия регулярному выражению.

Sed, как следует из названия, хорошо подходит для работы с текстом, передаваемым по конвейерам. Его базовый синтаксис — `sed -f SCRIPT` при сохранении инструкций по редактированию в файле `SCRIPT` или `sed -e COMMANDS` для выполнения `COMMANDS` непосредственно из командной строки. Если ни `-f` ни `-e` не присутствуют, `sed` использует первый параметр без опций в качестве файла сценария. Также можно использовать файл в качестве входных данных, просто указав его путь в качестве аргумента для `sed`.

`sed` инструкции состоят из одного символа, которому может предшествовать адрес или за которым может следовать один или несколько параметров, и применяются к каждой строке по очереди. Адреса могут быть представлены в виде номера строки, регулярного выражения или диапазона строк. Например, первую строку текстового потока можно удалить с помощью `1d`, где `1` указывает строку, к которой будет применена команда удаления `d`. Чтобы понять, как используется `sed`, рассмотрим вывод команды `` factor `seq 12` ``, которая возвращает простые множители для чисел от 1 до 12:

```bash
$ factor `seq 12`
1:
2: 2
3: 3
4: 2 2
5: 5
6: 2 3
7: 7
8: 2 2 2
9: 3 3
10: 2 5
11: 11
12: 2 2 3
```

Удаление первой строки с помощью `sed` выполняется с помощью `1d`:

```bash
$ factor `seq 12` | sed 1d
2: 2
3: 3
4: 2 2
5: 5
6: 2 3
7: 7
8: 2 2 2
9: 3 3
10: 2 5
11: 11
12: 2 2 3
```

Диапазон строк можно указать с помощью разделяющей запятой:

```bash
$ factor `seq 12` | sed 1,7d
8: 2 2 2
9: 3 3
10: 2 5
11: 11
12: 2 2 3
```

В одном выполнении можно использовать несколько инструкций, разделённых точкой с запятой. Однако в этом случае важно заключить их в скобки, чтобы точка с запятой не интерпретировалась оболочкой:

```bash
$ factor `seq 12` | sed "1,7d;11d"
8: 2 2 2
9: 3 3
10: 2 5
12: 2 2 3
```

В этом примере были выполнены две инструкции по удалению: сначала в строках с 1 по 7, а затем в строке 11. Адрес также может быть регулярным выражением, поэтому инструкция повлияет только на строки, соответствующие шаблону:

```bash
$ factor `seq 12` | sed "1d;/:.*2.*/d"
3: 3
5: 5
7: 7
9: 3 3
11: 11
```

Регулярное выражение `:.*2.*` соответствует любому вхождению числа 2 после двоеточия, что приводит к удалению строк, соответствующих числам с 2 в качестве делителя. При использовании `sed` всё, что находится между косыми чертами (`/`), считается регулярным выражением, и по умолчанию поддерживаются все базовые регулярные выражения. Например, `sed -e "/^#/d" /etc/services` показывает содержимое файла `/etc/services` без строк, начинающихся с `#` (строк с комментариями).

Инструкция по удалению `d` — это лишь одна из множества инструкций по редактированию, предоставляемых `sed`. Вместо удаления строки `sed` может заменить её заданным текстом:

```bash
$ factor `seq 12` | sed "1d;/:.*2.*/c REMOVED"
REMOVED
3: 3
REMOVED
5: 5
REMOVED
7: 7
REMOVED
9: 3 3
REMOVED
11: 11
REMOVED
```

Инструкция `c REMOVED` просто заменяет строку текстом `REMOVED`. В данном примере инструкция `:.*2.*` влияет на каждую строку с подстрокой, соответствующей регулярному выражению `c REMOVED`. Инструкция `a TEXT` копирует текст, указанный `TEXT` в новую строку после строки с совпадением. Инструкция `r FILE` делает то же самое, но копирует содержимое файла, указанного `FILE`. Инструкция `w` делает противоположное `r` действие, то есть строка будет добавлена в указанный файл.

Безусловно, наиболее используемой `sed` инструкцией является `s/FIND/REPLACE/`, которая используется для замены соответствия регулярному выражению `FIND` текстом, обозначенным `REPLACE`. Например, инструкция `s/hda/sda/` заменяет подстроку, соответствующую литералу RE, `hda` на `sda`. Замене будет подвергнуто только первое совпадение, найденное в строке, если только флажок `g` не будет установлен после инструкции, как в `s/hda/sda/g`.

Более реалистичный пример поможет проиллюстрировать возможности `sed`'s. Предположим, что медицинская клиника хочет отправлять своим клиентам текстовые сообщения, напоминающие им о запланированных на следующий день встречах. Типичный сценарий реализации предполагает использование профессиональной службы обмена мгновенными сообщениями, которая предоставляет API для доступа к системе, отвечающей за доставку сообщений. Эти сообщения обычно отправляются из той же системы, которая управляет приложением, контролирующим встречи клиентов, и запускаются в определённое время суток или при наступлении какого-либо другого события. В этой гипотетической ситуации приложение могло бы сгенерировать файл под названием `appointments.csv` с табличными данными обо всех встречах на следующий день, а затем использовать `sed` для отображения текстовых сообщений из файла шаблона под названием `template.txt`. Файлы CSV — это стандартный способ экспорта данных из запросов к базе данных, поэтому примеры  могут выглядеть следующим образом:

```bash
$ cat appointments.csv
"NAME","TIME","PHONE"
"Carol","11am","55557777"
"Dave","2pm","33334444"
```

В первой строке указаны названия для каждого столбца, которые будут использоваться для сопоставления тегов в файле шаблона:

```bash
$ cat template.txt
Hey <NAME>, don't forget your appointment tomorrow at <TIME>.
```

Знаки «меньше `<`» и «больше `>`» были добавлены к меткам, чтобы их можно было идентифицировать как теги. Следующий скрипт Bash анализирует все записи в очереди, используя `template.txt` в качестве шаблона сообщения:

```bash
#! /bin/bash

TEMPLATE=`cat template.txt`
TAGS=(`sed -ne '1s/^"//;1s/","/\n/g;1s/"$//p' appointments.csv`)
mapfile -t -s 1 ROWS < appointments.csv
for (( r = 0; r < ${#ROWS[*]}; r++ ))
do
  MSG=$TEMPLATE
  VALS=(`sed -e 's/^"//;s/","/\n/g;s/"$//' <<<${ROWS[$r]}`)
  for (( c = 0; c < ${#TAGS[*]}; c++ ))
  do
    MSG=`sed -e "s/<${TAGS[$c]}>/${VALS[$c]}/g" <<<"$MSG"`
  done
  echo curl --data message=\"$MSG\" --data phone=\"${VALS[2]}\" https://mysmsprovider/api
done
```

В реальном производственном сценарии также выполнялась бы аутентификация, проверка ошибок и ведение журнала, но в этом примере есть базовая функциональность для начала работы. Первые инструкции, выполняемые `sed`-командой, применяются только к первой строке — адресу `1` в `1s/^"//;1s/","/\n/g;1s/"$//p` — для удаления начальных и конечных кавычек — `1s/^"//` и `1s/"$//` — и замены разделителей полей символом новой строки: `1s/","/\n/g`. Для загрузки названий столбцов нужна только первая строка, поэтому несовпадающие строки будут игнорироваться с помощью опции `-n`, которая требует, чтобы флаг `p` был указан после последней `sed`-команды для вывода совпадающей строки. Затем теги сохраняются в переменной `TAGS` в виде массива Bash. С помощью команды `mapfile` создаётся ещё одна переменная массива Bash для хранения строк, содержащих назначения, в переменной массива `ROWS`.

Цикл `for` используется для обработки каждой строки с назначением, найденной в `ROWS`. Затем кавычки и разделители в назначении — назначение находится в переменной `${ROWS[$r]}`, используемой в качестве _строки здесь_ — заменяются на `sed`, аналогично командам, используемым для загрузки тегов. Затем разделённые значения назначения сохраняются в переменной массива `VALS`, где индексы массива 0, 1 и 2 соответствуют значениям `NAME`, `TIME` и `PHONE`.

Наконец, вложенный цикл `for` проходит по массиву `TAGS` и заменяет каждый тег, найденный в шаблоне, соответствующим значением в `VALS`. Переменная `MSG` содержит копию отображаемого шаблона, обновляемую командой подстановки `s/<${TAGS[$c]}>/${VALS[$c]}/g` при каждом проходе цикла через `TAGS`.

В результате получается отображаемое сообщение, например: `"Hey Carol, don’t forget your appointment tomorrow at 11am."` Отображаемое сообщение можно отправить в качестве параметра через HTTP-запрос с помощью `curl`, в виде почтового сообщения или любым другим подобным способом.

## Объединение grep и sed <a href="#combining_grep_and_sed" id="combining_grep_and_sed"></a>

Команды `grep` и `sed` можно использовать вместе, когда требуются более сложные процедуры обработки текста. Например, системный администратор может захотеть просмотреть все попытки входа на сервер. Файл `/var/log/wtmp` записывает все входы и выходы, а файл `/var/log/btmp` записывает неудачные попытки входа. Они записываются в двоичном формате, который можно прочитать с помощью команд `last` и `lastb` соответственно.

Вывод `lastb` показывает не только имя пользователя, использованное при неудачной попытке входа, но и его IP-адрес:

```bash
# lastb -d -a -n 10 --time-format notime
user     ssh:notty       (00:00)     81.161.63.251
nrostagn ssh:notty       (00:00)     vmd60532.contaboserver.net
pi       ssh:notty       (00:00)     132.red-88-20-39.staticip.rima-tde.net
pi       ssh:notty       (00:00)     132.red-88-20-39.staticip.rima-tde.net
pi       ssh:notty       (00:00)     46.6.11.56
pi       ssh:notty       (00:00)     46.6.11.56
nps      ssh:notty       (00:00)     vmd60532.contaboserver.net
narmadan ssh:notty       (00:00)     vmd60532.contaboserver.net
nominati ssh:notty       (00:00)     vmd60532.contaboserver.net
nominati ssh:notty       (00:00)     vmd60532.contaboserver.net
```

Опция `-d` преобразует IP-адрес в соответствующее имя хоста. Имя хоста может дать представление об интернет-провайдере или хостинге, которые использовались для выполнения этих неудачных попыток входа в систему. Опция `-a` помещает имя хоста в последний столбец, что упрощает фильтрацию, которая еще не применена. Опция `--time-format notime` скрывает время, когда была предпринята попытка входа в систему. Выполнение команды `lastb` может занять некоторое время, если было слишком много неудачных попыток входа в систему, поэтому вывод был ограничен десятью записями с опцией `-n 10`.

Не все удалённые IP-адреса имеют связанное с ними имя хоста, поэтому обратный DNS к ним не применяется, и их можно игнорировать. Хотя вы можете написать регулярное выражение, соответствующее ожидаемому формату имени хоста в конце строки, вероятно, проще написать регулярное выражение, соответствующее букве алфавита или цифре в конце строки. В следующем примере показано, как команда `grep` принимает список на стандартный ввод и удаляет строки без имён хостов:

```bash
# lastb -d -a --time-format notime | grep -v '[0-9]$' | head -n 10
nvidia   ssh:notty       (00:00)     vmd60532.contaboserver.net
n_tonson ssh:notty       (00:00)     vmd60532.contaboserver.net
nrostagn ssh:notty       (00:00)     vmd60532.contaboserver.net
pi       ssh:notty       (00:00)     132.red-88-20-39.staticip.rima-tde.net
pi       ssh:notty       (00:00)     132.red-88-20-39.staticip.rima-tde.net
nps      ssh:notty       (00:00)     vmd60532.contaboserver.net
narmadan ssh:notty       (00:00)     vmd60532.contaboserver.net
nominati ssh:notty       (00:00)     vmd60532.contaboserver.net
nominati ssh:notty       (00:00)     vmd60532.contaboserver.net
nominati ssh:notty       (00:00)     vmd60532.contaboserver.net
```

Опция `grep` команды `-v` показывает только строки, которые не соответствуют заданному регулярному выражению. Регулярное выражение, соответствующее любой строке, заканчивающейся цифрой (т. е. `[0-9]$`), будет захватывать только записи без имени хоста. Таким образом, `grep -v '[0-9]$'` будет показывать только строки, заканчивающиеся именем хоста.

Вывод можно отфильтровать ещё сильнее, оставив только доменное имя и удалив остальные части из каждой строки. Команда `sed` может сделать это с помощью команды замены, чтобы заменить всю строку обратной ссылкой на доменное имя в ней:

```bash
# lastb -d -a --time-format notime | grep -v '[0-9]$' | sed -e 's/.* \(.*\)$/\1/' | head -n 10
vmd60532.contaboserver.net
vmd60532.contaboserver.net
vmd60532.contaboserver.net
132.red-88-20-39.staticip.rima-tde.net
132.red-88-20-39.staticip.rima-tde.net
vmd60532.contaboserver.net
vmd60532.contaboserver.net
vmd60532.contaboserver.net
vmd60532.contaboserver.net
vmd60532.contaboserver.net
```

Скобки в `.* \(.*\)$` указывают `sed` на то, что нужно запомнить эту часть строки, то есть часть между последним пробелом и концом строки. В этом примере на эту часть ссылаются с помощью `\1` и используют для замены всей строки.

Очевидно, что большинство удалённых хостов пытаются выполнить вход более одного раза, поэтому одно и то же доменное имя повторяется. Чтобы удалить повторяющиеся записи, сначала их нужно отсортировать (с помощью команды `sort`), а затем передать в команду `uniq`:

```bash
# lastb -d -a --time-format notime | grep -v '[0-9]$' | sed -e 's/.* \(.*\)$/\1/' | sort | uniq | head -n 10
116-25-254-113-on-nets.com
132.red-88-20-39.staticip.rima-tde.net
145-40-33-205.power-speed.at
tor.laquadrature.net
tor.momx.site
ua-83-226-233-154.bbcust.telenor.se
vmd38161.contaboserver.net
vmd60532.contaboserver.net
vmi488063.contaboserver.net
vmi515749.contaboserver.net
```

Это показывает, как можно комбинировать различные команды для получения желаемого результата. Затем список имён хостов можно использовать для написания правил брандмауэра, блокирующих доступ, или для принятия других мер по обеспечению безопасности сервера.

Ответы на исследовательские упражнения

1.  Базовая структура HTML-файла начинается с элементов `html`, `head` и `body`, например:

    ```html
    <html>
    <head>
      <title>News Site</title>
    </head>
    <body>
      <h1>Headline</h1>
      <p>Information of interest.</p>
    </body>
    </html>
    ```

    Опишите, как можно использовать адреса в `sed` для отображения только элемента `body` и его содержимого.

    Чтобы отображались только `body`, адреса должны быть `/<body>/,/<\/body>/`, как в `sed -n -e '/<body>/,/<\/body>/p'`. Опция `-n` задаётся для `sed` таким образом, чтобы по умолчанию не отображались строки, поэтому команда `p` в конце выражения `sed` выводит соответствующие строки.
2.  Какое выражение `sed` удалит все теги из HTML-документа, оставив только отображаемый текст?

    Выражение `seds/<[^>]*>//g` заменит любое содержимое, заключённое в `<>`, на пустую строку.
3.  Файлы с расширением `.ovpn` очень популярны для настройки VPN-клиентов, поскольку они содержат не только настройки, но и содержимое ключей и сертификатов для клиента. Изначально эти ключи и сертификаты находятся в отдельных файлах, поэтому их нужно скопировать в файл `.ovpn`. Ниже приведён фрагмент шаблона `.ovpn`.

    ```csv
    client
    dev tun
    remote 192.168.1.155 1194
    <ca>
    ca.crt
    </ca>
    <cert>
    client.crt
    </cert>
    <key>
    client.key
    </key>
    <tls-auth>
    ta.key
    </tls-auth>
    ```

    Предположим, что файлы `ca.crt`, `client.crt`, `client.key` и `ta.key` находятся в текущем каталоге. Как изменить конфигурацию шаблона с помощью `sed` так, чтобы каждое имя файла заменялось его содержимым?

    Команда

    ```
    sed -r -e 's/(^[^.]*)\.(crt|key)$/cat \1.\2/e' < client.template > client.ovpn
    ```

    заменяет любую строку, заканчивающуюся на `.crt` или `.key`, содержимым файла, имя которого совпадает с именем строки. Опция `-r` указывает `sed` на использование расширенных регулярных выражений, а `e` в конце выражения указывает `sed` на замену совпадений выводом команды `cat \1.\2`. Обратные ссылки `\1` и `\2` соответствуют имени файла и расширению, найденным в совпадении.
