# Урок 3.7.1.

## Введение <a href="#sec.103.7_01-in" id="sec.103.7_01-in"></a>

Алгоритмы поиска строк широко используются в нескольких задачах обработки данных, настолько широко, что в Unix-подобных операционных системах есть собственная повсеместная реализация: _регулярные выражения_, часто сокращаемые до _RE_. Регулярные выражения состоят из последовательностей символов, которые образуют общий шаблон, используемый для поиска и иногда изменения соответствующей последовательности в более длинной строке символов. Регулярные выражения значительно расширяют возможности:

* Написание правил синтаксического анализа запросов на HTTP-серверах, _nginx_ в частности.
* Написнаие скриптов, которые преобразуют текстовые наборы данных в другой формат.
* Поиск интересующих вас событий в записях журнала или документах.
* Фильтровние документов разметки, с сохранением семантического содержания.

Самое простое регулярное выражение содержит как минимум один _атом_. Атом, названный так потому, что он является базовым элементом регулярного выражения, — это просто символ, который может иметь или не иметь особое значение. Большинство обычных символов однозначны, они сохраняют своё буквальное значение, в то время как другие имеют особое значение:

`.` (точка)

Атом совпадает с любым символом.

`^` (каретка)

Атом совпадает с началом строки.

`$` (знак доллара)

Атом совпадает с концом строки.

Например, регулярное выражение `bc`, состоящее из буквенных символов `b` и `c`, можно найти в строке `abcd`, но нельзя найти в строке `a1cd`. С другой стороны, регулярное выражение `.c` можно найти в строках `abcd` и `a1cd`, так как точка `.` соответствует любому символу.

Атомы «каретка» и «доллар» используются, когда интересны только совпадения в начале или в конце строки. По этой причине их также называют _якорями_. Например, `cd` можно найти в `abcd`, но `^cd` нельзя. Аналогично, `ab` можно найти в `abcd`, но `ab$` нельзя. Атомы «каретка» `^` и «доллар» `$` являются буквенными символами, за исключением случаев, когда они находятся в начале или в конце регулярного выражения.

## Выражение в скобках <a href="#bracket_expression" id="bracket_expression"></a>

Существует ещё один тип атомов, называемый _выражениями в скобках_. Хотя это и не один символ, скобки `[]` (включая их содержимое) считаются одним атомом. Выражение в скобках обычно представляет собой просто список буквенных символов, заключённых в `[]`, что позволяет атому соответствовать любому отдельному символу из списка. Например, выражение `[1b]` можно найти в строках `abcd` и `a1cd`. Чтобы указать символы, которым атом не должен соответствовать, список должен начинаться с `^`, как в `[^1b]`. В выражениях в скобках также можно указывать диапазоны символов. Например, `[0−9]` соответствует цифрам от 0 до 9, а `[a−z]` соответствует любой строчной букве. Диапазоны следует использовать с осторожностью, так как они могут различаться в разных регионах.

Списки выражений в квадратных скобках также принимают классы вместо отдельных символов и диапазонов. Традиционные классы символов:

`[:alnum:]`

Представляет собой буквенно-цифровой символ.

`[:alpha:]`

Представляет собой буквенный символ.

`[:ascii:]`

Представляет символ, который вписывается в набор символов ASCII.

`[:blank:]`

Представляет собой пустой символ, то есть пробел или табуляцию.

`[:cntrl:]`

Представляет собой управляющий символ.

`[:digit:]`

Представляет собой цифру (от 0 до 9).

`[:graph:]`

Представляет любой печатаемый символ, кроме пробела.

`[:lower:]`

Представляет собой символ в нижнем регистре.

`[:print:]`

Представляет любой печатный символ, включая пробел.

`[:punct:]`

Представляет собой любой печатный символ, который не является пробелом или буквенно-цифровым символом.

`[:space:]`

Представляет собой символы пробела: пробел, перевод строки (`\f`), символ новой строки (`\n`), возврат каретки (`\r`), горизонтальный табулятор (`\t`), вертикальный табулятор (`\v`).

`[:upper:]`

Представляет собой заглавную букву.

`[:xdigit:]`

Представляет собой шестнадцатеричные цифры (от 0 до F).

Классы символов можно комбинировать с одиночными символами и диапазонами, но нельзя использовать в качестве конечной точки диапазона. Кроме того, классы символов можно использовать только в выражениях в квадратных скобках, а не как отдельный элемент вне скобок.

## Кванторы <a href="#quantifiers" id="quantifiers"></a>

Область действия атома, состоящего из одного символа или из скобок, можно изменить с помощью _квантификатора атомов_. Квантификаторы атомов определяют _последовательности_ атомов, то есть совпадения происходят, когда в строке обнаруживается последовательное повторение атома. Подстрока, соответствующая совпадению, называется _фрагментом_. Несмотря на это, квантификаторы и другие элементы регулярных выражений обрабатываются по-разному в зависимости от используемого стандарта.

Согласно стандарту POSIX, существует две формы регулярных выражений: «базовые» регулярные выражения и «расширенные» регулярные выражения. Большинство текстовых программ в любом обычном дистрибутиве Linux поддерживают обе формы, поэтому важно знать их различия, чтобы избежать проблем с совместимостью и выбрать наиболее подходящую реализацию для поставленной задачи.

Квантификатор `*` выполняет одну и ту же функцию как в базовых, так и в расширенных регулярных выражениях (атом встречается ноль или более раз) и является буквенным символом, если он стоит в начале регулярного выражения или если перед ним стоит обратная косая черта `\`. Квантификаторы `` ` will select pieces containing one or more atom matches in sequence. With the question mark quantifier `?`, a match will occur if the corresponding atom appears once or if it doesn't appear at all. If preceded by a backslash `\`, their special meaning is not considered. Basic regular expressions also support ` `` и `?` со знаком плюс, но перед ними должна стоять обратная косая черта. В отличие от расширенных регулярных выражений, `+` и `?` сами по себе являются буквенными символами в базовых регулярных выражениях.

## Границы <a href="#bounds" id="bounds"></a>

_Ограничение_ — это квантификатор атома, который, как следует из названия, позволяет пользователю задавать точные границы количества атомов. В расширенных регулярных выражениях ограничение может быть представлено в трёх формах:

`{i}`

Атом должен встречаться ровно `i` раз (`i` — целое число). Например, `[[:blank:]]{2}` соответствует ровно двум пробелам.

`{i,}`

Атом должен встречаться не менее `i` раз (`i` — целое число). Например, `[[:blank:]]{2,}` соответствует любой последовательности из двух или более пробелов.

`{i,j}`

Атом должен встречаться не менее `i` раз и не более `j` раз (`i` и `j` целые числа, `j` больше `i`). Например, `xyz{2,4}` соответствует строке `xy` с двумя-четырьмя символами `z` подряд.

В любом случае, если подстрока соответствует регулярному выражению, а более длинная подстрока, начинающаяся с той же точки, тоже соответствует, то будет учитываться более длинная подстрока.

Базовые регулярные выражения также поддерживают границы, но перед разделителями должны стоять `\`: `\{` и `\}`. Сами по себе `{` и `}` интерпретируются как буквенные символы.`\{` за которым следует символ, отличный от цифры, является буквенным символом, а не началом границы.

## Ответвления и обратные ссылки <a href="#branches_and_back_references" id="branches_and_back_references"></a>

Базовые регулярные выражения также отличаются от расширенных регулярных выражений другим важным аспектом: расширенное регулярное выражение может быть разделено на _ветви_, каждая из которых является независимым регулярным выражением. Ветви разделяются символом `|`, и объединенное регулярное выражение будет соответствовать всему, что соответствует любой из ветвей. Например, `he|him` будет соответствовать, если в исследуемой строке найдена подстрока `he` или `him`. Базовые регулярные выражения интерпретируют `|` как буквенный символ. Однако большинство программ, поддерживающих базовые регулярные выражения, допускают ответвления с `\|`.

Расширенное регулярное выражение, заключённое в `()`, может использоваться в _обратной ссылке_. Например, `([[:digit:]])\1` будет соответствовать любому регулярному выражению, которое повторяется хотя бы один раз, потому что `\1` в выражении является обратной ссылкой на фрагмент, соответствующий первому подвыражению в скобках. Если в регулярном выражении есть несколько подвыражений в скобках, на них можно ссылаться с помощью `\2`, `\3` и так далее.

В базовых регулярных выражениях подвыражения должны быть заключены в `\(` и `\)`, где `(` и `)` сами по себе являются обычными символами. Индикатор обратной ссылки используется так же, как и в расширенных регулярных выражениях.

#### Поиск с помощью регулярных выражений <a href="#searching_with_regular_expressions" id="searching_with_regular_expressions"></a>

Непосредственная польза регулярных выражений заключается в улучшении поиска в файловых системах и текстовых документах. Опция `-regex` команды `find` позволяет проверять каждый путь в иерархии каталогов на соответствие регулярному выражению. Например,

```bash
$ find $HOME -regex '.*/\..*' -size +100M
```

поиск файлов размером более 100 мегабайт, но только в путях внутри домашнего каталога пользователя, которые содержат совпадение с `.*/\..*`, то есть `/.` в окружении любого другого количества символов. Другими словами, будут перечислены только скрытые файлы или файлы внутри скрытых каталогов, независимо от положения `/.` в соответствующем пути. Для регулярных выражений без учёта регистра следует использовать опцию `-iregex`:

```bash
$ find /usr/share/fonts -regextype posix-extended -iregex '.*(dejavu|liberation).*sans.*(italic|oblique).*'
/usr/share/fonts/dejavu/DejaVuSansCondensed-BoldOblique.ttf
/usr/share/fonts/dejavu/DejaVuSansCondensed-Oblique.ttf
/usr/share/fonts/dejavu/DejaVuSans-BoldOblique.ttf
/usr/share/fonts/dejavu/DejaVuSans-Oblique.ttf
/usr/share/fonts/dejavu/DejaVuSansMono-BoldOblique.ttf
/usr/share/fonts/dejavu/DejaVuSansMono-Oblique.ttf
/usr/share/fonts/liberation/LiberationSans-BoldItalic.ttf
/usr/share/fonts/liberation/LiberationSans-Italic.ttf
```

В этом примере регулярное выражение содержит ветви (написанные в _расширенном_ стиле) для перечисления только определенных файлов шрифтов в `/usr/share/fonts` иерархии каталогов. Расширенные регулярные выражения по умолчанию не поддерживаются, но `find` позволяет включить их с помощью `-regextype posix-extended` или `-regextype egrep`. Стандартом RE по умолчанию для `find` является _findutils-default_, который фактически является клоном базовых регулярных выражений.

Часто возникает необходимость передать вывод программы в команду `less` в том случае, если он не помещается на экране. Команда `less` разбивает ввод на страницы, по одному экрану за раз, что позволяет пользователю легко перемещаться по тексту вверх и вниз. Кроме того, `less` позволяет пользователю выполнять поиск по регулярным выражениям. Эта функция особенно важна, поскольку `less` является пагинатором по умолчанию, используемым для многих повседневных задач, таких как просмотр записей в журнале или обращение к страницам руководства. Например, при чтении страницы руководства нажатие клавиши / откроет окно поиска. Это типичный сценарий, в котором полезны регулярные выражения, поскольку параметры команд перечислены сразу после поля страницы в общем макете страницы руководства. Однако один и тот же параметр может встречаться в тексте несколько раз, что делает поиск по буквам невозможным. Несмотря на это, если вы введёте `^[[:blank:]]*-o` — или, проще говоря, `^ *-o` — в поле поиска, то после нажатия клавиши Enter вы сразу перейдёте к разделу `-o` (если он существует), что позволит вам быстрее ознакомиться с описанием параметра.

## Краткие сведения <a href="#sec.103.7_01-su" id="sec.103.7_01-su"></a>

В этом уроке рассматривается общая поддержка регулярных выражений в Linux — широко используемого стандарта, возможности сопоставления шаблонов которого поддерживаются большинством программ, связанных с текстом. Урок состоит из следующих этапов:

* Что такое регулярное выражение.
* Основные компоненты регулярного выражения.
* Различия между обычными и расширенными регулярными выражениями.
* Как выполнять простой поиск по тексту и файлам с помощью регулярных выражений.

## Ответы на упражнения с руководством <a href="#sec.103.7_01-age" id="sec.103.7_01-age"></a>

1.  Какое расширенное регулярное выражение будет соответствовать любому адресу электронной почты, например `info@example.org`?

    ```bash
    egrep «\S+@\S+\.\S+»
    ```
2.  Какое расширенное регулярное выражение будет соответствовать только любому IPv4-адресу в стандартном формате с точками и четырьмя цифрами, например `192.168.15.1`?

    ```bash
    egrep «[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}»
    ```
3.  Как можно использовать команду `grep` для вывода содержимого файла `/etc/services` без учёта всех комментариев (строк, начинающихся с `#`)?

    ```bash
    grep -v ^# /etc/services
    ```
4.  Файл `domains.txt` содержит список доменных имён, по одному в строке. Как использовать команду `egrep` для вывода только `.org` или `.com` доменов?

    ```bash
    egrep ".org$|.com$" domains.txt
    ```

## Ответы на исследовательские упражнения <a href="#sec.103.7_01-aee" id="sec.103.7_01-aee"></a>
