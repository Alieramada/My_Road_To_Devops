# Урок 3.4.2.

## Введение <a href="#sec.103.4_02-in" id="sec.103.4_02-in"></a>

Один из аспектов философии Unix гласит, что каждая программа должна иметь определённое назначение и не должна пытаться включать в себя функции, выходящие за рамки её возможностей. Но простота не означает менее продуманные результаты, потому что разные программы можно объединять в цепочки для получения комбинированного результата. Символ вертикальной черты `|`, также известный как символ _канала_, можно использовать для создания конвейера, соединяющего вывод одной программы напрямую с вводом другой программы, а _подстановка команд_ позволяет сохранять вывод программы в переменной или использовать его напрямую в качестве аргумента другой команды.

## Каналы <a href="#sec.103.4_02-pi" id="sec.103.4_02-pi"></a>

В отличие от перенаправления, при использовании каналов данные передаются слева направо в командной строке, и целью является другой процесс, а не путь к файловой системе, дескриптор файла или документ Here. Символ канала `|` указывает командной оболочке запускать все отдельные команды одновременно и подключать вывод предыдущей команды к вводу следующей команды слева направо. Например, вместо использования перенаправлений содержимое файла, `/proc/cpuinfo` отправляемого в стандартный вывод с помощью `cat`, может быть передано в stdin из `wc` с помощью следующей команды:

```bash
$ cat /proc/cpuinfo | wc
 208 1184 6096
```

При отсутствии пути к файлу `wc` подсчитывает количество строк, слов и символов, которые он получает на стандартный ввод, как в этом примере. В составной команде может быть несколько каналов. В следующем примере используются два канала:

```bash
$ cat /proc/cpuinfo | grep 'model name' | uniq
model name      : Intel(R) Xeon(R) CPU           X5355  @ 2.66GHz
```

Содержимое файла `/proc/cpuinfo`, созданного с помощью `cat /proc/cpuinfo`, было передано в команду `grep 'model name'`, которая затем выбирает только строки, содержащие термин `model name`. На компьютере, на котором запущен пример, много процессоров, поэтому строки с `model name` повторяются. Последняя команда передаёт `grep 'model name'` в `uniq`, которая отвечает за пропуск любой строки, равной предыдущей.

Каналы можно комбинировать с перенаправлениями в одной командной строке. Предыдущий пример можно переписать в более простой форме:

```bash
$ grep 'model name' </proc/cpuinfo | uniq
model name      : Intel(R) Xeon(R) CPU           X5355  @ 2.66GHz
```

Переадресация ввода для `grep` не является строго обязательной, поскольку `grep` принимает в качестве аргумента путь к файлу, но этот пример показывает, как создавать такие комбинированные команды.

Трубы и перенаправления являются эксклюзивными, то есть один источник может быть сопоставлен только с одним получателем. Тем не менее, можно перенаправить вывод в файл и при этом видеть его на экране с помощью программы `tee`. Для этого первая программа отправляет свой вывод на стандартный ввод `tee` и предоставляет последней имя файла для сохранения данных:

```bash
$ grep 'model name' </proc/cpuinfo | uniq | tee cpu_model.txt
model name      : Intel(R) Xeon(R) CPU           X5355  @ 2.66GHz
$ cat cpu_model.txt
model name      : Intel(R) Xeon(R) CPU           X5355  @ 2.66GHz
```

Вывод последней программы в цепочке, сгенерированный `uniq`, отображается и сохраняется в файле `cpu_model.txt`. Чтобы не перезаписывать содержимое указанного файла, а добавлять в него данные, необходимо указать опцию `-a` для `tee`.

Только стандартный вывод процесса записывается в канал. Допустим, вам нужно выполнить длительную компиляцию на экране и в то же время сохранить стандартный вывод и стандартную ошибку в файл для последующего просмотра. Если в вашем текущем каталоге нет _Makefile_, следующая команда выдаст ошибку:

```bash
$ make | tee log.txt
make: *** No targets specified and no makefile found.  Stop.
```

Несмотря на то, что сообщение об ошибке, сгенерированное `make` и отображаемое на экране, не было перехвачено `tee`, файл _log.txt_ был создан пустым. Прежде чем канал сможет перехватить stderr, необходимо выполнить перенаправление:

```bash
$ make 2>&1 | tee log.txt
make: *** No targets specified and no makefile found.  Stop.
$ cat log.txt
make: *** No targets specified and no makefile found.  Stop.
```

В этом примере стандартный поток ошибок `make` был перенаправлен в стандартный поток вывода, поэтому `tee` смог перехватить его с помощью канала, отобразить на экране и сохранить в файле `log.txt`. В подобных случаях может быть полезно сохранять сообщения об ошибках для последующего анализа.\


## Подстановка команд

Другой способ получить вывод команды — _подстановка команды_. Если поместить команду в обратные кавычки, Bash заменит её стандартным выводом. В следующем примере показано, как использовать стандартный вывод программы в качестве аргумента для другой программы:

```
$ mkdir `date +%Y-%m-%d`
$ ls
2019-09-05
```

Вывод программы `date`, текущая дата в формате _год-месяц-день_, был использован в качестве аргумента для создания каталога с `mkdir`. Аналогичный результат можно получить, используя `$()` вместо обратных кавычек:

```bash
$ rmdir 2019-09-05
$ mkdir $(date +%Y-%m-%d)
$ ls
2019-09-05
```

Этот же метод можно использовать для сохранения вывода команды в переменной:

```bash
$ OS=`uname -o`
$ echo $OS
GNU/Linux
```

Команда `uname -o` выводит общее название текущей операционной системы, которое было сохранено в переменной сеанса `OS`. Присвоение результата выполнения команды переменной очень полезно в скриптах, так как позволяет хранить и обрабатывать данные разными способами.

В зависимости от вывода, сгенерированного заменяемой командой, встроенная команда подстановки может не подойти. Более сложный метод использования вывода программы в качестве аргумента другой программы использует промежуточное звено под названием `xargs`. Программа `xargs` использует содержимое, полученное через стандартный ввод, для запуска заданной команды с этим содержимым в качестве аргумента. В следующем примере показано, как c`xargs` запустить программу `identify` с аргументами, предоставленными программой `find`:

```bash
$ find /usr/share/icons -name 'debian*' | xargs identify -format "%f: %wx%h\n"
debian-swirl.svg: 48x48
debian-swirl.png: 22x22
debian-swirl.png: 32x32
debian-swirl.png: 256x256
debian-swirl.png: 48x48
debian-swirl.png: 16x16
debian-swirl.png: 24x24
debian-swirl.svg: 48x48
```

Программа `identify` является частью _ImageMagick_, набора инструментов командной строки для просмотра, преобразования и редактирования большинства типов файлов изображений. В этом примере `xargs` взял все пути, перечисленные `find` и передал их в качестве аргументов `identify` , которая затем показывает информацию о каждом файле в формате, требуемом опцией `-format`. Файлы, найденные `find` в этом примере, представляют собой изображения с логотипом дистрибутива в файловой системе Debian. `-format` является параметром `identify`, а не `xargs`.

Опция `-n 1` требует, чтобы `xargs` выполняла заданную команду только с одним аргументом за раз. В этом примере вместо передачи всех путей, найденных `find` в качестве списка аргументов для `identify`, с помощью `xargs -n 1` команда `identify` будет выполняться для каждого пути по отдельности. С помощью `-n 2` команда `identify` будет выполняться с двумя путями в качестве аргументов, `-n 3` — с тремя путями в качестве аргументов и так далее. Аналогично, когда `xargs` обрабатывает многострочный контент — как в случае с вводом, предоставляемым `find` — с помощью опции `-L` можно ограничить количество строк, используемых в качестве аргументов при выполнении команды.

{% hint style="info" %}
Использование `xargs` с опцией `-n 1` или `-L 1` для обработки вывода, сгенерированного `find` может быть необязательным. Команда `find` имеет опцию `-exec` для запуска заданной команды для каждого элемента результатов поиска.
{% endhint %}

Если в путях есть пробелы, важно запустить `find` с опцией `-print0`. Эта опция указывает `find` использовать нулевой символ между каждой записью, чтобы `xargs` мог правильно проанализировать список (вывод был подавлен):

```bash
$ find . -name '*avi' -print0 -o -name '*mp4' -print0 -o -name '*mkv' -print0 | xargs -0 du | sort -n
```

Опция `-0` указывает`xargs`, что нулевой символ следует использовать в качестве разделителя. Таким образом, пути к файлам, указанные в `find`, будут правильно проанализированы, даже если в них есть пробелы или другие специальные символы. В предыдущем примере показано, как использовать команду `du` для определения использования диска каждым найденным файлом, а затем отсортировать результаты по размеру. Выходные данные были отключены для краткости. Обратите внимание, что для каждого критерия поиска необходимо разместить `-print0` опцию для `find`.

По умолчанию `xargs` помещает аргументы выполняемой команды в конец. Чтобы изменить это поведение, следует использовать опцию `-I`:

```
$ find . -mindepth 2 -name '*avi' -print0 -o -name '*mp4' -print0 -o -name '*mkv' -print0 | xargs -0 -I PATH mv PATH ./
```

В последнем примере каждый файл, найденный с помощью `find`, перемещается в текущий каталог. Поскольку исходный путь (пути) должен быть указан в `mv` перед целевым путём, для опции `-I` `xargs` задаётся термин-заместитель, который затем соответствующим образом размещается рядом с `mv`. При использовании нулевого символа в качестве разделителя нет необходимости заключать термин-заместитель в кавычки.

## Исследовательские упражнения <a href="#sec.103.4_02-ee" id="sec.103.4_02-ee"></a>

1. Простая программа резервного копирования периодически создает образ раздела `/dev/sda1` с `dd < /dev/sda1 > sda1.img`. Для выполнения будущих проверок целостности данных программа также генерирует хэш SHA1 файла с `sha1sum < sda1.img > sda1.sha1`. Если добавить каналы и команду `tee`, как эти две команды будут объединены в одну?
2. Команда `tar` используется для архивирования множества файлов в один файл с сохранением структуры каталогов. Опция `-T` позволяет указать файл, содержащий пути к архивируемым файлам. Например, `find /etc -type f | tar -cJ -f /srv/backup/etc.tar.xz -T -` создаёт сжатый файл tar `etc.tar.xz` из списка, предоставленного командой `find` (опция `-T -` указывает на стандартный ввод в качестве списка путей). Чтобы избежать возможных ошибок синтаксического анализа из-за путей, содержащих пробелы, какие параметры команды должны присутствовать для `find` и `tar`?
3. Вместо того чтобы открывать новый сеанс удалённой оболочки, команда `ssh` может просто выполнить команду, указанную в качестве аргумента: `ssh user@storage "remote command"`. Учитывая, что `ssh` также позволяет перенаправлять стандартный вывод локальной программы на стандартный ввод удалённой программы, как команда `cat` может передать локальный файл с именем `etc.tar.gz` в `/srv/backup/etc.tar.gz` в `user@storage` через `ssh`?

## Краткие сведения <a href="#sec.103.4_02-su" id="sec.103.4_02-su"></a>

В этом уроке рассматриваются традиционные методы межпроцессного взаимодействия, используемые в Linux. _Последовательное выполнение команд_ создаёт канал односторонней связи между двумя процессами, а _подстановка команд_ позволяет сохранять выходные данные процесса в переменной оболочки. Урок состоит из следующих этапов:

* Как можно использовать потоки для передачи выходных данных процесса на вход другого процесса.
* Назначение команд `tee` и `xargs`.
* Как получить вывод процесса с помощью _подстановки команд_, сохранив его в переменной или используя напрямую в качестве параметра для другой команды.

Были рассмотрены следующие команды и процедуры:

* Конвейерная обработка команд с помощью `|`.
* Замена команд обратными метками и `$()`.
* Команды `tee`, `xargs` и `find`.

## Ответы на упражнения с руководством <a href="#sec.103.4_02-age" id="sec.103.4_02-age"></a>

1.  Удобно сохранять дату выполнения действий, выполняемых автоматизированными скриптами. Команда `date +%Y-%m-%d` показывает текущую дату в формате _год-месяц-день_. Как можно сохранить вывод такой команды в переменной оболочки с именем `TODAY` с помощью подстановки команд?

    ```bash
    $ TODAY=`date +%Y-%m-%d`
    ```

    или

    ```bash
    $ TODAY=$(date +%Y-%m-%d)
    ```
2.  Как с помощью команды `echo` отправить содержимое переменной `TODAY` на стандартный ввод команды `sed s/-/./g`?

    ```bash
    $ echo $TODAY | sed s/-/./g
    ```
3.  Как можно использовать вывод команды `date +%Y-%m-%d` в качестве строки Here для команды `sed s/-/./g`?

    ```bash
    $ sed s/-/./g <<< `date +%Y-%m-%d`
    ```

    или

    ```bash
    $ sed s/-/./g <<< $(date +%Y-%m-%d)
    ```
4.  Команда `convert image.jpeg -resize 25% small/image.jpeg` создаёт уменьшенную версию `image.jpeg` и помещает полученное изображение в файл с таким же названием в подкаталоге `small`. Как с помощью `xargs` выполнить ту же команду для каждого изображения, перечисленного в файле `filelist.txt`?

    ```bash
    $ xargs -I IMG convert IMG -resize 25% small/IMG < filelist.txt
    ```

    или

    ```bash
    $ xargs -I IMG convert IMG -resize 25% small/IMG < filelist.txt
    ```

## Ответы на исследовательские упражнения <a href="#sec.103.4_02-aee" id="sec.103.4_02-aee"></a>

1.  Простая программа резервного копирования периодически создает образ раздела `/dev/sda1` с `dd < /dev/sda1 > sda1.img`. Для выполнения будущих проверок целостности данных программа также генерирует хэш SHA1 файла с `sha1sum < sda1.img > sda1.sha1`. Если добавить каналы и команду `tee`, как эти две команды будут объединены в одну?

    ```bash
    # dd < /dev/sda1 | tee sda1.img | sha1sum > sda1.sha1
    ```
2.  Команда `tar` используется для архивирования множества файлов в один файл с сохранением структуры каталогов. Опция `-T` позволяет указать файл, содержащий пути к архивируемым файлам. Например, `find /etc -type f | tar -cJ -f /srv/backup/etc.tar.xz -T -` создаёт сжатый файл tar `etc.tar.xz` из списка, предоставленного командой `find` (опция `-T -` указывает на стандартный ввод в качестве списка путей). Чтобы избежать возможных ошибок синтаксического анализа из-за путей, содержащих пробелы, какие параметры команды должны присутствовать для `find` и `tar`?

    Варианты `-print0` и `--null`:

    ```
    $ find /etc -type f -print0 | tar -cJ -f /srv/backup/etc.tar.xz --null -T -
    ```
3.  Вместо того чтобы открывать новый сеанс удалённой оболочки, команда `ssh` может просто выполнить команду, указанную в качестве аргумента: `ssh user@storage "remote command"`. Учитывая, что `ssh` также позволяет перенаправлять стандартный вывод локальной программы на стандартный ввод удалённой программы, как бы `cat` перенаправил локальный файл с именем `etc.tar.gz` в `/srv/backup/etc.tar.gz` на `user@storage` через `ssh`?

    ```bash
    $ cat etc.tar.gz | ssh user@storage "cat > /srv/backup/etc.tar.gz"
    ```

    или

    ```bash
    $ ssh user@storage "cat > /srv/backup/etc.tar.gz" < etc.tar.gz
    ```
