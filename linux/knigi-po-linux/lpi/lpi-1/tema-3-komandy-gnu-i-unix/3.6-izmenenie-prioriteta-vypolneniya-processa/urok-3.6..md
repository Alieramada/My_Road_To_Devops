# Урок 3.6.

## Введение <a href="#sec.103.6_01-in" id="sec.103.6_01-in"></a>

Операционные системы, способные одновременно запускать несколько процессов, называются многозадачными или многопроцессорными. Хотя настоящая одновременная работа возможна только при наличии более чем одного процессора, даже однопроцессорные системы могут имитировать одновременную работу, очень быстро переключаясь между процессами. Этот метод также используется в системах с большим количеством эквивалентных процессоров или _симметричных многопроцессорных (SMP)_ системах  _symmetric multi-processor_, поскольку количество потенциальных одновременных процессов значительно превышает количество доступных процессоров.

На самом деле только один процесс может одновременно управлять ЦП. Однако большинство действий процессов — это _системные вызовы_, то есть запущенный процесс передаёт управление ЦП операционной системы, чтобы тот выполнил запрошенную операцию. Системные вызовы отвечают за все взаимодействия между устройствами, например за выделение памяти, чтение и запись в файловых системах, вывод текста на экран, взаимодействие с пользователем, передачу данных по сети и т. д. Передача управления ЦП во время системного вызова позволяет операционной системе решить, возвращать ли управление ЦП предыдущему процессу или передать его другому процессу. Поскольку современные ЦП могут выполнять инструкции гораздо быстрее, чем большинство внешних устройств могут взаимодействовать друг с другом, новый управляющий процесс может выполнять большую часть работы ЦП, пока запрошенные ранее аппаратные средства ещё не ответили. Чтобы обеспечить максимальную загрузку ЦП, многопроцессорные операционные системы поддерживают динамическую очередь активных процессов, ожидающих выделения времени ЦП.

Несмотря на то, что они позволяют значительно повысить эффективность использования ЦП, полагаться исключительно на системные вызовы для переключения между процессами недостаточно для достижения удовлетворительной производительности при многозадачной работе. Процесс, который не выполняет системных вызовов, может бесконечно долго управлять ЦП. Именно поэтому современные операционные системы также являются _прерывистыми_, то есть запущенный процесс может быть возвращён в очередь, чтобы более важный процесс мог управлять ЦП, даже если запущенный процесс не выполнял системных вызовов.

## Планировщик Linux <a href="#sec.103.6_01-ls" id="sec.103.6_01-ls"></a>

Linux, как упреждающая многопроцессорная операционная система, реализует планировщик, который организует очередь процессов. Точнее говоря, планировщик также решает, какой _поток_ из очереди будет выполняться — процесс может разветвляться на множество независимых потоков, — но в этом контексте термины «процесс» и «поток» взаимозаменяемы. У каждого процесса есть два предиката, которые влияют на его планирование: _политика планирования_ и _приоритет планирования_.

Существует два основных типа политик планирования: _политики реального времени_ и _обычные политики_. Процессы, работающие по политике реального времени, планируются напрямую в соответствии с их приоритетами. Если более важный процесс становится готовым к запуску, менее важный запущенный процесс прерывается, и процесс с более высоким приоритетом получает управление ЦП. Процесс с более низким приоритетом получает управление ЦП только в том случае, если процессы с более высоким приоритетом простаивают или ожидают отклика оборудования.

Любой процесс реального времени имеет более высокий приоритет, чем обычный процесс. В качестве операционной системы общего назначения Linux запускает лишь несколько процессов реального времени. Большинство процессов, включая системные и пользовательские программы, запускаются в соответствии с обычными политиками планирования. Обычные процессы обычно имеют одинаковый приоритет, но обычные политики могут определять правила приоритета выполнения с помощью другого предиката процесса: _**значения nice**_. Чтобы избежать путаницы с динамическими приоритетами, основанными на значениях nice, приоритеты планирования обычно называют _статическими_ приоритетами планирования.

Планировщик Linux можно настроить множеством различных способов, и существуют ещё более сложные способы установки приоритетов, но эти общие принципы применимы всегда. При проверке и настройке планирования процессов важно помнить, что это повлияет только на процессы с обычной политикой планирования.

## Приоритеты чтения <a href="#sec.103.6_01-rp" id="sec.103.6_01-rp"></a>

Linux резервирует статические приоритеты в диапазоне от 0 до 99 для процессов реального времени, а обычным процессам присваиваются статические приоритеты в диапазоне от 100 до 139, то есть существует 39 различных уровней приоритета для обычных процессов. Меньшие значения означают более высокий приоритет. Статический приоритет активного процесса можно найти в файле `sched` в соответствующем каталоге в файловой системе `/proc`:

<pre><code><strong>$ grep ^prio /proc/1/sched
</strong>prio                   :       120
</code></pre>

Как показано в примере, строка, начинающаяся с `prio`, указывает значение приоритета процесса (процесс с PID 1 — это _init_ или _systemd_, первый процесс, который ядро запускает во время инициализации системы). Стандартный приоритет для обычных процессов — 120, его можно уменьшить до 100 или увеличить до 139. Приоритеты всех запущенных процессов можно проверить с помощью команды `ps -Al` или `ps -el`:

```bash
$ ps -el
F S   UID   PID  PPID  C PRI  NI ADDR SZ WCHAN  TTY          TIME CMD
4 S     0     1     0  0  80   0 -  9292 -      ?        00:00:00 systemd
4 S     0    19     1  0  80   0 -  8817 -      ?        00:00:00 systemd-journal
4 S   104    61     1  0  80   0 - 64097 -      ?        00:00:00 rsyslogd
4 S     0    63     1  0  80   0 -  7244 -      ?        00:00:00 cron
1 S     0   126     1  0  80   0 -  4031 -      ?        00:00:00 dhclient
4 S     0   154     1  0  80   0 -  3937 -      pts/0    00:00:00 agetty
4 S     0   155     1  0  80   0 -  3937 -      pts/1    00:00:00 agetty
4 S     0   156     1  0  80   0 -  3937 -      pts/2    00:00:00 agetty
4 S     0   157     1  0  80   0 -  3937 -      pts/3    00:00:00 agetty
4 S     0   158     1  0  80   0 -  3937 -      console  00:00:00 agetty
4 S     0   160     1  0  80   0 - 16377 -      ?        00:00:00 sshd
4 S     0   280     0  0  80   0 -  5301 -      ?        00:00:00 bash
0 R     0   392   280  0  80   0 -  7221 -      ?        00:00:00 ps
```

В столбце `PRI` указан статический приоритет, назначенный ядром. Однако обратите внимание, что значение приоритета, отображаемое `ps` отличается от значения, полученного в предыдущем примере. По историческим причинам приоритеты, отображаемые `ps` по умолчанию, находятся в диапазоне от -40 до 99, поэтому фактический приоритет получается путём прибавления к нему 40 (в частности, 80 + 40 = 120).

Также можно непрерывно отслеживать процессы, которыми в данный момент управляет ядро Linux, с помощью программы `top`. Как и в случае с `ps`, `top` также по-другому отображает значение приоритета. Чтобы было проще идентифицировать процессы реального времени, `top` вычитает из значения приоритета 100, в результате чего все приоритеты реального времени становятся отрицательными, а отрицательное число или _rt_ указывает на них. Таким образом, обычные приоритеты, отображаемые `top`, находятся в диапазоне от 0 до 39.

{% hint style="info" %}
Чтобы получить более подробную информацию с помощью команды `ps`, можно использовать дополнительные параметры. Сравните вывод этой команды с выводом из нашего предыдущего примера:

```
$ ps -e -o user,uid,comm,tty,pid,ppid,pri,pmem,pcpu --sort=-pcpu | head
```
{% endhint %}

## nice процесса <a href="#sec.103.6_01-ni" id="sec.103.6_01-ni"></a>

Каждый обычный процесс начинается со значением nice по умолчанию, равным 0 (приоритет 120). Название _nice_ происходит от идеи, что «более привлекательные» процессы позволяют другим процессам выполняться перед ними в определённой очереди выполнения. Значения nice варьируются от -20 (менее привлекательные, высокий приоритет) до 19 (более привлекательные, низкий приоритет). В Linux также можно назначать разные значения nice потокам в рамках одного процесса. Столбец `NI` в выводе `ps` указывает на значение _nice_.

Только пользователь с правами суперпользователя может понизить приоритет процесса ниже нуля. Можно запустить процесс с нестандартным приоритетом с помощью команды `nice`. По умолчанию `nice` изменяет приоритет на 10, но его можно указать с помощью опции `-n`:

```bash
$ nice -n 15 tar czf home_backup.tar.gz /home
```

В этом примере команда `tar` выполняется с приоритетом 15. Команду `renice` можно использовать для изменения приоритета запущенного процесса. Параметр `-p` указывает номер PID целевого процесса. Например:

```bash
# renice -10 -p 2164
2164 (process ID) old priority 0, new priority -10
```

Опции `-g` и `-u` используются для изменения всех процессов конкретной группы или пользователя соответственно. С помощью `renice +5 -g users приоритет` процессов, принадлежащих пользователям группы _users_, будет увеличено на пять.

Помимо `renice` приоритет процессов можно изменить с помощью других программ, например, программы `top`. На главном экране вверху можно изменить приоритет процесса, нажав `r` и затем номер PID процесса:

## Ответы на исследовательские упражнения <a href="#sec.103.6_01-aee" id="sec.103.6_01-aee"></a>

1.  Изменение приоритетов процессов обычно требуется, когда процесс занимает слишком много процессорного времени. При использовании `ps` со стандартными параметрами для вывода всех системных процессов в длинном формате, какой `--sort` флаг позволит отсортировать процессы по загрузке процессора в порядке возрастания?

    <pre class="language-bash"><code class="lang-bash"><strong>$ ps -el --sort = pcpu
    </strong></code></pre>
2.  Команда `schedtool` может устанавливать все параметры планирования процессора, на которые способна Linux, или отображать информацию для заданных процессов. Как ее можно использовать для отображения параметров планирования процесса`1750`? Кроме того, как можно использовать `schedtool` для перевода процесса 1750 в режим реального времени с приоритетом -90 (как показано `top`)?

    ```
    $ schedtool 1750
    ```

    ```bash
    $ schedtool -R -p 89 1750
    ```
