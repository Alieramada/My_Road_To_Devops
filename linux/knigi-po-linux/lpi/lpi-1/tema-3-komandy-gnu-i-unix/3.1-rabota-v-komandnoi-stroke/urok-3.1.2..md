# Урок 3.1.2.

## Введение <a href="#sec.103.1_02-in" id="sec.103.1_02-in"></a>

Среда операционной системы включает в себя базовые инструменты, такие как оболочки командной строки, а иногда и графический интерфейс, которые понадобятся вам для выполнения задач. Но ваша среда также будет включать каталог ярлыков и предустановленных значений. Здесь мы научимся просматривать, вызывать и управлять этими значениями.

## Поиск переменных окружения <a href="#finding_your_environment_variables" id="finding_your_environment_variables"></a>

Итак, как же определить текущие значения каждой из наших переменных среды? Один из способов — использовать команду `env`:

```bash
$ env
DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/1000/bus
XDG_RUNTIME_DIR=/run/user/1000
XAUTHORITY=/run/user/1000/gdm/Xauthority
XDG_CONFIG_DIRS=/etc/xdg/xdg-ubuntu:/etc/xdg
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/snap/bin
GJS_DEBUG_TOPICS=JS ERROR;JS LOG
[...]
```

Вы получите много выходных данных — гораздо больше, чем в приведённом выше фрагменте. Но пока обратите внимание на запись `PATH` в которой указаны каталоги, в которых ваша оболочка (и другие программы) будет искать другие программы без необходимости указывать полный путь. С помощью этого набора вы можете запустить двоичную программу, которая находится, скажем, в `/usr/local/bin` из вашего домашнего каталога, и она будет работать так, как если бы файл был локальным.

Давайте ненадолго сменим тему. Команда `echo` выведет на экран всё, что вы ей скажете. Хотите верьте, хотите нет, но во многих случаях будет очень полезно, если `echo` буквально повторит что-то.

```bash
$ echo "Hi. How are you?"
Hi. How are you?
```

Но есть ещё кое-что, что вы можете сделать с помощью `echo`. Если вы введёте в него имя переменной среды и укажете, что это переменная, добавив к имени переменной `$` в качестве префикса, то вместо того, чтобы просто вывести имя переменной, оболочка расширит его и выдаст вам значение. Не знаете, есть ли ваш любимый каталог в пути? Вы можете быстро проверить это, введя `echo`:

```bash
$ echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/snap/bin
```

## Создание новых переменных окружения <a href="#creating_new_environment_variables" id="creating_new_environment_variables"></a>

Вы можете добавить в свою среду собственные переменные. Самый простой способ — использовать символ `=`. Строка слева будет именем вашей новой переменной, а строка справа — её значением. Теперь вы можете передать имя переменной в `echo` для подтверждения, что всё работает:

```bash
$ myvar=hello
$ echo $myvar
hello
```

{% hint style="info" %}
Обратите внимание, что по обе стороны от знака равенства при присвоении переменной нет пробелов.
{% endhint %}

Но действительно ли это сработало? Введите `bash` в терминале, чтобы открыть новую оболочку. Эта новая оболочка выглядит точно так же, как та, в которой вы только что находились, но на самом деле она является _дочерней_ по отношению к исходной (которую мы называем _родительской_). Теперь в этой новой дочерней оболочке попробуйте заставить `echo` работать так же, как раньше. Ничего не происходит. Что происходит?

```bash
$ bash
$ echo $myvar

$
```

Переменная, которую вы создадите так, как мы только что сделали, будет доступна только локально — в текущем сеансе оболочки. Если вы откроете новую оболочку или закроете сеанс с помощью `exit` — переменная не сохранится. Если вы введёте `exit` , вы вернётесь в исходную родительскую оболочку, в которой мы сейчас находимся. Вы можете ввести `echo $myvar` ещё раз, чтобы убедиться, что переменная по-прежнему действительна. Теперь введите `export myvar` для передачи переменной дочерним оболочкам, которые вы можете открыть впоследствии. Попробуйте: введите `bash` для новой оболочки, а затем `echo`:

```bash
$ exit
$ export myvar
$ bash
$ echo $myvar
hello
```

Всё это может показаться немного глупым, когда мы создаём оболочки без особой цели. Но понимание того, как переменные оболочки распространяются по вашей системе, станет очень важным, когда вы начнёте писать серьёзные скрипты.

## Удаление переменных окружения <a href="#deleting_environment_variables" id="deleting_environment_variables"></a>

Хотите узнать, как очистить все созданные вами временные переменные? Один из способов — просто закрыть родительскую оболочку или перезагрузить компьютер. Но есть и более простые способы. Например, `unset`. Набрав `unset` (без `$`), вы уничтожите переменную.&#x20;

```bash
$ unset myvar
$ echo $myvar

$
```

Если есть команда `unset` , то можно поспорить, что должна быть и команда `set` , которая с ней связана. При выполнении `set` само по себе будет выводиться много информации, но она не сильно отличается от того, что вы получили с помощью `env` . Посмотрите на первую строку вывода, который вы получите при фильтрации по `PATH:`

```bash
$ set | grep PATH
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/snap/bin
[...]
```

В чём разница между `set` и `env`? Для наших целей главное, что `set` выводит все переменные и функции. Давайте это проиллюстрируем. Мы создадим новую переменную под названием `mynewvar` и подтвердим, что она существует:\


```bash
$ mynewvar=goodbye
$ echo $mynewvar
goodbye
```

Теперь при выполнении `env` с использованием `grep` для фильтрации по строке `mynewvar` не будет выводиться никаких результатов. Но при выполнении `set` таким же образом мы увидим нашу локальную переменную.

```bash
$ env | grep mynewvar

$ set | grep mynewvar
mynewvar=goodbye
```

## Кавычки для экранирования специальных символов <a href="#quoting_to_escape_special_characters" id="quoting_to_escape_special_characters"></a>

Сейчас самое подходящее время, чтобы познакомить вас с проблемой специальных символов. Буквенно-цифровые символы (a-z и 0-9) обычно считываются Bash буквально. Если вы попытаетесь создать новый файл с именем `myfile` , вы просто введёте `touch` , а затем `myfile` , и Bash поймёт, что с этим делать. Но если вы хотите включить в имя файла специальный символ, вам придётся немного потрудиться.

Чтобы проиллюстрировать это, мы введём `touch` и последуем за ним с заголовком: `my big file`. Проблема в том, что между словами есть два пробела, которые интерпретирует Bash. Хотя технически пробел нельзя назвать «символом», он похож на него в том смысле, что Bash не будет воспринимать его буквально. Если вы перечислите содержимое текущего каталога, то вместо одного файла с именем `my big file` вы увидите три файла с именами `my`, `big`, и `file`. Это связано с тем, что Bash решил, что вы хотите создать несколько файлов, имена которых вы передаёте в списке:

```bash
$ touch my big file
$ ls
my big file
```

Пробелы будут интерпретироваться так же, если вы удалите (`rm`) все три файла одной командой:

```bash
$ rm my big file
```

Теперь давайте попробуем сделать это правильно. Введите `touch` и три части вашего имени файла, но на этот раз заключите имя в кавычки. На этот раз всё получилось. При просмотре содержимого каталога вы увидите один файл с правильным именем.

```bash
$ touch "my big file"
$ ls
'my big file'
```

Есть и другие способы добиться того же эффекта. Например, одинарные кавычки работают так же хорошо, как и двойные. (Обратите внимание, что одинарные кавычки сохраняют буквенное значение всех символов, а двойные кавычки сохраняют все символы, _кроме_ `$`, `` ` ``, `\` и, в некоторых случаях, `!`.)

```bash
$ rm 'my big file'
```

Если перед каждым специальным символом поставить обратную косую черту, то Bash «спрячет» его особенность и будет воспринимать буквально.

```bash
$ touch my\ big\ file
```

## Краткие сведения <a href="#sec.103.1_02-su" id="sec.103.1_02-su"></a>

На этом уроке вы узнали:

* Как определить переменные окружения вашей системы.
* Как создать свои собственные переменные среды и экспортировать их в другие оболочки.
* Как удалить переменные среды и как использовать команды `env` и `set`.
* Как экранировать специальные символы, чтобы Bash читал их буквально.

В этом уроке обсуждались следующие команды:

`echo`

Вывести входные строки и переменные.

`env`

Вывести информацию о переменных среды.

`export`

Передайть переменную окружения дочерним оболочкам.

`unset`

Отменить установку значений и атрибутов переменных и функций оболочки.

## Ответы на упражнения с руководством <a href="#sec.103.1_02-age" id="sec.103.1_02-age"></a>

1.  Используйте команду `export` для добавления нового каталога в путь (это не сохранится после перезагрузки).

    Вы можете временно добавить новый каталог (например, `myfiles` в вашем домашнем каталоге) в путь с помощью `export PATH="/home/yourname/myfiles:$PATH"`. Создайте простой скрипт в каталоге `myfiles/`, сделайте его исполняемым и попробуйте запустить из другого каталога. Эти команды предполагают, что вы находитесь в своём домашнем каталоге, в котором есть каталог с именем `myfiles`.

    ```bash
    $ touch myfiles/myscript.sh
    $ echo '#!/bin/bash' >> myfiles/myscript.sh
    $ echo 'echo Hello' >> myfiles/myscript.sh
    $ chmod +x myfiles/myscript.sh
    $ myscript.sh
    Hello
    ```
2.  Используйте команду `unset` для удаления переменной `PATH`. Попробуйте выполнить команду (например, `sudo cat /etc/shadow`) с помощью `sudo`. Что произошло? Почему? (Выход из командной строки вернёт вас в исходное состояние.)

    При вводе `unset PATH` текущие настройки пути будут удалены. Попытка запустить двоичный файл без указания его абсолютного адреса завершится ошибкой. По этой причине попытка запустить команду с помощью sudo (которая сама по себе является двоичной программой, расположенной в `/usr/bin/sudo`) завершится ошибкой, если вы не укажете абсолютное местоположение, например: `/usr/bin/sudo /bin/cat /etc/shadow`. Вы можете сбросить настройки `PATH` с помощью `export` или просто выйдя из оболочки.

## Ответы на исследовательские упражнения <a href="#sec.103.1_02-aee" id="sec.103.1_02-aee"></a>

1.  Выполните поиск в Интернете, чтобы найти и изучить полный список специальных символов.

    Вот список: `& ; | * ? " ' [ ] ( ) $ < > { } # / \ ! ~`.
2.  Попробуйте выполнить команды, используя строки, состоящие из специальных символов, и различные методы их экранирования. Есть ли разница в поведении этих методов?

    При экранировании с помощью символов `"` сохраняются специальные значения знака доллара, обратной косой черты и прямой косой черты. При экранировании с помощью символа `'` _все_ символы будут отображаться как литералы.

```bash
$ echo "$mynewvar"
goodbye
$ echo '$mynewvar'
$mynewvar
```
