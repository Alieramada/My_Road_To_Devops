# Урок 3.2

## Введение <a href="#sec.103.2_01-in" id="sec.103.2_01-in"></a>

Работа с текстом — важная часть работы любого системного администратора. Дуг Макилрой, член первоначальной команды разработчиков Unix, обобщил философию Unix и сказал (среди прочего): «Пишите программы для работы с текстовыми потоками, потому что это универсальный интерфейс». Linux вдохновлён операционной системой Unix и полностью перенял её философию, поэтому администратор должен ожидать, что в дистрибутиве Linux будет много инструментов для работы с текстом.

## Краткий обзор перенаправлений и каналов <a href="#a_quick_review_on_redirections_and_pipes" id="a_quick_review_on_redirections_and_pipes"></a>

Также из философии Unix:

* Пишите программы, которые делают что-то одно, и делают это хорошо.
* Пишите программы для совместной работы.

Один из основных способов совместной работы программ — это _конвейерная передача данных_ и _перенаправление_. Практически все ваши программы для работы с текстом будут получать текст из стандартного ввода (_stdin_), выводить его в стандартный вывод (_stdout_) и отправлять возможные ошибки в стандартный вывод ошибок (_stderr_). Если вы не укажете иное, стандартный ввод будет представлять собой то, что вы вводите с клавиатуры (программа прочитает это после того, как вы нажмете клавишу Enter). Аналогичным образом стандартный вывод и ошибки будут отображаться на экране вашего терминала. Давайте посмотрим, как это работает.

В вашем терминале введите `cat` и нажмите клавишу Enter. Затем введите произвольный текст.

```bash
$ cat
This is a test
This is a test
Hey!
Hey!
It is repeating everything I type!
It is repeating everything I type!
(I will hit ctrl+c so I will stop this nonsense)
(I will hit ctrl+c so I will stop this nonsense)
^C
```

Для получения дополнительной информации о команде `cat` (термин происходит от “concatenate”) обратитесь к справочным страницам.

{% hint style="info" %}
Если вы работаете с очень простой установкой Linux-сервера, некоторые команды, такие как `info` и `less`, могут быть недоступны. В этом случае установите эти инструменты в свою систему, как описано в соответствующих уроках.
{% endhint %}

Как показано выше, если вы не укажете, откуда `cat` должен считывать данные, он будет считывать их со стандартного ввода (всё, что вы вводите) и выводить в окно терминала (на стандартный вывод).

Теперь попробуйте следующее:

```bash
$ cat > mytextfile
This is a test
I hope cat is storing this to mytextfile as I redirected the output
I will hit ctrl+c now and check this
^C

$ cat mytextfile
This is a test
I hope cat is storing this to mytextfile as I redirected the output
I will hit ctrl+c now and check this
```

`>` (больше, чем) указывает `cat` на то, что вывод должен быть направлен в файл `mytextfile`, а не в стандартный вывод. Теперь попробуйте следующее:

```bash
$ cat mytextfile > mynewtextfile
$ cat mynewtextfile
This is a test
I hope cat is storing this to mytextfile as I redirected the output
I will hit ctrl+c now and check this
```

Это приводит к копированию `mytextfile` в `mynewtextfile`. Вы можете убедиться, что эти два файла содержат одинаковое содержимое, выполнив `diff`

```bash
$ diff mynewtextfile mytextfile
```

Поскольку вывода нет, файлы равны. Теперь попробуйте оператор перенаправления (`>>`):

```bash
$ echo 'This is my new line' >> mynewtextfile
$ diff mynewtextfile mytextfile
4d3
< This is my new line
```

До сих пор мы использовали перенаправление для создания файлов и работы с ними. Мы также можем использовать каналы (обозначаемые символом `|`) для перенаправления вывода одной программы в другую. Давайте найдём строки, в которых встречается слово «this»:

```bash
$ cat mytextfile | grep this
I hope cat is storing this to mytextfile as I redirected the output
I will hit ctrl+c now and check this

$ cat mytextfile | grep -i this
This is a test
I hope cat is storing this to mytextfile as I redirected the output
I will hit ctrl+c now and check this
```

Теперь мы перенаправили вывод `cat` в другую команду: `grep`. Обратите внимание, что при игнорировании регистра (с помощью опции `-i`) в результате мы получаем дополнительную строку.

## Обработка текстовых потоков <a href="#processing_text_streams" id="processing_text_streams"></a>

## **Чтение сжатого файла**

Мы создадим файл с именем `ftu.txt` , содержащий список следующих команд:

```
bzcat
cat
cut
head
less
md5sum
nl
od
paste
sed
sha256sum
sha512sum
sort
split
tail
tr
uniq
wc
xzcat
zcat
```

Теперь мы будем использовать команду `grep` для вывода всех строк, содержащих строку `cat`:

```bash
$ cat ftu.txt | grep cat
bzcat
cat
xzcat
zcat
```

Другой способ получить эту информацию — просто использовать команду `grep` для фильтрации текста напрямую, без необходимости использовать другое приложение для отправки текстового потока в `stdout`.

```bash
$ grep cat ftu.txt
bzcat
cat
xzcat
zcat
```

{% hint style="info" %}
Помните, что существует множество способов выполнить одну и ту же задачу с помощью Linux.
{% endhint %}

Существуют и другие команды для работы со сжатыми файлами (`bzcat` для `bzip` сжатых файлов, `xzcat` для `xz` сжатых файлов и `zcat` для `gzip` сжатых файлов), и каждая из них используется для просмотра содержимого сжатого файла в зависимости от используемого алгоритма сжатия.

Убедитесь, что только что созданный файл `ftu.txt` является единственным в каталоге, затем создайте `gzip` сжатую версию файла:

```bash
$ ls ftu*
ftu.txt

$ gzip ftu.txt
$ ls ftu*
ftu.txt.gz
```

Затем используйте команду `zcat` для просмотра содержимого сжатого файла в формате gzipped:

```bash
$ zcat ftu.txt.gz
bzcat
cat
cut
head
less
md5sum
nl
od
paste
sed
sha256sum
sha512sum
sort
split
tail
tr
uniq
wc
xzcat
zcat
```

Обратите внимание, что `gzip` сжмёт `ftu.txt` в `ftu.txt.gz` и удалит исходный файл. По умолчанию команда `gzip` не выводит никаких сообщений. Однако, если вы хотите, чтобы `gzip` сообщала вам о своих действиях, используйте опцию `-v` для «подробного» вывода.

## **Просмотр файла в пейджере**

Вы знаете, что `cat` объединяет файл со стандартным выводом (если после команды указан файл). Файл `/var/log/syslog` — это место, где ваша система Linux хранит всё важное, что происходит в вашей системе. С помощью команды `sudo` можно повысить привилегии, чтобы иметь возможность читать файл `/var/log/syslog`:

```bash
$ sudo cat /var/log/syslog
```

...вы увидите, что сообщения очень быстро прокручиваются в окне терминала. Вы можете перенаправить вывод в программу `less` так, чтобы результаты отображались постранично. С помощью `less` вы можете перемещаться по выводам с помощью клавиш со стрелками, а также использовать `vi` для навигации и поиска по тексту.

Однако вместо того, чтобы передавать команду `cat` в программу разбиения на страницы, более практично просто использовать программу разбиения на страницы напрямую:

```bash
$ sudo less /var/log/syslog
```

## **Основы sed, редактора потоков**

Давайте посмотрим на другие файлы, термины и утилиты, в названиях которых нет `cat`: Мы можем сделать это, передав `-v` в `grep` и указав, что команда должна выводить только строки, не содержащие `cat`:

```bash
$ zcat ftu.txt.gz | grep -v cat
cut
head
less
md5sum
nl
od
paste
sed
sha256sum
sha512sum
sort
split
tail
tr
uniq
wc
```

Большую часть того, что мы можем сделать с помощью `grep`, мы также можем сделать с помощью `sed` — редактора потоков для фильтрации и преобразования текста (как указано на странице руководства `sed`). Сначала мы восстановим наш `ftu.txt` файл, распаковав `gzip` архив с файлом:

```bash
$ gunzip ftu.txt.gz
$ ls ftu*
ftu.txt
```

Теперь мы можем использовать `sed` для вывода только строк, содержащих строку `cat`:

```bash
$ sed -n /cat/p < ftu.txt
bzcat
cat
xzcat
zcat
```

Мы использовали знак «меньше» `<` для передачи содержимого файла `ftu.txt into` в нашу команду `sed` . Слово, заключённое в косые черты (т. е. `/cat/` ), — это термин, который мы ищем. Опция `-n` указывает `sed` не выводить никаких результатов (кроме тех, которые позже будут указаны командой `p` ). Попробуйте выполнить эту же команду без опции `-n` и посмотрите, что произойдёт. Затем попробуйте следующее:

```bash
$ sed /cat/d < ftu.txt
cut
head
less
md5sum
nl
od
paste
sed
sha256sum
sha512sum
sort
split
tail
tr
uniq
wc
```

Если мы не используем опцию `-n`, `sed` выведет всё содержимое файла, кроме того, что `d` указывает `sed` удалить из вывода.

Обычно `sed` используется для поиска и замены текста в файле. Предположим, вы хотите заменить все вхождения `cat` на `dog`. Для этого можно использовать `sed` и указать параметр `s` для замены каждого вхождения первого термина `cat` на второй термин `dog`:

<pre><code><strong>$ sed s/cat/dog/ &#x3C; ftu.txt
</strong>bzdog
dog
cut
head
less
md5sum
nl
od
paste
sed
sha256sum
sha512sum
sort
split
tail
tr
uniq
wc
xzdog
zdog
</code></pre>

Вместо того чтобы использовать оператор перенаправления (`<`) для передачи файла `ftu.txt` в нашу команду `sed`, мы можем просто использовать команду `sed` для работы с файлом напрямую. Далее мы попробуем это сделать, одновременно создавая резервную копию исходного файла:

```bash
$ sed -i.backup s/cat/dog/ ftu.txt
$ ls ftu*
ftu.txt ftu.txt.backup
```

Опция `-i` выполнит операцию `sed` на месте _исходного_ файла. Если вы не используете `.backup` после параметра `-i`, вы просто перепишете _исходный_ файл. То, что вы вводите после параметра `-i`, будет именем исходного файла, который будет сохранен до внесения изменений, которые вы попросили `sed` выполнить.

## **Обеспечение целостности данных**

Этот метод очень часто используется, когда серверы дистрибутивов Linux размещают загружаемые образы компакт-дисков или DVD-дисков с программным обеспечением вместе с файлами, содержащими вычисленные контрольные суммы этих образов дисков. {% endhint %}

После загрузки файла (например, изображения `debian-10.1.0-amd64-netinst.iso`), вы можете сравнить контрольную сумму загруженного файла со значением контрольной суммы, предоставленным вам.

Вот пример, чтобы проиллюстрировать сказанное. Мы вычислим значение SHA256 для файла `ftu.txt` с помощью команды `sha256sum`:

```bash
$ sha256sum ftu.txt
345452304fc26999a715652543c352e5fc7ee0c1b9deac6f57542ec91daf261c ftu.txt
```

Длинная строка символов, предшествующая имени файла, — это значение контрольной суммы SHA256 для этого текстового файла. Давайте создадим файл, содержащий это значение, чтобы использовать его для проверки целостности исходного текстового файла. Мы можем сделать это с помощью той же команды `sha256sum` и перена

ить вывод в файл:

```bash
$ sha256sum ftu.txt > sha256.txt
```

Теперь, чтобы проверить файл `ftu.txt`, мы просто используем ту же команду и указываем имя файла, содержащее значение контрольной суммы, вместе с параметром `-c`:

```bash
$ sha256sum -c sha256.txt
ftu.txt: ОК
```

Значение, содержащееся в файле, совпадает с вычисленной контрольной суммой SHA256 для нашего файла `ftu.txt` так, как мы и ожидали. Однако, если исходный файл был изменён (например, несколько байтов были потеряны при загрузке файла или кто-то намеренно вмешался в его содержимое), проверка значения не пройдёт. В таких случаях мы знаем, что наш файл повреждён, и мы не можем доверять целостности его содержимого. Чтобы доказать это, мы добавим в конец файла несколько строк:

```bash
$ echo "new entry" >> ftu.txt
```

Теперь мы попытаемся проверить целостность файла:

```bash
$ sha256sum -c sha256.txt
ftu.txt: FAILED
sha256sum: WARNING: 1 computed checksum did NOT match
```

И мы видим, что контрольная сумма не совпадает с ожидаемой для этого файла. Поэтому мы не можем быть уверены в целостности этого файла. Мы можем попытаться загрузить новую копию файла, сообщить о несоответствии контрольной суммы отправителю файла или сообщить об этом службе безопасности центра обработки данных в зависимости от важности файла.

## Краткие сведения <a href="#sec.103.2_01-su" id="sec.103.2_01-su"></a>

Работа с текстовыми потоками очень важна при администрировании любой системы Linux. Текстовые потоки можно обрабатывать с помощью скриптов для автоматизации повседневных задач или поиска важной отладочной информации в файлах журналов. Вот краткое описание команд, рассмотренных в этом уроке:

`cat`

Используется для объединения или чтения обычных текстовых файлов.

`bzcat`

Позволяет обрабатывать или считывать файлы, сжатые с использованием `bzip2` метода.

`xzcat`

Позволяет обрабатывать или считывать файлы, сжатые с использованием `xz` метода.

`zcat`

Позволяет обрабатывать или считывать файлы, сжатые с использованием `gzip` метода.

`less`

Эта команда разбивает содержимое файла на страницы и позволяет осуществлять навигацию и поиск.

`head`

По умолчанию эта команда выводит первые 10 строк файла. С помощью переключателя `-n` можно вывести меньше или больше строк.

`tail`

По умолчанию эта команда выводит последние 10 строк файла. С помощью переключателя `-n` можно вывести меньше или больше строк. Опция `-f` используется для отслеживания вывода текстового файла при записи в него новых данных.

`wc`

Сокращение от «подсчёт слов», но в зависимости от используемых вами параметров он будет подсчитывать символы, слова и строки.

`sort`

Используется для упорядочивания вывода списка в алфавитном, обратном алфавитном или случайном порядке.

`uniq`

Используется для составления списка (и подсчета) совпадающих строк.

`od`

Команда «octal dump» используется для отображения двоичного файла в восьмеричной, десятичной или шестнадцатеричной системе счисления.

`nl`

Команда «номер строки» отобразит количество строк в файле, а также создаст файл, в котором перед каждой строкой будет указан её номер.

`sed`

Редактор потоков можно использовать для поиска совпадений строк с помощью регулярных выражений, а также для редактирования файлов с помощью заранее заданных шаблонов.

`tr`

Команда translate может заменять символы, а также удалять и сжимать повторяющиеся символы.

`cut`

Эта команда может выводить столбцы текстовых файлов в виде полей в соответствии с разделителем символов в файле.

`paste`

Объединяйте файлы в столбцы на основе использования разделителей полей.

`split`

Эта команда может разделять большие файлы на более мелкие в зависимости от критериев, заданных в параметрах команды.

`md5sum`

Используется для вычисления значения хэша MD5 для файла. Также используется для проверки файла на соответствие существующему значению хэша для обеспечения целостности файла.

`sha256sum`

Используется для вычисления хэш-значения SHA256 для файла. Также используется для проверки файла на соответствие существующему хэш-значению для обеспечения целостности файла.

`sha512sum`

Используется для вычисления хэш-значения SHA512 для файла. Также используется для проверки файла на соответствие существующему хэш-значению для обеспечения целостности файла.

        Теперь, когда вы знаете, что есть несколько способов сделать одно и то же, когда следует использовать тот или иной способ? Это действительно зависит от нескольких факторов, два из которых наиболее важны: производительность и читаемость. В большинстве случаев вы будете использовать команды оболочки в сценариях оболочки для автоматизации задач, и чем больше и сложнее становятся ваши сценарии, тем больше вам нужно беспокоиться о том, чтобы они работали быстро.
    *   Проделайте то же самое с `sed` вместо `grep`

        Теперь вместо `grep` мы попробуем это с `sed`:

        ```bash
        $ sed -n /processor/p /proc/cpuinfo | wc -l
        ```

        Здесь мы использовали `sed` с параметром `-n`, поэтому `sed` не будет выводить ничего, кроме того, что соответствует выражению `processor`, как указано в команде `p` . Как и в решениях `grep` , `wc -l` будет подсчитывать количество строк, то есть количество имеющихся у нас процессоров.

        Изучите следующий пример:

        ```bash
        $ sed -n /processor/p /proc/cpuinfo | sed -n '$='
        ```

        Эта последовательность команд даёт те же результаты, что и в предыдущем примере, где вывод `sed` передавался в команду `wc`. Разница в том, что вместо использования `wc -l` для подсчёта количества строк `sed` снова вызывается для выполнения аналогичной функции. И снова мы подавляем вывод `sed` с помощью опции `-n`, за исключением выражения, которое мы явно вызываем, — `'$='`. Это выражение сообщает `sed` о необходимости сопоставить последнюю строку (`$`) и затем вывести номер этой строки (`=`).

       ```bash
       $ grep «:/bin/bash$» /etc/passwd | cut -d: -f1
       ```

       Имя пользователя — это первое поле (`-f1` параметр команды `cut`), а `/etc/passwd` файл использует `:` в качестве разделителей (`-d:` параметр команды `cut`). Мы просто перенаправляем вывод команды `grep` в соответствующую команду `cut`
   *   В вашей системе есть несколько пользователей, которые существуют для работы с определёнными программами или в административных целях. У них нет доступа к оболочке. Сколько таких пользователей в вашей системе?

       Самый простой способ найти это — вывести на печать строки для учётных записей, которые не используют оболочку Bash:

       ```bash
       $ grep -v «:/bin/bash$» /etc/passwd | wc -l
       ```
   *   Сколько пользователей и групп существует в вашей системе (помните: используйте только файл `/etc/passwd`).

       Первое поле в любой строке вашего файла `/etc/passwd` — это имя пользователя, второе обычно представляет собой `x` и указывает на то, что пароль пользователя здесь не хранится (он зашифрован в файле `/etc/shadow`). Третье — это идентификатор пользователя (UID), а четвёртое — идентификатор группы (GID). Таким образом, мы получаем количество пользователей:

       ```bash
       $ cut -d: -f3 /etc/passwd | wc -l
       ```

       Ну, в большинстве случаев так и будет. Однако бывают ситуации, когда вы устанавливаете разные права суперпользователя или других специальных пользователей с одинаковым UID (идентификатором пользователя). Поэтому на всякий случай мы передадим результат нашей команды `cut` в команду `sort` и затем посчитаем количество строк.

       ```bash
       $ cut -d: -f3 /etc/passwd | sort -u | wc -l
       ```

       Теперь перейдем к количеству групп:

       ```bash
       $ cut -d: -f4 /etc/passwd | sort -u | wc -l
       ```
   *   Перечислите только первую, последнюю и десятую строки вашего файла `/etc/passwd`

       Этого будет достаточно:

       ```bash
       $ sed -n -e '1'p -e '10'p -e '$'p /etc/passwd
       ```

       Помните, что параметр `-n` указывает `sed` не выводить ничего, кроме того, что указано в команде `p` . Знак доллара (`$`) здесь используется как регулярное выражение, обозначающее последнюю строку файла.
3.  Рассмотрим этот пример файла `/etc/passwd` . Скопируйте приведённые ниже строки в локальный файл с именем `mypasswd` для этого упражнения.

    ```bash

    libvirt-dnsmasq:x:122:133:Libvirt Dnsmasq,,,:/var/lib/libvirt/dnsmasq:/usr/sbin/nologin

    grace:x:1004:1000:Grace Kearns,Engineering,,,Main Office:/home/grace:/bin/ksh
    henry:x:1005:1000:Henry Adams,Sales,,,Main Office:/home/henry:/bin/bash
    john:x:1006:1000:John Chapel,Sales,,,Main Office:/home/john:/bin/bash
    ```

    *   Выведите список всех пользователей из группы 1000 (используйте `sed` для выбора только нужного поля) из вашего файла `mypasswd`:

        GID — это четвёртое поле в файле `/etc/passwd` . Возможно, вам захочется попробовать следующее:

        ```bash
        $ sed -n /1000/p mypasswd
        ```

        В этом случае вы также получите эту строку:

        ```bash
        carol:x:1000:2000:Carol Smith,Finance,,,Main Office:/home/carol:/bin/bash
        ```

        Вы знаете, что это неверно, поскольку Кэрол Смит является членом GID 2000, и совпадение произошло из-за UID. Однако вы могли заметить, что после GID следующее поле начинается с заглавной буквы. Мы можем использовать регулярное выражение, чтобы решить эту проблему.

        <pre class="language-bash"><code class="lang-bash"><strong>$ sed -n /:1000:[A-Z]/p mypasswd
        </strong></code></pre>

        Выражение `[A-Z]` будет соответствовать любому отдельному символу в верхнем регистре. Подробнее об этом вы узнаете в соответствующем уроке.
    *   Выведите только полные имена всех пользователей этой группы (используйте `sed` и `cut`):

        Используйте ту же технику, которую вы применяли для решения первой части этого упражнения, и передайте результат в команду `cut`

        ```bash
        $ sed -n /:1000:[A-Z]/p mypasswd | cut -d: -f5
        Dave Edwards,Finance,,,Main Office
        Emma Jones,Finance,,,Main Office
        Frank Cassidy,Finance,,,Main Office
        Grace Kearns,Engineering,,,Main Office
        Henry Adams,Sales,,,Main Office
        John Chapel,Sales,,,Main Office
        ```

        Не совсем так! Обратите внимание, что поля в результатах могут быть разделены `,`. Поэтому мы передадим вывод в другую команду `cut` с использованием `,` в качестве разделителя.

        ```bash
        $ sed -n /:1000:[A-Z]/p mypasswd | cut -d: -f5 | cut -d, -f1
        Dave Edwards
        Emma Jones
        Frank Cassidy
        Grace Kearns
        Henry Adams
        John Chapel
        ```

## Ответы на исследовательские упражнения <a href="#sec.103.2_01-aee" id="sec.103.2_01-aee"></a>

1.  Снова используя файл `mypasswd` из предыдущих упражнений, придумайте команду Bash, которая выберет одного человека из главного офиса для участия в розыгрыше. Используйте команду `sed` для вывода только строк, относящихся к главному офису, а затем последовательность команд `cut` для получения имени каждого пользователя из этих строк. Затем вам нужно будет случайным образом отсортировать эти имена и вывести только первое имя из списка.

    Сначала изучите, как параметр `-R` управляет выводом команды `sort` . Повторите эту команду несколько раз на своём компьютере (обратите внимание, что вам нужно будет заключить «Главный офис» в одинарные кавычки, чтобы `sed` обрабатывал его как одну строку):

    ```bash
    sed -n /'Main Office'/p mypasswd | cut -d: -f5 | cut -d, -f1 | sort -R
    ```

    Вот решение проблемы:

    ```bash
    $ sed -n /'Main Office'/p mypasswd | cut -d: -f5 | cut -d, -f1 | sort -R | head -1
    ```
2.  Сколько человек работают в сфере финансов, инженерии и продаж? (Подумайте о том, чтобы изучить команду `uniq`.)

    Продолжайте развивать то, что вы узнали из предыдущих упражнений. Попробуйте следующее:

    ```bash
    $ sed -n /'Main Office'/p mypasswd
    $ sed -n /'Main Office'/p mypasswd | cut -d, -f2
    ```

    Обратите внимание, что теперь нам не нужен `:` в качестве разделителя. Нам нужно только второе поле, когда мы разбиваем строки по символам `,`.

    ```bash
    $ sed -n /'Main Office'/p mypasswd | cut -d, -f2 | uniq -c
          4 Finance
          1 Engineering
          2 Sales
    ```

    Команда `uniq` выводит только уникальные строки (а не повторяющиеся), а параметр `-c` указывает `uniq` на необходимость подсчёта одинаковых строк. Здесь есть одна особенность: `uniq` учитывает только соседние строки. Если это не так, вам придётся использовать команду `sort` .
3.  Теперь вы хотите подготовить файл CSV (значения, разделенные запятыми), чтобы вы могли легко импортировать из `mypasswd` файла в предыдущем примере файл `names.csv` в LibreOffice. Содержимое файла будет иметь следующий формат:

    ```bash
    First Name,Last Name,Position
    Carol,Smith,Finance
    ...
    John,Chapel,Sales
    ```

    Совет: для достижения желаемых результатов используйте команды `sed`, `cut`, и `paste`. Обратите внимание, что в этом файле разделителем будет запятая (,).

    Начните с команд `sed` и `cut`, опираясь на то, что мы узнали из предыдущих упражнений:

    ```bash
    $ sed -n /'Main Office'/p mypasswd | cut -d: -f5 | cut -d" " -f1 > firstname
    ```

    Теперь у нас есть файл `firstname` с именами наших сотрудников.

    ```bash
    $ sed -n /'Main Office'/p mypasswd | cut -d: -f5 | cut -d" " -f2 | cut -d, -f1 > lastname
    ```

    Теперь у нас есть файл `lastname`, содержащий фамилии каждого сотрудника.

    Далее мы определяем, в каком отделе работает каждый сотрудник:

    ```bash
    $ sed -n /'Main Office'/p mypasswd | cut -d: -f5 | cut -d, -f2 > department
    ```

    Прежде чем приступить к работе над окончательным решением, попробуйте выполнить следующие команды, чтобы увидеть, какой результат они дают:

    ```bash
    $ cat firstname lastname department
    $ paste firstname lastname department
    ```

    А теперь перейдем к окончательному решению:

    ```bash
    $ paste firstname lastname department | tr '\t' ,
    $ paste firstname lastname department | tr '\t' , > names.csv
    ```

    Здесь мы используем команду `tr` для _замены_  разделителя табуляции на `,`. `tr` Это очень полезно, когда нам нужно заменить один символ на другой. Обязательно ознакомьтесь со справочными страницами для `tr` и `paste`. Например, мы можем использовать опцию `-d` для разделителя, чтобы упростить предыдущую команду:

    ```bash
    $ paste -d, firstname lastname department
    ```

    Мы использовали здесь команду `paste` только для того, чтобы вы с ней ознакомились. Однако мы могли бы легко выполнить все задачи в одной цепочке команд:

    ```bash
    $ sed -n /'Main Office'/p mypasswd | cut -d: -f5 | cut -d, -f1,2 | tr ' ' , > names.csv
    ```
4.  Предположим, что таблица `names.csv` в предыдущем упражнении — это важный файл, и мы хотим убедиться, что никто не внесёт в него изменения с момента отправки до момента получения его получателем. Как мы можем обеспечить целостность этого файла с помощью `md5sum`?

    Если вы заглянете в справочные страницы для `md5sum`, `sha256sum` и `sha512sum`, то увидите, что все они начинаются со следующего текста:

    “вычислить и проверить дайджест сообщений XXX”

    Где «XXX» — это алгоритм, который будет использоваться для создания этого _дайджеста сообщения_.

    Мы будем использовать `md5sum` в качестве примера, а затем вы сможете попробовать другие команды.

    ```bash
    $ md5sum names.csv
    61f0251fcab61d9575b1d0cbf0195e25  names.csv
    ```

    Теперь, например, вы можете сделать файл доступным через защищённый ftp-сервис и отправить сгенерированный _дайджест сообщения_ с помощью другого защищённого средства связи. Если файл был слегка изменён, _дайджест сообщения_ будет совершенно другим. Чтобы убедиться в этом, отредактируйте `names.csv` и замените «Джонс» на «Джеймс», как показано здесь:

    ```bash
    $ sed -i.backup s/Jones/James/ names.csv
    $ md5sum names.csv
    f44a0d68cb480466099021bf6d6d2e65  names.csv
    ```

    Всякий раз, когда вы делаете файлы доступными для скачивания, хорошей практикой будет также распространять _дайджест сообщения_, чтобы люди, которые скачивают ваш файл, могли создать новый _дайджест сообщения_ и сравнить его с оригиналом. Если вы перейдете по ссылке [https://kernel.org](https://kernel.org/), то найдете страницу [https://mirrors.edge.kernel.org/pub/linux/kernel/v5.x/sha256sums.asc](https://mirrors.edge.kernel.org/pub/linux/kernel/v5.x/sha256sums.asc), где вы можете получить sha256sum для всех файлов, доступных для скачивания.
5.  Вы пообещали себе, что будете читать классическую книгу по 100 строк в день, и решили начать с _«Моби Дика»_ Германа Мелвилла. Разработайте команду с помощью `split`, которая разделит эту книгу на части по 100 строк в каждой. Чтобы получить книгу в формате обычного текста, найдите её на [https://www.gutenberg.org](https://www.gutenberg.org/).

    Сначала мы загрузим всю книгу с сайта Project Gutenberg, где вы можете найти эту и другие книги, находящиеся в общественном достоянии.

    <pre class="language-bash"><code class="lang-bash"><strong>$ wget https://www.gutenberg.org/files/50461/50461-0.txt
    </strong></code></pre>

    Возможно, вам потребуется установить `wget`, если он ещё не установлен в вашей системе. В качестве альтернативы вы также можете использовать `curl`. Используйте `less` для проверки книги:

    ```
    $ less 50461-0.txt
    ```

    Теперь мы разделим книгу на части по 100 строк в каждой:

    ```
    $ split -l 100 -d 50461-0.txt melville
    ```

    `50461-0.txt` Это файл, который мы будем разделять. `melville` будет префиксом для разделённых файлов. Параметр `-l 100` указывает количество строк, а опция `-d` указывает `split` на нумерацию файлов (с использованием заданного суффикса). Вы можете использовать `nl` для любого из разделённых файлов (возможно, кроме последнего) и убедиться, что в каждом из них по 100 строк.
6.  Если вы используете `ls -l` для каталога `/etc`, какой список вы получите? Если вы используете команду `cut` для вывода команды `ls` и хотите отобразить только имена файлов, как вы это сделаете? А как насчёт имени файла и владельца файлов? Наряду с командами `ls -l` и `cut` используйте команду `tr` для _объединения_ нескольких пробелов в один, чтобы упростить форматирование вывода с помощью команды `cut`

    Команда `ls` сама по себе выдаст только имена файлов. Однако мы можем подготовить вывод `ls -l` (длинный список) для получения более конкретной информации.

    ```bash
    $ ls -l /etc | tr -s ' ' ,
    drwxr-xr-x,3,root,root,4096,out,24,16:58,acpi
    -rw-r--r--,1,root,root,3028,dez,17,2018,adduser.conf
    -rw-r--r--,1,root,root,10,out,2,17:38,adjtime
    drwxr-xr-x,2,root,root,12288,out,31,09:40,alternatives
    -rw-r--r--,1,root,root,401,mai,29,2017,anacrontab
    -rw-r--r--,1,root,root,433,out,1,2017,apg.conf
    drwxr-xr-x,6,root,root,4096,dez,17,2018,apm
    drwxr-xr-x,3,root,root,4096,out,24,16:58,apparmor
    drwxr-xr-x,9,root,root,4096,nov,6,20:20,apparmor.d
    ```

    Параметр `-s` указывает `tr` на то, что повторяющиеся пробелы нужно заменить одним пробелом. Команда `tr` работает с любым повторяющимся символом, который вы указываете. Затем мы заменяем пробелы запятой `,`. На самом деле в нашем примере нам не нужно заменять пробелы, поэтому мы просто опустим `,`.

    ```bash
    $ ls -l /etc | tr -s ' '
    drwxr-xr-x 3 root root 4096 out 24 16:58 acpi
    -rw-r--r-- 1 root root 3028 dez 17 2018 adduser.conf
    -rw-r--r-- 1 root root 10 out 2 17:38 adjtime
    drwxr-xr-x 2 root root 12288 out 31 09:40 alternatives
    -rw-r--r-- 1 root root 401 mai 29 2017 anacrontab
    -rw-r--r-- 1 root root 433 out 1 2017 apg.conf
    drwxr-xr-x 6 root root 4096 dez 17 2018 apm
    drwxr-xr-x 3 root root 4096 out 24 16:58 apparmor
    ```

    Если мне нужны только имена файлов, то всё, что нам нужно отобразить, — это девятое поле:

    ```bash
    $ ls -l /etc | tr -s ' ' | cut -d" " -f9
    ```

    Для имени файла и владельца файла нам понадобятся девятое и третье поля:

    ```bash
    $ ls -l /etc | tr -s ' ' | cut -d" " -f9,3
    ```

    Что, если нам нужны только названия папок и их владелец?

    ```bash
    $ ls -l /etc | grep ^d | tr -s ' ' | cut -d" " -f9,3
    ```
7.  В этом упражнении предполагается, что вы работаете на реальном компьютере (а не на виртуальной машине). У вас также должна быть с собой USB-флешка. Ознакомьтесь со страницами руководства по команде `tail` и узнайте, как отслеживать добавление текста в файл. Наблюдая за выводом команды `tail` в файле `/var/log/syslog`, вставьте USB-флешку. Запишите полную команду, которую вы бы использовали, чтобы узнать название продукта, производителя и общий объём памяти вашей USB-флешки.

    ```bash
    Nov  8 06:01:35 brod-avell kernel: [124954.369364] usb 1-4.3: Manufacturer: SanDisk
    ```
