# Урок 5.2.1.

## Введение <a href="#sec.105.2_01-in" id="sec.105.2_01-in"></a>

Среда оболочки Linux позволяет использовать файлы, называемые скриптами, которые содержат команды из любой доступной в системе программы в сочетании со встроенными командами оболочки для автоматизации пользовательских и/или системных задач. Действительно, многие задачи по обслуживанию операционной системы выполняются с помощью скриптов, состоящих из последовательностей команд, структур принятия решений и условных циклов. Хотя сценарии в большинстве случаев предназначены для задач, связанных с самой операционной системой, они также полезны для пользовательских задач, таких как массовое переименование файлов, сбор и анализ данных или любые другие повторяющиеся действия в командной строке.

Скрипты — это не что иное, как текстовые файлы, которые ведут себя как программы. Реальная программа — интерпретатор — считывает и выполняет инструкции, перечисленные в файле скрипта. Интерпретатор также может запустить интерактивный сеанс, в котором команды, в том числе скрипты, считываются и выполняются по мере ввода, как в случае с сеансами командной оболочки Linux. Файлы скриптов могут объединять эти инструкции и команды, если они становятся слишком сложными для реализации в виде псевдонима или пользовательской функции оболочки. Кроме того, файлы сценариев можно поддерживать, как обычные программы, и, поскольку это просто текстовые файлы, их можно создавать и изменять с помощью любого простого текстового редактора.

## Структура и выполнение скрипта <a href="#sec.105.2_01-sse" id="sec.105.2_01-sse"></a>

По сути, файл скрипта — это упорядоченная последовательность команд, которые должны быть выполнены соответствующим интерпретатором команд. Интерпретатор по-разному считывает файл сценария, и в сеансе оболочки Bash есть несколько способов сделать это, но интерпретатор по умолчанию для файла скрипта будет указан в первой строке скрипта сразу после символов `#!` (известных как _шебанг_). В скрипте с инструкциями для оболочки Bash первая строка должна быть `#!/bin/bash`. Если указать эту строку, интерпретатором для всех инструкций в файле будет `/bin/bash`. За исключением первой строки, все остальные строки, начинающиеся с символа решётки `#`, будут игнорироваться, поэтому их можно использовать для размещения напоминаний и комментариев. Пустые строки также игнорируются. Таким образом, очень краткий файл сценария оболочки можно записать следующим образом:

```bash
#!/bin/bash

# A very simple script

echo "Cheers from the script file! Current time is: "

date +%H:%M
```

В этом скрипте есть только две инструкции для интерпретатора `/bin/bash`: встроенная команда `echo` и команда `date`. Самый простой способ запустить файл скрипта — выполнить интерпретатор с путём к скрипту в качестве аргумента. Таким образом, если предположить, что предыдущий пример был сохранён в файле скрипта с именем `script.sh` в текущем каталоге, он будет прочитан и интерпретирован Bash с помощью следующей команды:

```bash
$ bash script.sh
Cheers from the script file! Current time is:
10:57
```

Команда `echo` автоматически добавит новую строку после вывода содержимого, но опция `-n` подавит это поведение. Таким образом, использование `echo -n` в скрипте приведёт к тому, что вывод обеих команд будет отображаться в одной строке:

```bash
$ bash script.sh
Cheers from the script file! Current time is: 10:57
```

Хотя это и необязательно, суффикс `.sh` помогает идентифицировать сценарии оболочки при перечислении и поиске файлов.

{% hint style="info" %}
Bash вызовет любую команду, указанную после `#!` в качестве интерпретатора для файла сценария. Это может быть полезно, например, для использования шебанга в других языках сценариев, таких как _Python_ (`#!/usr/bin/python`), _Perl_ (`#!/usr/bin/perl`) или _awk_ (`#!/usr/bin/awk`).
{% endhint %}

Если файл сценария предназначен для выполнения другими пользователями системы, важно проверить, установлены ли правильные разрешения на чтение. Команда `chmod o+r script.sh` предоставит разрешение на чтение всем пользователям системы, что позволит им выполнять `script.sh` с указанием пути к файлу сценария в качестве аргумента команды `bash`. Кроме того, для файла сценария может быть установлено разрешение на выполнение, чтобы его можно было выполнять как обычную команду. Разрешение на выполнение для файла сценария активируется командой `chmod`:

```bash
$ chmod +x script.sh 
```

Если установлен бит выполнения, файл сценария с именем `script.sh` в текущем каталоге можно выполнить напрямую с помощью команды `./script.sh`. Сценарии, размещённые в каталоге, указанном в переменной среды `PATH`, также будут доступны без указания полного пути.

{% hint style="info" %}
У скрипта, выполняющего ограниченные действия, может быть активировано разрешение SUID, поэтому обычные пользователи также могут запускать скрипт с правами суперпользователя. В этом случае очень важно убедиться, что ни один пользователь, кроме суперпользователя, не имеет права на запись в файл. В противном случае обычный пользователь может изменить файл для выполнения произвольных и потенциально опасных операций.
{% endhint %}

Расположение и отступы команд в файлах сценариев не являются слишком строгими. Каждая строка в сценарии оболочки будет выполняться как обычная команда оболочки в той же последовательности, в которой она появляется в файле сценария, и те же правила, которые применяются к командной строке, применяются и к каждой строке сценария в отдельности. Можно разместить две или более команд в одной строке, разделив их точкой с запятой:

```bash
echo "Cheers from the script file! Current time is:" ; date +%H:%M
```

Хотя этот формат может быть удобен в некоторых случаях, его использование необязательно, так как последовательные команды можно размещать по одной в строке, и они будут выполняться так же, как если бы они были разделены точкой с запятой. Другими словами, точка с запятой может быть заменена символом новой строки в файлах сценариев Bash.

При выполнении скрипта содержащиеся в нём команды не выполняются непосредственно в текущем сеансе, а запускаются новым процессом Bash, называемым _под-оболочкой_. Это предотвращает перезапись скриптом переменных среды текущего сеанса и оставление изменений в текущем сеансе без внимания. Если цель состоит в том, чтобы запустить содержимое скрипта в текущем сеансе оболочки, то его следует выполнять с помощью `source script.sh` или `. script.sh` (обратите внимание, что между точкой и названием скрипта есть пробел).

Как и в случае с выполнением любой другой команды, приглашение оболочки будет доступно только после завершения выполнения скрипта, а код состояния выхода будет доступен в переменной `$?` . Чтобы изменить это поведение и завершить текущую оболочку после завершения скрипта, перед скриптом или любой другой командой можно указать команду `exec` . Эта команда также заменит код состояния выхода текущей оболочки на свой собственный.

## Переменные <a href="#sec.105.2_01-var" id="sec.105.2_01-var"></a>

Переменные в скриптах оболочки ведут себя так же, как в интерактивных сеансах, при условии, что интерпретатор тот же. Например, формат `SOLUTION=42` (без пробелов вокруг знака равенства) присвоит значение `42` переменной с именем `SOLUTION`. По соглашению, для имён переменных используются заглавные буквы, но это необязательно. Однако имена переменных не могут начинаться с неалфавитных символов.

Помимо обычных переменных, создаваемых пользователем, в сценариях Bash также есть набор специальных переменных, называемых _параметрами_. В отличие от обычных переменных, имена параметров начинаются с небуквенного символа, обозначающего их функцию. Аргументы, передаваемые скрипту, и другая полезная информация хранятся в таких параметрах, как `$0`, `$*`, `$?` и т. д., где символ после знака доллара указывает на извлекаемую информацию:

`$*`

Все аргументы переданые скрипту.

`$@`

Все аргументы, передаваемые скрипту. При использовании с двойными кавычками, как в `"$@"`, каждый аргумент будет заключен в двойные кавычки.

`$#`

Количество аргументов.

`$0`

Имя файла скрипта.

`$!`

PID последней выполненной программы.

`$$`

PID текущей оболочки.

`$?`

Числовой код состояния завершения последней выполненной команды. Для стандартных процессов POSIX числовое значение `0` означает, что последняя команда была успешно выполнена, что также относится к сценариям оболочки.

_Позиционный параметр_ — это параметр, обозначаемый одной или несколькими цифрами, кроме цифры `0`. Например, переменная `$1` соответствует первому аргументу, переданному скрипту (позиционный параметр один), `$2` соответствует второму аргументу и так далее. Если позиция параметра больше девяти, его необходимо указывать в фигурных скобках, например `${10}`, `${11}`, и т. д.

Обычные переменные, с другой стороны, предназначены для хранения значений, введённых вручную, или результатов, сгенерированных другими командами. Например, команда `read` может использоваться внутри скрипта для запроса ввода данных пользователем во время выполнения скрипта:

```bash
echo "Do you want to continue (y/n)?"
read ANSWER
```

Возвращаемое значение будет сохранено в переменной `ANSWER` . Если имя переменной не указано, по умолчанию будет использоваться имя переменной `REPLY` . Также можно использовать команду `read` для одновременного чтения нескольких переменных:

```bash
echo "Type your first name and last name:"
read NAME SURNAME
```

В этом случае каждый разделённый пробелами элемент будет присвоен переменным `NAME` и `SURNAME` соответственно. Если количество заданных элементов превышает количество переменных, лишние элементы будут сохранены в последней переменной. `read` сама по себе может отображать сообщение для пользователя с помощью опции `-p`, что делает команду `echo` в этом случае ненужной:

```bash
read -p "Type your first name and last name:" NAME SURNAME
```

Скрипты, выполняющие системные задачи, часто нуждаются в информации, предоставляемой другими программами. Для сохранения вывода команды в переменной можно использовать _обратный апостроф (_\`)

```bash
$ OS=`uname -o`
```

В этом примере вывод команды `uname -o` будет сохранён в переменной `OS` . Аналогичный результат будет получен с помощью `$()`:

```bash
$ OS=$(uname -o)
```

Длина переменной, то есть количество содержащихся в ней символов, возвращается при добавлении хэш-тега `#` перед именем переменной. Однако для использования этой функции необходимо указать переменную с помощью фигурных скобок:

```bash
$ OS=$(uname -o)
$ echo $OS
GNU/Linux
$ echo ${#OS}
9
```

В Bash также есть одномерные массивы, поэтому набор связанных элементов можно хранить под одним именем переменной. Каждый элемент массива имеет числовой индекс, который необходимо использовать для записи и чтения значений в соответствующем элементе. В отличие от обычных переменных, массивы необходимо объявлять с помощью встроенной команды Bash `declare`. Например, чтобы объявить переменную с именем `SIZES` в виде массива:

```bash
$ declare -a SIZES
```

Массивы также могут быть объявлены неявно при заполнении из предопределённого списка элементов с помощью скобок:

```bash
$ SIZES=( 1048576 1073741824 )
```

В этом примере два больших целых числа были сохранены в массиве `SIZES` . На элементы массива необходимо ссылаться с помощью фигурных скобок и квадратных скобок, иначе Bash не сможет правильно изменить или отобразить элемент. Поскольку индексы массива начинаются с 0, содержимое первого элемента находится в `${SIZES[0]}`, второго элемента — в `${SIZES[1]}` и так далее:

```bash
$ echo ${SIZES[0]}
1048576
$ echo ${SIZES[1]}
1073741824
```

В отличие от чтения, изменение содержимого элемента массива выполняется без фигурных скобок (например, `SIZES[0]=1048576`). Как и в случае с обычными переменными, длина элемента массива возвращается с помощью символа решётки (например, `${#SIZES[0]}` для длины первого элемента в массиве `SIZES`). Общее количество элементов в массиве возвращается, если в качестве индекса используется `@` или `*`:

```bash
$ echo ${#SIZES[@]}
2
$ echo ${#SIZES[*]}
2
```

В отличие от чтения, изменение содержимого элемента массива выполняется без фигурных скобок (например, `SIZES[0]=1048576`). Как и в случае с обычными переменными, длина элемента массива возвращается с помощью символа решётки (например, `${#SIZES[0]}` для длины первого элемента в массиве `SIZES`). Общее количество элементов в массиве возвращается, если в качестве индекса используется `@` или `*`:

```bash
$ echo ${#SIZES[@]}
2
$ echo ${#SIZES[*]}
2
```

Массивы также можно объявлять, используя вывод команды в качестве начальных элементов с помощью подстановки команд. В следующем примере показано, как создать массив Bash, элементами которого являются поддерживаемые файловые системы текущей системы:

```bash
$ FS=( $(cut -f 2 < /proc/filesystems) )
```

Команда `cut -f 2 < /proc/filesystems` отобразит все файловые системы, поддерживаемые работающим ядром (перечислены во втором столбце файла `/proc/filesystems`), поэтому массив `FS` теперь содержит по одному элементу для каждой поддерживаемой файловой системы. Для инициализации массива можно использовать любое текстовое содержимое, так как по умолчанию любые термины, разделённые символами _пробела_, _табуляции_ или _новой строки_, станут элементами массива.

{% hint style="info" %}
Bash рассматривает каждый символ переменной среды `$IFS` (_разделитель полей ввода_) как разделитель. Чтобы изменить разделитель полей на символы новой строки, например, необходимо сбросить переменную IFS с помощью команды `IFS=$'\n'`.
{% endhint %}

## Арифметические выражения <a href="#sec.105.2_01-ae" id="sec.105.2_01-ae"></a>

Bash предоставляет практичный способ выполнения целочисленных арифметических операций с помощью встроенной команды `expr`. Например, две числовые переменные `$VAL1` и `$VAL2` можно сложить с помощью следующей команды:

```bash
$ SUM=`expr $VAL1 + $VAL2`
```

Результат примера будет доступен в переменной `$SUM`. Команду `expr` можно заменить на `$(())`, поэтому предыдущий пример можно переписать как `SUM=$(( $VAL1 + $VAL2 ))`. Выражения со степенями также допустимы с оператором двойных звёздочек, поэтому предыдущее объявление массива `SIZES=( 1048576 1073741824)` можно переписать как `SIZES=( $((1024**2)) $((1024**3)) )`.

Подстановку команд также можно использовать в арифметических выражениях. Например, файл `/proc/meminfo` содержит подробную информацию о системной памяти, включая количество свободных байт в оперативной памяти:

```bash
$ FREE=$(( 1000 * `sed -nre '2s/[^[:digit:]]//gp' < /proc/meminfo` ))
```

В этом примере показано, как с помощью команды `sed` можно проанализировать содержимое `/proc/meminfo` внутри арифметического выражения. Вторая строка файла `/proc/meminfo` содержит объём свободной памяти в тысячах байт, поэтому арифметическое выражение умножает его на 1000, чтобы получить количество свободных байт в оперативной памяти.

## Условные выражения <a href="#sec.105.2_01-ce" id="sec.105.2_01-ce"></a>

Некоторые сценарии обычно предназначены не для выполнения всех команд в файле сценария, а только тех команд, которые соответствуют заранее заданным критериям. Например, сценарий обслуживания может отправлять предупреждающее сообщение на электронную почту администратора только в том случае, если выполнение команды не удалось. Bash предоставляет специальные методы оценки успешности выполнения команд и общие условные структуры, более похожие на те, что используются в популярных языках программирования.

Если разделить команды с помощью `&&`, то команда справа будет выполнена только в том случае, если команда слева не вызвала ошибку, то есть если её статус выхода равен `0`:

```bash
COMMAND A && COMMAND B && COMMAND C
```

Если команды разделены `||`. , то происходит обратное. В этом случае следующая команда будет выполнена только в том случае, если предыдущая команда обнаружила ошибку, то есть если её возвращаемый код состояния отличается от 0.

Одной из важнейших особенностей всех языков программирования является возможность выполнять команды в зависимости от ранее определённых условий. Самый простой способ условно выполнять команды — использовать встроенную команду Bash `if`, которая выполняет одну или несколько команд только в том случае, если команда, указанная в качестве аргумента, возвращает код состояния 0 (успех). Другую команду, `test`, можно использовать для оценки множества различных специальных критериев, поэтому она чаще всего используется в сочетании с `if`. В следующем примере сообщение `Confirmed: /bin/bash is executable.` будет отображаться, если файл `/bin/bash` существует и является исполняемым:

```bash
if test -x /bin/bash ; then
  echo "Confirmed: /bin/bash is executable."
fi
```

Опция `-x` заставляет команду `test` возвращать код состояния 0 только в том случае, если указанный путь является исполняемым файлом. В следующем примере показан другой способ добиться того же результата, поскольку квадратные скобки можно использовать вместо `test`:

```bash
if [ -x /bin/bash ] ; then
  echo "Confirmed: /bin/bash is executable."
fi
```

Инструкция `else` необязательна для структуры `if` и может, если присутствует, определять команду или последовательность команд, которые будут выполняться, если условное выражение не является истинным:

```bash
if [ -x /bin/bash ] ; then
  echo "Confirmed: /bin/bash is executable."
else
  echo "No, /bin/bash is not executable."
fi
```

`if` Структуры всегда должны заканчиваться на `fi`, чтобы интерпретатор Bash знал, где заканчиваются условные команды.

## Вывод скрипта

Даже если скрипт предназначен только для работы с файлами, важно выводить сообщения о ходе выполнения на стандартный вывод, чтобы пользователь был в курсе любых проблем и мог использовать эти сообщения для создания журналов операций.

Встроенная команда Bash `echo` обычно используется для отображения простых текстовых строк, но она также предоставляет некоторые расширенные функции. С опцией `-e` команда `echo` может отображать специальные символы с помощью экранированных последовательностей (последовательность обратной косой черты, обозначающая специальный символ). Например:\


```bash
#!/bin/bash

# Get the operating system's generic name
OS=$(uname -o)

# Get the amount of free memory in bytes
FREE=$(( 1000 * `sed -nre '2s/[^[:digit:]]//gp' < /proc/meminfo` ))

echo -e "Operating system:\t$OS"
echo -e "Unallocated RAM:\t$(( $FREE / 1024**2 )) MB"
```

Хотя при использовании `echo` без параметров кавычки необязательны, их необходимо добавлять при использовании параметра `-e`, иначе специальные символы могут отображаться некорректно. В предыдущем скрипте обе команды `echo` используют символ табуляции  для выравнивания текста, в результате чего получается следующий вывод:

```bash
Operating system:       GNU/Linux
Unallocated RAM:        1491 MB
```

Символ новой строки  можно использовать для разделения строк вывода, поэтому при объединении двух команд `echo` в одну получается тот же результат:

```bash
echo -e "Operating system:\t$OS\nUnallocated RAM:\t$(( $FREE / 1024**2 )) MB"
```

Хотя команда `echo` подходит для отображения большинства текстовых сообщений, она может не подходить для отображения более сложных текстовых шаблонов. Встроенная команда `printf` в Bash позволяет лучше контролировать отображение переменных. Команда `printf` использует первый аргумент в качестве формата вывода, где заполнители будут заменены следующими аргументами в том порядке, в котором они указаны в командной строке. Например, сообщение из предыдущего примера можно сгенерировать с помощью следующей команды `printf`:

```bash
printf "Operating system:\t%s\nUnallocated RAM:\t%d MB\n" $OS $(( $FREE / 1024**2 ))
```

Заполнитель `%s` предназначен для текстового содержимого (он будет заменён на переменную `$OS`), а заполнитель `%d` предназначен для целых чисел (он будет заменён на полученное количество свободных мегабайт в оперативной памяти). `printf` не добавляет символ новой строки в конце текста, поэтому символ новой строки  при необходимости следует поместить в конец шаблона. Весь шаблон должен интерпретироваться как один аргумент, поэтому его необходимо заключить в кавычки.

{% hint style="info" %}
Формат подстановки заполнителей, выполняемой с помощью `printf`, можно настроить, используя тот же формат, что и функция `printf` в языке программирования C. Полное описание функции `printf` можно найти в справочной странице, доступ к которой осуществляется с помощью команды `man 3 printf`.
{% endhint %}

С помощью `printf` переменные размещаются за пределами текстового шаблона, что позволяет хранить текстовый шаблон в отдельной переменной:

```bash
MSG='Operating system:\t%s\nUnallocated RAM:\t%d MB\n'
printf "$MSG" $OS $(( $FREE / 1024**2 ))
```

Этот метод особенно полезен для отображения различных форматов вывода в зависимости от требований пользователя. Например, он упрощает написание сценария, в котором используется отдельный шаблон текста, если пользователю нужен список CSV (_значения, разделённые запятыми_), а не стандартное сообщение об ошибке.

* Массивы Bash
* Простые тесты и условное выполнение
* Форматирование выходных данных

Были рассмотрены следующие команды и процедуры:

### Ответы на Упражнения с Руководством <a href="#sec.105.2_01-age" id="sec.105.2_01-age"></a>

1.  Опция `-s` для команды `read` полезна при вводе паролей, так как она не отображает вводимый текст на экране. Как можно использовать команду `read` для сохранения вводимых пользователем данных в переменной `PASSWORD` и при этом скрыть вводимый текст?

    `read -s PASSWORD`
2.  Единственная цель команды `whoami` — отобразить имя пользователя, который её вызвал, поэтому она в основном используется в скриптах для идентификации пользователя, который их запускает. Как в скрипте Bash можно сохранить вывод команды `whoami` в переменной с именем `WHO`?

    `` WHO=`whoami` `` или `WHO=$(whoami)`
3.  Какой оператор Bash должен стоять между командами `apt-get dist-upgrade` и `systemctl reboot` в случае, если пользователь с правами root хочет выполнить `systemctl reboot` только в том случае, если `apt-get dist-upgrade` завершится успешно?

    Оператор `&&`, как в `apt-get dist-upgrade && systemctl reboot`.

Напишите конструкцию _if_, которая будет выполнять вышеупомянутую команду `mail` в случае, если предыдущая команда — какой бы она ни была — завершилась неудачно.

    `if [ "$?" -ne 0 ]; then mail -s "Maintenance Error" root <<<"Scheduled task error"; fi`
