# Урок 5.1.3.

## Введение <a href="#sec.105.1_03-in" id="sec.105.1_03-in"></a>

После изучения оболочек, сценариев запуска и переменных в предыдущих уроках мы завершим тему настройки оболочки, рассмотрев два очень интересных элемента оболочки: _псевдонимы_ и _функции_. По сути, вся группа переменных, псевдонимов и функций — и их влияние друг на друга — составляет среду оболочки.

Основное преимущество этих двух гибких и экономящих время средств командной оболочки связано с концепцией инкапсуляции: они позволяют объединять в одну команду несколько повторяющихся или циклических команд.

## Создание псевдонимов <a href="#creating_aliases" id="creating_aliases"></a>

Псевдоним — это альтернативное имя для другой команды (или команд). Он может работать как обычная команда, но вместо этого выполняет другую команду в соответствии с определением псевдонима.

Синтаксис для объявления псевдонимов довольно прост. Псевдонимы объявляются с помощью ключевого слова `alias` и последующего присвоения псевдонима. В свою очередь, присвоение псевдонима состоит из _имени псевдонима_, _знака равенства_ и одной или нескольких _команд_:

```bash
alias alias_name=command(s)
```

Например:

```bash
$ alias oldshell=sh
```

Этот неудобный псевдоним запустит экземпляр исходной оболочки `sh` при вводе пользователем `oldshell` в терминале:

```bash
$ oldshell
$
```

Преимущество псевдонимов в том, что они позволяют нам писать короткие версии длинных команд:

```
$ alias ls='ls --color=auto'
```

{% hint style="info" %}
Для получения информации о `ls` и его цветах введите `man dir_colors` в терминале.
{% endhint %}

Аналогичным образом мы можем создавать псевдонимы для последовательности объединённых команд — точка с запятой (`;`) используется в качестве разделителя. Например, мы можем создать псевдоним, который выдаст нам информацию о расположении исполняемого файла `git` и его версии:

```
$ alias git_info='which git;git --version'
```

Чтобы вызвать псевдоним, мы вводим его имя в терминал:

```bash
$ git_info
/usr/bin/git
версия git 2.7.4
```

Команда `alias` создаст список всех доступных псевдонимов в системе:

```bash
$ alias
alias git-info='which git;git --version'
alias ls='ls --color=auto'
alias oldshell='sh'
```

Команда `unalias` удаляет псевдонимы. Например, мы можем ввести `unalias git-info` и посмотреть, как он исчезнет из списка:

```bash
$ unalias git-info
$ alias
alias ls='ls --color=auto'
alias oldshell='sh'
```

Как мы видели в предыдущем уроке, когда мы использовали `alias hi='echo We salute you.'` для обозначения команд, мы должны заключать команды в кавычки (одинарные или двойные), если они содержат пробелы из-за аргументов или параметров:

```bash
$ alias greet='echo Hello world!'
$ greet
Hello world!
```

Команды с пробелами включают также команды с параметрами:

```bash
$ alias ll='ls -al'
```

Теперь `ll` выведет список всех файлов, включая скрытые (`a`), в длинном формате (`l`).

Мы можем ссылаться на переменные в псевдонимах:

```bash
$ reptile=uromastyx
$ alias greet='echo Hello $reptile!'
$ greet
Hello uromastyx!
```

Переменная также может быть присвоена в рамках псевдонима:

```bash
$ alias greet='reptile=tortoise; echo Hello $reptile!'
$ greet
Hello tortoise!
```

Мы можем избежать псевдонима с помощью `\`:

```bash
$ alias where?='echo $PWD'
$ where?
/home/user2
$ \where?
-bash: where?: command not found
```

Использование псевдонима полезно, когда псевдоним имеет то же имя, что и обычная команда. В этом случае псевдоним имеет приоритет над исходной командой, которая, однако, по-прежнему доступна при использовании псевдонима.

Аналогично, мы можем поместить псевдоним внутрь другого псевдонима:

```bash
$ where?
/home/user2
$ alias my_home=where?
$ my_home
/home/user2
```

Кроме того, мы можем поместить функцию в псевдоним, как показано ниже.

## **Расширение и оценка кавычек в псевдонимах**

При использовании кавычек с переменными среды одинарные кавычки делают расширение динамичным:

```bash
$ alias where?='echo $PWD'
$ where?
/home/user2
$ cd Music
$ where?
/home/user2/Music
```

Однако при использовании двойных кавычек расширение выполняется статически:

```bash
$ alias where?="echo $PWD"
$ where?
/home/user2
$ cd Music
$ where?
/home/user2
```

## **Сохранение псевдонимов: Сценарии запуска**

Как и в случае с переменными, чтобы наши псевдонимы сохранялись, мы должны поместить их в сценарии инициализации, которые запускаются при старте. Как мы уже знаем, хорошим файлом для размещения личных псевдонимов пользователей является `~/.bashrc`. Вероятно, вы уже найдёте там несколько псевдонимов (большинство из них закомментированы и готовы к использованию после удаления  `#`):

```bash
$ grep alias .bashrc
# enable color support of ls and also add handy aliases
    alias ls='ls --color=auto'
    #alias dir='dir --color=
    #alias vdir='vdir --color=
    #alias grep='grep --color=
    #alias fgrep='fgrep --color'
    #alias egrep='egrep --color=
# some more ls aliases
#ll='ls -al'
#alias la='ls -A'
#alias l='ls -CF'
# ~/.bash_aliases, instead of adding them here directly.
if [ -f ~/.bash_aliases ]; then
   . ~/.bash_aliases
```

Как вы можете видеть в последних трёх строках, нам предлагается создать собственный файл с псевдонимом — `~/.bash_aliases` — и использовать его с `.bashrc` при каждом запуске системы. Таким образом, мы можем выбрать этот вариант, создать и заполнить такой файл:

```bash
###########
# .bash_aliases:
# a file to be populated by the user's personal aliases (and sourced by ~/.bashrc).
###########
alias git_info='which git;git --version'
alias greet='echo Hello world!'
alias ll='ls -al'
alias where?='echo $PWD'
```

## Создание функций <a href="#creating_functions" id="creating_functions"></a>

По сравнению с псевдонимами, функции более программируемы и гибки, особенно когда речь идёт об использовании всего потенциала специальных встроенных переменных _Bash_ и позиционных параметров. Они также отлично подходят для работы со структурами управления потоком, такими как циклы или условные конструкции. Функцию можно рассматривать как команду, которая включает логику в виде блоков или наборов других команд.

## **Два синтаксиса для создания функций**

Существует два допустимых синтаксиса для определения функций.

Использование ключевого слова `function`

С одной стороны, мы можем использовать ключевое слово `function`, за которым следует имя функции и команды в фигурных скобках:

```bash
function function_name {
command #1
command #2
command #3
.
.
.
command #n
}
```

Используя `()`

С другой стороны, мы можем опустить ключевое слово `function` и вместо этого использовать две скобки сразу после названия функции:

```
function_name() {
command #1
command #2
command #3
.
.
.
command #n
}
```

Обычно функции помещают в файлы или скрипты. Однако их также можно вводить непосредственно в командную строку, размещая каждую команду в отдельной строке — обратите внимание, что `PS2`(`>`) указывает на новую строку после разрыва строки:

```bash
$ greet() {
> greeting="Hello world!"
> echo $greeting
> }
```

В любом случае — независимо от выбранного нами синтаксиса — если мы решим пропустить разрывы строк и написать функцию в одну строку, команды должны быть разделены точками с запятой (обратите внимание на точку с запятой после последней команды):

```bash
$ greet() { greeting="Привет, мир!"; echo $greeting; }
```

`bash` когда мы нажали Enter, программа не выдала ошибку, значит, наша функция готова к вызову. Чтобы вызваь функцию, мы должны ввести её название в терминал:

```bash
$ greet
Hello world!
```

Как и в случае с переменными и псевдонимами, если мы хотим, чтобы функции сохранялись при перезагрузке системы, мы должны поместить их в скрипты инициализации оболочки, такие как `/etc/bash.bashrc` (глобальные) или `~/.bashrc` (локальные).

{% hint style="info" %}
После добавления псевдонимов или функций в любой файл сценария запуска вам следует подключить такие файлы с помощью `.` или `source` для того, чтобы изменения вступили в силу, если вы не хотите выходить из системы и снова входить в неё или перезагружать систему.
{% endhint %}

## **Специальные встроенные переменные Bash**

_Bourne Again Shell_ поставляется с набором специальных переменных, которые особенно полезны для функций и скриптов. Они являются специальными, потому что на них можно только ссылаться, но не присваивать им значения. Вот список наиболее важных из них:

`$?`

Ссылка на эту переменную указывает на результат выполнения последней команды. Значение `0` означает успех:

```bash
$ ps aux | grep bash
user2 420 0,0 0,4 21156 5012 pts/0 Ss 17:10 0:00 -bash
user2 640 0,0 0,0 12784 936 pts/0 S+ 18:04 0:00 grep bash
$ echo $?
0
```

начение, отличное от `0` , означает ошибку:

```bash
user1@debian:~$ ps aux |rep bash
-bash: rep: command not found
user1@debian:~$ echo $?
127
```

`$$`

Расширяется до PID оболочки (идентификатора процесса).:

```bash
$ ps aux | grep bash
user2      420  0.0  0.4  21156  5012 pts/0    Ss   17:10   0:00 -bash
user2      640  0.0  0.0  12784   936 pts/0    S+   18:04   0:00 grep bash
$ echo $$
420
```

`$!`

Расширяется до PID последнего фонового задания:

```
$ ps aux | grep bash &
[1] 663
$ user2 420 0,0 0,4 21156 5012 pts/0 Ss+ 17:10 0:00 -bash
user2 663 0,0 0,0 12784 972 pts/0 S 18:08 0:00 grep bash
^C
[1]+ Готово ps aux | grep bash
$ echo $!
663
```

{% hint style="info" %}
Помните, что амперсанд (`&`) используется для запуска процессов в фоновом режиме.
{% endhint %}

Позиционные параметры `$0` - `$9`

Они заменяются параметрами или аргументами, передаваемыми функции (псевдониму или скрипту), — `$0` заменяется на имя скрипта или оболочки.

Давайте создадим функцию для демонстрации позиционных параметров — обратите внимание на `PS2` (`>`), обозначающие новые строки после разрывов строк:

```
$ special_vars() { > echo $0 > echo $1 > echo $2 > echo $3 }
```

Теперь мы вызовем функцию (`special_vars`) и передадим ей три параметра (`debian`, `ubuntu`, `zorin`):

```bash
$ special_vars debian ubuntu zorin
-bash
debian
ubuntu
zorin
```

Все сработало, как и ожидалось.

{% hint style="info" %}
Хотя технически возможно передавать позиционные параметры псевдонимам, это не совсем функционально, поскольку при использовании псевдонимов позиционные параметры всегда передаются в конце:

```bash
$ alias great_editor='echo $1 is a great text editor'
$ great_editor emacs
is a great text editor emacs
```
{% endhint %}

Другие специальные встроенные переменные Bash включают:

`$#`

Расширяется до количества аргументов, передаваемых команде.

`$@`, `$*`

Расширяются до аргументов, передаваемых команде.

`$_`

Расширяется до последнего параметра или имени скрипта (среди прочего; см. `man bash` для получения дополнительной информации!):

## **Переменные в функциях**

Конечно, переменные можно использовать внутри функций.

Чтобы доказать это, на этот раз мы создадим новый пустой файл с именем `funed` и поместим в него следующую функцию:

```
editors() {

editor=emacs

echo "My editor is: $editor. $editor is a fun text editor."
}
```

Как вы уже, наверное, догадались, сначала мы должны подключить файл, чтобы можно было вызвать функцию:

```bash
$ . funed
```

И теперь мы можем это проверить:

```bash
$ editors
My editor is emacs. emacs is a fun text editor.
```

Как вы можете заметить, для корректной работы функции `editors` необходимо сначала задать переменную `editor` . Область действия этой переменной ограничена текущей оболочкой, и мы можем ссылаться на неё, пока длится сеанс:

```bash
$ echo $editor
emacs
```

Вместе с локальными переменными мы также можем включить переменные окружения в нашу функцию:

```bash
editors() {

editor=emacs

echo "The text editor of $USER is: $editor."
}

editors
```

Обратите внимание, что на этот раз мы решили вызвать функцию из самого файла (`editors` в последней строке). Таким образом, когда мы запустим файл, функция также будет вызвана — сразу:

```bash
$ . funed
The text editor of user2 is: emacs.
```

## **Позиционные параметры в функциях**

Нечто подобное происходит и с позиционными параметрами.

Мы можем передавать их функциям из файла или скрипта (обратите внимание на последнюю строку: `editors tortoise`):

```bash
editors() {

editor=emacs

echo "The text editor of $USER is: $editor."
echo "Bash is not a $1 shell."
}

editors tortoise
```

Мы создаем исходный файл и доказываем, что он работает:

```bash
$ . funed
The text editor of user2 is: emacs.
Bash is not a tortoise shell.
```

А ещё мы можем передавать позиционные параметры функциям в командной строке. Чтобы это проверить, уберём последнюю строку файла:

```bash
editors() {

editor=emacs

echo "The text editor of $USER is: $editor."
echo "Bash is not a $1 shell."
}
```

Затем мы должны создать исходный файл:

```bash
$ . funed
```

Наконец, мы вызываем функцию с `tortoise` в качестве позиционного параметра `$1` в командной строке:

```bash
$ editors tortoise
The text editor of user2 is: emacs.
Bash is not a tortoise shell.
```

## **Функции в скриптах**

Функции в основном встречаются в скриптах Bash.

Превратить наш файл `funed` в скрипт (мы назовём его `funed.sh`) проще простого:

```bash
#!/bin/bash

editors() {

editor=emacs

echo "The text editor of $USER is: $editor."
echo "Bash is not a $1 shell."
}

editors tortoise
```

Вот и все! Мы добавили только две строки:

* Первая строка — это _шебанг_, который определяет, какая программа будет интерпретировать скрипт: `#!/bin/bash`. Как ни странно, этой программой является `bash` сама по себе.
* Последняя строка - это просто вызов функции.

Теперь осталось только одно — сделать скрипт исполняемым:

```bash
$ chmod +x funed.sh
```

И теперь оно готово к исполнению:

```bash
$ ./funed.sh
The text editor of user2 is: emacs.
Bash is not a tortoise shell.
```

{% hint style="info" %}
Вы узнаете все о _сценариях командной оболочки_ в следующих нескольких уроках.
{% endhint %}

## **Функция внутри псевдонима**

Как было сказано выше, мы можем поместить функцию внутрь псевдонима:

```bash
$ alias great_editor='gr8_ed() { echo $1 is a great text editor; unset -f gr8_ed; }; gr8_ed'
```

Это длинное значение псевдонима заслуживает объяснения. Давайте разберем его:

* Во-первых, это сама функция: `gr8_ed() { echo $1 is a great text editor; unset -f gr8_ed; }`
* Последняя команда в функции — `unset -f gr8_ed` — отменяет функцию, чтобы она не оставалась в текущем сеансе `bash` после вызова псевдонима.
* И последнее, но не менее важное: чтобы успешно вызвать псевдоним, мы должны сначала вызвать функцию: `gr8_ed`.

Давайте вызовем псевдоним и докажем, что он работает:

```bash
$ great_editor emacs
emacs is a great text editor
```

Как показано в `unset -f gr8_ed` выше, команда `unset` используется не только для удаления переменных, но и для удаления функций. На самом деле существуют специальные переключатели или параметры:

`unset -v`

для переменных

`unset -f`

для функций

Если используется без переключателей, `unset` сначала попытается удалить переменную, а если не получится, то попытается удалить функцию.

## **Функция внутри функции**

Теперь предположим, что мы хотим сообщать `user2` две вещи каждый раз, когда она входит в систему:

* Поздоровайтесь и порекомендуйте / похвалите текстовый редактор.
* Поскольку она начинает сохранять множество `Matroska` видеофайлов в своей `$HOME/Video` папке, мы также хотим предупредить её.

Для достижения этой цели мы внедрили в `/home/user2/.bashrc` следующие две функции:

Первая функция (`check_vids`) выполняет проверку `.mkv` файлов и выдает предупреждение:

```bash
check_vids() {
    ls -1 ~/Video/*.mkv > /dev/null 2>&1
    if [ "$?" = "0" ];then
        echo -e "Remember, you must not keep more than 5 video files in your Video folder.\nThanks."
    else
	echo -e "You do not have any videos in the Video folder. You can keep up to 5.\nThanks."
    fi
}
```

`check_vids` делает три вещи:

* Он выводит список файлов `mkv` в `~/Video` и отправляет результаты — и любые ошибки — в так называемое _хранилище_ (`/dev/null`).
* Он проверяет вывод предыдущей команды на успешность.
* В зависимости от результата теста он выводит одно из двух сообщений.

Вторая функция - это модифицированная версия нашей `editors` функции:

```bash
editors() {

editor=emacs

echo "Hi, $USER!"
echo "$editor is more than a text editor!"

check_vids
}

editors
```

Важно соблюдать две вещи:

* Последняя команда `editors` вызывает `check_vids` так, что обе функции выполняются последовательно: приветствие, похвала, проверка и предупреждение.
* `editors` Сама по себе она является точкой входа в последовательность функций, поэтому вызывается в последней строке (`editors`).

Теперь давайте войдем в систему под именем `user2` и докажем, что это работает:

```bash
# su - user2
Hi, user2!
emacs is more than a text editor!
Remember, you must not keep more than 5 video files in your Video folder.
Thanks.
```

## Краткие сведения <a href="#sec.105.1_03-su" id="sec.105.1_03-su"></a>

На этом уроке вы усвоили:

* Псевдонимы, и функции — важные функции оболочки, которые позволяют инкапсулировать повторяющиеся блоки кода.
* Псевдонимы полезны для создания более коротких версий длинных и/или сложных команд.
* Функции — это процедуры, которые реализуют логику и позволяют автоматизировать задачи, особенно при использовании в скриптах.
* Синтаксис для написания псевдонимов и функций.
* Как объединить несколько команд с помощью точки с запятой (`;`).
* Как правильно использовать кавычки с псевдонимами.
* Как сделать псевдонимы и функции постоянными.
* Специальные встроенные переменные Bash: `$?`, `$$`, `$!`, позиционные параметры (`$0`-`$9`), `$#`, `$@`, `$*` и `$_`.
* Как использовать переменные и позиционные параметры с функциями.
* Как использовать функции в скриптах.
* Как вызвать функцию из псевдонима.
* Как вызвать функцию из другой функции.
* Основы создания `bash` скрипта.

Команды и ключевые слова, используемые в этом уроке:

`alias`

Создание псевдонимов.

`unalias`

Удаление псевдонимов.

`cd`

Изменить каталог.

`grep`

Вывести линии, соответствующие шаблону.

`function`

Ключевое слово Shell для создания функций.

`.`

Создайть исходный файл.

`source`

Создайть исходный файл.

`ps`

Создать отчет о моментальном снимке текущих процессов.

`echo`

Отобразить строку текста.

`chmod`

Изменить биты режима файла, например, сделайте его исполняемым.

`unset`

Сбросит настройки переменных и функций.

`su`

Изменить идентификатор пользователя или стать суперпользователем.
