# Урок 5.1.2.

## Введение <a href="#sec.105.1_02-in" id="sec.105.1_02-in"></a>

Представьте себе переменную как воображаемый контейнер, в который можно временно поместить фрагмент информации. Как и в случае со сценариями инициализации, Bash классифицирует переменные как _локальные/вложенные_ (те, которые существуют только в пределах оболочки, в которой они были созданы) или _глобальные/внешние_ (те, которые наследуются дочерними оболочками и/или процессами). На самом деле, в предыдущем уроке мы рассмотрели оболочки и сценарии их конфигурации или инициализации. Теперь уместно отметить, что сила этих файлов запуска заключается в том, что они позволяют нам использовать переменные, а также псевдонимы и функции, которые помогают нам создавать и настраивать среду оболочки по нашему усмотрению.

## Переменные: назначение и ссылка <a href="#variables_assignment_and_reference" id="variables_assignment_and_reference"></a>

Переменная может быть определена как имя, содержащее значение.

В Bash присвоение значения имени называется _присвоением переменной_, и именно так мы создаём или задаём переменные. С другой стороны, процесс доступа к значению, содержащемуся в имени, называется _ссылкой на переменную_.

Синтаксис для назначения переменных следующий:

```
<variable_name>=<variable_value>
```

Например:

```bash
$ distro=zorinos
```

Переменная `distro` равна `zorinos`, то есть в памяти есть участок, содержащий значение `zorinos` — `distro` является указателем на него.

Однако обратите внимание, что при присвоении переменной по обе стороны от знака равенства не должно быть пробелов:

```
$ distro =zorinos
-bash: distro: command not found
$ distro= zorinos
-bash: zorinos: command not found
```

Из-за нашей ошибки  `distro` и `zorinos`  читаются Bash как команды.

Чтобы сослаться на переменную (то есть проверить её значение), мы используем команду `echo` перед именем переменной со знаком `$`:

```bash
$ echo $distro
zorinos
```

## **Имена переменных**

При выборе имён переменных существуют определённые правила, которые мы должны учитывать.

Имя переменной может содержать буквы (`a-z`,`A-Z`), цифры (`0-9`) и знаки подчёркивания (`_`):\


```bash
$ distro=zorinos
$ echo $distro
zorinos
$ DISTRO=zorinos
$ echo $DISTRO
zorinos
$ distro_1=zorinos
$ echo $distro_1
zorinos
$ _distro=zorinos
$ echo $_distro
zorinos
```

Оно не может начинаться с цифры, иначе Bash запутается:

```bash
$ 1distro=zorinos
-bash: 1distro=zorinos: command not found
```

Он не может содержать пробелы (даже в кавычках); вместо них обычно используются подчёркивания:

```bash
$ "my distro"=zorinos
-bash: my: command not found
$ my_distro=zorinos
$ echo $my_distro
zorinos
```

## **Значения переменных**

Что касается ссылок или значений переменных, важно также учитывать ряд правил.

Переменные могут содержать любые буквенно-цифровые символы (`a-z`,`A-Z0-9`,`?`), а также большинство других символов (`?`,`!`,`*`,`./`,, etc.)

```bash
$ distro=zorin12.4?
$ echo $distro
zorin12.4?
```

Значения переменных должны быть заключены в кавычки, если они содержат одинарные пробелы:

```bash
$ distro=zorin 12.4
-bash: 12.4: command not found
$ distro="zorin 12.4"
$ echo $distro
zorin 12.4
$ distro='zorin 12.4'
$ echo $distro
zorin 12.4
```

Значения переменных также должны быть заключены в кавычки, если они содержат такие символы, как те, что используются для перенаправления (`<`,`>`) или символ канала (`|`). Следующая команда создаёт только пустой файл с именем `zorin`:

```bash
$ distro=>zorin
$ echo $distro

$ ls zorin
```

Однако это работает, когда мы используем кавычки:

```bash
$ distro=">zorin"
$ echo $distro
>zorin
```

Однако одинарные и двойные кавычки не всегда взаимозаменяемы. В зависимости от того, что мы делаем с переменной (присваиваем ей значение или ссылаемся на неё), использование тех или иных кавычек имеет значение и приводит к разным результатам. В контексте присвоения переменной одинарные кавычки принимают все символы значения переменной _буквально_, в то время как двойные кавычки позволяют заменять переменные:

```bash
$ lizard=uromastyx
$ animal='My $lizard'
$ echo $animal
My $lizard
$ animal="My $lizard"
$ echo $animal
My uromastyx
```

С другой стороны, при обращении к переменной, значение которой содержит несколько начальных (или дополнительных) пробелов — иногда в сочетании со звёздочками, — необходимо использовать двойные кавычки после команды `echo` во избежание _разделения полей_ и _расширения пути_:\


```bash
$ lizard="   genus   |   uromastyx"
$ echo $lizard
genus | uromastyx
$ echo "$lizard"
   genus   |   uromastyx
```

Если ссылка на переменную содержит закрывающий восклицательный знак, он должен быть последним символом в строке (иначе Bash подумает, что мы ссылаемся на событие `history`):

```bash
$ distro=zorin.?/!os
-bash: !os: event not found
$ distro=zorin.?/!
$ echo $distro
zorin.?/!
```

Все обратные косые черты должны быть экранированы другой обратной косой чертой. Кроме того, если обратная косая черта является последним символом в строке и мы не экранируем её, Bash интерпретирует это как разрыв строки и выдаст новую строку:

```bash
$ distro=zorinos\
>
$ distro=zorinos\\
$ echo $distro
zorinos\
```

В следующих двух разделах мы рассмотрим основные различия между _локальными_ и _системными_ переменными.

## Локальные переменные или переменные оболочки

Локальные или системные переменные существуют только в той оболочке, в которой они были созданы. По соглашению локальные переменные записываются строчными буквами.

Для проведения нескольких тестов давайте создадим локальную переменную. Как объяснялось выше, мы выбираем подходящее имя переменной и присваиваем ей соответствующее значение. Например:\


```bash
$ reptile=tortoise
```

Теперь давайте воспользуемся командой `echo` для обращения к нашей переменной и проверим, что всё прошло как ожидалось:

```bash
$ echo $reptile
tortoise
```

В некоторых случаях — например, при написании скриптов — неизменяемость может быть интересной особенностью переменных. Если мы хотим, чтобы наши переменные были неизменяемыми, мы можем либо создать их `readonly`:

```bash
$ readonly reptile=tortoise
```

Или сделайте их такими после того, как они были созданы:

```bash
$ reptile=tortoise
$ readonly reptile
```

Теперь, если мы попытаемся изменить значение `reptile`, Bash откажется:

```bash
$ reptile=lizard
-bash: distro: readonly variable

```

{% hint style="info" %}
Чтобы вывести список всех переменных, доступных только для чтения, в текущем сеансе, введите в терминал `readonly` или `readonly -p`
{% endhint %}

Полезной командой при работе с локальными переменными является `set`.

`set` выводит все переменные и функции оболочки, назначенные в данный момент. Поскольку это может быть много строк (попробуйте сами!), рекомендуется использовать его в сочетании с пейджером, таким как `less`:

```bash
$ set | less
BASH=/bin/bash
BASHOPTS=checkwinsize:cmdhist:complete_fullquote:expand_aliases:extglob:extquote:force_fignore:histappend:interactive_comments:login_shell:progcomp:promptvars:sourcepath
BASH_ALIASES=()
BASH_ARGC=()
BASH_ARGV=()
BASH_CMDS=()
BASH_COMPLETION_COMPAT_DIR=/etc/bash_completion.d
BASH_LINENO=()
BASH_SOURCE=()
BASH_VERSINFO=([0]="4" [1]="4" [2]="12" [3]="1" [4]="release" [5]="x86_64-pc-linux-gnu")
BASH_VERSION='4.4.12(1)-release'
(...)
```

Есть ли там наша `reptile` переменная?

```bash
$ set | grep reptile
reptile=tortoise
```

Да, вот она!

Однако `reptile` — будучи локальной переменной — не будет наследоваться дочерними процессами, запущенными из текущей оболочки:

```bash
$ bash
$ set | grep reptile
$
```

{% hint style="info" %}
Введя в терминал команду `bash` мы открываем новую (дочернюю) оболочку.
{% endhint %}

Чтобы удалить все переменные (локальные или глобальные), мы используем команду `unset`:

```bash
$ echo $reptile
tortoise
$ unset reptile
$ echo $reptile
$
```

{% hint style="info" %}
`unset` За ним должно следовать только имя переменной (без символа `$` перед ним).
{% endhint %}

## Глобальные переменные или переменные среды <a href="#global_or_environment_variables" id="global_or_environment_variables"></a>

Глобальные переменные или переменные среды существуют для текущей оболочки, а также дл

```bash
$ echo $SHELL
/bin/bash
```

Мы можем рекурсивно передавать значения этих переменных другим переменным, и значение последних в конечном итоге будет равно значению первых:

```
$ my_shell=$SHELL
$ echo $my_shell
/bin/bash
$ your_shell=$my_shell
$ echo $your_shell
/bin/bash
$ our_shell=$your_shell
$ echo $our_shell
/bin/bash
```

Чтобы локальная переменная оболочки стала переменной среды, необходимо использовать команду `export`:

```bash
$ export reptile
```

С помощью `export reptile` мы превратили нашу локальную переменную в переменную среды, чтобы дочерние оболочки могли распознавать и использовать её:

```bash
$ bash
$ echo $reptile
tortoise
```

Аналогичным образом `export` можно использовать для установки и экспорта переменной сразу:

```bash
$ export amphibian=frog
```

Теперь мы можем открыть новый экземпляр Bash и успешно сослаться на новую переменную:

```bash
$ bash
$ echo $amphibian
frog
```

{% hint style="info" %}
С помощью `export -n <VARIABLE-NAME>` переменная будет снова преобразована в локальную переменную оболочки.
{% endhint %}

Команда `export` также выдаст нам список всех существующих переменных среды, если ввести её саму по себе (или с опцией `-p`):

```bash
$ export
declare -x HOME="/home/user2"
declare -x LANG="en_GB.UTF-8"
declare -x LOGNAME="user2"
(...)
declare -x PATH="/usr/local/bin:/usr/bin:/bin:/usr/local/games:/usr/games"
declare -x PWD="/home/user2"
declare -x SHELL="/bin/bash"
declare -x SHLVL="1"
declare -x SSH_CLIENT="192.168.1.10 49330 22"
declare -x SSH_CONNECTION="192.168.1.10 49330 192.168.1.7 22"
declare -x SSH_TTY="/dev/pts/0"
declare -x TERM="xterm-256color"
declare -x USER="user2"
declare -x XDG_RUNTIME_DIR="/run/user/1001"
declare -x XDG_SESSION_ID="8"
declare -x reptile="tortoise"
```

{% hint style="info" %}
Команда `declare -x` эквивалентна `export`.
{% endhint %}

Ещё две команды, которые можно использовать для вывода списка всех переменных среды, — это `env` и `printenv`:

```bash
$ env
SSH_CONNECTION=192.168.1.10 48678 192.168.1.7 22
LANG=en_GB.UTF-8
XDG_SESSION_ID=3
USER=user2
PWD=/home/user2
HOME=/home/user2
SSH_CLIENT=192.168.1.10 48678 22
SSH_TTY=/dev/pts/0
MAIL=/var/mail/user2
TERM=xterm-256color
SHELL=/bin/bash
SHLVL=1
LOGNAME=user2
XDG_RUNTIME_DIR=/run/user/1001
PATH=/usr/local/bin:/usr/bin:/bin:/usr/local/games:/usr/games
_=/usr/bin/env
```

Помимо того, что это синоним `env`, иногда мы можем использовать `printenv` аналогично тому, как мы используем `echo` команду для проверки значения переменной:

```
$ echo $PWD
/home/user2
$ printenv PWD
/home/user2
```

Однако обратите внимание, что при использовании `printenv` перед именем переменной не ставится `$`.

{% hint style="info" %}
`PWD` хранит путь к текущему рабочему каталогу. Мы подробнее рассмотрим эту и другие распространённые переменные среды позже.
{% endhint %}

## **Запуск программы в измененной среде**

`env` может использоваться для изменения среды оболочки во время выполнения программы.

Чтобы запустить новый сеанс Bash с максимально пустой средой — без большинства переменных (а также функций и псевдонимов), — мы будем использовать `env` с опцией `-i`:

```bash
$ env -i bash
```

Теперь большинство наших переменных окружения исчезли:

```bash
$ echo $USER
$
```

И осталось совсем немного:

```bash
$ env
LS_COLORS=
PWD=/home/user2
SHLVL=1
_=/usr/bin/printenv
```

Мы также можем использовать `env` для установки определенной переменной для конкретной программы.

На предыдущем уроке, когда мы обсуждали _неинтерактивные оболочки без входа в систему_, мы увидели, что скрипты не считывают стандартные файлы запуска, а вместо этого ищут значение переменной `BASH_ENV` и используют его в качестве файла запуска, если он существует.

Давайте продемонстрируем этот процесс:

1.  Мы создаем наш собственный загрузочный файл под названием `.startup_script` со следующим содержимым:

    ```bash
    CROCODILIAN=caiman
    ```
2.  Мы пишем Bash-скрипт с именем `test_env.sh` со следующим содержимым:

    ```bash
    #!/bin/bash

    echo $CROCODILIAN
    ```
3.  Мы устанавливаем исполняемый бит для нашего `test_env.sh` скрипта:

    ```bash
    $ chmod +x test_env.sh
    ```
4.  Наконец, мы используем `env` для установки `BASH_ENV` в `.startup_script` для `test_env.sh`:

    ```bash
    $ env BASH_ENV=/home/user2/.startup_script ./test_env.sh
    caiman
    ```

    Команда `env` остается неявной, даже если мы от нее избавимся:

    ```bash
    $ BASH_ENV=/home/user2/.startup_script ./test_env.sh
    caiman
    ```

{% hint style="info" %}
Если вы не понимаете строку `#!/bin/bash` или команду `chmod +x`, не паникуйте! Мы изучим всё необходимое о скриптах в будущих уроках. А пока просто запомните, что для выполнения скрипта из его собственного каталога мы используем `./some_script`.
{% endhint %}

## **Общие переменные среды**

Теперь пришло время рассмотреть некоторые наиболее важные переменные среды, которые задаются в файлах конфигурации Bash.

`DISPLAY`

Значение этой переменной, связанной с X-сервером, обычно состоит из трёх элементов:

* Имя хоста (его отсутствие означает `localhost`), на котором запущен X-сервер.
* Двоеточие в качестве разделителя.
*   Номер (обычно он обозначается `0` и относится к дисплею компьютера).

    ```bash
    $ printenv DISPLAY
    :0
    ```

    Пустое значение для этой переменной означает, что сервер не поддерживает систему X. Дополнительное число — например, `my.xserver:0:1` — указывает номер экрана, если их несколько.

`HISTCONTROL`

Эта переменная определяет, какие команды сохраняются в `HISTFILE` (см. ниже). Возможны три значения:

`ignorespace`

Команды, начинающиеся с пробела, сохраняться не будут.

`ignoredups`

Команда, которая совпадает с предыдущей, сохранена не будет.

`ignoreboth`

Команды, которые попадают в любую из двух предыдущих категорий, сохранены не будут.

```
$ echo $HISTCONTROL
ignoreboth
```

`HISTSIZE`

Это устанавливает количество команд, которые будут храниться в памяти во время сеанса работы оболочки.

```bash
$ echo $HISTSIZE
1000
```

`HISTFILESIZE`

Это устанавливает количество команд, которые будут сохранены в `HISTFILE` в начале и в конце сеанса:

```bash
$ echo $HISTFILESIZE 
2000
```

`HISTFILE`

Имя файла, в котором хранятся все вводимые команды. По умолчанию этот файл находится по адресу `~/.bash_history`:

```bash
$ echo $HISTFILE
/home/user2/.bash_history
```

{% hint style="info" %}
Чтобы просмотреть содержимое `HISTFILE`, мы просто вводим `history`. В качестве альтернативы мы можем указать количество команд, которые хотим увидеть, передав аргумент (количество последних команд) в `history` как в `history 3`.
{% endhint %}

`HOME`

Эта переменная хранит абсолютный путь к домашнему каталогу текущего пользователя и устанавливается при входе пользователя в систему.

Этот фрагмент кода — из `~/.profile` — говорит сам за себя (он использует `"$HOME/.bashrc"` в качестве источника, если тот существует):

```bash
    # include .bashrc if it exists
    if [ -f "$HOME/.bashrc" ]; then
	. "$HOME/.bashrc"
    fi
```

{% hint style="info" %}
Если вы не совсем понимаете оператор `if` , не волнуйтесь: просто обратитесь к урокам по написанию сценариев оболочки.
{% endhint %}

Помните, что `~` эквивалентно `$HOME`:

```bash
$ echo ~; echo $HOME
/home/carol
/home/carol
```

{% hint style="info" %}
Команды могут быть объединены точкой с запятой (`;`).
{% endhint %}

Мы также можем доказать это с помощью `if` утверждения:

```
$ if [ ~ == "$HOME" ]; then echo "true"; else echo "false"; fi
true
```

Помните: знак равенства `=` используется для присвоения значений переменным. `==` используется для проверки на равенство.

`HOSTNAME`

Эта переменная хранит TCP / IP-имя главного компьютера:

```bash
$ echo $HOSTNAME
debian
```

`HOSTTYPE`

Здесь хранится архитектура процессора главного компьютера:

```bash
$ echo $HOSTTYPE
x86_64
```

`LANG`

Эта переменная сохраняет языковой стандарт системы:

```bash
$ echo $LANG
en_UK.UTF-8
```

`LD_LIBRARY_PATH`

Эта переменная представляет собой набор каталогов, разделённых двоеточиями, в которых программы используют общие библиотеки:

```bash
$ echo $LD_LIBRARY_PATH
/usr/local/lib
```

`MAIL`

Эта переменная хранит файл, в котором Bash выполняет поиск электронной почты:

```bash
$ echo $MAIL
/var/mail/carol
```

Другим распространенным значением этой переменной является `/var/spool/mail/$USER`.

`MAILCHECK`

Эта переменная хранит числовое значение, которое указывает в секундах частоту, с которой Bash проверяет наличие новой почты:

```bash
$ echo $MAILCHECK
60
```

`PATH`

Эта переменная среды хранит список каталогов, в которых Bash ищет исполняемые файлы при запуске любой программы. На нашем примере эта переменная задается через общесистемный `/etc/profile` файл:

```bash
if [ "`id -u`" -eq 0 ]; then
  PATH="/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin"
else
  PATH="/usr/local/bin:/usr/bin:/bin:/usr/local/games:/usr/games"
fi
export PATH
```

С помощью `if` оператора проверяется личность пользователя, и — в зависимости от результата проверки (`root` или иначе) — мы получим одно `PATH` или другое. Наконец, выбранное `PATH` распространяется с помощью `export`.

Обратите внимание на две вещи, касающиеся ценности `PATH`:

* Имена каталогов записываются с использованием абсолютных путей.
*   Двоеточие используется в качестве разделителя.

    Если мы захотим включить папку `/usr/local/sbin` в `PATH` для обычных пользователей, мы изменим строку так, чтобы она выглядела следующим образом:

    ```bash
    (...)
    else
      PATH="/usr/local/bin:/usr/bin:/bin:/usr/local/games:/usr/games:/usr/local/sbin"
    fi
    export PATH
    ```

    Теперь мы можем увидеть, как меняется значение переменной, когда мы входим в систему как обычный пользователь:

    ```bash
    # su - carol
    $ echo $PATH
    /usr/local/bin:/usr/bin:/bin:/usr/local/games:/usr/games:/usr/local/sbin
    ```

    | Примечание | Мы также могли бы добавить `/usr/local/sbin` в `PATH` пользователя в командной строке, введя `PATH=/usr/local/sbin:$PATH` или `PATH=$PATH:/usr/local/sbin` — в первом случае `/usr/local/sbin` станет первым каталогом, в котором будут искать исполняемые файлы, а во втором — последним. |
    | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

`PS1`

Эта переменная хранит значение приглашения Bash. В следующем фрагменте кода (также из `/etc/profile`), оператор `if` проверяет личность пользователя и в зависимости от этого выдаёт ему очень лаконичное приглашение ( `#` для `root` или `$` для обычных пользователей):

```bash
if [ "`id -u`" -eq 0 ]; then
  PS1='# '
else
  PS1='$ '
fi
```

| Примечание | `id` из `root` — это `0`. Станьте `root` и проверьте это сами с помощью `id -u`. |
| ---------- | -------------------------------------------------------------------------------- |

Другие Переменные запроса включают:

`PS2`

Обычно устанавливается значение `>` и используется в качестве подсказки для продолжения длинных многострочных команд.

`PS3`

Используется в качестве приглашения для `select` команды.

`PS4`

Обычно устанавливается в `+` и используется для отладки.

`SHELL`

Эта переменная хранит абсолютный путь к текущей оболочке:

```bash
$ echo $SHELL
/bin/bash
```

`USER`

Здесь хранится имя текущего пользователя:

```bash
$ echo $USER
carol
```

Выведить линии, соответствующие шаблону.

`bash`

Запустить новую оболочку

Сбросить настройки переменных.
