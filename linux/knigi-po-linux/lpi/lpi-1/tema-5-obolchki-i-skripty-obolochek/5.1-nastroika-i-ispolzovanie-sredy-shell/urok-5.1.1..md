# Урок 5.1.1.

### Введение <a href="#sec.105.1_01-in" id="sec.105.1_01-in"></a>

Оболочка, пожалуй, является самым мощным инструментом в системе Linux и может быть определена как интерфейс между пользователем и ядром операционной системы. Она интерпретирует команды, введённые пользователем. Поэтому все системные администраторы должны уметь пользоваться оболочкой. Как мы, несомненно, уже знаем, Bourne Again Shell (_Bash_) является _фактической_ оболочкой для подавляющего большинства дистрибутивов Linux.

После запуска Bash — или любой другой оболочки, если уж на то пошло, — первым делом выполняется ряд сценариев запуска. Эти сценарии настраивают среду сеанса. Существуют как общесистемные, так и пользовательские сценарии. Мы можем добавлять в эти сценарии свои личные предпочтения или настройки, которые лучше всего соответствуют потребностям наших пользователей, в виде переменных, псевдонимов и функций.

Точный набор файлов для запуска зависит от очень важного параметра: типа оболочки. Давайте рассмотрим существующие типы оболочек.

## Типы оболочек: интерактивная и неинтерактивная, а также с логином и без логина <a href="#shell_types_interactive_vs_non_interactive_and_login_vs_non_login" id="shell_types_interactive_vs_non_interactive_and_login_vs_non_login"></a>

Для начала давайте проясним понятия _интерактивности_ и _входа в систему_ в контексте оболочек:

_**Интерактивные / Неинтерактивные оболочки**_

Этот тип оболочки относится к взаимодействию между пользователем и оболочкой: пользователь вводит команды в терминал с помощью клавиатуры, а оболочка выводит сообщения на экран.

_**Оболочки для входа / Не для входа в систему**_

Этот тип оболочки относится к событию, когда пользователь входит в компьютерную систему, предоставляя свои учётные данные, такие как имя пользователя и пароль.

Как интерактивные, так и неинтерактивные оболочки могут быть как с логином, так и без него, и любая возможная комбинация этих типов имеет своё конкретное применение.

_**Интерактивные оболочки для входа в систему**_ запускаются, когда пользователи входят в систему, и используются для настройки конфигурации пользователей в соответствии с их потребностями. Хорошим примером такого типа оболочки может служить группа пользователей, принадлежащих к одному отделу, которым в их сеансах требуется определенный набор переменных.

Под _**интерактивными оболочками без входа в систему**_ мы подразумеваем любые другие оболочки, открытые пользователем после входа в систему. Пользователи используют эти оболочки во время сеансов для выполнения задач по обслуживанию и администрированию, таких как установка переменных, времени, копирование файлов, написание скриптов и т. д.

С другой стороны, **неинтерактивные оболочки** не требуют какого-либо взаимодействия с человеком. Таким образом, эти оболочки не запрашивают у пользователя ввод данных, а их вывод — если он есть — в большинстве случаев записывается в журнал.

_**Неинтерактивные оболочки для входа в систему**_ встречаются довольно редко и непрактичны. Они практически не используются, и мы упомянем их только для того, чтобы понять, как работает оболочка. Некоторые странные примеры включают принудительный запуск скрипта из оболочки для входа в систему с помощью `/bin/bash --login <some_script>` или перенаправление стандартного вывода (_stdout_) команды на стандартный ввод (_stdin_) ssh-соединения:

```bash
<some_command> | ssh <some_user>@<some_server>
```

Что касается _неинтерактивной оболочки без входа в систему_, то она не предполагает ни взаимодействия, ни входа в систему от имени пользователя, поэтому здесь мы имеем в виду использование автоматизированных скриптов. Эти скрипты в основном используются для выполнения повторяющихся административных задач и задач по обслуживанию, например, в cron-заданиях. В таких случаях `bash` не считывает файлы запуска.

## **Открытие терминала**

Когда мы находимся в среде рабочего стола, мы можем либо открыть приложение-терминал, либо переключиться на одну из системных консолей. Таким образом, новая оболочка — это либо `pts` оболочка, если она открыта в эмуляторе терминала в графическом интерфейсе, либо `tty` оболочка, если она запущена с системной консоли. В первом случае мы имеем дело не с терминалом, а с эмулятором терминала. В рамках графических сеансов эмуляторы терминала, такие как _gnome-terminal_ или _konsole_, очень многофункциональны и удобны для пользователя по сравнению с текстовыми терминалами. К менее функциональным эмуляторам терминалов относятся, в частности, _XTerm_ и _sakura_.

Используя комбинации Ctrl+Alt+F1-F6, мы можем перейти к консольным входам, которые открывают интерактивную текстовую оболочку для входа в систему. Ctrl+Alt+F7 вернёт сеанс на рабочий стол.

{% hint style="info" %}
`tty` означает «телетайп»; `pts` означает «pseudo terminal slave». Для получения дополнительной информации: `man tty` и `man pts`.
{% endhint %}

## **Запуск оболчек с `bash`**

После входа в систему введите `bash` в терминале, чтобы открыть новую оболочку. Технически эта оболочка является дочерним процессом текущей оболочки.

При запуске дочернего процесса `bash` мы можем указать различные параметры, чтобы определить, какую оболочку мы хотим запустить. Вот несколько важных параметров `bash` вызова:

`bash -l` или `bash --login`

вызовет оболочку во входом в систему.

`bash -i`

вызовет интерактивную оболочку.

`bash --noprofile`

при входе в систему оболочки будут игнорировать как общесистемный файл запуска `/etc/profile`, так и файлы запуска на уровне пользователя `~/.bash_profile`, `~/.bash_login` и `~/.profile`.

`bash --norc`

интерактивные оболочки будут игнорировать как общесистемный файл запуска `/etc/bash.bashrc`, так и файл запуска на уровне пользователя `~/.bashrc`.

`bash --rcfile <file>`

интерактивные оболочки будут использовать `<file>` в качестве файла запуска, игнорируя общесистемные `/etc/bash.bashrc` и `~/.bashrc` на уровне пользователя.

Ниже мы обсудим различные загрузочные файлы.

## **Запуск снарядов с помощью `su` и `sudo`**

С помощью этих двух похожих программ мы можем создавать оболочки определённого типа:

`su`

Измените идентификатор пользователя или станьте суперпользователем (`root`). С помощью этой команды мы можем запустить как оболочку с логином, так и без него:

* `su - user2`, `su -l user2` или `su --login user2` запустит интерактивную оболочку  со входом в систему как `user2`.
* `su user2` запустит интерактивную оболочку без входа в систему как `user2`.
* `su - root` или `su -` запустит интерактивную оболочку со входом в систему как `root`.
* `su root` или `su` запустит интерактивную оболочку без входа в систему как `root`.

`sudo`

Выполняйте команды от имени другого пользователя (включая суперпользователя). Поскольку эта команда в основном используется для временного получения прав суперпользователя, пользователь, использующий её, должен быть в файле `sudoers` . Чтобы добавить пользователей в `sudoers` , нам нужно стать `root` , а затем выполнить:

```bash
root@debian:~# usermod -aG sudo user2
```

Точно так же, как `su`, `sudo` позволяет нам вызывать оболочки как для входа, так и без входа в систему:

* `sudo su - user2`, `sudo su -l user2` или `sudo su --login user2` запустит интерактивную оболочку со входом систему как `user2`.
* `sudo su user2` запустит интерактивную оболочку без входа в систему как `user2`.
* `sudo -u user2 -s` запустит интерактивную оболочку без входа в систему как `user2`.
* `sudo su - root` или `sudo su -` запустит интерактивную оболочку со входом в систему как `root`.
* `sudo -i` запустит интерактивную оболочку со входом в систему как `root`.
* `sudo -i <some_command>` запустит интерактивную оболочку со входом в систему под именем `root`, выполнит команду и вернётся к исходному пользователю.
* `sudo su root` или `sudo su` запустит интерактивную оболочку без входа в систему как `root`.
* `sudo -s` или `sudo -u root -s` запустит оболочку со входом в систему как `root`.

При использовании `su` или `sudo` важно учитывать конкретный сценарий запуска новой оболочки: нужна ли нам среда целевого пользователя или нет? Если да, то мы будем использовать параметры, которые запускают оболочки со входом в систему; если нет, то параметры, которые запускают оболочки без входа в систему.

## **Какой тип оболочки у нас есть?**

Чтобы узнать, в каком типе оболочки мы работаем, мы можем ввести в терминал `echo $0` и получить следующий результат:

Интерактивный со входом в систему

`-bash` или `-su`

Интерактивный без входа в систему

`bash` или `/bin/bash`

Неинтерактивный без входа в систему (скрипты)

`<name_of_script>`

## **Сколько у нас оболочек?**

Чтобы узнать, сколько `bash` оболочек запущено в системе, мы можем использовать команду `ps aux | grep bash`:

```bash
user2@debian:~$ ps aux | grep bash
user2       5270  0.1  0.1  25532  5664 pts/0    Ss   23:03   0:00 bash
user2       5411  0.3  0.1  25608  5268 tty1     S+   23:03   0:00 -bash
user2       5452  0.0  0.0  16760   940 pts/0    S+   23:04   0:00 grep --color=auto bash
```

`user2` в `debian` он вошёл в сеанс графического интерфейса (или X ) и открыл _gnome-terminal_, затем нажал Ctrl+Alt+F1, чтобы перейти в сеанс `tty` терминала. Наконец, он вернулся в сеанс графического интерфейса, нажав Ctrl+Alt+F7, и ввел команду `ps aux | grep bash`. Таким образом, на выходе отображается интерактивная оболочка без входа в систему через эмулятор терминала (`pts/0`) и интерактивная оболочка с входом в систему через соответствующий текстовый терминал (`tty1`). Обратите также внимание, что последнее поле каждой строки (команда) для первой команды — `bash` , а для второй — `-bash` .

## **Откуда оболочки получают свою конфигурацию: файлы запуска**

Что ж, теперь, когда мы знаем, какие типы оболочек можно найти в системе Linux, пришло время посмотреть, какие файлы запускаются той или иной оболочкой. Обратите внимание, что общесистемные или глобальные скрипты размещаются в каталоге `/etc/`, а локальные или пользовательские — в домашнем каталоге пользователя (`~`). Кроме того, если нужно найти несколько файлов, то после запуска одного из них остальные игнорируются. Изучите эти файлы самостоятельно с помощью вашего любимого текстового редактора или введя `less <startup_file>`.

{% hint style="info" %}
Файлы запуска можно разделить на специфичные для Bash (ограниченные только конфигурациями `bash` и командами) и общие (относящиеся к большинству оболочек).
{% endhint %}

## **Интерактивная оболочка входа в систему**

## **Глобальный уровень**

`/etc/profile`

Это общесистемный `.profile` файл для Bourne shell и Bourne совместимых оболочек. Посредством серии `if` инструкций этот файл устанавливает ряд переменных, таких как `PATH` и `PS1` соответственно, а также источники — если они существуют — как для файла, так и для файлов в каталоге `/etc/bash.bashrc`.... `/etc/profile.d`

`/etc/profile.d/*`

Этот каталог может содержать скрипты, которые выполняются с помощью `/etc/profile`.

## **Местный уровень**

`~/.bash_profile`

Этот специфичный для Bash файл используется для настройки пользовательской среды. Его также можно использовать для запуска `~/.bash_login` и `~/.profile`.

`~/.bash_login`

Этот файл, специфичный для Bash, будет выполняться только в том случае, если нет файла `~/.bash_profile` . Его название говорит о том, что он должен использоваться для запуска команд, необходимых при входе в систему.

`~/.profile`

Этот файл не относится к Bash и используется только в том случае, если не существует ни `~/.bash_profile` ни `~/.bash_login` — что обычно и происходит. Таким образом, основная цель `~/.profile` — проверить, запущена ли оболочка Bash, и, если да, использовать `~/.bashrc` если он существует. Обычно он устанавливает переменную `PATH` так, чтобы она включала личный `~/bin` каталог пользователя, если он существует.

`~/.bash_logout`

Если он существует, этот файл, специфичный для Bash, выполняет некоторые операции по очистке при выходе из оболочки. Это может быть удобно в таких случаях, как при удалённых сеансах.

## Изучение файлов конфигурации интерактивной оболочки со входом в систему

Давайте покажем некоторые из этих файлов в действии, изменив `/etc/profile` и `/home/user2/.profile`. Мы добавим к каждой строке напоминание о том, какой файл выполняется:

```bash
root@debian:~# echo 'echo Hello from /etc/profile' >> /etc/profile
root@debian:~# echo 'echo Hello from ~/.profile' >> ~/.profile
```

{% hint style="info" %}
Два оператора перенаправления `>>` добавляют вывод команды в существующий файл, не перезаписывая его. Если файл не существует, он будет создан.
{% endhint %}

Таким образом, по результатам выполнения соответствующих `echo` команд мы будем знать, когда каждый из этих файлов будет прочитан и выполнен. Чтобы убедиться в этом, давайте посмотрим, что происходит, когда `user2` входит в систему через `ssh` с другого компьютера:

```bash
user2@debian:~$ ssh user2@192.168.1.6
user2@192.168.1.6's password:
Linux debian 4.9.0-8-amd64 #1 SMP Debian 4.9.130-2 (2018-10-27) x86_64

The programs included with the Debian GNU/Linux system are free software;
the exact distribution terms for each program are described in the
individual files in /usr/share/doc/*/copyright.

Debian GNU/Linux comes with ABSOLUTELY NO WARRANTY, to the extent
permitted by applicable law.
Last login: Tue Nov 27 19:57:19 2018 from 192.168.1.10
Hello from /etc/profile
Hello from /home/user2/.profile
```

Как видно из последних двух строк, это сработало. Также обратите внимание на три момента:

* Глобальный файл был запущен первым.
* В домашнем каталоге `.bash_profile` не было файлов `.bash_login` or `user2`.
* Тильда (`~`) расшифровывается как абсолютный путь к файлу (`/home/user2/.profile`).

## **Интерактивная оболочка без входа в систему**

**Глобальный уровень**

`/etc/bash.bashrc`

Это общесистемный файл `.bashrc` для интерактивных оболочек `bash`. При его выполнении `bash` проверяется, что он запускается в интерактивном режиме, после каждой команды проверяется размер окна (при необходимости обновляются значения `LINES` и `COLUMNS`) и устанавливаются некоторые переменные.

**Местный уровень**

`~/.bashrc`

Помимо выполнения задач, аналогичных тем, что описаны для `/etc/bash.bashrc` на уровне пользователя (например, проверка размера окна или запуск в интерактивном режиме), этот файл, специфичный для Bash, обычно устанавливает некоторые переменные истории и источники `~/.bash_aliases` при их наличии. Кроме того, этот файл обычно используется для хранения пользовательских псевдонимов и функций.

Также стоит отметить, что `~/.bashrc` считывается, если `bash` обнаруживает, что `<stdin>` является сетевым подключением (как в случае с подключением _Secure Shell_ (SSH) в приведённом выше примере).

Изучение файлов конфигурации интерактивной оболочки без входа в систему

Давайте теперь изменим `/etc/bash.bashrc` и `/home/user2/.bashrc`:

```bash
root@debian:~# echo 'echo Привет из /etc/bash.bashrc' >> /etc/bash.bashrc
root@debian:~# echo 'echo Привет из ~/.bashrc' >> ~/.bashrc
```

И  вот,  что происходит, когда `user2` запускает новую оболочку:

```bash
user2@debian:~$ bash
Hello from /etc/bash.bashrc
Hello from /home/user2/.bashrc
```

И снова эти два файла были прочитаны и выполнены.

{% hint style="info" %}
Помните, что из-за порядка запуска файлов локальные файлы имеют приоритет над глобальными.
{% endhint %}

## **Неинтерактивная оболочка со входом в систему**

Неинтерактивная оболочка с опциями `-l` или `--login` вынуждена вести себя как оболочка входа в систему, поэтому запускаемые файлы будут такими же, как и для интерактивных оболочек входа в систему.

Чтобы доказать это, давайте напишем простой скрипт и сделаем его исполняемым. Мы не будем добавлять _шебанги_, потому что будем вызывать _исполняемый файл bash_ (`/bin/bash` с опцией входа в систему) из командной строки.

1. Мы создаём скрипт `test.sh` с командой `echo 'Hello from a script'` для того, чтобы убедиться, что скрипт работает успешно:

```bash
user2@debian:~$ echo "echo 'Hello from a script'" > test.sh
```

2. Делаем наш скрипт исполняемым:

```bash
user2@debian:~$ chmod +x ./test.sh
```

3. Наконец, мы вызываем `bash` с `-l` опцией для запуска скрипта:

```bash
user2@debian:~$ bash -l ./test.sh
Hello from /etc/profile
Hello from /home/user2/.profile
Hello from a script
```

Это работает! Перед запуском скрипта был выполнен вход в систему, и были выполнены `/etc/profile` и `~/.profile`.

{% hint style="info" %}
В следующих уроках мы узнаем о _shebangs_ и других аспектах написания сценариев оболочки.
{% endhint %}

Теперь давайте перенаправим стандартный вывод (_stdout_) команды `echo` на стандартный ввод (_stdin_) соединения `ssh` с помощью канала (`|`):

```bash
user2@debian:~$ echo "Hello-from-a-noninteractive-login-shell" | ssh user2@192.168.1.6
Pseudo-terminal will not be allocated because stdin is not a terminal.
user2@192.168.1.6's password:
Linux debian 4.9.0-8-amd64 #1 SMP Debian 4.9.130-2 (2018-10-27) x86_64

The programs included with the Debian GNU/Linux system are free software;
the exact distribution terms for each program are described in the
individual files in /usr/share/doc/*/copyright.

Debian GNU/Linux comes with ABSOLUTELY NO WARRANTY, to the extent
permitted by applicable law.
Hello from /etc/profile
Hello from /home/user2/.profile
-bash: line 1: Hello-from-a-noninteractive-login-shell: command not found
```

Опять же, `/etc/profile` и `~/.profile` выполняются. Кроме того, первая и последняя строки вывода довольно красноречивы с точки зрения поведения оболочки.

## **Неинтерактивная оболочка без входа в систему**

Скрипты не считывают ни один из перечисленных выше файлов, но ищут переменную среды `BASH_ENV`, при необходимости расширяют её значение и используют в качестве имени файла запуска для считывания и выполнения команд. Подробнее о _переменных среды_ мы узнаем на следующем уроке.

Как упоминалось выше, обычно `/etc/profile` и `~/.profile` гарантируют, что `/etc/bash.bashrc` и `~/.bashrc` будут выполнены после успешного входа в систему. Вывод следующей команды демонстрирует это явление:

```bash
root@debian:~# su - user2
Hello from /etc/bash.bashrc
Hello from /etc/profile
Hello from /home/user2/.bashrc
Hello from /home/user2/.profile
```

Учитывая строки, которые мы ранее добавили в сценарии запуска, и вызов интерактивной оболочки на уровне пользователя с помощью `su - user2` — четыре строки вывода можно объяснить следующим образом:

1. `Hello from /etc/bash.bashrc` означает, что `/etc/profile` имеет источник `/etc/bash.bashrc`.
2. `Hello from /etc/profile` означает, что `/etc/profile` был полностью прочитан и выполнен.
3. `Hello from /home/user2/.bashrc` означает, что `~/.profile` имеет источник `~/.bashrc`.
4. `Hello from /home/user2/.profile` означает, что `~/.profile` был полностью прочитан и выполнен.

Обратите внимание, что с помощью `su - <username>` (а также `su -l <username>` и `su --login <username>`) мы гарантируем вызов оболочки со воходом в систему, в то время как `su <username>` вызывал бы только `/etc/bash.bashrc` и `~/.bashrc`.

## **Поиск файлов**

В предыдущих разделах мы обсуждали, что некоторые сценарии запуска включают в себя другие сценарии или запускают их. Этот механизм называется поиском и объясняется в этом разделе.

## **Поиск файлов с помощью `.`**

Точка (`.`) обычно встречается в файлах запуска.

В файле `.profile` на нашем сервере Debian мы можем найти, например, следующий блок:

```bash
    # include .bashrc if it exists
    if [ -f "$HOME/.bashrc" ]; then
	. "$HOME/.bashrc"
    fi
```

Мы уже видели, как выполнение одного скрипта может привести к выполнению другого. Таким образом, оператор `if` гарантирует, что файл `$HOME/.bashrc` — если он существует (`-f`) — будет загружен (то есть прочитан и выполнен) при входе в систему:

```bash
. "$HOME/.bashrc"
```

{% hint style="info" %}
Как мы узнаем на следующем уроке, `$HOME` — это переменная среды, которая расширяется до абсолютного пути к домашнему каталогу пользователя.
{% endhint %}

Кроме того, мы можем использовать `.` всякий раз, когда изменяем файл автозагрузки и хотим, чтобы изменения вступили в силу без перезагрузки. Например, мы можем:

* добавьте псевдоним в `~/.bashrc`:

```bash
user2@debian:~$ echo "alias hi='echo We salute you.'" >> ~/.bashrc
```

{% hint style="info" %}
При отправке вывода одной команды в файл не забывайте, что добавление (`>>`) не следует путать с перезаписью (`>`).
{% endhint %}

* выведите последнюю строку `~/.bashrc`, чтобы проверить, все ли прошло нормально:

```bash
user2@debian:~$ tail -n 1 !$
tail -n 1 ~/.bashrc
alias hi='echo We salute you.'
```

{% hint style="info" %}
`!$` расширяется до последнего аргумента предыдущей команды, в нашем случае: `~/.bashrc`.
{% endhint %}

* создайте исходный файл вручную:

```bash
user2@debian:~$ . ~/.bashrc
```

и вызовите псевдоним, чтобы доказать, что он работает:

```bash
user2@debian:~$ hi
We salute you.
```

Обратитесь к следующему уроку, чтобы узнать о _псевдонимах_ и _переменных_.

## **Поиск файлов с помощью `source`**

Команда `source` является синонимом `.`. Поэтому для вызова `~/.bashrc` мы также можем сделать это следующим образом:

```bash
user2@debian:~$ source ~/.bashrc
```

## **Происхождение файлов запуска командной строки: `SKEL`**

`SKEL` Это переменная, значением которой является абсолютный путь к каталогу `skel`. Этот каталог служит шаблоном для структуры файловой системы домашних каталогов пользователей. Он включает файлы, которые будут унаследованы любыми новыми учётными записями пользователей (включая, конечно, файлы конфигурации для оболочек). `SKEL` и другие связанные переменные хранятся в `/etc/adduser.conf`, который является файлом конфигурации для `adduser`.

```bash
user2@debian:~$ grep SKEL /etc/adduser.conf
# The SKEL variable specifies the directory containing "skeletal" user
SKEL=/etc/skel
# If SKEL_IGNORE_REGEX is set, adduser will ignore files matching this
SKEL_IGNORE_REGEX="dpkg-(old|new|dist|save)"
```

`SKEL` задано значение `/etc/skel`; таким образом, сценарии запуска, которые настраивают наши оболочки, находятся там:

```bash
user2@debian:~$ ls -a /etc/skel/
. .. .bash_logout .bashrc .profile
```

{% hint style="info" %}
Помните, что файлы, начинающиеся с `.`, скрыты, поэтому для их отображения при просмотре содержимого каталога нужно использовать `ls -a`
{% endhint %}

Теперь давайте создадим каталог в `/etc/skel` для всех новых пользователей, чтобы они могли хранить в нём свои личные скрипты:

1.  По мере того, как `root` мы переходим к `/etc/skel`:

    ```bash
    root@debian:~# cd /etc/skel/
    root@debian:/etc/skel#
    ```
2.  Мы перечисляем его содержание:

    ```bash
    root@debian:/etc/skel# ls -a
    . .. .bash_logout .bashrc .profile
    ```
3.  Создаем наш каталог и проверяем, все ли прошло так, как ожидалось:

    ```bash
    root@debian:/etc/skel# mkdir my_personal_scripts
    root@debian:/etc/skel# ls -a
    . .. .bash_logout .bashrc my_personal_scripts .profile
    ```
4.  Теперь удаляем `user2` вместе с его `home` каталогом:

    ```bash
    root@debian:~# deluser --remove-home user2
    Looking for files to backup/remove ...
    Removing files ...
    Removing user `user2' ...
    Warning: group `user2' has no more members.
    Done.
    ```
5.  Мы снова добавляем `user2`, чтобы получить новый домашний каталог:

    ```
    root@debian:~# adduser user2
    Adding user `user2' ...
    Adding new group `user2' (1001) ...
    Adding new user `user2' (1001) with group `user2' ...
    Creating home directory `/home/user2' ...
    Copying files from `/etc/skel' ...
    Enter new UNIX password:
    Retype new UNIX password:
    passwd: password updated successfully
    Changing the user information for user2
    Enter the new value, or press ENTER for the default
    	Full Name []:
    	Room Number []:
    	Work Phone []:
    	Home Phone []:
    	Other []:
    Is the information correct? [Y/n] y
    ```
6.  Наконец, мы входим в систему под именем `user2` и перечисляем все файлы в `/home/user2`, чтобы проверить, всё ли прошло как ожидалось:

    ```bash
    root@debian:~# su - user2
    user2@debian:~$ pwd
    /home/user2
    user2@debian:~$ ls -a
    .  ..  .bash_history  .bash_logout  .bashrc  my_personal_scripts  .profile
    ```

    Это сработало.
