# Урок 3.4.1.

## Введение <a href="#sec.103.4_01-in" id="sec.103.4_01-in"></a>

Все компьютерные программы работают по одному и тому же общему принципу: данные, полученные из какого-либо источника, преобразуются для получения понятного результата. В контексте командной строки Linux источником данных может быть локальный файл, удалённый файл, устройство (например, клавиатура) и т. д. Выходные данные программы обычно отображаются на экране, но также часто бывает необходимо сохранить выходные данные в локальной файловой системе, отправить их на удалённое устройство, воспроизвести через динамики и т. д.

Операционные системы, созданные на основе Unix, такие как Linux, предлагают большое разнообразие методов ввода/вывода. В частности, метод _файловых дескрипторов_ позволяет динамически связывать целые числа с каналами данных, чтобы процесс мог ссылаться на них как на потоки входных/выходных данных.

Стандартные процессы Linux по умолчанию открывают три канала связи: канал _стандартного ввода_ (чаще всего называемый просто _stdin_), канал _стандартного вывода_ (_stdout_) и канал _стандартной ошибки_ (_stderr_). Числовые дескрипторы файлов, назначенные этим каналам, — `0` для stdin, `1` для stdout и `2` для stderr. Каналы связи также доступны через специальные устройства `/dev/stdin`, `/dev/stdout` и `/dev/stderr`.

Эти три стандартных канала связи позволяют программистам писать код, который считывает и записывает данные, не беспокоясь о том, с какого носителя они поступают или на какой носитель они отправляются. Например, если программе нужен набор данных в качестве входных, она может просто запросить данные со стандартного ввода, и то, что используется в качестве стандартного ввода, предоставит эти данные. Точно так же самый простой способ, с помощью которого программа может отобразить выходные данные, — это записать их в стандартный вывод. В стандартном сеансе командной оболочки клавиатура определяется как стандартный ввод, а экран монитора — как стандартный вывод и стандартную ошибку.

Оболочка Bash позволяет переназначать каналы связи при загрузке программы. Это позволяет, например, заменить экран в качестве стандартного вывода и использовать файл в локальной файловой системе в качестве стандартного вывода.

## Перенаправления <a href="#sec.103.4_01-re" id="sec.103.4_01-re"></a>

Переназначение файлового дескриптора канала в среде оболочки называется _перенаправлением_. Перенаправление определяется специальным символом в командной строке. Например, чтобы перенаправить стандартный вывод процесса в файл, в конце команды ставится символ _больше_ `>` и указывается путь к файлу, в который будет перенаправлен вывод:

```bash
$ cat /proc/cpuinfo >/tmp/cpu.txt
```

По умолчанию перенаправляется только содержимое, поступающее в стандартный вывод. Это происходит потому, что числовое значение файлового дескриптора должно быть указано непосредственно перед символом «больше», а если оно не указано, Bash перенаправляет стандартный вывод. Таким образом, использование `>` эквивалентно использованию `1>` (значение файлового дескриптора стандартного вывода равно `1`).

Чтобы перехватить содержимое stderr, вместо этого следует использовать перенаправление `2>` . Большинство программ командной строки отправляют отладочную информацию и сообщения об ошибках в стандартный канал ошибок. Например, можно перехватить сообщение об ошибке, вызванное попыткой прочитать несуществующий файл:

```bash
$ cat /proc/cpu_info 2>/tmp/error.txt
$ cat /tmp/error.txt
cat: /proc/cpu_info: No such file or directory
```

И стандартный вывод, и стандартный поток ошибок перенаправляются на одну и ту же цель с помощью `&>` или `>&`. Важно не ставить пробелы после амперсанда, иначе Bash воспримет это как указание запустить процесс в фоновом режиме, а не выполнить перенаправление.

Целевым объектом должен быть путь к файлу, доступному для записи, например `/tmp/cpu.txt` или дескриптор файла, доступный для записи. Целевой дескриптор файла обозначается амперсандом, за которым следует числовое значение дескриптора. Например, `1>&2` перенаправляет стандартный вывод в стандартный поток ошибок. Чтобы сделать наоборот, перенаправить стандартный поток ошибок в стандартный вывод, следует использовать `2>&1` вместо этого.

Хотя это и не очень полезно, учитывая, что есть более короткий способ выполнить ту же задачу, можно перенаправить stderr на stdout, а затем перенаправить его в файл. Например, перенаправление для записи stderr и stdout в файл с именем `log.txt` можно записать как `>log.txt 2>&1`. Однако основная причина перенаправления stderr на stdout заключается в том, чтобы можно было анализировать сообщения об отладке и ошибках. Можно перенаправить стандартный вывод программы на стандартный ввод другой программы, но нельзя напрямую перенаправить стандартную ошибку на стандартный ввод другой программы. Таким образом, сообщения программы, отправляемые в stderr, сначала нужно перенаправить в stdout, чтобы их могла прочитать другая программа через stdin.

Чтобы просто отбросить вывод команды, его содержимое можно перенаправить в специальный файл `/dev/null`. Например, `>log.txt 2>/dev/null` сохраняет содержимое стандартного вывода в файл `log.txt` и отбрасывает стандартный вывод. Файл `/dev/null` доступен для записи любому пользователю, но из него нельзя восстановить данные, так как они нигде не сохраняются.

Если указанная цель недоступна для записи (если путь указывает на каталог или файл только для чтения) и никаких изменений в цели не производится, отображается сообщение об ошибке. Однако перенаправление вывода перезаписывает существующую цель, доступную для записи, без какого-либо подтверждения. Файлы перезаписываются при перенаправлении вывода, если не включена опция `noclobber` Bash, которую можно включить для текущего сеанса с помощью команды `set -o noclobber` или `set -C`:

```bash
$ set -o noclobber
$ cat /proc/cpu_info 2>/tmp/error.txt
-bash: /tmp/error.txt: cannot overwrite existing file
```

Чтобы отключить параметр `noclobber` для текущего сеанса, выполните `set +o noclobber` или `set +C`. Чтобы сделать параметр `noclobber` постоянным, его необходимо включить в профиль Bash пользователя или в общесистемный профиль.

Даже при включённой опции `noclobber` можно добавить перенаправленные данные к существующему содержимому. Это делается с помощью перенаправления, записанного с использованием двух символов больше `>>`:\


```bash
$ cat /proc/cpu_info 2>>/tmp/error.txt
$ cat /tmp/error.txt
cat: /proc/cpu_info: No such file or directory
cat: /proc/cpu_info: No such file or directory
```

В предыдущем примере новое сообщение об ошибке было добавлено к существующему в файле `/tmp/error.txt`. Если файл ещё не существует, он будет создан с новыми данными.

Источник данных для стандартного ввода процесса также может быть переназначен. Символ «меньше» `<` используется для перенаправления содержимого файла на стандартный ввод процесса. В этом случае данные передаются справа налево: предполагается, что переназначенный дескриптор равен 0 слева от символа «меньше», а источник данных (путь к файлу) должен находиться справа от символа «меньше». Команда `uniq`, как и большинство утилит командной строки для обработки текста, по умолчанию принимает данные, отправленные на стандартный ввод:

```bash
$ uniq -c </tmp/error.txt
      2 cat: /proc/cpu_info: No such file or directory
```

Опция `-c` позволяет  `uniq` отобразить, сколько раз повторяющаяся строка встречается в тексте. Поскольку числовое значение перенаправленного файлового дескриптора было подавлено, команда в примере эквивалентна .`uniq -c 0</tmp/error.txt` Использование файлового дескриптора, отличного от при перенаправлении ввода, имеет смысл только в определённых контекстах, поскольку программа может запрашивать данные по файловым дескрипторам `0`, `3`, `4` и т. д. Действительно, программы могут использовать любое целое число больше 2 в качестве новых файловых дескрипторов для ввода/вывода данных. Например, следующий код на C считывает данные из файлового дескриптора `3` и просто копирует их в файловый дескриптор `4`:

```c
#include <stdio.h>

int main(int argc, char **argv){
  FILE *fd_3, *fd_4;
  // Open file descriptor 3
  fd_3 = fdopen(3, "r");
  // Open file descriptor 4
  fd_4 = fdopen(4, "w");
  // Read from file descriptor 3
  char buf[32];
  while ( fgets(buf, 32, fd_3) != NULL ){
    // Write to file descriptor 4
    fprintf(fd_4, "%s", buf);
  }
  // Close both file descriptors
  fclose(fd_3);
  fclose(fd_4);
}
```

{% hint style="info" %}
Программа должна корректно обрабатывать такие файловые дескрипторы, иначе она может попытаться выполнить недопустимую операцию чтения или записи и аварийно завершить работу.
{% endhint %}

Чтобы протестировать его, сохраните пример кода как `fd.c` и скомпилируйте его с помощью `gcc -o fd fd.c`. Этой программе нужны доступные файловые дескрипторы 3 и 4, чтобы она могла читать и записывать в них. Например, ранее созданный файл `/tmp/error.txt` можно использовать в качестве источника для файлового дескриптора `3`, а файловый дескриптор `4` можно перенаправить в стандартный вывод:

```bash
$ ./fd 3</tmp/error.txt 4>&1
cat: /proc/cpu_info: No such file or directory
cat: /proc/cpu_info: No such file or directory
```

С точки зрения программиста, использование файловых дескрипторов позволяет избежать необходимости анализировать параметры и пути к файловой системе. Один и тот же файловый дескриптор можно использовать даже для ввода и вывода. В этом случае файловый дескриптор определяется в командной строке с помощью символов «меньше» и «больше», как в `3<>/tmp/error.txt`.

## Здесь документ Here document и Здесь строка Here string <a href="#sec.103.4_01-hh" id="sec.103.4_01-hh"></a>

Другой способ перенаправить ввод — использовать методы _«Здесь документ»_ и _«Здесь строка»_. Перенаправление «Здесь документ» позволяет ввести многострочный текст, который будет использоваться в качестве перенаправленного содержимого. Два символа `<<` обозначают перенаправление «Здесь документ»:

```bash
$ wc -c <<EOF
> How many characters
> in this Here document?
> EOF
43
```

Справа от двух символов «меньше» `<<` находится завершающее выражение `EOF`. Режим вставки завершится, как только будет введена строка, содержащая только завершающее выражение. В качестве завершающего выражения можно использовать любое другое выражение, но важно не ставить пробелы между символом «меньше» и завершающим выражением. В приведенном выше примере две строки текста были отправлены на стандартный ввод команды `wc -c`, которая отображает количество символов. Как и в случае с перенаправлением ввода для файлов, если перенаправленный файловый дескриптор не используется, предполагается, что используется стандартный ввод (файловый дескриптор `0`).

Метод Here string очень похож на метод Here document, но только для одной строки:

```
$ wc -c <<<"How many characters in this Here string?"
41
```

В этом примере строка справа от трёх знаков меньше отправляется в стандартный ввод `wc -c` программы, которая подсчитывает количество символов. Строки, содержащие пробелы, должны быть заключены в кавычки, иначе в качестве строки Here будет использоваться только первое слово, а остальные будут переданы в качестве аргументов команде.

## Краткие сведения <a href="#sec.103.4_01-su" id="sec.103.4_01-su"></a>

В этом уроке рассматриваются методы запуска программы с перенаправлением стандартных каналов связи. Процессы Linux используют эти стандартные каналы в качестве общих _файловых дескрипторов_ для чтения и записи данных, что позволяет произвольно заменять их на файлы или устройства. Урок состоит из следующих этапов:

* Что такое файловые дескрипторы и какую роль они играют в Linux.
* Стандартные каналы связи каждого процесса: _stdin_, _stdout_ и _stderr_.
* Как правильно выполнить команду с использованием перенаправления данных как для ввода, так и для вывода.
* Как использовать _здесь документы_ и _здесь строки_ при перенаправлении ввода.

Были рассмотрены следующие команды и процедуры:

* Операторы перенаправления: `>`, `<`, `>>` `<<`, `<<<`,.
* Команды `cat`, `set`, `uniq` и `wc`.

## Ответы на упражнения с руководством <a href="#sec.103.4_01-age" id="sec.103.4_01-age"></a>

1.  Помимо текстовых файлов, команда `cat` может работать и с двоичными данными, например, отправляя содержимое блочного устройства в файл. Как с помощью перенаправления `cat` отправить содержимое устройства `/dev/sdc` в файл `sdc.img` в текущем каталоге?

    ```bash
    $ cat /dev/sdc > sdc.img
    ```
2.  Как называется стандартный канал, перенаправляемый командой `date 1> now.txt`?

    Стандартный вывод&#x20;
3.  При попытке перезаписать файл с помощью перенаправления пользователь получает сообщение об ошибке, в котором говорится, что опция `noclobber` включена. Как отключить опцию `noclobber` для текущего сеанса?

    `set +C` или `set +o noclobber`
4.  Каким будет результат выполнения команды `cat <<.>/dev/stdout`?

    Bash перейдёт в режим ввода Здесь Длкумента, а затем выйдет из него, когда в строке появится точка. Напечатанный текст будет перенаправлен в стандартный вывод (выведен на экран).

### Ответы на исследовательские упражнения <a href="#sec.103.4_01-aee" id="sec.103.4_01-aee"></a>

1.  Команда `cat /proc/cpu_info` выводит сообщение об ошибке, потому что `/proc/cpu_info` не существует. Команда `cat /proc/cpu_info 2>1` перенаправляет сообщение об ошибке куда?

    В файл с именем `1` в текущем каталоге.
2.  Можно ли будет по-прежнему удалять содержимое, отправленное в `/dev/null` , если опция `noclobber` включена для текущего сеанса оболочки?

    ДА. `/dev/null` это специальный файл, на который не влияет `noclobber`.
3.  Как перенаправить содержимое переменной `echo` в стандартный ввод команды `$USER` без использования `sha1sum`?

    ```
    $ sha1sum <<<$USER
    ```
4.  Ядро Linux сохраняет символические ссылки в `/proc/PID/fd/` на каждый файл, открытый процессом, где _PID_ — это идентификационный номер соответствующего процесса.     С помощью команды `ls -l /proc/1234/fd` можно отобразить цели всех символических ссылок в каталоге.
5.  Арифметические вычисления можно выполнять, используя только встроенные команды оболочки, но для вычислений с плавающей запятой требуются специальные программы, такие как `bc` (_базовый калькулятор_). С помощью `bc` можно даже указать количество знаков после запятой с помощью параметра `scale`. Однако `bc` принимает операции только через стандартный ввод, обычно вводимый в интерактивном режиме. Как можно отправить операцию с плавающей запятой `scale=6; 1/3` в стандартный ввод `bc` с помощью строки Here?

    ```bash
    $ bc <<<"scale=6; 1/3"
    ```
