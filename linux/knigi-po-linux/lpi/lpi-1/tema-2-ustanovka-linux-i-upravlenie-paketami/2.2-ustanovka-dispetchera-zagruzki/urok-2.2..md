# Урок 2.2.

## Введение <a href="#sec.102.2_01-in" id="sec.102.2_01-in"></a>

При включении компьютера первым запускается загрузчик. Это фрагмент кода, единственная цель которого — загрузить ядро операционной системы и передать ему управление. Ядро загрузит необходимые драйверы, инициализирует оборудование, а затем загрузит остальную часть операционной системы.

GRUB — это загрузчик, используемый в большинстве дистрибутивов Linux. Он может загружать ядро Linux или другие операционные системы, например Windows, и может обрабатывать несколько образов ядра и параметров в виде отдельных пунктов меню. Выбор ядра при загрузке осуществляется с помощью интерфейса, управляемого клавиатурой, а для редактирования параметров загрузки и параметров существует интерфейс командной строки.

Большинство дистрибутивов Linux устанавливают и настраивают GRUB (на самом деле GRUB 2) автоматически, поэтому обычному пользователю не нужно об этом задумываться. Однако системному администратору важно знать, как управлять процессом загрузки, чтобы, например, восстановить систему после сбоя загрузки после неудачного обновления ядра.

В этом уроке вы узнаете, как установить, настроить и использовать GRUB.

#### GRUB Legacy против GRUB 2 <a href="#grub_legacy_vs_grub_2" id="grub_legacy_vs_grub_2"></a>

Первоначальная версия GRUB (_Grand Unified Bootloader_), ныне известная как _GRUB Legacy_, была разработана в 1995 году в рамках проекта GNU Hurd, а затем стала загрузчиком по умолчанию во многих дистрибутивах Linux, заменив более ранние альтернативы, такие как LILO.

GRUB 2 — это полностью переработанная версия GRUB, которая стала более чистой, безопасной, надёжной и мощной. Среди множества преимуществ по сравнению с GRUB Legacy — гораздо более гибкий файл конфигурации (с большим количеством команд и условных операторов, похожих на скриптовый язык), более модульный дизайн и улучшенная локализация/интернационализация.

Также есть поддержка тем и графических меню загрузки с заставками, возможность загрузки ISO-образов LiveCD напрямую с жёсткого диска, улучшенная поддержка архитектур, отличных от x86, универсальная поддержка UUID (что упрощает идентификацию дисков и разделов) и многое другое.

GRUB Legacy больше не находится в активной разработке (последняя версия — 0.97, выпущена в 2005 году), и сегодня большинство основных дистрибутивов Linux устанавливают GRUB 2 в качестве загрузчика по умолчанию. Однако вы всё ещё можете встретить системы, использующие GRUB Legacy, поэтому важно знать, как его использовать и чем он отличается от GRUB 2.

#### Где находится загрузчик? <a href="#where_is_the_bootloader" id="where_is_the_bootloader"></a>

Исторически сложилось так, что жёсткие диски в системах, совместимых с IBM PC, были разделены на разделы по схеме MBR, созданной в 1982 году для IBM PC-DOS (MS-DOS) 2.0.

В этой схеме первый 512-байтовый сектор диска называется _главной загрузочной записью_ и содержит таблицу, описывающую разделы на диске (таблицу разделов), а также код начальной загрузки, называемый загрузчиком.

При включении компьютера этот очень маленький (из-за ограничений по размеру) код загрузчика загружается, выполняется и передаёт управление вторичному загрузчику на диске, обычно расположенному в 32-килобайтовом пространстве между MBR и первым разделом, который, в свою очередь, загружает операционную систему (системы).

На диске с разделами MBR загрузочный код GRUB устанавливается в MBR. Он загружается и передаёт управление «основному» образу, установленному между MBR и первым разделом. С этого момента GRUB может загружать остальные необходимые ресурсы (определения меню, файлы конфигурации и дополнительные модули) с диска.

Однако MBR имеет ограничения по количеству разделов (первоначально максимум 4 основных раздела, позже максимум 3 основных раздела с 1 расширенным разделом, разделённым на несколько логических разделов) и максимальному размеру диска в 2 ТБ. Чтобы преодолеть эти ограничения, была создана новая схема разбиения на разделы под названием GPT (_таблица разделов GUID GUID Partition Table_), которая является частью стандарта UEFI (_унифицированный расширяемый интерфейс встроенного ПО Unified Extensible Firmware Interface_).

Диски с разделами GPT можно использовать как на компьютерах с традиционным BIOS, так и на компьютерах с прошивкой UEFI. На компьютерах с BIOS вторая часть GRUB хранится в специальном загрузочном разделе BIOS.

В системах с прошивкой UEFI GRUB загружается прошивкой из файлов `grubia32.efi` (для 32-разрядных систем) или `grubx64.efi` (для 64-разрядных систем) из раздела, называемого ESP (_системный раздел EFI EFI System Partition_)).

## Раздел `/boot` <a href="#the_boot_partition" id="the_boot_partition"></a>

В Linux файлы, необходимые для процесса загрузки, обычно хранятся в загрузочном разделе, подключённом к корневой файловой системе и в просторечии называемом `/boot`.

В современных системах загрузочный раздел не нужен, так как загрузчики, такие как GRUB, обычно могут монтировать корневую файловую систему и искать нужные файлы в каталоге `/boot`, но это хорошая практика, так как она отделяет файлы, необходимые для процесса загрузки, от остальной файловой системы.

Этот раздел обычно является первым на диске. Это связано с тем, что в оригинальной BIOS IBM PC диски адресуются с помощью _цилиндров_, _головок_ и _секторов_  С_ylinders_, _Heads_ and _Sectors_ (CHS) с максимальным количеством 1024 цилиндров, 256 головок и 63 секторов, что приводит к максимальному размеру диска 528 МБ (504 МБ в MS-DOS). Это означает, что всё, что находится за этой отметкой, будет недоступно, если не используется другая схема адресации дисков (например, LBA, _логическая адресация блоков Logical Block Addressing_).

Таким образом, для максимальной совместимости раздел `/boot` обычно располагается в начале диска и заканчивается до 1024-го цилиндра (528 МБ), гарантируя, что компьютер всегда сможет загрузить ядро. Рекомендуемый размер этого раздела на современном компьютере составляет 300 МБ.

Другие причины для создания отдельного раздела `/boot` — шифрование и сжатие, поскольку некоторые методы могут ещё не поддерживаються GRUB 2, или если вам нужно отформатировать системный корневой раздел (`/`) с помощью неподдерживаемой файловой системы.

## **Содержимое загрузочного раздела**

Содержимое раздела `/boot` может различаться в зависимости от архитектуры системы или используемого загрузчика, но в системе на базе x86 вы обычно найдёте перечисленные ниже файлы. Большинство из них имеют суффикс `-VERSION`, где `-VERSION` — версия соответствующего ядра Linux. Так, например, файл конфигурации для ядра Linux версии `4.15.0-65-generic` будет называться `config-4.15.0-65-generic`.

Конфигурационный файл Config file

Этот файл, обычно называемый `config-VERSION` (см. пример выше), хранит параметры конфигурации ядра Linux. Этот файл генерируется автоматически при компиляции или установке нового ядра и _не должен_ изменяться пользователем напрямую.

Системная карта System map

Этот файл представляет собой справочную таблицу, сопоставляющую имена символов (например, переменных или функций) с соответствующими им позициями в памяти. Это полезно при отладке системных сбоев, известных как _паника ядра_, так как позволяет пользователю узнать, какая переменная или функция вызывалась в момент сбоя. Как и в случае с файлом конфигурации, имя обычно имеет вид `System.map-VERSION` (например, `System.map-4.15.0-65-generic`).

Ядро Linux Linux kernel

Это собственно ядро операционной системы. Название обычно выглядит как `vmlinux-VERSION` (например, `vmlinux-4.15.0-65-generic`). Вы также можете встретить название `vmlinuz` вместо `vmlinux`, где `z` в конце означает, что файл был сжат.

Начальный диск оперативной памяти Initial RAM disл

Обычно она называется `initrd.img-VERSION` и содержит минимальную корневую файловую систему, загруженную на RAM-диск, с утилитами и модулями ядра, необходимыми для того, чтобы ядро могло смонтировать реальную корневую файловую систему.

Файлы, связанные с загрузчиком

В системах с установленным GRUB они обычно находятся в `/boot/grub` и включают файл конфигурации GRUB (`/boot/grub/grub.cfg` для GRUB 2 или `/boot/grub/menu.lst` для GRUB Legacy), модули (в `/boot/grub/i386-pc`), файлы переводов (в `/boot/grub/locale`) и шрифты (в `/boot/grub/fonts`).

## GRUB 2 <a href="#grub_2" id="grub_2"></a>

## **Установка GRUB 2**

GRUB 2 можно установить с помощью утилиты `grub-install` . Если ваша система не загружается, вам нужно будет загрузиться с помощью Live-диска или аварийного диска, определить загрузочный раздел вашей системы, подключить его, а затем запустить утилиту.

{% hint style="info" %}
Приведённые ниже команды предполагают, что вы вошли в систему как пользователь root. Если нет, сначала выполните `sudo su -` для «превращения» в пользователя root. По завершении введите `exit` для выхода из системы и возврата к обычному пользователю.
{% endhint %}

Первый диск в системе обычно является _загрузочным устройством_, и вам может понадобиться узнать, есть ли на диске _загрузочный раздел_. Это можно сделать с помощью утилиты `fdisk`. Чтобы вывести список всех разделов на первом диске вашего компьютера, используйте:

```bash
# fdisk -l /dev/sda
Disk /dev/sda: 111,8 GiB, 120034123776 bytes, 234441648 sectors
Units: sectors of 1 * 512 = 512 bytes
Sector size (logical/physical): 512 bytes / 512 bytes
I/O size (minimum/optimal): 512 bytes / 512 bytes
Disklabel type: dos
Disk identifier: 0x97f8fef5

Device     Boot    Start       End   Sectors   Size Id Type
/dev/sda1  *        2048   2000895   1998848   976M 83 Linux
/dev/sda2        2002942 234440703 232437762 110,9G  5 Extended
/dev/sda5        2002944  18008063  16005120   7,6G 82 Linux swap / Solaris
/dev/sda6       18010112 234440703 216430592 103,2G 83 Linux
```

Раздел загрузки обозначается `*` в столбце «Boot». В приведенном выше примере это `/dev/sda1`.

Теперь создайте временный каталог в `/mnt` и смонтируйте раздел под ним:

```bash
# mkdir /mnt/tmp
# mount /dev/sda1 /mnt/tmp
```

Затем запустите `grub-install`, указав загрузочное _устройство_ (_не_ раздел) и каталог, в котором смонтирован загрузочный раздел. Если в вашей системе есть выделенный загрузочный раздел, команда будет следующей:

```sh
# grub-install --boot-directory=/mnt/tmp /dev/sda
```

Если вы устанавливаете программу в систему, в которой нет загрузочного раздела, а есть только каталог `/boot` в корневой файловой системе, укажите `grub-install` на него. Таким образом, команда будет выглядеть так:

```sh
# grub-install --boot-directory=/boot /dev/sda
```

## **Настройка GRUB 2**

Файл конфигурации GRUB 2 по умолчанию — `/boot/grub/grub.cfg`. Этот файл генерируется автоматически, и его редактирование вручную не рекомендуется. Чтобы внести изменения в конфигурацию GRUB, вам нужно отредактировать файл `/etc/default/grub` и затем запустить утилиту `update-grub` для создания соответствующего файла.

{% hint style="info" %}
`update-grub` обычно это сокращение от `grub-mkconfig -o /boot/grub/grub.cfg`, поэтому они дают те же результаты.
{% endhint %}

В файле `/etc/default/grub` есть несколько параметров, которые управляют поведением GRUB 2, например, ядро по умолчанию для загрузки, время ожидания, дополнительные параметры командной строки и т. д. Наиболее важные из них:

`GRUB_DEFAULT=`

Пункт меню по умолчанию для загрузки. Это может быть числовое значение (например, `0`, `1`, и т. д.), название пункта меню (например, `debian`) или `saved`, которое используется в сочетании с `GRUB_SAVEDEFAULT=`, как описано ниже. Имейте в виду, что пункты меню нумеруются с нуля, поэтому первый пункт меню — `0`, второй — `1` и т. д.

`GRUB_SAVEDEFAULT=`

Если для этого параметра установлено значение `true` и для `GRUB_DEFAULT=` установлено значение `saved`, то в качестве параметра загрузки по умолчанию всегда будет использоваться последний выбранный в меню загрузки параметр.

`GRUB_TIMEOUT=`

Тайм-аут в секундах до выбора пункта меню по умолчанию. Если установлено значение `0`, система загрузит пункт меню по умолчанию без отображения меню. Если установлено значение `-1`, система будет ждать, пока пользователь не выберет опцию, независимо от того, сколько времени это займёт.

`GRUB_CMDLINE_LINUX=`

Здесь перечислены параметры командной строки, которые будут добавлены в записи для ядра Linux.

`GRUB_CMDLINE_LINUX_DEFAULT=`

По умолчанию для каждого ядра Linux создаются две записи в меню: одна с параметрами по умолчанию и одна для восстановления. С помощью этой опции вы можете добавить дополнительные параметры, которые будут добавлены только к записи по умолчанию.

`GRUB_ENABLE_CRYPTODISK=`

Если установлено значение `y`, такие команды, как `grub-mkconfig`, `update-grub` и `grub-install`, будут искать зашифрованные диски и добавлять команды, необходимые для доступа к ним во время загрузки. Это отключает автоматическую загрузку (`GRUB_TIMEOUT=` с любым значением, кроме `-1`), поскольку для расшифровки дисков перед доступом к ним требуется парольная фраза.

## **Управление пунктами меню**

При запуске `update-grub` GRUB 2 выполнит поиск ядер и операционных систем на компьютере и создаст соответствующие пункты меню в файле `/boot/grub/grub.cfg` . Новые пункты можно добавлять вручную в файлы сценариев в каталоге `/etc/grub.d` .

Эти файлы должны быть исполняемыми и обрабатываться в числовом порядке с помощью `update-grub`. Поэтому `05_debian_theme` обрабатывается перед `10_linux` и так далее. Пользовательские пункты меню обычно добавляются в файл `40_custom`.

Базовый синтаксис для элемента меню показан ниже:

```sh
menuentry "Default OS" {
    set root=(hd0,1)
    linux /vmlinuz root=/dev/sda1 ro quiet splash
    initrd /initrd.img
}
```

Первая строка всегда начинается с `menuentry` и заканчивается `{`. Текст в кавычках будет отображаться в качестве метки записи в меню загрузки GRUB 2.

Параметр `set root` определяет диск и раздел, на котором находится корневая файловая система операционной системы. Обратите внимание, что в GRUB 2 диски нумеруются с нуля, поэтому `hd0` — это первый диск (`sda` в Linux), `hd1` — второй и так далее. Разделы, однако, нумеруются начиная с единицы. В приведённом выше примере корневая файловая система находится на первом диске (`hd0`), первом разделе (`,1`), или `sda1`.

Вместо прямого указания устройства и раздела вы также можете настроить GRUB 2 на поиск файловой системы с определённой меткой или UUID (_универсальным уникальным идентификатором_). Для этого используйте параметр `search --set=root` с последующим параметром `--label` и меткой файловой системы для поиска или `--fs-uuid` с последующим UUID файловой системы.

Вы можете найти UUID файловой системы с помощью приведенной ниже команды:

```sh
$ ls -l /dev/disk/by-uuid/
total 0
lrwxrwxrwx 1 root root 10 nov  4 08:40 3e0b34e2-949c-43f2-90b0-25454ac1595d -> ../../sda5
lrwxrwxrwx 1 root root 10 nov  4 08:40 428e35ee-5ad5-4dcb-adca-539aba6c2d84 -> ../../sda6
lrwxrwxrwx 1 root root 10 nov  5 19:10 56C11DCC5D2E1334 -> ../../sdb1
lrwxrwxrwx 1 root root 10 nov  4 08:40 ae71b214-0aec-48e8-80b2-090b6986b625 -> ../../sda1
```

В приведенном выше примере UUID для `/dev/sda1` — `ae71b214-0aec-48e8-80b2-090b6986b625`. Если вы хотите установить его в качестве корневого устройства для GRUB 2, команда будет выглядеть так: `search --set=root --fs-uuid ae71b214-0aec-48e8-80b2-090b6986b625`.

При использовании команды `search` обычно добавляется параметр `--no-floppy`, чтобы GRUB не тратил время на поиск на дискетах.

Строка `linux` указывает на расположение ядра операционной системы (в данном случае это файл `vmlinuz` в корне файловой системы). После этого вы можете передать ядру параметры командной строки.

В приведённом выше примере мы указали корневой раздел (`root=/dev/sda1`) и передали три параметра ядра: корневой раздел должен быть смонтирован только для чтения (`ro`), большинство сообщений журнала должно быть отключено (`quiet`) и должен отображаться заставка (`splash`).

Строка `initrd` указывает, где находится начальный RAM-диск. В приведённом выше примере файл `initrd.img` находится в корне файловой системы.

{% hint style="info" %}
В большинстве дистрибутивов Linux ядро и initrd на самом деле не находятся в корневом каталоге корневой файловой системы. Вместо этого это ссылки на реальные файлы внутри `/boot` каталога или раздела.
{% endhint %}

Последняя строка пункта меню должна содержать только символ `}`.

## **Взаимодействие с GRUB 2**

При загрузке системы с помощью GRUB 2 вы увидите меню с вариантами. Используйте клавиши со стрелками для выбора варианта и Enter для подтверждения и загрузки выбранного варианта.\


{% hint style="info" %}
Если вы видите только обратный отсчёт, но не меню, нажмите Shift для открытия меню.
{% endhint %}

Чтобы изменить параметр, выберите его с помощью клавиш со стрелками и нажмите E. Откроется окно редактора с содержимым `menuentry` параметра, как определено в `/boot/grub/grub.cfg`.

После редактирования параметра введите Ctrl+X или F10 для загрузки или Esc для возврата в меню.

Чтобы войти в оболочку GRUB 2, нажмите C на экране меню (или Ctrl+C) в окне редактирования). Вы увидите командную строку, подобную этой: `grub >`

Введите `help` для просмотра списка всех доступных команд или нажмите Esc для выхода из оболочки и возврата на экран меню.

{% hint style="info" %}
Помните, что это меню не появится, если для `GRUB_TIMEOUT` параметра установлено значение `0` in `/etc/default/grub`.
{% endhint %}

## **Загрузка из оболочки GRUB 2**

Вы можете использовать оболочку GRUB 2 для загрузки системы, если из-за неправильной настройки пункта меню загрузка не выполняется.

Первое, что вам нужно сделать, — это выяснить, где находится загрузочный раздел. Это можно сделать с помощью команды `ls`, которая покажет список разделов и дисков, обнаруженных GRUB 2.

```sh
grub> ls
(proc) (hd0) (hd0,msdos1)
```

В приведённом выше примере всё просто. Есть только один диск `(hd0)` с одним-единственным разделом: `(hd0,msdos1)`.

В вашей системе диски и разделы будут отличаться. В нашем примере первый раздел `hd0` называется `msdos1`, потому что диск был разделён с использованием схемы MBR. Если бы он был разделён с использованием GPT, название было бы `gpt1`.

Для загрузки Linux нам нужно ядро и начальный RAM-диск (initrd). Давайте проверим содержимое `(hd0,msdos1)`:

```sh
grub> ls (hd0,msdos1)/
lost+found/ swapfile etc/ media/ bin/ boot/ dev/ home/ lib/ lib64/ mnt/ opt/ proc/ root/ run/ sbin/ srv/ sys/ tmp/ usr/ var/ initrd.img initrd.img.old vmlinuz cdrom/
```

Вы можете добавить параметр `-l` к `ls` для получения длинного списка, похожего на тот, что вы получили бы в терминале Linux. Используйте Tab для автозаполнения имён дисков, разделов и файлов.

Обратите внимание, что у нас есть образы ядра (`vmlinuz`) и initrd (`initrd.img`) прямо в корневом каталоге. Если нет, мы могли бы проверить содержимое `/boot` с помощью `list (hd0,msdos1)/boot/`.

Теперь установите загрузочный раздел:

```sh
grub> set root=(hd0,msdos1)
```

Загрузите ядро Linux с помощью команды `linux`, за которой следует путь к ядру и параметр `root=`, указывающий ядру, где находится корневая файловая система операционной системы.

```sh
grub> linux /vmlinuz root=/dev/sda1
```

Загрузите начальный RAM-диск с помощью `initrd`, а затем укажите полный путь к файлу `initrd.img`:

```bash
grub> initrd /initrd.img
```

Теперь загрузите систему с помощью `boot`.

## **Загрузка из командной строки Rescue Shell**

В случае сбоя загрузки GRUB 2 может загрузить аварийную оболочку — упрощённую версию оболочки, о которой мы упоминали ранее. Вы узнаете её по командной строке, которая отображается как `grub rescue>`.

Процесс загрузки системы из этой оболочки почти такой же, как и в предыдущем случае. Однако вам нужно будет загрузить несколько модулей GRUB 2, чтобы всё работало.

После определения загрузочного раздела (с помощью `ls`, как показано выше) используйте команду `set prefix=` с полным путём к каталогу, содержащему файлы GRUB 2. Обычно `/boot/grub`. В нашем примере:

```sh
grub rescue> set prefix=(hd0,msdos1)/boot/grub
```

Теперь загрузите модули `normal` и `linux` с помощью `insmod` команды:

```sh
grub rescue> insmod normal
grub rescue> insmod linux
```

Затем установите загрузочный раздел с помощью `set root=` как описано выше, загрузите ядро Linux (с помощью `linux`), начальный RAM-диск (`initrd`) и попробуйте загрузиться с помощью `boot`.

## GRUB Legacy <a href="#grub_legacy" id="grub_legacy"></a>

## **Установка GRUB Legacy из работающей системы**

Чтобы установить GRUB Legacy на диск из работающей системы, мы воспользуемся утилитой `grub-install`. Базовая команда — `grub-install DEVICE`, где `DEVICE` — это диск, на который вы хотите установить GRUB Legacy. Например, `/dev/sda`.

```sh
# grub-install /dev/sda
```

Обратите внимание, что вам нужно указать _устройство_, на котором будет установлен GRUB Legacy, например `/dev/sda/`, _а не раздел_, как в `/dev/sda1`.

По умолчанию GRUB скопирует необходимые файлы в каталог `/boot` на указанном устройстве. Если вы хотите скопировать их в другой каталог, используйте параметр `--boot-directory=` и укажите полный путь к месту, куда следует скопировать файлы.

**Установка GRUB Legacy из оболочки GRUB**

Если по какой-то причине вы не можете загрузить систему и вам нужно переустановить GRUB Legacy, вы можете сделать это из оболочки GRUB на загрузочном диске GRUB Legacy.

В оболочке GRUB (введите `c` в меню загрузки, чтобы перейти к подсказке `grub>` ) первым шагом будет установка загрузочного устройства, на котором находится каталог `/boot` . Например, если этот каталог находится в первом разделе первого диска, команда будет выглядеть так:

```sh
grub> root (hd0,0)
```

Если вы не знаете, на каком устройстве находится каталог `/boot`, вы можете попросить GRUB найти его с помощью команды `find`, как показано ниже:

```sh
grub> find /boot/grub/stage1
 (hd0,0)
```

Затем установите загрузочный раздел, как описано выше, и используйте команду `setup` для установки GRUB Legacy в MBR и копирования необходимых файлов на диск:

```sh
grub> setup (hd0)
```

По завершении перезагрузите систему, и она должна загрузиться нормально.

## **Настройка устаревших элементов меню GRUB и настроек**

Записи и настройки меню GRUB Legacy хранятся в файле `/boot/grub/menu.lst`. Это простой текстовый файл со списком команд и параметров, который можно редактировать непосредственно в вашем любимом текстовом редакторе.

Строки, начинающиеся с `#`, считаются комментариями, а пустые строки игнорируются.

Пункт меню содержит как минимум три команды. Первая из них, `title` устанавливает заголовок операционной системы на экране меню. Вторая, `root` сообщает GRUB Legacy, с какого устройства или раздела следует загрузиться.

Третья запись `kernel` указывает полный путь к образу ядра, который должен быть загружен при выборе соответствующей записи. Обратите внимание, что этот путь относится к устройству, указанному в параметре `root`

Ниже приведен простой пример:

```sh
# This line is a comment
title My Linux Distribution
root (hd0,0)
kernel /vmlinuz root=/dev/hda1
```

В отличие от GRUB 2, в GRUB Legacy оба диска _и_ раздела нумеруются с нуля. Таким образом, команда `root (hd0,0)` установит загрузочный раздел как первый раздел (`0`) первого диска (`hd0`).

Вы можете опустить оператор `root`, если укажете загрузочное устройство перед путём в команде `kernel` . Синтаксис тот же, поэтому:

```sh
kernel (hd0,0)/vmlinuz root=dev/hda1
```

эквивалентен:

```bash
root (hd0,0)
kernel /vmlinuz root=/dev/hda1
```

Оба загрузят файл `vmlinuz` из корневого каталога (`/`) первого раздела первого диска (`hd0,0`).

Параметр `root=/dev/hda1` после команды `kernel` сообщает ядру Linux, какой раздел следует использовать в качестве корневой файловой системы. Это параметр ядра Linux, а не устаревшая команда GRUB.

{% hint style="info" %}
Чтобы узнать больше о параметрах ядра, см. [https://www.kernel.org/doc/html/v4.14/admin-guide/kernel-parameters.html](https://www.kernel.org/doc/html/v4.14/admin-guide/kernel-parameters.html).
{% endhint %}

Возможно, вам потребуется указать расположение начального образа RAM-диска для операционной системы с помощью параметра `initrd` . Полный путь к файлу можно указать так же, как в параметре `kernel` , а перед путём можно указать устройство или раздел, например:

```bash
# This line is a comment
title My Linux Distribution
root (hd0,0)
kernel /vmlinuz root=/dev/hda1
initrd /initrd.img
```

GRUB Legacy имеет модульную структуру, в которой модули (обычно хранящиеся в виде файлов `.mod` в `/boot/grub/i386-pc`) могут быть загружены для добавления дополнительных функций, таких как поддержка необычного оборудования, файловых систем или новых алгоритмов сжатия.

Модули загружаются с помощью команды `module` с указанием полного пути к соответствующему файлу `.mod` . Имейте в виду, что, как и в случае с ядрами и образами initrd, этот путь указывается относительно устройства, указанного в команде `root` .

Приведённый ниже пример загрузит модуль `915resolution`, необходимый для корректной установки разрешения кадрового буфера в системах с видеочипами Intel серии 800 или 900.

```bash
module /boot/grub/i386-pc/915resolution.mod
```

## **Chainloading других ОС**

GRUB Legacy можно использовать для загрузки неподдерживаемых операционных систем, таких как Windows, с помощью процесса, называемого **Chainloading**. Сначала загружается GRUB Legacy, а при выборе соответствующей опции загружается загрузчик нужной системы.

Типичная запись для окон с цепной загрузкой будет выглядеть следующим образом:

```bash
# Load Windows
title Windows XP
root (hd0,1)
makeactive
chainload +1
boot
```

Давайте рассмотрим каждый параметр. Как и прежде, `root (hd0,1)` указывает устройство и раздел, в котором находится загрузчик операционной системы, которую мы хотим загрузить. В этом примере — _второй_ раздел первого диска.

`makeactive`

будет установлен флаг, указывающий на то, что это активный раздел. Это работает только с основными разделами DOS.

`chainload +1`

сообщает GRUB о необходимости загрузить первый сектор загрузочного раздела. Обычно именно там находятся загрузчики.

`boot`

запустится загрузчик и загрузится соответствующая операционная система.

## Ответы на исследовательские упражнения <a href="#sec.102.2_01-aee" id="sec.102.2_01-aee"></a>

1.  Представьте, что пользователь настраивает GRUB Legacy для загрузки со второго раздела первого диска. Он пишет следующее пользовательское меню:

    ```bash
    title My Linux Distro
    root (hd0,2)
    kernel /vmlinuz root=/dev/hda1
    initrd /initrd.img
    ```

    Однако система не загружается. Что не так?

    Неверный загрузочный раздел. Помните, что, в отличие от GRUB 2, GRUB Legacy считает разделы с _нуля_. Таким образом, правильная команда для второго раздела первого диска должна быть `root (hd0,1)`.
2.  Представьте, что у вас есть диск с идентификатором `/dev/sda` с несколькими разделами. С помощью какой команды можно узнать, какой раздел является загрузочным в системе?

    Используйте `fdisk -l /dev/sda`. Раздел загрузки будет отмечен звёздочкой (`*`) в списке.
3.  Какую команду можно использовать для определения UUID раздела?

    Используйте `ls -la /dev/disk/by-uuid/` и ищите UUID, который указывает на раздел.
4.  Рассмотрим следующую запись для GRUB 2

    ```bash
    menuentry "Default OS" {
        set root=(hd0,1)
        linux /vmlinuz root=/dev/sda1 ro quiet splash
        initrd /initrd.img
    }
    ```

    Измените его так, чтобы система загружалась с диска с UUID `5dda0af3-c995-481a-a6f3-46dcd3b6998d`

    Вам нужно будет изменить оператор `set root` . Вместо указания диска и раздела укажите grub искать раздел с нужным UUID.

    ```bash
    menuentry "Default OS" {
        search --set=root --fs-uuid 5dda0af3-c995-481a-a6f3-46dcd3b6998d
        linux /vmlinuz root=/dev/sda1 ro quiet splash
        initrd /initrd.img
    }
    ```
5.  Как настроить GRUB 2 на ожидание в течение 10 секунд перед загрузкой пункта меню по умолчанию?

    Добавьте параметр `GRUB_TIMEOUT=10` в `/etc/default/grub`.
6.  Какие команды нужно ввести в устаревшей оболочке GRUB, чтобы установить GRUB на первый раздел второго диска?



    ```bash

    grub> setup (hd1)
    ```
