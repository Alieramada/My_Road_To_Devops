# Урок 4.4.

## Введение <a href="#sec.104.5_01-in" id="sec.104.5_01-in"></a>

Будучи многопользовательской системой, Linux должен каким-то образом отслеживать, кому принадлежит каждый файл и может ли пользователь выполнять действия с файлом. Это необходимо для обеспечения конфиденциальности пользователей, которые могут захотеть сохранить содержимое своих файлов в тайне, а также для обеспечения совместной работы, когда определённые файлы доступны нескольким пользователям.

Это делается с помощью трёхуровневой системы разрешений. Каждый файл на диске принадлежит пользователю и группе пользователей и имеет три набора разрешений: один для владельца, один для группы, которой принадлежит файл, и один для всех остальных. В этом уроке вы узнаете, как запрашивать разрешения для файла, что означают эти разрешения и как ими управлять.

## Запрос информации о файлах и каталогах <a href="#sec.104.5_01-qi" id="sec.104.5_01-qi"></a>

Команда `ls` используется для вывода списка содержимого любого каталога. В этой базовой форме вы видите только имена файлов:

```bash
$ ls
Another_Directory picture.jpg text.txt
```

Но для каждого файла доступно гораздо больше информации, включая его тип, размер, владельца и многое другое. Чтобы увидеть эту информацию, вы должны запросить `ls` «длинный» список с помощью параметра `-l`:

```bash
$ ls -l
total 536
drwxrwxr-x 2 carol carol 4096 Dec 10 15:57 Another_Directory
-rw------- 1 carol carol 539663 Dec 10 10:43 picture.jpg
-rw-rw-r-- 1 carol carol 1881 Dec 10 15:57 text.txt
```

Каждый столбец в приведённой выше таблице имеет своё значение. Давайте рассмотрим столбцы, имеющие отношение к этому уроку.

* В _первом_ столбце списка отображается тип файла и права доступа. Например, в `drwxrwxr-x`:
  * Первый символ, `d`, указывает на тип файла.
  * Следующие три символа, `rwx`, указывают на разрешения для владельца файла, также называемого _пользователем_ или `u`.
  * Следующие три символа, `rwx`, указывают на права _группы_, владеющей файлом, также называемой `g`.
  * Последние три символа, `r-x`, указывают на разрешения для всех остальных, также известные как _другие_ или `o`.

{% hint style="info" %}
Также часто можно услышать, что набор разрешений _others_ называют _мировыми_ разрешениями, например: «У всех остальных в мире есть эти разрешения».
{% endhint %}

* В _третьем_ и _четвёртом_ столбцах отображается информация о владельцах: соответственно, пользователе и группе, которым принадлежит файл.
* В _седьмом_ и последнем столбце указано имя файла.

Во _втором_ столбце указано количество жёстких ссылок, ведущих на этот файл. В _пятом_ столбце указан размер файла. В _шестом_ столбце указана дата и время последнего изменения файла. Но эти столбцы не имеют отношения к текущей теме.

## Как насчет каталогов? <a href="#what_about_directories" id="what_about_directories"></a>

Если вы попытаетесь запросить информацию о каталоге с помощью `ls -l`, вместо этого вы увидите список содержимого каталога:

```bash
$ ls -l Another_Directory/
total 0
-rw-r--r-- 1 carol carol 0 Dec 10 17:59 another_file.txt
```

Чтобы избежать этого и запросить информацию о самом каталоге, добавьте параметр `-d` к `ls`:

```bash
$ ls -l -d Another_Directory/
drwxrwxr-x 2 carol carol 4096 Dec 10 17:59 Another_Directory/
```

## Просмотр скрытых файлов <a href="#viewing_hidden_files" id="viewing_hidden_files"></a>

Список каталогов, который мы получили с помощью `ls -l` ранее, является неполным:

```bash
$ ls -l
total 544
drwxrwxr-x 2 carol carol   4096 Dec 10 17:59 Another_Directory
-rw------- 1 carol carol 539663 Dec 10 10:43 picture.jpg
-rw-rw-r-- 1 carol carol   1881 Dec 10 15:57 text.txt
```

В этом каталоге есть ещё три файла, но они скрыты. В Linux файлы, имена которых начинаются с точки (`.`), автоматически скрыты. Чтобы их увидеть, нужно добавить параметр `-a` к `ls`:

```bash
$ ls -l -a
total 544
drwxrwxr-x 3 carol carol   4096 Dec 10 16:01 .
drwxrwxr-x 4 carol carol   4096 Dec 10 15:56 ..
drwxrwxr-x 2 carol carol   4096 Dec 10 17:59 Another_Directory
-rw------- 1 carol carol 539663 Dec 10 10:43 picture.jpg
-rw-rw-r-- 1 carol carol   1881 Dec 10 15:57 text.txt
-rw-r--r-- 1 carol carol      0 Dec 10 16:01 .thisIsHidden
```

Файл `.thisIsHidden` просто скрыт, потому что его имя начинается с `.`.

Однако каталоги `.` и `..` являются специальными. `.` — это указатель на текущий каталог. А `..` — это указатель на родительский каталог, содержащий текущий. В Linux каждый каталог содержит как минимум эти два каталога.

{% hint style="info" %}
Вы можете комбинировать несколько параметров для `ls` (и многих других команд Linux). `ls -l -a` можно, например, записать как `ls -la`.
{% endhint %}

## Понимание типов файлов <a href="#understanding_filetypes" id="understanding_filetypes"></a>

Мы уже упоминали, что первая буква в каждом выводе `ls -l` описывает тип файла. Три наиболее распространённых типа файлов:

`-` (обычный файл)

Файл может содержать любые данные и помогать управлять этими данными. Файлы можно изменять, перемещать, копировать и удалять.

`d` (справочник)

Каталог содержит другие файлы или каталоги и помогает организовать файловую систему. Технически каталоги — это особый вид файлов.

`l` (символическая ссылка)

Этот «файл» является указателем на другой файл или каталог в другой части файловой системы.

Помимо них, есть ещё три типа файлов, о которых вам следует хотя бы знать, но которые не рассматриваются в этом уроке:

`b` (блочное устройство)

Этот файл обозначает виртуальное или физическое устройство, обычно диски или другие устройства хранения данных, например первый жёсткий диск, который может быть обозначен как `/dev/sda`.

`c` (символьное устройство)

Этот файл представляет собой виртуальное или физическое устройство. Терминалы (например, главный терминал на `/dev/ttyS0`) и последовательные порты являются распространёнными примерами символьных устройств.

`s` (сокет)

Сокеты служат "каналами” передачи информации между двумя программами.

{% hint style="info" %}
Не изменяйте разрешения для блочных устройств, символьных устройств или сокетов, если вы не знаете, что делаете. Это может привести к сбоям в работе вашей системы!
{% endhint %}

## Понимание Разрешений <a href="#understanding_permissions" id="understanding_permissions"></a>

В выводе `ls -l` права доступа к файлу отображаются сразу после типа файла в виде трёх групп по три символа в каждой в порядке `r`, `w` и `x`. Вот что они означают. Имейте в виду, что тире `-` означает отсутствие прав доступа.

## **Права доступа к файлам**

`r`

Обозначает _чтение_ и имеет восьмеричное значение `4` (не волнуйтесь, мы скоро обсудим восьмеричные числа). Это означает разрешение на открытие файла и чтение его содержимого.

`w`

Обозначает _запись_ и имеет восьмеричное значение `2`. Это означает разрешение на редактирование или удаление файла.

`x`

Обозначает _выполнение_ и имеет восьмеричное значение `1`. Это означает, что файл можно запустить как исполняемый файл или скрипт.

Так, например, файл с правами доступа `rw-` можно читать и записывать, но нельзя выполнить.

## **Права доступа к каталогам**

`r`

Обозначает _чтение_ и имеет восьмеричное значение `4`. Это означает разрешение на чтение содержимого каталога, например имён файлов. Но это _не_ подразумевает разрешение на чтение самих файлов.

`w`

Обозначает _запись_ и имеет восьмеричное значение `2`. Это означает разрешение на создание или удаление файлов в каталоге.

Имейте в виду, что вы не сможете внести эти изменения только с помощью разрешений _на запись_, вам также потребуется разрешение _на выполнение_ (`x`) для перехода в каталог.

`x`

Обозначает _выполнение_ и имеет восьмеричное значение `1`. Это означает разрешение на вход в каталог, но не на просмотр его файлов (для этого нужен `r`).

Последняя часть о каталогах может показаться немного запутанной. Давайте представим, например, что у вас есть каталог с именем `Another_Directory` со следующими разрешениями

```bash
$ ls -ld Another_Directory/
d--x--x--x 2 carol carol 4,0K Dec 20 18:46 Another_Directory
```

Также представьте, что внутри этого каталога у вас есть сценарий оболочки с именем `hello.sh`:

```bash
-rwxr-xr-x 1 carol carol 33 Dec 20 18:46 hello.sh
```

Если вы являетесь пользователем `carol` и попытаетесь вывести список содержимого `Another_Directory`, вы получите сообщение об ошибке, так как у вашего пользователя нет прав на чтение этого каталога:

```bash
$ ls -l Another_Directory/
ls: cannot open directory 'Another_Directory/': Permission denied
```

Однако у пользователя `carol` _есть_ права на выполнение, что означает, что он может войти в каталог. Таким образом, пользователь `carol` может получить доступ к файлам внутри каталога, если у него есть правильные права _на соответствующий файл_. Предположим, что у пользователя есть полные права (`rwx`) на скрипт `hello.sh`. Тогда он _может_ запустить скрипт, даже если _не может_ прочитать содержимое содержащего его каталога, если ему известно полное имя файла:

```bash
$ sh Another_Directory/hello.sh
Hello LPI World!
```

Как мы уже говорили, разрешения указываются последовательно: сначала для владельца файла, затем для группы владельцев, а затем для других пользователей. Всякий раз, когда кто-то пытается выполнить действие с файлом, разрешения проверяются таким же образом.

Сначала система проверяет, является ли текущий пользователь владельцем файла, и если это так, то применяет только первый набор разрешений. В противном случае она проверяет, принадлежит ли текущий пользователь к группе, владеющей файлом. В этом случае применяется только второй набор разрешений. В любом другом случае система применит третий набор разрешений.

Это означает, что если текущий пользователь является владельцем файла, то действуют только разрешения владельца, даже если разрешения группы или другие разрешения более широкие, чем разрешения владельца.

## Изменение прав доступа к файлам <a href="#sec.104.5_01-mp" id="sec.104.5_01-mp"></a>

Команда `chmod` используется для изменения прав доступа к файлу и принимает как минимум два параметра: первый описывает, какие права доступа нужно изменить, а второй указывает на файл или каталог, к которому будут применены изменения. Помните, что только владелец файла или системный администратор (root) может изменять права доступа к файлу.

Разрешения на изменение могут быть описаны двумя разными способами, или «режимами».

Первый режим, называемый _символическим_, обеспечивает детальный контроль, позволяя добавлять или отменять одно разрешение, не изменяя другие в наборе. Другой режим, называемый _восьмеричным_, проще в запоминании и быстрее в использовании, если вы хотите установить все значения разрешений сразу.

Оба режима приведут к одному и тому же конечному результату. Так, например, команды:

```bash
$ chmod ug+rw-x,o-rwx text.txt
```

и

```bash
$ chmod 660 text.txt 
```

будет выдан точно такой же результат - файл с установленными разрешениями:

```bash
-rw-rw---- 1 carol carol  765 Dec 20 21:25 text.txt
```

Теперь давайте посмотрим, как работает каждый режим.\


## **Символический режим**

При описании того, какие разрешения нужно изменить в _символическом режиме_, первый символ (символы) указывает (указывают), чьи разрешения вы будете изменять: пользователя (`u`), группы (`g`), других (`o`) и/или всех (`a`).

Затем вам нужно указать команде, что нужно сделать: вы можете предоставить разрешение (`+`), отозвать разрешение (`-`), или установить для него определённое значение (`=`).

Наконец, вы указываете, какое разрешение вы хотите использовать: чтение (`r`), запись (`w`), или выполнение (`x`).

Например, предположим, что у нас есть файл с именем `text.txt` со следующими правами доступа:

```bash
$ ls -l text.txt
-rw-r--r-- 1 carol carol 765 Dec 20 21:25 text.txt
```

Если вы хотите предоставить права на запись членам группы, владеющей файлом, используйте параметр `g+w` . Будет проще, если вы представите это так: «Для группы (`g` ) предоставить (`+`) права на запись (`w`)». Таким образом, команда будет выглядеть так:

```bash
$ chmod g + w text.txt 
```

Давайте проверим результат с помощью `ls`:

```bash
$ ls -l text.txt
-rw-rw-r-- 1 carol carol 765 Dec 20 21:25 text.txt
```

Вы хотите удалить права на чтение для владельца того же файла? Представьте, что вы говорите: «Для пользователя (`u`), отмените (`-`) права на чтение (`r`)». Таким образом, параметр будет выглядеть так: `u-r`

```bash
$ chmod u-r text.txt
$ ls -l text.txt
--w-rw-r-- 1 carol carol 765 Dec 20 21:25 text.txt
```

Что, если мы хотим установить права доступа в точности как `rw-` для всех? Тогда представьте это так: «Для всех (`a`), установить в точности (`=`) чтение (`r`), запись (`w`), и запрет на выполнение (`-`)». Итак:

```bash
$ chmod a=rw- text.txt
$ ls -l text.txt
-rw-rw-rw- 1 carol carol 765 Dec 20 21:25 text.txt
```

Конечно, можно изменить несколько разрешений одновременно. В этом случае разделите их запятыми (`,`):

```bash
$ chmod u+rwx,g-x text.txt
$ ls -lh text.txt
-rwxrw-rw- 1 carol carol 765 Dec 20 21:25 text.txt
```

Приведённый выше пример можно прочитать так: «Для пользователя (`u`), предоставить (`+`) права на чтение, запись и выполнение (`rwx`), для группы (`g`), отозвать (`-`) права на выполнение (`x`)».

При запуске в каталоге `chmod` изменяет только права доступа к каталогу. `chmod` Также есть рекурсивный режим, который полезен, если вы хотите изменить права доступа ко «всем файлам в каталоге и его подкаталогах». Чтобы использовать его, добавьте параметр `-R` после названия команды перед правами доступа, которые нужно изменить:

```bash
$ chmod -R u+rwx Another_Directory/
```

Эту команду можно прочитать так: «Рекурсивно (`-R`), для пользователя (`u`), предоставить (`+`) права на чтение, запись и выполнение (`rwx`)».

{% hint style="info" %}
Будьте осторожны и дважды подумайте, прежде чем использовать переключатель `-R`, так как можно легко изменить права доступа к файлам и каталогам, которые вы не хотите изменять, особенно к каталогам с большим количеством файлов и подкаталогов.
{% endhint %}

## **Восьмеричный режим**

В _восьмеричном режиме_ права доступа указываются по-другому: в виде трёхзначного значения в восьмеричной системе счисления.

У каждого разрешения есть соответствующее значение, и они указываются в следующем порядке: сначала идёт чтение (`r`), которое равно `4`, затем запись (`w`), которая равна `2`, и, наконец, выполнение (`x`), которое равно `1`. Если разрешения нет, используйте нулевое значение (`0`). Таким образом, разрешение `rwx` будет равно `7` (`4+2+1`), а `r-x` будет равно `5` (`4+0+1`).

Первая из трёх цифр в наборе разрешений обозначает разрешения для пользователя (`u`), вторая — для группы (`g`), а третья — для других пользователей (`o`). Если мы хотим установить для файла разрешения `rw-rw----`, то восьмеричное значение будет `660`:

```bash
$ chmod 660 text.txt
$ ls -l text.txt
-rw-rw---- 1 carol carol 765 Dec 20 21:25 text.txt
```

Кроме того, синтаксис в _восьмеричном режиме_ такой же, как и в _символическом режиме_. Первый параметр обозначает разрешения, которые вы хотите изменить, а второй параметр указывает на файл или каталог, в котором будут внесены изменения.

{% hint style="info" %}
Если значение разрешения _нечетное_, файл, несомненно, является исполняемым!
{% endhint %}

Какой синтаксис следует использовать? _Восьмеричный режим_ рекомендуется, если вы хотите изменить права доступа на определённое значение, например `640` (`rw- r-- ---`).

_Символический режим_ более полезен, если вы хотите изменить только одно значение, независимо от текущих разрешений для файла. Например, вы можете добавить пользователю разрешение на выполнение, используя только `chmod u+x script.sh` без учёта или даже не затрагивая текущие разрешения для группы и других пользователей.

## Изменение владельца файла <a href="#sec.104.5_01-mo" id="sec.104.5_01-mo"></a>

Команда `chown` используется для изменения владельца файла или каталога. Синтаксис довольно прост:

```bash
chown USERNAME:GROUPNAME FILENAME
```

Например, давайте проверим файл с именем `text.txt`:

```bash
$ ls -l text.txt
-rw-rw---- 1 carol carol 1881 Dec 10 15:57 text.txt
```

Пользователь, которому принадлежит файл, — `carol`, а группа — `carol`. Теперь мы изменим группу, которой принадлежит файл, на другую группу, например `students`:

```bash
$ chown carol:students text.txt
$ ls -l text.txt
-rw-rw---- 1 carol students 1881 Dec 10 15:57 text.txt
```

Имейте в виду, что пользователь, которому принадлежит файл, не обязательно должен входить в группу, которой принадлежит файл. В приведённом выше примере пользователю `carol` не обязательно быть членом группы `students`.

Если вы не хотите их менять, то можете не указывать набор разрешений пользователя или группы. Таким образом, чтобы изменить только группу, владеющую файлом, вы бы использовали `chown :students text.txt`. Чтобы изменить только пользователя, команда будет выглядеть как `chown carol: text.txt` или просто `chown carol text.txt`. В качестве альтернативы вы можете использовать команду `chgrp students text.txt`.

Если вы не являетесь системным администратором (пользователем с правами root), вы не можете изменить владельца файла на другого пользователя или группу, к которым вы не относитесь. Если вы попытаетесь это сделать, вы получите сообщение об ошибке `Operation not permitted`.

## Запрос группы <a href="#querying_groups" id="querying_groups"></a>

Прежде чем менять владельца файла, может быть полезно узнать, какие группы существуют в системе, какие пользователи являются членами группы и к каким группам принадлежит пользователь.

Чтобы узнать, какие группы существуют в вашей системе, введите `getent group`. Результат будет похож на этот (результат сокращён):

```bash
$ getent group
root:x:0:
daemon:x:1:
bin:x:2:
sys:x:3:
adm:x:4:syslog,rigues
tty:x:5:rigues
disk:x:6:
lp:x:7:
mail:x:8:
news:x:9:
uucp:x:10:rigues
```

Если вы хотите узнать, к каким группам принадлежит пользователь, добавьте имя пользователя в качестве параметра в `groups`:

```bash
$ groups carol
carol : carol students cdrom sudo dip plugdev lpadmin sambashare
```

Чтобы сделать обратное (посмотреть, какие пользователи входят в группу), используйте `groupmems`. Параметр `-g` указывает на группу, а `-l` выводит список всех её участников:

```bash
# groupmems -g cdrom -l
carol
```

## Разрешения по умолчанию <a href="#default_permissions" id="default_permissions"></a>

Давайте проведём эксперимент. Откройте окно терминала и создайте пустой файл с помощью следующей команды:

```bash
$ touch testfile
```

Теперь давайте посмотрим на разрешения для этого файла. В вашей системе они _могут_ отличаться, но предположим, что они выглядят следующим образом:

```bash
$ ls -lh testfile
-rw-r--r-- 1 carol carol 0 jul 13 21:55 testfile
```

Разрешения: `rw-r—​r--`: _чтение_ и _запись_ для пользователя, _чтение_ для группы и других пользователей или `644` в восьмеричном режиме. Теперь попробуйте создать каталог:

```bash
$ mkdir testdir
$ ls -lhd testdir
drwxr-xr-x 2 carol carol 4,0K jul 13 22:01 testdir
```

Теперь разрешения выглядят так: `rwxr-xr-x` : _чтение_, _запись_ и _выполнение_ для пользователя, _чтение_ и _выполнение_ для группы и других пользователей или `755` в восьмеричном режиме.

Независимо от того, в какой части файловой системы вы находитесь, каждый создаваемый вами файл или каталог будет иметь те же права доступа. Вы когда-нибудь задумывались, откуда они берутся?

Они берутся из _пользовательской маски_ или `umask`, которая устанавливает разрешения по умолчанию для каждого созданного файла. Текущие значения можно проверить с помощью команды `umask`:

```bash
$ umask
0022
```

Но это не похоже на `rw-r—​r--` или даже `644`. Может быть, нам стоит попробовать с параметром `-S` для вывода в символическом режиме:

```bash
$ umask -S
u=rwx,g=rx,o=rx
```

Это те же разрешения, которые были у нашего тестового каталога в одном из приведённых выше примеров. Но почему при создании файла разрешения были другими?

Ну, нет смысла устанавливать глобальные права на выполнение для всех файлов по умолчанию, верно? Директориям нужны права на выполнение (иначе вы не сможете в них войти), а файлам — нет, поэтому они их не получают. Отсюда и `rw-r—​r--`.

Помимо отображения разрешений по умолчанию, `umask` также можно использовать для их изменения в текущем сеансе оболочки. Например, если мы используем команду:

```bash
$ umask u=rwx,g=rwx,o=
```

Каждый новый каталог будет наследовать права доступа `rwxrwx---`, а каждый файл `rw-rw----` (поскольку они не получают права на выполнение). Если вы повторите приведённые выше примеры, чтобы создать `testfile` и `testdir` и проверить права доступа, вы должны получить:

```bash
$ ls -lhd test*
drwxrwx--- 2 carol carol 4,0K jul 13 22:25 testdir
-rw-rw---- 1 carol carol    0 jul 13 22:25 testfile
```

А если вы проверите `umask` без параметра `-S` (символический режим), то получите:

```bash
$ umask
0007
```

Результат выглядит непривычно, потому что используются другие значения. Вот таблица с каждым значением и его соответствующим смыслом:

| Значение | Разрешение для файлов | Разрешение для каталогов |
| -------- | --------------------- | ------------------------ |
| `0`      | `rw-`                 | `rwx`                    |
| `1`      | `rw-`                 | `rw-`                    |
| `2`      | `r--`                 | `r-x`                    |
| `3`      | `r--`                 | `r--`                    |
| `4`      | `-w-`                 | `-wx`                    |
| `5`      | `-w-`                 | `-w-`                    |
| `6`      | `---`                 | `--x`                    |
| `7`      | `---`                 | `---`                    |

Как видите, `007` соответствует `rwxrwx---`, как мы и просили. Ведущий ноль можно не учитывать.

## Специальные разрешения <a href="#special_permissions" id="special_permissions"></a>

Помимо разрешений на чтение, запись и выполнение для пользователя, группы и других пользователей, каждый файл может иметь три других _специальных разрешения_, которые могут изменить работу каталога или программы. Они могут быть указаны в символическом или восьмеричном режиме и выглядят следующим образом:

## **Sticky Bit**

Битовая маска, также называемая _флагом ограниченного удаления_, имеет восьмеричное значение `1` и в символическом режиме представлена `t` . Это относится только к каталогам и не влияет на обычные файлы. В Linux это не позволяет пользователям удалять или переименовывать файлы в каталоге, если они не являются владельцами этого файла или каталога.

Каталоги с установленным **Sticky Bit** показывают `t` вместо `x` в разрешениях для _других_ пользователей в выводе `ls -l`:

```bash
$ ls -ld Sample_Directory/
drwxr-xr-t 2 carol carol 4096 Dec 20 18:46 Sample_Directory/
```

В восьмеричном режиме специальные разрешения указываются с помощью четырёхзначного обозначения, где первая цифра обозначает специальное разрешение, на которое нужно воздействовать. Например, чтобы установить флаг «только чтение» (значение `1`) для каталога `Another_Directory` в восьмеричном режиме с разрешениями `755`, команда будет выглядеть так:

```bash
$ chmod 1755 Another_Directory
$ ls -ld Another_Directory
drwxr-xr-t 2 carol carol 4,0K Dec 20 18:46 Another_Directory
```

**Set GID**

**Set** GID, также известная как SGID или установка идентификатора группы, имеет восьмеричное значение `2` и в символическом режиме представлена `s` в разрешениях _группы_. Это можно применить к исполняемым файлам или каталогам. В случае с файлами это позволит запустить процесс с правами группы, которой принадлежит файл. В случае с каталогами это позволит каждому созданному в нём файлу или каталогу наследовать группу от родительского каталога.

Файлы и каталоги с битом SGID показывают `s` вместо `x` в разрешениях для _группы_ в выводе `ls -l`:

```bash
$ ls -l test.sh
-rwxr-sr-x 1 carol root 33 Dec 11 10:36 test.sh
```

Чтобы добавить права SGID к файлу в символическом режиме, выполните следующую команду:

```bash
$ chmod g+s test.sh
$ ls -l test.sh
-rwxr-sr-x 1 carol root     33 Dec 11 10:36 test.sh
```

Следующий пример поможет вам лучше понять, как SGID влияет на каталог. Предположим, у нас есть каталог с именем `Sample_Directory`, принадлежащий пользователю `carol` и группе `users` со следующей структурой разрешений:

```bash
$ ls -ldh Sample_Directory/
drwxr-xr-x 2 carol users 4,0K Jan 18 17:06 Sample_Directory/
```

Теперь давайте перейдём в этот каталог и с помощью команды `touch` создадим в нём пустой файл. В результате получится следующее:

```bash
$ cd Sample_Directory/
$ touch newfile
$ ls -lh newfile
-rw-r--r-- 1 carol carol 0 Jan 18 17:11 newfile
```

Как мы видим, файл принадлежит пользователю `carol` и группе `carol`. Но если бы в каталоге было установлено разрешение SGID, результат был бы другим. Сначала давайте добавим бит SGID в `Sample_Directory` и проверим результаты:

```bash
$ sudo chmod g+s Sample_Directory/
$ ls -ldh Sample_Directory/
drwxr-sr-x 2 carol users 4,0K Jan 18 17:17 Sample_Directory/
```

`s` в разрешениях группы указывает на то, что установлен бит SGID. Теперь мы перейдём в этот каталог и снова создадим пустой файл с помощью команды `touch`:

```bash
$ cd Sample_Directory/
$ touch emptyfile
$ ls -lh emptyfile
 -rw-r--r-- 1 carol users 0 Jan 18 17:20 emptyfile
```

Группа, которой принадлежит файл, — `users`. Это связано с тем, что бит SGID сделал файл наследующим группу владельца родительского каталога, которой является `users`.

**Set UID**

SUID, также известный как Set User ID, имеет восьмеричное значение `4` и отображается как `s` в разрешениях _пользователя_ в символическом режиме. Он применяется только к файлам и не влияет на каталоги. Его поведение аналогично биту SGID, но процесс будет выполняться с привилегиями _пользователя_, которому принадлежит файл. Файлы с битом SUID отображаются как `s` вместо `x` в разрешениях пользователя в выводе `ls -l`:

```bash
$ ls -ld test.sh
-rwsr-xr-x 1 carol carol 33 Dec 11 10:36 test.sh
```

Вы можете комбинировать несколько специальных разрешений для одного параметра. Например, чтобы установить SGID (значение `2`) и SUID (значение `4`) в восьмеричном режиме для скрипта `test.sh` с разрешениями `755`, введите:

```bash
$ chmod 6755 test.sh 
```

И результатом было бы:

```bash
$ ls -lh test.sh
-rwsr-sr-x 1 carol carol 66 Jan 18 17:29 test.sh
```

{% hint style="info" %}
Если ваш терминал поддерживает цветную печать, а в наши дни большинство терминалов её поддерживают, вы можете быстро проверить, установлены ли эти специальные разрешения, взглянув на вывод `ls -l`. Для бита «sticky» имя каталога может отображаться чёрным шрифтом на синем фоне. То же самое относится к файлам с битами SGID (жёлтый фон) и SUID (красный фон). Цвета могут отличаться в зависимости от того, какой дистрибутив Linux и настройки терминала вы используете
{% endhint %}

## Краткие сведения <a href="#sec.104.5_01-su" id="sec.104.5_01-su"></a>

В этом уроке вы узнали, как использовать `ls` для получения (и декодирования) информации о разрешениях для файлов, как контролировать или изменять, кто может создавать, удалять или изменять файлы с помощью `chmod`, как в _восьмеричном_, так и в _символическом_ режиме, как изменять владельца файлов с помощью `chown` и `chgrp`, а также как запрашивать и изменять маску разрешений по умолчанию для файлов и каталогов с помощью `umask`

В этом уроке обсуждались следующие команды:

`ls`

Перечислить файлы, необязательно включая такие сведения, как разрешения.

`chmod`

Изменить разрешения для файла или каталога.

`chown`

Изменить пользователя-владельца и/ или группу файлов или каталогов.

`chgrp`

Изменить группу владельцев файла или каталога.

`umask`

Запросить или установить маску разрешений по умолчанию для файлов и каталогов

## Ответы на упражнения с Руководством <a href="#sec.104.5_01-age" id="sec.104.5_01-age"></a>

1.  Создайте каталог с именем `emptydir` с помощью команды `mkdir emptydir`. Теперь с помощью `ls` выведите список разрешений для каталога `emptydir`.

    Добавьте параметр `-d` к `ls` для просмотра атрибутов файлов в каталоге вместо перечисления его содержимого. Итак, ответ таков:

    ```bash
    ls -l -d emptydir
    ```

    Бонусные баллы, если вы объединили два параметра в один, как в `ls -ld emptydir`.
2.  Создайте пустой файл с именем `emptyfile` с помощью команды `touch emptyfile`. Теперь, используя `chmod` в символическом режиме, добавьте права на выполнение для владельца файла `emptyfile` и удалите права на запись и выполнение для всех остальных. Сделайте это с помощью всего одной команды `chmod`.

    Подумайте об этом так:

    * «Для пользователя, которому принадлежит файл (`u`), добавьте (`+`) разрешения на выполнение (`x`)», то есть `u+x`.
    *   «Для группы (`g`) и других пользователей (`o`), удалите (`-`) разрешения на запись (`w`) и выполнение (`x`)», то есть `go-wx`.

        Чтобы объединить эти два набора разрешений, мы добавляем между ними запятую. Таким образом, конечный результат выглядит так:

        ```bash
        chmod u+x,go-wx emptyfile
        ```
3.  Какими будут права доступа по умолчанию для файла, если значение `umask` равно `027`?

    Разрешения будут следующими `rw-r-----`
4.  Предположим, что файл с именем `test.sh` — это сценарий оболочки со следующими правами доступа и владельцем:

    ```bash
    --rwxr-sr-x 1 carol root     33 Dec 11 10:36 test.sh
    ```

    *   Каковы разрешения для владельца файла?

        Права владельца (со 2-го по 4-й символ в выводе `ls -l`) — `rwx`, поэтому ответ: «читать, записывать и выполнять файл».
    *   Используя восьмеричную систему счисления, какой должен быть синтаксис команды chmod, чтобы «отменить» специальное разрешение, предоставленное этому файлу?

        Мы можем «отменить» специальные разрешения, передав четвёртую цифру `0` в `chmod`. Текущие разрешения — `755`, поэтому команда должна быть `chmod 0755`.
5.  Рассмотрим этот файл:

    ```bash
    $ ls -l /dev/sdb1
    brw-rw---- 1 root disk 8, 17 Dec 21 18:51 /dev/sdb
    ```

    Что это за файл`sdb1`? Кто может в него записывать?

    Первый символ в выводе `ls -l` показывает тип файла. `b` — это _блочное устройство_, обычно диск (внутренний или внешний), подключённый к компьютеру. Владелец (`root`) и любые пользователи из группы `disk` могут записывать в него данные.
6.  Рассмотрим следующие 4 файла:

    ```bash
    drwxr-xr-t 2 carol carol 4,0K Dec 20 18:46 Another_Directory
    ----r--r-- 1 carol carol    0 Dec 11 10:55 foo.bar
    -rw-rw-r-- 1 carol carol 1,2G Dec 20 18:22 HugeFile.zip
    drwxr-sr-x 2 carol users 4,0K Jan 18 17:26 Sample_Directory
    ```

    Запишите соответствующие разрешения для каждого файла и каталога в восьмеричном режиме с использованием 4-значного обозначения.

    Соответствующие разрешения в восьмеричном режиме следующие:

    | `Another_Directory` | `17551` для специальных разрешений, `755` для обычных разрешений (`rwx` для пользователя, `r-x` для группы и других).                                                        |
    | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
    | `foo.bar`           | `0044`Никаких специальных разрешений (поэтому первая цифра — `0`), никаких разрешений для пользователя (`---`) и только чтение (`r—​r--`) для группы и других пользователей. |
    | `HugeFile.zip`      | `0664`Никаких специальных разрешений, поэтому первая цифра — `0`. `6` (`rw-`) для пользователя и группы, `4` (`r--`) для остальных.                                          |
    | `Sample_Directory`  | `2` для бита SGID, `7` (`rwx`) для пользователя, `5` (`r-x`) для группы и другие.                                                                                            |

### Ответы на исследовательские упражнения <a href="#sec.104.5_01-aee" id="sec.104.5_01-aee"></a>

1.  Попробуйте сделать это в терминале: создайте пустой файл с именем `emptyfile` с помощью команды `touch emptyfile`. Теперь «обнулите» права доступа к файлу с помощью `chmod 000 emptyfile`. Что произойдёт, если вы измените права доступа к `emptyfile` с помощью передачи только _одного_ значения `chmod` в восьмеричном режиме, например `chmod 4 emptyfile`? А если вы используете два значения, например `chmod 44 emptyfile`? Что мы можем узнать о том, как `chmod` считывает числовое значение?

    Помните, что мы «обнулили» разрешения для `emptyfile`. Таким образом, его начальное состояние будет следующим:

    ```bash
    ---------- 1 carol carol    0 Dec 11 10:55 emptyfile
    ```

    Теперь давайте попробуем выполнить первую команду, `chmod 4 emptyfile`:

    ```bash
    $ chmod 4 emptyfile
    $ ls -l emptyfile
    -------r-- 1 carol carol 0 Dec 11 10:55 emptyfile
    ```

    Видите? Права доступа для _других_ были изменены. А что, если мы попробуем ввести две цифры, как в `chmod 44 emptyfile`?

    ```bash
    $ chmod 44 emptyfile
    $ ls -l emptyfile
    ----r--r-- 1 carol carol 0 Dec 11 10:55 emptyfile
    ```

    Теперь были изменены разрешения для _группы_ и _других_. Из этого можно сделать вывод, что в восьмеричном режиме `chmod` считывает значение «наоборот», начиная с младшей значащей цифры (_других_) и заканчивая старшей (_пользователя_). Если вы передаёте одну цифру, вы изменяете разрешения для _других_. Если вы передаёте две цифры, вы изменяете _группу_ и _других_, если три — _пользователя_, _группу_ и _других_, а если четыре — _пользователя_, _группу_, _других_ и специальные разрешения.
2.  Рассмотрим разрешения для временного каталога в системе Linux, `/tmp`:

    ```bash
    $ ls -l /tmp
    drwxrwxrwt  19 root root  16K Dec 21 18:58 tmp
    ```

    У пользователя, группы и других пользователей есть полные права доступа. Но может ли обычный пользователь удалить _какие-либо_ файлы в этом каталоге? Почему так происходит?

    `/tmp` Это то, что мы называем каталогом с _доступностью для записи всем пользователям_. Это означает, что любой пользователь может записывать в него данные. Но мы не хотим, чтобы один пользователь вмешивался в файлы, созданные другими пользователями, поэтому установлен _битовый флаг sticky_ (на что указывает `t` в разрешениях для _других пользователей_). Это означает, что пользователь может удалять файлы в `/tmp`, но только те, которые создал он сам.
3.  Файл с именем `test.sh` имеет следующие права доступа: `-rwsr-xr-x`, то есть установлен бит SUID. Теперь выполните следующие команды:

    ```bash
    $ chmod u-x test.sh
    $ ls -l test.sh
    -rwSr-xr-x 1 carol carol 33 Dec 11 10:36 test.sh
    ```

    Что мы сделали? Что означает заглавная буква `S`?

    Мы удалили права на выполнение для пользователя, которому принадлежит файл. `s` (или `t`) заменяет `x` в выводе `ls -l`, поэтому системе нужно как-то показывать, есть ли у пользователя права на выполнение. Для этого она меняет регистр специального символа.

    Строчная буква `s` в первой группе разрешений означает, что у пользователя, которому принадлежит файл, есть права на выполнение и установлен бит SUID. Прописная буква `S` означает, что у пользователя, которому принадлежит файл, нет (`-`) прав на выполнение и установлен бит SUID.

    То же самое можно сказать и о SGID: строчная буква `s` во второй группе разрешений означает, что у группы, владеющей файлом, есть права на выполнение и что установлен бит SGID. Прописная буква `S` означает, что у группы, владеющей файлом, нет (`-`) прав на выполнение и что установлен бит SGID.

    Это также относится к биту sticky, обозначаемому `t` в третьей группе разрешений. Строчная буква `t` означает, что бит sticky установлен и что у других пользователей есть права на выполнение. Прописная буква `T` означает, что бит sticky установлен и что у других пользователей нет прав на выполнение.
4.  Как создать каталог с именем `Box` так, чтобы все файлы автоматически принадлежали группе `users` и могли быть удалены только пользователем, который их создал?

    Это многоэтапный процесс. Первый шаг — создание каталога:

    ```bash
    $ mkdir Box
    ```

    Мы хотим, чтобы каждый файл, созданный в этом каталоге, автоматически присваивался группе `users`. Мы можем сделать это, назначив эту группу владельцем каталога, а затем установив для него бит SGID. Нам также нужно убедиться, что любой участник группы может записывать данные в этот каталог.

    Поскольку нас не интересуют другие разрешения и мы хотим «переключить» только специальные биты, имеет смысл использовать символьный режим:

    ```bash
    $ chown :users Box/
    $ chmod g+wxs Box/
    ```

    Обратите внимание, что если ваш текущий пользователь не входит в группу `users`, вам нужно будет использовать команду `sudo` перед приведёнными выше командами, чтобы выполнить изменение от имени пользователя root.

    Теперь о последнем шаге: убедитесь, что только пользователь, создавший файл, может его удалить. Для этого установите флаг «только для чтения» (обозначается `t`). Помните, что он устанавливается в разрешениях для других пользователей (`o`).

    ```bash
    $ chmod o + t Box /
    ```

    Разрешения для каталога `Box` должны быть следующими:

    ```bash
    drwxrwsr-t 2 carol users  4,0K Jan 18 19:09 Box
    ```

    Конечно, вы можете указать SGID и флаг sticky с помощью только одной команды `chmod`:

    <pre class="language-bash"><code class="lang-bash"><strong>$ chmod g + wxs, o + t Box/
    </strong></code></pre>

    Бонусные баллы, если вы подумали об этом.
