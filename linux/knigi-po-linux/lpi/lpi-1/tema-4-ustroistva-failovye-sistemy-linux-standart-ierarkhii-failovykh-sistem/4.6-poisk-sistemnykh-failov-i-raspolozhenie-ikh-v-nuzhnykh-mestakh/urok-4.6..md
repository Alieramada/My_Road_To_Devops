# Урок 4.6.

## Введение <a href="#sec.104.7_01-in" id="sec.104.7_01-in"></a>

Дистрибутивы Linux бывают разных форм и размеров, но почти все они следуют _стандарту иерархии файловых систем_ (_Filesystem Hierarchy Standard_ FHS), который определяет «стандартную структуру» файловой системы, значительно упрощая взаимодействие и системное администрирование. В этом уроке вы узнаете больше об этом стандарте и о том, как находить файлы в системе Linux.

## Стандарт иерархии файловой системы <a href="#the_filesystem_hierarchy_standard" id="the_filesystem_hierarchy_standard"></a>

Стандарт иерархии файловых систем (FHS) — это попытка Linux Foundation стандартизировать структуру каталогов и их содержимое в системах Linux. Соблюдение стандарта не является обязательным, но большинство дистрибутивов ему следуют.

{% hint style="info" %}
Те, кого интересуют подробности организации файловой системы, могут ознакомиться со спецификацией FHS 3.0, доступной в нескольких форматах по адресу: [http://refspecs.linuxfoundation.org/fhs.shtml](http://refspecs.linuxfoundation.org/fhs.shtml)
{% endhint %}

Согласно стандарту, базовая структура каталогов выглядит следующим образом:

`/`

Это корневой каталог, самый верхний каталог в иерархии. Все остальные каталоги находятся внутри него. Файловую систему часто сравнивают с «деревом», поэтому это «ствол», к которому подключены все ветви.

`/bin`

Основные двоичные файлы, доступные всем пользователям.

`/boot`

Файлы, необходимые для процесса загрузки, включая начальный RAM-диск (initrd) и само ядро Linux.

`/dev`

Файлы устройств. Это могут быть как физические устройства, подключённые к системе (например, `/dev/sda` первый диск SCSI или SATA), так и виртуальные устройства, предоставляемые ядром.

`/etc`

Файлы конфигурации для конкретного хоста. При необходимости программы могут создавать подкаталоги в `/etc` для хранения нескольких файлов конфигурации.

`/home`

У каждого пользователя в системе есть «домашний» каталог для хранения личных файлов и настроек, и большинство из них находятся в `/home`. Обычно домашний каталог совпадает с именем пользователя, поэтому у пользователя Джона каталог будет находиться в `/home/john`. Исключениями являются суперпользователь (root), у которого есть отдельный каталог (`/root`), и некоторые системные пользователи.

`/lib`

Общие библиотеки, необходимые для загрузки операционной системы и запуска двоичных файлов в `/bin` и `/sbin`.

`/media`

Здесь устанавливаются съёмные носители, подключаемые пользователем, такие как флеш-накопители, устройства чтения CD- и DVD-дисков, дискеты, карты памяти и внешние диски.

`/mnt`

Точка монтирования для временно смонтированных файловых систем.

`/opt`

Пакеты прикладного программного обеспечения.

`/root`

Домашний каталог для суперпользователя (root).

`/run`

Переменные данные во время выполнения.

`/sbin`

Системные двоичные файлы.

`/srv`

Данные, обслуживаемые системой. Например, страницы, обслуживаемые веб-сервером, могут храниться в `/srv/www`.

`/tmp`

Временные файлы.

`/usr`

Пользовательские данные только для чтения, включая данные, необходимые некоторым вспомогательным утилитам и приложениям.

`/proc`

Виртуальная файловая система, содержащая данные, относящиеся к запущенным процессам.

`/var`

Переменные данные, записываемые во время работы системы, включая очередь печати, данные журнала, почтовые ящики, временные файлы, кэш браузера и т. д.

Имейте в виду, что некоторые из этих каталогов, такие как `/etc`, `/usr` и `/var`, содержат целую иерархию подкаталогов.

## **Временные файлы**

Временные файлы — это файлы, используемые программами для хранения данных, которые нужны лишь на короткое время. Это могут быть данные запущенных процессов, журналы сбоев, временные файлы из автозагрузки, промежуточные файлы, используемые при преобразовании файлов, файлы кэша и тому подобное.

## **Расположение временных файлов**

Версия 3.0 _стандарта иерархии файловых систем_ (FHS) определяет стандартные места для временных файлов в системах Linux. Каждое место имеет своё назначение и поведение, и разработчикам рекомендуется следовать правилам, установленным FHS, при записи временных данных на диск.

`/tmp`

Согласно FHS, программы не должны предполагать, что файлы, записанные здесь, будут сохраняться между запусками программы. Рекомендуется очищать этот каталог (удалять все файлы) во время загрузки системы, хотя это необязательно.

`/var/tmp`

Ещё одно место для временных файлов, но его _не следует очищать_ при загрузке системы. Файлы, хранящиеся здесь, обычно сохраняются между перезагрузками.

`/run`

Этот каталог содержит переменные данные времени выполнения, используемые запущенными процессами, например файлы идентификаторов процессов (`.pid`). Программы, которым требуется более одного файла времени выполнения, могут создавать здесь подкаталоги. Это место _должно быть очищено_ при загрузке системы. Когда-то этот каталог назывался `/var/run`, а в некоторых системах `/var/run` может быть символической ссылкой на `/run`.

Обратите внимание, что ничто не мешает программе создавать временные файлы в других местах системы, но рекомендуется соблюдать соглашения, установленные FHS.

## Поиск файлов <a href="#finding_files" id="finding_files"></a>

Для поиска файлов в системе Linux можно использовать команду `find` . Это очень мощный инструмент, в котором есть множество параметров, позволяющих настроить его поведение и изменить вывод в соответствии с вашими потребностями.

Для начала `find` нужны два аргумента: начальная точка и то, что нужно найти. Например, чтобы найти все файлы в текущем каталоге (и подкаталогах), имена которых заканчиваются на `.jpg`, можно использовать:

```bash
$ find . -name '*.jpg'
./pixel_3a_seethrough_1.jpg
./Mate3.jpg
./Expert.jpg
./Pentaro.jpg
./Mate1.jpg
./Mate2.jpg
./Sala.jpg
./Hotbit.jpg
```

Это будет соответствовать любому файлу, последними четырьмя символами имени которого являются `.jpg`, независимо от того, что стоит перед ним, поскольку `*` это подстановочный знак для ”чего угодно". Однако посмотрите, что произойдет, если в `*`конце _шаблона будет добавлен еще один :_&#x20;

```bash
$ find . -name '*.jpg*'
./pixel_3a_seethrough_1.jpg
./Pentaro.jpg.zip
./Mate3.jpg
./Expert.jpg
./Pentaro.jpg
./Mate1.jpg
./Mate2.jpg
./Sala.jpg
./Hotbit.jpg
```

Файл `Pentaro.jpg.zip` (выделен выше) не был включен в предыдущий список, потому что, даже если он содержит `.jpg` в своем названии, он не соответствует шаблону, поскольку после него есть дополнительные символы. Новая модель означает “ничего `.jpg` , ничего”, так как он соответствует.

{% hint style="info" %}
Имейте в виду, что параметр `-name` чувствителен к регистру. Если вы хотите выполнить поиск без учёта регистра, используйте `-iname`.
{% endhint %}

Выражение `*.jpg` должно быть заключено в одинарные кавычки, чтобы оболочка не интерпретировала сам шаблон. Попробуйте без кавычек и посмотрите, что произойдёт.

По умолчанию `find` будет начинаться с начальной точки и проходить через все найденные подкаталоги (и подкаталоги этих подкаталогов). Вы можете ограничить это поведение с помощью параметров `-maxdepth N`, где `N` — максимальное количество уровней.

Чтобы выполнить поиск только в текущем каталоге, используйте `-maxdepth 1`. Предположим, у вас следующая структура каталогов:

```bash
directory
├── clients.txt
├── partners.txt -> clients.txt
└── somedir
    ├── anotherdir
    └── clients.txt
```

Чтобы выполнить поиск внутри `somedir`, нужно использовать `-maxdepth 2` (текущий каталог + 1 уровень вниз). Чтобы выполнить поиск внутри `anotherdir`, нужно использовать `-maxdepth 3` (текущий каталог + 2 уровня вниз). Параметр `-mindepth N` работает наоборот, выполняя поиск только в каталогах _как минимум_ `N` на 2 уровня ниже.

`-mount` Параметр можно использовать, чтобы избежать `find` сбоя внутри подключенных файловых систем. Вы также можете ограничить поиск определенными типами файловых систем, используя `-fstype` параметр. Таким образом, `find /mnt -fstype exfat -iname "*report*"` будет выполняться поиск только внутри файловых систем exFAT, смонтированных под `/mnt`.

## **Поиск атрибутов**

Вы можете использовать приведённые ниже параметры для поиска файлов с определёнными атрибутами, например, с возможностью записи для вашего пользователя, с определённым набором разрешений или определённого размера:

`-user USERNAME`

Соответствует файлам, принадлежащим пользователю `USERNAME`.

`-group GROUPNAME`

Соответствует файлам, принадлежащим группе `GROUPNAME`.

`-readable`

Сопоставляет файлы, доступные для чтения текущему пользователю.

`-writable`

Соответствует файлам, доступным для записи текущим пользователем.

`-executable`

Соответствует файлам, которые могут быть запущены текущим пользователем. В случае с каталогами это будет соответствовать любому каталогу, в который пользователь может войти (`x` разрешение).

`-perm NNNN`

Это будет соответствовать любым файлам, для которых установлено разрешение `NNNN` . Например, `-perm 0664` будет соответствовать любым файлам, для которых пользователь и группа могут читать и записывать данные, а другие пользователи могут только читать (или `rw-rw-r--`).

Вы можете добавить `-` перед `NNNN` для проверки файлов, которые имеют _по крайней мере_ указанное разрешение. Например, `-perm -644` будет соответствовать файлам, которые имеют как минимум `644` (`rw-r—​r--`) разрешений. Сюда входит файл с `664` (`rw-rw-r--`) или даже `775` (`rwxrwx-r-x`).

`-empty`

Будет соответствовать пустым файлам и каталогам.

`-size N`

Будет соответствовать любым файлам размером `N` байт, где `N` по умолчанию — это количество блоков по 512 байт. Вы можете добавить суффиксы к `N` для других единиц измерения: `Nc` будет считать размер в байтах, `Nk` — в килобайтах (КиБ, кратных 1024 байтам), `NM` — в мегабайтах (МиБ, кратных 1024 \* 1024) и `NG` — в гигабайтах (ГиБ, кратных 1024 \* 1024 \* 1024).

Опять же, вы можете добавить префиксы `+` или `-` (здесь они означают _больше, чем_ и _меньше, чем_) для поиска по относительным размерам. Например, `-size -10M` будет соответствовать любому файлу размером менее 10 МБ.

Например, чтобы найти в домашнем каталоге файлы, содержащие шаблон `report` без учёта регистра в любой части имени, имеющие права `0644` доступа, к которым обращались 10 дней назад и размер которых не менее 1 МБ, можно использовать

```bash
$ find ~ -iname "*report*" -perm 0644 -atime 10 -size +1M
```

## **Поиск по времени**

Помимо поиска по атрибутам, вы также можете выполнять поиск по времени, находя файлы, к которым обращались, атрибуты которых были изменены или которые были модифицированы в течение определённого периода времени. Параметры:

`-amin N`, `-cmin N`, `-mmin N`

Это позволит найти файлы, к которым обращались, атрибуты которых были изменены или которые были изменены (соответственно) `N` минут назад.

`-atime N`, `-ctime N`, `-mtime N`

Это позволит найти файлы, к которым обращались, атрибуты которых были изменены или которые были модифицированы `N*24` часов назад.

Для `-cmin N` и `-ctime N` любое изменение атрибута приведёт к совпадению, включая изменение разрешений, чтение или запись в файл. Это делает эти параметры особенно эффективными, поскольку практически любая операция с файлом приведёт к совпадению.

Следующий пример соответствует любому файлу в текущем каталоге, который был изменён менее 24 часов назад и имеет размер более 100 МБ:

```bash
$ find . -mtime -1 -size +100M
```

## **Использование `locate` и `updatedb`**

`locate` и `updatedb` — это команды, которые можно использовать для быстрого поиска файла, соответствующего заданному шаблону, в системе Linux. Но в отличие от `find`, `locate` не ищет шаблон в файловой системе: вместо этого он ищет его в базе данных, созданной с помощью команды `updatedb`. Это позволяет получать очень быстрые результаты, но они могут быть неточными в зависимости от того, когда в последний раз обновлялась база данных.

Самый простой способ использовать `locate` — просто задать шаблон для поиска. Например, чтобы найти все изображения в формате JPEG в вашей системе, вы можете использовать `locate jpg`. Список результатов может быть довольно длинным, но должен выглядеть примерно так:

```bash
$ locate jpg
/home/carol/Downloads/Expert.jpg
/home/carol/Downloads/Hotbit.jpg
/home/carol/Downloads/Mate1.jpg
/home/carol/Downloads/Mate2.jpg
/home/carol/Downloads/Mate3.jpg
/home/carol/Downloads/Pentaro.jpg
/home/carol/Downloads/Sala.jpg
/home/carol/Downloads/pixel_3a_seethrough_1.jpg
/home/carol/Downloads/jpg_specs.doc
```

Когда вас попросят ввести `jpg` шаблон, `locate` будет показано все, что содержит этот шаблон, независимо от того, что находится до или после него. Вы можете увидеть пример этого в файле `jpg_specs.doc` в приведенном выше списке: он содержит шаблон, но расширение отсутствует `jpg`.

{% hint style="info" %}
Помните, что с `locate` вы сопоставляете шаблоны, а не расширения файлов.
{% endhint %}

По умолчанию шаблон чувствителен к регистру. Это означает, что файлы, содержащие `.JPG`, не будут отображаться, так как шаблон написан в нижнем регистре. Чтобы этого избежать, передайте параметр `-i` в `locate`. Повторим наш предыдущий пример:

```bash
$ locate -i .jpg
/home/carol/Downloads/Expert.jpg
/home/carol/Downloads/Hotbit.jpg
/home/carol/Downloads/Mate1.jpg
/home/carol/Downloads/Mate1_old.JPG
/home/carol/Downloads/Mate2.jpg
/home/carol/Downloads/Mate3.jpg
/home/carol/Downloads/Pentaro.jpg
/home/carol/Downloads/Sala.jpg
/home/carol/Downloads/pixel_3a_seethrough_1.jpg
```

Обратите внимание, что файл `Mate1_old.JPG`, выделенный жирным шрифтом выше, не был указан в предыдущем списке.

Вы можете передать несколько шаблонов в `locate` просто разделив их пробелами. В приведенном ниже примере будет выполнен поиск без учета регистра для любых файлов, соответствующих шаблонам `zip` и `jpg`:

```bash
$ locate -i zip jpg
/home/carol/Downloads/Expert.jpg
/home/carol/Downloads/Hotbit.jpg
/home/carol/Downloads/Mate1.jpg
/home/carol/Downloads/Mate1_old.JPG
/home/carol/Downloads/Mate2.jpg
/home/carol/Downloads/Mate3.jpg
/home/carol/Downloads/OPENMSXPIHAT.zip
/home/carol/Downloads/Pentaro.jpg
/home/carol/Downloads/Sala.jpg
/home/carol/Downloads/gbs-control-master.zip
/home/carol/Downloads/lineage-16.0-20190711-MOD-quark.zip
/home/carol/Downloads/pixel_3a_seethrough_1.jpg
/home/carol/Downloads/jpg_specs.doc
```

При использовании нескольких шаблонов вы можете указать, что нужно отображать только файлы, соответствующие _всем_ из них. Это делается с помощью опции `-A`. В следующем примере будут показаны все файлы, соответствующие шаблонам `.jpg` _и_ `.zip`.

```bash
$ locate -A .jpg .zip
/home/carol/Downloads/Pentaro.jpg.zip
```

Если вы хотите подсчитать количество файлов, соответствующих заданному шаблону, вместо того чтобы показывать их полный путь, вы можете использовать опцию `-c` . Например, чтобы подсчитать количество файлов `.jpg` в системе:

```bash
$ locate -c .jpg
1174
```

Одна из проблем с `locate` заключается в том, что он показывает только записи, присутствующие в базе данных, созданной `updatedb` (расположенной в `/var/lib/mlocate.db`). Если база данных устарела, на выходе могут отображаться файлы, которые были удалены с момента последнего обновления. Один из способов избежать этого — добавить параметр `-e`, который будет проверять, существует ли файл, прежде чем отображать его на выходе.

Конечно, это не решит проблему с файлами, созданными _после_ последнего обновления базы данных, которые не отображаются. Для этого вам нужно будет обновить базу данных с помощью команды `updatedb`. Сколько времени это займёт, зависит от количества файлов на вашем диске.

## **Управление поведением `updatedb`**

Поведение `updatedb` можно контролировать с помощью файла `/etc/updatedb.conf`. Это текстовый файл, в котором каждая строка управляет одной переменной. Пустые строки игнорируются, а строки, начинающиеся с символа `#`, обрабатываются как комментарии.

`PRUNEFS=`

Любые типы файловых систем, указанные после этого параметра, не будут сканироваться с помощью `updatedb`. Список типов должен быть разделён пробелами, а сами типы не чувствительны к регистру, поэтому `NFS` и `nfs` — это одно и то же.

`PRUNENAMES=`

Это список имён каталогов, разделённых пробелами, которые не должны сканироваться с помощью `updatedb`.

`PRUNEPATHS=`

Это список путей, которые следует игнорировать с помощью `updatedb`. Пути должны быть разделены пробелами и указаны так же, как они были бы указаны с помощью `updatedb` (например, `/var/spool /media`)

`PRUNE_BIND_MOUNTS=`

Это простая переменная `yes` или `no` . Если установлено значение `yes` , примонтированные каталоги (каталоги, примонтированные с помощью команды `mount --bind` ) будут игнорироваться.

## **Поиск двоичных файлов, страниц руководства и исходного кода**

`which` Это очень полезная команда, которая показывает полный путь к исполняемому файлу. Например, если вы хотите найти исполняемый файл для `bash`, вы можете использовать:

```bash
$ which bash
/usr/bin/bash
```

Если добавить параметр `-a`, команда покажет все пути, которые соответствуют исполняемому файлу. Обратите внимание на разницу:

```bash
$ which mkfs.ext3
/usr/sbin/mkfs.ext3

$ which -a mkfs.ext3
/usr/sbin/mkfs.ext3
/sbin/mkfs.ext3
```

{% hint style="info" %}
Чтобы узнать, какие каталоги находятся в `PATH`, используйте команду `echo $PATH`. Это выведет (`echo`) содержимое переменной `PATH` (`$PATH`) в ваш терминал.
{% endhint %}

`type` Это аналогичная команда, которая показывает информацию о двоичном файле, в том числе о его расположении и типе. Просто используйте `type` после названия команды:

```bash
$ type locate
locate is /usr/bin/locate
```

Параметр `-a` работает так же, как и в `which`, показывая все пути, которые соответствуют исполняемому файлу. Например:

```bash
$ type -a locate
locate is /usr/bin/locate
locate is /bin/locate
```

А параметр `-t` покажет тип файла команды, который может быть `alias`, `keyword`, `function`, `builtin` или `file`. Например:

```bash
$ type -t locate
file

$ type -t ll
alias

$ type -t type
type is a built-in shell command
```

Команда `whereis` более универсальна и, помимо двоичных файлов, может использоваться для отображения расположения справочных страниц или даже исходного кода программы (если он доступен в вашей системе). Просто введите `whereis` и укажите имя двоичного файла:

```bash
$ whereis locate
locate: /usr/bin/locate /usr/share/man/man1/locate.1.gz
```

Приведенные выше результаты включают двоичные файлы (`/usr/bin/locate`) и сжатые страницы руководства (`/usr/share/man/man1/locate.1.gz`).

Вы можете быстро отфильтровать результаты с помощью переключателей командной строки, таких как `-b`, которые ограничат поиск только двоичными файлами, `-m`, которые ограничат поиск только справочными страницами, или `-s`, которые ограничат поиск только исходным кодом. Повторяя приведённый выше пример, вы получите:

```bash
$ whereis -b locate
locate: /usr/bin/locate

$ whereis -m locate
locate: /usr/share/man/man1/locate.1.gz
```

## Краткие сведения <a href="#sec.104.7_01-su" id="sec.104.7_01-su"></a>

В этом уроке вы узнали об основных принципах организации файловой системы на компьютере с Linux в соответствии с FHS, а также о том, как находить двоичные файлы и файлы по имени или по атрибутам. В этом уроке мы рассмотрели следующие команды:

`find`

Универсальная команда, используемая для поиска файлов и папок по различным критериям.

`locate`

Утилита, которая использует локальную базу данных, содержащую информацию о расположении локальных файлов.

`updatedb`

Обновляет локальную базу данных, используемую командой `locate`.

`which`

Отображает полный путь к исполняемому файлу.

`whereis`

Отображает расположение страниц руководства, двоичных файлов и исходного кода в системе.

`type`

Отображает расположение двоичного файла и тип приложения, к которому он относится (например, установленная программа, встроенная программа Bash и т. д.).

## Ответы на упражнения с Руководством <a href="#sec.104.7_01-age" id="sec.104.7_01-age"></a>

1.  Представьте, что программе нужно создать временный файл для однократного использования, который больше не понадобится после закрытия программы. В каком каталоге следует создать этот файл?

    Поскольку нам не нужен файл после завершения работы программы, правильный каталог — `/tmp`.
2.  Какой временный каталог _необходимо_ очистить в процессе загрузки?

    Каталог - это `/run` или, в некоторых системах, `/var/run`.
3.  С помощью `find` выполните поиск только в текущем каталоге файлов, доступных для записи пользователю, которые были изменены за последние 10 дней и имеют размер более 4 ГБ.

    Для этого вам понадобятся параметры `-writable`, `-mtime` и `-size`:

    ```bash
    find . -writable -mtime -10 -size +4G
    ```
4.  Используя `locate`, найдите все файлы, содержащие в своих названиях шаблоны `report` и либо `updated`, либо `update`, либо `updating`

    Поскольку `locate` необходимо, чтобы все шаблоны соответствовали друг другу, используйте `-A` опцию:

    ```bash
    locate -A "report" "updat"
    ```
5.  Как вы можете найти, где хранится справочная страница для `ifconfig`?

    Используйте `-m` параметр для `whereis`:

    ```bash
    whereis -m ifconfig
    ```
6.  Какую переменную нужно добавить в `/etc/updatedb.conf` для того, чтобы `updatedb` игнорировал `ntfs` файловые системы?

    За переменной `PRUNEFS=` следует тип файловой системы: `PRUNEFS=ntfs`
7.  Системный администратор хочет подключить внутренний диск (`/dev/sdc1`). Согласно FHS, в какой каталог следует подключить этот диск?

    На практике диск можно установить в любом месте. Однако FHS рекомендует устанавливать временные диски в `/mnt`

## Ответы на исследовательские упражнения <a href="#sec.104.7_01-aee" id="sec.104.7_01-aee"></a>

1.  При использовании `locate` результаты извлекаются из базы данных, созданной `updatedb`. Однако эта база данных может быть устаревшей, из-за чего `locate` показывает файлы, которых больше не существует. Как сделать так, чтобы `locate` показывал только существующие файлы?

    Добавьте `-e` параметр для определения местоположения, как в `locate -e PATTERN`.
2.  Найдите любой файл в текущем каталоге или подкаталогах на 2 уровня ниже, исключая подключённые файловые системы, в названии которых есть шаблон `Status` или `statute`.

    Помните, что для `-maxdepth` нужно учитывать также текущий каталог, поэтому нам нужны три уровня (текущий плюс два уровня ниже):

    ```bash
    find . -maxdepth 3  -mount -iname "*statu*"
    ```
3.  Ограничив поиск файловыми системами `ext4`, найдите все файлы в `/mnt` с разрешением на выполнение как минимум для группы, доступные для чтения текущему пользователю и изменённые за последние 2 часа.

    Используйте параметр `-fstype` для `mount` , чтобы ограничить поиск определёнными типами файловых систем. Файл, доступный для чтения текущему пользователю, будет иметь как минимум `4` в первой цифре разрешений, а файл, доступный для выполнения группой, будет иметь как минимум `1` во второй цифре. Поскольку нас не интересуют разрешения для других пользователей, мы можем использовать `0` для третьей цифры. Используйте `-cmin N` для фильтрации недавних изменений атрибутов, помня, что N указывается в минутах. Итак:

    ```bash
    find /mnt -fstype ext4 -perm -410 -cmin -120
    ```
4.  Найдите пустые файлы, которые были изменены более 30 дней назад и находятся как минимум на два уровня ниже текущего каталога

    Параметр `-mindepth N` можно использовать для ограничения поиска как минимум `N` уровнями ниже, но помните, что в подсчёт нужно включать текущий каталог. Используйте `-empty` для проверки пустых файлов и `-mtime N` для проверки времени изменения. Итак:

    ```bash
    find . -empty -mtime +30 -mindepth 3
    ```
5.  Предположим, что пользователи `carol` и `john` входят в группу `mkt`. Найдите в домашнем каталоге `john` все файлы, которые также доступны для чтения `carol`.

    Учитывая, что они являются членами одной группы, нам нужно как минимум `r` (`4`) в разрешениях группы, а остальные нас не интересуют. Итак:

    ```bash
    find /home/john -perm -040
    ```
