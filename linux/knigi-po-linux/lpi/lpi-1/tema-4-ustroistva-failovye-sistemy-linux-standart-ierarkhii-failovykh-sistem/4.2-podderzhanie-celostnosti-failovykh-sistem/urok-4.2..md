# Урок 4.2.

### Введение <a href="#sec.104.2_01-in" id="sec.104.2_01-in"></a>

Современные файловые системы Linux поддерживают ведение журнала. Это означает, что каждая операция регистрируется во внутреннем журнале (в _журнале_) перед выполнением. Если операция прерывается из-за системной ошибки (например, паники ядра, сбоя питания и т. д.), её можно восстановить, проверив журнал, что позволяет избежать повреждения файловой системы и потери данных.

Это значительно снижает потребность в ручной проверке файловой системы, но она всё равно может потребоваться. Знание инструментов, используемых для этого (и соответствующих параметров), может стать решающим фактором между ужином дома с семьёй и бессонной ночью в серверной на работе.

В этом уроке мы рассмотрим инструменты, доступные для мониторинга использования файловой системы, оптимизации её работы, а также для проверки и устранения повреждений.

## Проверка использования диска <a href="#checking_disk_usage" id="checking_disk_usage"></a>

Есть две команды, которые можно использовать для проверки того, сколько места используется и сколько осталось в файловой системе. Первая из них — `du`, что означает «использование диска disk usage».

`du` является рекурсивной по своей природе. В своей базовой форме команда просто показывает, сколько 1-килобайтных блоков используется в текущем каталоге и всех его подкаталогах:

```bash
$ du
4816	.
```

Это не очень полезно, поэтому мы можем запросить более «удобный для восприятия человеком» вывод, добавив параметр `-h`:

```bash
$ du -h
4.8М.
```

По умолчанию `du` показывает только количество использований для каталогов (с учётом всех файлов и подкаталогов внутри него). Чтобы показать количество использований для всех файлов в каталоге, используйте параметр `-a`:

```bash
$ du -ah
432K ./geminoid.jpg
508K ./Linear_B_Hero.jpg
468K ./LG-G8S-ThinQ-Mirror-White.jpg
656K ./LG-G8S-ThinQ-Range.jpg
60K ./Stranger3_Titulo.png
108K ./Baidu_Banho.jpg
324 КБ ./Xiaomi_Mimoji.png
284 КБ ./Mi_CC_9e.jpg
96 КБ ./Mimoji_Comparativo.jpg
32 КБ ./Xiaomi FCC.jpg
484 КБ ./geminoid2.jpg
108 КБ ./Mimoji_Abre.jpg
88 КБ ./Mi8_Hero.jpg
832 КБ ./Tablet_Linear_B.jpg
332 КБ ./Mimoji_Comparativo.png
4,8 МБ .
```

По умолчанию отображается использование каждого подкаталога, а затем общее использование текущего каталога, _включая_ подкаталоги:

```bash
$ du -h
4,8M ./Temp
6,0M .
```

В приведённом выше примере мы видим, что подкаталог `Temp` занимает 4,8 МБ, а текущий каталог, _включая_ `Temp` подкаталог, занимает 6,0 МБ. Но сколько места занимают _файлы_ в текущем каталоге, исключая подкаталог? Для этого у нас есть параметр `-S`:

```bash
$ du -Sh
4,8M ./Temp
1,3M .
```

{% hint style="info" %}
Имейте в виду, что параметры командной строки чувствительны к регистру: `-s` отличается от `-S`.
{% endhint %}

Если вы хотите сохранить это различие между пространством, используемым файлами в текущем каталоге, и пространством, используемым подкаталогами, но _также_ хотите получить общую сумму в конце, вы можете добавить параметр `-c`:

```bash
$ du -Shc
4.8M	./Temp
1.3M	.
6.0M	total
```

Вы можете управлять тем, насколько «глубоким» должен быть вывод `du` с помощью параметра `-d N`, где `N` описывает уровни. Например, если вы используете параметр `-d 1`, он покажет текущий каталог и его подкаталоги, но не подкаталоги подкаталогов.

Смотрите разницу ниже.&#x20;

```bash
$ du -h
216K ./somedir/anotherdir
224K ./somedir
232K .
```

```bash
$ du -h -d1
224K	./somedir
232K	.
```

Пожалуйста, обратите внимание, что даже если `anotherdir` не отображается, его размер всё равно учитывается.

Возможно, вы захотите исключить некоторые типы файлов из подсчёта. Это можно сделать с помощью `--exclude="PATTERN"`, где `PATTERN` — шаблон, с которым вы хотите сопоставить файлы. Рассмотрим этот каталог:

```bash
$ du -ah
124K ./ASM68K.EXE
2,0M ./Contra.bin
36K ./fixheadr.exe
4,0K ./README.txt
2,1M ./Contra_NEW.bin
4,0K ./Built.bat
8,0K ./Contra_Main.asm
4,2M .
```

Теперь мы будем использовать `--exclude` для фильтрации всех файлов с расширением `.bin`:

```bash
$ du -ah --exclude="*.bin"
124K ./ASM68K.EXE
36K ./fixheadr.exe
4.0K ./README.txt
4.0K ./Built.bat
8.0K ./Contra_Main.asm
180K .
```

Обратите внимание, что общее количество больше не отражает размер исключенных файлов.

## Обслуживание файловых систем ext2, ext3 и ext4 <a href="#maintaining_ext2_ext3_and_ext4_filesystems" id="maintaining_ext2_ext3_and_ext4_filesystems"></a>

Чтобы проверить файловую систему на наличие ошибок (и, возможно, исправить их), в Linux есть утилита `fsck` (подумайте о «filesystem check», и вы никогда не забудете это название). В самой простой форме вы можете вызвать её с помощью `fsck` и указать расположение файловой системы, которую хотите проверить:

```bash
# fsck /dev/sdb1
fsck from util-linux 2.33.1
e2fsck 1.44.6 (5-Mar-2019)
DT_2GB: clean, 20/121920 files, 369880/487680 blocks
```

{% hint style="info" %}
НИКОГДА не запускайте `fsck` (или связанные с ним утилиты) на подключённой файловой системе. Если вы всё равно это сделаете, данные могут быть потеряны.
{% endhint %}

`fsck` Сама по себе программа не проверяет файловую систему, она просто вызывает соответствующую утилиту для файловой системы. В приведённом выше примере, поскольку тип файловой системы не был указан, `fsck` по умолчанию предполагала файловую систему ext2/3/4 и вызывала `e2fsck`.

Чтобы указать файловую систему, используйте параметр `-t` и укажите имя файловой системы, например `fsck -t vfat /dev/sdc`. В качестве альтернативы вы можете напрямую вызвать утилиту для конкретной файловой системы, например `fsck.msdos` для файловых систем FAT.

{% hint style="info" %}
Введите `fsck` и затем Tab дважды, чтобы увидеть список всех связанных с этим команд в вашей системе.
{% endhint %}

`fsck` может принимать некоторые аргументы командной строки. Вот некоторые из наиболее распространённых:

`-A`

При этом будут проверены все файловые системы, перечисленные в `/etc/fstab`.

`-C`

Отображает индикатор выполнения при проверке файловой системы. В настоящее время работает только с файловыми системами ext2/3/4.

`-N`

Это выведет на экран информацию о том, что будет сделано, и завершится без фактической проверки файловой системы.

`-R`

При использовании в сочетании с `-A` это позволит пропустить проверку корневой файловой системы.

`-V`

Подробный режим выводит больше информации, чем обычно, во время работы. Это полезно для отладки.

Специальная утилита для файловых систем ext2, ext3 и ext4 — это `e2fsck`, также называемая `fsck.ext2`, `fsck.ext3` и `fsck.ext4` (эти три утилиты — просто ссылки на `e2fsck`). По умолчанию она работает в интерактивном режиме: при обнаружении ошибки в файловой системе она останавливается и спрашивает пользователя, что делать. Пользователь должен ввести `y` для устранения проблемы, `n` для того, чтобы оставить её без изменений, или `a` для устранения текущей проблемы и всех последующих.

Конечно, сидеть перед терминалом и ждать, пока `e2fsck` спросит, что делать, — не самое продуктивное занятие, особенно если вы имеете дело с большой файловой системой. Поэтому есть опции, которые позволяют `e2fsck` работать в неинтерактивном режиме:

`-p`

Программа попытается автоматически исправить все обнаруженные ошибки. Если будет обнаружена ошибка, требующая вмешательства системного администратора, `e2fsck` программа предоставит описание проблемы и завершит работу.

`-y`

Это даст ответ `y` (да) на все вопросы.

`-n`

Противоположность `-y`. Помимо ответа `n` (нет) на все вопросы, это приведёт к тому, что файловая система будет смонтирована только для чтения, то есть её нельзя будет изменить.

`-f`

Заставляет `e2fsck` проверять файловую систему, даже если она помечена как «чистая», то есть была правильно отмонтирована.

## **Точная настройка файловой системы ext**

Файловые системы ext имеют _счётчик монтирования_. При каждом монтировании файловой системы счётчик увеличивается на 1, и при достижении порогового значения (_максимального количества монтирований_) система будет автоматически проверена с помощью `e2fsck` при следующей загрузке.

Максимальное количество подключений можно задать с помощью параметра `-c N`, где `N` — это количество раз, которое файловая система может быть подключена без проверки. Параметр `-C N` устанавливает количество подключений системы равным `N`. Обратите внимание, что параметры командной строки чувствительны к регистру, поэтому `-c` отличается от `-C`.

Также можно задать временной интервал между проверками с помощью параметра `-i`, за которым следует число и буквы `d` для дней, `m` для месяцев и `y` для лет. Например, `-i 10d` будет проверять файловую систему при следующей перезагрузке каждые 10 дней. Используйте ноль в качестве значения, чтобы отключить эту функцию.

`-L` Для установки метки файловой системы можно использовать эту метку, которая может содержать до 16 символов. Параметр `-U` устанавливает UUID файловой системы, который представляет собой 128-битное шестнадцатеричное число. В приведенном выше примере UUID равен `6e2c12e3-472d-4bac-a257-c49ac07f3761`. И метку, и UUID можно использовать вместо имени устройства (например, `/dev/sda1`) для монтирования файловой системы.

Опция `-e BEHAVIOUR` определяет поведение ядра при обнаружении ошибки файловой системы. Возможны три варианта поведения:

`continue`

Продолжит выполнение в обычном режиме.

`remount-ro`

Перемонтирует файловую систему как доступную только для чтения.

`panic`

Вызовет панику ядра.

Поведение по умолчанию — `continue`. `remount-ro` может быть полезно в приложениях, где важны данные, так как оно немедленно останавливает запись на диск, предотвращая потенциальные ошибки.

Файловые системы ext3 — это, по сути, файловые системы ext2 с журналом. С помощью `tune2fs` вы можете добавить журнал в файловую систему ext2, тем самым преобразовав её в ext3. Процедура проста: просто передайте параметр `-j` в `tune2fs`, а затем укажите устройство, содержащее файловую систему:

```
# tune2fs -j /dev/sda1
```

После этого при монтировании преобразованной файловой системы не забудьте установить тип `ext3` для использования журнала.

При работе с файловыми системами с журналом параметр `-J` позволяет использовать дополнительные параметры для настройки некоторых параметров журнала, например `-J size=` для установки размера журнала (в мегабайтах), `-J location=` для указания места хранения журнала (либо конкретный блок, либо определённое место на диске с суффиксами, такими как `M` или `G`) и даже для размещения журнала на внешнем устройстве с помощью `-J device=`.

Вы можете указать несколько параметров одновременно, разделив их запятой. Например: `-J size=10,location=100M,device=/dev/sdb1` создаст журнал размером 10 МБ в позиции 100 МБ на устройстве `/dev/sdb1`.

{% hint style="info" %}
\
В `tune2fs` есть опция «грубой силы» `-f`, которая заставит программу завершить операцию, даже если будут обнаружены ошибки. Излишне говорить, что использовать её следует с особой осторожностью.
{% endhint %}

## **Обслуживание файловых систем XFS**

Для файловых систем XFS эквивалентом `fsck` является `xfs_repair`. Если вы подозреваете, что с файловой системой что-то не так, в первую очередь необходимо проверить её на наличие повреждений.

Это можно сделать, передав параметр `-n` в `xfs_repair`, а затем указав устройство, содержащее файловую систему. Параметр `-n` означает «не изменять»: файловая система будет проверена, будут сообщены об ошибках, но исправления не будут внесены:

```bash
# xfs_repair -n /dev/sdb1
Phase 1 - find and verify superblock...
Phase 2 - using internal log
        - zero log...
        - scan filesystem freespace and inode maps...
        - found root inode chunk
Phase 3 - for each AG...
        - scan (but do not clear) agi unlinked lists...
        - process known inodes and perform inode discovery...
        - agno = 0
        - agno = 1
        - agno = 2
        - agno = 3
        - process newly discovered inodes...
Phase 4 - check for duplicate blocks...
        - setting up duplicate extent list...
        - check for inodes claiming duplicate blocks...
        - agno = 1
        - agno = 3
        - agno = 0
        - agno = 2
No modify flag set, skipping phase 5
Phase 6 - check inode connectivity...
        - traversing filesystem ...
        - traversal finished ...
        - moving disconnected inodes to lost+found ...
Phase 7 - verify link counts...
No modify flag set, skipping filesystem flush and exiting.
```

Если ошибки найдены, вы можете продолжить ремонт без параметра `-n`, например так: `xfs_repair /dev/sdb1`.

`xfs_repair` допускает ряд параметров командной строки. Среди них:

`-l LOGDEV` и `-r RTDEV`

Они необходимы, если в файловой системе есть разделы внешнего журнала и реального времени. В этом случае замените `LOGDEV` и `RTDEV` на соответствующие устройства.

`-m N`

Используется для ограничения использования памяти `xfs_repair` до `N` мегабайт, что может быть полезно при настройке сервера. Согласно справочной странице, по умолчанию `xfs_repair` будет масштабировать использование памяти по мере необходимости, вплоть до 75% физической оперативной памяти системы.

`-d`

«Особый» режим позволит восстановить файловые системы, подключённые только для чтения.

`-v`

Возможно, вы уже догадались: подробный режим. При каждом использовании этого параметра «подробность» увеличивается (например, `-v -v` выведет больше информации, чем просто `-v`).

Обратите внимание, что `xfs_repair` не может восстанавливать файловые системы с «грязным» журналом. Вы можете «обнулить» повреждённый журнал с помощью параметра `-L`, но имейте в виду, что это _крайняя мера_, так как это может привести к повреждению файловой системы и потере данных.

Для отладки файловой системы XFS можно использовать утилиту `xfs_db`, как в `xfs_db /dev/sdb1`. В основном она используется для проверки различных элементов и параметров файловой системы.

Эта утилита имеет интерактивную подсказку, со множеством внутренних команд. Также доступна справочная система: введите `help` для просмотра списка всех команд и `help` с последующим названием команды для просмотра дополнительной информации о ней.

Ещё одна полезная утилита — `xfs_fsr`, которую можно использовать для реорганизации («дефрагментации») файловой системы XFS. При запуске без дополнительных аргументов она будет работать в течение двух часов и попытается выполнить дефрагментацию всех подключённых файловых систем XFS с возможностью записи, перечисленных в файле `/etc/mtab/`. Возможно, вам потребуется установить эту утилиту с помощью менеджера пакетов для вашего дистрибутива Linux, так как она может не входить в стандартную установку. Для получения дополнительной информации обратитесь к соответствующей справочной странице.

## Ответы на упражнения с Руководством <a href="#sec.104.2_01-age" id="sec.104.2_01-age"></a>

1.  Используя `du`, как мы можем проверить, сколько места занимают только файлы в текущем каталоге?

    Сначала используйте параметр `-S` для разделения вывода текущего каталога и его подкаталогов. Затем используйте `-d 0` для ограничения глубины вывода до нуля, что означает «без подкаталогов». Не забудьте `-h` для вывода в «удобном для человека» формате:

    ```
    $ du -S -h -d 0
    ```

    или

    ```
    $ du -Shd 0
    ```
2.  С помощью `df` выведите информацию о каждой файловой системе ext4, включая следующие поля в указанном порядке: устройство, точка монтирования, общее количество индексных дескрипторов, количество доступных индексных дескрипторов, процент свободного места.

    Вы можете отфильтровать файловые системы с помощью опции `-t` и указания имени файловой системы. Чтобы получить нужный результат, используйте `--output=source,target,itotal,iavail,pcent`. Итак, ответ таков:

    ```bash
    $ df -t ext4 --output=source,target,itotal,iavail,pcent
    ```
3.  Какая команда используется для запуска `e2fsck` на `/dev/sdc1` в неинтерактивном режиме с попыткой автоматически исправить большинство ошибок?

    Параметр для автоматической попытки исправить большинство ошибок — `-p`. Таким образом, ответ таков:

    <pre class="language-bash"><code class="lang-bash"><strong># e2fsck -p /dev/sdc1
    </strong></code></pre>
4.  Предположим, что `/dev/sdb1` — это файловая система ext2. Как преобразовать её в ext3 и одновременно сбросить количество подключений и изменить метку на `UserData`?

    Помните, что преобразование файловой системы ext2 в ext3 — это просто добавление журнала, что можно сделать с помощью параметра `-j`. Чтобы сбросить количество подключений, используйте `-C 0`. Чтобы изменить метку, используйте `-L UserData`. Правильный ответ:

    <pre class="language-bash"><code class="lang-bash"><strong># tune2fs -j -C 0 -L UserData /dev/sdb1
    </strong></code></pre>
5.  Как можно проверить файловую систему XFS на наличие ошибок, _не_ устраняя обнаруженные повреждения?

    Используйте `-n` параметр, как в `xfs -n`, за которым следует соответствующее устройство.

## Ответы на исследовательские упражнения <a href="#sec.104.2_01-aee" id="sec.104.2_01-aee"></a>

1.  Предположим, что у вас есть файловая система ext4 на `/dev/sda1` со следующими параметрами, полученными с помощью `tune2fs`:

    ```bash
    Mount count:              8
    Maximum mount count:      -1
    ```

    Что произойдет при следующей загрузке, если будет выдана команда `tune2fs -c 9 /dev/sda1`?

    Эта команда установит максимальное количество подключений для файловой системы на 9. Поскольку в настоящее время количество подключений равно 8, при следующей загрузке системы будет выполнена проверка файловой системы.
2.  Рассмотрим следующий вывод `du -h`:

    ```bash
    $ du -h
    216K ./somedir/anotherdir
    224K ./somedir
    232K .
    ```

    Сколько места занимают только файлы в текущем каталоге? Как можно переписать команду, чтобы отобразить эту информацию более наглядно?

    Из 232 КБ, используемых в общей сложности, 224 КБ используются подкаталогом `somedir` и его подкаталогами. Таким образом, если не учитывать их, 8 КБ занимают файлы в текущем каталоге. Эту информацию можно отобразить более наглядно с помощью параметра `-S`, который разделяет каталоги в подсчёте.
3.  Что произойдёт с файловой системой ext2 `/dev/sdb1` при выполнении следующей команды?

    ```bash
    # tune2fs -j /dev/sdb1 -J device=/dev/sdc1 -i 30d
    ```

    В `/dev/sdb1` будет добавлен журнал, и он будет преобразован в ext3. Журнал будет храниться на устройстве `/dev/sdc1`, а файловая система будет проверяться каждые 30 дней.
4.  Как проверить наличие ошибок в файловой системе XFS на `/dev/sda1` с разделом журнала на `/dev/sdc1` без фактического исправления ошибок?

    Используйте `xfs_repair`, а затем `-l /dev/sdc1` для обозначения устройства, содержащего раздел журнала, и `-n` для того, чтобы не вносить никаких изменений.

    ```
    # xfs_repair -l /dev/sdc1 -n
    ```
5.  В чем разница между `-T` и `-t` параметрами для `df`?

    Параметр `-T` будет включать тип каждой файловой системы в вывод `df`. `-t` — это фильтр, который будет отображать только файловые системы заданного типа, исключая все остальные.
