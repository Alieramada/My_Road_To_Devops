# Урок 4.3.

## Введение <a href="#sec.104.3_01-in" id="sec.104.3_01-in"></a>

До сих пор вы изучали, как разбивать диски на разделы и как создавать и поддерживать файловые системы на них. Однако прежде чем получить доступ к файловой системе в Linux, её необходимо _смонтировать_.

Это означает присоединение файловой системы к определённой точке в дереве каталогов вашей системы, которая называется _точкой монтирования_. Файловые системы можно монтировать вручную или автоматически, и существует множество способов сделать это. В этом уроке мы рассмотрим некоторые из них.

## Монтирование и размонтирование файловых систем <a href="#mounting_and_unmounting_filesystems" id="mounting_and_unmounting_filesystems"></a>

Команда для ручного монтирования файловой системы вызывается `mount` и ее синтаксис таков:

```bash
mount -t TYPE DEVICE MOUNTPOINT
```

Где:

`TYPE`

Тип монтируемой файловой системы (например, ext4, btrfs, exfat и т. д.).

`DEVICE`

Имя раздела, содержащего файловую систему (например, `/dev/sdb1`)

`MOUNTPOINT`

Где будет смонтирована файловая система. Монтируемый каталог не обязательно должен быть пустым, но он должен существовать. Однако любые файлы в нём будут недоступны по имени, пока файловая система смонтирована.

Например, чтобы подключить USB-накопитель с файловой системой exFAT, расположенный в `/dev/sdb1` в каталоге `flash` в вашей домашней папке, вы можете использовать:

```bash
# mount -t exfat /dev/sdb1 ~/flash/
```

{% hint style="info" %}
Во многих системах Linux используется оболочка Bash, и в них тильда `~` в пути к точке монтирования является сокращением для домашнего каталога текущего пользователя. Если текущий пользователь называется `john`, например, то он будет заменен на `/home/john`.
{% endhint %}

После монтирования содержимое файловой системы будет доступно в каталоге `~/flash`:

```bash
$  ls -lh ~/flash/
total 469M
-rwxrwxrwx 1 root root 454M jul 19 09:49 lineage-16.0-20190711-MOD-quark.zip
-rwxrwxrwx 1 root root  16M jul 19 09:44 twrp-3.2.3-mod_4-quark.img
```

## **Список смонтированных файловых систем**

Если вы введёте только `mount`, вы получите список всех файловых систем, подключённых в данный момент к вашей системе. Этот список может быть довольно длинным, потому что помимо дисков, подключённых к вашей системе, он также содержит ряд файловых систем в памяти, которые служат различным целям. Чтобы отфильтровать вывод, вы можете использовать параметр `-t` для вывода только файловых систем соответствующего типа, как показано ниже:

```bash
# mount -t ext4
/dev/sda1 on / type ext4 (rw,noatime,errors=remount-ro)
```

Вы можете указать сразу несколько файловых систем, разделив их запятой:

```bash
# mount -t ext4,fuseblk
/dev/sda1 on / type ext4 (rw,noatime,errors=remount-ro)
/dev/sdb1 on /home/carol/flash type fuseblk (rw,nosuid,nodev,relatime,user_id=0,group_id=0,default_permissions,allow_other,blksize=4096) [DT_8GB]
```

Выходные данные в приведенных выше примерах могут быть описаны в формате:

```bash
SOURCE on TARGET type TYPE OPTIONS
```

Где `SOURCE` — это раздел, содержащий файловую систему, `TARGET` — это каталог, в котором она смонтирована, `TYPE` — это тип файловой системы, а `OPTIONS` — это параметры, передаваемые команде `mount` во время монтирования.

## **Дополнительные параметры командной строки**

Существует множество параметров командной строки, которые можно использовать с `mount`. Вот некоторые из наиболее часто используемых:

`-a`

Это позволит подключить все файловые системы, перечисленные в файле `/etc/fstab` (подробнее об этом в следующем разделе).

`-o` или `--options`

Это передаст список _параметров монтирования_, разделённых запятыми, в команду монтирования, которая может изменить способ монтирования файловой системы. Они также будут обсуждаться вместе с `/etc/fstab`.

`-r` или `-ro`

При этом файловая система будет смонтирована как доступная только для чтения.

`-w` или `-rw`

При этом файловая система будет смонтирована как доступная для записи.

Чтобы размонтировать файловую систему, используйте команду `umount` с указанием имени устройства или точки монтирования. В приведённом выше примере приведённые ниже команды взаимозаменяемы:

```bash
# umount /dev/sdb1
# umount ~/flash
```

Некоторые параметры командной строки для `umount` являются:

`-a`

При этом будут размонтированы все файловые системы, перечисленные в `/etc/fstab`.

`-f`

Это приведёт к размонтированию файловой системы. Это может быть полезно, если вы смонтировали удалённую файловую систему, которая стала недоступной.

`-r`

Если файловая система не может быть отключена, она будет переведена в режим только для чтения.

## **Работа с открытыми файлами**

При размонтировании файловой системы вы можете столкнуться с сообщением об ошибке, в котором говорится, что `target is busy`. Это происходит, если какие-либо файлы в файловой системе открыты. Однако может быть не сразу понятно, где находится открытый файл или что обращается к файловой системе.

В таких случаях вы можете использовать команду `lsof` с указанием имени устройства, содержащего файловую систему, чтобы просмотреть список процессов, обращающихся к ней, и открытых файлов. Например:

```bash
# umount /dev/sdb1
umount: /media/carol/External_Drive: target is busy.

# lsof /dev/sdb1
COMMAND  PID   USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
evince  3135 carol   16r   REG   8,17 21881768 5195 /media/carol/External_Drive/Documents/E-Books/MagPi40.pdf
```

`COMMAND` — это имя исполняемого файла, открывшего файл, а `PID` — номер процесса. `NAME` — это имя открытого файла. В приведённом выше примере файл `MagPi40.pdf` открыт программой `evince` (просмотрщиком PDF). Если мы закроем программу, то сможем отключить файловую систему.

{% hint style="info" %}
Перед появлением `lsof` вывода `GNOME` пользователи могут увидеть предупреждающее сообщение в окне терминала.

```bash
lsof: WARNING: can't stat() fuse.gvfsd-fuse file system /run/user/1000/gvfs
Output information may be incomplete.
```

`lsof` пытается обработать все подключенные файловые системы. Это предупреждающее сообщение появляется, потому что `lsof` столкнулся с `GNOME` виртуальной файловой системой (GVFS). Это особый случай файловой системы в пользовательском пространстве (`FUSE`). Она действует как мост между `GNOME`, его API и ядром. Никто, даже root, не может получить доступ к одной из этих файловых систем, кроме владельца, который ее подключил (в данном случае, `GNOME`). Вы можете игнорировать это предупреждение.
{% endhint %}

## **Куда монтировать?**

Вы можете подключить файловую систему в любом месте, где захотите. Однако есть несколько рекомендаций, которых следует придерживаться, чтобы упростить администрирование системы.

Традиционно `/mnt` был каталогом, в котором монтировались все внешние устройства, и в нём существовало несколько предварительно настроенных «якорных точек» для распространённых устройств, таких как приводы CD-ROM (`/mnt/cdrom`) и дискеты (`/mnt/floppy`).

Это было заменено на `/media`, которая теперь является точкой подключения по умолчанию для любых съёмных носителей (например, внешних дисков, USB-накопителей, карт памяти и т. д.), подключённых к системе.

В большинстве современных дистрибутивов Linux и настольных сред съёмные устройства автоматически монтируются под именем `/media/USER/LABEL` при подключении к системе, где `USER` — это имя пользователя, а `LABEL` — метка устройства. Например, USB-накопитель с меткой `FlashDrive` пользователя `john` будет смонтирован под именем `/media/john/FlashDrive/`. Способ обработки отличается в зависимости от настольной среды.

Тем не менее, если вам нужно _вручную_ смонтировать файловую систему, рекомендуется монтировать её под `/mnt`.

## Монтирование файловых систем при загрузке <a href="#mounting_filesystems_on_bootup" id="mounting_filesystems_on_bootup"></a>

Файл `/etc/fstab` содержит описания файловых систем, которые можно подключить. Это текстовый файл, в котором каждая строка описывает подключаемую файловую систему и содержит шесть полей в следующем порядке:

```bash
FILESYSTEM MOUNTPOINT TYPE OPTIONS DUMP PASS
```

Где:

`FILESYSTEM`

Устройство, содержащее файловую систему, которую нужно смонтировать. Вместо устройства можно указать UUID или метку раздела, о чём мы поговорим позже.

`MOUNTPOINT`

Где будет смонтирована файловая система.

`TYPE`

Тип файловой системы.

`OPTIONS`

Параметры монтирования, которые будут переданы в `mount`.

`DUMP`

Указывает, следует ли учитывать файловые системы ext2, ext3 или ext4 при резервном копировании с помощью команды `dump` . Обычно это значение равно нулю, что означает, что их следует игнорировать.

`PASS`

Если значение не равно нулю, определяет порядок, в котором файловые системы будут проверяться при загрузке. Обычно оно равно нулю.

Например, первый раздел на первом диске компьютера можно описать так:

```bash
/dev/sda1  /  ext4  noatime,errors
```

Параметры монтирования в `OPTIONS` представляют собой разделённый запятыми список параметров, которые могут быть общими или специфичными для файловой системы. Среди общих параметров мы имеем:

`atime` и `noatime`

По умолчанию при каждом чтении файла обновляется информация о времени доступа. Отключение этой функции (с помощью `noatime`) может ускорить дисковый ввод-вывод. Не путайте это со временем изменения, которое обновляется при каждой записи в файл.

`auto` и `noauto`

Может ли файловая система автоматически монтироваться (или не может) с помощью `mount -a`.

`defaults`

Это передаст параметры `rw`, `suid`, `dev`, `exec`, `auto`, `nouser` и `async` в `mount`.

`dev` и `nodev`

Следует ли интерпретировать символьные или блочные устройства в смонтированной файловой системе.

`exec` и `noexec`

Разрешать или запрещать выполнение двоичных файлов в файловой системе.

`user` и `nouser`

Позволяет (или нет) обычному пользователю монтировать файловую систему.

`group`

Позволяет пользователю смонтировать файловую систему, если он принадлежит к той же группе, что и владелец устройства, на котором она находится.

`owner`

Позволяет пользователю смонтировать файловую систему, если пользователь владеет устройством, на котором она находится.

`suid` и `nosuid`

Разрешить или запретить использование битов SETUID и SETGID.

`ro` и `rw`

Смонтируйте файловую систему как доступную только для чтения или записи.

`remount`

Это приведёт к попытке перемонтировать уже подключённую файловую систему. Это используется не в `/etc/fstab`, а в качестве параметра для `mount -o`. Например, чтобы перемонтировать уже подключённый раздел `/dev/sdb1` только для чтения, можно использовать команду `mount -o remount,ro /dev/sdb1`. При перемонтировании не нужно указывать тип файловой системы, только имя устройства _или_ точку подключения.

`sync` и `async`

Выполнять ли все операции ввода-вывода с файловой системой синхронно или асинхронно. `async` Обычно по умолчанию используется асинхронный режим. В руководстве по `mount` указано, что использование `sync` на носителях с ограниченным количеством циклов записи (например, на флеш-накопителях или картах памяти) может сократить срок службы устройства.

## Использование идентификаторов пользовательского интерфейса и меток <a href="#using_uuids_and_labels" id="using_uuids_and_labels"></a>

При указании имени устройства, содержащего файловую систему для монтирования, могут возникнуть некоторые проблемы. Иногда одно и то же имя устройства может быть присвоено другому устройству в зависимости от того, когда и где оно было подключено к вашей системе. Например, USB-накопитель `/dev/sdb1` может быть назначен `/dev/sdc1` при подключении к другому порту или после другого USB-накопителя.

Один из способов избежать этого — указать метку или UUID (_универсальный уникальный идентификатор_) тома. Оба параметра указываются при создании файловой системы и не меняются, если только файловая система не будет удалена или ей вручную не будет назначена новая метка или UUID.

С помощью команды `lsblk` можно запросить информацию о файловой системе и узнать связанную с ней метку и UUID. Для этого используйте параметр `-f` и укажите имя устройства:

```bash
$ lsblk -f /dev/sda1
NAME FSTYPE LABEL UUID                                 FSAVAIL FSUSE% MOUNTPOINT
sda1 ext4         6e2c12e3-472d-4bac-a257-c49ac07f3761   64,9G    33% /
```

Вот значение каждого столбца:

`NAME`

Имя устройства, содержащего файловую систему.

`FSTYPE`

Тип файловой системы.

`LABEL`

Метка файловой системы.

`UUID`

Универсально уникальный идентификатор (UUID), присваиваемый файловой системе.

`FSAVAIL`

Сколько свободного места доступно в файловой системе.

`FSUSE%`

Процент использования файловой системы.

`MOUNTPOINT`

Где монтируется файловая система.

В `/etc/fstab` устройство можно указать по его UUID с помощью опции `UUID=` с последующим указанием UUID или с помощью `LABEL=`, за которой следует метка. Таким образом, вместо:

```bash
/dev/sda1  /  ext4  noatime,errors
```

Вы бы использовали:

```bash
UUID=6e2c12e3-472d-4bac-a257-c49ac07f3761  /  ext4  noatime,errors
```

Или, если у вас есть диск с меткой `homedisk`:

```bash
LABEL=homedisk  /home ext4  defaults
```

Тот же синтаксис можно использовать с командой `mount` . Вместо имени устройства укажите UUID или метку. Например, чтобы подключить внешний диск NTFS с UUID `56C11DCC5D2E1334` к `/mnt/external`, выполните команду:

```bash
$ mount -t ntfs UUID=56C11DCC5D2E1334 /mnt/external
```

## Монтирование дисков с помощью Systemd <a href="#mounting_disks_with_systemd" id="mounting_disks_with_systemd"></a>

_Systemd_ — это процесс инициализации, первый процесс, запускаемый во многих дистрибутивах Linux. Он отвечает за запуск других процессов, служб и начальной загрузки системы. Помимо множества других задач, systemd также можно использовать для управления монтированием (и автоматическим монтированием) файловых систем.

Чтобы использовать эту функцию systemd, вам нужно создать файл конфигурации, называемый _единицей монтирования_. Каждый монтируемый том получает свою собственную единицу монтирования, и они должны быть размещены в `/etc/systemd/system/`.

Модули монтирования — это простые текстовые файлы с расширением `.mount` . Базовый формат показан ниже:

```bash
[Unit]
Description=

[Mount]
What=
Where=
Type=
Options=

[Install]
WantedBy=
```

`Description=`

Краткое описание узла монитрования, что-то вроде `Mounts the backup disk`.

`What=`

Что нужно подключить. Том должен быть указан как `/dev/disk/by-uuid/VOL_UUID` где `VOL_UUID` — это UUID тома.

`Where=`

Должен быть указан полный путь к месту монтирования тома.

`Type=`

Тип файловой системы.

`Options=`

Параметры монтирования, которые вы можете передать, аналогичны тем, что используются с командой `mount` или в `/etc/fstab`.

`WantedBy=`

Используется для управления зависимостями. В данном случае мы будем использовать `multi-user.target`, что означает, что при каждой загрузке системы в многопользовательской среде (обычная загрузка) модуль будет подключаться.

Наш предыдущий пример внешнего диска можно было бы записать в виде:

```bash
[Unit]
Description=External data disk

[Mount]
What=/dev/disk/by-uuid/56C11DCC5D2E1334
Where=/mnt/external
Type=ntfs
Options=defaults

[Install]
WantedBy=multi-user.target
```

Но мы ещё не закончили. Для корректной работы устройство монтирования _должно_ иметь то же имя, что и точка монтирования. В данном случае точка монтирования — `/mnt/external`, поэтому файл должен называться `mnt-external.mount`.

После этого вам нужно перезапустить демон systemd с помощью команды `systemctl` и запустить модуль:

```bash
# systemctl daemon-reload
# systemctl start mnt-external.mount
```

Теперь содержимое внешнего диска должно быть доступно на `/mnt/external`. Вы можете проверить состояние подключения с помощью команды `systemctl status mnt-external.mount`, как показано ниже:

```bash
# systemctl status mnt-external.mount
● mnt-external.mount - External data disk
   Loaded: loaded (/etc/systemd/system/mnt-external.mount; disabled; vendor pres
   Active: active (mounted) since Mon 2019-08-19 22:27:02 -03; 14s ago
    Where: /mnt/external
     What: /dev/sdb1
    Tasks: 0 (limit: 4915)
   Memory: 128.0K
   CGroup: /system.slice/mnt-external.mount

ago 19 22:27:02 pop-os systemd[1]: Mounting External data disk...
ago 19 22:27:02 pop-os systemd[1]: Mounted External data disk.
```

Команда `systemctl start mnt-external.mount` включит устройство только на текущем сеансе. Если вы хотите включать его при каждой загрузке, замените `start` на `enable`:

```
# systemctl enable mnt-external.mount
```

## **Автоматическое монтирование**

Устройства монтирования могут автоматически монтироваться при доступе к точке монтирования. Для этого вам понадобится файл `.automount` вместе с файлом `.mount` для описания устройства. Базовый формат:

```bash
[Unit]
Description=

[Automount]
Where=

[Install]
WantedBy=multi-user.target
```

Как и раньше, `Description=` — это краткое описание файла, а `Where=` — точка монтирования. Например, файл `.automount` для нашего предыдущего примера будет выглядеть так:

```bash
[Unit]
Description=Automount for the external data disk

[Automount]
Where=/mnt/external

[Install]
WantedBy=multi-user.target
```

Сохраните файл с тем же именем, что и точка монтирования (в данном случае `mnt-external.automount`), перезагрузите systemd и запустите модуль:

```bash
# systemctl daemon-reload
# systemctl start mnt-external.automount
```

Теперь при каждом обращении к каталогу `/mnt/external` диск будет монтироваться. Как и раньше, чтобы включить автоматическое монтирование при каждой загрузке, используйте:

```bash
# systemctl enable mnt-external.automount
```

## Ответы на упражнения с Руководством <a href="#sec.104.3_01-age" id="sec.104.3_01-age"></a>

1.  Используя `mount`, как можно смонтировать файловую систему `ext4` на `/dev/sdc1` в `/mnt/external` в режиме только для чтения с помощью параметров `noatime` и `async`?

    ```bash
    # mount -t ext4 -o noatime,async,ro /dev/sdc1 /mnt/external
    ```
2.  При отключении файловой системы в `/dev/sdd2` вы получаете сообщение об ошибке `target is busy`. Как узнать, какие файлы в файловой системе открыты и какие процессы их открыли?

    Используйте `lsof`, за которым следует название устройства:

    ```bash
    $ lsof /dev/sdd2
    ```
3.  Рассмотрим следующую запись в `/etc/fstab`: `/dev/sdb1 /data ext4 noatime,noauto,async`. Будет ли эта файловая система смонтирована, если будет выполнена команда `mount -a`? Почему?

    Он не будет смонтирован. Ключ — это параметр `noauto`, который означает, что эта запись будет игнорироваться `mount -a`.
4.  Как вы можете узнать UUID файловой системы в разделе `/dev/sdb1`?

    Используйте `lsblk -f`, за которым следует имя файловой системы:

    ```bash
    $ lsblk -f /dev/sdb1
    ```
5.  Как использовать `mount` для перемонтирования файловой системы exFAT с UUID `6e2c12e3-472d-4bac-a257-c49ac07f3761` в режиме только для чтения, смонтированной в `/mnt/data`?

    Поскольку файловая система подключена, вам не нужно беспокоиться о типе файловой системы или идентификаторе, просто используйте опцию `remount` с параметром `ro` (только для чтения) и точкой подключения:

    ```bash
    # mount -o remount,ro /mnt/data
    ```
6.  Как получить список всех файловых систем `ext3` и `ntfs` в системе, которые в данный момент подключены?

    Используйте `mount -t`, за которым следует разделенный запятыми список файловых систем:

    ```bash
    # mount -t ext3,ntfs
    ```

## Ответы на исследовательские упражнения <a href="#sec.104.3_01-aee" id="sec.104.3_01-aee"></a>

1.  Рассмотрим следующую запись в `/etc/fstab`: `/dev/sdc1 /backup ext4 noatime,nouser,async`. Может ли пользователь смонтировать эту файловую систему с помощью команды `mount /backup`? Почему?

    Нет, параметр `nouser` не позволит обычным пользователям монтировать эту файловую систему.
2.  Рассмотрим удалённую файловую систему, подключённую по адресу `/mnt/server`, которая стала недоступной из-за потери сетевого подключения. Как можно принудительно отключить её или подключить как доступную только для чтения, если это невозможно?

    Передайте параметры `-f` и `-r` для отключения. Команда будет выглядеть так: `umount -f -r /mnt/server`. Помните, что параметры можно группировать, поэтому `umount -fr /mnt/server` тоже подойдёт.
3.  Напишите запись `/etc/fstab` для монтирования тома btrfs с меткой `Backup` на `/mnt/backup` с параметрами по умолчанию и без разрешения на выполнение двоичных файлов.

    Строка должна быть `LABEL=Backup /mnt/backup btrfs defaults,noexec`
4.  Рассмотрим следующий модуль монтирования systemd:

    ```bash
    [Unit]
    Description=External data disk

    [Mount]
    What=/dev/disk/by-uuid/56C11DCC5D2E1334
    Where=/mnt/external
    Type=ntfs
    Options=defaults

    [Install]
    WantedBy=multi-user.target
    ```

    *   Что было бы эквивалентной `/etc/fstab` записью для этой файловой системы?

        Запись будет выглядеть так: `UUID=56C11DCC5D2E1334 /mnt/external ntfs defaults`
5.  Каким должно быть имя файла для описанного выше модуля, чтобы его можно было использовать в systemd? Где его следует разместить?

    Имя файла должно совпадать с точкой монтирования, поэтому `mnt-external.mount` помещается в `/etc/systemd/system`.
