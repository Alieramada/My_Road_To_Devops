# Урок 4.1.

## Введение <a href="#sec.104.1_01-in" id="sec.104.1_01-in"></a>

В любой операционной системе перед использованием диска его необходимо разбить на разделы. Раздел — это логическое подмножество физического диска, а информация о разделах хранится в таблице разделов. Эта таблица содержит информацию о первом и последнем секторах раздела и его типе, а также дополнительные сведения о каждом разделе.

Обычно операционная система воспринимает каждый раздел как отдельный «диск», даже если все они находятся на одном физическом носителе. В системах Windows им присваиваются буквы, например `C:` (исторически это основной диск), `D:` и так далее. В Linux каждому разделу присваивается каталог в `/dev`, например `/dev/sda1` или `/dev/sda2`.

В этом уроке вы узнаете, как создавать, удалять, восстанавливать и изменять размер разделов с помощью трёх наиболее распространённых утилит (`fdisk`, `gdisk` и `parted`), как создавать на них файловую систему, а также как создавать и настраивать _раздел подкачки_ или _файл подкачки_ для использования в качестве виртуальной памяти.

{% hint style="info" %}
По историческим причинам в этом уроке мы будем называть носители информации «дисками», хотя современные системы хранения данных, такие как твердотельные накопители и флеш-накопители, вообще не содержат «дисков».
{% endhint %}

## Понимание MBR и GPT <a href="#understanding_mbr_and_gpt" id="understanding_mbr_and_gpt"></a>

Существует два основных способа хранения информации о разделах на жёстких дисках. Первый — MBR (_главная загрузочная запись Master Boot Record_), а второй — GPT (_таблица разделов GUID GUID Partition Table_).

MBR

Это пережиток ранних версий MS-DOS (в частности, PC-DOS 2.0 1983 года), которая на протяжении десятилетий была стандартной схемой разбиения на разделы на ПК. Таблица разделов хранится в первом секторе диска, называемом _загрузочным сектором_, вместе с загрузчиком, который в системах Linux обычно представляет собой загрузчик _GRUB_. Но у MBR есть ряд ограничений, которые препятствуют его использованию в современных системах, например, невозможность обращения к дискам размером более 2 ТБ и ограничение в 4 основных раздела на диск.

GUID

Система разбиения на разделы, которая устраняет многие недостатки MBR. Нет практического ограничения по размеру диска, а максимальное количество разделов ограничено только самой операционной системой. Она чаще встречается на более современных устройствах, использующих UEFI вместо старого BIOS.

При выполнении задач по администрированию системы вы, скорее всего, столкнётесь с использованием обеих схем, поэтому важно знать, как использовать инструменты, связанные с каждой из них, для создания, удаления или изменения разделов.

## **Управление разделами MBR с помощью FDISK**

Стандартной утилитой для управления разделами MBR в Linux является `fdisk`. Это интерактивная утилита с меню. Чтобы использовать её, введите `fdisk` и укажите имя устройства, соответствующего диску, который вы хотите отредактировать. Например, команда

```bash
# fdisk /dev/sda
```

нужно отредактировать таблицу разделов первого подключённого к SATA устройства (`sda`) в системе. Имейте в виду, что вам нужно указать устройство, соответствующее физическому диску, а не одному из его разделов (например, `/dev/sda1`).

{% hint style="info" %}
Все операции с дисками в этом уроке необходимо выполнять от имени пользователя `root` (системного администратора) или с правами суперпользователя `sudo`.
{% endhint %}

При вызове `fdisk` отобразится приветствие, затем предупреждение, и он будет ждать ваших команд.

```bash
# fdisk /dev/sda
Welcome to fdisk (util-linux 2.33.1).
Changes will remain in memory only, until you decide to write them.
Be careful before using the write command.

Command (m for help):
```

Это важное предупреждение. Вы можете создавать, редактировать или удалять разделы по своему усмотрению, но _ничего_ не будет записано на диск, если вы не воспользуетесь командой записи (`w`). Таким образом, вы можете «практиковаться» без риска потери данных, если не будете нажимать клавишу `w`. Чтобы выйти `fdisk` без сохранения изменений, используйте команду `q`.

{% hint style="info" %}
Тем не менее, вам не следует практиковаться на важных дисках, так как это всегда сопряжено с риском. Вместо этого используйте запасной внешний диск или USB-накопитель.
{% endhint %}

## **Печать текущей таблицы разделов**

Команда `p` используется для вывода текущей таблицы разделов. Вывод выглядит примерно так:

```bash
Command (m for help): p
Disk /dev/sda: 111.8 GiB, 120034123776 bytes, 234441648 sectors
Disk model: CT120BX500SSD1
Units: sectors of 1 * 512 = 512 bytes
Sector size (logical/physical): 512 bytes / 512 bytes
I/O size (minimum/optimal): 512 bytes / 512 bytes
Disklabel type: dos
Disk identifier: 0x97f8fef5

Device     Boot     Start       End   Sectors   Size Id Type
/dev/sda1            4096 226048942 226044847 107.8G 83 Linux
/dev/sda2       226048944 234437550   8388607     4G 82 Linux swap / Solaris
```

Вот значение каждого столбца:

`Device`

Устройство, назначенное разделу.

`Boot`

Показывает, является ли раздел "загрузочным” или нет.

`Start`

Сектор, с которого начинается раздел.

`End`

Сектор, где заканчивается раздел.

`Sectors`

Общее количество секторов в разделе. Умножьте его на размер сектора, чтобы получить размер раздела в байтах.

`Size`

Размер раздела в «удобном для восприятия человеком» формате. В приведенном выше примере значения указаны в гигабайтах.

`Id`

Числовое значение, представляющее тип раздела.

`Type`

Описание типа раздела.

## **Основные разделы против расширенных**

На диске MBR можно создать 2 основных типа разделов: _основные_ и _расширенные_. Как мы уже говорили, на диске можно создать только 4 основных раздела, и если вы хотите сделать диск «загрузочным», первый раздел должен быть основным.

Один из способов обойти это ограничение — создать расширенный раздел, который будет служить контейнером для _логических_ разделов. Например, у вас может быть основной раздел, расширенный раздел, занимающий оставшуюся часть дискового пространства, и пять логических разделов внутри него.

Для такой операционной системы, как Linux, первичные и расширенные разделы обрабатываются одинаково, поэтому нет «преимуществ» в использовании одного из них.

**Создание раздела**

Чтобы создать раздел, используйте команду `n` . По умолчанию разделы будут создаваться в начале нераспределённого пространства на диске. Вам будет предложено выбрать тип раздела (основной или расширенный), первый и последний сектора.

Для первого сектора обычно можно принять значение по умолчанию, предложенное `fdisk`, если только вам не нужно, чтобы раздел начинался с определённого сектора. Вместо указания последнего сектора можно указать размер, а затем буквы `K`, `M`, `G`, `T` или `P` (кило, мега, гига, тера или пета). Таким образом, если вы хотите создать раздел размером 1 ГБ, вы можете указать `+1G` в качестве `Last sector`, и `fdisk` определит размер раздела соответствующим образом. См. этот пример создания основного раздела:

```bash
Command (m for help): n
Partition type
   p   primary (0 primary, 0 extended, 4 free)
   e   extended (container for logical partitions)
Select (default p): p
Partition number (1-4, default 1): 1
First sector (2048-3903577, default 2048): 2048
Last sector, +/-sectors or +/-size{K,M,G,T,P} (2048-3903577, default 3903577): +1G
```

## **Проверка наличия нераспределенного пространства**

Если вы не знаете, сколько свободного места на диске, вы можете использовать команду `F` для отображения нераспределённого пространства следующим образом:

```bash
Command (m for help): F
Unpartitioned space /dev/sdd: 881 MiB, 923841536 bytes, 1804378 sectors
Units: sectors of 1 * 512 = 512 bytes
Sector size (logical/physical): 512 bytes / 512 bytes

  Start     End Sectors  Size
2099200 3903577 1804378  881M
```

## **Удаление разделов**

Чтобы удалить раздел, используйте команду `d`. `fdisk` запросит у вас номер раздела, который вы хотите удалить, _если только_ на диске _не будет только одного_ раздела. В этом случае этот раздел будет _выбран и немедленно удалён_.

Имейте в виду, что при удалении расширенного раздела все логические разделы внутри него также будут удалены.

**Следите за Пробелом!**

Имейте в виду, что при создании нового раздела с помощью `fdisk` максимальный размер будет ограничен максимальным количеством _непрерывного_ нераспределённого пространства на диске. Допустим, у вас есть следующая карта разделов:

```bash
Device     Boot   Start     End Sectors  Size Id Type
/dev/sdd1          2048 1050623 1048576  512M 83 Linux
/dev/sdd2       1050624 2099199 1048576  512M 83 Linux
/dev/sdd3       2099200 3147775 1048576  512M 83 Linux
```

Затем вы удаляете раздел 2 и проверяете наличие свободного места:

```bash
Command (m for help): F
Unpartitioned space /dev/sdd: 881 MiB, 923841536 bytes, 1804378 sectors
Units: sectors of 1 * 512 = 512 bytes
Sector size (logical/physical): 512 bytes / 512 bytes

  Start     End Sectors  Size
1050624 2099199 1048576  512M
3147776 3903577  755802  369M
```

Если сложить размер нераспределённого пространства, то теоретически у нас будет 881 МБ свободного места. Но посмотрим, что произойдёт, если мы попытаемся создать раздел размером 700 МБ:

```bash
Command (m for help): n
Partition type
   p   primary (2 primary, 0 extended, 2 free)
   e   extended (container for logical partitions)
Select (default p): p
Partition number (2,4, default 2): 2
First sector (1050624-3903577, default 1050624):
Last sector, +/-sectors or +/-size{K,M,G,T,P} (1050624-2099199, default 2099199): +700M
Value out of range.
```

Это происходит потому, что самым большим непрерывным нераспределённым пространством на диске является блок размером 512 МБ, который принадлежал разделу 2. Ваш новый раздел не может «перекрыть» раздел 3, чтобы использовать часть нераспределённого пространства после него.

## **Изменение типа раздела**

Иногда может потребоваться изменить тип раздела, особенно при работе с дисками, которые будут использоваться в других операционных системах и на других платформах. Это делается с помощью команды `t`, за которой следует номер раздела, который вы хотите изменить.

Тип раздела должен быть указан соответствующим шестнадцатеричным кодом. Список всех допустимых кодов можно увидеть с помощью команды `l`.

Не путайте тип раздела с используемой в нём файловой системой. Хотя изначально между ними была связь, сегодня вы не можете считать это верным. Например, раздел Linux может содержать любую файловую систему Linux, такую как _ext4_ или _ReiserFS_.

{% hint style="info" %}
Разделы Linux имеют тип `83` (Linux). Разделы подкачки имеют тип `82` (Linux Swap).
{% endhint %}

## **Управление разделами GUID с помощью GDISK**

Утилита `gdisk` является эквивалентом `fdisk` при работе с дисками с разделами GPT. Фактически, интерфейс создан по образцу `fdisk` с интерактивной подсказкой и теми же (или очень похожими) командами.

## **Печать текущей таблицы разделов**

Команда `p` используется для вывода текущей таблицы разделов. Вывод выглядит примерно так:

```bash
Command (? for help): p
Disk /dev/sdb: 3903578 sectors, 1.9 GiB
Model: DataTraveler 2.0
Sector size (logical/physical): 512/512 bytes
Disk identifier (GUID): AB41B5AA-A217-4D1E-8200-E062C54285BE
Partition table holds up to 128 entries
Main partition table begins at sector 2 and ends at sector 33
First usable sector is 34, last usable sector is 3903544
Partitions will be aligned on 2048-sector boundaries
Total free space is 1282071 sectors (626.0 MiB)

Number  Start (sector)    End (sector)  Size       Code  Name
   1            2048         2099199   1024.0 MiB  8300  Linux filesystem
   2         2623488         3147775   256.0 MiB   8300  Linux filesystem
```

С самого начала мы замечаем несколько разных вещей:

* У каждого диска есть уникальный идентификатор (GUID). Это 128-битное шестнадцатеричное число, присваиваемое случайным образом при создании таблицы разделов. Поскольку существует 3,4 × 1038 возможных значений для этого числа, вероятность того, что два случайных диска будут иметь одинаковый GUID, довольно мала. GUID можно использовать для определения того, какие файловые системы следует подключить во время загрузки (и где), что избавляет от необходимости использовать для этого путь к устройству (например, `/dev/sdb`).
* Видите фразу `Partition table holds up to 128 entries`? Верно, на диске GPT можно создать до 128 разделов. Благодаря этому нет необходимости в _основных_ и _расширенных_ разделах.
* Свободное место указано в последней строке, поэтому нет необходимости в эквиваленте команды `F` из fdisk.

## **Создание раздела**

Команда для создания раздела — `n`, как и в `fdisk`. Основное отличие заключается в том, что помимо номера раздела и первого и последнего секторов (или размера) вы также можете указать тип раздела во время его создания. Разделы GPT поддерживают гораздо больше типов, чем MBR. Вы можете просмотреть список всех поддерживаемых типов с помощью команды `l`.

**Удаление раздела**

Чтобы удалить раздел, введите `d` и номер раздела. В отличие от `fdisk`, первый раздел не будет выбран автоматически, если он является единственным на диске.

На GPT-дисках разделы можно легко переупорядочить или «отсортировать», чтобы избежать пробелов в последовательности нумерации. Для этого просто используйте команду `s` . Например, представьте диск со следующей таблицей разделов:

```bash
Number  Start (sector)    End (sector)  Size       Code  Name
   1            2048         2099199   1024.0 MiB  8300  Linux filesystem
   2         2099200         2361343   128.0 MiB   8300  Linux filesystem
   3         2361344         2623487   128.0 MiB   8300  Linux filesystem
```

Если вы удалите второй раздел, таблица станет:

```bash
Number  Start (sector)    End (sector)  Size       Code  Name
   1            2048         2099199   1024.0 MiB  8300  Linux filesystem
   3         2361344         2623487   128.0 MiB   8300  Linux filesystem
```

Если вы используете команду `s`, это станет:

```bash
Number  Start (sector)    End (sector)  Size       Code  Name
   1            2048         2099199   1024.0 MiB  8300  Linux filesystem
   2         2361344         2623487   128.0 MiB   8300  Linux filesystem
```

Обратите внимание, что третий раздел стал вторым.

**Пробел? Какой пробел?**

В отличие от MBR-дисков, при создании раздела на GPT-дисках размер не ограничивается максимальным количеством _непрерывного_ нераспределённого пространства. Вы можете использовать каждый свободный сектор, независимо от того, где он находится на диске.

## **Варианты восстановления**

На дисках GPT хранятся резервные копии заголовка GPT и таблицы разделов, что упрощает восстановление дисков в случае повреждения этих данных. `gdisk` предоставляет функции, помогающие в восстановлении, доступ к которым осуществляется с помощью команды `r`.

Вы можете восстановить поврежденный основной заголовок GPT или таблицу разделов с помощью `b` и `c` соответственно, или использовать основной заголовок и таблицу для восстановления резервной копии с помощью `d` и `e`. Помимо других операций, вы также можете преобразовать MBR в GPT с помощью `f` и сделать обратное с помощью `g`. Введите `?` в меню восстановления, чтобы получить список всех доступных команд восстановления и описания того, что они делают.

## Создание файловых систем <a href="#creating_file_systems" id="creating_file_systems"></a>

Разбивка диска на разделы — это только первый шаг к его использованию. После этого вам нужно будет отформатировать раздел с помощью файловой системы, прежде чем использовать его для хранения данных.

Файловая система управляет тем, как данные хранятся на диске и как к ним осуществляется доступ. Linux поддерживает множество файловых систем, некоторые из которых являются встроенными, например, семейство ext (расширенная файловая система), а другие взяты из других операционных систем, таких как FAT из MS-DOS, NTFS из Windows NT, HFS и HFS+ из Mac OS и т. д.

Стандартным инструментом для создания файловой системы в Linux является `mkfs`, который существует во множестве «вариантов» в зависимости от файловой системы, с которой он должен работать.

**Создание файловой системы ext2 / ext3 / ext4**

_Расширенная файловая система_ (ext) была первой файловой системой для Linux и с годами была заменена новыми версиями, названными ext2, ext3 и ext4, которые в настоящее время являются файловыми системами по умолчанию для многих дистрибутивов Linux.

Утилиты `mkfs.ext2`, `mkfs.ext3` и `mkfs.ext4` используются для создания файловых систем ext2, ext3 и ext4. На самом деле все эти «утилиты» существуют только как символические ссылки на другую утилиту под названием `mke2fs`. `mke2fs` изменяет свои настройки по умолчанию в зависимости от имени, под которым она вызывается. Таким образом, все они ведут себя одинаково и имеют одинаковые параметры командной строки.

Наиболее простой формой использования является:

```bash
# mkfs.ext2 TARGET
```

Где `TARGET` — имя раздела, в котором должна быть создана файловая система. Например, для создания файловой системы ext3 в `/dev/sdb1` команда будет выглядеть так:

```bash
# mkfs.ext3 /dev/sdb1
```

Вместо использования команды, соответствующей файловой системе, которую вы хотите создать, вы можете передать параметр `-t` в `mke2fs` с последующим указанием имени файловой системы. Например, следующие команды эквивалентны и создадут файловую систему ext4 на `/dev/sdb1`.

```bash
# mkfs.ext4 /dev/sdb1
# mke2fs -t ext4 /dev/sdb1
```

## **Параметры командной строки**

`mke2fs` поддерживает широкий спектр параметров и опций командной строки. Вот некоторые из наиболее важных из них. Все они также применимы к `mkfs.ext2`, `mkfs.ext3` и `mkfs.ext4`:

`-b SIZE`

Устанавливает размер блоков данных в устройстве на `SIZE` байт, что может составлять 1024, 2048 или 4096 байт на блок.

`-c`

Перед созданием файловой системы проверяет целевое устройство на наличие поврежденных блоков. Вы можете выполнить тщательную, но гораздо более медленную проверку, передав этот параметр дважды, как в `mkfs.ext4 -c -c TARGET`.

`-d DIRECTORY`

Копирует содержимое указанного каталога в корень новой файловой системы. Полезно, если вам нужно «предварительно заполнить» диск заранее подготовленным набором файлов.

`-F`

_Осторожно, Уилл Робинсон!_ Этот параметр _заставит_ mke2fs создать файловую систему, даже если другие переданные ему параметры или цель опасны или вообще бессмысленны. Если он указан дважды (как в `-F -F`), его можно использовать даже для создания файловой системы на устройстве, которое подключено или используется, что очень, _очень_ плохо.

`-L VOLUME_LABEL`

Будет установлена метка тома, указанная в `VOLUME_LABEL`. Эта метка должна содержать не более 16 символов.

`-n`

Это действительно полезная опция, которая имитирует создание файловой системы и показывает, что было бы сделано, если бы она выполнялась без опции `n` . Думайте об этом как о «пробном» режиме. Полезно проверить всё перед тем, как вносить какие-либо изменения на диск.

`-q`

Тихий режим. `mke2fs` будет работать в обычном режиме, но не будет выводить данные на терминал. Полезно при запуске `mke2fs` из скрипта.

`-U ID`

Это позволит задать UUID (_универсальный уникальный идентификатор_) раздела со значением, указанным в качестве идентификатора. UUID — это 128-битные числа в шестнадцатеричной системе счисления, которые служат для уникальной идентификации раздела в операционной системе. Это число задается в виде 32-значной строки в формате 8-4-4-4-12, что означает 8 цифр, дефис, 4 цифры, дефис, 4 цифры, дефис, 4 цифры, дефис, 12 цифр, например `D249E380-7719-45A1-813C-35186883987E`. Вместо идентификатора вы также можете указать параметры, например `clear` для очистки UUID файловой системы, `random` для использования случайно сгенерированного UUID или `time` для создания UUID на основе времени.

`-V`

Подробный режим выводит гораздо больше информации во время работы, чем обычно. Полезно для отладки.

## **Создание файловой системы XFS**

XFS — это высокопроизводительная файловая система, изначально разработанная компанией Silicon Graphics в 1993 году для операционной системы IRIX. Благодаря своей производительности и надёжности она широко используется на серверах и в других средах, где требуется высокая (или гарантированная) пропускная способность файловой системы.

Инструменты для управления файловыми системами XFS входят в состав пакета `xfsprogs` . Этот пакет может потребоваться установить вручную, так как он не входит в состав некоторых дистрибутивов Linux по умолчанию. В других дистрибутивах, например Red Hat Enterprise Linux 7, XFS используется в качестве файловой системы по умолчанию.

Файловые системы XFS делятся как минимум на 2 части: _сегмент журнала_, в котором ведётся журнал всех операций с файловой системой (обычно называемый _журналом_), и _сегмент данных_. Сегмент журнала может находиться внутри сегмента данных (по умолчанию) или даже на отдельном диске для повышения производительности и надёжности.

Самая простая команда для создания файловой системы XFS — `mkfs.xfs TARGET`, где `TARGET` — раздел, в котором вы хотите создать файловую систему. Например: `mkfs.xfs /dev/sda1`.

Как и в случае с `mke2fs`, `mkfs.xfs` поддерживает ряд параметров командной строки. Вот некоторые из наиболее распространённых.

`-b size=VALUE`

Устанавливает размер блока в файловой системе в байтах, равный значению, указанному в `VALUE`. Значение по умолчанию — 4096 байт (4 КиБ), минимальное значение — 512, а максимальное — 65536 (64 КиБ).

`-m crc=VALUE`

Параметры, начинающиеся с `-m`, — это параметры метаданных. Этот параметр включает (если `VALUE` равно `1`) или отключает (если `VALUE` равно `0`) использование проверок CRC32c для проверки целостности всех метаданных на диске. Это позволяет лучше обнаруживать ошибки и восстанавливаться после сбоев, связанных с аппаратными проблемами, поэтому по умолчанию этот параметр включен. Влияние этой проверки на производительность должно быть минимальным, поэтому обычно нет причин отключать ее.

`-m uuid=VALUE`

Устанавливает UUID раздела на значение, указанное в качестве VALUE. Помните, что UUID — это 32-значные (128 бит) числа в шестнадцатеричной системе счисления, состоящие из групп по 8, 4, 4, 4 и 12 цифр, разделённых тире, например `1E83E3A3-3AE9-4AAC-BF7E-29DFFECD36C0`.

`-f`

Принудительно создайте файловую систему на целевом устройстве, даже если на нём уже есть файловая система.

`-l logdev=DEVICE`

Это позволит разместить раздел журнала файловой системы на указанном устройстве, а не внутри раздела данных.

`-l size=VALUE`

При этом размер раздела журнала будет равен размеру, указанному в `VALUE`. Размер может быть указан в байтах, и могут использоваться такие суффиксы, как `m` или `g`. `-l size=10m`, например, ограничит раздел журнала 10 мегабайтами.

`-q`

Тихий режим. В этом режиме `mkfs.xfs` не будут выводиться параметры создаваемой файловой системы.

`-L LABEL`

Задаёт метку файловой системы, которая может содержать не более 12 символов.

`-N`

Подобно параметру `-n` в `mke2fs`, `mkfs.xfs` выведет все параметры для создания файловой системы, не создавая её.

## **Создание файловой системы FAT или VFAT**

Файловая система FAT была разработана для MS-DOS и за прошедшие годы претерпела множество изменений, кульминацией которых стал формат FAT32, выпущенный в 1996 году вместе с Windows 95 OSR2.

VFAT — это расширение формата FAT16 с поддержкой длинных (до 255 символов) имён файлов. Обе файловые системы обрабатываются одной и той же утилитой `mkfs.fat`. `mkfs.vfat` является её псевдонимом.

Файловая система FAT имеет существенные недостатки, которые ограничивают её использование на больших дисках. Например, FAT16 поддерживает тома размером не более 4 ГБ и максимальный размер файлов 2 ГБ. FAT32 увеличивает размер тома до 2 ПБ, а максимальный размер файлов до 4 ГБ. Из-за этого файловые системы FAT сегодня чаще используются на небольших флеш-накопителях или картах памяти (размером до 2 ГБ), а также на устаревших устройствах и операционных системах, которые не поддерживают более продвинутые файловые системы.

Самая простая команда для создания файловой системы FAT — `mkfs.fat TARGET`, где `TARGET` — это раздел, в котором вы хотите создать файловую систему. Например: `mkfs.fat /dev/sdc1`.

Как и другие утилиты, `mkfs.fat` поддерживает ряд параметров командной строки. Ниже приведены наиболее важные из них. Полный список и описание каждого параметра можно найти в руководстве по утилите с помощью команды `man mkfs.fat`.

`-c`

Проверяет целевое устройство на наличие поврежденных блоков перед созданием файловой системы.

`-C FILENAME BLOCK_COUNT`

Будет создан файл, указанный в `FILENAME`, а затем внутри него будет создана файловая система FAT, что фактически создаст пустой «образ диска», который впоследствии можно будет записать на устройство с помощью такой утилиты, как `dd` или подключить как петлевое устройство. При использовании этой опции после имени устройства необходимо указать количество блоков в файловой системе (`BLOCK_COUNT`).

`-F SIZE`

Выберите размер FAT (_File Allocation Table_) — 12, 16 или 32, то есть FAT12, FAT16 или FAT32. Если не указано, `mkfs.fat` будет выбран подходящий вариант в зависимости от размера файловой системы.

`-n NAME`

Задаёт метку тома или имя для файловой системы. Длина имени может достигать 11 символов, по умолчанию имя не задано.

`-v`

Подробный режим. Выводит гораздо больше информации, чем обычно, что полезно для отладки.

{% hint style="info" %}
`mkfs.fat` _Невозможно_ создать «загрузочную» файловую систему. Согласно странице руководства, «это не так просто, как может показаться», и это не будет реализовано.
{% endhint %}

## **Создание файловой системы exFAT**

exFAT — это файловая система, созданная Microsoft в 2006 году, которая устраняет одно из важнейших ограничений FAT32: размер файлов и дисков. В exFAT максимальный размер файла составляет 16 эксабайтов (против 4 ГБ в FAT32), а максимальный размер диска — 128 петабайтов.

Поскольку она хорошо поддерживается всеми тремя основными операционными системами (Windows, Linux и Mac OS), это хороший выбор там, где требуется совместимость, например, на флеш-накопителях большой ёмкости, картах памяти и внешних дисках. Фактически, это файловая система по умолчанию, определённая _Ассоциацией SD_, для карт памяти SDXC объёмом более 32 ГБ.

Утилита по умолчанию для создания файловых систем exFAT — `mkfs.exfat`, которая является ссылкой на `mkexfatfs`. Самая простая команда — `mkfs.exfat TARGET`, где `TARGET` — это раздел, в котором вы хотите создать файловую систему. Например: `mkfs.exfat /dev/sdb2`.

В отличие от других утилит, рассмотренных в этом уроке, `mkfs.exfat` имеет очень мало параметров командной строки. Вот они:

`-i VOL_ID`

Устанавливает идентификатор тома на значение, указанное в `VOL_ID`. Это 32-разрядное шестнадцатеричное число. Если идентификатор не задан, устанавливается идентификатор на основе текущего времени.

`-n NAME`

Задаёт метку тома или имя. Оно может содержать до 15 символов, а по умолчанию имя не задано.

`-p SECTOR`

Указывает первый сектор первого раздела на диске. Это необязательное значение, по умолчанию оно равно нулю.

`-s SECTORS`

Определяет количество физических секторов в кластере распределения. Это должно быть число, являющееся степенью двойки, например 1, 2, 4, 8 и так далее.

## **Знакомство с файловой системой Btrfs**

Btrfs (официальное название _файловая система B-Tree_, произносится как «Butter FS», «Better FS» или даже «Butterfuss», на ваш выбор) — это файловая система, которая разрабатывается с 2007 года специально для Linux корпорацией Oracle и другими компаниями, в том числе Fujitsu, Red Hat, Intel, SUSE и другими.

Существует множество функций, которые делают Btrfs привлекательной для современных систем, где часто используются большие объёмы памяти. Среди них — поддержка нескольких устройств (включая чередование, зеркалирование и чередование+зеркалирование, как в RAID-массиве), прозрачное сжатие, оптимизация SSD, инкрементное резервное копирование, моментальные снимки, онлайн-дефрагментация, офлайн-проверка, поддержка подтомов (с квотами), дедупликация и многое другое.

Поскольку это файловая система _с копированием при записи_, она очень устойчива к сбоям. Кроме того, Btrfs проста в использовании и хорошо поддерживается многими дистрибутивами Linux. А некоторые из них, например SUSE, используют её в качестве файловой системы по умолчанию.

{% hint style="info" %}
В традиционной файловой системе, когда вы хотите перезаписать часть файла, новые данные записываются непосредственно поверх старых данных, которые они заменяют. В файловой системе _с копированием при записи_ новые данные записываются в свободное место на диске, затем исходные метаданные файла обновляются, чтобы ссылаться на новые данные, и только после этого старые данные освобождаются, так как они больше не нужны. Это снижает вероятность потери данных в случае сбоя, поскольку старые данные удаляются только после того, как файловая система абсолютно уверена, что они больше не нужны, а новые данные уже на месте.
{% endhint %}

## **Создание файловой системы Btrfs**

Утилита `mkfs.btrfs` используется для создания файловой системы Btrfs. При использовании команды без каких-либо параметров на заданном устройстве создаётся файловая система Btrfs следующим образом:

```bash
# mkfs.btrfs /dev/sdb1
```

{% hint style="info" %}
Если в вашей системе нет утилиты `mkfs.btrfs` , найдите `btrfs-progs` в менеджере пакетов вашего дистрибутива.
{% endhint %}

Вы можете использовать `-L` для установки метки (или имени) для вашей файловой системы. Метки Btrfs могут содержать до 256 символов, кроме символов новой строки:

```bash
# mkfs.btrfs /dev/sdb1 -L "New Disk"
```

{% hint style="info" %}
Заключите метку в кавычки (как указано выше), если она содержит пробелы.
{% endhint %}

Обратите внимание на особенность Btrfs: вы можете передать _несколько_ устройств в команду `mkfs.btrfs`. При передаче более одного устройства файловая система будет охватывать все устройства, что аналогично настройке RAID или LVM. Чтобы указать, как метаданные будут распределяться в дисковом массиве, используйте параметр `-m`. Допустимые параметры: `raid0`, `raid1`, `raid5`, `raid6`, `raid10`, `single` и `dup`.

Например, чтобы создать файловую систему, охватывающую `/dev/sdb1` и `/dev/sdc1`, объединив два раздела в один большой, используйте:

```bash
# mkfs.btrfs -d single -m single /dev/sdb /dev/sdc
```

{% hint style="info" %}
Файловые системы, охватывающие несколько разделов, как показано выше, на первый взгляд могут показаться выгодными, но это не лучшая идея с точки зрения безопасности данных, поскольку сбой на одном из дисков массива означает неизбежную потерю данных. Чем больше дисков вы используете, тем выше риск, так как у вас появляется больше возможных точек отказа.
{% endhint %}

## **Управление** Subvolumes.

Subvolumes похожи на файловые системы внутри файловых систем. Представьте их как каталог, который можно подключить (и использовать) как отдельную файловую систему. Subvolumes упрощают организацию и администрирование системы, поскольку каждый из них может иметь отдельные квоты или правила создания снимков.

{% hint style="info" %}
Подтома не являются разделами. Раздел выделяет фиксированное пространство на диске. Это может привести к проблемам в дальнейшем, например, к нехватке места в одном разделе, когда в другом его ещё много. С подтомами такого не происходит, поскольку они «разделяют» свободное пространство своей корневой файловой системы и увеличиваются по мере необходимости.
{% endhint %}

Предположим, у вас есть файловая система Btrfs, подключённая к `/mnt/disk`, и вы хотите создать внутри неё подтом для хранения резервных копий. Давайте назовём его `BKP`:

```bash
# btrfs subvolume create /mnt/disk/BKP
```

Далее мы перечислим содержимое файловой системы `/mnt/disk` . Вы увидите, что у нас появился новый каталог, названный в честь нашего подтома.

```bash
$ ls -lh /mnt/disk/
total 0
drwxr-xr-x 1 root   root     0 jul 13 17:35 BKP
drwxrwxr-x 1 carol carol 988 jul 13 17:30 Images
```

{% hint style="info" %}
Да, к вложенным объемам можно _также_ обращаться, как к любому другому каталогу.
{% endhint %}

Мы можем проверить, активен ли вложенный объем, с помощью команды:

```bash
# btrfs subvolume show /mnt/disk/BKP/
	Name: 			BKP
	UUID: 			e90a1afe-69fa-da4f-9764-3384f66fa32e
	Parent UUID: 		-
	Received UUID: 		-
	Creation time: 		2019-07-13 17:35:40 -0300
	Subvolume ID: 		260
	Generation: 		23
	Gen at creation: 	22
	Parent ID: 		5
	Top level ID: 		5
	Flags: 			-
	Snapshot(s):
```

Вы можете подключить дополнительный том к `/mnt/BKP` с помощью параметра `-t btrfs -o subvol=NAME` в команде `mount`:

```bash
# mount -t btrfs -o subvol=BKP /dev/sdb1 /mnt/bkp
```

{% hint style="info" %}
Параметр `-t` определяет тип файловой системы, которая будет смонтирована.
{% endhint %}

## **Работа со моментальными снимками**

Снимки — это те же подтома, но предварительно заполненные содержимым тома, из которого был сделан снимок.

При создании моментальный снимок и исходный том имеют абсолютно одинаковое содержимое. Но с этого момента они будут различаться. Изменения, внесённые в исходный том (например, добавление, переименование или удаление файлов), не будут отражаться на моментальном снимке, и наоборот.

Имейте в виду, что моментальный снимок _не_ дублирует файлы и изначально почти не занимает места на диске. Он просто дублирует дерево файловой системы, указывая на исходные данные.

Команда для создания снимка состояния такая же, как и для создания подтома, просто добавьте параметр `snapshot` после `btrfs subvolume`. Приведённая ниже команда создаст снимок состояния файловой системы Btrfs, смонтированной в `/mnt/disk` в `/mnt/disk/snap`:

```bash
# btrfs subvolume snapshot /mnt/disk /mnt/disk/snap
```

Теперь представьте, что у вас есть следующее содержимое в `/mnt/disk`:

```bash
$ ls -lh
total 2,8M
-rw-rw-r-- 1 carol carol 109K jul 10 16:22 Galaxy_Note_10.png
-rw-rw-r-- 1 carol carol 484K jul  5 15:01 geminoid2.jpg
```

## **Несколько слов о сжатии**

Btrfs поддерживает прозрачное сжатие файлов с помощью трёх различных алгоритмов, доступных пользователю. Это делается автоматически для каждого файла, если файловая система смонтирована с опцией `-o compress`. Алгоритмы достаточно умны, чтобы распознавать несжимаемые файлы и не пытаться их сжимать, экономя системные ресурсы. Таким образом, в одном каталоге могут быть как сжатые, так и несжатые файлы. По умолчанию используется алгоритм сжатия ZLIB, но также доступны LZO (быстрее, но хуже сжимает) или ZSTD (быстрее, чем ZLIB, сравнимое сжатие) с несколькими уровнями сжатия (см. соответствующую цель в параметрах монтирования).

## Управление разделами с помощью GNU Parted <a href="#managing_partitions_with_gnu_parted" id="managing_partitions_with_gnu_parted"></a>

_GNU Parted_ — это очень мощный редактор разделов (отсюда и название), который можно использовать для создания, удаления, перемещения, изменения размера, восстановления и копирования разделов. Он может работать как с GPT-, так и с MBR-дисками и удовлетворять практически все ваши потребности в управлении дисками.

Существует множество графических интерфейсов, которые значительно упрощают работу с `parted`, например _GParted_ для настольных сред на базе GNOME и _KDE Partition Manager_ для настольных сред KDE. Однако вам следует научиться использовать `parted` в командной строке, поскольку в серверной среде вы никогда не сможете рассчитывать на доступность графической среды рабочего стола.

{% hint style="info" %}
В отличие от `fdisk` и `gdisk`, parted вносит изменения на диск _сразу_ после выполнения команды, не дожидаясь, пока другая команда запишет изменения на диск. При выполнении практических упражнений рекомендуется делать это на пустом или резервном диске или флеш-накопителе, чтобы избежать риска потери данных в случае ошибки.
{% endhint %}

Самый простой способ начать использовать parted — ввести `parted DEVICE`, где `DEVICE` — устройство, которым вы хотите управлять (`parted /dev/sdb`). Программа запускает интерактивный интерфейс командной строки, подобный `fdisk` и `gdisk` с `(parted)` подсказкой для ввода команд.

```bash
# parted /dev/sdb
GNU Parted 3.2
Using /dev/sdb
Welcome to GNU Parted! Type 'help' to view a list of commands.

(parted)
```

{% hint style="info" %}
Будьте внимательны! Если вы не укажете устройство, `parted` автоматически выберет для работы основной диск (обычно `/dev/sda`).
{% endhint %}

## **Выбор дисков**

Чтобы переключиться на другой диск, отличный от указанного в командной строке, можно использовать команду `select` с указанием имени устройства:

```bash
(parted) select /dev/sdb
Using /dev/sdb
```

## **Создание таблицы разделов на пустом диске**

Чтобы создать таблицу разделов на пустом диске, используйте команду `mklabel` с указанием типа таблицы разделов, который вы хотите использовать.

Поддерживается множество типов таблиц разделов, но вам следует знать об основных типах, `msdos` которые используются здесь для обозначения таблицы разделов MBR и `gpt` для обозначения таблицы разделов GPT. Чтобы создать таблицу разделов MBR, введите:

```bash
(parted) mklabel msdos
```

А для создания таблицы разделов GPT команда:

```bash
(parted) mklabel gpt
```

## **Создание раздела**

Для создания раздела используется команда `mkpart` с синтаксисом `mkpart PARTTYPE FSTYPE START END`, где:

`PARTTYPE`

Это тип раздела, который может быть `primary`, `logical` или `extended` в случае использования таблицы разделов MBR.

`FSTYPE`

Указывает, какая файловая система будет использоваться в этом разделе. Обратите внимание, что `parted` _не_ создаст файловую систему. Он просто устанавливает флаг в разделе, который сообщает ОС, какие данные ожидать от него.

`START`

Указывает точную точку на устройстве, с которой начинается раздел. Для указания этой точки можно использовать разные единицы измерения. `2s` можно использовать для указания второго сектора диска, а `1m` — для указания начала первого мегабайта диска. Другие распространённые единицы измерения — `B` (байты) и `%` (процент от объёма диска).

`END`

Указывает конец раздела. Обратите внимание, что это _не_ размер раздела, а _точка на диске, где он заканчивается_. Например, если вы укажете `100m`, раздел закончится через 100 МБ после начала диска. Вы можете использовать те же единицы измерения, что и в параметре `START`.

Итак, команда:

```bash
(parted) mkpart primary ext4 1m 100m
```

Создаёт основной раздел типа `ext4`, начиная с первого мегабайта диска и заканчивая 100-м мегабайтом.

## **Удаление раздела**

Чтобы удалить раздел, используйте команду `rm` с указанием номера раздела, который можно отобразить с помощью команды `print`. Таким образом, `rm 2` удалит второй раздел на выбранном в данный момент диске.

## **Восстановление разделов**

`parted` можно восстановить удаленный раздел. Предположим, у вас следующая структура разделов:

```bash
Number  Start   End     Size    File system  Name     Flags
 1      1049kB  99.6MB  98.6MB  ext4         primary
 2      99.6MB  200MB   100MB   ext4         primary
 3      200MB   300MB   99.6MB  ext4         primary
```

Вы случайно удалили раздел 2 с помощью `rm 2`. Чтобы восстановить его, вы можете использовать команду `rescue` с синтаксисом `rescue START END`, где `START` — приблизительное местоположение начала раздела, а `END` — приблизительное местоположение его конца.

`parted` программа просканирует диск в поисках разделов и предложит восстановить все найденные разделы. В приведенном выше примере раздел `2` начинался с 99,6 МБ и заканчивался на 200 МБ. Чтобы восстановить раздел, используйте следующую команду:

```bash
(parted) rescue 90m 210m
Information: A ext4 primary partition was found at 99.6MB -> 200MB.
Do you want to add it to the partition table?

Yes/No/Cancel? y
```

Это позволит восстановить раздел и его содержимое. Обратите внимание, что `rescue` может восстанавливать только разделы, на которых установлена файловая система. Пустые разделы не обнаруживаются.

## **Изменение размера разделов ext2 /3 /4**

`parted` можно использовать для изменения размера разделов, чтобы сделать их больше или меньше. Однако есть некоторые ограничения:

* Во время изменения размера раздел должен быть неиспользуемым и размонтированным.
* Вам нужно достаточно свободного места _после_ раздела, чтобы увеличить его до нужного размера.

Команда — `resizepart`, за которой следует номер раздела и место, где он должен заканчиваться. Например, если у вас есть следующая таблица разделов:

```bash
Number  Start   End     Size    File system  Name     Flags
 1      1049kB  99.6MB  98.6MB  ext4         primary
 2      99.6MB  200MB   100MB   ext4
 3      200MB   300MB   99.6MB  ext4         primary
```

При попытке увеличить раздел `1` с помощью `resizepart` появится сообщение об ошибке, так как при новом размере раздел `1` будет перекрывать раздел `2`. Однако раздел `3` можно изменить, так как после него есть свободное место, что можно проверить с помощью команды `print free`:

```bash
(parted) print free
Model: Kingston DataTraveler 2.0 (scsi)
Disk /dev/sdb: 1999MB
Sector size (logical/physical): 512B/512B
Partition Table: gpt
Disk Flags:

 Number  Start   End     Size    File system  Name     Flags
        17.4kB  1049kB  1031kB  Free Space
 1      1049kB  99.6MB  98.6MB  ext4         primary
 2      99.6MB  200MB   100MB   ext4
 3      200MB   300MB   99.6MB  ext4         primary
        300MB   1999MB  1699MB  Free Space
```

Таким образом, вы можете использовать следующую команду, чтобы уменьшить размер раздела 3 до 350 МБ:

```bash
(parted) resizepart 3 350m

(parted) print
Model: Kingston DataTraveler 2.0 (scsi)
Disk /dev/sdb: 1999MB
Sector size (logical/physical): 512B/512B
Partition Table: gpt
Disk Flags:

Number  Start   End     Size    File system  Name     Flags
 1      1049kB  99.6MB  98.6MB  ext4         primary
 2      99.6MB  200MB   100MB   ext4
 3      200MB   350MB   150MB   ext4         primary
```

Помните, что новая конечная точка отсчитывается от начала диска. Таким образом, поскольку раздел `3` заканчивался на 300 МБ, теперь он должен заканчиваться на 350 МБ.

Но изменение размера раздела — это только часть задачи. Вам также нужно изменить размер файловой системы, которая находится в нём. Для файловых систем ext2/3/4 это делается с помощью команды `resize2fs`. В приведённом выше примере раздел 3 при монтировании по-прежнему показывает «старый» размер:

```bash
$ df -h /dev/sdb3
Filesystem      Size  Used Avail Use% Mounted on
/dev/sdb3        88M  1.6M   80M   2% /media/carol/part3
```

Для изменения размера можно использовать команду `resize2fs DEVICE SIZE`, где `DEVICE` соответствует разделу, размер которого вы хотите изменить, а `SIZE` — новый размер. Если вы не укажете параметр размера, будет использовано всё доступное пространство раздела. Перед изменением размера рекомендуется отключить раздел.

В приведенном выше примере:

```bash
$ sudo resize2fs /dev/sdb3
resize2fs 1.44.6 (5-Mar-2019)
Resizing the filesystem on /dev/sdb3 to 146212 (1k) blocks.
The filesystem on /dev/sdb3 is now 146212 (1k) blocks long.

$ df -h /dev/sdb3
Filesystem      Size  Used Avail Use% Mounted on
/dev/sdb3       135M  1.6M  123M   2% /media/carol/part3
```

Чтобы _уменьшить_ раздел, нужно выполнить процесс в обратном порядке. _Сначала_ вы изменяете размер файловой системы до нового, меньшего размера, а затем изменяете размер самого раздела с помощью `parted`.

{% hint style="info" %}
Будьте внимательны при уменьшении размеров разделов. Если вы перепутаете порядок действий, вы потеряете данные!
{% endhint %}

В нашем примере:

```bash
# resize2fs /dev/sdb3 88m
resize2fs 1.44.6 (5-Mar-2019)
Resizing the filesystem on /dev/sdb3 to 90112 (1k) blocks.
The filesystem on /dev/sdb3 is now 90112 (1k) blocks long.

# parted /dev/sdb3
(parted) resizepart 3 300m
Warning: Shrinking a partition can cause data loss, are you sure
you want to continue?

Yes/No? y

(parted) print
Model: Kingston DataTraveler 2.0 (scsi)
Disk /dev/sdb: 1999MB
Sector size (logical/physical): 512B/512B
Partition Table: gpt
Disk Flags:

Number  Start   End     Size    File system  Name     Flags
 1      1049kB  99.6MB  98.6MB  ext4         primary
 2      99.6MB  200MB   100MB   ext4
 3      200MB   300MB   99.7MB  ext4         primary
```

{% hint style="info" %}
Вместо указания нового размера вы можете использовать параметр `-M` команды `resize2fs` для изменения размера файловой системы так, чтобы он был достаточно большим для содержащихся в ней файлов.
{% endhint %}

## Создание разделов подкачки <a href="#creating_swap_partitions" id="creating_swap_partitions"></a>

В Linux система может при необходимости переносить страницы памяти из оперативной памяти на диск, сохраняя их в отдельном пространстве, обычно реализованном в виде отдельного раздела на диске, который называется _разделом подкачки_ или просто _swap_. Этот раздел должен быть определённого типа и настроен с помощью соответствующей утилиты (`mkswap`), прежде чем его можно будет использовать.

Чтобы создать раздел подкачки с помощью `fdisk` или `gdisk`, просто действуйте так же, как при создании обычного раздела, как описано выше. Единственное отличие заключается в том, что вам нужно будет изменить тип раздела на _Linux swap_.

* В `fdisk` используйте команду `t`. Выберите раздел, который вы хотите использовать, и измените его тип на `82`. Запишите изменения на диск и завершите работу с помощью `w`.
* В `gdisk` команда для изменения типа раздела также `t` , но код `8200`. Запишите изменения на диск и выйдите с помощью `w`.

Если вы используете `parted`, то при создании раздел должен быть определён как раздел подкачки. Просто используйте `linux-swap` в качестве типа файловой системы. Например, команда для создания раздела подкачки размером 500 МБ, начиная с 300 МБ на диске, выглядит так:

```bash
(parted) mkpart primary linux-swap 301m 800m
```

После создания и правильной идентификации раздела просто используйте `mkswap` с указанием устройства, представляющего раздел, который вы хотите использовать, например:

```bash
# mkswap /dev/sda2
```

Чтобы включить подкачку в этом разделе, используйте `swapon`, за которым следует название устройства:

<pre class="language-bash"><code class="lang-bash"><strong># swapon /dev/sda2
</strong></code></pre>

Аналогичным образом, `swapoff` с последующим указанием имени устройства отключит своп на этом устройстве.

Linux также поддерживает использование _файлов подкачки_ вместо разделов. Просто создайте пустой файл нужного размера с помощью `dd` и затем используйте `mkswap` и `swapon` с этим файлом в качестве цели.

Следующие команды создадут в текущем каталоге файл размером 1 ГБ под названием `myswap` и заполнят его нулями, а затем настроят и активируют его как файл подкачки.

Создаем файл подкачки:

```bash
$ dd if=/dev/zero of=myswap bs=1M count=1024
1024+0 records in
1024+0 records out
1073741824 bytes (1.1 GB, 1.0 GiB) copied, 7.49254 s, 143 MB/s
```

`if=` — это входной файл, источник данных, которые будут записаны в файл. В данном случае это `/dev/zero` устройство, которое предоставляет столько `NULL` символов, сколько запрошено. `of=` — это выходной файл, файл, который будет создан. `bs=` — это размер блоков данных, здесь указанный в мегабайтах, а `count=` — это количество блоков, которые будут записаны на выход. 1024 блока по 1 МБ каждый равны 1 ГБ.

```bash
# mkswap myswap
Setting up swapspace version 1, size = 1024 MiB (1073737728 bytes)
no label, UUID=49c53bc4-c4b1-4a8b-a613-8f42cb275b2b

# swapon myswap
```

При использовании приведённых выше команд этот файл подкачки будет использоваться только во время текущего сеанса работы системы. Если компьютер перезагрузится, файл по-прежнему будет доступен, но не будет загружаться автоматически. Вы можете автоматизировать этот процесс, добавив новый файл подкачки в `/etc/fstab`, о чём мы поговорим в следующем уроке.

{% hint style="info" %}
И `mkswap` и `swapon` сообщат, если у вашего файла подкачки небезопасные разрешения. Рекомендуемый флаг разрешений для файла — `0600`. Владелец и группа должны быть `root.`
{% endhint %}

## Ответы на упражнения с Руководством <a href="#sec.104.1_01-age" id="sec.104.1_01-age"></a>

1.  Какую схему разбиения на разделы следует использовать для разделения жёсткого диска объёмом 3 ТБ на три раздела по 1 ГБ? Почему?

    GPT, так как  MBR поддерживает жесткие диски объемом не более 2 ТБ.
2.  В `gdisk` как узнать, сколько места доступно на диске?

    Используйте `p` (печать). Общее свободное пространство будет отображаться в последней строке перед самой таблицей разделов.
3.  Какая команда нужна для создания файловой системы ext3 с проверкой на наличие повреждённых блоков, с меткой `MyDisk` и случайным UUID на устройстве `/dev/sdc1`?

    Команда будет выглядеть так: `mkfs.ext3 -c -L MyDisk -U random /dev/sdc1`. В качестве альтернативы `mke2fs -t ext3` можно использовать вместо `mkfs.ext3`
4.  С помощью `parted` какая команда создаст раздел ext4 размером 300 МБ, начиная с 500 МБ на диске?

    Используйте `mkpart primary ext4 500m 800m`. Помните, что вам придётся создать файловую систему с помощью `mkfs.ext4`, так как parted этого не делает.
5.  Представьте, что у вас есть 2 раздела, один на `/dev/sda1` и другой на `/dev/sdb1`, оба размером 20 ГБ. Как вы можете использовать их в одной файловой системе Btrfs таким образом, чтобы содержимое одного раздела автоматически зеркалировалось на другом, как в конфигурации RAID1? Какого размера будет файловая система?

    Используйте `mkfs.btrfs /dev/sda1 /dev/sdb1 -m raid1`. Полученная файловая система будет иметь размер 20 ГБ, так как один раздел будет просто зеркальным отражением другого.

### Ответы на исследовательские упражнения <a href="#sec.104.1_01-aee" id="sec.104.1_01-aee"></a>

1.  Рассмотрим диск объёмом 2 ГБ с таблицей разделов MBR и следующей структурой:

    ```bash
    Disk /dev/sdb: 1.9 GiB, 1998631936 bytes, 3903578 sectors
    Disk model: DataTraveler 2.0
    Units: sectors of 1 * 512 = 512 bytes
    Sector size (logical/physical): 512 bytes / 512 bytes
    I/O size (minimum/optimal): 512 bytes / 512 bytes
    Disklabel type: dos
    Disk identifier: 0x31a83a48

    Device     Boot   Start     End Sectors  Size Id Type
    /dev/sdb1          2048 1050623 1048576  512M 83 Linux
    /dev/sdb3       2099200 3147775 1048576  512M 83 Linux
    ```

    Можете ли вы создать на нём раздел размером 600 МБ? Зачем?

    Вы не можете этого сделать, потому что недостаточно свободного места. Первый признак того, что что-то «не так», — это список устройств: у вас есть `/dev/sdb1` и `/dev/sdb3`, но нет `/dev/sdb2`. Значит, чего-то не хватает.

    Затем вам нужно посмотреть, где заканчивается один раздел и начинается другой. Первый раздел заканчивается на секторе `1050623`, а второй начинается на `2099200`. Это «пробел» в 1048577 секторов. При 512 байтах на сектор это 536 871 424 байта. Если разделить это число на 1024, получится 524 288 килобайт. Снова разделите на 1024, и вы получите… 512 МБ. Это размер «пробела».

    Если размер диска составляет 2 ГБ, то после раздела 3 у нас останется не более 512 МБ. Даже если у нас в общей сложности останется около 1 ГБ нераспределённого пространства, самый большой непрерывный блок составляет 512 МБ. Таким образом, для раздела размером 600 МБ места не хватит.
2.  На диске `/dev/sdc` у нас есть первый раздел размером 1 ГБ, содержащий файловую систему ext4 с 241 МБ файлов. Как с помощью `parted` уменьшить его размер так, чтобы в нём было достаточно места для файлов?

    Это многоэтапная операция. Сначала вам нужно уменьшить файловую систему с помощью `resize2fs`. Вместо того чтобы указывать новый размер напрямую, вы можете использовать параметр `-M` так, чтобы он был «достаточно большим». Итак: `resize2fs -M /dev/sdc1`.

    Затем вы изменяете размер самого раздела с помощью parted, используя `resizepart`. Поскольку это первый раздел, мы можем предположить, что он начинается с нуля и заканчивается на 241 МБ. Таким образом, команда будет resizepart 1 241M.
3.  Представьте, что у вас есть диск с меткой `/dev/sdb`, и вы хотите создать раздел размером 1 ГБ в его начале. Итак, с помощью `parted` вы создаёте раздел с меткой `mkpart primary linux-swap 0 1024M`. Затем вы включаете подкачку для этого раздела с помощью `swapon /dev/sdb1`, но получаете следующее сообщение об ошибке:

    `swapon: /dev/sdb1: read swap header failed`

    Что пошло не так?

    Вы создали раздел нужного типа (`linux-swap`), но помните, что `mkpart` _не создаётся файловая система_. Вы забыли сначала настроить раздел в качестве пространства подкачки с помощью `mkswap` перед его использованием.
4.  Во время этого урока вы пробовали выполнить несколько команд в `parted` но по ошибке удалили 3-й раздел на своём жёстком диске. Вы знаете, что он располагался после раздела EFI размером 250 МБ и раздела подкачки размером 4 ГБ и занимал 10 ГБ. Какую команду `parted` вы можете использовать для его восстановления?

    Не паникуйте, у вас есть вся информация, необходимая для восстановления раздела, просто используйте `rescue` и посчитайте. Перед этим у вас было 250 МБ + 4,096 МБ (4 \* 1024), поэтому начальная точка должна быть около 4346 МБ. Плюс размер 10.240 МБ (10 \* 1024), он должен заканчиваться на 14.586 МБ. Таким образом, `rescue 4346m 14586m` должно получиться. Возможно, вам придётся немного «подстраховаться» при спасении, начав немного раньше и закончив немного позже, в зависимости от геометрии вашего диска.
5.  Представьте, что у вас есть неиспользуемый раздел размером 4 ГБ на `/dev/sda3`. Используя `fdisk`, какую последовательность действий нужно выполнить, чтобы превратить его в активный раздел подкачки?

    Сначала измените тип раздела на «Linux Swap» (82), запишите изменения на диск и выйдите. Затем используйте `mkswap` для настройки раздела в качестве области подкачки. Затем используйте `swapon` для её включения.
