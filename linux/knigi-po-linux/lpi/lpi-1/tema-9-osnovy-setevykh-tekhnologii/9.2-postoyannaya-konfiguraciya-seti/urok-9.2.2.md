# Урок 9.2.2

## Введение <a href="#sec.109.2_02-in" id="sec.109.2_02-in"></a>

Linux поддерживает практически все сетевые технологии, используемые для подключения серверов, контейнеров, виртуальных машин, настольных компьютеров и мобильных устройств. Соединения между всеми этими сетевыми узлами могут быть динамическими и разнородными, что требует соответствующего управления со стороны операционной системы, работающей на них.

В прошлом дистрибутивы разрабатывали собственные специализированные решения для управления динамической сетевой инфраструктурой. Сегодня такие инструменты, как _NetworkManager_ и _systemd_, предоставляют более комплексные и интегрированные функции для удовлетворения всех конкретных потребностей.

## _NetworkManager_

В большинстве дистрибутивов Linux для настройки и управления сетевыми подключениями системы используется демон _NetworkManager_. Цель NetworkManager — сделать настройку сети максимально простой и автоматической. Например, при использовании DHCP NetworkManager при необходимости организует изменение маршрута, получение IP-адреса и обновление локального списка DNS-серверов. При наличии проводного и беспроводного подключений NetworkManager по умолчанию отдает приоритет проводному подключению. NetworkManager будет стараться поддерживать хотя бы одно подключение активным постоянно, если это возможно.

{% hint style="info" %}
Запрос с использованием DHCP (_протокола динамической конфигурации хоста Dynamic Host Configuration Protocol_)) обычно отправляется через сетевой адаптер сразу после установления соединения с сетью. Сервер DHCP, работающий в сети, отвечает настройками (IP-адрес, сетевая маска, маршрут по умолчанию и т. д.), которые запрашивающая сторона должна использовать для связи по протоколу IP.
{% endhint %}

По умолчанию демон NetworkManager управляет сетевыми интерфейсами, не упомянутыми в файле `/etc/network/interfaces` . Он делает это, чтобы не мешать другим методам настройки, которые также могут присутствовать, и изменять только неиспользуемые интерфейсы.

Служба NetworkManager работает в фоновом режиме с правами суперпользователя и запускает необходимые действия для поддержания системы в рабочем состоянии. Обычные пользователи могут создавать и изменять сетевые подключения с помощью клиентских приложений, которые, хотя и не имеют прав суперпользователя, могут взаимодействовать с базовой службой для выполнения запрошенных действий.

Клиентские приложения для NetworkManager доступны как для командной строки, так и для графической среды. В последнем случае клиентское приложение поставляется как дополнение к среде рабочего стола (под такими названиями, как _nm-tray_, _network-manager-gnome_, _nm-applet_ или _plasma-nm_) и обычно доступно через значок индикатора в углу панели рабочего стола или в утилите настройки системы.

В командной строке NetworkManager предоставляет две клиентские программы: `nmcli` и `nmtui`. Обе программы имеют одинаковые базовые функции, но `nmtui` имеет интерфейс на основе curses, а `nmcli` является более полной командой, которую также можно использовать в скриптах. Команда `nmcli` разделяет все свойства сети, управляемые NetworkManager, на категории, называемые _объектами_:

`general`

Общее состояние и операции NetworkManager.

`networking`

Общий сетевой контроль.

`radio`

radio switches NetworkManager.

`connection`

Подключения NetworkManager.

`device`

Устройства, управляемые NetworkManager.

`agent`

&#x20;NetworkManager secret агент или агент polkit.

`monitor`

Мониторинг  NetworkManager.

Имя объекта является основным аргументом команды `nmcli`. Например, чтобы отобразить общее состояние подключения системы, в качестве аргумента следует указать объект `general`.

```bash
$ nmcli general
STATE      CONNECTIVITY  WIFI-HW  WIFI     WWAN-HW  WWAN
connected  full          enabled  enabled  enabled  enabled
```

Столбец `STATE` указывает, подключена ли система к сети или нет. Если подключение ограничено из-за неправильной внешней настройки или ограничений доступа, то в `CONNECTIVITY` столбце не будет отображаться `full` состояние подключения. Если `Portal` появляется в `CONNECTIVITY` столбце, это означает, что для завершения процесса подключения требуются дополнительные шаги аутентификации (обычно через веб-браузер). Остальные столбцы сообщают о состоянии беспроводных подключений (если таковые имеются), либо`WIFI`, либо `WWAN` (Широковещательная беспроводная сеть, т. е. Сотовые сети). Суффикс `HW` указывает на то, что состояние относится к сетевому устройству, а не к системному сетевому подключению, то есть показывает, включено или отключено оборудование для экономии энергии.

Помимо аргумента объекта, для выполнения `nmcli` также требуется аргумент команды. Команда `status` используется по умолчанию, если отсутствует аргумент команды, поэтому команда `nmcli general` фактически интерпретируется как `nmcli general status`.

Вряд ли потребуется предпринимать какие-либо действия, если сетевой адаптер напрямую подключен к точке доступа с помощью кабелей, но для подключения новых пользователей к беспроводным сетям требуется дополнительное взаимодействие. `nmcli` упрощает процесс подключения и сохраняет настройки для автоматического подключения в будущем, поэтому это очень удобно для ноутбуков и других мобильных устройств.

Перед подключением к Wi-Fi удобно сначала просмотреть список доступных сетей в локальной зоне. Если в системе есть работающий адаптер Wi-Fi, то объект `device` будет использовать его для сканирования доступных сетей с помощью команды `nmcli device wifi list`:

```bash
$ nmcli device wifi list
IN-USE  BSSID              SSID        MODE   CHAN  RATE        SIGNAL  BARS  SECURITY
        90:F6:52:C5:FA:12  Hypnotoad   Infra  11    130 Mbit/s  67      ▂▄▆_  WPA2
        10:72:23:C7:27:AC  Jumbao      Infra  1     130 Mbit/s  55      ▂▄__  WPA2
        00:1F:33:33:E9:BE  NETGEAR     Infra  1     54 Mbit/s   35      ▂▄__  WPA1 WPA2
        A4:33:D7:85:6D:B0  AP53        Infra  11    130 Mbit/s  32      ▂▄__  WPA1 WPA2
        98:1E:19:1D:CC:3A  Bruma       Infra  1     195 Mbit/s  22      ▂___  WPA1 WPA2
```

Большинство пользователей, вероятно, будут использовать имя в столбце `SSID` для идентификации интересующей их сети. Например, команда `nmcli` может подключиться к сети с именем `Hypnotoad` с помощью объекта `device`:

```bash
$ nmcli device wifi connect Hypnotoad
```

Если команда выполняется в эмуляторе терминала в графической среде, то появится диалоговое окно с запросом пароля сети. При выполнении в текстовой консоли пароль можно указать вместе с другими аргументами:

```bash
$ nmcli device wifi connect Hypnotoad password MyPassword
```

Если сеть Wi-Fi скрывает своё имя SSID, `nmcli` всё равно может подключиться к ней с помощью дополнительных `hidden yes` аргументов:

```bash
$ nmcli device wifi connect Hypnotoad password MyPassword hidden yes
```

Если в системе есть несколько адаптеров Wi-Fi, нужный из них можно указать с помощью `ifname`. Например, для подключения с помощью адаптера с именем `wlo1`:

```bash
$ nmcli device wifi connect Hypnotoad password MyPassword ifname wlo1
```

После успешного подключения NetworkManager присвоит ему имя по соответствующему SSID (если это подключение по Wi-Fi) и сохранит его для будущих подключений. Имена подключений и их UUID перечислены в команде `nmcli connection show`:

```bash
$ nmcli connection show
NAME               UUID                                  TYPE      DEVICE
Ethernet           53440255-567e-300d-9922-b28f0786f56e  ethernet  enp3s5
tun0               cae685e1-b0c4-405a-8ece-6d424e1fb5f8  tun       tun0
Hypnotoad          6fdec048-bcc5-490a-832b-da83d8cb7915  wifi      wlo1
4G                 a2cf4460-0cb7-42e3-8df3-ccb927f2fd88  gsm       --
```

Отображается тип каждого подключения, который может быть `ethernet`, `wifi`, `tun`, `gsm`, `bridge` и т. д., а также устройство, с которым оно связано. Чтобы выполнить действия с конкретным подключением, необходимо указать его имя или UUID. Чтобы отключить подключение `Hypnotoad`, например:

```bash
$ nmcli connection down Hypnotoad
Connection 'Hypnotoad' successfully deactivated
```

Аналогичным образом для подключения можно использовать команду `nmcli connection up Hypnotoad`, так как теперь она сохраняется в NetworkManager. Для повторного подключения также можно использовать имя интерфейса, но в этом случае вместо него следует использовать объект `device`:

```bash
$ nmcli device disconnect wlo2
Device 'wlo1' successfully disconnected.
```

Имя интерфейса также может быть использовано для восстановления соединения:

```bash
$ nmcli device connect wlo2
Device 'wlo1' successfully activated with '833692de-377e-4f91-a3dc-d9a2b1fcf6cb'.
```

Обратите внимание, что UUID подключения меняется при каждом подключении, поэтому для единообразия лучше использовать его имя.

Если беспроводной адаптер доступен, но не используется, его можно отключить для экономии энергии. На этот раз объект _radio_ должен быть передан в `nmcli`:

```bash
$ nmcli radio wifi off
```

Конечно, беспроводное устройство можно снова включить с помощью команды `nmcli radio wifi on`.

После установления соединения в дальнейшем не потребуется ручного вмешательства, поскольку NetworkManager определяет доступные известные сети и автоматически подключается к ним. При необходимости NetworkManager может использовать плагины, расширяющие его функции, например, плагин для поддержки VPN-соединений.

## systemd-networkd <a href="#sec.109.2_02-sn" id="sec.109.2_02-sn"></a>

Системы, работающие под управлением systemd, могут использовать встроенные демоны для управления сетевым подключением: `systemd-networkd` для управления сетевыми интерфейсами и `systemd-resolved` для управления локальным разрешением имён. Эти службы обратно совместимы с устаревшими методами настройки Linux, но в настройке сетевых интерфейсов есть особенности, о которых стоит знать.

Файлы конфигурации, используемые systemd-networkd для настройки сетевых интерфейсов, можно найти в любом из следующих трёх каталогов:

`/lib/systemd/network`

Системный сетевой каталог.

`/run/systemd/network`

Сетевой каталог изменяемой среды выполнения.

`/etc/systemd/network`

Каталог локальной административной сети.

Файлы обрабатываются в лексикографическом порядке, поэтому рекомендуется начинать их названия с цифр, чтобы порядок был проще для восприятия и настройки.

Файлы в `/etc` имеют наивысший приоритет, в то время как файлы в `/run` имеют приоритет над файлами с тем же именем в `/lib`. Это означает, что если файлы конфигурации в разных каталогах имеют одинаковое имя, то systemd-networkd будет игнорировать файлы с более низким приоритетом. Такое разделение файлов позволяет изменять настройки интерфейса без необходимости изменять исходные файлы: изменения можно вносить в `/etc/systemd/network` для переопределения изменений в `/lib/systemd/network`.

Назначение каждого файла конфигурации зависит от его суффикса. Имена файлов, оканчивающиеся на `.netdev`, используются systemd-networkd для создания виртуальных сетевых устройств, таких как _мосты_ или _туннели_. Файлы, оканчивающиеся на `.link`, задают низкоуровневые конфигурации для соответствующего сетевого интерфейса. systemd-networkd автоматически обнаруживает и настраивает сетевые устройства по мере их появления, а также игнорирует устройства, уже настроенные другими способами, поэтому в большинстве случаев нет необходимости добавлять эти файлы.

Самый важный суффикс — `.network`. Файлы с этим суффиксом можно использовать для настройки сетевых адресов и маршрутов. Как и в случае с другими типами файлов конфигурации, имя файла определяет порядок его обработки. Сетевой интерфейс, на который ссылается файл конфигурации, определяется в разделе `` [Match]` `` внутри файла.

Например, сетевой интерфейс Ethernet `enp3s5` можно выбрать в файле `/etc/systemd/network/30-lan.network` с помощью записи `Name=enp3s5` в разделе `[Match]`:

```bash
[Match]
Name=enp3s5
```

Также допускается использование списка имён, разделённых пробелами, для одновременного сопоставления многих сетевых интерфейсов с одним и тем же файлом. Имена могут содержать подстановочные знаки в стиле оболочки, например `en*`. Другие записи содержат различные правила сопоставления, например выбор сетевого устройства по MAC-адресу:

```bash
[Match]
MACAddress=00:16:3e:8d:2b:5b
```

Настройки устройства находятся в разделе `[Network]` файла. Для простой статической конфигурации сети требуются только записи `Address` и `Gateway`:

```bash
[Match]
MACAddress=00:16:3e:8d:2b:5b

[Network]
Address=192.168.0.100/24
Gateway=192.168.0.1
```

Чтобы использовать протокол DHCP вместо статических IP-адресов, вместо `DHCP` следует использовать запись:

```bash
[Match]
MACAddress=00:16:3e:8d:2b:5b

[Network]
DHCP=yes
```

Служба systemd-networkd попытается получить адреса IPv4 и IPv6 для сетевого интерфейса. Чтобы использовать только IPv4,  следует использовать`DHCP=ipv4`. Аналогичным образом, `DHCP=ipv6` будет игнорировать настройки IPv4 и использовать только предоставленный адрес IPv6.

Беспроводные сети, защищённые паролем, также могут быть настроены с помощью systemd-networkd, но сетевой адаптер должен быть уже аутентифицирован в сети, прежде чем systemd-networkd сможет его настроить. Аутентификация выполняется с помощью _WPA supplicant_, программы, предназначенной для настройки сетевых адаптеров для сетей, защищённых паролем.

Первым шагом является создание файла учетных данных с помощью команды `wpa_passphrase`:

```bash
# wpa_passphrase MyWifi > /etc/wpa_supplicant/wpa_supplicant-wlo1.conf
```

Эта команда примет парольную фразу для беспроводной сети `MyWifi` со стандартного ввода и сохранит её хэш в `/etc/wpa_supplicant/wpa_supplicant-wlo1.conf`. Обратите внимание, что имя файла должно содержать соответствующее название беспроводного интерфейса, поэтому в имени файла есть `wlo1`

Менеджер systemd считывает файлы паролей WPA в `/etc/wpa_supplicant/` и создаёт соответствующую службу для запуска WPA supplicant и подключения к интерфейсу. Файл паролей, созданный в примере, будет иметь соответствующую службу под названием `wpa_supplicant@wlo1.service`. Команда `systemctl start wpa_supplicant@wlo1.service` свяжет беспроводной адаптер с удалённой точкой доступа. Команда `systemctl enable wpa_supplicant@wlo1.service` автоматически свяжет их во время загрузки.

Наконец, в `.network` должен присутствовать файл `wlo1`, соответствующий интерфейсу `/etc/systemd/network/`, так как systemd-networkd будет использовать его для настройки интерфейса, как только WPA supplicant завершит подключение к точке доступа.

## Краткие сведения <a href="#sec.109.2_02-su" id="sec.109.2_02-su"></a>

В этом уроке рассматриваются распространённые инструменты, используемые в Linux для управления разнородными и динамическими сетевыми подключениями. Хотя большинство методов настройки не требуют вмешательства пользователя, иногда это необходимо, и такие инструменты, как _NetworkManager_ и _systemd-networkd_, могут свести хлопоты к минимуму. В уроке рассматриваются следующие темы:

* Как NetworkManager и systemd-networkd интегрируются с системой.
* Как пользователь может взаимодействовать с NetworkManager и systemd-networkd.
* Базовая конфигурация интерфейса как с NetworkManager, так и с systemd-networkd.

Были рассмотрены следующие концепции, команды и процедуры:

* Клиентские команды NetworkManager: `nmtui` и `nmcli`.
* Сканирование и подключение к беспроводным сетям с помощью `nmcli` соответствующих команд.
* Постоянные подключения к сети Wi-Fi с использованием systemd-networkd.

## Ответы на Упражнения с Руководством <a href="#sec.109.2_02-age" id="sec.109.2_02-age"></a>

1.  Что означает слово `Portal` в столбце `CONNECTIVITY` в выводе команды `nmcli general status`?

    Это означает, что для завершения процесса подключения требуются дополнительные шаги аутентификации (обычно через веб-браузер).
2.  Как обычный пользователь может использовать команду `nmcli` в консольном терминале для подключения к беспроводной сети `MyWifi` с паролем `MyPassword`?

    В текстовом терминале команда будет выглядеть следующим образом

    ```bash
    $ nmcli device wifi connect MyWifi password MyPassword
    ```
3.  С помощью какой команды можно включить беспроводной адаптер, если он был ранее отключен операционной системой?

    ```bash
    $ nmcli radio wifi on
    ```
4.  В какой каталог следует поместить пользовательские файлы конфигурации, если systemd-networkd управляет сетевыми интерфейсами?

    В каталоге локальной административной сети: `/etc/systemd/network`.

## Ответы на Исследовательские упражнения <a href="#sec.109.2_02-aee" id="sec.109.2_02-aee"></a>

1.  Как пользователь может выполнить команду `nmcli` для удаления неиспользуемого подключения с именем `Hotel Internet`?

    ```bash
    $ nmcli connection delete "Hotel Internet"
    ```
2.  NetworkManager периодически сканирует сети Wi-Fi, и команда `nmcli device wifi list` выводит только точки доступа, обнаруженные при последнем сканировании. Как использовать команду `nmcli` для того, чтобы NetworkManager немедленно повторно просканировал все доступные точки доступа?

    Пользователь с правами суперпользователя может запустить `nmcli device wifi rescan` для повторного сканирования доступных точек доступа NetworkManager.
3.  Какую запись `name` следует использовать в разделе `[Match]` файла конфигурации systemd-networkd, чтобы она соответствовала всем интерфейсам Ethernet?

    Запись `name=en*`, так как `en` является префиксом для интерфейсов Ethernet в Linux, а systemd-networkd поддерживает подстановочные знаки, как в оболочке.
4.  Как следует выполнить команду `wpa_passphrase` для использования парольной фразы, переданной в качестве аргумента, а не из стандартного ввода?

    Пароль должен быть указан сразу после SSID, как  wpa\_passphrase MyWifi MyPassword.
