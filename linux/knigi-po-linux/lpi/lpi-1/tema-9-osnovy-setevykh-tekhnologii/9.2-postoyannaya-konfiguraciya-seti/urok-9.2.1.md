# Урок 9.2.1

## Введение <a href="#sec.109.2_01-in" id="sec.109.2_01-in"></a>

В любой сети TCP/IP каждый узел должен настроить свой сетевой адаптер в соответствии с требованиями сети, иначе они не смогут взаимодействовать друг с другом. Поэтому системный администратор должен выполнить базовую настройку, чтобы операционная система могла настроить соответствующий сетевой интерфейс, а также идентифицировать себя и основные функции сети при каждой загрузке.

Настройки сети не зависят от операционной системы, но у каждой из них есть свои методы хранения и применения этих настроек. Системы Linux используют конфигурации, хранящиеся в текстовых файлах в каталоге `/etc`, для подключения к сети во время загрузки. Стоит знать, как используются эти файлы, чтобы избежать потери подключения из-за неправильной локальной настройки.

## Сетевой интерфейс <a href="#sec.109.2_01-ni" id="sec.109.2_01-ni"></a>

_Сетевой интерфейс_ — это термин, которым операционная система обозначает канал связи, настроенный для работы с сетевым оборудованием, подключённым к системе, например, с устройством Ethernet или Wi-Fi. Исключением является _петлевой(loopback)_ интерфейс, который операционная система использует, когда ей нужно установить соединение с самой собой, но основная цель сетевого интерфейса — обеспечить маршрут, по которому можно отправлять локальные данные и получать удалённые данные. Если сетевой интерфейс не настроен должным образом, операционная система не сможет взаимодействовать с другими компьютерами в сети.

В большинстве случаев правильные настройки интерфейса либо заданы по умолчанию, либо настраиваются во время установки операционной системы. Тем не менее, эти настройки часто приходится проверять или даже изменять, если связь работает неправильно или если поведение интерфейса требует настройки.

Существует множество команд Linux для вывода списка сетевых интерфейсов, присутствующих в системе, но не все они доступны во всех дистрибутивах. Однако команда `ip` является частью базового набора сетевых инструментов, поставляемых со всеми дистрибутивами Linux, и может использоваться для вывода списка сетевых интерфейсов. Полная команда для вывода списка интерфейсов выглядит так: `ip link show`:

```bash
$ ip link show
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN mode DEFAULT group default qlen 1000
        link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00
2: enp3s5: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP mode DEFAULT group default qlen 1000
        link/ether 00:16:3e:8d:2b:5b brd ff:ff:ff:ff:ff:ff
```

Если доступно, также можно использовать команду `nmcli device`:

```bash
$ nmcli device
DEVICE      TYPE      STATE      CONNECTION
enp3s5      ethernet  connected  Gigabit Powerline Adapter
lo          loopback  unmanaged  --
```

Команды, показанные в примерах, не изменяют никаких настроек в системе, поэтому их может выполнить пользователь без прав администратора. Обе команды выводят список двух сетевых интерфейсов: `lo` (петлевой интерфейс) и `enp3s5` (интерфейс Ethernet).

На настольных компьютерах и ноутбуках под управлением Linux обычно есть два или три предустановленных сетевых интерфейса: один для виртуального петлевого интерфейса, а остальные назначаются сетевому оборудованию, обнаруженному системой. С другой стороны, на серверах и сетевых устройствах под управлением Linux может быть несколько десятков сетевых интерфейсов, но ко всем из них применяются одни и те же принципы. Абстракция, предоставляемая операционной системой, позволяет настраивать сетевые интерфейсы с помощью одних и тех же методов независимо от используемого оборудования.

Однако знание подробностей об аппаратном обеспечении, лежащем в основе интерфейса, может быть полезно для лучшего понимания того, что происходит, когда связь работает не так, как ожидалось. В системе, где доступно множество сетевых интерфейсов, может быть не очевидно, какой из них соответствует Wi-Fi, а какой — Ethernet. По этой причине в Linux используется соглашение об именовании интерфейсов, которое помогает определить, какой сетевой интерфейс соответствует какому устройству и порту.

## Имена интерфейсов <a href="#sec.109.2_01-ina" id="sec.109.2_01-ina"></a>

В более старых дистрибутивах Linux сетевые интерфейсы Ethernet назывались `eth0`, `eth1`, и т. д. и нумеровались в соответствии с порядком, в котором ядро идентифицирует устройства. Беспроводные интерфейсы назывались `wlan0`, `wlan1`, и т. д. Однако это соглашение об именовании не уточняет, какой именно порт Ethernet соответствует интерфейсу `eth0`, например. В зависимости от того, как определялось оборудование, после перезагрузки два сетевых интерфейса могли даже поменяться названиями.

Чтобы устранить эту неоднозначность, в более современных системах Linux используется предсказуемое соглашение об именовании сетевых интерфейсов, обеспечивающее более тесную связь между названием интерфейса и базовым аппаратным подключением.

В дистрибутивах Linux, использующих схему именования systemd, все имена интерфейсов начинаются с двухсимвольного префикса, обозначающего тип интерфейса:

`en`

Ethernet

`ib`

InfiniBand

`sl`

Serial line IP (slip)

`wl`

Беспроводная локальная сеть (WLAN)

`ww`

Беспроводная глобальная сеть (WWAN)

Операционная система использует следующие правила для присвоения имён и номеров сетевым интерфейсам в порядке убывания приоритета:

1. Интерфейс по индексу, предоставленному BIOS или прошивкой встроенных устройств, например `eno1`.
2. Интерфейс в соответствии с индексом слота PCI Express, указанным в BIOS или прошивке, например `ens1`.
3. Интерфейс по его адресу на соответствующей шине, например `enp3s5`.
4. Интерфейс по MAC-адресу, например `enx78e7d1ea46da`.
5. Интерфейс, используя устаревшее соглашение, например, `eth0`.

Например, можно предположить, что сетевой интерфейс `enp3s5` был назван так, потому что он не подходил под первые два метода именования, поэтому вместо этого был использован его адрес на соответствующей шине и в соответствующем слоте. Адрес устройства `03:05.0`, указанный в выводе команды `lspci`, указывает на связанное устройство:

```bash
$ lspci | fgrep Ethernet
03:05.0 Ethernet controller: Realtek Semiconductor Co., Ltd. RTL-8110SC/8169SC Gigabit Ethernet (rev 10)
```

Сетевые интерфейсы создаются самим ядром Linux, но существует множество команд, которые можно использовать для взаимодействия с ними. Обычно настройка происходит автоматически, и нет необходимости изменять параметры вручную. Тем не менее, с помощью имени интерфейса можно указать ядру, как действовать при его настройке в случае необходимости.

## Управление интерфейсом <a href="#sec.109.2_01-im" id="sec.109.2_01-im"></a>

На протяжении многих лет было разработано несколько программ для взаимодействия с сетевыми функциями, предоставляемыми ядром Linux. Хотя старую команду `ifconfig` по-прежнему можно использовать для простой настройки и запросов интерфейсов, она устарела из-за ограниченной поддержки неэфирных интерфейсов. Команду `ifconfig` заменила команда `ip`, которая способна управлять многими другими аспектами интерфейсов TCP/IP, такими как маршруты и туннели.

Множество возможностей команды `ip` могут оказаться избыточными для большинства обычных задач, поэтому существуют вспомогательные команды, упрощающие активацию и настройку сетевых интерфейсов. Команды `ifup` и `ifdown` можно использовать для настройки сетевых интерфейсов на основе определений интерфейсов, содержащихся в файле `/etc/network/interfaces`. Хотя их можно вызывать вручную, эти команды обычно выполняются автоматически при загрузке системы.

Все сетевые интерфейсы, управляемые `ifup` и `ifdown`, должны быть перечислены в файле `/etc/network/interfaces` . Формат файла прост: строки, начинающиеся со слова `auto`, используются для идентификации физических интерфейсов, которые будут активированы при выполнении `ifup` с опцией `-a` . Имя интерфейса должно следовать за словом `auto` в той же строке. Все интерфейсы, отмеченные `auto`, активируются при загрузке в том порядке, в котором они перечислены.

{% hint style="info" %}
Методы настройки сети, используемые в `ifup` и `ifdown`, не стандартизированы во всех дистрибутивах Linux. Например, в CentOS настройки интерфейса хранятся в отдельных файлах в каталоге `/etc/sysconfig/network-scripts/`, и формат конфигурации, используемый в них, немного отличается от формата, используемого в `/etc/network/interfaces`.
{% endhint %}

Фактическая конфигурация интерфейса записывается в другой строке, начиная со слова `iface`, за которым следует имя интерфейса, имя семейства адресов, которое использует интерфейс, и имя метода, используемого для настройки интерфейса. В следующем примере показан базовый файл конфигурации для интерфейсов `lo` (петлевой) и `enp3s5`:

```bash
auto lo
iface lo inet loopback

auto enp3s5
iface enp3s5 inet dhcp
```

Семейство адресов должно быть `inet` для сети TCP/IP, но также поддерживается сеть IPX (`ipx`), и сеть IPv6 (`inet6`). Для петлевых интерфейсов используется метод `loopback` настройки. При использовании метода `dhcp` интерфейс будет использовать настройки IP, предоставленные DHCP-сервером сети. Настройки из примера конфигурации позволяют выполнить команду `ifup` с именем интерфейса `enp3s5` в качестве аргумента:

```bash
# ifup enp3s5
Internet Systems Consortium DHCP Client 4.4.1
Copyright 2004-2018 Internet Systems Consortium.
All rights reserved.
For info, please visit https://www.isc.org/software/dhcp/

Listening on LPF/enp3s5/00:16:3e:8d:2b:5b
Sending on   LPF/enp3s5/00:16:3e:8d:2b:5b
Sending on   Socket/fallback
DHCPDISCOVER on enp3s5 to 255.255.255.255 port 67 interval 4
DHCPOFFER of 10.90.170.158 from 10.90.170.1
DHCPREQUEST for 10.90.170.158 on enp3s5 to 255.255.255.255 port 67
DHCPACK of 10.90.170.158 from 10.90.170.1
bound to 10.90.170.158 -- renewal in 1616 seconds.
```

В этом примере для интерфейса `enp3s5` был выбран метод `dhcp`, поэтому команда `ifup` вызвала клиентскую программу DHCP для получения настроек IP с сервера DHCP. Аналогичным образом команда `ifdown enp3s5` может использоваться для отключения интерфейса.

В сетях без DHCP-сервера вместо него можно использовать метод `static` и вручную задать IP-адрес в `/etc/network/interfaces`. Например:

```bash
iface enp3s5 inet static
    address 192.168.1.2/24
    gateway 192.168.1.1
```

Интерфейсы, использующие метод `static` не нуждаются в соответствующей директиве `auto` , поскольку они активируются при обнаружении сетевого оборудования.

Если для одного и того же интерфейса задано более одной `iface` записи, то при подключении к этому интерфейсу будут применяться все настроенные адреса и параметры. Это полезно для настройки адресов IPv4 и IPv6 на одном и том же интерфейсе, а также для настройки нескольких адресов одного типа на одном интерфейсе.

## Локальные и Удаленные Имена <a href="#sec.109.2_01-lrn" id="sec.109.2_01-lrn"></a>

Работающая настройка TCP/IP — это лишь первый шаг к полноценному использованию сети. Помимо возможности идентифицировать узлы сети по их IP-адресам, система должна уметь идентифицировать их по именам, более понятным людям.

Имя, под которым система идентифицирует себя, можно настроить, и рекомендуется указывать его, даже если компьютер не предназначен для подключения к сети. Локальное имя часто совпадает с сетевым именем компьютера, но это не всегда так. Если файл `/etc/hostname` существует, операционная система будет использовать содержимое первой строки в качестве локального имени, которое впоследствии будет называться просто _hostname_. Строки, начинающиеся с `#` внутри `/etc/hostname`, игнорируются.

Файл `/etc/hostname` можно редактировать напрямую, но имя хоста также можно задать с помощью команды `hostnamectl` . При использовании подкоманды `set-hostname` команда `hostnamectl` принимает имя в качестве аргумента и записывает его в `/etc/hostname`:

```bash
# hostnamectl set-hostname storage
# cat /etc/hostname
```

Имя хоста, заданное в `/etc/hostname`, является _статическим_ именем хоста, то есть именем, которое используется для инициализации имени хоста системы при загрузке. Статическое имя хоста может представлять собой строку произвольной длины до 64 символов. Однако рекомендуется, чтобы оно состояло только из символов нижнего регистра ASCII и не содержало пробелов или точек. Оно также должно соответствовать формату, допустимому для меток доменных имён DNS, хотя это и не является строгим требованием.

Команда `hostnamectl` может задавать два других типа имён хостов в дополнение к статическому имени хоста:

_Pretty hostname_

В отличие от статического имени хоста, pretty hostname хоста может содержать любые специальные символы. Его можно использовать для присвоения более информативного имени компьютеру, например “LAN Shared Storage”:

```bash
# hostnamectl --pretty set-hostname «LAN Shared Storage»
```

Временное имя хоста

Используется, когда статическое имя хоста не задано или когда оно является именем `localhost` по умолчанию. Временное имя хоста обычно задается вместе с другими автоматическими настройками, но его также можно изменить с помощью команды `hostnamectl`, например

```bash
# hostnamectl --transient set-hostname generic-host
```

Если не используется ни опция `--pretty` ни опция `--transient`, то все три типа имён хостов будут установлены на заданное имя. Чтобы установить статическое имя хоста, но не красивые и временные имена, следует использовать опцию `--static`. Во всех случаях в файле `/etc/hostname` сохраняется только статическое имя хоста. Команда `hostnamectl` также может использоваться для отображения различных описательных и идентификационных сведений о работающей системе:

```bash
$ hostnamectl status
     Static hostname: storage
     Pretty hostname: LAN Shared Storage
  Transient hostname: generic-host
           Icon name: computer-server
             Chassis: server
          Machine ID: d91962a957f749bbaf16da3c9c86e093
             Boot ID: 8c11dcab9c3d4f5aa53f4f4e8fdc6318
    Operating System: Debian GNU/Linux 10 (buster)
              Kernel: Linux 4.19.0-8-amd64
        Architecture: x86-64
```

Это действие по умолчанию для команды `hostnamectl`, поэтому подкоманду `status` можно не указывать.

Что касается имён удалённых сетевых узлов, то операционная система может использовать два основных способа сопоставления имён и IP-адресов: использовать локальный источник или использовать удалённый сервер для преобразования имён в IP-адреса и наоборот. Эти методы могут дополнять друг друга, а их порядок приоритета определяется в файле конфигурации _Name Service Switch_: `/etc/nsswitch.conf`. Этот файл используется системой и приложениями для определения не только источников сопоставления имён и IP-адресов, но и источников, из которых можно получить информацию о службе имён в различных категориях, называемых _базами данных_.

База данных _hosts_ отслеживает соответствие между именами хостов и адресами хостов. Строка внутри `/etc/nsswitch.conf` с префиксом `hosts` определяет службы, отвечающие за предоставление этих соответствий:

```bash
hosts: files dns
```

В этом примере `files` и `dns` — это имена служб, которые определяют, как будет работать процесс поиска имён хостов. Сначала система будет искать совпадения в локальных файлах, а затем запросит совпадения у службы DNS.

Локальный файл для базы данных хостов — это `/etc/hosts` простой текстовый файл, в котором IP-адреса сопоставляются с именами хостов, по одной строке на IP-адрес, например:

```bash
127.0.0.1 localhost
```

IP-адрес _127.0.0.1_ — это адрес по умолчанию для интерфейса обратной связи, отсюда и его связь с именем _localhost_.

Также можно привязать дополнительные псевдонимы к тому же IP-адресу. Псевдонимы могут содержать альтернативные варианты написания, более короткие имена хостов и должны добавляться в конец строки, например:

```bash
192.168.1.10 foo.mydomain.org foo
```

Правила форматирования для `/etc/hosts` файла следующие:

* Поля записи разделяются любым количеством пробелов и/или символов табуляции.
* Текст от символа `#` до конца строки является комментарием и игнорируется.
* Имена хостов могут содержать только буквенно-цифровые символы, знаки минус и точки.
* Имена хостов должны начинаться с буквы и заканчиваться буквенно-цифровым символом.

Адреса IPv6 также могут быть добавлены в `/etc/hosts`. Следующая запись относится к петлевому адресу IPv6:

```bash
::1 localhost ip6-localhost ip6-loopback
```

В соответствии со спецификацией `files` службы, спецификация `dns` указывает системе запросить у DNS-сервера нужную ассоциацию имени и IP-адреса. Набор процедур, отвечающих за этот метод, называется _resolver_, а его конфигурационный файл — `/etc/resolv.conf`. В следующем примере показан общий `/etc/resolv.conf` файл, содержащий записи для общедоступных DNS-серверов Google:

```bash
nameserver 8.8.4.4
nameserver 8.8.8.8
```

Как показано в примере, ключевое слово `nameserver` указывает на IP-адрес DNS-сервера. Требуется только один сервер имён, но можно указать до трёх серверов имён. Дополнительные серверы будут использоваться в качестве резервных. Если записи о серверах имён отсутствуют, по умолчанию используется сервер имён на локальном компьютере.

Резолвер можно настроить так, чтобы он автоматически добавлял домен к именам перед обращением к серверу имён. Например:

```bash
nameserver 8.8.4.4
nameserver 8.8.8.8
domain mydomain.org
search mydomain.net mydomain.com
```

Запись `domain` устанавливает `mydomain.org` в качестве локального доменного имени, поэтому запросы для имён в этом домене будут разрешать использование коротких имён относительно локального домена. Запись `search` имеет аналогичное назначение, но принимает список доменов, которые будут проверяться при вводе короткого имени. По умолчанию она содержит только локальное доменное имя.

## Краткие сведения <a href="#sec.109.2_01-su" id="sec.109.2_01-su"></a>

В этом уроке рассказывается о том, как вносить постоянные изменения в конфигурацию локальной сети с помощью стандартных файлов и команд Linux. Linux ожидает, что настройки TCP/IP будут находиться в определённых местах, и может потребоваться их изменить, если настройки по умолчанию не подходят. В уроке рассматриваются следующие темы:

* Как Linux идентифицирует сетевые интерфейсы.
* Активация интерфейса во время загрузки и базовая настройка IP-адреса.
* Как операционная система связывает имена с узлами.

Были рассмотрены следующие концепции, команды и процедуры:

* Соглашения об именовании интерфейсов.
* Перечисление сетевых интерфейсов с помощью `ip` и `nmcli`.
* Активация интерфейса с помощью `ifup` и `ifdown`.
* Команда `hostnamectl` и `/etc/hostname` файл.
* Файлы `/etc/nsswitch.conf`, `/etc/hosts` и `/etc/resolv.conf`.

## Ответы на Упражнения с Руководством <a href="#sec.109.2_01-age" id="sec.109.2_01-age"></a>

1.  Какие команды можно использовать для составления списка сетевых адаптеров, присутствующих в системе?

    Команды `ip link show`, `nmcli device` и устаревший `ifconfig`.
2.  Каков тип сетевого адаптера, имя интерфейса которого `wlo1`?

    Название начинается на `wl`, значит, это адаптер беспроводной локальной сети.
3.  Какую роль играет файл `/etc/network/interfaces` во время загрузки?

    В нём есть конфигурации, используемые командой `ifup` для активации соответствующих интерфейсов во время загрузки.
4.  Какая запись в `/etc/network/interfaces` настраивает интерфейс `eno1` для получения IP-адреса с помощью DHCP?

    Линия `iface eno1 inet dhcp`.

## Ответы на Исследовательские упражнения <a href="#sec.109.2_01-aee" id="sec.109.2_01-aee"></a>

1.  Как можно использовать команду `hostnamectl` для изменения только _статического_ имени хоста локального компьютера на `firewall`?

    С `--static` опцией: `hostnamectl --static set-hostname firewall`.
2.  Какие данные, кроме имен хостов, могут быть изменены командой `hostnamectl`?

    `hostnamectl` Вы также можете задать значок по умолчанию для локального компьютера, его тип, местоположение и среду развёртывания.
3.  Какая запись в `/etc/hosts` связывает оба имени `firewall` и `router` с IP `10.8.0.1`?

    Линия `10.8.0.1 firewall router`.
4.  Как можно изменить файл `/etc/resolv.conf` таким образом, чтобы все DNS-запросы отправлялись на `1.1.1.1`?

    Используя `nameserver 1.1.1.1` в качестве единственной записи сервера имен.
