# Урок 9.1.1.

## Введение <a href="#sec.109.1_01-in" id="sec.109.1_01-in"></a>

TCP/IP (_протокол управления передачей/интернет-протокол Transmission Control Protocol/Internet Protocol_) — это набор протоколов, используемых для обеспечения связи между компьютерами. Несмотря на название, набор состоит из нескольких протоколов, таких как IP, TCP, UDP, ICMP, DNS, SMTP, ARP и других.

#### IP (Интернет-протокол) <a href="#ip_internet_protocol" id="ip_internet_protocol"></a>

IP — это протокол, отвечающий за логическую адресацию хоста, что позволяет отправлять пакеты с одного хоста на другой. Для этого каждому устройству в сети присваивается уникальный IP-адрес, и одному устройству можно присвоить несколько адресов.

В четвёртой версии IP-протокола, обычно называемой IPv4, адрес состоит из 32 бит, разделённых на 4 группы по 8 бит, представленных в десятичной форме и называемых «четырёхзначным десятичным числом». Например:

Двоичный формат (4 группы по 8 бит)

```
11000000.10101000.00001010.00010100
```

Десятичный формат

`192.168.10.20`

В IPv4 значения для каждого октета могут находиться в диапазоне от 0 до 255, что эквивалентно 11111111 в двоичном формате.

## **Классы адресов**

Теоретически IP-адреса делятся на классы, которые определяются диапазоном первого октета, как показано в таблице ниже:

| Класс | Первый Октект | Диапазон                        | Пример           |
| ----- | ------------- | ------------------------------- | ---------------- |
| A     | 1-126         | `1.0.0.0` – `126.255.255.255`   | `10.25.13.10`    |
| B     | 128-191       | `128.0.0.0` – `191.255.255.255` | `141.150.200.1`  |
| C     | 192-223       | `192.0.0.0` – `223.255.255.255` | `200.178.12.242` |

## **Публичные и Частные IP-адреса**

Как упоминалось ранее, для осуществления связи каждое устройство в сети должно быть связано как минимум с одним уникальным IP-адресом. Однако если бы каждое устройство, подключённое к Интернету, имело уникальный IP-адрес, то на всех не хватило бы IP-адресов (v4). Поэтому были определены _частные_ IP-адреса.

Частные IP-адреса — это диапазоны IP-адресов, зарезервированные для использования во внутренних (частных) сетях компаний, учреждений, домов и т. д. В пределах одной сети использование IP-адреса остаётся уникальным. Однако один и тот же частный IP-адрес может использоваться в любой частной сети.

Таким образом, в Интернете мы используем общедоступные IP-адреса, которые распознаются и маршрутизируются через Интернет, а в частных сетях используются зарезервированные диапазоны IP-адресов. Маршрутизатор отвечает за преобразование трафика из частной сети в общедоступную и наоборот.

Диапазоны частных IP-адресов, разделённые по классам, представлены в таблице ниже:

| Класс | Первый Октет | Диапазон                        | Частные IP-адреса                 |
| ----- | ------------ | ------------------------------- | --------------------------------- |
| A     | 1-126        | `1.0.0.0` – `126.255.255.255`   | `10.0.0.0` – `10.255.255.255`     |
| B     | 128-191      | `128.0.0.0` – `191.255.255.255` | `172.16.0.0` – `172.31.255.255`   |
| C     | 192-223      | `192.0.0.0` – `223.255.255.255` | `192.168.0.0` – `192.168.255.255` |

## **Преобразование из десятичного формата в двоичный**

Для тех, кто изучает эту тему, важно знать, как преобразовывать IP-адреса из двоичного формата в десятичный и обратно.

Преобразование из десятичного формата в двоичный выполняется путём последовательного деления на 2. В качестве примера преобразуем число 105 следующим образом:

1.  Разделив значение 105 на 2, мы получим:

    ```
    105/2
    Частное = 52
    Остаток = 1
    ```
2.  Последовательно делите частное на 2, пока частное не станет равным 1:

    ```
    52/2
    Остаток = 0
    Частное = 26
    ```

    ```
    26/2
    Остаток = 0
    Частное = 13
    ```

    ```
    13/2
    Остаток = 1
    Частное = 6
    ```

    ```
    6/2
    Остаток = 0
    Частное = 3
    ```

    ```
    3/2
    Остаток = 1
    Частное = 1
    ```
3.  Сгруппируйте последнее частное, за которым следует остаток от всех делений:

    ```
    1101001
    ```
4.  Заполняйте 0 слева до тех пор, пока не будет заполнено 8 бит:

    ```
    01101001
    ```
5. В итоге мы получили, что десятичное число 105 равно двоичному числу 01101001.

## **Преобразование из двоичного формата в десятичный**

В этом примере мы будем использовать двоичное значение `10110000`.

1.  Каждый бит связан со значением, возведённым в степень двойки. Степени начинаются с 0 и увеличиваются справа налево. В этом примере мы получим:

    | 1  | 0  | 1  | 1  | 0  | 0  | 0  | 0  |
    | -- | -- | -- | -- | -- | -- | -- | -- |
    | 27 | 26 | 25 | 24 | 23 | 22 | 21 | 20 |
2.  Если бит равен 1, мы присваиваем значение соответствующей степени, если бит равен 0, результатом будет 0.

    | 1   | 0  | 1  | 1  | 0  | 0  | 0  | 0  |
    | --- | -- | -- | -- | -- | -- | -- | -- |
    | 27  | 26 | 25 | 24 | 23 | 22 | 21 | 20 |
    | 128 | 0  | 32 | 16 | 0  | 0  | 0  | 0  |
3.  Суммируйте все значения:

    128 + 32 + 16 = 176
4. Таким образом, 10110000 в двоичной системе равно 176 в десятичной системе.

## **Сетевая маска**

Сетевая маска (или _netmask_) используется вместе с IP-адресом для определения того, какая часть IP-адреса представляет сеть, а какая — хосты. Она имеет тот же формат, что и IP-адрес, то есть состоит из 32 бит, разделённых на 4 группы по 8 бит. Например:

| Десятичная дробь | Бинарный                              | CIDR |
| ---------------- | ------------------------------------- | ---- |
| `255.0.0.0`      | `11111111.00000000.00000000.00000000` | `8`  |
| `255.255.0.0`    | `11111111.11111111.00000000.00000000` | `16` |
| `255.255.255.0`  | `11111111.11111111.11111111.00000000` | `24` |

Если взять в качестве примера маску `255.255.0.0`, то она указывает на то, что в связанном с ней IP-адресе первые 16 бит (2 первых десятичных знака) определяют сеть/подсеть, а последние 16 бит используются для уникальной идентификации хостов в сети.

Упомянутая выше CIDR (_бесклассовая междоменная маршрутизация Classless Inter-Domain Routing_) связана с упрощённой маской, которая указывает количество битов (1), связанных с сетью/подсетью. Эта маска обычно используется вместо десятичного формата, например `/24` вместо `255.255.255.0`.

Интересно отметить, что у каждого класса IP-адресов есть стандартная маска, которая выглядит следующим образом:

| Класс | Первый Октет | Диапазон                        | Маска по умолчанию   |
| ----- | ------------ | ------------------------------- | -------------------- |
| A     | 1-126        | `1.0.0.0` – `126.255.255.255`   | `255.0.0.0 / 8`      |
| B     | 128-191      | `128.0.0.0` – `191.255.255.255` | `255.255.0.0 / 16`   |
| C     | 192-223      | `192.0.0.0` – `223.255.255.255` | `255.255.255.0 / 24` |

Однако этот шаблон не означает, что эта маска будет использоваться всегда. Можно использовать любую маску с любым IP-адресом, как мы увидим ниже.

Вот несколько примеров использования IP-адресов и масок:

```
192.168.8.12 / 255.255.255.0 / 24
```

Диапазон

`192.168.8.0` - `192.168.8.255`

Сетевой адрес

`192.168.8.0`

Широковещательный Адрес

`192.168.8.255`

Хосты

`192.168.8.1` - `192.168.8.254`

В данном случае первые 3 цифры (первые 24 бита) IP-адреса определяют сеть, а последняя цифра идентифицирует адреса хостов, то есть диапазон этой сети составляет от `192.168.8.0` до `192.168.8.255`.

Теперь у нас есть два важных понятия: у каждой сети/подсети есть 2 зарезервированных адреса. Первый адрес в диапазоне называется _сетевым адресом_. В данном случае `192.168.8.0` используется для идентификации самой сети/подсети. Последний адрес в диапазоне называется _широковещательным адресом_, в данном случае `192.168.8.255`. Этот адрес назначения используется для отправки одного и того же сообщения (пакета) всем IP-хостам в этой сети/подсети.

Сетевые и широковещательные адреса не могут использоваться устройствами в сети. Поэтому список IP-адресов, которые можно эффективно настроить, варьируется от `192.168.8.1` до `192.168.8.254`.

Теперь пример с тем же IP, но с другой маской:

```
192.168.8.12 / 255.255.0.0 / 16
```

Диапазон

`192.168.0.0` - `192.168.255.255`

Сетевой адрес

`192.168.0.0`

Широковещательный Адрес

`192.168.255.255`

Хосты

`192.168.0.1` – `192.168.255.254`

Посмотрите, как разные маски изменяют диапазон IP-адресов в одной и той же сети/подсети.

Разделение сетей по маскам не ограничивается значениями по умолчанию (8, 16, 24). Мы можем создавать подразделения по своему усмотрению, добавляя или удаляя биты в идентификаторе сети, создавая новые подсети.

Например:

```
11111111.11111111.11111111.00000000 = 255.255.255.0 = 24
```

Если мы хотим разделить описанную выше сеть на две, просто добавьте ещё один бит к идентификатору сети в маске, как показано ниже:

```
11111111.11111111.11111111.10000000 = 255.255.255.128 = 25
```

Таким образом, у нас есть следующие подсети:

```
192.168.8.0   - 192.168.8.127
192.168.8.128 - 192.168.8.255
```

Если мы еще больше увеличим подразделенность сети:

```
11111111.11111111.11111111.11000000 = 255.255.255.192 = 26
```

У нас будет:

```
192.168.8.0   - 192.168.8.63
192.168.8.64  - 192.168.8.127
192.168.8.128 - 192.168.8.191
192.168.8.192 - 192.168.8.255
```

Обратите внимание, что в каждой подсети у нас будут зарезервированные сетевые (первые в диапазоне) и широковещательные (последние в диапазоне) адреса, поэтому чем больше сеть разделена на подсети, тем меньше IP-адресов могут эффективно использоваться хостами.

## **Идентификация сетевых и широковещательных адресов**

С помощью IP-адреса и маски мы можем определить сетевой адрес и широковещательный адрес и, таким образом, задать диапазон IP-адресов для сети/подсети.

Сетевой адрес получается путём логического «И» между IP-адресом и маской в их двоичных форматах. Давайте рассмотрим пример с использованием IP `192.168.8.12` и маски `255.255.255.192`.

Преобразуя десятичное число в двоичное, как мы видели ранее, мы получаем:

```
11000000.10101000.00001000.00001100 (192.168.8.12)
11111111.11111111.11111111.11000000 (255.255.255.192)
```

При использовании «логического И» мы получаем 1 и 1 = 1, 0 и 0 = 0, 1 и 0 = 0, поэтому:

```
11000000.10101000.00001000.00001100 (192.168.8.12)
11111111.11111111.11111111.11000000 (255.255.255.192)
11000000.10101000.00001000.00000000
```

Итак, сетевой адрес для этой подсети - `192.168.8.0`.

Теперь, чтобы получить широковещательный адрес, мы должны использовать сетевой адрес, в котором все биты, относящиеся к адресу хоста, равны 1:

```
11000000.10101000.00001000.00000000 (192.168.8.0)
11111111.11111111.11111111.11000000 (255.255.255.192)
11000000.10101000.00001000.00111111
```

Тогда широковещательный адрес будет `192.168.8.63`.

В заключение, мы имеем:

```
192.168.8.12 / 255.255.255.192 / 26
```

Диапазон

`192.168.8.0` - `192.168.8.63`

Сетевой адрес

`192.168.8.0`

Широковещательный Адрес

`192.168.8.63`

Хосты

`192.168.8.1` – `192.168.8.62`

## **Маршрут по умолчанию**

Как мы уже видели, устройства, находящиеся в одной логической сети/подсети, могут напрямую взаимодействовать по протоколу IP.

Но давайте рассмотрим приведенный ниже пример:

Сеть 1

`192.168.10.0/24`

Сеть 2

`192.168.200.0/24`

В этом случае компьютер `192.168.10.20` не может напрямую отправить пакет на компьютер `192.168.200.100`, поскольку они находятся в разных логических сетях.

Для обеспечения такой связи используется маршрутизатор (или набор маршрутизаторов). Маршрутизатор в такой конфигурации также можно назвать шлюзом, поскольку он обеспечивает связь между двумя сетями. Это устройство имеет доступ к обеим сетям, поскольку настроено на IP-адреса обеих сетей. Например, `192.168.10.1` и `192.168.200.1`, и по этой причине оно может выступать посредником в такой связи.

Чтобы это стало возможным, каждый хост в сети должен быть настроен на так называемый _маршрут по умолчанию_. Маршрут по умолчанию указывает IP-адрес, на который должны отправляться все пакеты, целью которых является IP-адрес, не входящий в логическую сеть хоста.

В приведённом выше примере маршрутом по умолчанию для компьютеров в сети `192.168.10.0/24` будет IP-адрес `192.168.10.1`, который является IP-адресом маршрутизатора/шлюза, а маршрутом по умолчанию для компьютеров в сети `192.168.200.0/24` будет `192.168.200.1`.

Маршрут по умолчанию также используется для того, чтобы компьютеры в частной сети (LAN) имели доступ к Интернету (WAN) через маршрутизатор.

## Ответы на Исследовательские упражнения <a href="#sec.109.1_01-aee" id="sec.109.1_01-aee"></a>

1.  Почему диапазоны IP-адресов, начинающиеся с `127` и заканчивающиеся на `224`, не входят в классы IP-адресов A, B или C?

    Диапазон, начинающийся с `127`, зарезервирован для обратных адресов, используемых для тестирования и внутренней связи между процессами, например, для адреса `127.0.0.1`. Кроме того, адреса выше `224` также не используются в качестве адресов хостов, а применяются для многоадресной рассылки и других целей.
2.  Одно из очень важных полей IP-пакета — это TTL (_время жизни_). Какова функция этого поля и как оно работает?

    TTL определяет время жизни пакета. Это реализовано с помощью счётчика, в котором начальное значение, заданное в источнике, уменьшается на единицу в каждом шлюзе/маршрутизаторе, через который проходит пакет, что также называется «переходом». Если этот счётчик достигает 0, пакет отбрасывается.
3.  Объясните функцию NAT и когда она используется.

    Функция NAT (_преобразование сетевых адресов Network Address Translation_) позволяет хостам во внутренней сети, использующим частные IP-адреса, получать доступ к Интернету, как если бы они были напрямую подключены к нему, с использованием публичного IP-адреса на шлюзе.
