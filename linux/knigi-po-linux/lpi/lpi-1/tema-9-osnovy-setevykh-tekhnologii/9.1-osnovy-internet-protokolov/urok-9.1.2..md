# Урок 9.1.2.

## Введение <a href="#sec.109.1_02-in" id="sec.109.1_02-in"></a>

В начале этой темы мы увидели, что стек TCP/IP состоит из ряда различных протоколов. До сих пор мы изучали протокол IP, который обеспечивает связь между компьютерами с помощью IP-адресов, масок, маршрутов и т. д.

Чтобы хост мог получить доступ к сервису, доступному на другом хосте, в дополнение к протоколу IP-адресации на сетевом уровне необходимо использовать протокол транспортного уровня, например протоколы TCP и UDP.

Эти протоколы осуществляют обмен данными через сетевые порты. Таким образом, помимо определения IP-адресов источника и получателя, для доступа к сервису будут использоваться порты источника и получателя.

Порт идентифицируется 16-битным полем, что обеспечивает ограничение в 65 535 возможных портов. Службы (адреса назначения) используют порты с 1 по 1023, которые называются _привилегированными портами_, поскольку имеют root-доступ к системе. Источник соединения будет использовать диапазон портов с 1024 по 65 535, которые называются _непривилегированными портами_ или портами сокетов.

Порты, используемые каждым типом службы, стандартизированы и контролируются IANA (_Управлением по присвоению номеров в Интернете Internet Assigned Numbers Authority_). Это означает, что в любой системе порт 22 используется службой SSH, порт 80 — службой HTTP и так далее.

## Протокол управления передачей (TCP) <a href="#transmission_control_protocol_tcp" id="transmission_control_protocol_tcp"></a>

TCP — это транспортный протокол, ориентированный на установление соединения. Это означает, что соединение устанавливается между клиентом через порт сокета и сервисом через стандартный порт сервиса. Протокол отвечает за корректную доставку всех пакетов, проверку целостности и порядка пакетов, а также за повторную передачу пакетов, потерянных из-за сетевых ошибок.

Таким образом, приложению не нужно реализовывать этот контроль потока данных, поскольку он уже гарантирован протоколом TCP.

## Протокол пользовательских дейтаграмм (UDP) <a href="#user_datagram_protocol_udp" id="user_datagram_protocol_udp"></a>

UDP устанавливает соединение между клиентом и сервисом, но не контролирует передачу данных по этому соединению. Другими словами, он не проверяет, не потерялись ли пакеты, не нарушен ли порядок их следования и т. д. Приложение отвечает за реализацию необходимых средств контроля.

Поскольку UDP обеспечивает меньшую степень контроля, он повышает производительность передачи данных, что важно для некоторых типов сервисов.

## Протокол управляющих сообщений Интернета (ICMP) <a href="#internet_control_message_protocol_icmp" id="internet_control_message_protocol_icmp"></a>

ICMP — это протокол сетевого уровня в стеке TCP/IP, основная функция которого заключается в анализе и управлении сетевыми элементами, что позволяет, например:

* Контроль объёма трафика
* Обнаружение недоступных конечных точек
* Перенаправление маршрута
* Проверка состояния удалённых хостов

Это протокол, используемый командой `ping`, который будет рассмотрен в другом разделе.

## IPv6 <a href="#ipv6" id="ipv6"></a>

До сих пор мы изучали четвёртую версию IP-протокола, то есть IPv4. Это была стандартная версия, используемая во всех сетевых и интернет-средах. Однако у неё есть ограничения, особенно в отношении количества доступных адресов, и в условиях, когда все устройства так или иначе подключены к интернету (см. «Интернет вещей»), всё чаще используется шестая версия IP-протокола, обычно называемая IPv6.

IPv6 привносит ряд изменений, новые реализации и функции, а также новое представление самого адреса.

Каждый IPv6-адрес состоит из 128 бит, разделённых на 8 групп по 16 бит, представленных шестнадцатеричными значениями.

Например:

```
2001:0db8:85a3:08d3:1319:8a2e:0370:7344
```

## **Сокращения**

В некоторых ситуациях IPv6 определяет способы сокращения адресов. Давайте рассмотрим следующий адрес:

```
2001:0db8:85a3:0000:0000:0000:0000:7344
```

Первая возможность заключается в сокращении строк с `0000` до просто `0`, в результате чего:

```
2001:0db8:85a3:0:0:0:0:7344
```

Кроме того, в случае групповых строк со значением `0` их можно не указывать следующим образом:

```
2001:0db8:85a3::7344
```

Однако это последнее сокращение можно использовать в адресе только один раз. Смотрите пример:

```
2001:0db8:85a3:0000:0000:1319:0000:7344

2001:0db8:85a3:0:0:1319:0:7344

2001:0db8:85a3::1319:0:7344
```

## **Типы адресов IPv6**

IPv6 классифицирует адреса на 3 типа:

_Unicast_

Определяет один сетевой интерфейс. По умолчанию 64 бита слева определяют сеть, а 64 бита справа определяют интерфейс.

_Multicast_

Определяет набор сетевых интерфейсов. Пакет, отправленный на многоадресный адрес, будет отправлен на все интерфейсы, входящие в эту группу. Несмотря на схожесть, его не следует путать с широковещательной рассылкой, которая не существует в протоколе IPv6.

_Anycast_

Это также определяет набор интерфейсов в сети, но пакет, отправленный на _anycast_-адрес, будет доставлен только на один адрес из этого набора, а не на все.

## **Различия между IPv4 и IPv6**

Помимо адреса, между 4-й и 6-й версиями IP можно выделить ещё несколько различий. Вот некоторые из них:

*   Сервисные порты соответствуют тем же стандартам и протоколам (TCP, UDP), разница только в представлении IP-адреса и набора портов. В IPv6 IP-адрес должен быть защищён `[]` (скобками):

    IPv4

    `200.216.10.15:443`

    IPv6

    `[2001:0db8:85a3:08d3:1319:8a2e:0370:7344]:443`
* В IPv6 нет функции широковещательной рассылки в том виде, в котором она существует в IPv4. Однако того же результата можно добиться, отправив пакет по адресу `ff02::1`, который будет получен всеми хостами в локальной сети. Это похоже на использование `224.0.0.1` в IPv4 для многоадресной рассылки в качестве получателя.
* Благодаря функции SLAAC (_автоконфигурации адреса без сохранения состояния_) хосты IPv6 могут самостоятельно настраиваться.
* Поле TTL (_время жизни_) в IPv4 было заменено на «Hop Limit» в заголовке IPv6.
* Все интерфейсы IPv6 имеют локальный адрес, называемый локальным адресом канала, с префиксом `fe80::/10`.
* IPv6 реализует _протокол обнаружения соседей_ (NDP), который похож на ARP, используемый в IPv4, но обладает гораздо более широкими возможностями.
