# Урок 9.4.

## Введение <a href="#sec.109.4_01-in" id="sec.109.4_01-in"></a>

В этом уроке рассказывается о настройке разрешения имён на стороне клиента и о том, как использовать несколько инструментов для разрешения имён в командной строке.

Запоминать и поддерживать в актуальном состоянии IP-адреса, идентификаторы UID и GID, а также другие числа для всего подряд невозможно. Службы преобразования имён преобразуют легко запоминающиеся имена в числа и наоборот. В этом уроке основное внимание уделяется преобразованию имён хостов, но аналогичный процесс происходит с именами пользователей, групп, номерами портов и некоторыми другими.

## Процесс Разрешения имен <a href="#name_resolution_process" id="name_resolution_process"></a>

Программы, преобразующие имена в числа, почти всегда используют функции, предоставляемые стандартной библиотекой C, которая в системах Linux называется glibc и является частью проекта GNU. Первое, что делают эти функции, — считывают из файла `/etc/nsswitch.conf` инструкции по преобразованию имён такого типа. В этом уроке основное внимание уделяется преобразованию имён хостов, но тот же процесс применим и к другим типам преобразования имён. После считывания `/etc/nsswitch.conf` процесс ищет имя указанным способом. Поскольку `/etc/nsswitch.conf` поддерживает плагины, дальше может быть что угодно. После того как функция находит имя или номер, она возвращает результат вызывающему процессу.

## Классы DNS <a href="#dns_classes" id="dns_classes"></a>

В DNS есть три класса записей: IN, HS и CH. В этом уроке все DNS-запросы будут иметь тип IN. Класс IN предназначен для интернет-адресов, использующих стек TCP/IP. Класс CH предназначен для ChaosNet — сетевой технологии, которая просуществовала недолго и больше не используется. Класс HS предназначен для Hesiod. Hesiod — это способ хранения таких данных, как пароли и записи групп в DNS. Hesiod выходит за рамки этого урока.

## **Понимание `/etc/nsswitch.conf`**

Лучший способ узнать об этом файле — прочитать справочную страницу, которая является частью проекта справочных страниц Linux. Она доступна в большинстве систем. Доступ к ней можно получить с помощью команды `man nsswitch.conf`. Кроме того, её можно найти по адресу [https://man7.org/linux/man-pages/dir\_section\_5.html](https://man7.org/linux/man-pages/dir_section_5.html)

Ниже приведен простой пример `/etc/nsswitch.conf` с его справочной страницы:

```bash
           passwd:         compat
           group:          compat
           shadow:         compat

           hosts:          dns [!UNAVAIL=return] files
           networks:       nis [NOTFOUND=return] files
           ethers:         nis [NOTFOUND=return] files
           protocols:      nis [NOTFOUND=return] files
           rpc:            nis [NOTFOUND=return] files
           services:       nis [NOTFOUND=return] files
           # This is a comment. It is ignored by the resolution functions.
```

Файл разделён на столбцы. Крайний левый столбец — это тип базы данных имён. Остальные столбцы — это методы, которые функции разрешения должны использовать для поиска имени. За методами следуют функции слева направо. Столбцы с `[]` используются для предоставления некоторой ограниченной условной логики для столбца, расположенного непосредственно слева от него.

Предположим, что процесс пытается разрешить имя хоста `learning.lpi.org`. Он вызовет соответствующую библиотеку C (скорее всего, `gethostbyname`). Затем эта функция прочитает `/etc/nsswitch.conf`. Поскольку процесс ищет имя хоста, он найдёт строку, начинающуюся с `hosts`. Затем он попытается использовать DNS для разрешения имени. Следующий столбец `[!UNAVAIL=return]` означает, что если служба _не_ недоступна, то не пытайтесь использовать следующий источник, то есть если DNS доступен, прекратите попытки разрешить имя хоста, даже если серверы имён не могут этого сделать. Если DNS недоступен, перейдите к следующему источнику. В данном случае следующим источником является `files`.

Когда вы видите столбец в формате `[result=action]`, это означает, что когда выполняется поиск в распознавателе столбца слева от него `result`, то `action` выполняется. Если перед `result` стоит`!`, это означает, что если результата нет `result`, то выполните `action`. Описание возможных результатов и действий смотрите на странице руководства.

Теперь предположим, что процесс пытается преобразовать номер порта в имя службы. Он прочитает строку `services`. Первым в списке источников будет NIS. NIS расшифровывается как _сетевая информационная служба_  _Network Information Service_ (иногда её называют «жёлтыми страницами»). Это старая служба, которая позволяла централизованно управлять такими вещами, как пользователи. Сейчас она редко используется из-за слабой защиты. Следующий столбец `[NOTFOUND=return]` означает, что если поиск удался, но служба не найдена, поиск следует прекратить. Если вышеупомянутое условие не выполняется, используйте локальные файлы.

Все, что находится справа от `#`, является комментарием и игнорируется.

## **`/etc/resolv.conf`Файл**

Файл `/etc/resolv.conf` используется для настройки разрешения хостов через DNS. В некоторых дистрибутивах есть сценарии запуска, демоны и другие инструменты, которые записывают данные в этот файл. Имейте это в виду при редактировании этого файла вручную. Если это так, ознакомьтесь с документацией по вашему дистрибутиву и любым инструментам настройки сети. Некоторые инструменты, например Network Manager, оставляют в файле комментарий, сообщающий, что изменения, внесённые вручную, будут перезаписаны.

Как и в случае с `/etc/nsswitch.conf`, с этим файлом связана справочная страница. Доступ к ней можно получить с помощью команды `man resolv.conf` или по адресу [https://man7.org/linux/man-pages/man5/resolv.conf.5.html](https://man7.org/linux/man-pages/man5/resolv.conf.5.html).

Формат файла довольно прост. В крайнем левом столбце находится опция `name`. Остальные столбцы в той же строке содержат значение опции.

Наиболее распространённым вариантом является опция `nameserver` . Она используется для указания IPv4- или IPv6-адреса DNS-сервера. На момент написания этой статьи вы можете указать до трёх серверов имён. Если в вашей `/etc/resolv.conf` нет опции `nameserver` , ваша система по умолчанию будет использовать сервер имён на локальном компьютере.

Ниже приведен простой пример файла, который является репрезентативным для распространенных конфигураций:

```bash
search lpi.org
nameserver 10.0.0.53
nameserver fd00:ffff::2:53
```

Параметр `search` используется для разрешения поиска по коротким формам. В приведенном примере настроен единый домен поиска `lpi.org`. Это означает, что любая попытка разрешить имя хоста без доменной части будет `.lpi.org` добавлена перед поиском. Например, если вы попытаетесь выполнить поиск узла с именем `learning`, распознаватель выполнит поиск `learning.lpi.org`. Вы можете настроить до шести поисковых доменов.

Другим распространенным параметром является параметр `domain`. Он используется для задания вашего локального доменного имени. Если этот параметр отсутствует, по умолчанию используется значение "все после первого" `.` в имени хоста компьютера. Если имя хоста не содержит `.`, предполагается, что компьютер является частью корневого домена. Как `search`, `domain` может использоваться для поиска по коротким именам.

Имейте в виду, что `domain` и `search` являются взаимоисключающими. Если присутствуют оба варианта, используется последний экземпляр в файле.

Существует несколько параметров, которые можно настроить, чтобы повлиять на поведение резолвера. Чтобы настроить их, используйте ключевое слово `options` с последующим указанием имени настраиваемого параметра и, если применимо, `:` с последующим указанием значения. Ниже приведён пример настройки параметра тайм-аута, который определяет, сколько секунд резолвер будет ожидать ответа от сервера имён, прежде чем сдаться:

```bash
option timeout:3
```

Есть и другие варианты `resolv.conf`, но эти наиболее распространены.

## **`/etc/hosts`Файл**

Файл `/etc/hosts` используется для преобразования имён в IP-адреса и наоборот. Поддерживаются как IPv4, так и IPv6. В левом столбце указан IP-адрес, в остальных — имена, связанные с этим адресом. Чаще всего `/etc/hosts` используется для хостов и адресов, для которых невозможно использовать DNS, например для обратных адресов. В приведённом ниже примере указаны IP-адреса критически важных компонентов инфраструктуры.

Вот реалистичный пример `/etc/hosts` файла:

```bash
127.0.0.1       localhost
127.0.1.1       proxy
::1             localhost ip6-localhost ip6-loopback
ff02::1         ip6-allnodes
ff02::2         ip6-allrouters

10.0.0.1        gateway.lpi.org gateway gw
fd00:ffff::1    gateway.lpi.org gateway gw

10.0.1.53       dns1.lpi.org
fd00:ffff::1:53 dns1.lpi.org
10.0.2.53       dns2.lpi.org
fd00:ffff::2:53 dns2.lpi.org
```

## **systemd-resolved**

Systemd предоставляет службу под названием `systemd-resolved`. Она предоставляет mDNS, DNS и LLMNR. Когда она запущена, она прослушивает DNS-запросы на `127.0.0.53`. Она _не_ предоставляет полноценный DNS-сервер. Любые DNS-запросы, которые она получает, обрабатываются с помощью запросов к серверам, настроенным в `/etc/systemd/resolv.conf` или `/etc/resolv.conf`. Если вы хотите использовать эту функцию, используйте `resolve` вместо `hosts` в `/etc/nsswitch.conf`. Имейте в виду, что пакет ОС с библиотекой `systemd-resolved` может не быть установлен по умолчанию.

## Инструменты разрешения имен <a href="#name_resolution_tools" id="name_resolution_tools"></a>

Пользователям Linux доступно множество инструментов для разрешения имён. В этом уроке мы рассмотрим три из них. Один из них, `getent`, полезен для просмотра того, как будут обрабатываться запросы в реальном мире. Другая команда — `host`, которая полезна для простых DNS-запросов. Программа под названием `dig` полезна для сложных DNS-операций, которые могут помочь в устранении неполадок на DNS-сервере.

**Команда `getent`**

Утилита `getent` используется для отображения записей из баз данных служб имён. Она может извлекать записи из любого источника, настраиваемого с помощью `/etc/nsswitch.conf`.

Чтобы использовать `getent`, выполните команду с указанием типа имени, которое вы хотите преобразовать, и, при необходимости, конкретной записи для поиска. Если вы укажете только тип имени, `getent` попытается отобразить все записи этого типа данных:

```bash
$ getent hosts
127.0.0.1       localhost
127.0.1.1       proxy
10.0.1.53       dns1.lpi.org
10.0.2.53       dns2.lpi.org
127.0.0.1       localhost ip6-localhost ip6-loopback
$ getent hosts dns1.lpi.org
fd00:ffff::1:53 dns1.lpi.org
```

Начиная с версии glibc 2.2.5, вы можете принудительно использовать `getent` конкретный источник данных с помощью опции `-s` . Ниже приведён пример:

```bash
$ getent -s files hosts learning.lpi.org
::1             learning.lpi.org
$ getent -s dns hosts learning.lpi.org
208.94.166.198  learning.lpi.org
```

**Команда `host`**&#x20;

`host` Это простая программа для поиска записей DNS. Без параметров, если `host` задано имя, она возвращает наборы записей A, AAAA и MX. Если задан IPv4- или IPv6-адрес, она выводит запись PTR, если таковая имеется:

```bash
$ host wikipedia.org
wikipedia.org has address 208.80.154.224
wikipedia.org has IPv6 address 2620:0:861:ed1a::1
wikipedia.org mail is handled by 10 mx1001.wikimedia.org.
wikipedia.org mail is handled by 50 mx2001.wikimedia.org.
$ host 208.80.154.224
224.154.80.208.in-addr.arpa domain name pointer text-lb.eqiad.wikimedia.org.
```

Если вы ищете определенный тип записи, вы можете использовать `host -t`:

```bash
$ host -t NS lpi.org
lpi.org name server dns1.easydns.com.
lpi.org name server dns3.easydns.ca.
lpi.org name server dns2.easydns.net.
$ host -t SOA lpi.org
lpi.org has SOA record dns1.easydns.com. zone.easydns.com. 1593109612 3600 600 1209600 300
```

`host` Также можно использовать для запроса конкретного сервера имён, если вы не хотите использовать те, что указаны в `/etc/resolv.conf`. Просто добавьте IP-адрес или имя хоста сервера, который вы хотите использовать, в качестве последнего аргумента:

```bash
$ host -t MX lpi.org dns1.easydns.com
Using domain server:
Name: dns1.easydns.com
Address: 64.68.192.10#53
Aliases:

lpi.org mail is handled by 10 aspmx4.googlemail.com.
lpi.org mail is handled by 10 aspmx2.googlemail.com.
lpi.org mail is handled by 5 alt1.aspmx.l.google.com.
lpi.org mail is handled by 0 aspmx.l.google.com.
lpi.org mail is handled by 10 aspmx5.googlemail.com.
lpi.org mail is handled by 10 aspmx3.googlemail.com.
lpi.org mail is handled by 5 alt2.aspmx.l.google.com.
```

**Команда `dig`**&#x20;

Другой инструмент для запроса DNS-серверов — `dig`. Эта команда гораздо более подробная, чем `host`. По умолчанию `dig` запрашивает записи A. Вероятно, она слишком подробная для простого поиска IP-адреса или имени хоста. `dig` подходит для простых запросов, но больше подходит для устранения неполадок в конфигурации DNS-сервера:

```bash
$ dig learning.lpi.org

;; QUESTION SECTION:
;learning.lpi.org.		IN	A

;; ANSWER SECTION:
learning.lpi.org.	600	IN	A	208.94.166.198

;; AUTHORITY SECTION:
lpi.org.		86400	IN	NS	dns2.easydns.net.
lpi.org.		86400	IN	NS	dns1.easydns.com.
lpi.org.		86400	IN	NS	dns3.easydns.ca.
```

Как видите, `dig` предоставляет много информации. Вывод разделён на разделы. В первом разделе отображается информация об установленной версии `dig` и отправленном запросе, а также о любых параметрах, использованных для команды. Далее отображается информация о запросе и ответе.

В следующем разделе представлена информация об используемых расширениях EDNS и запросе. В этом примере используется расширение cookie. `dig` ищет запись A для `learning.lpi.org`.

В следующем разделе показан результат запроса. Число во втором столбце — это TTL ресурса в секундах.

Остальная часть вывода содержит информацию о серверах имён домена, включая записи NS для сервера, а также записи A и AAAA серверов в записи NS домена.

Как и `host`, вы можете указать тип записи с помощью `-t` опции:


У Dig есть множество опций для точной настройки как вывода, так и запроса, отправляемого на сервер. Эти опции начинаются с `+`. Одна из опций — `short` — подавляет весь вывод, кроме результата:

```bash
$ dig +short lpi.org
65.39.134.165
$ dig +short -t SOA lpi.org
dns1.easydns.com. zone.easydns.com. 1593109612 3600 600 1209600 300
```

## Краткие сведения <a href="#sec.109.4_01-su" id="sec.109.4_01-su"></a>

Команда `getent` — отличный инструмент для просмотра результатов вызовов резолверов. Для простых DNS-запросов `host` проста в использовании и выдаёт понятный результат. Если вам нужна подробная информация или вы хотите точно настроить DNS-запрос, `dig` — лучший выбор.

Благодаря возможности добавлять плагины общих библиотек и настраивать поведение распознавателя, Linux отлично поддерживает разрешение имён и чисел различных типов. Программу `getent` можно использовать для разрешения имён с помощью библиотек распознавателя. `host` и `dig` можно использовать для запроса DNS-серверов.

Файл `/etc/nsswitch.conf` используется для настройки поведения распознавателя. Вы можете изменять источники данных и добавлять простую условную логику для типов имён с несколькими источниками.

DNS настраивается путём редактирования `/etc/resolv.conf`. Во многих дистрибутивах есть инструменты, которые управляют этим файлом за вас, поэтому обязательно ознакомьтесь с документацией по вашей системе, если изменения, внесённые вручную, не сохраняются.

Файл `/etc/hosts` используется для преобразования имён хостов в IP-адреса и наоборот. Обычно он используется для определения имён, таких как `localhost`, которые недоступны через DNS.

В файлах конфигурации, описанных в этом уроке, можно оставлять комментарии. Любой текст справа от `#` игнорируется системой.

## Ответы на Упражнения с Руководством <a href="#sec.109.4_01-age" id="sec.109.4_01-age"></a>

1.  Что будет делать приведенная ниже команда?

    ```bash
    getent group openldap
    ```

    Он прочитает `/etc/nsswitch.conf`, найдёт группу `openldap` в перечисленных источниках и отобразит информацию о ней, если она будет найдена.
2.  В чём заключается основное различие между `getent` и другими инструментами, описанными в `host` и `dig`?

    `getent` ищет имена с помощью библиотек преобразователей, остальные просто запрашивают DNS. `getent` можно использовать для устранения неполадок с `/etc/nsswitch.conf` и настройки библиотек преобразования имён, которые использует ваша система. `host` и `dig` используются для поиска DNS-записей.
3.  Какой вариант `dig` и `host` используется для указания типа записи, которую вы хотите получить?

    Обе программы используют `-t` для указания типа записи, которую вы хотите найти.
4.  Какая из перечисленных ниже записей является правильной `/etc/hosts`?

    | `::1 localhost`           | X |
    | ------------------------- | - |
    | **`localhost 127.0.0.1`** |   |

    `::1 localhost` Это правильная строка. В левом столбце всегда указывается IPv4- или IPv6-адрес.
5.  Какой параметр `getent` используется для указания источника данных, который следует использовать для поиска?

    Параметр `-s` используется для указания источника данных. Например:

    ```bash
    $ getent -s files hosts learning.lpi.org
    192.168.10.25   learning.lpi.org
    $ getent -s dns hosts learning.lpi.org
    208.94.166.198  learning.lpi.org
    ```

## Ответы на Исследовательские упражнения <a href="#sec.109.4_01-aee" id="sec.109.4_01-aee"></a>

1.  Если вы отредактируете `/etc/resolv.conf` ниже с помощью текстового редактора, что, скорее всего, произойдёт?

    ```
    # Generated by NetworkManager
    nameserver 192.168.1.20
    ```

    | Изменения будут перезаписаны NetworkManager.                       | X |
    | ------------------------------------------------------------------ | - |
    | NetworkManager обновит свою конфигурацию с учетом ваших изменений. |   |

2.  Что означает следующая строка в `/etc/nsswitch.conf`:

    ```bash
    hosts: files [SUCCESS=continue] dns
    ```

    При поиске имён хостов сначала проверяются ваши `/etc/hosts` файлы, а затем DNS. Если запись найдена в файлах и DNS, то используется запись в DNS.
3.  Учитывая следующее, `/etc/resolv.conf` почему система не разрешает имена через DNS?

    ```bash
    search lpi.org
    #nameserver fd00:ffff::1:53
    #nameserver 10.0.1.53
    ```

    Оба DNS-сервера закомментированы, и на локальном хосте не работает DNS-сервер.
4.  Что делает команда `dig +noall +answer +question lpi.org`?

    Он ищет запись A для `lpi.org` и отображает только запрос и ответ.
5.  Как можно изменить настройки по умолчанию `dig` без указания их в командной строке?

    Вы создаете `.digrc` файл в своем домашнем каталоге.
