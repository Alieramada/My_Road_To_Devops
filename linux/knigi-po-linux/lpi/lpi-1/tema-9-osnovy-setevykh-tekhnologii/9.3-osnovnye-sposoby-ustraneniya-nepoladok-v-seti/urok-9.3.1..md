# Урок 9.3.1.

## Введение <a href="#sec.109.3_01-in" id="sec.109.3_01-in"></a>

Linux обладает очень гибкими и мощными сетевыми возможностями. На самом деле, операционные системы на базе Linux часто используются на обычных сетевых устройствах, в том числе на дорогостоящем коммерческом оборудовании. Сетевые возможности Linux сами по себе могут стать сертификацией. Учитывая это, в данном уроке мы рассмотрим лишь несколько базовых инструментов для настройки и устранения неполадок.

Перед этим уроком обязательно просмотрите уроки, посвящённые интернет-протоколам и постоянной настройке сети. В этом уроке мы рассмотрим инструменты для настройки и устранения неполадок в сетях IPv4 и IPv6.

Хотя это и не является официальной целью, _профайлеры пакетов_, такие как `tcpdump`, являются полезными инструментами для устранения неполадок. Профайлеры пакетов позволяют просматривать и записывать пакеты, поступающие на сетевой интерфейс или выходящие с него. Такие инструменты, как _просмотрщики шестнадцатеричных данных_ и _анализаторы протоколов_, позволяют просматривать эти пакеты более детально, чем обычно позволяет профайлер пакетов. Не помешает хотя бы знать о таких программах.

## О команде `ip` <a href="#about_the_ip_command" id="about_the_ip_command"></a>

Команда `ip` — это довольно новая утилита, которая используется для просмотра и настройки практически всего, что связано с сетевыми настройками. В этом уроке рассматриваются некоторые наиболее часто используемые подкоманды `ip`, но он лишь поверхностно знакомит с тем, что доступно. Умение читать документацию поможет вам гораздо эффективнее использовать эту утилиту.

У каждой подкоманды `ip` есть своя справочная страница. В разделе `SEE ALSO` справочной страницы `ip` есть их список:

```bash
$ man ip
...
SEE ALSO
       ip-address(8), ip-addrlabel(8), ip-l2tp(8), ip-link(8), ip-maddress(8),
       ip-monitor(8), ip-mroute(8), ip-neighbour(8), ip-netns(8), ip-
       ntable(8), ip-route(8), ip-rule(8), ip-tcp_metrics(8), ip-token(8), ip-
       tunnel(8), ip-xfrm(8)
       IP Command reference ip-cref.ps
```

Вместо того чтобы каждый раз заглядывать в справочную страницу, просто добавьте `-` и название подкоманды в `ip`, например `man ip-route`.

Другим источником информации является функция справки. Чтобы просмотреть встроенную справку, добавьте `help` после подкоманды:

```bash
$ ip address help
Usage: ip address {add|change|replace} IFADDR dev IFNAME [ LIFETIME ]
                                                      [ CONFFLAG-LIST ]
       ip address del IFADDR dev IFNAME [mngtmpaddr]
       ip address {save|flush} [ dev IFNAME ] [ scope SCOPE-ID ]
                            [ to PREFIX ] [ FLAG-LIST ] [ label LABEL ] [up]
       ip address [ show [ dev IFNAME ] [ scope SCOPE-ID ] [ master DEVICE ]
                         [ type TYPE ] [ to PREFIX ] [ FLAG-LIST ]
                         [ label LABEL ] [up] [ vrf NAME ] ]
       ip address {showdump|restore}
IFADDR := PREFIX | ADDR peer PREFIX
```

## Обзор маски сети и маршрутизации <a href="#netmask_and_routing_review" id="netmask_and_routing_review"></a>

IPv4 и IPv6 — это так называемые маршрутизируемые протоколы. Это означает, что они разработаны таким образом, чтобы разработчики сетей могли управлять потоком трафика. Ethernet не является маршрутизируемым протоколом. Это означает, что если вы подключите несколько устройств друг к другу только с помощью Ethernet, вы мало что сможете сделать для управления потоком сетевого трафика. Любые меры по управлению трафиком будут аналогичны текущим маршрутизируемым протоколам.

Маршрутизируемые протоколы позволяют разработчикам сетей сегментировать сети, чтобы снизить требования к обработке данных на устройствах подключения, обеспечить резервирование и управлять трафиком.

Адреса IPv4 и IPv6 состоят из двух частей. Первый набор битов составляет сетевую часть, а второй — хостовую. Количество битов, составляющих сетевую часть, определяется _сетевой маской_ (также называемой _маской подсети_). Иногда её также называют _длиной префикса_. Независимо от названия, это количество битов, которые компьютер обрабатывает как сетевую часть адреса. В IPv4 иногда это значение указывается в десятичной системе счисления с точками.

Ниже приведён пример использования IPv4. Обратите внимание, что двоичные цифры сохраняют своё значение в октетах, даже если они разделены маской сети.

```
192.168.130.5/20

          192      168      130      5
          11000000 10101000 10000010 00000101

20 bits = 11111111 11111111 11110000 00000000

Network = 192.168.128.0
Host    = 2.5
```

Сетевая часть адреса используется компьютерами с протоколом IPv4 или IPv6 для поиска интерфейса, через который следует отправить пакет, в таблице маршрутизации. Когда хост с протоколом IPv4 или IPv6, на котором включена маршрутизация, получает пакет, предназначенный не для него самого, он пытается сопоставить сетевую часть адреса получателя с сетью в таблице маршрутизации. Если соответствующая запись найдена, пакет отправляется в пункт назначения, указанный в таблице маршрутизации. Если записи не найдены и настроен маршрут по умолчанию, пакет отправляется по маршруту по умолчанию. Если запись не найдена и не настроен маршрут по умолчанию, пакет отбрасывается.

## Настройка интерфейса <a href="#configuring_an_interface" id="configuring_an_interface"></a>

Мы рассмотрим два инструмента, которые можно использовать для настройки сетевого интерфейса: `ifconfig` и `ip`. Программа `ifconfig` по-прежнему широко используется, но считается устаревшим инструментом и может быть недоступна в новых системах.

{% hint style="info" %}
В более новых дистрибутивах Linux установка пакета `net-tools` предоставит вам устаревшие сетевые команды.
{% endhint %}

Прежде чем настраивать интерфейс, необходимо узнать, какие интерфейсы доступны. Это можно сделать несколькими способами. Один из них — использовать опцию `-a` в `ifconfig`:

```bash
$ ifconfig -a
```

Другой способ — использовать `ip`. Иногда вы будете видеть примеры с `ip addr`, `ip a`, а иногда с `ip address`. Они взаимозаменяемы. Официально подкоманда — `ip address`. Это означает, что если вы хотите просмотреть справочную страницу, вы должны использовать `man ip-address` а не `man ip-addr`.

`link`Подкоманда для `ip` отобразит список интерфейсных ссылок, доступных для настройки:

```bash
$ ip link
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN mode DEFAULT group default qlen 1000
    link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00
2: enp0s3: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc pfifo_fast state UP mode DEFAULT group default qlen 1000
    link/ether 08:00:27:54:18:57 brd ff:ff:ff:ff:ff:ff
3: enp0s8: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc pfifo_fast state UP mode DEFAULT group default qlen 1000
    link/ether 08:00:27:ab:11:3e brd ff:ff:ff:ff:ff:ff
```

Если файловая система `sys` подключена, вы также можете вывести список содержимого `/sys/class/net`:

```bash
$ ls /sys/class/net
enp0s3 enp0s8 lo
```

Чтобы настроить интерфейс с помощью `ifconfig`, вы должны войти в систему как пользователь root или использовать такую утилиту, как `sudo` для запуска команды с правами пользователя root. Следуйте приведенному ниже примеру:

```bash
# ifconfig enp1s0 192.168.50.50/24
```

Версия для Linux `ifconfig` отличается гибкостью в отношении того, как вы указываете маску подсети:

<pre class="language-bash"><code class="lang-bash"><strong># ifconfig eth2 192.168.50.50 netmask 255.255.255.0
</strong><strong># ifconfig eth2 192.168.50.50 netmask 0xffffff00
</strong><strong># ifconfig enp0s8 add 2001:db8::10/64
</strong></code></pre>

Обратите внимание, что в IPv6 используется ключевое слово `add`. Если вы не добавите `add` перед адресом IPv6, вы получите сообщение об ошибке.

Следующая команда настраивает интерфейс с помощью `ip`:

<pre class="language-bash"><code class="lang-bash"><strong># ip addr add 192.168.5.5/24 dev enp0s8
</strong><strong># ip addr add 2001:db8::10/64 dev enp0s8
</strong></code></pre>

С помощью `ip` одна и та же команда используется как для IPv4, так и для IPv6.

## **Настройка низкоуровневых параметров**

Команда `ip link` используется для настройки параметров интерфейса или протокола низкого уровня, таких как виртуальные локальные сети, ARP или MTU, а также для отключения интерфейса.

Распространённой задачей для `ip link` является отключение или включение интерфейса. Это можно сделать и с помощью `ifconfig`:

```bash
# ip link set dev enp0s8 down
# ip link show dev enp0s8
3: enp0s8: <BROADCAST,MULTICAST> mtu 1500 qdisc pfifo_fast state DOWN mode DEFAULT group default qlen 1000
    link/ether 08:00:27:ab:11:3e brd ff:ff:ff:ff:ff:ff
# ifconfig enp0s8 up
# ip link show dev enp0s8
3: enp0s8: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc pfifo_fast state UP mode DEFAULT group default qlen 1000
    link/ether 08:00:27:ab:11:3e brd ff:ff:ff:ff:ff:ff
```

Иногда может потребоваться изменить MTU интерфейса. Как и в случае с включением/отключением интерфейсов, это можно сделать с помощью `ifconfig` или `ip link`:

```bash
# ip link set enp0s8 mtu 2000
# ip link show dev enp0s3
2: enp0s3: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 2000 qdisc pfifo_fast state UP mode DEFAULT group default qlen 1000
    link/ether 08:00:27:54:53:59 brd ff:ff:ff:ff:ff:ff
# ifconfig enp0s3 mtu 1500
# ip link show dev enp0s3
2: enp0s3: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc pfifo_fast state UP mode DEFAULT group default qlen 1000
    link/ether 08:00:27:54:53:59 brd ff:ff:ff:ff:ff:ff
```

## Таблица маршрутизации <a href="#the_routing_table" id="the_routing_table"></a>

Для просмотра таблицы маршрутизации можно использовать команды `route`, `netstat -r`, и `ip route`. Если вы хотите изменить маршруты, вам нужно использовать `route` или `ip route`. Ниже приведены примеры просмотра таблицы маршрутизации:

```bash
$ netstat -r
Kernel IP routing table
Destination     Gateway         Genmask         Flags   MSS Window  irtt Iface
default         10.0.2.2        0.0.0.0         UG        0 0          0 enp0s3
10.0.2.0        0.0.0.0         255.255.255.0   U         0 0          0 enp0s3
192.168.150.0   0.0.0.0         255.255.255.0   U         0 0          0 enp0s8
$ ip route
default via 10.0.2.2 dev enp0s3 proto dhcp metric 100
10.0.2.0/24 dev enp0s3 proto kernel scope link src 10.0.2.15 metric 100
192.168.150.0/24 dev enp0s8 proto kernel scope link src 192.168.150.200
$ route
Kernel IP routing table
Destination     Gateway         Genmask         Flags Metric Ref    Use Iface
default         10.0.2.2        0.0.0.0         UG    100    0        0 enp0s3
10.0.2.0        0.0.0.0         255.255.255.0   U     100    0        0 enp0s3
192.168.150.0   0.0.0.0         255.255.255.0   U     0      0        0 enp0s8
```

Обратите внимание, что нет вывода данных для IPv6. Если вы хотите просмотреть таблицу маршрутизации для IPv6, вы должны использовать `route -6`, `netstat -6r`, и `ip -6 route`.

```bash
$ route -6
Kernel IPv6 routing table
Destination                    Next Hop                   Flag Met Ref Use If
2001:db8::/64                  [::]                       U    256 0      0 enp0s8
fe80::/64                      [::]                       U    100 0      0 enp0s3
2002:a00::/24                  [::]                       !n   1024 0      0 lo
[::]/0                         2001:db8::1                UG   1   0      0 enp0s8
localhost/128                  [::]                       Un   0   2     84 lo
2001:db8::10/128               [::]                       Un   0   1      0 lo
fe80::a00:27ff:fe54:5359/128   [::]                       Un   0   1      0 lo
ff00::/8                       [::]                       U    256 1      3 enp0s3
ff00::/8                       [::]                       U    256 1      6 enp0s8
```

Пример `netstat -r6` был опущен, так как его вывод идентичен `route -6`. Некоторые результаты выполнения приведенной выше команды `route` говорят сами за себя. В столбце `Flag` содержится некоторая информация о маршруте. Флаг `U` указывает на то, что маршрут активен. `!` означает отказ от маршрута, то есть маршрут с `!` не будет использоваться. Флаг `n` означает, что маршрут не был кэширован. Ядро поддерживает кэш маршрутов для более быстрого поиска отдельно от всех известных маршрутов. Флаг `G` указывает на шлюз. Столбец `Metric` или `Met` не используется ядром. Он относится к административному расстоянию до цели. Это административное расстояние используется протоколами маршрутизации для определения динамических маршрутов. Столбец `Ref` — это количество ссылок, или число использований маршрута. Как и `Metric`, он не используется ядром Linux. Столбец `Use` показывает количество обращений к маршруту.

В выводе `netstat -r` `MSS` указывает максимальный размер сегмента для TCP-соединений на этом маршруте. В столбце `Window` указан размер окна TCP по умолчанию. В `irtt` указано время передачи пакетов по этому маршруту.

Выходные данные `ip route` и `ip -6 route` выглядят следующим образом:

1. Пункт назначения.
2. Необязательный адрес, за которым следует интерфейс.
3. Протокол маршрутизации, используемый для добавления маршрута.
4. Область действия маршрута. Если этот параметр не указан, то это глобальная область действия или шлюз.
5. Метрика маршрута. Используется протоколами динамической маршрутизации для определения стоимости маршрута. Не используется в большинстве систем.
6. Если это маршрут IPv6, то предпочтение маршрута RFC4191.

Работа с несколькими примерами должна прояснить это:

Пример IPv4

```bash
default via 10.0.2.2 dev enp0s3 proto dhcp metric 100
```

1. Пункт назначения - это маршрут по умолчанию.
2. Адрес шлюза `10.0.2.2` доступен через интерфейс `enp0s3`.
3. Он был добавлен в таблицу маршрутизации DHCP.
4. Область действия была опущена, поэтому она носит глобальный характер.
5. Стоимость маршрута равна `100`.
6. Нет предпочтений в отношении маршрута IPv6.

Пример IPv6

```bash
fc0::/64 dev enp0s8 proto kernel metric 256 pref medium
```

1. Пункт назначения находится `fc0::/64`.
2. Он доступен через интерфейс `enp0s8`.
3. Он был добавлен автоматически ядром.
4. Область действия была опущена, поэтому она носит глобальный характер.
5. Стоимость маршрута равна `256`.
6. У него есть предпочтение IPv6, равное `medium`.

## **Управление Маршрутами**

Маршрутами можно управлять с помощью `route` или `ip route`. Ниже приведён пример добавления и удаления маршрута с помощью команды `route`. При использовании `route` необходимо использовать опцию `-6` для IPv6:

```bash
# ping6 -c 2 2001:db8:1::20
connect: Network is unreachable
# route -6 add 2001:db8:1::/64 gw 2001:db8::3
# ping6 -c 2 2001:db8:1::20
PING 2001:db8:1::20(2001:db8:1::20) 56 data bytes
64 bytes from 2001:db8:1::20: icmp_seq=1 ttl=64 time=0.451 ms
64 bytes from 2001:db8:1::20: icmp_seq=2 ttl=64 time=0.438 ms
# route -6 del 2001:db8:1::/64 gw 2001:db8::3
# ping6 -c 2 2001:db8:1::20
connect: Network is unreachable
```

Ниже приведен тот же пример использования команды `ip route`:

```bash
# ping6 -c 2 2001:db8:1:20
connect: Network is unreachable
# ip route add 2001:db8:1::/64 via 2001:db8::3
# ping6 -c 2 2001:db8:1:20
PING 2001:db8:1::20(2001:db8:1::20) 56 data bytes
64 bytes from 2001:db8:1::20: icmp_seq=2 ttl=64 time=0.529 ms
64 bytes from 2001:db8:1::20: icmp_seq=2 ttl=64 time=0.438 ms
# ip route del 2001:db8:1::/64 via 2001:db8::3
# ping6 -c 2 2001:db8:1::20
connect: Network is unreachable
```

## Краткие сведения <a href="#sec.109.3_01-su" id="sec.109.3_01-su"></a>

Сеть обычно настраивается с помощью сценариев запуска системы или вспомогательного приложения, такого как NetworkManager. В большинстве дистрибутивов есть инструменты, которые редактируют файлы конфигурации сценариев запуска. Для получения подробной информации обратитесь к документации вашего дистрибутива.

Возможность вручную настраивать сеть позволяет более эффективно устранять неполадки. Это полезно в минимальных средах, используемых для таких задач, как восстановление из резервных копий или переход на новое оборудование.

Утилиты, рассмотренные в этом разделе, обладают более широкими возможностями, чем те, что рассматриваются в этом уроке. Чтобы ознакомиться с доступными опциями, стоит просмотреть справочную страницу каждой из них. Команды `ss` и `ip` — это современный способ выполнения задач, в то время как остальные, хотя и широко используются, считаются устаревшими инструментами.

Лучший способ познакомиться с перечисленными инструментами — это практика. Используя компьютер со скромным объёмом оперативной памяти, можно создать виртуальную сетевую лабораторию с помощью виртуальных машин, на которых можно практиковаться. Трёх виртуальных машин достаточно, чтобы освоиться с перечисленными инструментами.

Команды, используемые в этом уроке, включают:

`ifconfig`

Устаревшая утилита, используемая для настройки сетевых интерфейсов и проверки их состояния.

`ip`

Современная и универсальная утилита, используемая для настройки сетевых интерфейсов и анализа их состояния.

`netstat`

Устаревшая команда, используемая для просмотра текущих сетевых подключений и информации о маршруте.

`route`

Устаревшая команда, используемая для просмотра или изменения системной таблицы маршрутизации.

## Ответы на Упражнения с Руководством <a href="#sec.109.3_01-age" id="sec.109.3_01-age"></a>

1.  Какие команды можно использовать для составления списка сетевых интерфейсов?

    Любая из приведенных ниже команд:

    `ip link`, `ifconfig -a`, или `ls /sys/class/net`
2.  Как бы вы временно отключили интерфейс? Как бы вы его снова включили?

    Вы могли бы использовать `ifconfig` или `ip link`:

    Использование `ifconfig`:

    ```bash
    $ ifconfig wlan1 down
    $ ifconfig wlan1 up
    ```

    Использование `ip link`:

    ```bash
    $ ip link set wlan1 down
    $ ip link set wlan1 up
    ```
3. Какая из перечисленных ниже масок подсети является приемлемой для IPv4?
   * `255.252.0.0`
   *   `/24`

       Остальные перечисленные маски недействительны, поскольку они не разделяют адрес на две части: первая часть определяет сеть, а вторая — хост. Левые биты маски всегда будут равны `1`, а правые — `0`.
4.  Какие команды вы можете использовать для проверки вашего маршрута по умолчанию?

    Вы можете использовать `route`, `netstat -r` или `ip route`:

    ```
    $ route
    Kernel IP routing table
    Destination     Gateway         Genmask         Flags Metric Ref    Use Iface
    default         server          0.0.0.0         UG    600    0        0 wlan1
    192.168.1.0     0.0.0.0         255.255.255.0   U     600    0        0 wlan1
    $ netstat -r
    Kernel IP routing table
    Destination     Gateway         Genmask         Flags   MSS Window  irtt Iface
    default         server          0.0.0.0         UG        0 0          0 wlan1
    192.168.1.0     0.0.0.0         255.255.255.0   U         0 0          0 wlan1
    $ ip route
    default via 192.168.1.20 dev wlan1 proto static metric 600
    192.168.1.0/24 dev wlan1 proto kernel scope link src 192.168.1.24 metric 600
    ```
5.  Как бы добавить второй IP-адрес к интерфейсу?

    Вы можете использовать `ip address` или `ifconfig`. Имейте в виду, что `ifconfig` — это устаревший инструмент:

    ```bash
    $ ip addr add 172.16.15.16/16 dev enp0s9 label enp0s9:sub1
    ```

    Часть команды `label enp0s9:sub1` добавляет псевдоним к `enp0s9`. Если вы не используете устаревший `ifconfig` синтаксис, вы можете опустить его. Если вы это сделаете, команда все равно будет работать, но только что добавленный адрес не будет отображаться в выводе `ifconfig`.

    Вы также можете использовать `ifconfig`:

    ```bash
    $ ifconfig enp0s9:sub1 172.16.15.16/16
    ```

## Ответы на Исследовательские упражнения <a href="#sec.109.3_01-aee" id="sec.109.3_01-aee"></a>

1.  Какую подкоманду `ip` можно использовать для настройки тегов vlan?

    `ip link` имеет `vlan` опцию, которую можно использовать. Ниже приведен пример пометки вспомогательного интерфейса vlan 20.

    ```bash
    # ip link add link enp0s9 name enp0s9.20 type vlan id 20
    ```
2.  Как бы вы настроили маршрут по умолчанию?

    Используя `route` или `ip route`:

    ```bash
    # route add default gw 192.168.1.1
    # ip route add default via 192.168.1.1
    ```
3.  Как бы вы получили подробную информацию о команде `ip neighbour`? Что произойдёт, если вы запустите её самостоятельно?

    Прочитав справочную страницу:

    ```
    $ man ip-neigbour
    ```

    Он отображает ваш ARP-кэш:

    ```
    $ ip neighbour
    10.0.2.2 dev enp0s3 lladdr 52:54:00:12:35:02 REACHABLE
    ```
4.  Как вы создадите резервную копию таблицы маршрутизации? Как вы восстановите её?

    Приведенный ниже пример демонстрирует резервное копирование и восстановление таблицы маршрутизации:

    ```bash
    # ip route save > /root/routes/route_backup
    # ip route restore < /root/routes/route_backup
    ```
5.  Какую `ip` подкоманду можно использовать для настройки параметров связующего дерева?

    Подобно управлению настройками vlan, `ip link` можно настроить связующее дерево с помощью `bridge` типа. В примере показано добавление виртуального интерфейса с приоритетом STP 50:

    ```
    # ip link add link enp0s9 name enp0s9.50 type bridge priority 50
    ```
