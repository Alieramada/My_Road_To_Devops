# Урок 9.3.2

## Введение <a href="#sec.109.3_02-in" id="sec.109.3_02-in"></a>

В операционных системах на базе Linux есть множество инструментов для устранения неполадок в сети. В этом уроке мы рассмотрим некоторые из наиболее распространённых. К этому моменту вы уже должны разбираться в OSI или других многоуровневых сетевых моделях, адресации IPv4 или IPv6, а также в основах маршрутизации и коммутации.

Лучший способ проверить подключение к сети — попытаться использовать своё приложение. Если это не помогло, существует множество инструментов для диагностики проблем.

## Тестирование соединений  `ping` <a href="#testing_connections_with_ping" id="testing_connections_with_ping"></a>

Команды `ping` и `ping6` можно использовать для отправки запроса ICMP Echo на адрес IPv4 или IPv6 соответственно. Запрос ICMP Echo отправляет небольшой объём данных на адрес назначения. Если адрес назначения доступен, он отправит ответное сообщение ICMP Echo отправителю с теми же данными, которые были отправлены ему:

```bash
$ ping -c 3 192.168.50.2
PING 192.168.50.2 (192.168.50.2) 56(84) bytes of data.
64 bytes from 192.168.50.2: icmp_seq=1 ttl=64 time=0.525 ms
64 bytes from 192.168.50.2: icmp_seq=2 ttl=64 time=0.419 ms
64 bytes from 192.168.50.2: icmp_seq=3 ttl=64 time=0.449 ms

--- 192.168.50.2 ping statistics ---
3 packets transmitted, 3 received, 0% packet loss, time 2006ms
rtt min/avg/max/mdev = 0.419/0.464/0.525/0.047 ms
```

```bash
$ ping6 -c 3 2001:db8::10
PING 2001:db8::10(2001:db8::10) 56 data bytes
64 bytes from 2001:db8::10: icmp_seq=1 ttl=64 time=0.425 ms
64 bytes from 2001:db8::10: icmp_seq=2 ttl=64 time=0.480 ms
64 bytes from 2001:db8::10: icmp_seq=3 ttl=64 time=0.725 ms

--- 2001:db8::10 ping statistics ---
3 packets transmitted, 3 received, 0% packet loss, time 2000ms
rtt min/avg/max/mdev = 0.425/0.543/0.725/0.131 ms
```

Опция `-c` используется для указания количества отправляемых пакетов. Если вы не укажете эту опцию, `ping` и `ping6` будут продолжать отправлять пакеты до тех пор, пока вы не остановите их, обычно с помощью комбинации клавиш <kbd>Ctrl</kbd>+<kbd>C</kbd>.

Если вы не можете пропинговать хост, это не значит, что вы не можете подключиться к нему. Во многих организациях есть брандмауэры или списки контроля доступа к маршрутизаторам, которые блокируют всё, кроме самого необходимого для функционирования их систем. Это включает в себя запросы и ответы ICMP. Поскольку эти пакеты могут содержать произвольные данные, опытный злоумышленник может использовать их для кражи данных.

## Отслеживание Маршрутов <a href="#tracing_routes" id="tracing_routes"></a>

С помощью программ `traceroute` и `traceroute6` можно показать маршрут, по которому пакет добирается до пункта назначения. Для этого они отправляют несколько пакетов в пункт назначения, увеличивая поле _Time-To-Live_ (TTL) в заголовке IP с каждым последующим пакетом. Каждый маршрутизатор на пути будет отвечать сообщением ICMP о превышении TTL:

```bash
$ traceroute 192.168.1.20
traceroute to 192.168.1.20 (192.168.1.20), 30 hops max, 60 byte packets
 1  10.0.2.2 (10.0.2.2)  0.396 ms  0.171 ms  0.132 ms
 2  192.168.1.20 (192.168.1.20)  2.665 ms  2.573 ms  2.573 ms
$ traceroute 192.168.50.2
traceroute to 192.168.50.2 (192.168.50.2), 30 hops max, 60 byte packets
 1  192.168.50.2 (192.168.50.2)  0.433 ms  0.273 ms  0.171 ms
$ traceroute6 2001:db8::11
traceroute to 2001:db8::11 (2001:db8::11), 30 hops max, 80 byte packets
 1  2001:db8::11 (2001:db8::11)  0.716 ms  0.550 ms  0.641 ms
$ traceroute 2001:db8::11
traceroute to 2001:db8::11 (2001:db8::11), 30 hops max, 80 byte packets
 1  2001:db8::10 (2001:db8::11)  0.617 ms  0.461 ms  0.387 ms
$ traceroute net2.example.net
traceroute to net2.example.net (192.168.50.2), 30 hops max, 60 byte packets
 1  net2.example.net (192.168.50.2)  0.533 ms  0.529 ms  0.504 ms
$ traceroute6 net2.example.net
traceroute to net2.example.net (2001:db8::11), 30 hops max, 80 byte packets
```

По умолчанию `traceroute` отправляет 3 пакета UDP с ненужными данными на порт 33434, увеличивая его каждый раз, когда отправляет пакет. Каждая строка в выводе команды — это интерфейс маршрутизатора, через который проходит пакет. Время, указанное в каждой строке вывода, — это время прохождения каждого пакета в обе стороны. IP-адрес — это адрес рассматриваемого интерфейса маршрутизатора. Если `traceroute` может это сделать, он использует DNS-имя интерфейса маршрутизатора. Иногда вместо времени вы увидите `*` Когда это происходит, это означает, что `traceroute` никогда не получал сообщение о превышении TTL для этого пакета. Если вы начинаете видеть такое сообщение, это часто указывает на то, что последний ответ является последним этапом маршрута.

Если у вас есть доступ к `root`, опция `-I` позволит `traceroute` использовать эхо-запросы ICMP вместо UDP-пакетов. Это часто более эффективно, чем UDP, потому что целевой хост с большей вероятностью ответит на эхо-запрос ICMP, чем на UDP-пакет:

## Поиск MTU С Помощью `tracepath` <a href="#finding_mtus_with_tracepath" id="finding_mtus_with_tracepath"></a>

Команда `tracepath` похожа на `traceroute`. Разница в том, что она отслеживает размеры _максимальной единицы передачи_ (MTU) на пути следования. MTU — это либо заданная настройка сетевого интерфейса, либо аппаратное ограничение на передачу или приём самой большой единицы данных протокола. Программа `tracepath` работает так же, как `traceroute`: она увеличивает TTL с каждым пакетом. Отличие в том, что она отправляет очень большую дейтаграмму UDP. Дейтаграмма почти всегда будет больше, чем MTU устройства с наименьшим MTU на маршруте. Когда пакет достигает этого устройства, оно обычно отвечает пакетом с сообщением о том, что пункт назначения недоступен. В пакете ICMP с сообщением о том, что пункт назначения недоступен, есть поле для MTU канала, по которому он отправил бы пакет, если бы мог. `tracepath` Затем он отправляет все последующие пакеты такого размера:

```bash
$ tracepath 192.168.1.20
 1?: [LOCALHOST]                                         pmtu 1500
 1:  10.0.2.2                                              0.321ms
 1:  10.0.2.2                                              0.110ms
 2:  192.168.1.20                                          2.714ms reached
     Resume: pmtu 1500 hops 2 back 64
```

В отличие от `traceroute`, вы должны явно использовать `tracepath6` для IPv6:

```bash
$ tracepath 2001:db8::11
tracepath: 2001:db8::11: Address family for hostname not supported
$ tracepath6 2001:db8::11
 1?: [LOCALHOST]                        0.027ms pmtu 1500
 1:  net2.example.net                                      0.917ms reached
 1:  net2.example.net                                      0.527ms reached
     Resume: pmtu 1500 hops 1 back 1
```

Результат аналогичен `traceroute`. Преимущество `tracepath` в том, что в последней строке выводится наименьший MTU для всего канала связи. Это может быть полезно при устранении неполадок в соединениях, которые не могут обрабатывать фрагменты.

Как и в случае с предыдущими инструментами для устранения неполадок, оборудование может блокировать ваши пакеты данных.

## Создание произвольных Соединений <a href="#creating_arbitrary_connections" id="creating_arbitrary_connections"></a>

Программа `nc` , известная как netcat, может отправлять или получать произвольные данные по сетевому соединению TCP или UDP. Из приведённых ниже примеров становится понятна её функциональность.

Вот пример настройки прослушивателя на порту `1234`:

```bash
$ nc -l 1234
LPI Example
```

Вывод `LPI Example` появляется после приведённого ниже примера, в котором настраивается отправитель netcat для отправки пакетов на `net2.example.net` на порт `1234`. Опция `-l` используется для указания того, что вы хотите, чтобы `nc` получал данные, а не отправлял их:

```bash
$ nc net2.example.net 1234
LPI Example
```

Нажмите <kbd>Ctrl</kbd>+<kbd>C</kbd> в любой системе, чтобы прервать соединение.

Netcat работает как с IPv4, так и с IPv6-адресами. Он работает как с TCP, так и с UDP. Его можно использовать даже для создания простой удалённой оболочки.

{% hint style="info" %}
Обратите внимание, что не все версии `nc` поддерживают параметр `-e` . Обязательно ознакомьтесь со справочными страницами вашей версии, чтобы получить информацию о безопасности этого параметра, а также альтернативные способы выполнения команд в удалённой системе.
{% endhint %}

```bash
$ hostname
net2
$ nc -u -e /bin/bash -l 1234
```

Опция `-u` предназначена для UDP. `-e` Она указывает netcat отправлять всё, что он получает, на стандартный ввод исполняемого файла, следующего за ним. В этом примере `/bin/bash`.

```bash
$ hostname
net1
$ nc -u net2.example.net 1234
hostname
net2
pwd
/home/emma
```

Обратите внимание, что вывод команды `hostname` совпадает с выводом прослушивающего хоста, а вывод команды `pwd` — с каталогом?

## Просмотр текущих Подключений и Прослушивателей <a href="#viewing_current_connections_and_listeners" id="viewing_current_connections_and_listeners"></a>

Программы `netstat` и `ss` можно использовать для просмотра состояния ваших текущих слушателей и подключений. Как и в случае с `ifconfig`, `netstat` это устаревший инструмент. Обе `netstat` и `ss` имеют схожий вывод и опции. Вот некоторые опции, доступные для обеих программ.:

`-a`

Показывает все сокеты.

`-l`

Показывает прослушивающие сокеты.

`-p`

Показывает процесс, связанный с подключением.

`-n`

Предотвращает поиск имен как для портов, так и для адресов.

`-t`

Показывает TCP-соединения.

`-u`

Показывает UDP-соединения.

В приведённых ниже примерах показан результат работы часто используемого набора параметров для обеих программ:

```bash

tcp6       0      0 :::22                   :::*                    LISTEN      892/sshd
tcp6       0      0 ::1:25                  :::*                    LISTEN      1141/master
udp        0      0 0.0.0.0:68              0.0.0.0:*                           692/dhclient
# ss -tulnp
# ss -tulnp
```

Столбец `Recv-Q` — это количество пакетов, которые сокет получил, но не передал своей программе. Столбец `Send-Q` — это количество пакетов, которые сокет отправил, но которые не были подтверждены получателем. Остальные столбцы говорят сами за себя.

## Краткие сведения <a href="#sec.109.3_02-su" id="sec.109.3_02-su"></a>

Сеть обычно настраивается с помощью сценариев запуска системы или вспомогательного приложения, такого как NetworkManager. В большинстве дистрибутивов есть инструменты, которые редактируют файлы конфигурации сценариев запуска. Для получения подробной информации обратитесь к документации вашего дистрибутива.

Возможность вручную настраивать сеть позволяет более эффективно устранять неполадки. Это полезно в минимальных средах, используемых для таких задач, как восстановление из резервных копий или переход на новое оборудование.

Утилиты, рассмотренные в этом разделе, обладают более широкими возможностями, чем те, что рассматриваются в этом уроке. Чтобы ознакомиться с доступными опциями, стоит просмотреть справочную страницу каждой из них. Команды `ss` и `ip` — это современный способ выполнения задач, в то время как остальные, хотя и широко используются, считаются устаревшими инструментами.

Лучший способ познакомиться с перечисленными инструментами — это практика. Используя компьютер со скромным объёмом оперативной памяти, можно создать виртуальную сетевую лабораторию с помощью виртуальных машин, на которых можно практиковаться. Трёх виртуальных машин достаточно, чтобы освоиться с перечисленными инструментами.

Команды , рассмотренные в этом уроке, включают:

`ping` и `ping6`

Используется для передачи пакетов ICMP на удалённый хост для проверки доступности сетевого подключения.

`traceroute` и `traceroute6`

Используется для отслеживания пути по сети, чтобы определить её связность.

`tracepath` и `tracepath6`

Используется для отслеживания пути по сети, а также для определения размера MTU на маршруте.

`nc`

Используется для установки произвольных соединений в сети для проверки подключения, а также для поиска в сети доступных служб и устройств.

`netstat`

Устаревшая команда, используемая для определения открытых сетевых подключений системы и статистики.

`ss`

Современная команда, используемая для определения открытых сетевых подключений системы и статистики.

## Ответы на Упражнения с Руководством <a href="#sec.109.3_02-age" id="sec.109.3_02-age"></a>

1.  Какие команды вы бы использовали для отправки ICMP-эха `learning.lpi.org`?

    Вы бы использовали `ping` или `ping6`:

    ```bash
    $ ping learning.lpi.org
    ```

    или

    ```bash
    $ ping6 learning.lpi.org
    ```
2.  Как вы могли бы определить маршрут до `8.8.8.8`?

    С помощью команд `tracepath` или `traceroute`.

    ```bash
    $ tracepath 8.8.8.8
    ```

    или

    ```bash
    $ traceroute 8.8.8.8
    ```
3.  Какая команда покажет, прослушивает ли какой-либо процесс TCP-порт 80?

    С `ss`:

    ```bash
    $ ss -ln | grep ":80"
    ```

    С `netstat`:

    ```bash
    $ netstat -ln | grep ":80"
    ```

    Хотя это и не является обязательным требованием для экзамена, вы также можете использовать `lsof`:

    ```bash
    # lsof -Pi:80
    ```
4.  Как вы могли бы определить, какой процесс прослушивает порт?

    Опять же, есть несколько способов сделать это. Вы можете использовать `lsof` так же, как в предыдущем ответе, заменив номер порта. Вы также можете использовать `netstat` или `ss` с опцией `-p`. Помните, что `netstat` считается устаревшим инструментом.

    <pre class="language-bash"><code class="lang-bash"><strong># netstat -lnp | grep «:22»
    </strong></code></pre>

    Те же параметры, которые работают с `netstat`, также работают с `ss`:

    ```bash
    # ss -lnp | grep ":22"
    ```
5.  Как вы могли бы определить максимальный MTU сетевого пути?

    С помощью команды `tracepath`:

    ```
    $ tracepath somehost.example.com
    ```

## Ответы на Исследовательские упражнения <a href="#sec.109.3_02-aee" id="sec.109.3_02-aee"></a>

1.  Как можно использовать netcat для отправки HTTP-запроса на веб-сервер?

    Введите в терминал строку HTTP-запроса, любые заголовки и пустую строку:

    ```bash
    $ nc learning.lpi.org 80
    GET /index.html HTTP/1.1
    HOST: learning.lpi.org

    HTTP/1.1 302 Found
    Location: https://learning.lpi.org:443/index.html
    Date: Wed, 27 May 2020 22:54:46 GMT
    Content-Length: 5
    Content-Type: text/plain; charset=utf-8

    Found
    ```
2. Существует ряд возможных причин. Вот некоторые из них:
   * Удаленный хост не работает.
   * ACL маршрутизатора блокирует ваш ping.
   * Брандмауэр удаленного хостинга блокирует ваш ping.
   * Возможно, вы используете неправильное имя или адрес хостинга.
   * Ваше разрешение имени возвращает неверный адрес.
   * Неправильная конфигурация сети вашего компьютера.
   * Брандмауэр вашего компьютера блокирует это.
   * Неправильная конфигурация сети удаленного хоста.
   * Интерфейс (ы) вашего компьютера отключен.
   * Интерфейс (ы) удаленного компьютера отключен.
   * Сетевой компонент, такой как коммутатор, кабель или маршрутизатор, между вашим компьютером и удалённым устройством больше не работает.
3.  Назовите инструмент, с помощью которого можно отслеживать сетевые пакеты, поступающие на хост Linux или покидающие его.

    Можно использовать как `tcpdump`, так и `wireshark`.
4.  Как вы можете заставить `traceroute` использовать другой интерфейс?

    Используя опцию `-i`:

    ```bash
    $ traceroute -i eth2 learning.lpi.org
    traceroute -i eth2 learning.lpi.org
    traceroute to learning.lpi.org (208.94.166.201), 30 hops max, 60 byte packets
    ...
    ```
5.  Возможно ли для `traceroute` сообщить о MTU?

    Да, с `--mtu` опцией:

    ```bash
    # traceroute -I --mtu  learning.lpi.org
    traceroute to learning.lpi.org (208.94.166.201), 30 hops max, 65000 byte packets
     1  047-132-144-001.res.spectrum.com (47.132.144.1)  9.974 ms F=1500  10.476 ms  4.743 ms
     2  096-034-094-106.biz.spectrum.com (96.34.94.106)  8.697 ms  9.963 ms  10.321 ms
    ...
    ```
