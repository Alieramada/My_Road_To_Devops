## Повышение безопасности аутентификации с помощью теневых паролей <a href="#improve_authentication_security_with_shadow_passwords" id="improve_authentication_security_with_shadow_passwords"></a>

Основные компоненты данных учётной записи пользователя хранятся в файле `/etc/passwd`. Этот файл содержит семь полей: имя пользователя, место для ввода пароля, идентификатор пользователя, идентификатор группы, комментарий (также известный как GECOS), расположение домашнего каталога и оболочка по умолчанию. Простой способ запомнить порядок этих полей — представить процесс входа пользователя в систему: сначала вы вводите имя пользователя и пароль (здесь обычно обозначается `x`). Система сопоставит их с идентификатором пользователя (uid) и идентификатором группы (gid). После ввода комментария или поля GECOS назначается домашний каталог пользователя и, наконец, указывается оболочка по умолчанию.

Хотя в современных системах пароль больше не хранится в файле `/etc/passwd`. Вместо этого поле пароля содержит только `x` в нижнем регистре. Файл `/etc/passwd` должен быть доступен для чтения всем пользователям. Поэтому хранить там пароли не рекомендуется.`x` указывает на то, что зашифрованный (хешированный) пароль фактически хранится в файле `/etc/shadow`. Этот файл не должен быть доступен для чтения всем пользователям.

Настройки пароля настраиваются с помощью команд `passwd` и `chage`. Обе команды изменят запись для пользователя `emma` в файле `/etc/shadow`. Как суперпользователь вы можете установить пароль для пользователя `emma` с помощью следующей команды:

```bash
$ sudo passwd emma
New password:
Retype new password:
passwd: password updated successfully
```

Затем вам дважды будет предложено подтвердить новый пароль.

Чтобы просмотреть время истечения срока действия пароля и другие настройки истечения срока действия пароля для пользователя `emma` используйте:

```bash
$ sudo chage -l emma
Last password change					: Apr 27, 2020
Password expires					: never
Password inactive					: never
Account expires						: never
Minimum number of days between password change		: 0
Maximum number of days between password change		: 99999
Number of days of warning before password expires	: 7
```

Чтобы запретить пользователю `emma` входить в систему, суперпользователь может установить дату истечения срока действия пароля, предшествующую текущей дате. Например, если сегодня 27 марта 2020 года, вы можете установить срок действия пароля пользователя на более раннюю дату:

```bash
$ sudo chage -E 2020-03-26 emma
```

В качестве альтернативы, суперпользователь может использовать:

```bash
$ sudo passwd -l emma
```

чтобы временно заблокировать учётную запись с помощью опции `-l` для `passwd`. Чтобы проверить действие этих изменений, попробуйте войти в учётную запись `emma`:

```bash
$ sudo login emma
Password:
Your account has expired; please contact your system administrator

Authentication failure
```

Чтобы временно запретить всем пользователям, кроме пользователя root, входить в систему, суперпользователь может создать файл с именем `/etc/nologin`. Этот файл может содержать сообщение для пользователей, уведомляющее их о том, почему они не могут войти в систему (например, уведомления о техническом обслуживании системы). Подробнее см. `man 5 nologin`. Примечание. также существует команда `nologin`, которая может использоваться для предотвращения входа в систему, если для пользователя установлена оболочка по умолчанию. Например:

```bash
$ sudo usermod -s /sbin/nologin emma
```

Смотрите `man 8 nologin` для получения более подробной информаци

## Как использовать Superdaemon для прослушивания входящих сетевых подключений <a href="#how_to_use_a_superdaemon_to_listen_for_incoming_network_connections" id="how_to_use_a_superdaemon_to_listen_for_incoming_network_connections"></a>

Сетевые службы, такие как веб-серверы, почтовые серверы и серверы печати, обычно работают как отдельные службы, прослушивающие выделенный сетевой порт. Все эти отдельные службы работают параллельно. В классической системе на базе Sys-V-init каждой из этих служб можно управлять с помощью команды `service`. В современных системах на базе systemd для управления службой используется `systemctl`.

В прежние времена доступность компьютерных ресурсов была гораздо ниже. Запуск множества служб в автономном режиме одновременно не был хорошим вариантом. Вместо этого использовался так называемый Superdaemon, который прослушивал входящие сетевые подключения и запускал соответствующую службу по требованию. Этот метод создания сетевого подключения занимал немного больше времени. Хорошо известными Superdaemon являются `inetd` и `xinetd`. В современных системах на базе systemd аналогичным образом можно использовать модуль `systemd.socket`. В этом разделе мы будем использовать `xinetd` для перехвата подключений к демону `sshd` и запуска этого демона по запросу, чтобы продемонстрировать, как используется Superdaemon.

Перед настройкой службы `xinetd` необходимо выполнить некоторые подготовительные действия. Неважно, используете ли вы систему на базе Debian или Red Hat. Хотя эти инструкции были протестированы на Debian/GNU Linux 9.9, они должны работать в любой современной системе Linux с systemd без каких-либо существенных изменений. Сначала убедитесь, что пакеты `openssh-server` и `xinetd` установлены. Теперь проверьте, работает ли служба SSH:

```bash
$ systemctl status sshd
● ssh.service - OpenBSD Secure Shell server
   Loaded: loaded (/lib/systemd/system/ssh.service; enabled; vendor preset: enabled)
   Active: active (running) since Mon 2020-04-27 09:33:48 EDT; 3h 11min ago
     Docs: man:sshd(8)
           man:sshd_config(5)
  Process: 430 ExecStartPre=/usr/sbin/sshd -t (code=exited, status=0/SUCCESS)
 Main PID: 460 (sshd)
    Tasks: 1 (limit: 1119)
   Memory: 5.3M
   CGroup: /system.slice/ssh.service
           └─460 /usr/sbin/sshd -D
```

Также убедитесь, что служба SSH прослушивает стандартный сетевой порт 22:

```bash
# lsof -i :22
COMMAND  PID USER   FD   TYPE   DEVICE SIZE/OFF NODE NAME
sshd    1194 root    3u  IPv4 16053268      0t0  TCP *:ssh (LISTEN)
sshd    1194 root    4u  IPv6 16053270      0t0  TCP *:ssh (LISTEN)
```

Наконец, остановите службу SSH с помощью:

```bash
$ sudo systemctl stop sshd.service
```

Если вы хотите, чтобы это изменение было постоянным и сохранялось после перезагрузки, используйте `systemctl disable sshd.service`.

Теперь вы можете создать файл конфигурации xinetd `/etc/xinetd.d/ssh` с некоторыми базовыми настройками:

```bash
service ssh
{
	disable		= no
	socket_type	= stream
	protocol	= tcp
	wait		= no
	user		= root
	server		= /usr/sbin/sshd
	server_args 	= -i
	flags		= IPv4
	interface	= 192.168.178.1
}
```

Перезапустите службу xinetd с помощью:

```bash
$ sudo systemctl restart xinetd.service
```

Проверьте, какая служба сейчас прослушивает входящие SSH-соединения.

```bash
$ sudo lsof -i :22
COMMAND   PID USER   FD   TYPE  DEVICE SIZE/OFF NODE NAME
xinetd  24098 root    5u  IPv4 7345141      0t0  TCP 192.168.178.1:ssh (LISTEN)
```

Мы видим, что служба xinetd взяла на себя управление доступом к порту 22.

Вот ещё немного информации о конфигурации `xinetd`: Основной файл конфигурации — `/etc/xinetd.conf`:

```bash
# Simple configuration file for xinetd
#
# Some defaults, and include /etc/xinetd.d/

defaults
{

# Please note that you need a log_type line to be able to use log_on_success
# and log_on_failure. The default is the following :
# log_type = SYSLOG daemon info

}

includedir /etc/xinetd.d
```

Помимо настроек по умолчанию, существует только одна директива для установки каталога включения. В этом каталоге вы можете создать отдельный файл конфигурации для каждой службы, которую вы хотите использовать с `xinetd`. Мы сделали это выше для службы SSH и назвали файл `/etc/xinetd.d/ssh`. Названия файлов конфигурации могут быть любыми, кроме тех, которые содержат точку (`.`) или заканчиваются на тильду (`~`). Но принято называть файл в честь службы, которую вы хотите настроить.

Некоторые файлы конфигурации в `/etc/xinet.d/` каталоге уже предоставлены дистрибутивом:

```bash
$ ls -l /etc/xinetd.d
total 52
-rw-r--r-- 1 root root 640 Feb  5  2018 chargen
-rw-r--r-- 1 root root 313 Feb  5  2018 chargen-udp
-rw-r--r-- 1 root root 502 Apr 11 10:18 daytime
-rw-r--r-- 1 root root 313 Feb  5  2018 daytime-udp
-rw-r--r-- 1 root root 391 Feb  5  2018 discard
-rw-r--r-- 1 root root 312 Feb  5  2018 discard-udp
-rw-r--r-- 1 root root 422 Feb  5  2018 echo
-rw-r--r-- 1 root root 304 Feb  5  2018 echo-udp
-rw-r--r-- 1 root root 312 Feb  5  2018 servers
-rw-r--r-- 1 root root 314 Feb  5  2018 services
-rw-r--r-- 1 root root 569 Feb  5  2018 time
-rw-r--r-- 1 root root 313 Feb  5  2018 time-udp
```

Эти файлы можно использовать в качестве шаблонов в том редком случае, когда вам нужно использовать устаревшие сервисы, такие как `daytime`, очень раннюю версию сервера времени. Все эти файлы-шаблоны содержат директиву `disable = yes`.

Вот ещё немного подробностей о директивах, используемых в примере файла `/etc/xinetd.d/ssh` для ssh выше.

```bash
service ssh
{
	disable		= no
	socket_type	= stream
	protocol	= tcp
	wait		= no
	user		= root
	server		= /usr/sbin/sshd
	server_args 	= -i
	flags		= IPv4
	interface	= 192.168.178.1
}
```

`service`

Перечисляет службы, которыми должен управлять xinetd. Вы можете использовать либо номер порта, например 22, либо имя, сопоставленное с номером порта в `/etc/services` например `ssh`.

`{`

Подробные настройки начинаются с открывающей фигурной скобки.

`disable`

Чтобы активировать эти настройки, установите значение `no`. Если вы хотите временно отключить эту настройку, установите значение `yes`.

`socket_type`

Вы можете выбрать `stream` для TCP-сокетов или `dgram` для UDP-сокетов и многое другое.

`protocol`

Выберите либо TCP, либо UDP.

`wait`

Для TCP-соединений это значение обычно равно `no`.

`user`

Сервис, запущенный в этой строке, будет принадлежать этому пользователю.

`server`

Полный путь к службе, которая должна быть запущена с помощью `xinetd`.

`server_args`

Здесь вы можете добавить параметры для службы. Если служба запускается суперсервером, многим службам требуется специальный параметр. Для SSH это параметр `-i`

`flags`

Вы можете выбрать IPv4, IPv6 и другие.

`interface`

Сетевой интерфейс, которым `xinetd` должен управлять. Примечание: вы также можете выбрать директиву `bind`, которая является синонимом `interface`.

`}`

Завершите работу закрывающей фигурной скобкой.

Преемниками служб, запущенных суперсервером `xinetd`, являются сокетные модули systemd. Настройка сокетного модуля systemd очень проста, поскольку для SSH уже существует предустановленный сокетный модуль systemd. Убедитесь, что службы `xinetd` и SSH не запущены.

Теперь вам просто нужно запустить SSH-сокет unit:

```bash
$ sudo systemctl start ssh.socket
```

Чтобы проверить, какая служба сейчас прослушивает порт 22, мы снова используем `lsof` . Обратите внимание, что для отображения номера порта вместо названия службы в выводе используется опция `-P` :&#x20;

```bash
$ sudo lsof -i :22 -P
COMMAND PID USER   FD   TYPE   DEVICE SIZE/OFF NODE NAME
systemd   1 root   57u  IPv6 14730112      0t0  TCP *:22 (LISTEN)
```

Чтобы завершить этот сеанс, вам нужно попытаться войти на свой сервер с помощью выбранного вами SSH-клиента.

{% hint style="info" %}
В случае, если `systemctl start ssh.socket` не работает с вашим дистрибутивом, попробуйте `systemctl start sshd.socket`.
{% endhint %}

## Проверка служб на наличие ненужных демонов <a href="#checking_services_for_unnecessary_daemons" id="checking_services_for_unnecessary_daemons"></a>

В целях безопасности, а также для управления системными ресурсами важно иметь представление о том, какие службы запущены. Ненужные и неиспользуемые службы следует отключить. Например, если вам не нужно распространять веб-страницы, нет необходимости запускать веб-сервер, такой как Apache или nginx.

В системах на базе SyS-V-init вы можете проверить состояние всех служб следующим образом:

```bash
$ sudo service --status-all
```

Проверьте, нужны ли все службы, перечисленные в выводе команды, и отключите все ненужные службы с помощью (для систем на базе Debian):

```bash
$ sudo update-rc.d SERVICE-NAME remove
```

Или в системах на базе Red Hat:

```bash
$ sudo chkconfig SERVICE-NAME off
```

В современных системах на базе systemd для вывода списка всех запущенных служб можно использовать следующее:

```bash
$ systemctl list-units --state active --type service
```

Затем вы бы отключили каждый ненужный сервисный модуль с помощью:

```bash
$ sudo systemctl disable UNIT --now
```

Эта команда остановит службу и удалит её из списка служб, чтобы она не запускалась при следующей загрузке системы.

Кроме того, для просмотра сетевых служб прослушивания вы можете использовать `netstat` в более старых системах (при условии, что у вас установлен пакет `net-tools`):

```bash
$ netstat -ltu
Active Internet connections (only servers)
Proto Recv-Q Send-Q Local Address           Foreign Address         State
tcp        0      0 0.0.0.0:ssh             0.0.0.0:*               LISTEN
tcp        0      0 localhost:mysql         0.0.0.0:*               LISTEN
tcp6       0      0 [::]:http               [::]:*                  LISTEN
tcp6       0      0 [::]:ssh                [::]:*                  LISTEN
udp        0      0 0.0.0.0:bootpc          0.0.0.0:*
```

Или в современных системах можно использовать эквивалентную команду `ss` (для «служб сокетов»):

```bash
$ ss -ltu
Netid      State         Recv-Q        Send-Q      Local Address:Port           Peer Address:Port
udp        UNCONN        0             0                 0.0.0.0:bootpc              0.0.0.0:*
tcp        LISTEN        0             128               0.0.0.0:ssh                 0.0.0.0:*
tcp        LISTEN        0             80              127.0.0.1:mysql               0.0.0.0:*
tcp        LISTEN        0             128                     *:http                      *:*
tcp        LISTEN        0             128                  [::]:ssh                    [::]:*
```

## TCP -оболочки как своего рода простой брандмауэр <a href="#tcp_wrappers_as_sort_of_a_simple_firewall" id="tcp_wrappers_as_sort_of_a_simple_firewall"></a>

Во времена, когда для Linux не было брандмауэров, для защиты сетевых подключений к хосту использовались TCP-оболочки. В настоящее время многие программы больше не подчиняются TCP-оболочкам. В последних дистрибутивах на базе Red Hat (например, Fedora 29) поддержка TCP-оболочек была полностью удалена. Чтобы поддерживать устаревшие системы Linux, которые всё ещё используют TCP-оболочки, полезно иметь базовые знания об этой технологии.

В качестве базового примера мы снова воспользуемся сервисом SSH. Сервис на нашем примере хоста должен быть доступен только из локальной сети. Сначала мы проверяем, использует ли демон SSH библиотеку `libwrap`, которая поддерживает TCP-оболочки:

```bash
$ ldd /usr/sbin/sshd | grep "libwrap"
        libwrap.so.0 => /lib/x86_64-linux-gnu/libwrap.so.0 (0x00007f91dbec0000)
```

Теперь мы добавим в файл следующую строку `/etc/hosts.deny`:

```bash
sshd: ALL
```

Наконец, мы настраиваем исключение в файле `/etc/hosts.allow` для SSH-подключений из локальной сети:

```bash
sshd: LOCAL
```

Изменения вступают в силу немедленно, нет необходимости перезапускать какую-либо службу. Вы можете проверить это с помощью `ssh` клиента.

1. В каком файле хранятся пароли, а также некоторые настройки безопасности паролей, например, срок действия.
2. Назначение супердемона `xinetd` и способы его запуска и запуска службы `sshd` по требованию.
3. Как проверить, какие сетевые службы запущены и как отключить ненужные службы.
4. Использовние TCP-оболочки как своего рода простого брандмауэра.

Команды, используемые в лаборатории, и упражнения:

`chage`

Измените возраст пароля пользователя.

`chkconfig`

Классическая команда, изначально использовавшаяся в системах на базе Red Hat для настройки запуска службы при загрузке.

`netstat`

Классическая утилита (теперь в пакете `net-tools`), которая отображает демоны, имеющие доступ к сетевым портам в системе, и их использование.

`nologin`

Команда, которую можно использовать вместо оболочки пользователя, чтобы предотвратить его вход в систему.

`passwd`

Используется для создания или изменения пароля пользователя.

`service`

Более старый способ управления состоянием демона, например, остановка или запуск службы.

`ss`

Современный аналог `netstat`, но также отображает больше информации о различных сокетах, используемых в системе.

`systemctl`

Команда системного управления, используемая для контроля различных аспектов работы служб и сокетов на компьютере с помощью systemd.

`update-rc.d`

Классическая команда, аналогичная `chkconfig` и позволяющая включить или отключить запуск службы при загрузке в дистрибутивах на базе Debian.

`xinetd`

Супердемон, который может управлять доступом к сетевой службе по требованию, таким образом оставляя службу неактивной до тех пор, пока она не будет вызвана для выполнения какой-либо задачи.

## Ответы на Упражнения с Руководством <a href="#sec.110.2_01-age" id="sec.110.2_01-age"></a>

1.  Как можно разблокировать ранее заблокированную учетную запись `emma`?

    Суперпользователь может запустить `passwd -u emma`, чтобы разблокировать учетную запись.
2.  Ранее для учётной записи `emma` был установлен срок действия. Как можно установить срок действия `never`?

    Суперпользователь может использовать `chage -E -1 emma` для установки бессрочного срока действия. Этот параметр можно проверить с помощью `chage -l emma`.
3.  Представьте, что служба печати CUPS, обрабатывающая задания на печать, не нужна на вашем сервере. Как вы можете навсегда отключить эту службу? Как вы можете проверить, что соответствующий порт больше не активен?

    Как проблема с суперпользователем

    ```bash
    systemctl disable cups.service --now
    ```

    Теперь вы можете проверить

    ```bash
    netstat -l | grep «:ipp» или «ss -l | grep «:ipp»
    ```
4.  Вы установили веб-сервер nginx. Как проверить, поддерживает ли nginx TCP-оболочки?

    Команда

    ```bash
    ldd /usr/sbin/nginx | grep «libwrap»
    ```

    покажет запись на случай, если nginx поддерживает TCP-оболочки.

## Ответы на Исследовательские упражнения <a href="#sec.110.2_01-aee" id="sec.110.2_01-aee"></a>

1.  Проверьте, не мешает ли наличие файла `/etc/nologin` входу пользователя `root` в систему?

    Пользователь `root` по-прежнему может войти в систему.
2.  Препятствует ли наличие файла `/etc/nologin` входу без пароля с помощью SSH-ключей?

    Да, также запрещен вход в систему без пароля.
3.  Что происходит при входе в систему, когда файл `/etc/nologin` содержит только эту строку текста `login currently is not possible`.

    Будет показано сообщение `login currently is not possible`, и вход в систему будет запрещен.
4.  Может ли обычный пользователь `emma` получить информацию о пользователе `root`, содержащуюся в файле `/etc/passwd`, например, с помощью команды `grep root /etc/passwd`?

    Да, потому что у всех пользователей есть разрешение на чтение этого файла.
5.  Может ли обычный пользователь `emma` получить информацию о своём хешированном пароле, содержащуюся в файле `/etc/shadow` с помощью команды `grep -i emma /etc/shadow`?

    Нет, потому что обычные пользователи не имеют прав на чтение этого файла.
6.  Какие шаги необходимо предпринять, чтобы включить и проверить работу древнего daytime сервиса, обрабатываемого xinetd? Обратите внимание, что это всего лишь ознакомительное упражнение, не делайте этого в рабочей среде.

    Сначала измените файл `/etc/xinetd.d/daytime` и установите директиву `disable = no`. Затем перезапустите службу xinetd `systemctl restart xinetd.service` (или `service xinetd restart` в системах с SyS-V-Init). Теперь вы можете проверить, работает ли `nc localhost daytime`. Вместо `nc` вы также можете использовать `netcat`.
