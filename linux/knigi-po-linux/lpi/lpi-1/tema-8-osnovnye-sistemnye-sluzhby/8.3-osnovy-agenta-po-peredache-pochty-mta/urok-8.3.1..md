# Урок 8.3.1.

## Введение <a href="#sec.108.3_01-in" id="sec.108.3_01-in"></a>

В Unix-подобных операционных системах, таких как Linux, у каждого пользователя есть свой _почтовый ящик_: специальное место в файловой системе, недоступное для других пользователей, кроме root, где хранятся личные сообщения электронной почты пользователя. Новые входящие сообщения добавляются в почтовый ящик пользователя _агентом передачи почты_ (MTA). MTA — это программа, работающая как системная служба, которая собирает сообщения, отправленные другими локальными учётными записями, а также сообщения, полученные из сети и отправленные удалёнными учётными записями пользователей.

Тот же MTA также отвечает за отправку сообщений в сеть, если адрес получателя относится к удалённой учётной записи. Для этого он использует расположение в файловой системе в качестве _исходящего почтового ящика_ для всех пользователей системы: как только пользователь помещает новое сообщение в исходящий почтовый ящик, MTA определяет целевой сетевой узел по доменному имени, указанному в адресе электронной почты получателя, — части после знака `@` — и затем пытается передать сообщение удалённому MTA с помощью _простого протокола передачи почты_ (SMTP). Протокол SMTP был разработан с учётом ненадёжных сетей, поэтому он попытается установить альтернативные маршруты доставки, если основной узел назначения недоступен.

## Локальный и удаленный MTA <a href="#sec.108.3_01-lra" id="sec.108.3_01-lra"></a>

Традиционные учётные записи пользователей на компьютерах, подключённых к сети, представляют собой простейший сценарий обмена электронной почтой, при котором на каждом сетевом узле работает собственный демон MTA. Для отправки и получения электронных писем не требуется никакого другого программного обеспечения, кроме MTA. Однако на практике чаще используется удалённая учётная запись электронной почты без активного локального сервиса MTA (т. е. вместо этого используется приложение-клиент электронной почты для доступа к удалённой учётной записи).

В отличие от локальных учётных записей, удалённая учётная запись электронной почты, также называемая _удалённым почтовым ящиком_, требует аутентификации пользователя для предоставления доступа к почтовому ящику пользователя и удалённому MTA (в данном случае просто _SMTP-серверу_). В то время как пользователь, взаимодействующий с локальным почтовым ящиком и MTA, уже идентифицирован системой, удалённая система должна подтвердить личность пользователя, прежде чем обрабатывать его сообщения с помощью IMAP или POP3.

{% hint style="info" %}
В настоящее время наиболее распространённым способом отправки и получения электронной почты является использование учётной записи на удалённом сервере, например, централизованного почтового сервера компании, на котором хранятся учётные записи всех сотрудников, или личного почтового сервиса, такого как _Gmail_ от Google. Вместо того, чтобы собирать сообщения, отправленные локально, приложение для работы с электронной почтой подключается к удалённому почтовому ящику и извлекает сообщения оттуда. Для извлечения сообщений с удалённого сервера обычно используются протоколы POP3 и IMAP, но могут применяться и другие нестандартные протоколы.
{% endhint %}

Когда демон MTA работает в локальной системе, локальные пользователи могут отправлять электронные письма другим локальным пользователям или пользователям на удалённом компьютере при условии, что в их системе также есть служба MTA, принимающая сетевые подключения. Порт TCP 25 является стандартным портом для SMTP-связи, но могут использоваться и другие порты в зависимости от используемой схемы аутентификации и/или шифрования (если они используются).

Если не рассматривать топологии, включающие доступ к удалённым почтовым ящикам, сеть обмена электронной почтой между обычными учётными записями пользователей Linux может быть реализована при условии, что на всех узлах сети есть активный MTA, способный выполнять следующие задачи:

* Поддерживайте очередь исходящих сообщений для отправки. Для каждого сообщения в очереди локальный MTA определяет MTA получателя по адресу получателя.
* Общайтесь с удалёнными демонами MTA с помощью SMTP. Локальный MTA должен иметь возможность использовать протокол передачи почты (SMTP) через стек TCP/IP для получения, отправки и перенаправления сообщений от/к другим удалённым демонам MTA.
* Для каждой локальной учётной записи создайте отдельный почтовый ящик. MTA обычно сохраняет сообщения в формате _mbox_: в одном текстовом файле последовательно хранятся все сообщения электронной почты.

Обычно в качестве местоположения в адресах электронной почты указывается доменное имя, например `lpi.org` в `info@lpi.org`. В этом случае MTA отправителя запрашивает у DNS-сервера соответствующую запись MX. Запись MX в DNS содержит IP-адрес MTA, обрабатывающего электронную почту для этого домена. Если для одного и того же домена в DNS указано несколько записей MX, MTA должен попытаться связаться с ними в соответствии с их приоритетом. Если в адресе получателя не указано доменное имя или у домена нет записи MX, то часть после символа `@` будет рассматриваться как хост MTA получателя.

Необходимо учитывать аспекты безопасности, если хосты MTA будут доступны хостам в Интернете. Например, неизвестный пользователь может использовать локальный MTA, чтобы выдать себя за другого пользователя и отправлять потенциально вредоносные электронные письма. MTA, который слепо пересылает электронные письма, называется _открытым ретранслятором_, если его можно использовать в качестве посредника для сокрытия истинного отправителя сообщения. Чтобы предотвратить такое злоупотребление, рекомендуется принимать подключения только от авторизованных доменов и внедрить безопасную схему аутентификации.

Кроме того, существует множество различных реализаций MTA для Linux, каждая из которых ориентирована на определённые аспекты, такие как совместимость, производительность, безопасность и т. д. Тем не менее, все MTA следуют одним и тем же основным принципам и предоставляют схожие функции.

## MTA для Linux <a href="#sec.108.3_01-lmta" id="sec.108.3_01-lmta"></a>

Традиционным MTA, доступным для систем Linux, является _Sendmail_ — очень гибкий MTA общего назначения, используемый во многих Unix-подобных операционных системах. Среди других распространённых MTA — _Postfix_, _qmail_ и _Exim_. Основная причина, по которой стоит выбрать альтернативный MTA, заключается в том, что так будет проще реализовать расширенные функции, поскольку настройка пользовательских почтовых серверов в Sendmail может оказаться сложной задачей. Кроме того, в каждом дистрибутиве может быть свой предпочтительный MTA с предустановленными настройками, подходящими для большинства распространённых конфигураций. Все MTA предназначены для замены Sendmail, поэтому все приложения, совместимые с Sendmail, должны работать независимо от того, какой MTA используется.

Если MTA работает, но не принимает сетевые подключения, он сможет доставлять сообщения электронной почты только на локальный компьютер. Для `sendmail` MTA необходимо изменить `/etc/mail/sendmail.mc` файл, чтобы он принимал нелокальные подключения. Для этого нужно изменить запись



```
DAEMON_OPTIONS(`Port=smtp,Addr=127.0.0.1, Name=MTA')dnl
```

Необходимо изменить его на правильный сетевой адрес и перезапустить службу. Некоторые дистрибутивы Linux, например Debian, могут предлагать инструменты для настройки, которые помогут запустить почтовый сервер с предустановленным набором часто используемых функций.

{% hint style="info" %}
\
Из-за проблем с безопасностью в большинстве дистрибутивов Linux MTA по умолчанию не устанавливается. Чтобы протестировать примеры, приведённые в этом уроке, убедитесь, что на каждом компьютере запущен MTA и что он принимает соединения на TCP-порту 25. В целях безопасности во время тестирования эти системы не должны принимать входящие соединения из общедоступного интернета.
{% endhint %}

Как только MTA запускается и начинает принимать соединения из сети, новые сообщения электронной почты передаются ему с помощью команд SMTP, которые отправляются через TCP-соединение. Команду `nc` — сетевую утилиту, которая считывает и записывает общие данные в сети, — можно использовать для отправки команд SMTP непосредственно в MTA. Если команда `nc` недоступна, она будет установлена вместе с пакетом _ncat_ или _nmap-ncat_, в зависимости от используемой системы управления пакетами. Запись команд SMTP непосредственно в MTA поможет вам лучше понять протокол и другие общие концепции электронной почты, а также диагностировать проблемы в процессе доставки почты.

Если, например, пользователь `emma` на хосте `lab1.campus` хочет отправить сообщение пользователю `dave` на хосте `lab2.campus`, он может использовать команду `nc` для прямого подключения к MTA `lab2.campus` при условии, что он прослушивает TCP-порт 25:

```
$ nc lab2.campus 25
220 lab2.campus ESMTP Sendmail 8.15.2/8.15.2; Sat, 16 Nov 2019 00:16:07 GMT
HELO lab1.campus
250 lab2.campus Hello lab1.campus [10.0.3.134], pleased to meet you
MAIL FROM: emma@lab1.campus
250 2.1.0 emma@lab1.campus... Sender ok
RCPT TO: dave@lab2.campus
250 2.1.5 dave@lab2.campus... Recipient ok
DATA
354 Enter mail, end with "." on a line by itself
Subject: Recipient MTA Test

Hi Dave, this is a test for your MTA.
.
250 2.0.0 xAG0G7Y0000595 Message accepted for delivery
QUIT
221 2.0.0 lab2.campus closing connection
```

Как только соединение установлено, удалённый MTA идентифицирует себя и становится готовым к приёму команд SMTP. Первая команда SMTP в примере, `HELO lab1.campus` указывает `lab1.campus` в качестве инициатора обмена. Следующие две команды, `MAIL FROM: emma@lab1.campus` и `RCPT TO: dave@lab2.campus`, указывают отправителя и получателя. Собственно электронное письмо начинается после команды `DATA` и заканчивается точкой в отдельной строке. Чтобы добавить в электронное письмо поле `subject`, оно должно находиться в первой строке после команды `DATA` как показано в примере. Если используется поле темы, между ним и содержимым письма должна быть пустая строка. Команда `QUIT` завершает соединение с MTA на хосте `lab2.campus`.

На хосте `lab2.campus` пользователь `dave` получит сообщение, аналогичное `You have new mail in /var/spool/mail/dave` сразу после входа в сеанс командной строки. Этот файл будет содержать исходное электронное письмо, отправленное `emma` пользователем, а также заголовки, добавленные MTA:

```
$ cat /var/spool/mail/dave
From emma@lab1.campus  Sat Nov 16 00:19:13 2019
Return-Path: <emma@lab1.campus>
Received: from lab1.campus (lab1.campus [10.0.3.134])
	by lab2.campus (8.15.2/8.15.2) with SMTP id xAG0G7Y0000595
	for dave@lab2.campus; Sat, 16 Nov 2019 00:17:06 GMT
Date: Sat, 16 Nov 2019 00:16:07 GMT
From: emma@lab1.campus
Message-Id: <201911160017.xAG0G7Y0000595@lab2.campus>
Subject: Recipient MTA Test

Hi Dave, this is a test for your MTA.
```
