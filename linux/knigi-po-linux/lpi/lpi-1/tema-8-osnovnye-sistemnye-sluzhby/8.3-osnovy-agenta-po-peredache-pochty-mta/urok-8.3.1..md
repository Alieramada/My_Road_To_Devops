# Урок 8.3.1.

## Введение <a href="#sec.108.3_01-in" id="sec.108.3_01-in"></a>

В Unix-подобных операционных системах, таких как Linux, у каждого пользователя есть свой _почтовый ящик_: специальное место в файловой системе, недоступное для других пользователей, кроме root, где хранятся личные сообщения электронной почты пользователя. Новые входящие сообщения добавляются в почтовый ящик пользователя _агентом передачи почты_ (MTA). MTA — это программа, работающая как системная служба, которая собирает сообщения, отправленные другими локальными учётными записями, а также сообщения, полученные из сети и отправленные удалёнными учётными записями пользователей.

Тот же MTA также отвечает за отправку сообщений в сеть, если адрес получателя относится к удалённой учётной записи. Для этого он использует расположение в файловой системе в качестве _исходящего почтового ящика_ для всех пользователей системы: как только пользователь помещает новое сообщение в исходящий почтовый ящик, MTA определяет целевой сетевой узел по доменному имени, указанному в адресе электронной почты получателя, — части после знака `@` — и затем пытается передать сообщение удалённому MTA с помощью _простого протокола передачи почты_ (SMTP). Протокол SMTP был разработан с учётом ненадёжных сетей, поэтому он попытается установить альтернативные маршруты доставки, если основной узел назначения недоступен.

## Локальный и удаленный MTA <a href="#sec.108.3_01-lra" id="sec.108.3_01-lra"></a>

Традиционные учётные записи пользователей на компьютерах, подключённых к сети, представляют собой простейший сценарий обмена электронной почтой, при котором на каждом сетевом узле работает собственный демон MTA. Для отправки и получения электронных писем не требуется никакого другого программного обеспечения, кроме MTA. Однако на практике чаще используется удалённая учётная запись электронной почты без активного локального сервиса MTA (т. е. вместо этого используется приложение-клиент электронной почты для доступа к удалённой учётной записи).

В отличие от локальных учётных записей, удалённая учётная запись электронной почты, также называемая _удалённым почтовым ящиком_, требует аутентификации пользователя для предоставления доступа к почтовому ящику пользователя и удалённому MTA (в данном случае просто _SMTP-серверу_). В то время как пользователь, взаимодействующий с локальным почтовым ящиком и MTA, уже идентифицирован системой, удалённая система должна подтвердить личность пользователя, прежде чем обрабатывать его сообщения с помощью IMAP или POP3.

{% hint style="info" %}
В настоящее время наиболее распространённым способом отправки и получения электронной почты является использование учётной записи на удалённом сервере, например, централизованного почтового сервера компании, на котором хранятся учётные записи всех сотрудников, или личного почтового сервиса, такого как _Gmail_ от Google. Вместо того, чтобы собирать сообщения, отправленные локально, приложение для работы с электронной почтой подключается к удалённому почтовому ящику и извлекает сообщения оттуда. Для извлечения сообщений с удалённого сервера обычно используются протоколы POP3 и IMAP, но могут применяться и другие нестандартные протоколы.
{% endhint %}

Когда демон MTA работает в локальной системе, локальные пользователи могут отправлять электронные письма другим локальным пользователям или пользователям на удалённом компьютере при условии, что в их системе также есть служба MTA, принимающая сетевые подключения. Порт TCP 25 является стандартным портом для SMTP-связи, но могут использоваться и другие порты в зависимости от используемой схемы аутентификации и/или шифрования (если они используются).

Если не рассматривать топологии, включающие доступ к удалённым почтовым ящикам, сеть обмена электронной почтой между обычными учётными записями пользователей Linux может быть реализована при условии, что на всех узлах сети есть активный MTA, способный выполнять следующие задачи:

* Поддерживайте очередь исходящих сообщений для отправки. Для каждого сообщения в очереди локальный MTA определяет MTA получателя по адресу получателя.
* Общайтесь с удалёнными демонами MTA с помощью SMTP. Локальный MTA должен иметь возможность использовать протокол передачи почты (SMTP) через стек TCP/IP для получения, отправки и перенаправления сообщений от/к другим удалённым демонам MTA.
* Для каждой локальной учётной записи создайте отдельный почтовый ящик. MTA обычно сохраняет сообщения в формате _mbox_: в одном текстовом файле последовательно хранятся все сообщения электронной почты.

Обычно в качестве местоположения в адресах электронной почты указывается доменное имя, например `lpi.org` в `info@lpi.org`. В этом случае MTA отправителя запрашивает у DNS-сервера соответствующую запись MX. Запись MX в DNS содержит IP-адрес MTA, обрабатывающего электронную почту для этого домена. Если для одного и того же домена в DNS указано несколько записей MX, MTA должен попытаться связаться с ними в соответствии с их приоритетом. Если в адресе получателя не указано доменное имя или у домена нет записи MX, то часть после символа `@` будет рассматриваться как хост MTA получателя.

Необходимо учитывать аспекты безопасности, если хосты MTA будут доступны хостам в Интернете. Например, неизвестный пользователь может использовать локальный MTA, чтобы выдать себя за другого пользователя и отправлять потенциально вредоносные электронные письма. MTA, который слепо пересылает электронные письма, называется _открытым ретранслятором_, если его можно использовать в качестве посредника для сокрытия истинного отправителя сообщения. Чтобы предотвратить такое злоупотребление, рекомендуется принимать подключения только от авторизованных доменов и внедрить безопасную схему аутентификации.

Кроме того, существует множество различных реализаций MTA для Linux, каждая из которых ориентирована на определённые аспекты, такие как совместимость, производительность, безопасность и т. д. Тем не менее, все MTA следуют одним и тем же основным принципам и предоставляют схожие функции.

## MTA для Linux <a href="#sec.108.3_01-lmta" id="sec.108.3_01-lmta"></a>

Традиционным MTA, доступным для систем Linux, является _Sendmail_ — очень гибкий MTA общего назначения, используемый во многих Unix-подобных операционных системах. Среди других распространённых MTA — _Postfix_, _qmail_ и _Exim_. Основная причина, по которой стоит выбрать альтернативный MTA, заключается в том, что так будет проще реализовать расширенные функции, поскольку настройка пользовательских почтовых серверов в Sendmail может оказаться сложной задачей. Кроме того, в каждом дистрибутиве может быть свой предпочтительный MTA с предустановленными настройками, подходящими для большинства распространённых конфигураций. Все MTA предназначены для замены Sendmail, поэтому все приложения, совместимые с Sendmail, должны работать независимо от того, какой MTA используется.

Если MTA работает, но не принимает сетевые подключения, он сможет доставлять сообщения электронной почты только на локальный компьютер. Для `sendmail` MTA необходимо изменить `/etc/mail/sendmail.mc` файл, чтобы он принимал нелокальные подключения. Для этого нужно изменить запись



```
DAEMON_OPTIONS(`Port=smtp,Addr=127.0.0.1, Name=MTA')dnl
```

Необходимо изменить его на правильный сетевой адрес и перезапустить службу. Некоторые дистрибутивы Linux, например Debian, могут предлагать инструменты для настройки, которые помогут запустить почтовый сервер с предустановленным набором часто используемых функций.

{% hint style="info" %}
\
Из-за проблем с безопасностью в большинстве дистрибутивов Linux MTA по умолчанию не устанавливается. Чтобы протестировать примеры, приведённые в этом уроке, убедитесь, что на каждом компьютере запущен MTA и что он принимает соединения на TCP-порту 25. В целях безопасности во время тестирования эти системы не должны принимать входящие соединения из общедоступного интернета.
{% endhint %}

Как только MTA запускается и начинает принимать соединения из сети, новые сообщения электронной почты передаются ему с помощью команд SMTP, которые отправляются через TCP-соединение. Команду `nc` — сетевую утилиту, которая считывает и записывает общие данные в сети, — можно использовать для отправки команд SMTP непосредственно в MTA. Если команда `nc` недоступна, она будет установлена вместе с пакетом _ncat_ или _nmap-ncat_, в зависимости от используемой системы управления пакетами. Запись команд SMTP непосредственно в MTA поможет вам лучше понять протокол и другие общие концепции электронной почты, а также диагностировать проблемы в процессе доставки почты.

Если, например, пользователь `emma` на хосте `lab1.campus` хочет отправить сообщение пользователю `dave` на хосте `lab2.campus`, он может использовать команду `nc` для прямого подключения к MTA `lab2.campus` при условии, что он прослушивает TCP-порт 25:

```
$ nc lab2.campus 25
220 lab2.campus ESMTP Sendmail 8.15.2/8.15.2; Sat, 16 Nov 2019 00:16:07 GMT
HELO lab1.campus
250 lab2.campus Hello lab1.campus [10.0.3.134], pleased to meet you
MAIL FROM: emma@lab1.campus
250 2.1.0 emma@lab1.campus... Sender ok
RCPT TO: dave@lab2.campus
250 2.1.5 dave@lab2.campus... Recipient ok
DATA
354 Enter mail, end with "." on a line by itself
Subject: Recipient MTA Test

Hi Dave, this is a test for your MTA.
.
250 2.0.0 xAG0G7Y0000595 Message accepted for delivery
QUIT
221 2.0.0 lab2.campus closing connection
```

Как только соединение установлено, удалённый MTA идентифицирует себя и становится готовым к приёму команд SMTP. Первая команда SMTP в примере, `HELO lab1.campus` указывает `lab1.campus` в качестве инициатора обмена. Следующие две команды, `MAIL FROM: emma@lab1.campus` и `RCPT TO: dave@lab2.campus`, указывают отправителя и получателя. Собственно электронное письмо начинается после команды `DATA` и заканчивается точкой в отдельной строке. Чтобы добавить в электронное письмо поле `subject`, оно должно находиться в первой строке после команды `DATA` как показано в примере. Если используется поле темы, между ним и содержимым письма должна быть пустая строка. Команда `QUIT` завершает соединение с MTA на хосте `lab2.campus`.

На хосте `lab2.campus` пользователь `dave` получит сообщение, аналогичное `You have new mail in /var/spool/mail/dave` сразу после входа в сеанс командной строки. Этот файл будет содержать исходное электронное письмо, отправленное `emma` пользователем, а также заголовки, добавленные MTA:

```
$ cat /var/spool/mail/dave
From emma@lab1.campus  Sat Nov 16 00:19:13 2019
Return-Path: <emma@lab1.campus>
Received: from lab1.campus (lab1.campus [10.0.3.134])
	by lab2.campus (8.15.2/8.15.2) with SMTP id xAG0G7Y0000595
	for dave@lab2.campus; Sat, 16 Nov 2019 00:17:06 GMT
Date: Sat, 16 Nov 2019 00:16:07 GMT
From: emma@lab1.campus
Message-Id: <201911160017.xAG0G7Y0000595@lab2.campus>
Subject: Recipient MTA Test

Hi Dave, this is a test for your MTA.
```

Заголовок `Received:` показывает, что сообщение от `lab1.campus` было получено напрямую `lab2.campus`. По умолчанию MTA принимают только сообщения для локальных получателей. Если пользователь `emma` попытается отправить электронное письмо пользователю `henry` на хосте `lab3.campus`, но будет использовать `lab2.campus` MTA вместо `lab3.campus` MTA, то, скорее всего, возникнет следующая ошибка:

```
$ nc lab2.campus 25
220 lab2.campus ESMTP Sendmail 8.15.2/8.15.2; Sat, 16 Nov 2019 00:31:44 GMT
HELO lab1.campus
250 lab2.campus Hello lab1.campus [10.0.3.134], pleased to meet you
MAIL FROM: emma@lab1.campus
250 2.1.0 emma@lab1.campus... Sender ok
RCPT TO: henry@lab3.campus
550 5.7.1 henry@lab3.campus... Relaying denied
```

Номера ответов SMTP, начинающиеся с 5, например сообщение `Relaying denied`, указывают на ошибку. Бывают ситуации, когда ретрансляция желательна, например, когда хосты, отправляющие и получающие электронные письма, не подключены постоянно: промежуточный MTA может быть настроен на приём электронных писем, предназначенных для других хостов, и выступать в качестве _ретрансляционного_ SMTP-сервера, который может пересылать сообщения между MTA.

Возможность направлять трафик электронной почты через промежуточные SMTP-серверы препятствует попыткам прямого подключения к хосту, указанному в адресе электронной почты получателя, как показано в предыдущих примерах. Кроме того, в адресе электронной почты часто указывается доменное имя (после `@`), поэтому фактическое имя соответствующего хоста MTA необходимо получать через DNS. Поэтому рекомендуется делегировать задачу определения соответствующего хоста назначения локальному MTA или удалённому SMTP-серверу при использовании удалённых почтовых ящиков.

Sendmail предоставляет команду `sendmail` для выполнения многих операций, связанных с электронной почтой, в том числе для помощи в составлении новых сообщений. Он также требует от пользователя ввода заголовков электронной почты вручную, но в более удобной форме, чем при непосредственном использовании команд SMTP. Таким образом, более подходящим способом для пользователя `emma@lab1.campus` отправить электронное письмо `dave@lab2.campus` будет:

```
$ sendmail dave@lab2.campus
From: emma@lab1.campus
To: dave@lab2.campus
Subject: Sender MTA Test

Hi Dave, this is a test for my MTA.
.
```

И снова точка в конце строки завершает сообщение. Сообщение должно быть немедленно отправлено получателю, если только локальный MTA не смог связаться с удалённым MTA. Команда `mailq`, если она выполняется от имени пользователя root, покажет все недоставленные сообщения. Если, например, MTA по адресу `lab2.campus` не ответил, то команда `mailq` выведет список недоставленных сообщений и причину сбоя:

```
# mailq
		/var/spool/mqueue (1 request)
-----Q-ID----- --Size-- -----Q-Time----- ------------Sender/Recipient-----------
xAIK3D9S000453       36 Mon Nov 18 20:03 <emma@lab1.campus>
                 (Deferred: Connection refused by lab2.campus.)
					 <dave@lab2.campus>
		Total requests: 1
```

По умолчанию место назначения для исходящей очереди — `/var/spool/mqueue/`, но разные MTA могут использовать разные места в каталоге `/var/spool/`. Например, Postfix создаст дерево каталогов в `/var/spool/postfix/` для управления очередью. Команда `mailq` эквивалентна `sendmail -bp`, и они должны присутствовать независимо от MTA, установленного в системе. Для обеспечения обратной совместимости большинство MTA предоставляют эти традиционные команды для управления почтой.

Если основной хост назначения электронной почты, указанный в DNS-записи MX для домена, недоступен, MTA попытается связаться с хостами с более низким приоритетом (если они указаны). Если ни один из них не доступен, сообщение останется в локальной очереди исходящей почты и будет отправлено позже. Если это настроено, MTA может периодически проверять доступность удаленных хостов и предпринимать новую попытку доставки. При использовании MTA, совместимого с Sendmail, новая попытка будет предпринята немедленно с помощью команды `sendmail -q`.

Sendmail будет сохранять входящие сообщения в файле, названном в честь владельца соответствующего почтового ящика, например `/var/spool/mail/dave`. Другие MTA, например Postfix, могут сохранять входящие сообщения электронной почты в таких местах, как `/var/mail/dave`, но содержимое файла будет таким же. В этом примере для составления сообщения на хосте отправителя использовалась команда `sendmail`, поэтому в исходных заголовках сообщения видно, что оно прошло дополнительные этапы, прежде чем попасть в конечный пункт назначения:

```
$ cat /var/spool/mail/dave
From emma@lab1.campus  Mon Nov 18 20:07:39 2019
Return-Path: <emma@lab1.campus>
Received: from lab1.campus (lab1.campus [10.0.3.134])
	by lab2.campus (8.15.2/8.15.2) with ESMTPS id xAIK7clC000432
	(version=TLSv1.3 cipher=TLS_AES_256_GCM_SHA384 bits=256 verify=NOT)
	for <dave@lab2.campus>; Mon, 18 Nov 2019 20:07:38 GMT
Received: from lab1.campus (localhost [127.0.0.1])
	by lab1.campus (8.15.2/8.15.2) with ESMTPS id xAIK3D9S000453
	(version=TLSv1.3 cipher=TLS_AES_256_GCM_SHA384 bits=256 verify=NOT)
	for <dave@lab2.campus>; Mon, 18 Nov 2019 20:03:13 GMT
Received: (from emma@localhost)
	by lab1.campus (8.15.2/8.15.2/Submit) id xAIK0doL000449
	for dave@lab2.campus; Mon, 18 Nov 2019 20:00:39 GMT
Date: Mon, 18 Nov 2019 20:00:39 GMT
Message-Id: <201911182000.xAIK0doL000449@lab1.campus>
From: emma@lab1.campus
To: dave@lab2.campus
Subject: Sender MTA Test

Hi Dave, this is a test for my MTA.
```

Снизу вверх строки, начинающиеся с `Received:`, показывают маршрут, пройденный сообщением. Сообщение было отправлено пользователем `emma` с помощью команды, `sendmail dave@lab2.campus` выданной на `lab1.campus`, как указано в первом `Received:` заголовке. Затем, все еще включенный `lab1.campus`, MTA использует ESMTPS — надмножество SMTP, которое добавляет расширения шифрования, — для отправки сообщения в MTA по адресу `lab2.campus`, как указано в последнем (верхнем) `Received:` заголовке.

MTA завершает свою работу после сохранения сообщения в папке "Входящие" пользователя. Обычно выполняется какая-либо фильтрация электронной почты, такая как блокировщик нежелательной почты или применение определенных пользователем правил фильтрации. Эти задачи выполняются сторонними приложениями, работающими совместно с MTA. MTA может, например, вызвать утилиту _SpamAssassin_, чтобы пометить подозрительные сообщения, используя ее функции анализа текста.

Хотя это и возможно, читать файл почтового ящика напрямую неудобно. Вместо этого рекомендуется использовать программу-клиент электронной почты (например, Thunderbird, Evolution или KMail), которая проанализирует файл и соответствующим образом обработает сообщения. Такие программы также предлагают дополнительные функции, например, ярлыки для часто используемых действий, подкаталоги почтового ящика и т. д.

## `mail` Командные и почтовые пользовательские агенты (MUA) <a href="#sec.108.3_01-mc" id="sec.108.3_01-mc"></a>

Можно написать электронное письмо напрямую в исходном формате, но гораздо практичнее использовать клиентское приложение, также известное как MUA (_Mail User Agent_), чтобы ускорить процесс и избежать ошибок. MUA выполняет работу «под капотом», то есть почтовый клиент представляет и упорядочивает полученные сообщения и обеспечивает надлежащую связь с MTA после того, как пользователь отправит электронное письмо.

Существует множество различных типов почтовых пользовательских агентов. Настольные приложения, такие как _Mozilla Thunderbird_ и _Evolution_ от Gnome, поддерживают как локальные, так и удалённые учётные записи электронной почты. Даже _веб-интерфейсы электронной почты_ можно рассматривать как разновидность MUA, поскольку они обеспечивают взаимодействие между пользователем и базовым MTA. Однако почтовые клиенты не ограничиваются графическими интерфейсами: консольные почтовые клиенты широко используются для доступа к почтовым ящикам, не интегрированным с графическим интерфейсом, и для автоматизации задач, связанных с электронной почтой, в сценариях командной оболочки.

Изначально команда `mail` в Unix предназначалась только для обмена сообщениями между пользователями локальной системы (первая команда `mail` появилась в первой версии Unix, выпущенной в 1971 году). Когда обмен электронной почтой в сети стал более распространённым, были созданы другие программы для работы с новой системой доставки, которые постепенно заменили старую программу `mail` .

В настоящее время наиболее часто используемая команда `mail` предоставляется пакетом _mailx_, который совместим со всеми современными функциями электронной почты. В большинстве дистрибутивов Linux команда `mail` является просто символической ссылкой на команду `mailx`. Другие реализации, такие как пакет _GNU Mailutils_, в основном предоставляют те же функции, что и `mailx`. Однако между ними есть небольшие различия, особенно в отношении параметров командной строки.

Независимо от реализации, все современные версии команды `mail` работают в двух режимах: _обычном режиме_ и _режиме отправки_. Если в качестве аргумента для команды `mail` указан адрес электронной почты, она перейдёт в режим отправки, в противном случае — в обычный (читательский) режим. В обычном режиме полученные сообщения перечисляются с числовым индексом для каждого из них, чтобы пользователь мог обращаться к ним по отдельности при вводе команд в интерактивном режиме. Например, команда `print 1` может использоваться для отображения содержимого сообщения под номером 1. Интерактивные команды можно сокращать, поэтому такие команды, как `print` или `delete` или `reply` можно заменить на `p` или `d` или `r` соответственно. Команда `mail` всегда будет учитывать последнее полученное или просмотренное сообщение, если номер индекса сообщения не указан. Команда `quit` или `q` завершает работу программы.

_Режим отправки_ особенно полезен для автоматической отправки электронных писем. Его можно использовать, например, для отправки электронного письма системному администратору, если запланированный сценарий обслуживания не выполняет свою задачу. В режиме отправки `mail` будет использовать содержимое _стандартного ввода_ в качестве тела сообщения:

```
$ mail -s "Maintenance fail" henry@lab3.campus <<<"The maintenance script failed at `date`"
```

В этом примере опция `-s` была добавлена для включения поля темы в сообщение. Тело сообщения было передано с помощью перенаправления _Hereline_ на стандартный ввод, но содержимое файла или вывод команды также можно передать в _stdin_ программы. Если содержимое не передано с помощью перенаправления на стандартный ввод, программа будет ожидать, пока пользователь введёт тело сообщения. В этом случае нажатие клавиши <kbd>Ctrl</kbd>+<kbd>D</kbd> завершит сообщение. Команда `mail` немедленно завершит работу после добавления сообщения в исходящую очередь.

## Настройка доставки <a href="#sec.108.3_01-dc" id="sec.108.3_01-dc"></a>

По умолчанию учётные записи электронной почты в системе Linux связаны со стандартными системными учётными записями. Например, если у пользователя Кэрол имя пользователя `carol` на хосте `lab2.campus`, то её адрес электронной почты будет `carol@lab2.campus`. Эту однозначную связь между системными учётными записями и почтовыми ящиками можно расширить с помощью стандартных методов, предоставляемых большинством дистрибутивов Linux, в частности механизма маршрутизации электронной почты, предоставляемого файлом `/etc/aliases`.

Псевдоним электронной почты — это «виртуальный» получатель электронной почты, чьи входящие сообщения перенаправляются в существующие локальные почтовые ящики или в другие типы хранилищ или обработчиков сообщений. Псевдонимы полезны, например, для того, чтобы отправлять сообщения, отправленные на адрес `postmaster@lab2.campus`, в почтовый ящик Кэрол, который является обычным локальным почтовым ящиком в системе `lab2.campus`. Для этого в файл `postmaster: carol` в `/etc/aliases` следует добавить строку `lab2.campus`. После изменения файла `/etc/aliases` следует выполнить команду `newaliases` для обновления базы данных псевдонимов MTA и вступления изменений в силу. Команды `sendmail -bi` или `sendmail -I` также можно использовать для обновления базы данных псевдонимов.

Псевдонимы определяются по одному в строке в формате `<alias>: <destination>`. Помимо обычных локальных почтовых ящиков, обозначаемых соответствующим именем пользователя, доступны и другие типы получателей:

* Полный путь (начинающийся с `/`) к файлу. Сообщения, отправленные на соответствующий псевдоним, будут добавлены в файл.
* Команда для обработки сообщения. `<destination>` должна начинаться с символа канала, и если команда содержит специальные символы (например, пробелы), она должна быть заключена в двойные кавычки. Например, псевдоним `subscribe: |subscribe.sh` в `lab2.campus` будет перенаправлять все сообщения, отправленные на `subscribe@lab2.campus` на стандартный ввод команды `subscribe.sh`. Если sendmail работает в _ограниченном режиме оболочки_, разрешённые команды — или ссылки на них — должны быть в `/etc/smrsh/`.
* Файл включения. Один псевдоним может иметь несколько целевых объектов (разделённых запятыми), поэтому может быть удобнее хранить их во внешнем файле. Ключевое слово `:include:` должно указывать путь к файлу, как в `:include:/var/local/destinations`
* Внешний адрес. Псевдонимы также могут пересылать сообщения на внешние адреса электронной почты.
* Другой псевдоним.

Локальный пользователь без прав администратора может создать псевдонимы для своей электронной почты, отредактировав файл `.forward` в своём домашнем каталоге. Поскольку псевдонимы могут влиять только на его собственный почтовый ящик, достаточно только части `<destination>` в файле. Например, чтобы пересылать все входящие письма на внешний адрес, пользователь `dave` в `lab2.campus` может создать следующий файл `~/.forward`:

```
$ cat ~/.forward
emma@lab1.campus
```

Он будет перенаправлять все сообщения электронной почты, отправленные на `dave@lab2.campus` на `emma@lab1.campus`. Как и в случае с файлом `/etc/aliases`, в `.forward` можно добавить другие правила перенаправления, по одному в строке. Тем не менее, файл `.forward` должен быть доступен для записи только его владельцу, и нет необходимости выполнять команду `newaliases` после его изменения. Файлы, начинающиеся с точки, не отображаются в обычных списках файлов, из-за чего пользователь может не знать об активных псевдонимах. Поэтому при диагностике проблем с доставкой электронной почты важно проверить, существует ли файл.

## Краткие сведения <a href="#sec.108.3_01-su" id="sec.108.3_01-su"></a>

В этом уроке рассматривается роль и использование агентов передачи почты в системах Linux. MTA обеспечивает стандартный способ взаимодействия между учётными записями пользователей и может быть объединён с другим программным обеспечением для обеспечения дополнительных функций. В уроке рассматриваются следующие темы:

* Понятия, связанные с технологиями электронной почты, почтовыми ящиками и протоколами.
* Как MTA в Linux обмениваются сообщениями по сети.
* Консольные почтовые клиенты и MUA (агенты пользователей почты).
* Локальные псевдонимы и переадресация электронной почты.

Были рассмотрены следующие технологии, команды и процедуры:

* SMTP и связанные с ним протоколы.
* MTA, доступные для Linux: Sendmail, Postfix, qmail, Exim.
* Команды MTA и MUA: `sendmail` и `mail`.
* Административные файлы и команды: `mailq`, `/etc/aliases`, `newaliases`, `~/.forward`.

## Ответы на Упражнения с Руководством <a href="#sec.108.3_01-age" id="sec.108.3_01-age"></a>

1.  Без дополнительных параметров или аргументов команда `mail henry@lab3.campus` переходит в режим ввода, чтобы пользователь мог ввести сообщение в `henry@lab3.campus`. После завершения ввода сообщения, какое нажатие клавиши закроет режим ввода и отправит электронное письмо?

    Нажатие <kbd>Ctrl</kbd>+<kbd>D</kbd> приведёт к закрытию программы и отправке электронного письма.
2.  Какую команду может выполнить пользователь с правами root, чтобы вывести список недоставленных сообщений, отправленных из локальной системы?

    Команда `mailq` или `sendmail -bp`.
3.  Как пользователь без привилегий может использовать стандартный метод MTA для автоматической пересылки всей входящей почты на адрес `dave@lab2.campus`?

    Пользователь должен добавить `dave@lab2.campus` в `~/.forward`.

## Ответы на Исследовательские упражнения <a href="#sec.108.3_01-aee" id="sec.108.3_01-aee"></a>

1.  С помощью команды `mail` из `mailx` какая команда отправит сообщение на адрес `emma@lab1.campus` с файлом `logs.tar.gz` в качестве вложения и выводом команды `uname -a` в качестве текста письма?

    `uname -a | mail -a logs.tar.gz emma@lab1.campus`
2.  Администратор службы электронной почты хочет отслеживать передачу электронных писем по сети, но не хочет засорять свой почтовый ящик тестовыми сообщениями. Как этот администратор может настроить общесистемный псевдоним электронной почты, чтобы перенаправлять все письма, отправленные пользователю `test`, в файл `/dev/null`?

    Строка `test: /dev/null` в `/etc/aliases` перенаправит все сообщения, отправленные в локальный почтовый ящик `test`, в файл `/dev/null`.
3.  Какую команду, помимо `newaliases`, можно использовать для обновления базы псевдонимов после добавления нового псевдонима в `/etc/aliases`?

    Команда `sendmail -bi` или `sendmail -I`.
