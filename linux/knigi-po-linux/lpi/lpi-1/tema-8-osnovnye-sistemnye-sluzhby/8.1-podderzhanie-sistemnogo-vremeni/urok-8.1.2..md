# Урок 8.1.2.

Введение

В то время как персональные компьютеры способны самостоятельно поддерживать достаточно точное время, производственные вычисления и сетевые среды требуют очень точного времени. Наиболее точное время измеряется _эталонными часами_, которые обычно являются атомными часами. В современном мире была разработана система, в которой все компьютерные системы, подключённые к интернету, могут быть синхронизированы с этими эталонными часами с помощью так называемого _протокола сетевого времени_ (NTP). Компьютерная система с NTP сможет синхронизировать свои системные часы со временем, предоставляемым эталонными часами. Если системное время и время, измеренное на этих серверах, отличаются, то компьютер будет постепенно ускорять или замедлять своё внутреннее системное время до тех пор, пока системное время не сравняется с сетевым.

NTP использует иерархическую структуру для распространения времени. Эталонные часы подключены к серверам, расположенным в верхней части иерархии. Эти серверы являются машинами _Stratum 1_ и, как правило, недоступны для общественности. Однако машины Stratum 1 доступны для машин _Stratum 2_, которые доступны для машин _Stratum 3_ и так далее. Серверы Stratum 2 доступны для общественности, как и любые машины, расположенные ниже в иерархии. При настройке NTP для большой сети рекомендуется, чтобы небольшое количество компьютеров подключалось к серверам Stratum 2+, а затем эти компьютеры предоставляли NTP всем остальным компьютерам. Таким образом можно свести к минимуму нагрузку на компьютеры Stratum 2.

При обсуждении NTP используются некоторые важные термины. Некоторые из этих терминов используются в командах, которые мы будем использовать для отслеживания состояния NTP на наших компьютерах:

Смещение\Offset

Это означает абсолютную разницу между системным временем и временем NTP. Например, если системные часы показывают 12:00:02, а время NTP — 11:59:58, то разница между двумя часами составляет четыре секунды.

Шаг\Step

Если разница во времени между поставщиком NTP и потребителем превышает 128 мс, то NTP выполнит одно значительное изменение системного времени, а не замедлит или ускорит его. Это называется _шагом_.

Slew

Под синхронизацией понимается изменение системного времени, когда разница между системным временем и NTP составляет менее 128 мс. В этом случае изменения будут вноситься постепенно. Это называется _синхронизацией_.

Insane Time

Если разница между системным временем и временем NTP превышает 17 минут, то системное время считается _неправильным_, и демон NTP не будет вносить никаких изменений в системное время. Чтобы привести системное время в соответствие с правильным временем в пределах 17 минут, необходимо предпринять специальные меры.

Дрейф\Drift

Дрейф — это явление, при котором два часовых механизма со временем расходятся во времени. По сути, если два часовых механизма изначально синхронизированы, но затем со временем расходятся во времени, то происходит дрейф часов.

Дрожание\Jitter

Дрожание — это величина смещения с момента последнего запроса к часам. Таким образом, если последняя синхронизация NTP произошла 17 минут назад, а смещение между поставщиком и потребителем NTP составляет 3 миллисекунды, то 3 миллисекунды — это и есть дрожание.

Теперь мы обсудим некоторые конкретные способы, которыми Linux реализует NTP.

## timedatectl <a href="#timedatectl" id="timedatectl"></a>

Если в вашем дистрибутиве Linux используется `timedatectl`, то по умолчанию он реализует _SNTP_-клиент, а не полноценную реализацию NTP. Это менее сложная реализация сетевого времени, которая означает, что ваш компьютер не будет предоставлять NTP другим подключённым компьютерам.

В этом случае SNTP не будет работать, если не запущена служба `timesyncd` . Как и в случае со всеми службами systemd, мы можем проверить, запущена ли она, с помощью:

## NTP Daemon <a href="#ntp_daemon" id="ntp_daemon"></a>

Системное время регулярно сравнивается с сетевым временем. Для этого в фоновом режиме должен работать _демон_. Во многих системах Linux этот демон называется `ntpd`. `ntpd` Это позволит компьютеру не только _потреблять_ время (то есть синхронизировать собственные часы с внешним источником), но и _предоставлять_ время другим компьютерам.

Предположим, что наш компьютер работает на базе systemd и использует `systemctl` для управления демонами. Мы установим пакеты `ntp` с помощью соответствующего менеджера пакетов, а затем убедимся, что наш демон `ntpd` работает, проверив его статус:

```
$ systemctl status ntpd

●  ntpd.service - Network Time Service
   Loaded: loaded (/usr/lib/systemd/system/ntpd.service; enabled; vendor preset: disabled)
   Active: active (running) since Fri 2019-12-06 03:27:21 EST; 7h ago
  Process: 856 ExecStart=/usr/sbin/ntpd -u ntp:ntp $OPTIONS (code=exited, status=0/SUCCESS)
 Main PID: 867 (ntpd)
   CGroup: /system.slice/ntpd.service
           `-867 /usr/sbin/ntpd -u ntp:ntp -g
```

В некоторых случаях может потребоваться одновременно запустить и включить `ntpd`. На большинстве компьютеров с Linux это делается следующим образом:

```bash
# systemctl enable ntpd && systemctl start ntpd
```

Запросы NTP выполняются на TCP-порте 123. Если NTP не работает, убедитесь, что этот порт открыт и прослушивается.

## Конфигурация NTP <a href="#ntp_configuration" id="ntp_configuration"></a>

NTP может опрашивать несколько источников и выбирать наилучшие варианты для установки системного времени. Если сетевое подключение потеряно, NTP использует предыдущие корректировки из своей истории для прогнозирования будущих корректировок.

В зависимости от вашего дистрибутива Linux список сетевых серверов времени будет храниться в разных местах. Предположим, что `ntp` установлен на вашем компьютере.

Файл `/etc/ntp.conf` содержит информацию о конфигурации синхронизации вашей системы с сетевым временем. Этот файл можно прочитать и изменить с помощью `vi` или `nano`.

По умолчанию используемые серверы NTP будут указаны в следующем разделе:

```bash
# Use public servers from the pool.ntp.org project.
# Please consider joining the pool (http://www.pool.ntp.org/join.html).
server 0.centos.pool.ntp.org iburst
server 1.centos.pool.ntp.org iburst
server 2.centos.pool.ntp.org iburst
server 3.centos.pool.ntp.org iburst
```

Синтаксис для добавления NTP-серверов выглядит следующим образом:

```bash
server (IP Address)
server server.url.localhost
```

Адреса серверов могут быть IP-адресами или URL-адресами, если DNS настроен правильно. В этом случае запрос всегда будет направляться на сервер.

Сетевой администратор также может рассмотреть возможность использования (или настройки) _пула_. В этом случае мы предполагаем, что есть несколько провайдеров NTP, на всех из которых запущены демоны NTP и установлено одинаковое время. Когда клиент запрашивает пул, провайдер выбирается случайным образом. Это помогает распределить сетевую нагрузку между несколькими компьютерами, чтобы ни один компьютер в пуле не обрабатывал все запросы NTP.

Как правило, `/etc/ntp.conf` заполняется пулом серверов под названием `pool.ntp.org`. Так, например, `server 0.centos.pool.ntp.org` — это пул NTP по умолчанию, предоставляемый компьютерам CentOS.

## pool.ntp.org <a href="#pool_ntp_org" id="pool_ntp_org"></a>

Серверы NTP, используемые по умолчанию, являются проектом с открытым исходным кодом. Дополнительную информацию можно найти на [ntppool.org](https://www.ntppool.org/en/).

> Подумайте, подходит ли вам NTP Pool. Если бизнес, организация или жизнь человека зависят от точного времени или могут пострадать из-за его неточности, вам не следует «просто брать его из интернета». NTP Pool, как правило, отличается очень высоким качеством, но это сервис, которым в свободное время управляют добровольцы. Пожалуйста, проконсультируйтесь со своими поставщиками оборудования и услуг о том, как настроить для вас локальный и надёжный сервис. Ознакомьтесь также с нашими условиями предоставления услуг. Мы рекомендуем серверы времени от Meinberg, но вы также можете найти серверы времени от End Run, Spectracom и многих других.

— ntppool.org

## ntpdate <a href="#ntpdate" id="ntpdate"></a>

Во время первоначальной настройки системное время и NTP могут быть серьёзно рассогласованы. Если _смещение_ между системным временем и временем NTP превышает 17 минут, то демон NTP не будет вносить изменения в системное время. В этом случае потребуется ручное вмешательство.

Во-первых, если `ntpd` работает, необходимо _остановить_ службу. Для этого используйте `systemctl stop ntpd`

Затем используйте `ntpdate pool.ntp.org` для выполнения первоначальной однократной синхронизации, где `pool.ntp.org` — это IP-адрес или URL-адрес NTP-сервера. Может потребоваться более одной синхронизации.

## ntpq <a href="#ntpq" id="ntpq"></a>

`ntpq` Это утилита для мониторинга состояния NTP. После запуска и настройки демона NTP `ntpq` можно использовать для проверки его состояния:

```
$ ntpq -p
     remote           refid      st t when poll reach   delay   offset  jitter
==============================================================================
+37.44.185.42    91.189.94.4      3 u   86  128  377  126.509  -20.398   6.838
+ntp2.0x00.lv    193.204.114.233  2 u   82  128  377  143.885   -8.105   8.478
*inspektor-vlan1 121.131.112.137  2 u   17  128  377  112.878  -23.619   7.959
 b1-66er.matrix. 18.26.4.105      2 u  484  128   10   34.907   -0.811  16.123
```

В этом случае `-p` означает _печать_, и будет выведена сводка о одноранговых узлах. Адреса хостов также могут быть возвращены в виде IP-адресов с помощью `-n`.

`remote`

имя хоста NTP-провайдера.

`refid`

Ссылочный идентификатор поставщика NTP.

`st`

Страта провайдера.

`when`

Количество секунд, прошедших с момента последнего запроса.

`poll`

Количество секунд между запросами.

`reach`

Идентификатор состояния, указывающий, был ли достигнут сервер. При успешном подключении это число увеличивается на 1.

`delay`

Время в мс между запросом и ответом сервера.

`offset`

Время в мс между системным временем и временем NTP.

`jitter`

Смещение в мс между системным временем и NTP в последнем запросе.

`ntpq` Также есть интерактивный режим, который доступен при запуске без параметров или аргументов. Опция `?` возвращает список команд, которые `ntpq` распознает.

## chrony <a href="#chrony" id="chrony"></a>

`chrony` Это ещё один способ реализации NTP. Он установлен по умолчанию в некоторых системах Linux, но доступен для скачивания во всех основных дистрибутивах. `chronyd` — это демон chrony, а `chronyc` — интерфейс командной строки. Может потребоваться запустить и включить `chronyd` перед взаимодействием с `chronyc`.

Если установка chrony имеет конфигурацию по умолчанию, то с помощью команды `chronyc tracking` можно получить информацию о NTP и системном времени:

```bash
$ chronyc tracking

Stratum         : 3
Ref time (UTC)  : Thu Jan 09 19:18:35 2020
System time     : 0.000134029 seconds fast of NTP time
Last offset     : +0.000166506 seconds
RMS offset      : 0.000470712 seconds
Frequency       : 919.818 ppm slow
Residual freq   : +0.078 ppm
Skew            : 0.555 ppm
Root delay      : 0.006151616 seconds
Root dispersion : 0.010947504 seconds
Update interval : 129.8 seconds
Leap status     : Normal
```

Этот вывод содержит много информации, больше, чем в других реализациях.

`Reference ID`

Ссылочный идентификатор и имя, с которыми в данный момент синхронизирован компьютер.

`Stratum`

Количество переходов к компьютеру с подключенными опорными часами.

`Ref time`

Это время по всемирному координированному времени, когда было выполнено последнее измерение эталонным источником.

`System time`

Задержка системных часов с синхронизированного сервера.

`Last offset`

Предполагаемое смещение последнего обновления часов.

`RMS offset`

Долгосрочное среднее значение значения смещения.

`Frequency`

Это скорость, с которой часы системы будут идти неправильно, если chronyd не будет их корректировать. Она указана в частях на миллион (ppm).

`Residual freq`

Остаточная частота, показывающая разницу между измерениями эталонного источника и используемой в данный момент частотой.

`Skew`

Предполагаемая граница погрешности частоты.

`Root delay`

Общее время задержки сетевого соединения с компьютером, с которым синхронизируется компьютер.

`Leap status`

Это статус перехода на летнее время, который может принимать одно из следующих значений: нормальное, вставка второго часового пояса, удаление второго часового пояса или отсутствие синхронизации.

Наконец, `chronyc sources` вернёт информацию о серверах NTP, которые используются для синхронизации времени:

```bash

```

На данный момент на этом компьютере не настроено ни одного источника. Мы можем добавить источники из `pool.ntp.org` , открыв файл конфигурации chrony. Обычно он находится по адресу `/etc/chrony.conf`. Открыв этот файл, мы увидим, что некоторые серверы указаны по умолчанию:

```bash
210 Number of sources = 0
MS Name/IP address         Stratum Poll Reach LastRx Last sample
===============================================================================
# Most computers using chrony will send measurement requests to one or
# more 'NTP servers'.  You will probably find that your Internet Service

# you can access at http://support.ntp.org/bin/view/Servers/WebHome or
# you can use servers from the 3.arch.pool.ntp.org project.

! server 0.arch.pool.ntp.org iburst iburst
! server 1.arch.pool.ntp.org iburst iburst
! server 2.arch.pool.ntp.org iburst iburst

! pool 3.arch.pool.ntp.org iburst
```

Эти серверы также послужат руководством по синтаксису при вводе наших собственных серверов. Однако в этом случае мы просто удалим `!` в начале каждой строки, тем самым раскомментировав эти строки и используя серверы по умолчанию из проекта `pool.ntp.org` .

Кроме того, в этом файле мы можем изменить настройки по умолчанию, касающиеся перекоса и дрейфа, а также расположение файла дрейфа и файла ключей.

На этом компьютере нам нужно внести большую начальную поправку в тактовую частоту. Мы раскомментируем следующую строку:

```bash
! makestep 1.0 3
```

После внесения изменений в файл конфигурации перезапустите службу `chronyd` и затем используйте `chronyc makestep` для ручной установки системных часов:

```
# chronyc makestep
200 OK
```

А затем используйте `chronyc tracking`, как и раньше, чтобы убедиться, что изменения произошли.

## Ответы на Исследовательские упражнения <a href="#sec.108.1_02-aee" id="sec.108.1_02-aee"></a>

1.  Исследуйте различия между SNTP и NTP.

    | SNTP                                             | NTP                                                                             |
    | ------------------------------------------------ | ------------------------------------------------------------------------------- |
    | менее точный                                     | более точный                                                                    |
    | требует меньше ресурсов                          | требуется больше ресурсов                                                       |
    | не может выступать в качестве поставщика времени | может выступать в качестве поставщика времени                                   |
    | только время выполнения шагов                    | шаги или время замедления                                                       |
    | запрашивает время из одного источника            | может отслеживать несколько NTP-серверов и использовать оптимального провайдера |
2.  Почему системный администратор может _не_ использовать `pool.ntp.org`?

    С сайта ntppool.org: если для вас крайне важно, чтобы время было точным, вам следует рассмотреть альтернативу. Аналогичным образом, если у вашего интернет-провайдера есть сервер времени, рекомендуется использовать его.
3.  Как бы системный администратор решил присоединиться к проекту `pool.ntp.org` или внести свой вклад иным образом?

    С сайта www.ntppool.org: ваш сервер должен иметь статический IP-адрес и постоянное подключение к интернету. Статический IP-адрес не должен меняться вообще или, по крайней мере, не чаще одного раза в год. Кроме того, требования к пропускной способности невелики: от 384 до 512 Кбит/с. К участию приглашаются серверы Stratum 3 или 4.
