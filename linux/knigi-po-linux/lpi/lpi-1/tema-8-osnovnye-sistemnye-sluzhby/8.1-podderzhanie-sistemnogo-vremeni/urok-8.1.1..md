# Урок 8.1.1.

## Введение <a href="#sec.108.1_01-in" id="sec.108.1_01-in"></a>

Точное определение времени имеет решающее значение для современных вычислений. Однако реализация функции определения времени на удивление сложна. Для конечного пользователя функция определения времени кажется тривиальной, но система должна уметь разумно справляться со многими особенностями и крайними случаями. Обратите внимание, что часовые пояса не статичны, а могут быть изменены административным или политическим решением. Страна может отказаться от перехода на летнее время. Любая программа должна уметь логически обрабатывать эти изменения. К счастью для системных администраторов, решения для учёта времени в операционной системе Linux являются зрелыми, надёжными и обычно работают без особых проблем.

Когда компьютер с Linux загружается, он начинает отсчитывать время. Мы называем это _системными часами_, поскольку они обновляются операционной системой. Кроме того, в современных компьютерах есть _аппаратные_ или _часы реального времени_. Эти аппаратные часы часто являются частью материнской платы и отсчитывают время независимо от того, работает компьютер или нет. Во время загрузки системное время устанавливается по аппаратным часам, но по большей части эти два вида часов работают независимо друг от друга. В этом уроке мы обсудим методы взаимодействия как с системными, так и с аппаратными часами.

В большинстве современных систем Linux системное время и аппаратное время синхронизируются с _сетевым временем_, которое реализуется с помощью _протокола сетевого времени_ _Network Time Protocol_ (NTP). В подавляющем большинстве случаев единственную настройку, которую потребуется выполнить обычному пользователю, — это установить часовой пояс, а обо всём остальном позаботится NTP. Однако мы рассмотрим несколько способов работы со временем вручную, а особенности настройки сетевого времени будут рассмотрены в следующем уроке.

## Местное и Всемирное время <a href="#local_versus_universal_time" id="local_versus_universal_time"></a>

Системные часы настроены на всемирное координированное время (UTC), которое является местным временем в Гринвиче, Великобритания. Обычно пользователь хочет знать своё _местное время_. Местное время рассчитывается на основе UTC с применением _сдвига_ в зависимости от часового пояса и перехода на летнее время. Таким образом можно избежать многих сложностей.

Системные часы можно настроить на время UTC или местное время, но рекомендуется также настроить их на время UTC.

## Date <a href="#date" id="date"></a>

`date` это основная утилита, которая просто выводит местное время:

```bash
$ date
Sun Nov 17 12:55:06 EST 2019
```

Изменение параметров команды `date` приведёт к изменению формата вывода.

Например, пользователь может использовать `date -u` для просмотра текущего времени UTC.

```bash
$ date -u
Sun Nov 17 18:02:51 UTC 2019
```

Некоторые другие часто используемые параметры возвращают местное время в формате, соответствующем принятому формату RFC:

`-I`

Дата/время в формате ISO 8601. Добавление `date` (`-Idate`) ограничит вывод только датой. Другие форматы: `hours`, `minutes`, `seconds` и `ns` для наносекунд.

`-R`

Возвращает дату и время в формате RFC 5322.

`--rfc-3339`

Возвращает дату и время в формате RFC 3339.

Формат `date` может быть настроен пользователем с помощью последовательностей, указанных в справочной странице. Например, текущее время может быть отформатировано как время по стандарту Unix следующим образом:

```bash
$ date +%s
1574014515
```

Из справочной страницы `date` мы видим, что `%s` относится к времени Unix.

Время Unix используется внутри большинства Unix-подобных систем. Оно хранит время UTC в виде количества секунд, прошедших с _начала отсчёта_, которое было определено как 1 января 1970 года.

{% hint style="info" %}
В настоящее время для хранения времени в формате Unix требуется 32 бита. В будущем 32 бита станет недостаточно для хранения текущего времени в формате Unix. Это вызовет серьёзные проблемы в любых 32-битных системах Linux. К счастью, это произойдёт не раньше 19 января 2038 года.
{% endhint %}

Используя эти последовательности, мы можем отформатировать дату и время практически в любом формате, необходимом для любого приложения. Конечно, в большинстве случаев предпочтительнее придерживаться общепринятого стандарта.

Кроме того, `date --date` можно использовать для форматирования времени, отличного от текущего. В этом случае пользователь может указать дату, которая будет применяться в системе, например, по времени Unix:

```bash
$ date --date='@1564013011'
Wed Jul 24 20:03:31 EDT 2019
```

Использование опции `--debug` может быть очень полезным для успешного анализа даты. Посмотрите, что происходит при передаче корректной даты в команду:

```bash
$ date --debug --date="Fri, 03 Jan 2020 14:00:17 -0500"
date: parsed day part: Fri (day ordinal=0 number=5)
date: parsed date part: (Y-M-D) 2020-01-03
date: parsed time part: 14:00:17 UTC-05
date: input timezone: parsed date/time string (-05)
date: using specified time as starting value: '14:00:17'
date: warning: day (Fri) ignored when explicit dates are given
date: starting date/time: '(Y-M-D) 2020-01-03 14:00:17 TZ=-05'
date: '(Y-M-D) 2020-01-03 14:00:17 TZ=-05' = 1578078017 epoch-seconds
date: timezone: system default
date: final: 1578078017.000000000 (epoch-seconds)
date: final: (Y-M-D) 2020-01-03 19:00:17 (UTC)
date: final: (Y-M-D) 2020-01-03 14:00:17 (UTC-05)
```

Это может быть удобным инструментом при устранении неполадок в приложении, которое генерирует дату.

## Аппаратные часы <a href="#hardware_clock" id="hardware_clock"></a>

Пользователь может запустить команду `hwclock` для просмотра времени, отображаемого на часах реального времени. Для выполнения этой команды потребуются повышенные привилегии, поэтому в данном случае мы будем использовать `sudo` для вызова команды:

```bash
$ sudo hwclock
2019-11-20 11:31:29.217627-05:00
```

Использование опции `--verbose` вернет больше выходных данных, которые могут быть полезны для устранения неполадок:

```bash
$ sudo hwclock --verbose
hwclock from util-linux 2.34
System Time: 1578079387.976029
Trying to open: /dev/rtc0
Using the rtc interface to the clock.
Assuming hardware clock is kept in UTC time.
Waiting for clock tick...
...got clock tick
Time read from Hardware Clock: 2020/01/03 19:23:08
Hw clock time : 2020/01/03 19:23:08 = 1578079388 seconds since 1969
Time since last adjustment is 1578079388 seconds
Calculated Hardware Clock drift is 0.000000 seconds
2020-01-03 14:23:07.948436-05:00
```

Обратите внимание на `Calculated Hardware Clock drift`. Этот вывод может показать, что системное время и аппаратное время отличаются друг от друга.

## timedatectl <a href="#timedatectl" id="timedatectl"></a>

`timedatectl` Это команда, которую можно использовать для проверки общего состояния времени и даты, в том числе для проверки синхронизации сетевого времени (протокол сетевого времени будет рассмотрен в следующем уроке).

По умолчанию `timedatectl` возвращает информацию, аналогичную `date`, но с добавлением времени RTC (аппаратного обеспечения), а также статуса службы NTP:

```bash
$ timedatectl
               Local time: Thu 2019-12-05 11:08:05 EST
           Universal time: Thu 2019-12-05 16:08:05 UTC
                 RTC time: Thu 2019-12-05 16:08:05
                Time zone: America/Toronto (EST, -0500)
System clock synchronized: yes
              NTP service: active
          RTC in local TZ: no
```

## **Установка времени С помощью timedatectl**

Если NTP недоступен, для установки времени рекомендуется использовать `timedatectl` вместо `date` или `hwclock`:

```bash
# timedatectl set-time '2011-11-25 14:00:00'
```

Процесс аналогичен `date`. Пользователь также может установить время независимо от даты в формате ЧЧ:ММ:СС.

## **Настройка Часового пояса С помощью timedatectl**

`timedatectl` Это предпочтительный способ установки локального часового пояса в системах Linux на базе `systemd` при отсутствии графического интерфейса. `timedatectl` выводит список возможных часовых поясов, а затем часовой пояс можно установить, используя один из них в качестве аргумента.

Сначала мы перечислим возможные часовые пояса:

```bash
$ timedatectl list-timezones
Africa/Abidjan
Africa/Accra
Africa/Algiers
Africa/Bissau
Africa/Cairo
...
```

Список возможных часовых поясов длинный, поэтому в этом случае рекомендуется использовать команду `grep` .

Далее мы можем установить часовой пояс, используя один из элементов возвращённого списка:

```bash
$ timedatectl set-timezone Africa/Cairo
$ timedatectl
               Local time: Thu 2019-12-05 18:18:10 EET
           Universal time: Thu 2019-12-05 16:18:10 UTC
                 RTC time: Thu 2019-12-05 16:18:10
                Time zone: Africa/Cairo (EET, +0200)
System clock synchronized: yes
              NTP service: active
          RTC in local TZ: no
```

Имейте в виду, что название часового пояса должно быть точным. Например, `Africa/Cairo` изменит часовой пояс, а `cairo` или `africa/cairo` — нет.

## **Отключение NTP С помощью timedatectl**

В некоторых случаях может потребоваться отключить NTP. Это можно сделать с помощью `systemctl`, но мы продемонстрируем это с помощью `timedatectl`:

```bash
# timedatectl set-ntp no
$ timedatectl
             Local time: Thu 2019-12-05 18:19:04 EET Universal time: Thu 2019-12-05 16:19:04 UTC
               RTC time: Thu 2019-12-05 16:19:04
              Time zone: Africa/Cairo (EET, +0200)
            NTP enabled: no
       NTP synchronized: no
        RTC in local TZ: no
             DST active: n/a
```

## Установка Часового пояса Без timedatectl <a href="#setting_time_zone_without_timedatectl" id="setting_time_zone_without_timedatectl"></a>

Настройка часового пояса — стандартный этап при установке Linux на новый компьютер. Если процесс установки графический, то, скорее всего, это будет сделано без участия пользователя.

Каталог `/usr/share/zoneinfo` содержит информацию о различных возможных часовых поясах. В каталоге `zoneinfo` есть подкаталоги, содержащие названия континентов, а также другие символические ссылки. Рекомендуется искать `zoneinfo` своего региона, начиная с континента.

`zoneinfo` файлы содержат правила, необходимые для вычисления смещения местного времени относительно UTC, а также важны, если в вашем регионе действует летнее время. Содержимое `/etc/localtime` будет считываться, когда Linux потребуется определить местный часовой пояс. Чтобы установить часовой пояс без использования графического интерфейса, пользователь должен создать символическую ссылку для своего местоположения из `/usr/share/zoneinfo` в `/etc/localtime`. Например:

```bash
$ ln -s /usr/share/zoneinfo/Canada/Eastern /etc/localtime
```

После установки правильного часового пояса часто рекомендуется запустить:

```bash
# hwclock --systohc
```

Это позволит установить _аппаратные часы_ по _системным часам_ (то есть часы реального времени будут установлены на то же время, что и `date`). Обратите внимание, что эта команда выполняется с правами суперпользователя, то есть при входе в систему с правами суперпользователя.

`/etc/timezone` похоже на `/etc/localtime`. Это представление данных о местном часовом поясе, и поэтому его можно считать с помощью `cat`:

```bash
$ cat /etc/timezone
America/Toronto
```

Обратите внимание, что этот файл используется не во всех дистрибутивах Linux.

## Установка даты и времени Без timedatectl <a href="#setting_date_and_time_without_timedatectl" id="setting_date_and_time_without_timedatectl"></a>

{% hint style="info" %}
Большинство современных систем Linux используют `systemd` для настройки и обслуживания, поэтому не рекомендуется использовать `date` или `hwclock` для установки времени. `systemd` Для этого используется `timedatectl` . Тем не менее, важно знать эти устаревшие команды на случай, если вам придётся администрировать более старую систему.
{% endhint %}

## Использование date

`У date` есть возможность установить системное время. Используйте `--set` или `-s` для установки даты и времени. Вы также можете использовать `--debug` для проверки правильности синтаксического анализа команды:

```bash
# date --set="11 Nov 2011 11:11:11"
```

Обратите внимание, что для установки даты здесь требуются права суперпользователя. Мы также можем изменить время или дату самостоятельно:

```bash
# date +%Y%m%d -s "20111125"
```

Здесь мы должны указать последовательности, чтобы наша строка была правильно проанализирована. Например, `%Y` относится к году, поэтому первые четыре цифры `2011` будут интерпретированы как 2011 год. Аналогично, `%T` — это последовательность для времени, и здесь она показана при установке времени

```bash
# date +%T -s "13:11:00"
```

После изменения системного времени рекомендуется также настроить аппаратные часы, чтобы системные и аппаратные часы были синхронизированы:

```bash
# hwclock --systohc
```

`systohc` означает “преобразование системных часов в аппаратные”.

## **Использование hwclock**

Вместо того чтобы настраивать системные часы и обновлять аппаратные часы, вы можете выполнить процесс в обратном порядке. Мы начнём с настройки аппаратных часов:

```bash
# hwclock --set --date "4/12/2019 11:15:19"
# hwclock
Fri 12 Apr 2019 6:15:19 AM EST -0.562862 seconds
```

Обратите внимание, что по умолчанию `hwclock` ожидает время в формате UTC, но по умолчанию возвращает местное время.

После установки аппаратных часов нам нужно будет обновить системные часы с их помощью. `hctosys` можно понимать как «аппаратные часы для системных часов».

```
# hwclock --hctosys
```

Отображение или изменение системных часов. Другие опции:

Отображение времени по Гринвичу.

`+%s`

Использовать последовательность для отображения времени эпохи.

Указать конкретное время для отображения, а не текущее.

Отображать отладочные сообщения при анализе введенной пользователем даты.

`hwclock`

Использовать системные часы для установки аппаратных часов.

Использовать аппаратные часы для установки системных часов.

Установить время вручную.

Перечислить возможные часовые пояса.

    | --------------------------------- | ------- | ---------------------- | --------------- |
    | `date -u`                         | X       |                        |                 |
    | `hwclock --set --date "12:00:00"` |         | X                      |                 |
    | `timedatectl`                     |         |                        | X               |
    | `timedatectl \| grep RTC`         |         | X                      |                 |
    | `hwclock --hctosys`               | X       |                        |                 |
    | `date +%T -s "08:00:00"`          | X       |                        |                 |
    | `timedatectl set-time 1980-01-10` |         |                        | X               |
2.  Ознакомьтесь со следующим выводом, а затем исправьте формат аргумента, чтобы команда выполнялась успешно:

    ```bash
    $ date --debug --date "20/20/12 0:10 -3"

    date: warning: value 20 has less than 4 digits. Assuming MM/DD/YY[YY]
    date: parsed date part: (Y-M-D) 0002-20-20
    date: parsed time part: 00:10:00 UTC-03
    date: input timezone: parsed date/time string (-03)
    date: using specified time as starting value: '00:10:00'
    date: error: invalid date/time value:
    date:     user provided time: '(Y-M-D) 0002-20-20 00:10:00 TZ=-03'
    date:        normalized time: '(Y-M-D) 0003-08-20 00:10:00 TZ=-03'
    date:                                  ---- --
    date:      possible reasons:
    date:        numeric values overflow;
    date:        incorrect timezone
    ```

    `date --debug --set "12/20/20 0:10 -3"`
3.  Используйте команду `date` и последовательности, чтобы установить в системе месяц февраль. Остальные параметры даты и времени оставьте без изменений.

    `date +%m -s "2"`
4.  Если приведённая выше команда выполнена успешно, используйте `hwclock` для установки аппаратных часов по системным часам.

    `hwclock -systohc`
5.  Есть место под названием `eucla`. На каком континенте оно находится? Используйте команду `grep` чтобы узнать. Введите полную команду ниже:

    `timedatectl list-timezones \| grep -i eucla`

    или

    `grep -ri eucla /usr/share/zoneinfo`
6.  Установите для вашего текущего часового пояса значение `eucla`.

    `timedatectl set-timezone 'Australia/Eucla'`

    или

    `ln -s /usr/share/zoneinfo/Australia/Eucla /etc/localtime`

### Ответы на Исследовательские упражнения <a href="#sec.108.1_01-aee" id="sec.108.1_01-aee"></a>

1.  Какой способ установки времени является оптимальным? В каком случае предпочтительный способ может оказаться невозможным?

    В большинстве дистрибутивов Linux NTP включён по умолчанию и должен работать без вмешательства пользователя для установки системного времени. Однако если система Linux не подключена к интернету, NTP будет недоступен. Например, встроенная система Linux, работающая на промышленном оборудовании, может не иметь подключения к сети.
2.  Как вы думаете, почему существует так много способов выполнить одну и ту же задачу, то есть установить системное время?

    Поскольку установка времени была обязательным требованием для всех систем \*nix на протяжении десятилетий, существует множество устаревших методов установки времени, которые используются до сих пор.
3.  После 19 января 2038 года для хранения системного времени Linux потребуется 64-битное число. Однако мы можем просто установить «новую эру». Например, 1 января 2038 года в полночь можно установить время новой эры `0`. Как вы думаете, почему это не стало предпочтительным решением?

    К 2038 году подавляющее большинство компьютеров уже будут работать на 64-битных процессорах, и использование 64-битного числа не приведёт к значительному снижению производительности. Однако невозможно оценить риски, связанные с «перезапуском» времени эпохи таким образом. Это может повлиять на большое количество устаревшего программного обеспечения. Например, у банков и крупных компаний часто есть большое количество старых программ, которые они используют для внутренних целей. Таким образом, этот сценарий, как и многие другие, представляет собой исследование компромиссов. На любые 32-битные системы, которые будут работать в 2038 году, повлияет переполнение времени эпохи, но на устаревшее программное обеспечение повлияет изменение значения времени эпохи.
