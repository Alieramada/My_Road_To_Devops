# Урок 8.4.1.

## Введение <a href="#sec.108.4_01-in" id="sec.108.4_01-in"></a>

Заявления о «безбумажном обществе», появившиеся с изобретением компьютеров, до сих пор не подтвердились. Многие организации по-прежнему полагаются на печатные или «бумажные» страницы с информацией. Учитывая это, мы можем понять, насколько важно для пользователя компьютера знать, как печатать из системы, а также для администратора — как поддерживать работоспособность компьютера при работе с принтерами.

В Linux, как и во многих других операционных системах, программный стек _Common Unix Printing System_ (CUPS) позволяет выполнять печать и управлять принтером с компьютера. Вот очень упрощённое описание того, как выполняется печать файла в Linux с помощью CUPS:

1. Пользователь отправляет файл для печати.
2. Демон CUPS `cupsd` затем _записывает_ задание на печать. CUPS присваивает этому заданию на печать номер, а также информацию о том, в какой очереди печати находится задание, и название документа для печати.
3. CUPS использует _фильтры_, установленные в системе, для создания отформатированного файла, который может использовать принтер.
4. Затем CUPS отправляет отформатированный файл на принтер для печати.

Мы рассмотрим эти шаги более подробно, а также способы установки принтера в Linux и управления им.

## Сервис CUPS <a href="#the_cups_service" id="the_cups_service"></a>

В большинстве настольных версий Linux пакеты CUPS уже установлены. В минимальных версиях Linux пакеты CUPS могут быть не установлены в зависимости от дистрибутива. Базовую установку CUPS можно выполнить в системе Debian следующим образом:

```bash
$ sudo apt install cups
```

В системах Fedora процесс установки так же прост. После установки в Fedora и других дистрибутивах на базе Red Hat вам нужно будет вручную запустить службу CUPS:

```bash
$ sudo dnf install cups
...
$ sudo systemctl start cups.service
```

После завершения установки вы можете проверить, работает ли служба CUPS, с помощью команды `systemctl`:

```bash
$ systemctl status cups.service
● cups.service - CUPS Scheduler
   Loaded: loaded (/lib/systemd/system/cups.service; enabled; vendor preset: enabled)
   Active: active (running) since Thu 2020-06-25 14:35:47 EDT; 41min ago
     Docs: man:cupsd(8)
 Main PID: 3136 (cupsd)
    Tasks: 2 (limit: 1119)
   Memory: 3.2M
   CGroup: /system.slice/cups.service
           ├─3136 /usr/sbin/cupsd -l
           └─3175 /usr/lib/cups/notifier/dbus dbus://
```

Как и многие другие демоны Linux, CUPS использует для своей работы набор файлов конфигурации. Ниже перечислены основные из них, представляющие интерес для системного администратора:

`/etc/cups/cupsd.conf`

Этот файл содержит настройки конфигурации для самой службы CUPS. Если вы хоть немного знакомы с файлом конфигурации веб-сервера Apache, то файл конфигурации CUPS будет вам знаком, так как в нём используется очень похожий синтаксис. Файл `cupsd.conf` содержит настройки для таких параметров, как управление доступом к различным используемым в системе очередям печати, включение или отключение веб-интерфейса CUPS, а также уровень ведения журнала, который будет использовать демон.

`/etc/printcap`

Это устаревший файл, который использовался протоколом LPD (_Line Printer Daemon_) до появления CUPS. CUPS по-прежнему создаёт этот файл в системах для обратной совместимости, и часто он является символической ссылкой на `/run/cups/printcap`. Каждая строка в этом файле содержит информацию о принтере, к которому система имеет доступ.

`/etc/cups/printers.conf`

Этот файл содержит информацию о каждом принтере, настроенном для использования системой CUPS. Каждый принтер и связанная с ним очередь печати в этом файле заключены в `<Printer></Printer>` строку. Этот файл содержит список отдельных принтеров, находящихся в `/etc/printcap`.

{% hint style="info" %}
\
Не следует вносить изменения в файл `/etc/cups/printers.conf` в командной строке во время работы службы CUPS.
{% endhint %}

`/etc/cups/ppd/`

Это не файл конфигурации, а каталог, в котором хранятся файлы _PostScript Printer Description_ (PPD) для принтеров, использующих их. Возможности каждого принтера будут храниться в файле PPD (с расширением `.ppd`). Это текстовые файлы, которые соответствуют определённому формату.

Служба CUPS также использует ведение журналов во многом так же, как и служба Apache 2. Журналы хранятся в `/var/log/cups/` и содержат `access_log`, `page_log`, и `error_log`. `access_log` ведет запись о доступе к веб-интерфейсу CUPS, а также о действиях, выполненных в нем, таких как управление принтером. `page_log` отслеживает задания на печать, отправленные в очереди печати, управляемые установкой CUPS. `error_log` содержит сообщения о неудачных заданиях на печать и других ошибках, зафиксированных веб-интерфейсом.

Далее мы рассмотрим инструменты и утилиты, которые используются для управления службой CUPS.

## **Использование веб-интерфейса**

Как было сказано ранее, файл конфигурации `/etc/cups/cupsd.conf` определяет, включён ли веб-интерфейс системы CUPS. Параметр конфигурации выглядит следующим образом:

```bash
# Web interface setting...
WebInterface Yes
```

Если веб-интерфейс включен, то CUPS можно управлять с помощью браузера по URL-адресу по умолчанию `http://localhost:631`. По умолчанию пользователь системы может просматривать принтеры и очереди печати, но для внесения любых изменений в конфигурацию требуется аутентификация пользователя с правами root в веб-сервисе. Строка конфигурации в файле `/etc/cups/cupsd.conf` для ограничения доступа к административным функциям будет выглядеть следующим образом:

```bash
# All administration operations require an administrator to authenticate...
<Limit CUPS-Add-Modify-Printer CUPS-Delete-Printer CUPS-Add-Modify-Class CUPS-Delete-Class CUPS-Set-Default>
  AuthType Default
  Require user @SYSTEM
  Order deny,allow
</Limit>
```

Вот разбивка этих вариантов:

`AuthType Default`

будет использовать базовое приглашение аутентификации, когда для выполнения действия требуется root-доступ.

`Require user @SYSTEM`

указывает на то, что для выполнения операции потребуется пользователь с правами администратора. Это можно изменить на `@groupname` где участники `groupname` могут управлять службой CUPS или отдельным пользователям может быть предоставлен список, как в `Require user carol, tim`.

`Order deny,allow`

Это похоже на параметр конфигурации Apache 2, при котором действие по умолчанию запрещено, если пользователь (или член группы) не прошёл аутентификацию.

Веб-интерфейс CUPS можно отключить, сначала остановив службу CUPS, изменив параметр `WebInterface` с `Yes` на `No`, а затем перезапустив службу CUPS.

Веб-интерфейс CUPS похож на обычный веб-сайт с вкладками для навигации по различным разделам системы CUPS. Вкладки в веб-интерфейсе включают следующее:

Home

На главной странице будет указана текущая версия CUPS, которая установлена. Она также разбивает CUPS на разделы, такие как:

CUPS for Users

Содержит описание CUPS, параметры командной строки для работы с принтерами и очередями печати, а также ссылку на форум пользователей CUPS.

CUPS for Administrators

В интерфейсе предусмотрены ссылки для установки принтеров и управления ими, а также ссылки на информацию о работе с принтерами в сети.

CUPS for Developers

Предоставляет ссылки на разработку CUPS, а также на создание PPD-файлов для принтеров.

Administration

Страница администрирования также разбита на разделы:

Printers

Здесь администратор может добавлять в систему новые принтеры, находить принтеры, подключённые к системе, и управлять уже установленными принтерами.

Classes

Классы — это механизм, с помощью которого принтеры можно добавлять в группы с определёнными политиками. Например, класс может содержать группу принтеров, которые относятся к определённому этажу здания и на которых могут печатать только пользователи из определённого отдела. Другой класс может иметь ограничения на количество страниц, которые может распечатать пользователь. Классы не создаются по умолчанию при установке CUPS и должны быть определены администратором. Это раздел в веб-интерфейсе CUPS, в котором можно создавать новые классы и управлять ими.

Jobs

Здесь администратор может просмотреть все задания на печать, которые в данный момент находятся в очереди для всех принтеров, которыми управляет эта установка CUPS.

Server

Здесь администратор может внести изменения в файл `/etc/cups/cupsd.conf` . Кроме того, с помощью флажков доступны дополнительные параметры конфигурации, такие как разрешение общего доступа к принтерам, подключённым к этой установке CUPS, в сети, расширенная аутентификация и разрешение удалённого управления принтерами.

Classes

Если в системе настроены классы принтеров, они будут перечислены на этой странице. В каждом классе принтеров можно управлять всеми принтерами в классе одновременно, а также просматривать все задания, ожидающие выполнения на принтерах этого класса.

Help

На этой вкладке представлены ссылки на всю доступную документацию по CUPS, которая установлена в системе.

Jobs

Вкладка «Задания» позволяет искать отдельные задания на печать, а также просматривать все текущие задания на печать, управляемые сервером.

Printers

На вкладке «Принтеры» перечислены все принтеры, которыми в данный момент управляет система, а также представлен краткий обзор состояния каждого принтера. По каждому принтеру в списке можно щелкнуть, и администратор перейдет на страницу, где можно управлять каждым принтером по отдельности. Информация о принтерах на этой вкладке поступает из файла `/etc/cups/printers.conf`

## Установка принтера <a href="#installing_a_printer" id="installing_a_printer"></a>

Добавление очереди печати в систему — это простой процесс в веб-интерфейсе CUPS:

1. Перейдите на вкладку "**Администрирование**", затем на кнопку "**Добавить принтер**".
2. На следующей странице будут представлены различные варианты в зависимости от того, как ваш принтер подключен к системе. Если это локальный принтер, выберите наиболее подходящий вариант, например, к какому порту подключен принтер или какое стороннее программное обеспечение для принтера может быть установлено. CUPS также попытается обнаружить принтеры, подключенные к сети, и отобразить их здесь. Вы также можете выбрать вариант прямого подключения к сетевому принтеру в зависимости от того, какие протоколы сетевой печати поддерживает принтер. Выберите подходящий вариант и нажмите кнопку **Продолжить**.
3. На следующей странице вы сможете указать название, описание и местоположение принтера (например, ”бэк-офис“ или "стойка регистрации” и т.д.). Если вы хотите предоставить общий доступ к этому принтеру по сети, вы также можете установить флажок для этой опции на этой странице. После ввода настроек нажмите кнопку **Продолжить**.
4. На следующей странице можно выбрать марку и модель принтера. Это позволяет CUPS выполнять поиск в локально установленной базе данных наиболее подходящих драйверов и файлов PPD для использования с принтером. Если у вас есть PPD-файл, предоставленный производителем принтера, перейдите к его расположению и выберите его для использования здесь. Как только это будет сделано, нажмите на кнопку **Добавить принтер**.
5. На последней странице вы можете задать параметры по умолчанию, такие как размер страницы, который будет использовать принтер, и разрешение символов, печатаемых на странице. Нажмите кнопку **«Задать параметры по умолчанию»**, и ваш принтер будет установлен в вашей системе.

{% hint style="info" %}
Многие десктопные Linux будут иметь различные инструменты, которые можно использовать для установки принтера. Среды рабочего стола GNOME и KDE имеют свои собственные встроенные приложения, которые можно использовать для установки принтеров и управления ими. Кроме того, некоторые дистрибутивы предоставляют отдельные приложения для управления принтером. Однако, когда речь идет об установке сервера, на котором будут печатать многие пользователи, веб-интерфейс CUPS может предоставить наилучшие инструменты для решения этой задачи.
{% endhint %}

Очередь печати принтера также можно настроить с помощью устаревших команд LPD/LPR. Вот пример использования команды `lpadmin`:

```bash
$ sudo lpadmin -p ENVY-4510 -L "office" -v socket://192.168.150.25 -m everywhere
```

Мы разберем команду на части, чтобы проиллюстрировать используемые здесь параметры:

* Поскольку для добавления принтера в систему требуется пользователь с правами администратора, мы добавляем к команде `lpadmin` символ `sudo`.
* Параметр `-p` — это место назначения для заданий на печать. По сути, это удобное название, чтобы пользователь знал, куда будут отправляться задания на печать. Обычно можно указать название принтера.
* Параметр `-L` — это местоположение принтера. Это необязательно, но полезно, если вам нужно управлять несколькими принтерами, расположенными в разных местах.
* Параметр `-v` предназначен для URI устройства-принтера. URI устройства — это то, что нужно очереди печати CUPS для отправки заданий на печать на конкретный принтер. В нашем примере мы используем сетевое расположение с указанным IP-адресом.
* Последний параметр, `-m` — «повсюду». Это позволяет CUPS определить модель принтера и выбрать нужный файл PPD. В современных версиях CUPS лучше использовать параметр «повсюду», чтобы CUPS мог проверить URI устройства (установленный с помощью предыдущего параметра `-v`), чтобы автоматически выбрать нужный файл PPD для принтера. В современных ситуациях CUPS просто использует IPP, как описано ниже.

Как было сказано ранее, лучше всего позволить CUPS автоматически определять, какой файл PPD использовать для конкретной очереди печати. Однако для просмотра доступных файлов PPD можно использовать устаревшую команду `lpinfo`. Просто укажите параметр `--make-and-model` для принтера, который вы хотите установить, и параметр `-m`.

```bash
$ lpinfo --make-and-model "HP Envy 4510" -m
hplip:0/ppd/hplip/HP/hp-envy_4510_series-hpijs.ppd HP Envy 4510 Series hpijs, 3.17.10
hplip:1/ppd/hplip/HP/hp-envy_4510_series-hpijs.ppd HP Envy 4510 Series hpijs, 3.17.10
hplip:2/ppd/hplip/HP/hp-envy_4510_series-hpijs.ppd HP Envy 4510 Series hpijs, 3.17.10
drv:///hpcups.crv/hp-envy_4510_series.ppd HP Envy 4510 Series, hpcups 3.17.10
everywhere IPP Everywhere
```

Обратите внимание, что команда `lpinfo` устарела. Здесь она показана в качестве примера перечисления файлов драйверов печати, которые может использовать принтер.

{% hint style="info" %}
будущих версиях CUPS устаревшие драйверы будут заменены на IPP (_протокол интернет-печати_) и стандартные форматы файлов. Вывод предыдущей команды иллюстрирует это на примере `everywhere IPP Everywhere` возможности печати. IPP может выполнять те же задачи, для которых используется драйвер печати. IPP, как и веб-интерфейс CUPS, использует сетевой порт 631 с протоколом TCP.
{% endhint %}

Принтер по умолчанию можно настроить с помощью команды `lpoptions` . Таким образом, если большинство (или все) заданий на печать будут отправляться на определенный принтер, то принтер, указанный с помощью команды `lpoptions` , будет принтером по умолчанию. Просто укажите принтер вместе с опцией `-d:`&#x20;

```bash
$ lpoptions -d ENVY-4510
```

## Управление принтерами <a href="#managing_printers" id="managing_printers"></a>

После установки принтера администратор может использовать веб-интерфейс для управления доступными параметрами принтера. Более прямой способ управления принтером — использование команды `lpadmin`

Один из вариантов — разрешить общий доступ к принтеру по сети. Этого можно добиться с помощью опции `printer-is-shared` и указания принтера с помощью опции `-p`:

<pre class="language-bash"><code class="lang-bash"><strong>$ sudo lpadmin -p FRONT-DESK -o printer-is-shared=true
</strong></code></pre>

Администратор также может настроить очередь печати таким образом, чтобы она принимала задания на печать только от определённых пользователей, при этом имена пользователей разделяются запятыми:

```bash
$ sudo lpadmin -p FRONT-DESK -u allow:carol,frank,grace
```

И наоборот, только определённым пользователям может быть отказано в доступе к конкретной очереди печати:

```bash
$ sudo lpadmin -p FRONT-DESK -u deny:dave
```

Группы пользователей также можно использовать для разрешения или запрета доступа к очереди печати при условии, что перед названием группы стоит символ «at» (`@`).

```bash
$ sudo lpadmin -p FRONT-DESK -u deny:@sales,@marketing
```

В очереди печати также может быть настроена политика обработки ошибок на случай возникновения проблем при печати задания. С помощью политик задание на печать может быть прервано (`abort-job`) или предпринята еще одна попытка его печати в более позднее время (`retry-job`). Другие политики включают возможность немедленно остановить принтер в случае возникновения ошибки (`stop-printer`), а также возможность повторить попытку печати сразу после обнаружения сбоя (`retry-current-job`). Вот пример, в котором политика принтера настроена на прерывание задания на печать в случае возникновения ошибки на `FRONT-DESK` принтере:

```bash
$ sudo lpadmin -p FRONT-DESK -o printer-error-policy=abort-job
```

Обязательно ознакомьтесь со страницами руководства по команде `lpadmin` в разделе `lpadmin(8)` для получения более подробной информации об использовании этой команды.

## Отправка заданий на печать <a href="#submitting_print_jobs" id="submitting_print_jobs"></a>

Многие настольные приложения позволяют отправлять задания на печать из пункта меню или с помощью сочетания клавиш <kbd>Ctrl</kbd>+<kbd>p</kbd>. Если вы работаете в системе Linux, в которой не используется среда рабочего стола, вы все равно можете отправлять файлы на принтер с помощью устаревших команд LPD/LPR.

Команда `lpr` («удаленный доступ к принтеру» line printer remote) используется для отправки задания на печать в очередь принтера. В самой простой форме команды требуется только имя файла и команда `lpr`:

```bash
$ lpr report.txt 
```

Приведённая выше команда отправит файл `report.txt` в очередь печати по умолчанию для системы (определяемую файлом `/etc/cups/printers.conf`).

Если в CUPS установлено несколько принтеров, то с помощью команды `lpstat` можно вывести список доступных принтеров, используя параметр `-p`, а параметр `-d` укажет, какой из них является принтером по умолчанию:

```bash
$ lpstat -p -d
printer FRONT-DESK is idle.  enabled since Mon 03 Aug 2020 10:33:07 AM EDT
printer PostScript_oc0303387803 disabled since Sat 07 Mar 2020 08:33:11 PM EST -
	reason unknown
printer ENVY-4510 is idle.  enabled since Fri 31 Jul 2020 10:08:31 AM EDT
system default destination: ENVY-4510
```

Таким образом, в нашем примере файл `report.txt` будет отправлен на принтер `ENVY-4510`, так как он установлен по умолчанию. Если файл нужно распечатать на другом принтере, укажите принтер вместе с опцией `-P`:

```bash
$ lpr -P FRONT-DESK report.txt
```

Когда задание на печать отправляется в CUPS, демон определяет, какой сервер лучше всего подходит для выполнения задачи. CUPS может использовать различные драйверы принтеров, фильтры, аппаратные мониторы портов и другое программное обеспечение для корректной обработки документа. Бывают случаи, когда пользователю, печатающему документ, необходимо внести изменения в _способ_ печати документа. Многие графические приложения значительно упрощают эту задачу. Существуют также параметры командной строки, которые можно использовать для изменения способа печати документа. При отправке задания на печать через командную строку можно использовать переключатель `-o` (для «параметров») в сочетании с конкретными условиями для настройки макета документа перед печатью. Вот краткий список часто используемых параметров:

`landscape`

Документ печатается с поворотом страницы на 90 градусов по часовой стрелке. Опция `orientation-requested=4` позволяет добиться того же результата.

`two-sided-long-edge`

Принтер распечатает документ в альбомной ориентации на обеих сторонах бумаги, если принтер поддерживает эту функцию.

`two-sided-short-edge`

Принтер распечатает документ в альбомной ориентации на обеих сторонах бумаги, если принтер поддерживает эту функцию.

`media`

Принтер распечатает задание на бумаге указанного формата. Доступные форматы бумаги для печати зависят от принтера, но вот список распространённых форматов:

| Вариант размера | Цель            |
| --------------- | --------------- |
| `A4`            | ISO A4          |
| `Letter`        | US Letter       |
| `Legal`         | US Legal        |
| `DL`            | ISO DL Envelope |
| `COM10`         | US #10 Envelope |

`collate`

Объедините распечатанный документ. Это полезно, если у вас многостраничный документ, который будет распечатан несколько раз, так как все страницы каждого документа будут распечатаны по порядку. Установите этот параметр на `true` для включения или `false` для отключения.

`page-ranges`

Эту опцию можно использовать для выбора одной страницы для печати или определённого набора страниц для печати из документа. Пример: `-o page-ranges=5-7,9,15`. Это позволит распечатать страницы 5, 6 и 7, а затем страницы 9 и 15.

`fit-to-page`

Распечатайте документ так, чтобы файл был масштабирован в соответствии с размером бумаги. Если в распечатываемом файле нет информации о размере страницы, возможно, что распечатка будет масштабирована неправильно и части документа могут оказаться за пределами страницы или документ может быть слишком маленьким.

`outputorder`

Распечатайте документ в порядке `reverse` или `normal` для начала печати со страницы 1. Если принтер печатает страницы лицевой стороной вниз, по умолчанию используется порядок `-o outputorder=normal` , а принтеры, которые печатают страницы лицевой стороной вверх, будут печатать в порядке `-o outputorder=reverse`.
